1. 內表是什麼：記憶體中的臨時表

內表（internal table）是程式執行期間在記憶體中建立的一張臨時表。你可以對它做插入、修改、刪除、查詢，程式跑完它就自動被釋放，不必像 T-SQL 的 #table 還要記得 DROP（雖然 T-SQL 現在也有 DECLARE @table 了）。

老師的第一句話：掌握內表是成為 ABAPer 的關鍵一步。除了寫程式之外，小到 SELECT-OPTIONS、大到 Function Module 的 TABLES 參數、ALV 的資料來源，到處都是 internal table 的影子。

口訣：內表要掌握十大技巧 —— 種類、建立、附加、合併、更改、刪除、查詢、去重、排序、加總。這十個動作學會了，ABAP 的資料處理就過關了。

內表、表格列（table line）與工作區（work area）

  • 內表：多筆資料的集合（相當於 SQL 的 table）。
  • table line：內表中的一筆記錄，很容易跟工作區搞混。
  • 工作區 work area：內表是「按行存取」的，必須有一塊區域當作與內表互相傳輸的介面。從內表讀資料時，被定址的那一行內容會覆蓋工作區；要寫資料進內表時，必須先把資料填進工作區。

換句話說：工作區＝一列的結構，內表＝很多列。在現代 ABAP 中，工作區往往不需要事先宣告，直接用 INTO DATA(ls_x) 或 ASSIGNING FIELD-SYMBOL(<ls_x>) 在迴圈裡就地產生。

DESCRIBE TABLE itab LINES n. 就等於 SQL 的 SELECT COUNT(*) FROM table。7.02 之後更建議直接用內建函數 lines( itab )，可以寫在運算式裡。

2. 三種內表型別與 KEY 設計（STANDARD / SORTED / HASHED）

內表共三種類型，差別在「怎麼找到那一列」：

型別關鍵字索引主鍵存取複雜度適用時機
標準表STANDARD TABLE有主表索引（可用 INDEX / sy-tabix）Non-unique循序 O(n)；有排序＋BINARY SEARCH 才 O(log n)一般報表、資料量小（＜1 萬筆）。簡單環境用它就夠了
排序表SORTED TABLE有邏輯索引，依主鍵昇冪自動排序後存放UNIQUE 或 NON-UNIQUEO(log n)（二分搜尋，系統自動做）邊新增邊排序、需要頻繁 READ 的中量資料（＞1 萬筆）
雜湊表HASHED TABLE沒有主表索引，只能用鍵值存取必須 UNIQUEO(1)，定址時間與筆數無關巨量資料（＞10 萬筆）的鍵值查表、對照檔

SAP 官方對 hashed table 的定義：資料列依 hash 演算法存放、以唯一 hash key 存取；沒有主表索引，但可以另外掛 secondary table index（透過 secondary key）。

老師的實測結論（用 SE30／SAT 量）：小資料量時排序表比較快；資料量很大時雜湊表勝出。不過有了 HANA 之後，大多數效能問題在 DB 層就解掉了，HASH 表用到的時機相對變少——但知道有這個工具，遇到極端狀況才有牌可打。

主鍵、次鍵與 USING KEY

  • Primary key：WITH [UNIQUE|NON-UNIQUE] KEY f1 f2。若用 TYPE TABLE OF struct 而不指定 KEY，預設是「所有非數值欄位（c／n／d／t／string）當 non-unique 標準鍵」——這通常不是你要的，也會拖慢比對。
  • WITH EMPTY KEY：7.40 起可宣告空鍵，明確表示「我不靠 key 找資料，只用 index」，比預設標準鍵乾淨。
  • Secondary key：一張內表可以同時掛多組次鍵（SORTED 或 HASHED），讓同一份資料有多種查法。存取時用 USING KEY <key_name> 指定要走哪一把鍵。
  • DEFAULT KEY：舊式寫法，等同標準鍵，效能差，新程式不建議。

4. WITH HEADER LINE：為什麼不要再用

WITH HEADER LINE 是讓工作區與內表同名的舊機制。itab-field1 = 1. APPEND itab. 看起來很省事，但它是 ABAP 3.0 時代的產物。

講義引用的英文說明重點：header line 就是一個隱含的介面（interface），沒有它就必須自己宣告工作區；但在新版 SAP 上，header line 已經是 obsolete，而且物件導向 ABAP（class / method）根本不支援。

指令對「無 header line」的內表對「有 header line」的內表
CLEAR it.清空內表只清空工作區（陷阱！）
CLEAR it[].清空內表清空內表
REFRESH it.清空內表清空內表，不會清工作區
FREE it.清空內表並釋放記憶體同左

*&---------------------------------------------------------------------*
REPORT zdemo_headerline.

" ==== 反例：舊寫法，自己的程式請勿模仿 ====
" DATA it_marah TYPE TABLE OF mara WITH HEADER LINE.
" it_marah-matnr = 'A'.
" APPEND it_marah.            " 把工作區附加進內表
" CLEAR  it_marah.            " 只清工作區，內表還在！

" ==== 正解：工作區與內表分開，語意清楚 ====

DATA ls_mara TYPE mara.

ls_mara-matnr = 'A'.
APPEND ls_mara TO lt_mara.

CLEAR ls_mara.                " 清工作區
CLEAR lt_mara.                " 清內表（無 header line 時 CLEAR 就是清整張表）

" ==== 更好：連工作區都不用宣告 ====
DATA lt_mat TYPE STANDARD TABLE OF mara WITH EMPTY KEY.
APPEND VALUE #( matnr = 'A' mtart = 'FERT' ) TO lt_mat.

LOOP AT lt_mat INTO DATA(ls_line).
  WRITE: / ls_line-matnr, ls_line-mtart.
ENDLOOP.
遇到舊程式看不出某個名稱是內表還是工作區時，先 debug：在 Debugger 裡打 itab 看到的是工作區，打 itab[] 看到的才是內表。另外 OCCURS 0 的宣告形同 WITH HEADER LINE。

5. 內表的新增：APPEND / INSERT / COLLECT / VALUE

講義的口訣：內表新增有五個方法 —— INSERT、COLLECT（累加數值）、APPEND、MOVE、＝（賦值），再加上 SELECT ... INTO TABLE。使用時機：

  • 只要存資料、要速度 → APPEND（附加到最後，只能用在 STANDARD TABLE）。
  • 要數字欄位自動加總、或要保證沒有重複條目 → COLLECT（等同 GROUP BY 的效果）。
  • 要插到既有列的前面、或依 key 插入 SORTED／HASHED → INSERT。
  • 整張表複製覆蓋 → lt_a = lt_b.（MOVE 已過時，直接用等號）。

COLLECT 的行為要記牢：比對所有非數值欄位，找到相同的那一列就把數值欄位累加上去；找不到就新增一列。非常適合做小計、合計、總計。

*& Report ZDEMO_02_13  內表的新增（原講義第 13 個練習 Z202202_13 改寫）
*&---------------------------------------------------------------------*
REPORT zdemo_02_13.

TYPES: BEGIN OF ty_student,
         name TYPE char10,
         age  TYPE int2,
       END OF ty_student.

DATA: lt_stu TYPE STANDARD TABLE OF ty_student WITH EMPTY KEY,
      lt_tot TYPE STANDARD TABLE OF ty_student WITH EMPTY KEY.

" 1) APPEND：附加到表尾（最快）
DO 2 TIMES.
  APPEND VALUE #( name = 'CASPER' age = sy-index ) TO lt_stu.
ENDDO.

" 2) INSERT ... INDEX：插到指定位置之前
INSERT VALUE #( name = 'NCU' age = 3 ) INTO lt_stu INDEX 1.

" 3) INSERT INITIAL LINE：插一列空白列
"    常用在 SELECT-OPTIONS 要先塞一列空行進 range 表時
INSERT INITIAL LINE INTO lt_stu INDEX 1 ASSIGNING FIELD-SYMBOL(<ls_blank>).
<ls_blank>-name = 'BLANK'.

" 4) COLLECT：非數值欄位相同就累加數值欄位
DATA ls_stu TYPE ty_student.
ls_stu = VALUE #( name = 'NCU' age = 3 ).
COLLECT ls_stu INTO lt_stu.        " NCU 已存在 → age 變成 6

" 5) 多筆附加／插入
APPEND LINES OF lt_stu TO lt_tot.
APPEND LINES OF lt_stu FROM 2 TO 3 TO lt_tot.   " 注意：是第 2~3 列，不是 1~2
INSERT LINES OF lt_stu INTO lt_tot INDEX 1.

" 6) 整表覆蓋（MOVE 已過時，用等號）
DATA(lt_copy) = lt_stu.

" 7) 一次建整張表：VALUE 建構式（7.40+，最現代）
DATA(lt_new) = VALUE ty_t_dummy( ( name = 'A' age = 1 )
                                 ( name = 'B' age = 2 )
                                 ( name = 'C' age = 3 ) ).

LOOP AT lt_stu INTO DATA(ls_out).
  WRITE: / ls_out-name, ls_out-age.
ENDLOOP.
效能口訣：用 APPEND LINES OF it_a TO it_b 取代 LOOP AT it_a ... APPEND ... ENDLOOP。一行指令在核心層搬資料，比迴圈逐列搬快好幾個數量級。

把資料庫資料直接灌進內表，才是最常用的「新增」：

" 一次讀進內表（現代寫法：明列欄位 ＋ 內嵌宣告 ＋ 逸出字元 @）
SELECT bname AS name,
       persnumber AS telnum,
       addrnumber AS addr
  FROM usr21
  INTO TABLE @DATA(lt_emp)
  UP TO 10 ROWS.

" 追加到已存在的內表（不清空原內容）
SELECT bname AS name,
       persnumber AS telnum,
       addrnumber AS addr
  FROM usr21
  APPENDING TABLE @lt_emp
  WHERE bname LIKE 'Z%'.
欄位名稱不同名時，用 AS 重新命名，就不必再靠 INTO CORRESPONDING FIELDS OF 硬湊。CORRESPONDING 的比對是執行期做的，欄位一多就會慢，而且欄位名打錯不會報錯、只會靜靜地漏資料。

6. 內表的修改：MODIFY ... TRANSPORTING ... WHERE

語法骨架：

MODIFY itab FROM wa [INDEX idx] [TRANSPORTING f1 f2 ...] [WHERE cond].
  • 只給 INDEX：改指定那一列（在 LOOP 裡常搭配 sy-tabix）。
  • 加 TRANSPORTING：只更新列出的欄位，其他欄位保持原值。
  • 加 WHERE：整批更新（此時一定要有 TRANSPORTING）。

TYPES: BEGIN OF ty_student,
         name TYPE char10,
         age  TYPE int2,
       END OF ty_student.

DATA lt_stu TYPE STANDARD TABLE OF ty_student WITH EMPTY KEY.

DO 2 TIMES.
  APPEND VALUE #( name = 'CASPER' age = sy-index ) TO lt_stu.
ENDDO.

DATA(ls_stu) = VALUE ty_student( name = 'NCU' age = 3 ).

" 1) 依 index 整列覆蓋
MODIFY lt_stu FROM ls_stu INDEX 2.

" 2) 依 index 只更新 NAME 欄位
ls_stu = VALUE #( name = 'NCUBA' age = 1 ).
MODIFY lt_stu FROM ls_stu INDEX 1 TRANSPORTING name.

" 3) 整批更新：所有 name = 'NCUBA' 的列，把 age 改成 99
ls_stu-age = 99.
MODIFY lt_stu FROM ls_stu TRANSPORTING age WHERE name = 'NCUBA'.

" 4) 最現代的做法：用 field-symbol 就地改，不需要 MODIFY 回寫
LOOP AT lt_stu ASSIGNING FIELD-SYMBOL(<ls_stu>) WHERE name = 'CASPER'.
  <ls_stu>-age = <ls_stu>-age + 1.
ENDLOOP.

LOOP AT lt_stu INTO DATA(ls_out).
  WRITE: / ls_out-name, ls_out-age.
ENDLOOP.
批次改內表，用 MODIFY ... TRANSPORTING ... WHERE 或 LOOP AT ... ASSIGNING，不要寫「LOOP → 改工作區 → MODIFY FROM wa INDEX sy-tabix」的三段式，那是最慢的寫法。
在 SORTED / HASHED 內表上，不可以修改主鍵欄位，執行期會拋出例外。要改鍵值只能 DELETE 再 INSERT。

7. 內表的刪除與去重：DELETE / ADJACENT DUPLICATES

DELETE TABLE itab WITH TABLE KEY k1 = v1 k2 = v2.  " 依主鍵刪除
DELETE TABLE itab FROM wa.                          " 依工作區的鍵值刪除
DELETE itab INDEX idx.                              " 依索引刪除
DELETE itab FROM idx1 TO idx2.                      " 依索引區間刪除
DELETE itab WHERE cond.                             " 依條件刪除（最常用）
DELETE ADJACENT DUPLICATES FROM itab COMPARING f1 f2.
DELETE ADJACENT DUPLICATES FROM itab COMPARING ALL FIELDS.
DELETE ADJACENT DUPLICATES 只刪「相鄰」的重複列。所以執行前一定要先 SORT，而且 SORT 的欄位必須涵蓋 COMPARING 的欄位；用 COMPARING ALL FIELDS 就要對所有欄位排序。沒排序就去重，是新手最常見的 bug —— 資料看起來少了一些、又沒少乾淨。

實務案例：在 LOOP 中刪除自己 —— USING KEY loop_key

講義收錄了一段工作上遇到的真實案例：把系統資料與 Excel 對照，Excel 裡沒有的就把系統那一列刪掉。在 LOOP 內刪除正在迴圈的那張表是很危險的動作（索引會位移），所以必須加 USING KEY loop_key，讓系統知道刪除要走「目前迴圈用的那把鍵」，避免跳列。

" 原講義寫法（FORM clear_data）的現代化版本
METHOD clear_data.

  CHECK it_ekes_xls IS NOT INITIAL.        " 對照表是空的就不要動作

  LOOP AT it_zmmb0021 ASSIGNING FIELD-SYMBOL(<ls_zmm>).

    " 用 line_exists 取代 READ TABLE + sy-subrc 判斷
    IF NOT line_exists( it_ekes_xls[ ebeln = <ls_zmm>-ebeln
                                     ebelp = <ls_zmm>-ebelp
                                     etens = <ls_zmm>-ekes_etens ] ).
      " 迴圈中刪除自己，一定要指定 loop_key，避免索引錯位
      DELETE it_zmmb0021 USING KEY loop_key.
    ENDIF.

  ENDLOOP.

ENDMETHOD.

10. 排序、去重、計數、清空與動態 SORT

SORT itab [BY f1 [ASCENDING|DESCENDING] f2 ...] [AS TEXT] [STABLE].

老師在 ZKEPH 成本報表踩過的真實坑：沒有排序的內表，抓到哪一筆是「不保證」的。成本評價之後會有兩種角度（item category H 與 cost component E），兩者的成本欄位數量不同，程式若沒排序就 READ，有時抓到 H、有時抓到 E，成本結果就不穩定。結論：只要「只取一筆」，就必須先確定排序或明確過濾條件（例如固定取 H）。同樣的道理也適用於 SELECT 沒有 ORDER BY 的情況。

SELECT [SINGLE [FOR UPDATE]] [DISTINCT]
       FROM data_source [AS alias]
            [ [INNER] JOIN | LEFT|RIGHT [OUTER [MANY TO ONE]] JOIN | CROSS JOIN
              data_source [AS alias] ON join_cond ]
            [ USING CLIENT @lv_mandt | CLIENT SPECIFIED | USING ALL CLIENTS ]
       FIELDS col1, col2, sql_expression AS alias, ...
       [ FOR ALL ENTRIES IN @itab ] WHERE sql_cond
       [ GROUP BY col1, col2 | GROUPING SETS ( ... ) ]
       [ HAVING sql_cond ]
       [ UNION [ALL|DISTINCT] SELECT ... ]
       [ ORDER BY PRIMARY KEY | col1 [ASCENDING|DESCENDING], ... ]
       INTO   { @DATA(wa) | TABLE @DATA(itab) | ( @a, @b, @c )
              | CORRESPONDING FIELDS OF TABLE @itab
              | TABLE @itab PACKAGE SIZE n }
       [ APPENDING TABLE @itab ]
       [ UP TO n ROWS ] [ OFFSET o ]
       [ BYPASSING BUFFER ]
       [ CONNECTION con ].

常用子句速查：

子句意義備註
SELECT SINGLE只取一列必須給齊主鍵才保證唯一；不可與 GROUP BY、FOR ALL ENTRIES 併用
DISTINCT去除重複列不可與 SELECT SINGLE、也不建議與大量欄位併用
UP TO n ROWS / OFFSET o取前 n 列 / 跳過 o 列OFFSET 必須搭配 ORDER BY 才有意義（7.50+）
PACKAGE SIZE n分批讀進內表搭配 SELECT ... ENDSELECT，處理巨量資料避免記憶體爆掉
BYPASSING BUFFER略過表緩衝，直接讀 DB需要絕對最新資料時用
FOR UPDATE讀取時加 DB 鎖SAP 建議改用 ENQUEUE 鎖物件，見資料字典章

15. JOIN 與子查詢

多表查詢有兩條路：在 SE11 建 View（可重複使用），或在程式裡 JOIN（一次性）。老師的思考題：「你的程式到底要用 SQL 關聯多表？還是建成一個 View 方便日後重複使用？」判斷標準：

  • 邏輯會被多支程式重複使用、或要給 Fiori／OData 消費 → 建 CDS View（S/4HANA 首選，取代自建 DB View）。
  • 只有這支程式用、關聯條件會隨選擇畫面變動 → 程式裡 JOIN。

JOIN 三要素：連接哪些表、連接條件（ON）、連接哪些欄位。型態：

  • INNER JOIN：兩表都有對應的資料才出現。
  • LEFT OUTER JOIN：保證左邊的主資料表全部秀出，右表沒對到就是 NULL（在 ABAP 會轉成型別初始值）。
  • RIGHT OUTER JOIN / CROSS JOIN：較少用；CROSS JOIN 是笛卡兒積，非常危險。

17. FOR ALL ENTRIES：四大陷阱與替代方案

FOR ALL ENTRIES（FAE）的用途：先建一張驅動內表，再用它限制第二段 SELECT。經典例子是先從 EKKO 撈出採購單號，再用它去 EKPO 撈明細。

*&---------------------------------------------------------------------*
REPORT zdemo_fae.

" 驅動表：只取需要的鍵欄位
SELECT ebeln, bukrs, lifnr, bedat
  FROM ekko
  WHERE bukrs = @lv_bukrs
  INTO TABLE @DATA(lt_ekko)
  UP TO 10 ROWS.

" ★ 陷阱一：驅動內表若為空，FAE 會回傳「整張表」，而且 WHERE 的其他條件也被忽略
"    所以一定要先判斷 IS NOT INITIAL
IF lt_ekko IS NOT INITIAL.

  " ★ 陷阱二：驅動表要先去重，否則同一個 key 會被送好幾次，白白浪費 DB 往返
  DATA(lt_key) = lt_ekko.
  SORT lt_key BY ebeln.
  DELETE ADJACENT DUPLICATES FROM lt_key COMPARING ebeln.

  SELECT ebeln, ebelp, matnr, werks, menge, netwr
    FROM ekpo
    FOR ALL ENTRIES IN @lt_key
    WHERE ebeln = @lt_key-ebeln
      AND loekz = @space
    INTO TABLE @DATA(lt_ekpo).

ENDIF.
FOR ALL ENTRIES 四大陷阱
① 空表災難：驅動內表是空的時候，FAE 條件整段被忽略，連同 WHERE 中其他條件也一併失效，結果是「把整張表撈回來」。講義用 EKPO 實測過三種情況（無 FAE／有 FAE／FAE 表為空），第三種筆數會暴增。解法：一律先寫 IF lt_x IS NOT INITIAL.
② 自動 DISTINCT：FAE 的結果會自動去除完全重複的列。如果 SELECT 清單沒有包含目標表的完整主鍵，會「莫名其妙少資料」。解法：SELECT 清單一定要含齊主鍵欄位。
③ 被拆成多次 DB 呼叫：系統會依 profile 參數 rsdb/max_blocking_factor 把驅動表切成很多段，逐段丟給 DB。驅動表沒去重、或筆數上萬，往返次數就爆掉。
④ 型別必須相符：驅動內表欄位的型別與長度要和 DB 欄位一致，否則轉型時可能靜默地對不到。另外 FAE 不可與 SELECT SINGLE、也不建議與 GROUP BY 併用，而且 FAE 的驅動表不能是 header line。

S/4HANA 的替代方案（優先順序由上而下）：

  1. JOIN：兩張表本來就有關聯，直接 JOIN，一次往返。
  2. 子查詢 IN / EXISTS：邏輯是「存在性判斷」時最乾淨。
  3. CTE（WITH）：中間結果多、邏輯分層時可讀性最好。
  4. SELECT ... FROM @itab（7.52+）：把已在記憶體的內表當成資料來源，直接下 SQL。
  5. CDS View / AMDP：邏輯複雜、會被重複使用時的正解。

18. SELECT SINGLE vs UP TO 1 ROWS（HANA 沒有排序保證）

講義 08-00 特別開一節講這個差異，重點是主鍵：

SELECT SINGLESELECT ... UP TO 1 ROWS
條件要求必須指定全部主鍵才保證取到唯一那筆；缺任何一個主鍵就不該用任意條件、甚至不給條件都可以
可否 ORDER BY不可以可以，因此可以「取最新／最大的那一筆」
回傳一個工作區可 INTO 工作區或內表
沒給齊主鍵時回傳「任意一筆」，結果不保證穩定加 ORDER BY 就穩定
HANA 沒有排序保證：資料在欄式儲存中沒有固定的實體順序，同一段沒有 ORDER BY 的 SQL，今天跟明天、單機與多節點，回傳順序可能不同。所以「取最新一筆」絕不能靠 SELECT SINGLE 或不加 ORDER BY 的 UP TO 1 ROWS。
這正是老師 ZKEPH 成本抓錯的同一類問題：沒有排序，就沒有「第一筆」可言。

UPDATE dbtab SET f1 = @v1, f2 = @v2 WHERE cond.

*&---------------------------------------------------------------------*

DATA lt_scarr TYPE STANDARD TABLE OF scarr WITH EMPTY KEY.

lt_scarr = VALUE #( ( carrid   = '000'
                      carrname = 'CASPER'
                      currcode = 'TWD'
                      url      = 'www.cerps.com.tw' ) ).

INSERT scarr FROM TABLE @lt_scarr ACCEPTING DUPLICATE KEYS.
DATA(lv_ins) = sy-dbcnt.

UPDATE scarr SET url = 'www.cerps.com.tw'
             WHERE carrid = '000'.

MODIFY scarr FROM TABLE @lt_scarr.

DELETE FROM scarr WHERE carrid = '000'.

IF sy-subrc = 0.
  COMMIT WORK AND WAIT.        " AND WAIT：等更新任務完成才往下（報表要立刻讀回時必用）
  MESSAGE '異動成功' TYPE 'S'.
ELSE.
  ROLLBACK WORK.
  MESSAGE '異動失敗，已回復' TYPE 'E'.

正式系統的鐵律：
① 不要直接對 SAP 標準表下 INSERT / UPDATE / DELETE。標準表背後有一致性檢查、狀態欄位、變更文件、後續帳務，必須走 BAPI / BDC / 標準交易。自建的 Z 表才可以直接寫。
② UPDATE 一定要寫 WHERE，講義原文就標「這是危險的做法」。
③ 呼叫 BAPI 之後要自己下 BAPI_TRANSACTION_COMMIT；在 update task 或 BAdI 裡不可以亂下 COMMIT WORK，會把別人的 LUW 一起提交掉。
④ COMMIT WORK AND WAIT 與 COMMIT WORK 的差別：前者等非同步更新完成，後者不等。報表寫完馬上要讀回來時，用 AND WAIT。

EXEC SQL（已過時，只為讀懂舊程式）

講義 02-09 用 EXEC SQL ... ENDEXEC 示範查詢、建立 Oracle 函數與游標。三個語法規則要記得：語句結尾不加句點、區塊內不可有註解（星號與雙引號都不行）、參數用冒號 :var 而不是問號；欄位與條件都用逗號分開。

AMDP 與 CDS：真正的 code pushdown

  • CDS View（ABAP Core Data Services）：在 ADT／Eclipse 用 DDL 定義的視圖，取代 SE11 的 DB View。支援 association、annotation、參數、聚合、CASE、視窗函數，可直接被 ABAP SQL、OData、Fiori、Analytics 消費。S/4HANA 的第一選擇。

22. 效能觀念：Code Pushdown 與 S/4HANA 的巨表

講義 02-11 整理的 Open SQL 注意事項，是 ABAP 效能的基本功。這裡逐條保留並補上 S/4HANA 的現況：

講義守則S/4HANA 的補充
避免在迴圈中寫 SELECT，改用 FOR ALL ENTRIES 一次抽進內表更好的做法是 JOIN／子查詢／CDS View；FAE 只是次佳解
JOIN 不要關聯太多表，順序小表→大表HANA 的 optimizer 會自行決定順序；但表數量多仍會讓執行計畫變複雜，建議拆成 CTE
只查自己需要的欄位，少用 SELECT *在欄式資料庫上這條更重要：HANA 只讀被指定的欄位，少一欄就少一份 I/O
WHERE 多用索引、主鍵HANA 主要靠欄式掃描，但 驅動欄位（如 MANDT、BUKRS、GJAHR、WERKS）仍要帶；SE11 可建 secondary index，S/4 也常用 CDS 的 index-like 設計
不要用 SELECT ... ENDSELECT正確；要處理巨量資料請用 PACKAGE SIZE 分批，或 OFFSET / UP TO 分頁
不要用 <>（不走索引），改用 > 或 <HANA 上影響已較小，但仍建議把條件寫成正向（IN / BETWEEN）比較好被最佳化
不要用 ORDER BY，撈回來再在內表排這一條在 HANA 上要反過來：HANA 排序很快，且沒有 ORDER BY 就沒有順序保證。需要順序就在 SQL 排
內表求和：能在 SQL 做就在 SQL 做；否則用 AT END OF；COLLECT 在大量資料時較慢正確。優先用 GROUP BY 讓 DB 加總，其次視窗函數，最後才回到內表
用 APPEND LINES OF 取代 LOOP＋APPEND正確，永遠成立
Code Pushdown 一句話：能讓資料庫算的，就不要搬回 ABAP 算。搬 100 萬列回應用伺服器再 LOOP 加總，和一句 GROUP BY 的差距，是分鐘與秒的差距。

S/4HANA 的兩張巨表：ACDOCA 與 MATDOC

  • ACDOCA（Universal Journal）：S/4 把 BKPF/BSEG、FAGLFLEXA、COEP、ANEP、MLIT 等總帳／管理會計／獲利分析明細通通合併到這一張表，欄位數超過 300、資料量以億計。查詢時 RLDNR（分類帳）、RBUKRS（公司代碼）、GJAHR（年度）幾乎是必帶條件，再加期間 POPER 或傳票號 BELNR。BSEG／BKPF 在 S/4 仍存在，但報表請改讀 ACDOCA 或其 CDS View（I_JournalEntryItem 等）。
  • MATDOC：S/4 把 MKPF＋MSEG 合併成 MATDOC，所有物料文件內容都存在這張表。MKPF／MSEG 變成相容性 CDS View（讀得到、但效能不好）。庫存數量表 MARD-LABST、MBEW 等在 S/4 也已改成由 MATDOC 聚合而來的相容視圖，不要對它們做大量迴圈式查詢，改用 NSDM 系列 CDS View 或標準 FM。
  • 物料主檔仍是 MARA（一般）／MAKT（描述）／MARC（工廠）／MARD（儲位）；MARA-MATNR 在 S/4 長度為 40（原 18），寫程式不要再寫死 18 碼。

24. 綜合練習一：歐幾里德距離（Euclidean distance）與 Z-score

這是講義的期中題 Z00_MIDTERM：從自建表 ZEUCLIDEAN（欄位 ID、HEIGHT、HOBBY、AGE）讀出所有人，先把三個欄位標準化成 Z-score，再算每個人與「使用者輸入的那個 ID」之間的歐幾里德距離，最後標出最適伙伴（自己標 O、最近的人標 X）。

公式：z = ( x − 平均 ) / 標準差；距離 = √( Σ ( z_i − z_target,i )² )。標準差可以呼叫標準函數 RMMATH1_VARIANCE_DEVIATION（回傳 E_VARIANCE、E_DEVIATION、E_AVERAGE），或自己算。

*&---------------------------------------------------------------------*
*& Report ZDEMO_EUCLIDEAN  歐幾里德距離＋Z-score（原 Z00_MIDTERM 現代化改寫）
*&---------------------------------------------------------------------*
REPORT zdemo_euclidean.

TYPES: BEGIN OF ty_zeuc,
         id            TYPE zeuclidean-id,
         height        TYPE zeuclidean-height,
         hobby         TYPE zeuclidean-hobby,
         age           TYPE zeuclidean-age,
         z_height      TYPE p LENGTH 8 DECIMALS 4,
         z_hobby       TYPE p LENGTH 8 DECIMALS 4,
         z_age         TYPE p LENGTH 8 DECIMALS 4,
         distance      TYPE p LENGTH 8 DECIMALS 4,
         best_fit      TYPE char1,
       END OF ty_zeuc.

PARAMETERS p_id TYPE zeuclidean-id OBLIGATORY.

" 1) 一次讀進內表
SELECT id, height, hobby, age
  FROM zeuclidean
  ORDER BY id                                  " 一定要排序，結果才穩定
  INTO CORRESPONDING FIELDS OF TABLE @DATA(lt_zeuc).

IF lt_zeuc IS INITIAL.
  MESSAGE '沒有資料' TYPE 'E'.
ENDIF.

DATA(lv_n) = lines( lt_zeuc ).

" 2) 用 REDUCE 算平均，不必寫迴圈
DATA(lv_avg_h) = REDUCE f( INIT s = 0 FOR ls IN lt_zeuc NEXT s = s + ls-height ) / lv_n.
DATA(lv_avg_o) = REDUCE f( INIT s = 0 FOR ls IN lt_zeuc NEXT s = s + ls-hobby  ) / lv_n.
DATA(lv_avg_a) = REDUCE f( INIT s = 0 FOR ls IN lt_zeuc NEXT s = s + ls-age    ) / lv_n.

" 3) 母體標準差 = sqrt( Σ(x-平均)² / n )
DATA(lv_std_h) = sqrt( REDUCE f( INIT s = 0 FOR ls IN lt_zeuc
                                 NEXT s = s + ( ls-height - lv_avg_h ) ** 2 ) / lv_n ).
DATA(lv_std_o) = sqrt( REDUCE f( INIT s = 0 FOR ls IN lt_zeuc
                                 NEXT s = s + ( ls-hobby  - lv_avg_o ) ** 2 ) / lv_n ).
DATA(lv_std_a) = sqrt( REDUCE f( INIT s = 0 FOR ls IN lt_zeuc
                                 NEXT s = s + ( ls-age    - lv_avg_a ) ** 2 ) / lv_n ).

" 4) 算 Z-score：用 field-symbol 就地寫回，不必 MODIFY
LOOP AT lt_zeuc ASSIGNING FIELD-SYMBOL(<ls>).
  <ls>-z_height = COND #( WHEN lv_std_h > 0 THEN ( <ls>-height - lv_avg_h ) / lv_std_h ELSE 0 ).
  <ls>-z_hobby  = COND #( WHEN lv_std_o > 0 THEN ( <ls>-hobby  - lv_avg_o ) / lv_std_o ELSE 0 ).
  <ls>-z_age    = COND #( WHEN lv_std_a > 0 THEN ( <ls>-age    - lv_avg_a ) / lv_std_a ELSE 0 ).
ENDLOOP.

" 5) 定位使用者輸入的那一筆
IF NOT line_exists( lt_zeuc[ id = p_id ] ).
  MESSAGE |查無 ID { p_id }| TYPE 'E'.
ENDIF.
DATA(ls_target) = lt_zeuc[ id = p_id ].

" 6) 算每一筆與 target 的歐幾里德距離

  <ls2>-distance = sqrt( ( <ls2>-z_height - ls_target-z_height ) ** 2
                       + ( <ls2>-z_hobby  - ls_target-z_hobby  ) ** 2
                       + ( <ls2>-z_age    - ls_target-z_age    ) ** 2 ).
ENDLOOP.

                         FOR ls IN lt_zeuc WHERE ( distance > 0 )
                         NEXT m = COND #( WHEN ls-distance < m THEN ls-distance ELSE m ) ).

  <ls3>-best_fit = COND #( WHEN <ls3>-id = ls_target-id  THEN 'O'
                           WHEN <ls3>-distance = lv_min  THEN 'X'
                           ELSE space ).
ENDLOOP.

25. 綜合練習二：標準差與 Z-score 找異常值

講義 10-3 的 ZSTDDEV_DEMO 用一組固定數值示範 sum / count / mean / stddev，接著加上 Z-score 的六行程式。進階挑戰是：把這個概念套到 ACDOCA 的會計科目 740300，找出借方金額的異常值。

*&---------------------------------------------------------------------*
*& Report ZDEMO_STDDEV  標準差 / Z-score 找異常值（原 ZSTDDEV_DEMO 進階版）
*&---------------------------------------------------------------------*
REPORT zdemo_stddev.

PARAMETERS: p_bukrs TYPE acdoca-rbukrs OBLIGATORY,
            p_gjahr TYPE acdoca-gjahr  OBLIGATORY,
            p_racct TYPE acdoca-racct  DEFAULT '0000740300',
            p_z     TYPE p LENGTH 3 DECIMALS 1 DEFAULT '2.0'.  " |z| 超過就算異常

TYPES: BEGIN OF ty_line,
         belnr  TYPE acdoca-belnr,
         docln  TYPE acdoca-docln,
         budat  TYPE acdoca-budat,
         hsl    TYPE acdoca-hsl,
         zscore TYPE p LENGTH 8 DECIMALS 4,
         flag   TYPE char1,
       END OF ty_line.

" 1) 讓 DB 先做過濾與加總（code pushdown）
SELECT belnr, docln, budat, hsl
  FROM acdoca
  WHERE rldnr  = '0L'
    AND rbukrs = @p_bukrs
    AND gjahr  = @p_gjahr
    AND racct  = @p_racct
    AND drcrk  = 'S'                  " 借方
  ORDER BY belnr, docln
  INTO CORRESPONDING FIELDS OF TABLE @DATA(lt_data).

IF lt_data IS INITIAL.
  MESSAGE '查無資料' TYPE 'S' DISPLAY LIKE 'E'.
  RETURN.
ENDIF.

" 2) 平均與母體標準差
DATA(lv_n)    = lines( lt_data ).
DATA(lv_sum)  = REDUCE f( INIT s = 0 FOR ls IN lt_data NEXT s = s + ls-hsl ).
DATA(lv_mean) = lv_sum / lv_n.
DATA(lv_std)  = sqrt( REDUCE f( INIT s = 0 FOR ls IN lt_data
                                NEXT s = s + ( ls-hsl - lv_mean ) ** 2 ) / lv_n ).

" 3) 算 Z-score 並標記異常
LOOP AT lt_data ASSIGNING FIELD-SYMBOL(<ls>).
  <ls>-zscore = COND #( WHEN lv_std > 0 THEN ( <ls>-hsl - lv_mean ) / lv_std ELSE 0 ).
  <ls>-flag   = COND #( WHEN abs( <ls>-zscore ) >= p_z THEN 'X' ELSE space ).
ENDLOOP.

WRITE: / |筆數 { lv_n }，加總 { lv_sum }，平均 { lv_mean }，標準差 { lv_std }|.
ULINE.
WRITE: / '傳票號', 25 '行號', 35 '過帳日', 50 '金額', 70 'Z-score', 85 '異常'.
LOOP AT lt_data INTO DATA(ls_out).
  WRITE: /  ls_out-belnr,
         25 ls_out-docln,
         35 ls_out-budat,
         50 ls_out-hsl,
         70 ls_out-zscore,
         85 ls_out-flag.
ENDLOOP.

26. 長文本（Long Text）與內表

SAP 的長文本（訂單抬頭備註、料件長描述等）不存在一般欄位，而是存在 STXH（表頭）／STXL（內容，壓縮），並且用四個鍵定位：TDOBJECT（物件）、TDID（文字 ID）、TDSPRAS（語言）、TDNAME（物件鍵）。內容以 TLINE 結構的內表傳遞，所以它其實是內表章的延伸應用。

  14. EXEC SQL 為什麼不該再用？替代方案是什麼？答：已 obsolete，且不做 client 處理、不走表緩衝、不檢查授權；改用 ADBC（CL_SQL_STATEMENT）、AMDP 或 CDS。
