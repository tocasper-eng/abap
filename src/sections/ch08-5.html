步驟原程式做法用到的物件
① 算日期期初日＝起始月的 1 號；「期末日」其實是結束月的下個月 1 號（用字串拼接處理跨年、補前導零）字串運算
② 讀未清項SELECT … ENDSELECT 讀 BSID JOIN BKPF，條件 BUDAT < 下月 1 號，排除 XREVERSING／XREVERSEDBSID、BKPF

④ 彙總期初／期末每筆依 SHKZG 決定正負，全部加到「期末」，BUDAT 早於期初日的再加到「期初」，用 COLLECT 依客戶＋科目＋幣別彙總COLLECT
⑤ 本期明細BUDAT ≥ 期初日的放進 GT_DATA內表

10. ZFIU014N 實際成本、物料帳與 ACDOCA：排序與分類帳的坑

程式取「實際成本」的做法是：從 VBRP 找回交貨單 LIPS，再找它的子行項目（UEPOS = 上層行號，例如成套品的組件），到物料帳 CKMLHD＋CKMLCR 找過帳期間之前最近一期的期間單價 PVPRS，乘以交貨數量。這段邏輯有三個 bug，而且每一個都跟本館一再強調的「排序」有關：

  1. 沒有篩選 CURTP（幣別類型）。CKMLCR 每個期間會有多列：10＝公司代碼幣別、30＝集團幣別、31＝集團估價……。不指定 CURTP，同一期間就有好幾個價格，程式「讀第一筆」拿到哪一個幣別，取決於資料庫回傳順序。這跟 Casper 在成本評價專案遇到的 H／E 問題是同一類：資料裡同時存在兩種角度的值，程式沒有明確指定、也沒有排序，結果就不穩定。

13. 帳齡區間計算：到期日、天數與分段

帳齡計算分三步，原程式分散在 FICN_DUE_CALCULATION、FICN_GET_FAEDE、FICN_PUT_AGING：

  1. 決定到期日：把行項目的基準日 ZFBDT、付款條件天數 ZBD1T／ZBD2T／ZBD3T、借貸別放進結構 FAEDE，呼叫 DETERMINE_DUE_DATE 得到淨到期日 NETDT。貸項若有參照發票（REBZG），要沿用原發票的付款條件（Note 1758888、2761822 修的就是這件事）。
  2. 算逾期天數：天數＝關鍵日－淨到期日（勾選 P_FBLDT 時改用基準日）。負數表示還沒到期。
  3. 分段：舊版用一長串 IF … ELSEIF 比較 8 個邊界，還要處理「某個邊界沒填」的各種組合；新版把邊界放進內表 GT_PDATES_NEW，再用動態組欄位名 'GS_OUTPUT-SEGMENT' && lv_index 加 ASSIGN (lv_varname) 寫入。Note 2805460 修的是負天數（未到期）也被分進某一段的錯誤。

    "分段表已依 idx 排好，且連續不重疊，所以恰好命中一段
    LOOP AT mt_bucket INTO DATA(ls_b) WHERE from_day <= iv_days AND to_day >= iv_days.

15. ZFIU040 匯出與 FTP 上傳：密碼處理的資安問題

Z 版本在 END-OF-SELECTION 最後加了一個分支：選「匯出」時，把帳齡結果轉成 Tab 分隔文字，用 FTP 上傳到外部伺服器。流程如下：

  1. 從自建表 ZFIT007 以程式名（SY-CPROG）讀出 FTP 主機、使用者、密碼、目的路徑。
  2. 用 HTTP_SCRAMBLE 搭配一個寫死在程式裡的整數 key，把密碼轉成 FTP_CONNECT 接受的格式。
  3. FTP_CONNECT（經由 RFC 目的地 SAPFTP）→ 視需要 FTP_COMMAND 'set passive on' → FTP_R3_TO_SERVER 以字元模式上傳 → FTP_DISCONNECT → RFC_CONNECTION_CLOSE。
這段設計有嚴重的資安問題，不可照抄：
① 密碼以明文存在自建表：任何有 SE16／SE16N 權限的人都看得到；表的內容還會跟著用戶端複製、系統複製進入測試機。
② HTTP_SCRAMBLE 不是加密：它只是把明文轉成 FTP 函數要的格式，key 又寫死在原始碼裡，任何能看程式的人都能還原。
③ FTP 本身是明文協定：帳號、密碼與應收資料（客戶名稱、金額、信用額度）都以明文在網路上傳送。
④ 錯誤處理不完整：FTP_CONNECT 失敗時沒有檢查 SY-SUBRC 就繼續上傳；RAISING invalid_output_file 寫在 FORM 裡，執行時會變成執行期錯誤。

正確的做法依優先順序：

  1. 不要在 ABAP 裡處理外部系統帳密。改由整合平台（SAP Integration Suite／PI/PO 等）或作業系統層的排程以 SFTP（金鑰驗證）取檔，ABAP 只負責把檔案寫到應用伺服器目錄（邏輯檔名 FILE，寫檔方式見 4-4 章）。
  2. 如果外部系統提供 HTTPS API，就在 SM59 建 Type G／H 目的地，帳密或用戶端憑證放在目的地設定（存在 SAP 安全儲存區，不會出現在 SE16），憑證信任鏈在 STRUST 維護。程式只知道目的地名稱。
  3. 真的只能用 FTP 時，至少把帳密從自建表移除，並限制 RFC 目的地與程式的執行權限；同時把這個風險寫進上線文件，讓資安單位簽核。

原程式的問題與改進

問題說明
ROLLBACK 永遠不會執行失敗分支先 LEAVE LIST-PROCESSING 才 ROLLBACK WORK，後者是死碼；若覆蓋模式已經 DELETE FROM 全表，這時會發生什麼取決於後續是否有隱含 COMMIT——這正是整張對照表被清空的經典事故
POPUP_TO_CONFIRM 參數錯置第二個按鈕的文字「NO」被傳給了 ICON_BUTTON_1（圖示參數），應該是 TEXT_BUTTON_2
沒有任何資料檢核ZIP 前導零、產品組是否存在、重複鍵、欄位超長全部沒檢查；TEXT_CONVERT_XLS_TO_SAP 依欄位位置對應，Excel 多一欄或少一欄就整批錯位
沒有權限檢查與鎖任何能執行程式的人都能清空整張表，與 SM30 同時操作也不會被擋
AT SELECTION-SCREEN 用 STOP檔案路徑空白時 MESSAGE … TYPE 'S' 後 STOP，在選擇畫面事件中不恰當；應直接用 TYPE 'E' 讓使用者修正
訊息與註解複製殘留範本下載的訊息寫「註冊材料批導模板」，註解寫 ZMMU005——從 MM 程式複製過來沒改
Maintain 功能其實不需要程式建一個參數交易碼（SE93，以 SM30 為基礎、預設表名並跳過首畫面）即可，還能掛在使用者選單
先找標準：ZIP 到業務轄區的對應，在 SAP 標準中有幾種做法可評估：客戶主檔的銷售地區（KNVV-BZIRK）搭配業務員夥伴功能、SD 夥伴決定程序，或 S/4HANA 的轄區管理（Territory Management，多見於 SAP Sales Cloud／CRM 整合情境）。自建表可以，但請確定它真的是「標準做不到」才建，並讓它有外鍵與檢查表，不要成為沒人管的平行主資料。
上線注意：① 自建表要設定「交付類別 C（客戶資料）」與表格維護產生器的授權群組；② 對照表是跨用戶端還是用戶端相依要想清楚（本表有 MANDT，是用戶端相依）；③ 第一次上線用覆蓋模式匯入前，先把現有資料下載備份。

練習與自我檢核

  1. ZFIR012 的期初餘額為什麼要同時讀 BSID 與 BSAD？在 S/4HANA 用 ACDOCA 改寫時，只要一個條件就能取代這個做法，是哪個條件？
    參考答案要點：已清項的借貸兩筆會互相抵銷，只讀未清項 BSID 會漏掉「期初之後才清帳」的項目；期初餘額是「所有 BUDAT < 期初日的行項目總和，不論是否已清」。ACDOCA 的條件就是 budat < 期初日（加上 RLDNR = '0L'、KOART = 'D'，並依做法決定是否排除 BSTAT = 'C' 的結轉列）。
  2. ACDOCA 的 HSL 與 BSID 的 DMBTR 在正負號上有什麼差別？原程式的哪些寫法因此可以刪除？
    參考答案要點：HSL 已帶正負號（貸方為負），DMBTR 永遠為正，要看 SHKZG。所有 IF shkzg = 'H' … * -1 的轉換都可以刪除，借方欄＝HSL > 0、貸方欄＝|HSL| 且 HSL < 0。
  3. ZFIR012 把同客戶多個科目用「&」串成一個字串。為什麼這在 HANA 上會造成結果不穩定？
    參考答案要點：串接順序取決於內表順序，而內表順序來自 SELECT 回傳順序；HANA 沒有預設排序，同樣資料每次執行順序可能不同。一定要先明確 ORDER BY／SORT 再串接，或乾脆依科目分列。
  4. ZFIU014N 讀 CKMLCR 取實際價格時漏了哪兩個條件或欄位？各會造成什麼錯？
    參考答案要點：① 沒篩 CURTP（幣別類型），同一期間多種幣別的價格混在一起，讀到哪一筆看資料庫順序（與 H／E 成本角度混用是同一類問題）；② 沒除以 PEINH（價格單位），價格單位不為 1 的物料成本會被放大。另外 FRM_DEAL_DATA2 取「最新一期」沒有限制不晚於過帳期間。
  5. ZFIU014N 讀 ACDOCA 時沒有指定 RLDNR，可能發生什麼事？
    參考答案要點：系統若有平行分類帳（例如 IFRS、稅務帳），同一筆交易會在每個分類帳各出現一次，SUM 後金額會變兩倍或更多。報表一律指定 RLDNR = '0L'（或參數化）。
  6. 毛利公式「收入－折扣－VVACS－VVACT」在什麼前提下才是對的？要怎麼確認？
    參考答案要點：只有 VVACT 代表「實際與標準的差異」時才成立；若 VVACT 是完整實際成本，就重複扣成本。要在 KEA0 查值欄位定義、KE4I 查條件類型對照、KE30 對數，並與 CO 顧問書面確認。
  7. 為什麼毛利報表的科目條件要用 STVARV 多筆 EQ，而不是 BT 區間？
    參考答案要點：區間比的是字典序，新開同字首、用途不同的科目會被自動納入；列舉讓每個科目都經過人確認，新增科目時報表不會悄悄改變口徑。這是 Casper「列舉優於區間」的直接應用。
  8. 請寫出帳齡「逾期天數」的計算方式，並說明勾選「將基準日期用作淨到期日」時有何不同。參照發票的貸項要注意什麼？
    參考答案要點：天數＝關鍵日－淨到期日（DETERMINE_DUE_DATE 或 BSEG-NETDT），負數為未到期；勾選時改用基準日 ZFBDT。參照發票（REBZG 有值、REBZT ≠ 'V'）的貸項要沿用原發票的基準日與付款條件。
  9. 帳齡分段用一張「分段表」定義有什麼好處？建立分段表時要檢查什麼？
    參考答案要點：分段邏輯只寫一次、段數可變、標籤由邊界自動產生不會與判斷不一致；建立時檢查邊界嚴格遞增，確保連續、不重疊、無缺口，並固定一段「未到期」處理負天數。
  10. ZFIU040 的 FTP 上傳有哪些資安問題？請提出兩種較安全的替代方案。
    參考答案要點：密碼明文存在自建表、HTTP_SCRAMBLE 搭配寫死 key 只是混淆不是加密、FTP 明文傳輸、錯誤處理缺失。替代：① ABAP 只寫檔到應用伺服器，由整合平台或 OS 排程以 SFTP 金鑰取檔；② 對方提供 HTTPS API 時，用 SM59 Type G 目的地（帳密／憑證存在安全儲存區、STRUST 管理憑證）加 CL_HTTP_CLIENT=>CREATE_BY_DESTINATION，程式中不出現任何帳密。
  11. 為什麼說複製標準程式 RFIDCN_AR_AGING 是昂貴的客製？如果需求只是「把標準帳齡結果匯出給外部系統」，你會怎麼做？
    參考答案要點：Z 複本收不到 SAP Note 修正，升級後會與標準分岔，還要自己維護 6,000 行。可以用標準報表（S_ALR_87012178、FBL5H、Fiori 帳齡 App），再寫小程式以 SUBMIT 或 CL_SALV_BS_RUNTIME_INFO 取得結果後匯出。
  12. ZFIU011 匯入 Excel 時，ZIP「00501」可能變成什麼？程式要怎麼處理？這跟哪一條實務經驗有關？
    參考答案要點：Excel 會把它當數字存成 501。程式要判斷是純數字且不足 5 碼時補回前導零（|{ lv_zip WIDTH = 5 ALIGN = RIGHT PAD = '0' }|）；產品組也要 ALPHA 轉換。前導零會讓字串比較與區間條件出錯，正是「列舉優於區間」提醒的 ALPHA 前導零問題。
  13. ZFIU011 原程式在匯入失敗時的 ROLLBACK 有什麼問題？正確的寫入順序應該是什麼？
    參考答案要點：ROLLBACK 寫在 LEAVE LIST-PROCESSING 之後，永遠不會執行。正確順序：全部檢核通過 → 權限檢查 → ENQUEUE 鎖表 → DELETE（若覆蓋）＋MODIFY 同一 LUW → 成功 COMMIT、失敗 ROLLBACK → DEQUEUE。
  14. 請列出三張在 S/4HANA 已成為相容性視圖的 FI 表，以及兩項已不再使用的 CO 功能。
    參考答案要點：BSID／BSAD／BSIK／BSAK／BSIS／BSAS、KNC1、LFC1、GLT0（任三）；已不使用：統馭分類帳 COFIT、傳統利潤中心會計 GLPCT／GLPCA、獨立成本要素主檔（KA01，改在 FS00 維護）。
