第 5-17 章 BC440 網際網路應用元件（ITS、WebTransaction、WebRFC）與現代替代

BC440〈Developing Internet Application Components〉是 SAP 在網際網路剛興起時，讓 R/3 走上瀏覽器的第一代技術：用網際網路交易伺服器（ITS）把 Dynpro 畫面轉成 HTML（WebTransaction），或讓函數模組直接吐出 HTML／MIME（WebRFC）。這些技術今天大多已走入歷史：ITS 從 NetWeaver 2004 起整合進 Kernel，成為 Integrated ITS／SAP GUI for HTML，WebRFC 已停止支援。本章照原課程九個單元整理觀念（HTTP 無狀態、同步、服務檔、隱式登入、MIME 物件，這些觀念今天仍然成立），並用大量篇幅對照 S/4HANA 的替代方案：ICF（SICF）HTTP handler、REST／JSON、OData（SEGW、RAP）、Fiori。

2. 單元二：R/3 與 Web 的連接、ITS 與 SAP 的 GUI 策略

為什麼需要 ITS（p9–p10）：R/3 是三層主從式架構（SAP GUI → 應用伺服器 → 資料庫）。課程用兩個問答切入：

  • 使用者沒裝 SAP GUI 又要用 R/3，最簡單的方法？用瀏覽器，作業系統都內建。
  • 瀏覽器要怎麼拿到 R/3 的資料？加一台轉換伺服器，把 R/3 資料轉成 HTML，或把 HTML 輸入轉回 R/3 看得懂的格式。

接著要處理兩件事：① R/3 與 Web 的連接（資料怎麼出去、怎麼進來）；② 業務邏輯仍留在 R/3 處理。又因為當年網頁的互動能力遠弱於 SAP GUI，必須設計新的處理模式──商業物件與 BAPI（見 4-1 章、5-12 章）。

ITS 擴充三層架構（p11–p12）：ITS 把 R/3 延伸到網際網路上，可視為一個「特殊的 SAP GUI」，能與傳統 GUI 同時運作。瀏覽器只要支援 HTML 3.2 以上即可，不需要 Java Applet 或 ActiveX；但互動式 Web 報表當年必須用 IE 4.0 以上。構成元件：

  • Web 伺服器：如微軟 IIS，須提供應用程式介面與 ITS 連接（IIS 為 ISAPI）。
  • ITS：一般裝在 Windows 伺服器，負責把 R/3 資料轉成 HTML。
  • R/3 應用伺服器：3.0G 以上，安裝 IAC。

IAC 與 SAP 的 HTML GUI（p13–p15）：SAP 的 GUI 分三類──Windows GUI、Java GUI、HTML 瀏覽器。瀏覽器的用法又分三種：

方式組成特性
直接轉成 HTML 的功能標準交易自動轉換與 GUI 功能最一致，但因 Web 原則與 GUI 不同，當年這類功能會越來越少（今天的 SAP GUI for HTML 反而是主流）
WebTransaction（IAC）標準 R/3 交易＋服務檔＋HTMLBusiness 範本；每個畫面對應一個範本部分實現 R/3 標準功能；交易須依規範特別開發
WebRFC（IAC）支援 RFC 的函數模組＋WebRFC 範本（都在應用伺服器）＋WebRFC 閘道（在 ITS）ITS 把參數表傳給函數模組，收回已產生好的 HTML 頁或 MIME 物件（文字、圖片、PDF…）

ITS 與 mySAP.com（p16–p17）：mySAP.com 是入口網站（Portal）概念普及之前 SAP 的企業入口品牌，分內部的 Workplace（給員工）與外部的 Marketplace（給客戶；SAP 至今仍把 service.sap.com 稱為 Service Marketplace）。Workplace 架構是：瀏覽器 → HTTP 伺服器 → Workplace 伺服器（單一登入 SSO）→ ITS → 後端 R/3。除了瀏覽器，也可用 Java GUI、Windows 終端服務、Windows GUI 存取。

S/4HANA 現況：Workplace → SAP Enterprise Portal → 今天的 SAP Fiori Launchpad（on-premise）或 SAP Build Work Zone（雲端）。Service Marketplace 已併入 SAP for Me／SAP Support Portal。ITS 從 NetWeaver 2004（6.40）起整合進 ABAP Kernel（Integrated ITS），不再需要另外安裝 WGate／AGate；Fiori Launchpad 可用「Transaction」類磁磚透過 SAP GUI for HTML 開啟傳統交易。

3. 單元三：網際網路、HTTP 與安全基礎（附 ICF 對照）

這個單元是純網路觀念，今天寫 REST／OData 一樣用得到。重點整理：

  • 網際網路（p19）：由政府、研究機構、公司等共同營運的網路之網路。IETF 制訂通訊協定，標準以 RFC（Requests for Comments）發布──注意，這個 RFC 不是 SAP 的 Remote Function Call。
  • TCP/IP（p20）：TCP（RFC 793）負責分段、封包、可靠傳輸、連線與斷線；IP（RFC 791）負責定址與路由。强晟的比喻：IP 是都市計畫、IP 位址是門牌，TCP 是公車系統。
  • 路由器與 DNS（p21）：路由器連接兩個獨立的 IP 網路（像十字路口）；DNS 把好記的網域名稱轉成 IP 位址。
  • 服務與埠（p22–p23）：郵件（RFC 821）、新聞（RFC 977）、WWW（RFC 2068）、FTP（RFC 959）、Telnet（RFC 854）；標準埠號當年定義在 RFC 1060。一個 IP＋TCP 埠到另一個 IP＋TCP 埠的連線稱為 Socket。
  • URL（p24）：protocol://host:port/pathname，四部分為協定、主機、埠（預設可省略）、路徑。
  • HTTP（p26–p27）：WWW 的應用協定，基於 TCP/IP，無狀態（stateless）──一次請求／回應結束，伺服器就釋放用戶端資訊。方法：GET（取資料）、POST（送表單）、PUT（送物件）、DELETE（刪物件）、HEAD（只要標頭）。狀態碼：1xx 資訊、2xx 成功、3xx 重導、4xx 用戶端錯誤、5xx 伺服器錯誤。
  • 快取（p28）：伺服器端快取／Proxy 可多層；快取會向伺服器驗證狀態，瀏覽器緩衝區則不驗證伺服器檔案是否已變。
  • Cookie（p29）：伺服器附在回應中、最大 4KB、瀏覽器下次請求會帶回；長度不夠就用 Session ID 當鍵值，把狀態存在伺服器端。
  • 安全要點（p30）：存取控制、機密性、認證、完整性、收發雙方核對；防火墙是一種依 IP／埠／服務／內容過濾的特殊路由器。
  • 加密（p31–p32）：對稱加密（DES 56-bit，快、金鑰須安全傳遞）、非對稱加密（RSA，慢，可做機密性、認證、完整性）；SSL 介於應用協定與 TCP/IP 之間，HTTPS＝HTTP over SSL，埠 443。
  • 內部網路與 Proxy（p33–p34）：Intranet 與 Internet 技術完全相同，私有位址段如 192.168.x.x；Proxy 維護內外埠的對應表，通常也帶 HTTP 快取。
教材需要更正的地方：
  • p31 寫「非對稱加密：私鑰用於加密，公鑰用於解密」只對數位簽章成立；若目的是機密性，是用對方的公鑰加密、私鑰解密。
  • DES 56-bit 早已不安全，今天用 AES；SSL 各版本也已全數淘汰，現在一律是 TLS 1.2／1.3（習慣上仍叫 SSL）。SAP 端的憑證在 STRUST 維護。
  • HTTP/1.1 的 RFC 2068 已被 RFC 2616、RFC 7230~7235、再被現行的 RFC 9110／9112 取代；埠號登錄也改由 IANA 維護，不再是 RFC 1060。

在 S/4HANA 裡，HTTP 請求由 ICM 接收，交給 ICF（Internet Communication Framework）依 URL 路徑找到 SICF 中的服務節點，再呼叫該節點的 HTTP handler 類別（實作 IF_HTTP_EXTENSION）。上面所有的 HTTP 觀念──方法、標頭、狀態碼、Cookie、無狀態／有狀態──都能在 handler 裡直接操作：

*&-------------------------------------------------------------*
*& ICF handler：把單元三的 HTTP 觀念對應到 ABAP 物件
*&  SICF 建節點 /sap/bc/zbc440/echo，Handler List 填本類別
*&-------------------------------------------------------------*
CLASS zcl_bc440_http_echo DEFINITION PUBLIC FINAL CREATE PUBLIC.
  PUBLIC SECTION.
    INTERFACES if_http_extension.
ENDCLASS.

CLASS zcl_bc440_http_echo IMPLEMENTATION.
  METHOD if_http_extension~handle_request.
    " 1. HTTP 方法（GET/POST/PUT/DELETE/HEAD）放在偽標頭 ~request_method
    DATA(lv_method) = server->request->get_header_field(
                        if_http_header_fields_sap=>request_method ).
    " 2. 一般標頭與 URL 路徑
    DATA(lv_agent) = server->request->get_header_field( 'user-agent' ).
    DATA(lv_path)  = server->request->get_header_field(
                        if_http_header_fields_sap=>path_info ).
    " 3. Cookie：讀取與設定（對應 p29 的 Session ID 觀念）
    server->request->get_cookie( EXPORTING name  = 'ZBC440_VISIT'
                                 IMPORTING value = DATA(lv_visit) ).
    DATA(lv_count) = COND i( WHEN lv_visit CO '0123456789 ' AND lv_visit IS NOT INITIAL
                             THEN CONV i( lv_visit ) + 1
                             ELSE 1 ).
    server->response->set_cookie( name  = 'ZBC440_VISIT'
                                  value = |{ lv_count }|
                                  path  = '/sap/bc/zbc440' ).
    " 4. HTTP 預設無狀態；非必要不要改成 stateful（會占住 session 記憶體）
    " server->set_session_stateful( stateful = if_http_server=>co_enabled ).

    " 5. 回應：狀態碼 + Content-Type + 本文
    CASE lv_method.
      WHEN 'GET' OR 'HEAD'.
        server->response->set_status( code = 200 reason = 'OK' ).
        server->response->set_content_type( 'text/plain; charset=utf-8' ).
        IF lv_method = 'GET'.
          server->response->set_cdata(
            |method={ lv_method }\npath={ lv_path }\nagent={ lv_agent }\nvisit={ lv_count }| ).
        ENDIF.
      WHEN OTHERS.
        server->response->set_status( code = 405 reason = 'Method Not Allowed' ).
        server->response->set_header_field( name = 'Allow' value = 'GET, HEAD' ).
    ENDCASE.
  ENDMETHOD.
ENDCLASS.
ICF 服務建好後一定要在 SICF 按右鍵 Activate Service，否則會回 403／404。「服務沒啟用」是 Fiori、OData、WEBGUI 上線第一天最常見的錯誤，傳輸到 QAS／PRD 後也要再確認一次（ICF 節點的啟用狀態不一定隨傳輸帶過去）。

4. 單元四：HTML、表單與 CGI（附 ABAP 產生安全 HTML）

原課程用一整個單元教 HTML（p35–p55），重點如下：

  • HTML 特性：描述頁面的邏輯結構而非外觀、平台無關、是 SGML 的一種實作、1990 年起用於 WWW；標準由 W3C 與 IETF 制訂。當時最新是 HTML 3.2（1997/2）與 HTML 4.0（1998/4）。
  • 標籤規則：成對的 <tag>…</tag>、可帶參數、瀏覽器忽略看不懂的標籤、大小寫無關；連續空白視為一個、換行被忽略；註解 <!-- -->。<head> 放 title／meta／base，<body> 放顯示內容。
  • CSS（p41）：「層疊」的意思是同一樣式可在外部檔、文件內、標籤上多處定義，最接近元素者優先。
  • 圖片（p42–p43）：src、alt、width、height；縮小顯示並不會減少下載量；一個含 n 張圖的頁面會產生 n＋1 個 HTTP 請求。
  • 超連結（p44）：可能變成「死連結」；錨點用 <a href="page.html#pos">。
  • 表格（p45）：table／tr／th／td，border、width、align、valign、colspan。
  • 分框（p46–p47）：frameset 的 rows／cols（百分比、像素、相對比例 *）；連結的 target 可為 _top、_parent、_self（預設）、_blank 或框架名稱。
  • CGI（p48）：NCSA 定義（1.1 版），HTTP 伺服器與 CGI 程式必須在同一台機器（靠環境變數傳參數）；廠商另有更有效率的 ISAPI（IIS）與 NSAPI（Netscape）。
  • 表單（p49–p53）：<form action method target>；元素必須有 name 才會被送出；表單不能巢狀。文字框的 maxlength（一個中文字算 1）、password（只是顯示成 *，傳輸時是明文）、hidden、submit（一個表單可有多個送出鈕，程式靠按鈕名稱區分動作）、image、radio（以 name 分組）、select、checkbox（沒勾就完全不送，所以要搭一個同名 hidden 欄位）。
  • GET 與 POST（p54）：GET 把資料附在 URL 後、是預設方法、直接點連結一定是 GET；POST 把資料放在請求本文，不會被快取。
  • HTTP 無狀態的三種解法（p55）：隱藏欄位、把狀態附在 URL（$PATH_INFO）、Cookie（$HTTP_COOKIE）。
筆記中的 HTML 錯字與過時寫法：圖片標籤是 <img> 不是 <image>；下拉選項是 <option> 不是 <options>；<intpu> 應為 <input>；scr="main.html" 應為 src、</framset> 應為 </frameset>；$HTTTP_COOKIE 多了一個 T。另外 <font>、<frameset> 在 HTML5 已廢止；「GET 最多 4KB」是當年瀏覽器／伺服器的實作限制，並非 HTTP 規範。

今天在 ABAP 裡產生 HTML（例如 ICF handler 回一個簡單的查詢頁、或寄 HTML 郵件，見 4-4 章），重點只有一個：所有使用者輸入都要經過 HTML escape，否則就是 XSS 漏洞。下面把 p49–p55 的表單、GET/POST、hidden 欄位觀念用現代 ABAP 實作：

5. 單元五（一）：ITS 架構──五層、WGate／AGate 與安裝方式

五層主從式架構（p57）：Web 瀏覽器 → HTTP 伺服器 → ITS → R/3 應用伺服器 → R/3 資料庫伺服器。對 R/3 而言，HTTP 伺服器＋ITS 構成了應用層與展示層之間的介面；一個 ITS 可連多個 HTTP 伺服器與多個 R/3 應用伺服器。ITS 的工作：使用者登入管理、把 R/3 畫面資料轉成 HTML、狀態管理、與 R/3 同步。

元件負責連線協定
WGate（W＝Web）與 HTTP 伺服器溝通CGI、ISAPI（IIS）或 NSAPI（Netscape），依 HTTP 伺服器種類選擇
AGate（A＝Application）與 R/3 應用伺服器溝通；存放服務檔、範本DIAG（Dynamic Information and Action Gateway，SAP GUI 專用協定，WebTransaction 用）或 RFC（WebRFC 用）
WGate ↔ AGate兩者可裝在不同主機HTTP（可再加 SNC 加密）

應用伺服器可呼叫函數模組 ITS_PING 判斷請求來自 SAP GUI 還是 ITS（第 12 節會用到）。

安裝方式（p59）：

  • 單主機：ITS 與 HTTP 伺服器裝在同一台 Windows，安全性較差，多用於測試。
  • 雙主機：AGate 一台 Windows；WGate＋HTTP 伺服器另一台 Windows 或 UNIX（AIX），是常規做法。
  • 單一虛擬 ITS 對多 HTTP 伺服器：一台 Windows 裝多個 ITS 實例，分別對應多台 HTTP 伺服器，節省 ITS 主機。
  • 虛擬單主機：一台伺服器裝多套單主機實例。
S/4HANA 現況：Integrated ITS。從 NetWeaver 2004（SAP_BASIS 6.40）起，ITS 被整合進 ABAP Kernel，WGate／AGate、IIS、獨立 Windows 伺服器全部不需要了：HTTP 由 ICM 接收，ITS 在應用伺服器的工作處理程序中直接把 Dynpro 轉成 HTML。常用 ICF 服務：
  • /sap/bc/gui/sap/its/webgui：SAP GUI for HTML（WEBGUI），任何交易都能在瀏覽器執行，URL 可加 ?~transaction=VA03。
  • Internet Service 物件在 SE80（或 SIAC1）維護；啟用 ITS 相關服務後，需執行程式 SIAC_PUBLISH_ALL_INTERNAL 把 ITS 標準範本與 MIME 發佈到內部 ITS。
獨立安裝的 ITS 6.20 已結束維護。舊系統若還有獨立 ITS，升級 S/4HANA 時必須改用 Integrated ITS 或改寫為 Fiori／Web Dynpro。

6. 單元五（二）：服務檔（.srvc）與登入方式

服務（Service）（p60）：ITS 以 URL 定位服務，格式為 http://<server>/<path>/wgate/<service>/! 或 …/wgate?~service=<service>；客製服務以 Z 開頭。服務負責：登入 R/3、執行交易碼／函數模組／報表、把畫面或清單轉成 HTML。服務啟動時在應用伺服器建立 SAP GUI 或 RFC 會話，ITS 負責把 HTTP 請求對應到正確的會話；服務結束（登出或逾時）會話就結束。

SAP@Web Studio（p61–p62）：維護 WebTransaction 元件（服務檔、HTMLBusiness 範本、MIME 物件、語言相關的預留位置檔）的 Windows 工具，以「專案」組織，有精靈；物件可經 Workbench Organizer 與傳輸系統在系統間傳遞。站台定義精靈步驟：命名 → 指定 WGate 主機 → 指定 AGate 主機 → 虛擬 ITS 名稱 → HTTP 伺服器 URL 與埠。發佈（Publish）＝把 MIME 物件複製到 HTTP 伺服器、把服務／範本／文字檔匯入 ITS。

服務檔（p63）：放在 AGate 主機上的純文字檔，每行「參數 空白或 Tab 值」。啟動服務 <service> 時先讀 Global.srvc，再讀 <service>.srvc，重複的參數由後者覆蓋。參數分四類：

7. 單元五（三）：網際網路使用者（Internet User）

概念（p69、p92）：WebTransaction 的網際網路使用者（例如 B2C 的客戶）不需要 R/3 帳號；ITS 先用一個共用帳號（隱式登入）登入，再用另一頁確認網際網路使用者的身分。

  • 以 SFLIGHT 模型為例：客戶主資料在 SCUSTOMER，網際網路使用者的登入資料在 BAPIUSW01。
  • 客戶、供應商等不同商業物件各有主檔，但登入資料都對應到 BAPIUSW01。
  • 建立網際網路使用者時不會檢查他是否存在於主檔中；執行時只檢查：① 是否存在於 BAPIUSW01；② 密碼是否正確。
  • 檢查密碼的標準 BAPI 命名規則：BAPI_<Business Object>_CHECKPASSWORD。
  • 可用專用交易碼（SU05 維護網際網路使用者）新增、刪除、改名、鎖定／解鎖、初始化密碼、修改密碼。
當年S/4HANA 做法
BAPIUSW01＋共用 R/3 帳號外部系統整合：SU01 的 Communication 使用者（類型 B）或 Service 使用者，搭配最小權限角色；雲端版用 Communication Arrangement／Communication User
B2C 客戶自助SAP Commerce Cloud、SAP Build Apps 等前台＋SAP Cloud Identity Services（IAS）做身分驗證，後端透過 OData／API 存取 S/4HANA，而不是讓外部使用者直接登入 ERP
密碼 BAPI 自行驗證交給身分提供者（IdP）做 SAML／OAuth；ABAP 只看已驗證的使用者與角色
共用帳號的隱式登入等於「誰都用同一個人登入 ERP」，稽核軌跡（建立者、修改者）全部變成同一個帳號。現代專案若真要做匿名服務，請把邏輯限縮在唯讀查詢，寫入動作一律要求具名驗證。

8. 單元六（一）：WebTransaction 程式設計模型與 BAPI

交易屬性（p72）：WebTransaction 讓完全未受 SAP 訓練的網路使用者也能使用部分 R/3 功能，可用多媒體輔助理解。至少包含 R/3 交易、服務檔、HTMLBusiness 範本。其中 R/3 交易的限制：

  • 只能用「簡單畫面」：只含標準 SAP 元素、不含 EnjoySAP 控制項（ALV Grid、Tree、TextEdit 等 Control Framework 元件，見 5-10 章），才能轉成 HTML。
  • 必須允許透過 ITS 同步（第 11 節）。
  • 輸入說明（F4）必須用特殊技術提供（第 12 節的上下文巨集）。
  • 業務邏輯用 BAPI 快速組成。

BAPI 的三個要點（p73，詳見 BC417／5-12 章）：① BAPI 就是允許 RFC 的函數模組，用 CALL FUNCTION 呼叫；② 因為非 SAP 系統也能呼叫，不能用 ABAP 例外機制，改用 RETURN 參數回傳訊息；③ BAPI 一般同步呼叫，透過更新任務改資料庫，BAPI 內部不可有 COMMIT WORK，由呼叫端決定提交。

設計流程（p74）：① 需求：業務是否真的要上網 → ② 任務流程 → ③ 搜尋 BAPI（BAPI 交易）→ ④ 建 R/3 交易（程式＋TCODE，只呼叫 BAPI）→ ⑤ 在 SAP@Web Studio 建 HTMLBusiness 範本、美化、多語。

「UI 只負責畫面、業務邏輯全部走 BAPI」這個分層原則在今天完全沒變，只是 BAPI 換成了 RAP 的 Behavior（或仍用 BAPI 包在 OData 後面）。這正是 Casper 的第三條經驗──先找標準：訂單、預訂、主資料的建立幾乎都有標準 BAPI 或標準 API（SAP Business Accelerator Hub），不要自己寫 INSERT。

課程情境「預訂航班」的業務邏輯，用現代寫法包成一個可被 Web handler、OData 或 Dynpro 共用的類別：

9. 單元六（二）：服務與範本──HTMLBusiness 語法

服務描述（p75）：服務檔裡的屬性條目又稱服務描述；服務精靈只需建立 Global.srvc 裡沒有的屬性；發佈時把服務檔複製到 AGate。

HTMLBusiness（p76–p77）：語法類似 C，嵌在標準 HTML 中（很像 ASP），用反引號 `（鍵盤 Esc 下方那一個）包起來，因為它在 HTML 中沒有特殊意義；SAP@Web Studio 以藍色顯示。最簡單的用法就是在範本中寫與畫面欄位同名的變數；可用的畫面欄位屬性：

.label欄位標籤.maxSize最多可輸入字元數

.exists欄位顯示或被停用

  • 範本精靈（p79）：依 R/3 畫面自動產生範本，自動建立 form 並把輸入／輸出欄位與標籤轉成 input；依 ~theme 與 ~language 管理；範本在 R/3 產生，所以 SAP@Web Studio 需要 RFC 連線到 R/3。
  • 檔案階層（p80）：AGate 下 GLOBAL.srvc、BC440.srvc（BC440_100.html、BC440_200.html）、ZWTEST.srvc（ZWTEST_101.html…）。
  • 發佈、建置、執行（p81）：Publish＝複製檔案；Build＝語法檢查＋存檔＋複製；Go＝Build 後在瀏覽器啟動服務（强晟註：Build／Go 是借用 Turbo C 的詞彙）。
  • 表單輸入（p82）：技術上 ITS 就是一個接收 HTML 輸入的 CGI 程式，把查詢字串的值填入同名畫面欄位；form 的 action 用 wgateURL() 產生；服務參數 ~submitChecking=1 時找不到同名欄位會報錯。

HTMLBusiness 函數與運算子（p103–p106）：

10. 單元六（三）：傳輸、主題與語言、步進迴圈、MIME 物件

與 Workbench Organizer 的連接（p93–p94）：標準三系統 DEV（開發）→ QAS（整合測試）→ PRD（生產），每個系統各有自己的 ITS。R/3 與 ITS 之間的傳輸一律經由 SAP@Web Studio，有四種動作：

動作說明
增加（Add）在 R/3 建立物件（每個物件只做一次）
取得（Get）從 R/3 讀取物件，不修改
簽出（Check out）鎖定並讀取 R/3 中的物件
簽入（Check in）把修改寫回 R/3 並解鎖

專案物件和相關 ABAP 程式一起傳輸；到了 QAS／PRD 再用「發佈」把物件載入 WGate 與 AGate。今天 Internet Service、ICF 節點、MIME Repository 物件都是一般的 Repository 物件，走標準傳輸請求即可（見 1-1 章）。

主題（Theme）（p95–p96）：同一套業務邏輯的不同版面（就像 BC425 的畫面變式與 GuiXT，見 5-14 章）；由範本決定、服務啟動時載入、執行中不可更換。~theme 的選擇順序：URL → <service>.srvc → Global.srvc，都沒有就不用主題；URL 指定 ~theme="" 表示強制不用主題。

語言相依（p97–p100）：

  • 參照資料字典的物件自動以登入語言顯示，不需額外設定；~windowTitle（等同 SET TITLEBAR）、~messageLine 也跟登入語言。
  • 非字典文字用語言預留位置檔 <service>_<langu>.htrc，範本中以 `#<PlaceHolder>` 引用；或直接做語言專屬範本 <service>_<dynnr>_<langu>.html；也可用 `#<filename>` 引入語言相依文字檔（不能與預留位置同時用）。
  • 登入語言 ~language 與範本語言 ~templateLanguage 可以不同；選擇順序同樣是 URL → 服務檔 → 全域檔；~templateLanguage 空白則用登入語言。

11. 單元六（四）：瀏覽器與 R/3 的同步（上一頁問題）

14. 單元七（一）：WebRFC──函數模組直接輸出 HTML

WebRFC 是什麼（p120–p121）：基於 ITS 與 R/3 之間的 RFC 連線，ITS 把參數表傳給 R/3 上特殊的 RFC 函數模組，並從回應接收 HTML 頁或 MIME 物件表。支援 WebRFC 的函數模組可以：產生 HTML 或 MIME、讀寫資料庫表、把商業物件當交易使用、在多次連續 WebRFC 呼叫中使用交易、在 R/3 中提供簡單的範本概念。

*"--------------------------------------------------------------
*"  TABLES   QUERY_STRING STRUCTURE W3QUERY
*"           HTML         STRUCTURE W3HTML
*"           MIME         STRUCTURE W3MIME
*"  CHANGING VALUE(CONTENT_TYPE)   LIKE W3PARAM-CONT_TYPE
*"           VALUE(CONTENT_LENGTH) LIKE W3PARAM-CONT_LEN

  DATA(ls_key) = VALUE wwwdatatab(
                   relid = 'MI'
                   objid = to_upper( server->request->get_form_field( 'id' ) ) ).

  " 白名單：只允許 ZBC440_ 開頭，避免任意讀取 WWWDATA 其他物件

    server->response->set_status( code = 403 reason = 'Forbidden' ).
    RETURN.
  ENDIF.

  " 讀 WWWPARAMS 的 mimetype / filesize（一次讀兩筆，用列舉 IN 而非區間）
  SELECT name, value
    FROM wwwparams
    WHERE relid = @ls_key-relid
      AND objid = @ls_key-objid
      AND name  IN ( 'mimetype', 'filesize' )
    INTO TABLE @DATA(lt_param).
  IF sy-subrc <> 0.
    server->response->set_status( code = 404 reason = 'Not Found' ).
    RETURN.
  ENDIF.

    EXPORTING
      key               = ls_key
    TABLES
      mime              = lt_mime
    EXCEPTIONS
      wrong_object_type = 1
      import_error      = 2
      OTHERS            = 3.
  IF sy-subrc <> 0.
    server->response->set_status( code = 500 reason = 'Import Error' ).
    RETURN.
  ENDIF.

  DATA(lv_size) = 0.
  DATA(lv_type) = `application/octet-stream`.
  LOOP AT lt_param INTO DATA(ls_param).
    CASE ls_param-name.
      WHEN 'filesize'. lv_size = condense( ls_param-value ).
      WHEN 'mimetype'. lv_type = to_lower( condense( ls_param-value ) ).
    ENDCASE.
  ENDLOOP.

  DATA lv_xstr TYPE xstring.
  CALL FUNCTION 'SCMS_BINARY_TO_XSTRING'
    EXPORTING
      input_length = lv_size
    IMPORTING
      buffer       = lv_xstr
    TABLES
      binary_tab   = lt_mime.

  server->response->set_content_type( lv_type ).
  server->response->set_header_field( name  = 'Cache-Control'
                                      value = 'max-age=86400' ).   "單元三的快取觀念
  server->response->set_data( lv_xstr ).
ENDMETHOD.
WebRFC 的 S/4HANA 現況：WebRFC 依賴獨立 ITS 的 RFC 閘道（sapxgwfc），Integrated ITS 不再提供此功能，WebRFC 已停用；SURL 裡的函數在新系統中可能仍存在（向下相容），但不應再用於新開發。替代方案依需求選擇：直接回檔案或簡單頁面 → ICF handler；給程式呼叫的資料介面 → REST（ICF）或 OData；給人用的畫面 → Fiori。

16. 單元八：ITS 管理──可擴充性、安全、安裝、日誌與管理工具

可擴充性（p142–p143）：外部看，多瀏覽器可用多台 HTTP 伺服器；每個 WGate 只對應一台 HTTP 伺服器與一個 AGate；一個 AGate 可被多個 WGate 使用並連多台 R/3 應用伺服器。內部看，WGate 啟動服務時會啟動 AGate 上的對映管理器（Mapping Manager），之後會話步驟與 AGate 實例溝通；AGate 也有分派器、工作執行緒、會話記憶體等與 R/3 類似的結構，可調整登錄機碼 …\ITS\2.0\<virtual ITS>\Programs\AGate 下的 MaxWorkThreads、MaxSessions。

18. 單元九延伸（二）：用 ICF 寫 REST API（JSON 進出）

把課程情境「顯示航班連線、預訂航班」做成 REST API：GET 查詢、POST 建立預訂。步驟 （依 SAP 標準步驟整理）：

  1. SE24／ADT 建類別，實作 IF_HTTP_EXTENSION。
  2. SICF 在 default_host/sap/bc/ 下建子節點（例如 zbc440_api），Handler List 填類別名；Logon Data 視需求設定；存檔後 Activate Service。

  METHOD if_http_extension~handle_request.
    DATA(lv_method) = server->request->get_header_field(
                        if_http_header_fields_sap=>request_method ).
    CASE lv_method.
      WHEN 'GET'.
        " 多值條件用列舉：?carrid=LH,AA,UA → 轉成 EQ 列舉的 RANGE，而不是 BT 區間

          FROM spfli

          INTO TABLE @DATA(lt_conn)

          EXPORTING json        = server->request->get_cdata( )
                    pretty_name = /ui2/cl_json=>pretty_mode-camel_case
          CHANGING  data        = ls_req ).

自寫 REST handler 的坑：
  • ICF 對 POST／PUT／DELETE 不會自動做 CSRF 防護（OData 服務會）；若給瀏覽器呼叫，要自行實作 X-CSRF-Token 或只開放給系統帳號。
  • 日期、金額的 JSON 格式要自己約定（/UI2/CL_JSON 對 DATS／TIMS 的輸出格式依版本與參數而異，上線前請實測並寫進介面規格）；金額要搭配幣別，不要只傳數字。
  • set_status 的 reason 留空時由 ICM 補標準文字即可；錯誤回應也要回 JSON，不要回 HTML 錯誤頁，呼叫端才解析得了。
  • JSON 處理除了 /UI2/CL_JSON，也可用 kernel 內建的 CALL TRANSFORMATION id 搭配 cl_sxml_string_writer=>create( type = if_sxml=>co_xt_json )（asJSON 格式）；較新版本（ABAP Cloud／S/4HANA 2021 以後）另有 XCO 的 xco_cp_json，使用前請確認系統版本已提供。

20. 單元九延伸（四）：OData 與 Fiori──SEGW 與 RAP

OData 是 SAP 在 HTTP 之上的標準資料協定：URL 就是查詢（$filter、$orderby、$top、$skip、$expand），有中繼資料（$metadata）、CSRF、ETag、批次（$batch），Fiori 前端直接吃。S/4HANA 1809 有兩條路：

方式開發註冊／測試適用
SEGW（Gateway Service Builder）建專案 → 資料模型（Entity Type／Set）→ Generate Runtime Objects → 在 *_DPC_EXT 重新定義 GET_ENTITYSET／GET_ENTITY／CREATE_ENTITY…/IWFND/MAINT_SERVICE 註冊；/IWFND/GW_CLIENT 測試1809 的主流；複雜邏輯、既有 BAPI 包裝
CDS＋@OData.publish: trueCDS View 加註記，自動產生 OData V2（SADL）同上唯讀查詢、報表型 Fiori Elements（1809 可用，後續版本改建議 RAP）
RAPCDS View Entity＋Behavior Definition／Implementation＋Service Definition＋Service Binding（ADT）Service Binding 上直接 Publish／PreviewS/4HANA 1909 起逐步提供、2020 起完整（DEFINE VIEW ENTITY 需 ABAP 7.55／S/4HANA 2020）；新開發首選

SEGW 的 GET_ENTITYSET：把 OData 的 $filter 轉成 RANGE、排序、分頁，並把 Casper 的第一條經驗寫進去──$top／$skip 分頁若沒有穩定排序，HANA 上翻頁會重複或漏資料：

*& ZCL_ZBC440_FLIGHT_DPC_EXT → 重新定義 FLIGHTSET_GET_ENTITYSET
*&   GET /sap/opu/odata/sap/ZBC440_FLIGHT_SRV/FlightSet?$filter=Carrid eq 'LH'&$top=20
*&-------------------------------------------------------------*
METHOD flightset_get_entityset.
  " 1. $filter → select-options（屬性名用 ABAP 欄位名）
  DATA(lt_filter) = io_tech_request_context->get_filter( )->get_filter_select_options( ).
  DATA lt_r_carrid TYPE RANGE OF s_carr_id.
  DATA lt_r_connid TYPE RANGE OF s_conn_id.
  LOOP AT lt_filter INTO DATA(ls_filter).
    CASE ls_filter-property.
      WHEN 'CARRID'. lt_r_carrid = CORRESPONDING #( ls_filter-select_options ).
      WHEN 'CONNID'. lt_r_connid = CORRESPONDING #( ls_filter-select_options ).
    ENDCASE.
  ENDLOOP.

  " 2. 查詢：一定要有穩定的 ORDER BY（主鍵），分頁才可靠
  SELECT carrid, connid, fldate, price, currency, seatsmax, seatsocc
    FROM sflight
    WHERE carrid IN @lt_r_carrid
      AND connid IN @lt_r_connid
    ORDER BY carrid, connid, fldate
    INTO CORRESPONDING FIELDS OF TABLE @et_entityset.

  " 3. $inlinecount 與 $top / $skip
  IF io_tech_request_context->has_inlinecount( ) = abap_true.
    es_response_context-inlinecount = lines( et_entityset ).
  ENDIF.
  /iwbep/cl_mgw_data_util=>paging( EXPORTING is_paging = is_paging
                                   CHANGING  ct_data   = et_entityset ).
ENDMETHOD.
大量資料時，應把 $top／$skip 直接轉成 SQL 的 UP TO n ROWS OFFSET m（7.51+），在資料庫端分頁，而不是先全部讀進記憶體再用 paging 裁切；但同樣必須先有 ORDER BY。Fiori 前端做「多選篩選」時，產生的是多個 eq 條件的 OR，這正好符合 Casper 第二條經驗「列舉比區間安全」──設計 API 參數時不要讓呼叫端傳號碼區間。

練習與自我檢核

  1. ITS 的五層架構是哪五層？WGate 與 AGate 各負責什麼、用什麼協定連線？
    參考答案要點：瀏覽器 → HTTP 伺服器 → ITS → R/3 應用伺服器 → 資料庫。WGate 對 HTTP 伺服器（CGI／ISAPI／NSAPI）；AGate 對應用伺服器（WebTransaction 用 DIAG、WebRFC 用 RFC）；WGate↔AGate 用 HTTP，可 SNC 加密。今天 ITS 已整合進 Kernel，由 ICM／ICF 取代 WGate＋IIS。
  2. Global.srvc 與 <service>.srvc 的讀取順序？何謂隱式登入與顯式登入？現代 SICF 的對應是什麼？
    要點：先 Global 再個別服務檔，後者覆蓋；~client／~login／~password／~language 全填＝隱式（共用帳號），有缺＝顯式（ITS 產生登入頁）。SICF 對應為服務節點的 Logon Data（匿名服務）與標準登入程序；匿名帳號用 Service 型使用者、最小權限。
  3. 為什麼 WebTransaction 只能用「簡單畫面」？BAPI 為什麼不能用例外、不能 COMMIT？
    要點：EnjoySAP 控制項（Control Framework）無法轉成 HTML；BAPI 可被非 SAP 系統呼叫，所以用 RETURN（BAPIRET2）回報；提交權在呼叫端，以 BAPI_TRANSACTION_COMMIT（WAIT）控制 LUW。
  4. 使用者按瀏覽器「上一頁」會發生什麼事？~SyncBehaviour 兩種值的差別？AWSY 功能碼要怎麼處理？
    要點：瀏覽器與 R/3 畫面狀態不一致，送出的資料被忽略。NoResync 只顯示禁止訊息；Resync 由 ITS 送 AWSY<prog><dynnr>，交易在 PAI 呼叫 ITS_GET_SYNC_INFO 取 SITSSYNC（SUBSC='MAIN'）並回捲到該畫面；分框用 AWSS／AWSY。現代 REST 無狀態，改用 ETag 樂觀鎖。
  5. field-set、field-transport、field-get 哪一個會立即觸發 RFC？為什麼 field-transport 不要放在 LOOP 裡？
    要點：field-set 只累積清單；field-transport 一次傳送；field-get 立即執行。放 LOOP 會每行觸發一次 RFC，大量資料時效能很差。Include 為 AVWRTCXM；判斷是否 ITS 用 ITS_PING。
  6. 寫出 WebRFC 函數模組的標準介面，並說明 RETURN_CODE 0／1／3 的意義。
    要點：TABLES QUERY_STRING（W3QUERY）、HTML（W3HTML）、MIME（W3MIME）；CHANGING CONTENT_TYPE、CONTENT_LENGTH、RETURN_CODE（W3PARAM）。0＝關閉連線、1＝保持、3＝關閉並結束 ITS 會話。函數要在 SMW0 做 Internet Release；呼叫 URL 為 …/wgate/WebRFC/!?_function=…。
  7. 指出强晟筆記中至少四處錯誤並更正。
    要點：SWO1 → SMW0；WHEN 'AWSY' OF 'AWSS' → OR；QUEST_STRING → QUERY_STRING；striCmp 是不分大小寫；tsadmin → itsadmin；HTML_TEMPLATE_MERGER → WWW_HTML_MERGER；非對稱加密的機密性是公鑰加密私鑰解密；<image>／<options>／<intpu> 的錯字；mimeURL 的 language 少了 ~。
  8. 實作題：寫一個 ICF handler，GET /sap/bc/zbc440_api?carrid=LH,AA 回傳 SPFLI 的 JSON；說明為什麼一定要 ORDER BY，以及為什麼把多值參數轉成 EQ 列舉。
    要點：參考第 18 節程式。HANA 沒有預設排序，分頁或取第一筆若不排序，結果每次可能不同（Casper 第一條經驗：成本評價 H／E 兩種角度交錯被抓到）；區間比的是字典序，遇到號碼段不連續或前導零會多抓漏抓，列舉才精確（第二條經驗）。記得 SICF 啟用服務、Handler 內做 AUTHORITY-CHECK。
  9. 實作題：用 CL_HTTP_CLIENT 呼叫外部 REST。URL 與帳密該放哪裡？背景作業要注意什麼？
    要點：放 SM59 型別 G 目的地（系統相依設定，傳輸後各環境各自指向測試／正式端點），憑證匯入 STRUST SSL Client PSE；背景作業要關閉登入彈窗（propertytype_logon_popup = co_disabled），檢查 send／receive 的 sy-subrc 與 HTTP 狀態碼，最後 close( )。
  10. 情境題：客戶要讓「沒有裝 SAP GUI 的倉管人員」在平板上查庫存並做簡單過帳，你會怎麼選技術？

  11. SMW0 在 S/4HANA 還有什麼用途？WWWDATA 與 WWWPARAMS 各存什麼？
    要點：存 Excel／Word 範本、Logo 等二進位物件（Binary data，RELID='MI'）與 HTML 範本（RELID='HT'）；WWWDATA 存物件內容，WWWPARAMS 存 mimetype、filesize 等屬性。可用 WWWDATA_IMPORT 讀出、DOWNLOAD_WEB_OBJECT 下載，或如第 15 節由 ICF 直接提供。
