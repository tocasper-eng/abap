1. 選擇畫面在 SAP 的定位

螢幕（Screen）是 ABAP 設計最重要的工作之一。SAP 的單據、主資料維護幾乎都靠螢幕，一支程式可以包含多個螢幕。螢幕上的 Dialog 就是使用者和程式之間的各種互動：輸入資料、選菜單、按按鈕、單擊或雙擊清單項目。

但選擇畫面（Selection Screen）不需要你去 SE51 建 Screen Number——它是由原始碼中的宣告語句自動產生的「簡易型螢幕」。這是它最大的優點：

  • 簡單方便：幾行宣告就有一個可用的輸入畫面，不必畫 Layout、不必寫 PBO/PAI 模組。
  • 移植方便：畫面定義就在程式裡，跟著程式一起傳輸，不會漏傳 Screen。
  • 自動型別檢查：使用者輸入的值會自動與欄位型別比對。
  • 自動接上字典：用 DDIC 資料元素宣告，F1 直接顯示欄位文件、F4 直接叫出字典掛的搜尋說明。
  • 多語系文字：選擇文字（Selection Texts）可以多語維護，執行時自動用使用者的登入語言顯示。
  • 可存成變式（Variant）：重複使用，也是背景排程的必要條件。
標準選擇畫面的螢幕編號固定是 1000（sy-dynnr = '1000'）。用 SELECTION-SCREEN BEGIN OF SCREEN n 自行定義的則從 1001 開始由你指定。這個編號在寫 F4 輔助說明（要傳 DYNPNR）時會用到。
老師的定位很清楚：「簡單，但是有很多要注意的技巧；另外條件變式的善用技巧也要能掌握。」 這一章八成的內容都在講那些「技巧」。

2. PARAMETERS：單值輸入的完整語法

PARAMETERS 產生一個單值輸入框，它同時也是程式裡的一個普通變數，可以直接拿來運算、直接寫進 WHERE 條件（用 =）。

PARAMETERS para[(len)] | para [LENGTH len]
  [TYPE type [DECIMALS dec]] | [LIKE dobj]
  [DEFAULT val]
  [OBLIGATORY] [NO-DISPLAY] [LOWER CASE] [VALUE CHECK]
  [AS CHECKBOX] | [RADIOBUTTON GROUP grp] | [AS LISTBOX VISIBLE LENGTH vlen]
  [VISIBLE LENGTH vlen]
  [MEMORY ID pid] [MATCHCODE OBJECT sh] [MODIF ID mid] [USER-COMMAND ucom]
  [AS SEARCH PATTERN] [NO INTERVALS].
附加語法作用注意事項 / 老師提醒
TYPE t / LIKE dobj指定型別。TYPE 接型別（DDIC 資料元素、表欄位、內建型別）；LIKE 接既有資料物件新程式一律用 TYPE。用 DDIC 型別才會自動有 F1 文件與 F4 說明
DEFAULT val設定預設值不能用 VALUE！這是 PARAMETERS 與 DATA 最容易混淆的一點
OBLIGATORY必填，欄位左邊出現打勾符號，沒填不讓執行與 NO-DISPLAY 互斥
NO-DISPLAY不顯示在畫面上，但仍是選擇畫面的一部分可用 SUBMIT ... WITH 或變式傳值進來，是「隱藏開關」的標準做法。加了 NO-DISPLAY 之後型別限制放寬（可以用 STRING 等）
LOWER CASE保留小寫，不自動轉大寫檔名、E-mail、密碼、URL 一定要加。忘了加是最常見的「查不到資料」原因之一
AS CHECKBOX核取方塊，型別固定為 CHAR1（'X' / space）判斷用 IF p_flag = abap_true.
RADIOBUTTON GROUP g單選鈕，同 group 只能選一個，型別 CHAR1群組名最長 4 碼；一組至少要兩個；要用 DEFAULT 'X' 指定預設選哪個，否則預設是第一個
AS LISTBOX VISIBLE LENGTH n下拉清單，n 是顯示寬度值從 Domain 固定值／檢查表自動來，或用 FM VRM_SET_VALUES 自己灌
VISIBLE LENGTH n只縮短顯示寬度，內部長度不變常配 TYPE STRING 使用（STRING 不加這個會佔滿整行）
MATCHCODE OBJECT sh指定 SE11 的搜尋說明（Search Help）覆寫資料元素原本掛的搜尋說明
MEMORY ID pid與 SAP 記憶體（SPA/GPA）掛勾，進畫面自動 GET、執行時自動 SET傳統上用 3 碼（MAT、WRK、BUK）。ID 要先存在於 TPARA，否則語法檢查會出警告
MODIF ID mid把欄位歸到一個群組（最長 3 碼），供 LOOP AT SCREEN 判斷 screen-group1動態顯示／隱藏／變灰的關鍵，見第 13 節
USER-COMMAND ucom只能給 CHECKBOX / RADIOBUTTON / LISTBOX 用；勾選時觸發 PAI，畫面重繪功能碼由 sscrfields-ucomm 讀取。沒有它，勾了 checkbox 畫面不會有反應
VALUE CHECK對 DDIC 檢查表 / 固定值做輸入檢查只對有檢查表的 DDIC 型別有效
AS SEARCH PATTERN當作主鍵構成的搜尋樣式欄位搭配邏輯資料庫使用，現在很少用
NO INTERVALS在 block 內對齊時壓縮空間常放在 BEGIN OF BLOCK 上，讓整個框架的欄位不留區間位
兩個硬性限制記牢：
1. PARAMETERS / SELECT-OPTIONS 的名稱不得超過 8 個字元（含 P_、S_ 前綴）。取名 P_WERKSXX 就會語法錯誤。
2. 預設值只能用 DEFAULT，不能用 VALUE；VALUE 是 DATA 的語法。
命名慣例：PARAMETERS 用 P_ 開頭、SELECT-OPTIONS 用 S_ 開頭、RADIOBUTTON 用 R_ 開頭。這不是語法規定，但全世界的 ABAPer 都這樣寫，維護的人一眼就看得懂。

5. SELECT-OPTIONS：四欄內表 SIGN / OPTION / LOW / HIGH

PARAMETERS 只能給一個值，實務上使用者要的是「這批料號」「這段日期」「排除這幾張單」。這就是 SELECT-OPTIONS。

SELECT-OPTIONS sel FOR dobj.   " dobj 必須是已宣告的資料物件或表欄位

執行後，使用者輸入的內容會傳到一個自動產生的內表，這個內表的結構永遠是這四欄：

欄位值域意義
SIGNI / EI = Include 包含；E = Exclude 排除。不可以留空白
OPTIONEQ NE GT GE LT LE BT NB CP NP比較運算子，見下表
LOW值維護項目－前（單值或區間下限）
HIGH值維護項目－後（區間上限，只有 BT / NB 才填）
OPTION意義對應 SQL範例（欄位 MATNR）
EQ等於=MATNR = 'DXTR1000'
NE不等於<>MATNR <> 'DXTR1000'
GT大於>MATNR > 'DXTR1000'
GE大於等於>=MATNR >= 'DXTR1000'
LT小於<MATNR < 'DXTR1000'
LE小於等於<=MATNR <= 'DXTR1000'
BT介於（含頭含尾）BETWEENMATNR BETWEEN 'DXTR1000' AND 'DXTR2000'
NB不介於NOT BETWEENMATNR NOT BETWEEN ...
CP模式比對LIKEMATNR LIKE 'DXTR1*'（* 任意字串、+ 任意單一字元、# 逸出）
NP模式不比對NOT LIKEMATNR NOT LIKE 'DXTR1*'
老師強調：「光是這四個欄位就能變化出無窮的條件式，非常靈活、非常強大。善用之，能好好教導前端使用者。」 很多客戶抱怨「報表不好用」，其實是沒人教他們按右邊那顆「多重選擇」按鈕（黃綠色箭頭），可以一次貼上幾百個料號、可以設排除。
Debug 觀察法（老師特別交代一定要會）：s_s1 ～ s_s7 每一個都是獨立的內表。在 Debug 時，如果結構（表頭列）與內表同名，要用 s_s1[] 才看得到內表本體；變數旁邊有小帽子（hat）圖示就代表它是 WITH HEADER LINE。可以在程式中直接寫 BREAK-POINT. 或用 BREAK-POINT ID，實務上更常用 BREAK sy-uname.（只對自己中斷，不會影響其他使用者）。

SELECT-OPTIONS s_s7 FOR gv_vbeln NO INTERVALS.                     " 只能單值

  " 用 Debug 觀察 s_s1[] ~ s_s7[]，確認它們都是四欄內表
  BREAK sy-uname.

  SELECT vbeln, erdat, ernam, netwr, waerk
    FROM vbak
    WHERE vbeln IN @s_s2                 " SELECT-OPTIONS 一律用 IN
    INTO TABLE @DATA(lt_vbak)

S/4HANA：不要再寫 TABLES:。TABLES 會產生一個全域的表工作區（等同 WITH HEADER LINE 的近親），在 ABAP Objects（類別／方法）裡根本不允許，也是 ATC 檢查的固定扣分項。SELECT-OPTIONS 只是需要一個「有型別的資料物件」，用 DATA gv_x TYPE vbak-vbeln. 完全等效，而且 F1 / F4 / 轉換常式全部保留。
NO INTERVALS 與 NO-EXTENSION 常被搞混：
・NO INTERVALS＝拿掉「到（HIGH）」欄位 → 只能單值，但可以按多重選擇輸入很多列。
・NO-EXTENSION＝拿掉右邊那顆多重選擇按鈕 → 只能一列，但那一列還是可以填區間。
兩個一起加，才等於「只能填一個單值」。

7. RANGES 與自建 range 的正確填法

SELECT-OPTIONS 同時做兩件事：畫面元素 ＋ 四欄內表。如果你只要那個四欄內表、不要畫面（例如程式內部自己組條件），那就是 RANGES。

SELECT-OPTIONSRANGES（舊）DATA ... TYPE RANGE OF（新，建議）
產生畫面欄位是否否
產生四欄內表是是是
WITH HEADER LINE是（無法避免）是（因此已過時）否
可宣告在方法／類別內否否可以
可存進變式是否否
 
" 舊寫法（講義時代）：RANGES 會產生 header line，S/4 請避免
"RANGES r_matnr FOR mara-matnr.

" 現代寫法一：直接宣告 range 型別的內表
DATA lr_matnr TYPE RANGE OF mara-matnr.

" 現代寫法二：先定型別，方法簽章／FM 介面可重複使用
TYPES ty_r_matnr TYPE RANGE OF mara-matnr.
DATA  lr_werks   TYPE RANGE OF marc-werks.

" 用 VALUE # 一次組好（sign / option 可以提到括號外共用）
lr_matnr = VALUE #( sign = 'I' option = 'EQ'
                    ( low = 'DXTR1000' )
                    ( low = 'DXTR1001' )
                    ( low = 'DXTR1002' ) ).

" 需要區間就明確寫出 BT，並且 low / high 都要填
APPEND VALUE #( sign = 'I' option = 'BT'
                low = '20250101' high = '20251231' ) TO lr_datum.

" 由內表批次轉成 range（FOR 迴圈）
TYPES ty_r_kunnr TYPE RANGE OF kna1-kunnr.
DATA(lr_kunnr) = VALUE ty_r_kunnr(
    FOR ls IN lt_customer ( sign = 'I' option = 'EQ' low = ls-kunnr ) ).

如果要在程式裡「加料」到畫面上的 SELECT-OPTIONS（例如 INITIALIZATION 給預設條件），建議一律用 方括號 明確指定內表本體，避免踩到 header line：

INITIALIZATION.
  " 明確寫 s_matnr[]，不依賴 header line
  APPEND VALUE #( sign = 'I' option = 'CP' low = 'DXTR1*' ) TO s_matnr[].
  APPEND VALUE #( sign = 'E' option = 'EQ' low = 'DXTR1205' ) TO s_matnr[].
自建 range 的五條鐵律（違反任何一條，SELECT 的結果都可能靜默出錯）：
1. SIGN 一定要填 'I' 或 'E'，大寫，不可空白。空白的 SIGN 在 ABAP SQL 的 IN 條件裡行為未定義。
2. OPTION 一定要填，而且要跟 HIGH 一致：填了 HIGH 就必須用 BT / NB；用 EQ/GT/LE… 時 HIGH 必須留空。填了 HIGH 又用 EQ，SAP 只看 LOW，HIGH 被默默忽略。
3. 空的 range ＝ 不設限，會撈全表。所以做「使用者不填就不查」的邏輯要自己擋：IF lr_matnr IS INITIAL. MESSAGE ... TYPE 'E'. ENDIF.
4. E（排除）列是在 I（包含）列之後才套用：結果 ＝（所有 I 列的聯集）減去（所有 E 列的聯集）。若表中只有 E 列沒有 I 列，等於「全部資料扣掉排除的」——這常常是使用者以為只會查到幾筆、結果跑了十分鐘的原因。
5. low / high 要用資料庫的內部格式。MATNR、KUNNR、LIFNR、EQUNR 都有 ALPHA 轉換常式，畫面輸入 100、資料庫存的是 000000000000000100。自己塞值要先呼叫 CONVERSION_EXIT_ALPHA_INPUT（或用 |{ lv_matnr ALPHA = IN }|）。
" 自己塞料號時，務必補零成內部格式
DATA(lv_internal) = |{ lv_input ALPHA = IN }|.
APPEND VALUE #( sign = 'I' option = 'EQ' low = lv_internal ) TO lr_matnr.

" 反過來要顯示給人看時
WRITE / |{ ls_mara-matnr ALPHA = OUT }|.

8. 【重點陷阱】區間（BT）與列舉（EQ）的答案為什麼會不一樣

這是老師在真實專案上付出代價換來的經驗：同一批資料，條件用「區間」跟用「列舉」，跑出來的答案不一樣，而用列舉的那個才是對的。

結論先講：能列舉就列舉（I/EQ 一筆一筆列，或 I/CP 加 E/EQ 排除），不要圖省事寫 BT 區間。會踩雷的原因有五個，全部都是「靜默出錯」——不會 dump、不會報錯，只是數字錯了。

原因一：CHAR 欄位的 BT 是「字典順序」比較，不是數值比較。
SAP 裡幾乎所有代碼欄位（MATNR、VBELN、BELNR、KOSTL）都是字元型。字元比較是逐字元比的，所以：

  • 'DXTR1201' BT 'DXTR1210' 會把 DXTR12010、DXTR1205A、DXTR120X 這種「開頭相同但更長／帶字尾」的料號一併撈進來（因為它們排在中間）。
  • 反過來，'9' BT '100' 在字元世界裡是空集合（因為 '9' > '1'），使用者以為查了 9 到 100，結果一筆都沒有。

原因二：ALPHA 轉換常式讓邊界值對不上。
畫面上輸入是有做轉換的（1201 → 000000000000001201），但程式裡自己填 range 的 low/high 沒人幫你轉。用 EQ 列舉時，某一筆對不上就是那一筆查不到，很容易被發現；用 BT 時，邊界對不上會讓整段區間多抓或少抓，而且看起來還很合理。

原因三：實務上的號碼段幾乎不是連續的。
料號 DXTR1201～DXTR1210 中間，可能夾著別的廠、別的類別、甚至別的公司代碼的資料。BT 是「凡是排在這兩端之間的都算」，它不知道你的業務規則；列舉是「我點名的這幾筆才算」。只要編碼帶有業務意義，區間就一定會誤傷。

原因四：編碼規則會變。
今年的區間寫死 'A2025000001' TO 'A2025999999'，明年前綴改成 B 就整段失效，而且一樣不報錯，只是報表變成 0 筆。列舉至少會在「找不到某筆」時被人發現。

原因五：BT 的 HIGH 是「含尾」，但只有在長度一致時才直覺。
日期、數量、金額型別沒問題；但字元欄位長度不一致時，BT 的「含尾」語意會跟人的直覺差很多。

所以老師在 ZOOALV 案例裡用的是這個模式：用 I/CP 圈範圍，再用 E/EQ 逐筆挖掉——既省手工，又精準：

" 正確示範：包含 DXTR1* 全部，再明確排除 DXTR1201 ~ DXTR1210 這十筆
INITIALIZATION.
  APPEND VALUE #( sign = 'I' option = 'CP' low = 'DXTR1*' ) TO s_matnr[].

  DO 10 TIMES.
    DATA(lv_num)   = 1200 + sy-index.
    DATA(lv_matnr) = |DXTR{ lv_num }|.
    APPEND VALUE #( sign = 'E' option = 'EQ' low = lv_matnr ) TO s_matnr[].
  ENDDO.

" 錯誤示範（不要學）：看起來一樣，實際會誤殺 DXTR12010、DXTR1205A ...
"  APPEND VALUE #( sign = 'E' option = 'BT'
"                  low = 'DXTR1201' high = 'DXTR1210' ) TO s_matnr[].
條件類型SIGNOPTION範例老師評語
包含一整群'I''CP'DXTR1*圈範圍用這個，比 BT 安全
逐筆排除'E''EQ'DXTR1201 … DXTR1210正解：一筆一筆點名
區間排除'E''BT'DXTR1201 ~ DXTR1210會抓錯：長度／字尾不同的會被誤殺
老師口訣：「條件寧可囉唆，不要聰明。」 多寫十行 APPEND，換來答案永遠正確，這筆交易非常划算。真的必須用區間時（例如日期、會計期間、工廠這種格式固定的欄位），請確認：型別是 DATS/NUMC/定長 CHAR、且沒有轉換常式、且業務上確定是連續的。
延伸提醒：「換個寫法答案就不一樣」還有另一個常見兇手——SELECT 沒有排序。
同一筆業務資料在系統裡可能存在多種「角度」（例如成本估算就同時有 H＝Item Category 項目類別 與 E＝Cost Component 成本組成 兩種構成，兩者的欄位數量還不一樣）。若程式用 SELECT SINGLE 或沒有 ORDER BY 就取第一筆，抓到 H 還是 E 完全看資料庫當下的心情，結果就會時對時錯、不穩定。
正確做法是：在 WHERE 裡明確限定角度（例如固定只取 H），再加 ORDER BY 保證順序。「條件要精準」和「取值要有序」是同一個問題的兩面。

9. SELECTION-SCREEN：把畫面排漂亮

SELECTION-SCREEN 用來建立畫面的框架結構，包括螢幕元素的建立與子螢幕的建立。完整指令清單：

指令作用
BEGIN OF BLOCK b [WITH FRAME] [TITLE t] [NO INTERVALS] … END OF BLOCK b建立一個（帶標題的）方框群組；最多可巢狀 5 層
BEGIN OF LINE … END OF LINE把多個元素排在同一行（此區間內元素不會自動換行）
SKIP [n]空 n 行
ULINE [/pos(len)]畫一條水平線
POSITION pos把游標移到第 pos 欄；也可用 POS_LOW / POS_HIGH 對齊選項欄位
COMMENT pos(len) name [FOR FIELD f] [MODIF ID m]放一段說明文字；FOR FIELD 讓這段文字的 F1 連到該欄位的說明
PUSHBUTTON pos(len) name USER-COMMAND uc [VISIBLE LENGTH n]畫面上的按鈕
FUNCTION KEY n在應用工具列加按鈕（n = 1～5，功能碼 FC01～FC05）

講義的 Z202202_38（第 38 個練習），示範兩個 BLOCK 加一個自訂畫面 1001：

  PARAMETERS p_pb TYPE vbak-vbeln.
SELECTION-SCREEN END OF BLOCK b2.

" 自訂的第二張選擇畫面（編號自 1001 起）
SELECTION-SCREEN BEGIN OF SCREEN 1001 TITLE TEXT-t01.
  SELECTION-SCREEN COMMENT /1(30) TEXT-003.
  PARAMETERS p_p9 TYPE vbak-vbeln.

SELECTION-SCREEN END OF SCREEN 1001.

條件多到一頁塞不下時，用頁籤（Tabbed Block）。做法是：先把每組條件做成 AS SUBSCREEN 的選擇畫面，再用 TABBED BLOCK 把它們掛上去。

REPORT z_tabbed_demo.

SELECTION-SCREEN END OF SCREEN 1200.

  tab2 = '進階設定'.

11. 文字元素與多語翻譯

在 SELECT-OPTIONS 與 PARAMETERS 的設計中，畫面上顯示的名稱預設就是物件的定義名（P_P1、S_MATNR），這對使用者完全沒有意義。SAP 提供 Text Elements（文字元素） 來自訂，路徑：ABAP 編輯器 → 轉到（Goto）→ 文字元素（Text Elements）。共三類：

類別用途引用方式
清單標題 List Headings定義 Report 的標題與欄位抬頭，配合 WRITE 輸出使用系統自動套用在傳統清單上方
選擇文字 Selection Texts設定 PARAMETERS / SELECT-OPTIONS 的抬頭文字自動顯示；勾「字典」欄可直接沿用資料元素的短文
文字符號 Text Symbols自訂任意文字，三位代碼TEXT-001，或 '預設文字'(001)
 
" 兩種引用寫法的差別：
WRITE / TEXT-001.              " 若 001 未維護，畫面上是空白，很難查
WRITE / '銷售訂單清單'(001).    " 若 001 未維護，就顯示括號前的字面值（建議！）

" 訊息也可以用文字符號
MESSAGE |{ TEXT-e01 }：{ p_werks }| TYPE 'E'.
老師的三個實作提醒：
1. 「'字面值'(001)」這種寫法最安全——文字符號沒維護時至少還看得到字，而且雙擊就能建立。
2. 文字元素要單獨啟用（Activate）！很多人改完 Selection Texts 存檔就走，結果畫面沒變，就是忘了對文字元素按啟用。
3. 設定值與當前登入語言綁定；程式若要支援多語，每種語言都要各自維護。

翻譯路徑：

  • 編輯器內：More（更多）→ Goto（轉到）→ Translation（翻譯），選來源語言與目標語言。
  • 正式翻譯工具：SE63 → Translation → ABAP Objects → Short Texts，可批次處理程式的所有短文。
  • 下拉選單裡能選的語言，必須是系統已經安裝的語言；沒裝的語言選不到。

1. INITIALIZATION 設的值會被變式（Variant）和 SUBMIT ... WITH 傳進來的值覆蓋。 這是設計如此（否則變式就沒意義），但常讓人以為「我的預設值不見了」。

14. 自製 F4 輔助說明

函數用途
F4IF_INT_TABLE_VALUE_REQUEST用自己組出來的內表當值清單（最常用）

      FROM vbak

    ENDIF.

  ENDMETHOD.
ENDCLASS.

四個終止指令的差別（老師特別列出來對照，很容易考也很容易寫錯）：

指令可用於行為
STOPINITIALIZATION、AT SELECTION-SCREEN、START-OF-SELECTION、GET在 INITIALIZATION 中：直接送出畫面；在其他事件中：直接跳到 END-OF-SELECTION。不想執行 END-OF-SELECTION 就改用 RETURN 或 EXIT
EXIT迴圈（DO/WHILE/LOOP/SELECT）與處理模組迴圈中：只跳出當前這一層迴圈；在 START-OF-SELECTION / GET / END-OF-SELECTION 中：直接觸發清單輸出、不執行 END-OF-SELECTION；沒有清單就回到選擇畫面。SAP 建議 EXIT 只用於迴圈
RETURN事件塊、Dialog Module、程序（FM／方法／副程式）無條件離開當前處理模組，不管包了幾層迴圈（這是與 EXIT 最大的差別），不影響後續模組
CHECK迴圈與處理模組迴圈中：條件不成立就跳過本次迴圈剩餘部分，繼續下一圈（相當於 CONTINUE）；事件中：中斷本事件後續程式碼，不影響其他模組。SAP 建議 CHECK 只用於迴圈
REJECT邏輯資料庫的 GET 事件類似 CHECK，但即使在迴圈內也會退出本次紀錄（含子節點）的處理，直接讀下一筆
老師的建議照抄 SAP：EXIT 和 CHECK 只用在迴圈裡；要離開處理模組（FORM／METHOD／事件塊）一律用 RETURN。 這樣讀程式的人不必猜「這個 EXIT 是跳出迴圈還是跳出整個模組」。

18. 變式（Variant）與背景執行

把選擇畫面填好的一整組條件存起來重複使用，就是變式。這是老師說的「條件變式的善用技巧」，也是背景排程的前提。

  1. 在選擇畫面填好條件 → 點儲存（Save）圖示 → 輸入變式名稱與描述 → 儲存。
  2. 執行時：Goto → Variants → Get（或畫面上的「取得變式」按鈕）。
  3. 維護／刪除：SE38 → 選 Variants → Change。

變式屬性（Attributes）是很多人沒用過但很好用的功能：

屬性作用
Only for Background Processing只給背景 job 用，前台看不到
Protect Variant只有建立者能改
Do not display in catalog不出現在變式清單（隱藏用）
Save field without values該欄位不存值（每次執行都空白）
Protect field套用變式後該欄位變唯讀，使用者不能改
Hide field / Hide field 'BIS'套用變式後隱藏該欄位／只隱藏 HIGH 欄
Selection variable動態值：D = 動態日期計算（今天、本月最後一天、上月…）；T = 取 TVARVC 表變數；B = 使用者出口
排程報表最實用的組合：日期欄位設 Selection variable = D「目前日期」或「上個月的第一天／最後一天」，這樣一支 job 每天／每月自動跑出正確區間，不必每個月改變式。若多支程式要共用同一組值（例如「目前結帳期間」），就用 T（TVARVC），在 STVARV（部分系統為 STVARVC）維護一次，全部程式跟著變。

背景執行：

  • SE38 → Program → Execute in Background（或 F9），選印表機、選日期／時間、選變式。

21. 綜合案例：複雜條件 ＋ OO ALV

第 11 節配合 ABAP3-2 的 ZOOALV_2_GRID，把「INITIALIZATION 預填複雜條件」與 ALV 顯示接起來，這是本章的集大成：

REPORT zooalv_2_grid.

DATA gv_matnr TYPE mara-matnr.

SELECTION-SCREEN BEGIN OF BLOCK blk1 WITH FRAME TITLE TEXT-001.
  SELECT-OPTIONS s_matnr FOR gv_matnr.
SELECTION-SCREEN END OF BLOCK blk1.

" 預設條件：包含 DXTR1*，逐筆排除 DXTR1201 ~ DXTR1210
INITIALIZATION.
  APPEND VALUE #( sign = 'I' option = 'CP' low = 'DXTR1*' ) TO s_matnr[].

  DO 10 TIMES.
    DATA(lv_num)   = 1200 + sy-index.
    DATA(lv_matnr) = |DXTR{ lv_num }|.
    APPEND VALUE #( sign = 'E' option = 'EQ' low = lv_matnr ) TO s_matnr[].
  ENDDO.

START-OF-SELECTION.
  SELECT a~matnr, a~mtart, a~matkl, a~meins, b~maktx
    FROM mara AS a
    LEFT OUTER JOIN makt AS b ON b~matnr = a~matnr AND b~spras = @sy-langu
    WHERE a~matnr IN @s_matnr          " SELECT-OPTIONS 用 IN，逸出字元 @ 不可少
    INTO TABLE @DATA(lt_mara)
    ORDER BY a~matnr.                  " 一定要排序，結果才穩定

  IF lt_mara IS INITIAL.
    MESSAGE '查無符合條件的物料' TYPE 'S' DISPLAY LIKE 'W'.
    RETURN.
  ENDIF.

  TRY.
      cl_salv_table=>factory( IMPORTING r_salv_table = DATA(lo_alv)
                              CHANGING  t_table      = lt_mara ).

      lo_alv->get_functions( )->set_all( abap_true ).       " 開啟全部工具列功能
      lo_alv->get_columns( )->set_optimize( abap_true ).    " 欄寬自動最佳化
      lo_alv->get_display_settings( )->set_list_header( |物料清單（{ lines( lt_mara ) } 筆）| ).
      lo_alv->display( ).

    CATCH cx_salv_msg INTO DATA(lx_salv).
      MESSAGE lx_salv->get_text( ) TYPE 'E'.
  ENDTRY.
講義最後那句 WRITE: space.「關鍵！觸發畫面顯示」是舊 ALV 的權宜之計。
它的用途是：當你用 CL_GUI_ALV_GRID 掛在 Docking Container 上、而程式只有選擇畫面沒有任何螢幕時，必須先產生一個清單（List）畫面，Grid 才有地方可掛。
在 S/4HANA 上，全螢幕報表請直接用 CL_SALV_TABLE——它自己會建立畫面，完全不需要這一招；只有需要「可編輯欄位、複雜事件、多個 Grid 併排」時才回頭用 CL_GUI_ALV_GRID ＋ 自建 Screen（見第 3-2 章）。

22. 選擇畫面設計檢查清單（Code Review 用）

  • 參數／選項名稱 ≤ 8 碼，前綴 P_ / S_ / R_ 一致。
  • 全部用 DDIC 型別宣告（有 F1／F4／轉換常式），不要用 CHARn 硬幹。
  • 沒有 TABLES:（唯一例外：TABLES sscrfields.）。
  • 檔名、E-mail、路徑類欄位有 LOWER CASE。
  • 條件能列舉就列舉，避免 BT 區間；自建 range 的 SIGN／OPTION 都有填、大寫、與 HIGH 一致。
  • 「使用者什麼都不填就撈全表」的情況已被擋掉（OBLIGATORY 或 AT SELECTION-SCREEN 檢核）。
  • SELECT 一律明列欄位、帶 @ 逸出主機變數、加 ORDER BY。
  • 條件檢核放 AT SELECTION-SCREEN（訊息 TYPE 'E'），不要放 START-OF-SELECTION。
  • 預填資料放 INITIALIZATION，不要放 AT SELECTION-SCREEN OUTPUT（會愈跑愈多筆）。
  • Selection Texts 全部維護好並單獨啟用；多語系客戶要做翻譯（SE63）。
  • 需要排程的程式：確認 sy-batch 分流、沒有 CL_GUI_* 呼叫、必填欄位有變式。
  • 需要重複執行的條件，做成變式並考慮用 Selection variable（D／T）處理日期。
