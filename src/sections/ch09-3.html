3. MRP Element 在程式裡從哪裡來

同一份「庫存／需求清單」可以從幾個地方拿，差別在「即時或是 MRP 當下的快照」以及「是否為 released API」：

來源性質適用備註
MD04即時（每次開啟重新讀單據）使用者查詢程式可用 SET PARAMETER ID 'MAT'／'WRK' 後 CALL TRANSACTION 'MD04' 跳轉
MD_STOCK_REQUIREMENTS_LIST_API即時，輸出 MDPSX／MDEZX／MDSUX 與 E_MDKP客製報表（缺料表、交期推算）非 released，但實務上最常用；完整案例見 6-6 章
BAPI_MATERIAL_STOCK_REQ_LIST即時，BAPI 介面（MRP_ITEMS 等）RFC、外部系統唯讀 BAPI；參數與結構請以 SE37 確認（S/4 另有長料號參數）
MDKP／MDTB（MD05 MRP 清單）MRP 執行當下的快照比對「MRP 跑完當時」的結果MDKP 是表頭（DTNUM），MDTB 是項目；會過時，不適合當即時資料
PPH_DBVM（S/4HANA）計劃檔（planning file）了解哪些料會被下一次 MRP 重算S/4HANA 以 PPH_DBVM 取代 ECC 的 MDVM／DBVM；它記錄「待計劃的料」，不是 MRP 元素本身
S/4HANA MRP Live（MD01N）的注意事項（有不確定處，請在系統確認）：MRP Live 在 HANA 裡以資料庫程序執行，依 SAP 說明預設不產生 MD05 用的 MRP 清單，因此 MDKP／MDTB 在 S/4HANA 可能是空的或只剩舊資料——需要 MRP 結果時請用 MD_STOCK_REQUIREMENTS_LIST_API 讀即時清單。網路資料中常見的「PPH_DBVM_MRP」這類物件名稱，本章無法確認是否存在於 1809；PPH_* 開頭的是 MRP Live 內部物件，就算存在也不是 released API，不建議客製程式直接讀取。可以在 SE11 以 PPH_DBVM* 搜尋自己系統的實際物件。

BAPI 版本的呼叫方式（適合 RFC 給外部系統，或不想依賴非 released 函數時）：

" 介面請以 SE37 確認：S/4HANA 另有 40 碼長料號參數（MATERIAL_LONG 等）
DATA lt_items  TYPE STANDARD TABLE OF bapi_mrp_items WITH EMPTY KEY.
DATA ls_return TYPE bapiret2.

CALL FUNCTION 'BAPI_MATERIAL_STOCK_REQ_LIST'
  EXPORTING
    material  = p_matnr
    plant     = p_werks
  IMPORTING
    return    = ls_return
  TABLES
    mrp_items = lt_items.

IF ls_return-type CA 'EA'.
  MESSAGE ls_return-message TYPE 'I' DISPLAY LIKE 'E'.
  RETURN.
ENDIF.

" 唯讀 BAPI，不需要 BAPI_TRANSACTION_COMMIT
" MRP_ITEMS 的欄位（MRP_ELEMENT_IND = DELKZ、AVAIL_DATE、REC_REQD_QTY …）請以 SE11 BAPI_MRP_ITEMS 確認
LOOP AT lt_items INTO DATA(ls_item).
  WRITE: / ls_item-mrp_element_ind, ls_item-avail_date, ls_item-rec_reqd_qty.
ENDLOOP.

IF sy-subrc <> 0.

MDPS／MDEZ 的 DELKZ（MRP 元素指示碼，2 碼）是程式判斷元素種類唯一可靠的欄位。完整的 DELKZ ↔ MD04 縮寫 ↔ 底層資料表對照，已整理在 6-6 章第 5 節，這裡不重複，只列本章常用、可以確認的幾個：

PAPlanned order收PLAF

其餘元素（JIT、排程協議、調撥下達單…）的代碼請在自己系統查 MRP 元素文字表 T457T（SE11 確認欄位），或直接從 API 回傳的 MDEZX 抓出「代碼 ↔ 縮寫」清單，以系統為準：

" 從 API 結果整理出本料實際出現的 DELKZ ↔ 縮寫（以系統實際值為準，不寫死）
TYPES: BEGIN OF ty_elem,
         delkz TYPE mdez-delkz,
         delb0 TYPE mdez-delb0,
         cnt   TYPE i,
       END OF ty_elem.
DATA lt_elem TYPE SORTED TABLE OF ty_elem WITH UNIQUE KEY delkz.

LOOP AT lt_mdez INTO DATA(ls_e) GROUP BY ( delkz = ls_e-delkz
                                           delb0 = ls_e-delb0
                                           size  = GROUP SIZE ) INTO DATA(ls_grp).
  INSERT VALUE #( delkz = ls_grp-delkz delb0 = ls_grp-delb0 cnt = ls_grp-size ) INTO TABLE lt_elem.
ENDLOOP.

依 DELKZ 分流，計算「供給合計、需求合計、只算已確定供給」這類生管常問的數字：

" 供給：排除 PA（計劃訂單）、BA（請購）這種還沒確定的單據——「已確定供給」
DATA(lv_firm_supply) = REDUCE mng01( INIT s = CONV mng01( 0 )
                                     FOR r IN lt_mdez
                                     WHERE ( plumi = '+' AND delkz <> 'PA' AND delkz <> 'BA' )
                                     NEXT s = s + r-mng01 ).

" 需求：PLUMI = '-'；MNG01 需求列本身是負數，取絕對值較好閱讀
DATA(lv_demand) = REDUCE mng01( INIT d = CONV mng01( 0 )
                                FOR r IN lt_mdez WHERE ( plumi = '-' )
                                NEXT d = d + abs( r-mng01 ) ).

" 列顯示用的中文分類：用 SWITCH 對 DELKZ，不要對 DELB0
LOOP AT lt_mdez INTO DATA(ls_row).
  DATA(lv_kind) = SWITCH string( ls_row-delkz
                    WHEN 'WB'               THEN `庫存`
                    WHEN 'PA' OR 'FE'       THEN `生產供給`
                    WHEN 'BA' OR 'BE' OR 'LA' THEN `採購供給`
                    WHEN 'AR' OR 'SB' OR 'BB' THEN `元件需求`
                    WHEN 'VC' OR 'VJ'       THEN `銷售需求`
                    WHEN 'PP'               THEN `計劃獨立需求`
                    ELSE                         `其他` ).
  WRITE: / ls_row-dat00, ls_row-delkz, lv_kind, ls_row-mng01.
ENDLOOP.
PLUMI（收／發指示）與 MNG01 的正負號在 MDEZ 上的實際值，請先用一支料在 MD04 對照 debug 看一次再寫邏輯；6-6 章的案例就是依 PLUMI 拆成「收／發／期初」三欄。

5. 重工：投 A 產 A 的遞迴 BOM 與 ML 價差

講義第 02 節記錄的是一個常見提問：重工工單「投 A 產 A」——領同一個料，廠內重工後產出同一個料號。用遞迴 BOM（元件 = 表頭料）開生產工單時，重工數量一大，CO 的 Material Ledger 會算出金額超大的價格差異；但實務上又確實是同一個料進、同一個料出。講義列出的參考資料是 SAP note 2031136，以及 1610 之後適用的 note 2998739（note 內容請登入 SAP for Me 查閱，本章不轉述）。

重工在 SAP 常見的幾種做法（實際要選哪一種，需要 PP 與 CO 顧問一起決定）：

做法作法摘要對成本的影響
遞迴 BOM 的生產工單BOM 項目元件 = 表頭料，需在 CS02 的 BOM 項目勾選「允許遞迴」指示碼（欄位請以 SE11 查 STPO 確認）投入與產出同料號，ML 多階實際成本要迭代計算，量大時容易出現講義描述的大額價差
重工工單（rework order）從原工單的作業衍生重工工單，只記錄重工作業與額外投料重工成本歸到原工單或另行結算，不必把 A 當元件投入
在原工單加重工作業CO02 在途程中插入重工作業重工成本留在原工單，不另產生一次「投 A 產 A」
不含料號的工單／結算到成本中心只收集重工的人工與額外材料庫存價值不變，重工費用當期費用化
ABAP 能幫上的忙是「先把重工工單找出來」，讓 CO 月結前先檢查數量與價差來源（CKM3N），而不是等 ML 算完才發現。判斷邏輯很單純：工單的元件預留（RESB）裡出現與表頭產出料（AFPO-MATNR）相同的料號。
" 找出「投 A 產 A」的工單：元件料號 = 產出料號
SELECT FROM afpo AS p
       INNER JOIN resb AS r ON r~aufnr = p~aufnr
                           AND r~matnr = p~matnr
       INNER JOIN aufk AS k ON k~aufnr = p~aufnr
  FIELDS p~aufnr, p~posnr, p~matnr, p~pwerk,
         p~psmng, p~wemng, p~meins,
         r~rsnum, r~rspos, r~bdmng, r~enmng, k~auart
  WHERE p~pwerk IN @s_werks
    AND k~erdat IN @s_erdat
    AND k~autyp = '10'              " 10 = PP 生產工單
    AND r~xloek = @abap_false       " 排除已刪除的預留項目
  ORDER BY p~aufnr, p~posnr, r~rspos
  INTO TABLE @DATA(lt_rework).

IF lt_rework IS INITIAL.
  MESSAGE '期間內沒有投入料 = 產出料的工單' TYPE 'S'.
ENDIF.

6. ZCO03 業務情境、選擇畫面與輸出

業務情境：教學系統（GBIKE）上，生管或課堂學員要一張「最近開了哪些生產工單」的清單：誰建的、什麼時候開始／完工、數量多少、屬於哪個計劃工單與 MRP 區域，並依建檔人員分組編項次。原程式只看工單主檔，沒有狀態與收貨數量，所以只能回答「開了什麼單」，回答不了「做到哪裡」。改寫版把這兩個缺口補上。

選擇畫面：原程式只有一個 S_ERDAT（AUFK 建檔日期），但 SQL 其實寫死 GSTRP > '20221201'，S_ERDAT 是撈完才在記憶體過濾。改寫後的選擇畫面如下：

REPORT zco03.

DATA gv_aufnr TYPE aufk-aufnr.     " 只給 SELECT-OPTIONS 參照型別，取代 TABLES
DATA gv_erdat TYPE aufk-erdat.
DATA gv_werks TYPE afpo-pwerk.
DATA gv_auart TYPE aufk-auart.

8. 關鍵段落（一）：一次 JOIN 取代迴圈內 SELECT SINGLE

原程式先 JOIN AFPO／AFKO，再對每一筆工單 SELECT SINGLE * FROM AUFK（N 筆工單就 N＋1 次資料庫往返），而且 WHERE 寫死日期、真正的選擇條件 S_ERDAT 在撈完之後才用 DELETE 過濾。改寫後全部條件下推：

METHOD select_orders.
  " 要排除的系統狀態（勾選框決定）；空的 RANGE 在 IN 條件等於「全部成立」，所以放一個不存在的值
  DATA lr_excl TYPE RANGE OF jest-stat.
  IF p_nodel = abap_true.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = 'I0076' ) TO lr_excl.   " DLFL 刪除旗標
  ENDIF.
  IF p_noclo = abap_true.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = 'I0046' ) TO lr_excl.   " CLSD 已結
  ENDIF.
  IF lr_excl IS INITIAL.
    APPEND VALUE #( sign = 'I' option = 'EQ' low = '#NONE' ) TO lr_excl.
  ENDIF.

  SELECT FROM afko AS h
         INNER JOIN afpo AS p ON p~aufnr = h~aufnr
         INNER JOIN aufk AS k ON k~aufnr = h~aufnr
    FIELDS h~aufnr, p~posnr, k~auart, p~matnr,
           h~gstrp, h~gltrp, h~ftrms, h~ftrmi, h~gamng, h~gmein,
           p~psmng, p~wemng, p~meins,
           h~plnbez, p~plnum, p~pwerk, p~dauat, p~berid,
           k~ernam, k~erdat, k~autyp, k~kokrs, k~waers,
           k~kalsm, k~kvewe, k~scope, k~objnr
    WHERE p~pwerk IN @s_werks
      AND k~auart IN @s_auart
      AND h~aufnr IN @s_aufnr
      AND k~erdat IN @s_erdat
      AND k~ernam IN @s_ernam
      AND k~autyp = '10'                                   " 只要 PP 生產工單
      AND NOT EXISTS ( SELECT objnr FROM jest
                         WHERE objnr = k~objnr
                           AND stat  IN @lr_excl
                           AND inact = @space )            " 只看目前有效的狀態
    ORDER BY k~ernam, h~aufnr, p~posnr                     " HANA 沒有預設排序
    INTO CORRESPONDING FIELDS OF TABLE @mt_out.

  " 計算欄位：未收量與收貨率
  LOOP AT mt_out ASSIGNING FIELD-SYMBOL(<o>).
    <o>-open_qty = COND #( WHEN <o>-psmng > <o>-wemng THEN <o>-psmng - <o>-wemng ELSE 0 ).
    <o>-gr_pct   = COND #( WHEN <o>-psmng > 0 THEN <o>-wemng / <o>-psmng * 100 ELSE 0 ).
  ENDLOOP.
ENDMETHOD.
原程式沒有 AUTYP 條件。AUFK 同時存放內部訂單（01）、生產工單（10）、維修工單（30）、流程訂單（40）等，雖然 JOIN AFKO／AFPO 已經隱含只剩生產類訂單，但流程訂單（PP-PI）也有 AFKO／AFPO，GBIKE 以外的正式系統若有 PP-PI 就會混進來，所以明寫 autyp = '10'。

9. 關鍵段落（二）：工單狀態 JEST／TJ02T

工單的狀態不在 AUFK／AFKO 的欄位裡，而是以物件號碼 OBJNR（生產工單是「OR」＋工單號碼）掛在狀態表 JEST：一個物件同時有多個狀態列，每列一個狀態碼 STAT。系統狀態 I 開頭，文字在 TJ02T（ISTAT、SPRAS、TXT04、TXT30）；使用者狀態 E 開頭，文字在 TJ30T（還要看狀態參數檔 STSMA）。

STATTXT04（英文登入）意義
I0001CRTD已建立
I0002REL已下達
I0010PCNF部分確認
I0009CNF已確認
I0012DLV已交貨（收貨完成）
I0045TECO技術完成
I0046CLSD已結
I0076DLFL刪除旗標
判斷狀態一定要加 INACT = space。JEST 會保留曾經有效、後來被取消的狀態列（INACT = 'X'）——例如 TECO 後又「取消技術完成」，I0045 那一列還在，只是 INACT = 'X'。只寫 stat = 'I0045' 會把已取消 TECO 的工單誤判成已完成。另外，邏輯判斷用 STAT 代碼，不要用 TXT04：中文登入時 TXT04 會是翻譯過的文字。上表的代碼建議在自己系統用 TJ02T 再確認一次。

批次做法：一次讀出所有工單的有效系統狀態，依 OBJNR 串成字串（大量資料時比逐筆呼叫函數快很多）：

METHOD read_status.
  CHECK mt_out IS NOT INITIAL.

  TYPES tt_objnr TYPE SORTED TABLE OF j_objnr WITH UNIQUE KEY table_line.
  DATA(lt_objnr) = VALUE tt_objnr( FOR GROUPS g OF o IN mt_out GROUP BY o-objnr ( g ) ).

  SELECT FROM jest AS s
         INNER JOIN tj02t AS t ON t~istat = s~stat
                              AND t~spras = @sy-langu
    FIELDS s~objnr, s~stat, t~txt04
    FOR ALL ENTRIES IN @lt_objnr
    WHERE s~objnr = @lt_objnr-table_line
      AND s~inact = @space                 " 只要目前有效的狀態
      AND s~stat LIKE 'I%'                 " 系統狀態；使用者狀態 E* 的文字在 TJ30T
    INTO TABLE @DATA(lt_stat).

  SORT lt_stat BY objnr stat.              " FOR ALL ENTRIES 不保證順序，排好才穩定

  LOOP AT mt_out ASSIGNING FIELD-SYMBOL(<o>).
    <o>-status = REDUCE char40( INIT s = ``
                               FOR st IN lt_stat WHERE ( objnr = <o>-objnr )
                               NEXT s = condense( |{ s } { st-txt04 }| ) ).
  ENDLOOP.
ENDMETHOD.

單筆或需要「與 CO03 畫面一模一樣的狀態字串（含使用者狀態）」時，用標準函數 STATUS_TEXT_EDIT：

DATA lv_sys_line  TYPE bsvx-sttxt.   " 型別請以 SE37 介面確認
DATA lv_user_line TYPE bsvx-sttxt.

CALL FUNCTION 'STATUS_TEXT_EDIT'
  EXPORTING
    objnr            = ls_out-objnr
    spras            = sy-langu
    flg_user_stat    = abap_true      " 同時回傳使用者狀態
    only_active      = abap_true      " 只顯示有效狀態（等同 INACT = space）
  IMPORTING
    line             = lv_sys_line    " 例：REL  PCNF PRC  MACM SETC
    user_line        = lv_user_line
  EXCEPTIONS
    object_not_found = 1
    OTHERS           = 2.
IF sy-subrc <> 0.
  CLEAR lv_sys_line.
ENDIF.

" 要判斷「是否已下達」時，查代碼而不是解析字串
SELECT SINGLE FROM jest
  FIELDS stat
  WHERE objnr = @ls_out-objnr
    AND stat  = 'I0002'
    AND inact = @space
  INTO @DATA(lv_rel_stat).
DATA(lv_released) = xsdbool( sy-subrc = 0 ).
STATUS_TEXT_EDIT 每呼叫一次就讀一次狀態，工單數量上千時會明顯變慢；清單報表用上一段的批次 JOIN，雙擊明細或列印單張時才用函數。另一種寫法是標準函數 STATUS_READ 讀單一物件的狀態表，介面請以 SE37 確認。

10. 關鍵段落（三）：項次與 CL_SALV_TABLE 輸出

原程式的「項次」其實不是列號，而是建檔人員的組別序號：SORT BY ERNAM 後，每換一位建檔人員 LV_RECN 加 1，同一人所有工單項次相同。改寫保留這個語意，用 GROUP BY 迴圈表達：

METHOD number_by_creator.
  " mt_out 已在 SELECT 以 ernam, aufnr, posnr 排序
  DATA lv_recn TYPE i.
  LOOP AT mt_out INTO DATA(ls_o) GROUP BY ls_o-ernam INTO DATA(lv_ernam).
    lv_recn = lv_recn + 1.                       " 1809 不用 +=（7.54 起才支援）
    LOOP AT GROUP lv_ernam ASSIGNING FIELD-SYMBOL(<m>).
      <m>-recn = lv_recn.
    ENDLOOP.
  ENDLOOP.
ENDMETHOD.

METHOD on_double_click.
  " 雙擊工單號碼跳 CO03；雙擊料號跳 MD04
  READ TABLE mt_out INDEX row INTO DATA(ls_row).
  CHECK sy-subrc = 0.
  CASE column.
    WHEN 'AUFNR'.
      SET PARAMETER ID 'ANR' FIELD ls_row-aufnr.
      CALL TRANSACTION 'CO03' WITH AUTHORITY-CHECK AND SKIP FIRST SCREEN.
    WHEN 'MATNR' OR 'PLNBEZ'.
      SET PARAMETER ID 'MAT' FIELD ls_row-matnr.
      SET PARAMETER ID 'WRK' FIELD ls_row-pwerk.
      CALL TRANSACTION 'MD04' WITH AUTHORITY-CHECK AND SKIP FIRST SCREEN.
  ENDCASE.
ENDMETHOD.
原程式的「雙擊彈出明細」（LAYOUT-DETAIL_POPUP、F2CODE = '&ETA'）在 CL_SALV_TABLE 的標準工具列已有「明細」按鈕，不必另外設定；原程式 USER_COMMAND 只處理 'EXIT'（LEAVE PROGRAM），而標準工具列本來就有返回鍵，也不需要自訂 PF-STATUS。CALL TRANSACTION … WITH AUTHORITY-CHECK 在 7.40 SP02 以上可用，1809 沒有問題。

11. S/4HANA：released CDS view I_ManufacturingOrder

S/4HANA 提供 released（C1 可用於客製開發）的 CDS view I_ManufacturingOrder，以 ManufacturingOrder 為鍵，封裝了 AFKO／AFPO／AUFK 的欄位與關聯，是 ABAP Cloud／RAP 或 Fiori 報表的建議資料來源；傳統 SE38 報表直接讀 AFKO／AFPO／AUFK 仍然可以。

13. 上線注意：權限、ALPHA 與列舉條件

權限：原程式用自建表 ZABAP（使用者名單）決定誰能執行，這在教學系統限定學員很方便，但正式系統應改用標準授權物件，並在 SE93 建交易碼時掛上 S_TCODE。生產工單常用的授權物件是 C_AFKO_AWK（工廠＋工單類型），欄位請以 SU21 確認：

METHOD check_authority.
  rv_ok = abap_true.
  SELECT FROM t001w FIELDS werks WHERE werks IN @s_werks INTO TABLE @DATA(lt_werks).
  LOOP AT lt_werks INTO DATA(ls_w).
    AUTHORITY-CHECK OBJECT 'C_AFKO_AWK'          " 欄位名稱請以 SU21 確認
      ID 'WERKS'  FIELD ls_w-werks
      ID 'AUFART' DUMMY.
    IF sy-subrc <> 0.
      MESSAGE |沒有工廠 { ls_w-werks } 的生產工單顯示權限| TYPE 'S' DISPLAY LIKE 'E'.
      rv_ok = abap_false.
      RETURN.
    ENDIF.
  ENDLOOP.
ENDMETHOD.

METHOD run.
  CHECK check_authority( ).
  select_orders( ).
  IF mt_out IS INITIAL.
    MESSAGE '沒有符合條件的生產工單' TYPE 'S'.
    RETURN.
  ENDIF.
  read_status( ).
  number_by_creator( ).
  display( ).
ENDMETHOD.

工單號碼的 ALPHA 前導零與列舉條件：AUFNR 是 12 碼 CHAR，資料庫存的是「000001000123」。選擇畫面的 SELECT-OPTIONS 會自動做轉換，但程式自己組條件（例如從 Excel 上傳的工單清單、介面傳進來的號碼）時必須自己補零：

" 從外部清單組工單條件：一律多筆 EQ 列舉，並做 ALPHA 轉換
DATA lt_input TYPE STANDARD TABLE OF string WITH EMPTY KEY.   " 例：上傳的 1000123、1000456
DATA lr_aufnr TYPE RANGE OF aufk-aufnr.

lr_aufnr = VALUE #( FOR lv_in IN lt_input
                    ( sign = 'I' option = 'EQ'
                      low  = |{ CONV aufnr( condense( lv_in ) ) ALPHA = IN }| ) ).
SORT lr_aufnr BY low.
DELETE ADJACENT DUPLICATES FROM lr_aufnr COMPARING low.

SELECT FROM aufk
  FIELDS aufnr, auart, objnr
  WHERE aufnr IN @lr_aufnr
  ORDER BY aufnr
  INTO TABLE @DATA(lt_orders).
工單號碼用列舉（多筆 EQ）比用區間（BT）安全。AUFK 的號碼範圍是依訂單類型分配的，內部訂單、維修工單、生產工單可能交錯在同一段數字附近；區間比的是字典序而不是業務語意，一個 BT 就可能把別種訂單、或號碼範圍改過之後的新舊號碼一起帶進來，沒補零的值更會整段比錯。工單類型（AUART）也一樣，列出要的 ZP01、ZP02… 比寫 Z* 或 BT 安全。
HANA 沒有預設排序。原程式只 SORT BY ERNAM，同一建檔人員底下的工單順序每次執行都可能不同；任何「取第一張工單」「取最早開始日」的邏輯都要先明確 ORDER BY 或 SORT 到唯一鍵（ernam、aufnr、posnr）。FOR ALL ENTRIES 的結果也不保證順序，讀完狀態後要自己 SORT（§9 已示範）。
上線前檢核：① 用 COOIS 以相同條件跑一次，筆數與數量（PSMNG、WEMNG）要對得起來；② 找一張曾經 TECO 又取消 TECO 的工單，確認狀態欄沒有顯示 TECO；③ 找一張有聯產品（多個 AFPO 項目）的工單，確認每個項目各一列；④ 用 ST05 確認只有一次主 SELECT＋一次狀態 SELECT；⑤ 用沒有該工廠權限的帳號測試訊息。先找標準：如果使用者只是要「工單清單＋狀態」，COOIS 加版面變式就能滿足，客製報表要有標準做不到的理由（例如依建檔人員分組、收貨率、跳 MD04）。
