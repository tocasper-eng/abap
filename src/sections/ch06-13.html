2. 下載之前先決定四件事

決策選項建議
寫到哪裡使用者電腦（前景）／應用伺服器（背景）互動報表用 GUI_DOWNLOAD；排程作業（SM36）一定是 OPEN DATASET，背景沒有 SAP GUI 可以寫本機檔
分隔符號逗號、Tab、分號、直線 |給 Excel 雙擊開啟用逗號 CSV；資料裡常有逗號（地址、物料說明）時改 Tab 或 |，Power BI 都能指定分隔符號
編碼UTF-8、UTF-8 含 BOM、Big5（cp 8300）一律 UTF-8。要給 Excel 直接開，就加 BOM，否則中文會變亂碼；Power BI／Python 讀 UTF-8 無 BOM 也沒問題
表頭技術名（CARRID）或欄位文字（航空公司）給人看用欄位文字；給系統介面用技術名且固定順序，並在規格中寫明
CSV 的數字與日期一律輸出「機器格式」：金額用小數點、不加千分位；日期用 YYYY-MM-DD。字串範本的 DATE = ISO 可直接做到。使用者設定（SU3 的小數點格式）不同時，WRITE TO 的輸出會跟著變，Power BI 就會解析錯誤。

4. 泛用 CSV 轉換器：RTTS 取欄位文字當表頭、處理引號跳脫

每支報表都手寫一次欄位清單很煩。下面的區域類別吃任何「結構內表」，用 RTTS 讀 DDIC 欄位文字當表頭，並依 RFC 4180 的規則：欄位內含分隔符號、雙引號或換行時，整欄用雙引號包起來，內部的 " 變成 ""。

CLASS lcl_csv DEFINITION FINAL.
  PUBLIC SECTION.
    CLASS-METHODS to_lines
      IMPORTING it_data         TYPE ANY TABLE
                iv_sep          TYPE c DEFAULT ','
                iv_ddic_header  TYPE abap_bool DEFAULT abap_true
      RETURNING VALUE(rt_lines) TYPE string_table.
  PRIVATE SECTION.
    CLASS-METHODS escape
      IMPORTING iv_value      TYPE string
                iv_sep        TYPE c
      RETURNING VALUE(rv_out) TYPE string.
ENDCLASS.

CLASS lcl_csv IMPLEMENTATION.
  METHOD to_lines.
    DATA(lo_tab)    = CAST cl_abap_tabledescr( cl_abap_typedescr=>describe_by_data( it_data ) ).
    DATA(lo_struct) = CAST cl_abap_structdescr( lo_tab->get_table_line_type( ) ).

    " 表頭：有 DDIC 參照就用中長度欄位文字（SCRTEXT_M），否則用技術名
    DATA(lt_comp) = lo_struct->get_components( ).
    DATA(lt_head) = VALUE string_table( FOR c IN lt_comp ( CONV string( c-name ) ) ).
    IF iv_ddic_header = abap_true.
      LOOP AT lt_comp INTO DATA(ls_comp).
        DATA(lv_idx) = sy-tabix.
        IF ls_comp-type->kind <> cl_abap_typedescr=>kind_elem.
          CONTINUE.
        ENDIF.
        DATA(lo_elem) = CAST cl_abap_elemdescr( ls_comp-type ).
        IF lo_elem->is_ddic_type( ) = abap_true.
          DATA(ls_field) = lo_elem->get_ddic_field( sy-langu ).
          IF ls_field-scrtext_m IS NOT INITIAL.
            lt_head[ lv_idx ] = ls_field-scrtext_m.
          ENDIF.
        ENDIF.
      ENDLOOP.
    ENDIF.
    APPEND concat_lines_of( table = VALUE string_table( FOR h IN lt_head ( escape( iv_value = h iv_sep = iv_sep ) ) )
                            sep   = iv_sep ) TO rt_lines.

    " 資料列
    LOOP AT it_data ASSIGNING FIELD-SYMBOL(<ls_row>).
      DATA(lt_cells) = VALUE string_table( ).
      DO lines( lt_comp ) TIMES.
        ASSIGN COMPONENT sy-index OF STRUCTURE <ls_row> TO FIELD-SYMBOL(<lv_cell>).
        DATA(lv_txt) = COND string(
          WHEN cl_abap_typedescr=>describe_by_data( <lv_cell> )->type_kind = cl_abap_typedescr=>typekind_date
          THEN |{ CONV d( <lv_cell> ) DATE = ISO }|
          ELSE condense( val = |{ <lv_cell> }| ) ).
        APPEND escape( iv_value = lv_txt iv_sep = iv_sep ) TO lt_cells.
      ENDDO.
      APPEND concat_lines_of( table = lt_cells sep = iv_sep ) TO rt_lines.
    ENDLOOP.
  ENDMETHOD.

  METHOD escape.
    rv_out = iv_value.
    IF rv_out CA |{ iv_sep }"{ cl_abap_char_utilities=>cr_lf }|.
      rv_out = |"{ replace( val = rv_out sub = `"` with = `""` occ = 0 ) }"|.
    ENDIF.
  ENDMETHOD.
ENDCLASS.

" 使用：DATA(lt_lines) = lcl_csv=>to_lines( it_data = lt_spfli iv_sep = ',' ).
字串範本 |{ <lv_cell> }| 對數值欄位輸出的是「不帶千分位、小數點為 .」的格式，正是 CSV 需要的；但如果你改用 WRITE … TO，會套用使用者的數字格式設定，德式設定會輸出 1.234,50，匯進 Power BI 就變成錯的數字。欄位若有轉換常式（例如 MATNR 的 ALPHA、MEINS 的 CUNIT），要輸出外部格式請用 |{ lv ALPHA = OUT }| 或對應的 CONVERSION_EXIT 函數。

8. SAP Indirect Access：資料被第三方系統用到時的授權問題

素材 2 的標題是「下載 TXT 到 Power BI」，但內容其實是一篇提醒授權風險的文章。以下是重點摘要（用本書的話重新整理，非翻譯），出處：Rimini Street，Don't Get Tripped Up by SAP's Indirect Access License。

  • 定義：依 SAP 的說法，只要人、裝置或系統沒有直接登入 SAP，卻透過非 SAP 的前端、客製方案或第三方應用程式「使用到」ERP／S/4HANA 核心的處理能力，或由機器人、RPA、IoT 裝置等非人員自動存取核心，都屬於 Indirect Access（間接存取）。
  • 為什麼容易踩雷：企業導入 AI、IoT、行動 App 時，資料在系統之間流動，IT 部門未必意識到這些流動在授權上被怎麼認定，往往要到稽核才發現。
  • Diageo 案例：英國酒商 Diageo 原本由客服中心人員在 SAP ERP 下單，這些人員是有授權的使用者。2011 年起改用 Salesforce 的平台讓客戶自行下單、並開發拜訪管理 App，這些系統透過 SAP PI 與 ERP 互動。SAP 稽核後主張這些外部使用者也需要授權，在英國法院求償超過 5,000 萬歐元的授權費用，法院判 SAP 勝訴（和解金額未公開）。
  • 教訓：「中間隔了一層介面（PI、RFC、API）」不等於沒有使用 SAP；授權判斷看的是誰從核心得到處理結果，而不是誰按下登入鍵。
本節是技術人員的背景知識，不是法律意見。授權條件請以貴公司與 SAP 的合約為準；專案要新增第三方系統讀寫 SAP 資料之前，請先會同採購或 SAP 客戶經理確認授權模式。

9. Digital Access：2018 年起的「以文件計價」模式與 Power BI 的考量

Diageo 等案之後，SAP 在 2018 年提出 Digital Access 授權模式：間接存取不再依「使用者人數」計算，而是依第三方系統在 SAP 裡產生的文件數計價。SAP 公告的文件類型包括銷售單、發票、採購單、服務與維護文件、生產文件、品質管理文件、時間管理文件、物料文件、財務文件等九類（詳細定義與計數規則請以 SAP 官方文件與合約附件為準）。之後 SAP 也推出轉換方案，讓既有客戶把舊授權折抵成 Digital Access。

情境授權上的一般理解技術人員該做的事
有授權的使用者在 SAP 裡執行報表，自己下載 CSV 後用 Power BI 分析通常被視為直接使用；風險最低留下誰、何時、下載了什麼的紀錄
排程作業每天把資料寫成檔案，Power BI 自動取檔屬於資料匯出（讀取），依 Digital Access 的文件定義，單純讀取一般不計文件數；但各家合約用語不同在規格書寫明「只讀、不回寫」，列出匯出的表與欄位
Power BI／第三方工具即時連 SAP 讀資料（OData、RFC、DB 直連）是否構成 Indirect／Digital Access、是否違反資料庫授權，依合約與連線方式而定事前確認授權；DB 直連另有 HANA 授權限制（見第 10 節）
第三方系統回寫 SAP，建立訂單、發票、物料文件這正是 Digital Access 計數的核心情境估算每年文件量，交給採購評估成本
USMM（系統量測）與 SAP 提供的 Digital Access 評估工具可以估算系統內由介面建立的文件數。實際的工具名稱、SAP Note 與計數方式隨時間更新，請以 SAP Support Portal 最新資訊為準。

10. 把 SAP 資料給 Power BI 的四條路

做法怎麼做優點缺點／注意
① 檔案匯出本章第 3～6 節：CSV（UTF-8）放共用資料夾或 SharePoint，Power BI 透過 Gateway 排程重新整理最簡單、授權風險最低、SAP 權限可控（程式自己檢查 AUTHORITY-CHECK）非即時；檔案管理、增量與失敗重送要自己做
② OData（CDS 或 SEGW）CDS View 加 @OData.publish: true 或以 SEGW 建 Gateway 服務，在 /IWFND/MAINT_SERVICE 註冊；Power BI 用 OData 摘要連接器讀取即時、沿用 SAP 授權（DCL 存取控制）、欄位語意清楚大量資料時分頁與效能要設計；屬於第三方即時讀取，授權要確認
③ SAP HANA 直連Power BI 的 SAP HANA 連接器直接查 HANA 的 View效能最好、可 DirectQuery多數 S/4HANA 客戶是 HANA Runtime 授權，一般不允許第三方工具直接存取資料庫，必須是 Full Use 授權才考慮；繞過應用層也就繞過 SAP 的權限檢查

11. 課堂題目：找出與你最速配的同學——z-score 與歐氏距離

題目：每位同學有身高、興趣（1～9 的代碼）、年紀三個屬性，找出「整體最相近」的人。三個屬性單位不同（公分、代碼、歲），直接相減的話身高差 10 公分會完全蓋過年紀差 3 歲，所以要先標準化：

  • z-score：z = (x − 平均) ÷ 標準差。標準化後每個屬性平均為 0、標準差為 1，三者等權。
  • 歐氏距離：d(A,B) = √[(zh(A)−zh(B))² + (zi(A)−zi(B))² + (za(A)−za(B))²]，zh、zi、za 分別是身高、興趣、年紀的 z-score。距離最小（且不是自己）的人就是「最速配」。

合成資料（12 人，數值為編造）：

ID身高興趣年紀ID身高興趣年紀
S01165222S07161625
S02158724S08174222
S03172321S09183928
S04180827S10167426
S05169123S11171324
S06176530S12178729

母體標準差還是樣本標準差？

公式Excel本例身高
母體（population）σ = √[Σ(x−μ)² ÷ n]STDEV.P7.2667
樣本（sample）s = √[Σ(x−x̄)² ÷ (n−1)]STDEV（＝ STDEV.S）7.5899

原題 Excel 用的是 STDEV，也就是樣本標準差（除以 n−1）。全班就是要分析的全部對象，理論上用母體標準差比較合理；不過兩者只差一個常數倍數 √(n/(n−1))，所有 z-score 與距離同比例縮放，誰是最近鄰完全不變，只有距離的數值不同。程式要與 Excel 對得起來，就用樣本標準差，並把選擇做成參數。

「興趣」是代碼（1＝運動、2＝音樂……之類），不是真正的數值，代碼 2 和 3 不代表興趣比較接近。教學題為了簡單把它當數值；實務上類別型屬性應改用 one-hot 編碼或「相同＝0、不同＝1」的距離。

12. ABAP 實作一：資料、平均與標準差（REDUCE）

REPORT zbest_match.

PARAMETERS p_samp AS CHECKBOX DEFAULT 'X'.   " X＝樣本標準差（同 Excel STDEV）

TYPES: BEGIN OF ty_student,
         id       TYPE c LENGTH 3,
         height   TYPE p LENGTH 5 DECIMALS 1,
         interest TYPE i,
         age      TYPE i,
       END OF ty_student,
       tt_student TYPE STANDARD TABLE OF ty_student WITH KEY id.

TYPES: BEGIN OF ty_stat,
         mean TYPE f,
         sd   TYPE f,
       END OF ty_stat.

CLASS lcl_stat DEFINITION FINAL.
  PUBLIC SECTION.
    TYPES tt_f TYPE STANDARD TABLE OF f WITH EMPTY KEY.
    CLASS-METHODS calc
      IMPORTING it_x         TYPE tt_f
                iv_sample    TYPE abap_bool
      RETURNING VALUE(rs_st) TYPE ty_stat.
ENDCLASS.

CLASS lcl_stat IMPLEMENTATION.
  METHOD calc.
    DATA(lv_n) = lines( it_x ).
    IF lv_n < 2.
      RETURN.                                        " 少於 2 筆無法算樣本標準差
    ENDIF.
    rs_st-mean = REDUCE f( INIT s = CONV f( 0 ) FOR x IN it_x NEXT s = s + x ) / lv_n.
    DATA(lv_ss) = REDUCE f( INIT s = CONV f( 0 )
                            FOR x IN it_x
                            NEXT s = s + ( x - rs_st-mean ) * ( x - rs_st-mean ) ).
    rs_st-sd = sqrt( lv_ss / COND f( WHEN iv_sample = abap_true THEN lv_n - 1 ELSE lv_n ) ).
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  " 合成資料（實務上改成 SELECT 自訂表）
  DATA(lt_stu) = VALUE tt_student(
    ( id = 'S01' height = 165 interest = 2 age = 22 )
    ( id = 'S02' height = 158 interest = 7 age = 24 )
    ( id = 'S03' height = 172 interest = 3 age = 21 )
    ( id = 'S04' height = 180 interest = 8 age = 27 )
    ( id = 'S05' height = 169 interest = 1 age = 23 )
    ( id = 'S06' height = 176 interest = 5 age = 30 )
    ( id = 'S07' height = 161 interest = 6 age = 25 )
    ( id = 'S08' height = 174 interest = 2 age = 22 )
    ( id = 'S09' height = 183 interest = 9 age = 28 )
    ( id = 'S10' height = 167 interest = 4 age = 26 )
    ( id = 'S11' height = 171 interest = 3 age = 24 )
    ( id = 'S12' height = 178 interest = 7 age = 29 ) ).

  DATA(ls_h) = lcl_stat=>calc( it_x = VALUE #( FOR s IN lt_stu ( CONV f( s-height ) ) )   iv_sample = p_samp ).
  DATA(ls_i) = lcl_stat=>calc( it_x = VALUE #( FOR s IN lt_stu ( CONV f( s-interest ) ) ) iv_sample = p_samp ).
  DATA(ls_a) = lcl_stat=>calc( it_x = VALUE #( FOR s IN lt_stu ( CONV f( s-age ) ) )      iv_sample = p_samp ).

以樣本標準差計算，結果應為：身高平均 171.1667、標準差 7.5899；興趣平均 4.75、標準差 2.6328；年紀平均 25.0833、標準差 2.9375。可以貼進 Excel 用 AVERAGE／STDEV 對帳。

統計運算請用 TYPE f 或 decfloat34，不要用 TYPE i：lv_ss / lv_n 兩邊都是整數時，ABAP 會以整數型別計算並四捨五入（不是截斷），平均與標準差都會失真。另外標準差為 0（例如全班同年）時 z-score 會除以零，要先判斷 sd = 0 就把該屬性的 z 全設為 0。

13. ABAP 實作二：z-score、兩兩距離與最近鄰，用 CL_SALV_TABLE 輸出

  TYPES: BEGIN OF ty_out,
           id        TYPE c LENGTH 3,
           height    TYPE p LENGTH 5 DECIMALS 1,
           interest  TYPE i,
           age       TYPE i,
           z_height  TYPE p LENGTH 8 DECIMALS 4,
           z_interest TYPE p LENGTH 8 DECIMALS 4,
           z_age     TYPE p LENGTH 8 DECIMALS 4,
           best_id   TYPE c LENGTH 3,
           best_dist TYPE p LENGTH 8 DECIMALS 4,
         END OF ty_out.
  DATA lt_out TYPE STANDARD TABLE OF ty_out WITH EMPTY KEY.

  " lcl_z 的定義（見下一段）要放在 START-OF-SELECTION 之前；標準差為 0 時 z 一律為 0
  DATA(lo_z) = NEW lcl_z( ).
  lt_out = VALUE #( FOR s IN lt_stu
                    ( id         = s-id
                      height     = s-height
                      interest   = s-interest
                      age        = s-age
                      z_height   = lo_z->z( iv_x = CONV f( s-height )   is_st = ls_h )
                      z_interest = lo_z->z( iv_x = CONV f( s-interest ) is_st = ls_i )
                      z_age      = lo_z->z( iv_x = CONV f( s-age )      is_st = ls_a ) ) ).

  " 兩兩距離：n 很小，O(n²) 沒問題；距離相同時取 ID 較小者，結果才穩定
  LOOP AT lt_out ASSIGNING FIELD-SYMBOL(<me>).
    DATA(lv_best) = CONV f( -1 ).
    LOOP AT lt_out INTO DATA(ls_other) WHERE id <> <me>-id.
      DATA(lv_d) = sqrt( ( <me>-z_height   - ls_other-z_height )   ** 2
                       + ( <me>-z_interest - ls_other-z_interest ) ** 2
                       + ( <me>-z_age      - ls_other-z_age )      ** 2 ).
      IF lv_best < 0 OR lv_d < lv_best.       " 嚴格小於：同分保留先出現（ID 小）的人
        lv_best       = lv_d.
        <me>-best_id  = ls_other-id.
      ENDIF.
    ENDLOOP.
    <me>-best_dist = lv_best.
  ENDLOOP.

  TRY.
      cl_salv_table=>factory( IMPORTING r_salv_table = DATA(lo_alv)
                              CHANGING  t_table      = lt_out ).
      lo_alv->get_functions( )->set_all( abap_true ).
      lo_alv->get_columns( )->set_optimize( abap_true ).
      DATA(lo_cols) = lo_alv->get_columns( ).
      CAST cl_salv_column_table( lo_cols->get_column( 'ID' ) )->set_key( abap_true ).
      lo_cols->get_column( 'Z_HEIGHT' )->set_long_text( '身高 z' ).
      lo_cols->get_column( 'Z_INTEREST' )->set_long_text( '興趣 z' ).
      lo_cols->get_column( 'Z_AGE' )->set_long_text( '年紀 z' ).
      lo_cols->get_column( 'BEST_ID' )->set_long_text( '最速配' ).
      lo_cols->get_column( 'BEST_DIST' )->set_long_text( '距離' ).
      lo_alv->display( ).
    CATCH cx_salv_msg cx_salv_not_found INTO DATA(lx_salv).
      MESSAGE lx_salv->get_text( ) TYPE 'E'.
  ENDTRY.
CLASS lcl_z DEFINITION FINAL.
  PUBLIC SECTION.
    METHODS z
      IMPORTING iv_x        TYPE f
                is_st       TYPE ty_stat
      RETURNING VALUE(rv_z) TYPE f.
ENDCLASS.

CLASS lcl_z IMPLEMENTATION.
  METHOD z.
    rv_z = COND #( WHEN is_st-sd = 0 THEN 0
                   ELSE ( iv_x - is_st-mean ) / is_st-sd ).
  ENDMETHOD.
ENDCLASS.

15. 資料量大時：在 HANA 端算（AMDP 與 STDDEV）

12 個人在 ABAP 裡算毫無壓力；但若是「每個物料過去 24 個月的出貨量平均與標準差」（安全庫存、異常偵測），把數百萬筆拉到應用伺服器再 REDUCE 就不划算了，應該把聚合推到資料庫（Code Pushdown）。

  • ABAP SQL：聚合函數有 AVG、SUM、MIN、MAX、COUNT，沒有標準差（以 7.5x 為準；新版本是否增加請以 ABAP Keyword Documentation 的 aggregate functions 頁確認）。可以用 SUM(x)、SUM(x*x)、COUNT(*) 在 ABAP 端推算變異數，但要注意浮點誤差。
  • AMDP（SQLScript）：HANA SQL 提供 STDDEV（樣本）以及 STDDEV_POP、STDDEV_SAMP、VAR 等聚合函數。
CLASS zcl_stat_amdp DEFINITION PUBLIC FINAL CREATE PUBLIC.
  PUBLIC SECTION.
    INTERFACES if_amdp_marker_hdb.
    TYPES: BEGIN OF ty_matstat,
             matnr   TYPE matnr,
             cnt     TYPE i,
             avg_qty TYPE f,
             sd_samp TYPE f,
           END OF ty_matstat,
           tt_matstat TYPE STANDARD TABLE OF ty_matstat WITH EMPTY KEY.
    CLASS-METHODS issue_stat
      IMPORTING VALUE(iv_client) TYPE mandt
                VALUE(iv_from)   TYPE budat
                VALUE(iv_to)     TYPE budat
      EXPORTING VALUE(et_stat)   TYPE tt_matstat.
ENDCLASS.

CLASS zcl_stat_amdp IMPLEMENTATION.
  METHOD issue_stat BY DATABASE PROCEDURE FOR HDB LANGUAGE SQLSCRIPT
                    OPTIONS READ-ONLY USING matdoc.
    -- 每月出貨量（移動類型 601）→ 各物料月出貨量的平均與樣本標準差
    lt_month = SELECT matnr,
                      LEFT( budat, 6 ) AS yyyymm,
                      SUM( stock_qty ) AS qty
                 FROM matdoc
                WHERE mandt = :iv_client
                  AND bwart = '601'
                  AND budat BETWEEN :iv_from AND :iv_to
                GROUP BY matnr, LEFT( budat, 6 );

    et_stat = SELECT matnr,
                     COUNT( * )                        AS cnt,
                     TO_DOUBLE( AVG( ABS( qty ) ) )    AS avg_qty,
                     TO_DOUBLE( STDDEV( ABS( qty ) ) ) AS sd_samp
                FROM :lt_month
               GROUP BY matnr
              HAVING COUNT( * ) >= 2
               ORDER BY matnr;
  ENDMETHOD.
ENDCLASS.
請確認後再用：
  • STDDEV、STDDEV_POP、STDDEV_SAMP 是 HANA SQLScript 的函數名，不是 ABAP SQL；各 HANA 版本的支援請以 SAP HANA SQL Reference Guide 的 Aggregate Functions 章節確認。本書沒有把握的部分：HANA 的 STDDEV 在只有 1 筆時回傳 NULL 或 0，範例用 HAVING COUNT(*) >= 2 避開。
  • MATDOC 的 STOCK_QTY 有正負號，欄位名與 601 的方向請依系統實際資料確認。這裡只是示意寫法，條件用列舉（多筆 EQ）比用區間安全，若要納入多個移動類型請傳入清單，不要寫 BETWEEN。
  • AMDP 的 client 要自己處理（範例以 iv_client 傳入 sy-mandt）；新版可改用 AMDP OPTIONS CDS SESSION CLIENT 或讀 CDS View（版本門檻請查 ABAP Keyword Documentation）。
  • 樣本或母體的選擇與第 11 節相同：要跟 Excel 的 STDEV 對帳就用樣本（STDDEV／STDDEV_SAMP）。
