2. SAPscript 概觀：Form、列印程式與 Composer（Unit 1–2）

每家公司都要大量輸出版面固定、資料變動的文件：發票、交貨單、薪資單、支票、訂單確認、催款單。版面事先定義好，但要把地址、訂單明細這些資料「合併」進去，而且往往是大量批次列印。SAPscript 就是為這個需求設計的整合式文字輸入與表單列印工具，廣泛用在 FI、SD、MM 與線上文件。

教材列出的優點：PC 編輯器支援亞洲語言；表單可依國家產生不同地址格式、同時處理多幣別；所有單據統一設計風格；可在 SAP 支援的所有前端執行。

三個角色、一條流水線（Figure 14–15）：

元件負責什麼維護工具
Form（表單）定義文件的外觀與結構：頁面、視窗、段落／字元格式、預設文字模組與變數位置。改版面（搬字、換字型、改 Tab）只要改 FormSE71（舊選單 Tools → SAPscript → Form）
Print Program（列印程式）① 從資料庫或使用者輸入取資料 ② 選擇表單，決定印哪些文字元素、順序與次數 ③ 決定輸出裝置、份數、是否立即列印SE38／SE80（ABAP 報表或 Module Pool）
Composer（排版器）接收列印程式透過程式介面送來的每一個指令，依 Form 的版面排版、把符號換成實際值（系統日期、列印程式的資料），處理換行換頁、控制命令與長文字，最後產生 OTF（Output Text Format） 放進 Spool系統核心，不能改
背口訣：「程式管資料與順序，表單管長相，Composer 管排版與換頁。」SAPscript 的列印順序完全由列印程式呼叫 WRITE_FORM 的順序決定——這是它與 SmartForms 最大的不同（SmartForms 的流程邏輯在表單裡，列印程式只負責取資料）。

多數使用者只會碰到 SAPscript 的編輯器（例如在 VA02 輸入表頭文字、MM02 輸入採購長文字），這些長文字就是 SAPscript 文字，存在 STXH（表頭）／STXL（內容，壓縮存放）中，稍後 §16 用 READ_TEXT 讀取。

3. Form 元素（一）：Header、Pages、Windows、Page Windows（Unit 3）

一張典型表單（教材以 Booking Confirmation 訂位確認函為例，Figure 16）包含：收件地址、寄件人、本文、業務資料（訂位明細），而且文字與資料常常會跨好幾頁。SAPscript 用以下子物件組織表單：

  • Header（表頭資料）：Administrative Data 與 Basic Settings。
  • Page Layout：Pages、Windows、Page Windows（圖形 Form Painter 把三者合併成單一「Layout」元件）。
  • Paragraph Formats、Character Formats（§4）。
  • Documentation：表單各元件的說明長文字。

Header 必填項目

區塊內容重點
Administrative Data表單名稱、Client、語言、最後修改日、狀態狀態：New（剛建立，不能印）→ Active（Form → Activate 後才能印）→ Revised（改過存檔但未啟用；列印時仍用 Active 版）。Utilities → Reset 可撤銷未啟用的修改
Basic SettingsFirst Page、Default Paragraph、Tab 預設間距、Page Format（DINA4／LETTER）與方向、Lines/inch（LPI）、Characters/inch（CPI）、字型家族與大小First Page 與 Default Paragraph 是必填。單位用 CH（字元）或 LN（行）時會自動換算成 CPI／LPI

Header 設定只在「該元件沒有自己的設定時」才生效——例如某視窗沒指定預設段落，就用 Header 的 Default Paragraph。這是 SAPscript 的繼承規則：字元格式 → 段落格式 → 視窗預設段落 → Header。

Pages：頁面與頁序

一張表單可以有多個頁面。頁序是靜態決定的：Header 的 First Page ＋ 每頁屬性的 Next Page。沒有 Next Page，列印就在當頁結束。常見設計：FIRST（有抬頭、地址）→ Next Page = NEXT，NEXT 的 Next Page 指向自己。頁面屬性另有 Page Counter（遞增／不變／重設）與 Print Attributes（紙匣、單雙面）。

Windows 與 Page Windows：邏輯與實體分開

頁面上的各個輸出區塊叫 Window。同一個視窗可能出現在很多頁，所以 SAPscript 區分：

  • Window（邏輯視窗）：定義在整張表單層級，裡面的文字（Text Elements）對整張表單有效。
  • Page Window（頁面視窗）：把邏輯視窗「擺」到某一頁，給定位置（距上、距左）與大小（寬、高），單位可用 CM、MM、IN、PT、TW、CH、LN。同一個視窗在不同頁可以有不同位置大小。
視窗類型行為注意
MAIN放長度不定、會跨頁的本文（例如某客戶的所有訂位）。當頁滿了 SAPscript 自動在下一頁的 MAIN 繼續輸出各頁的 MAIN 位置、高度可不同，但寬度必須一致。要印標籤或多欄文件，可在同一頁建多個 Main Window（Edit → Windows → Create → Main window，編號 00、01…）
VAR每頁都會輸出該視窗的內容，大小位置可逐頁不同放不下的文字直接遺失，不會續到下一頁
CONST各頁尺寸相同Release 4.0 以前的類型，行為與 VAR 相同，新表單不必用

圖形 Form Painter 分成三塊：表單元素（例如頁面）、元素清單（該頁的視窗）、屬性清單（位置、大小、類型、預設段落）。Design／Text 按鈕切換設計模式（拖拉視窗）與文字模式；Options 可放大、設定格線與自動對齊。（依講義步驟整理）

在 S/4HANA 的 SAP GUI 裡，圖形 Form Painter 需要前端元件支援，部分新版 GUI／Web GUI 環境打不開時，改用 SE71 → Settings → Form Painter 取消勾選 Graphical Form Painter，退回英數模式（alphanumeric），功能完全相同。

4. Form 元素（二）：段落格式、字元格式、文件與測試列印（Unit 3）

Paragraph Formats（段落格式）

段落格式以 1–2 碼的鍵值命名（例如 P1、HD、IT），屬性分四組（Standard → Font → Tabs → Outline）：

屬性組內容
Standard左／右邊界、首行縮排、行距、段前／段後間距、對齊（左、右、置中、左右對齊 Justified）、Page Protection（段落內不自動換頁）、Next Paragraph Same Page
Font字型家族（Courier、Helvetica、Times）、字級（以 1/10 點為單位，120 = 12pt）、粗體、斜體、底線（間距、粗細、濃度）。家族留空、字級 0、粗斜底線設 Retain → 沿用 Header 的字型
Tabs可定義任意多個 Tab 位置，對齊方式：LEFT、RIGHT、CENTER、SIGN、DECIMAL。SIGN＝數字靠右並預留負號位置；DECIMAL＝小數點對齊。段落 Tab 之外仍有 Header 的標準 Tab
Outline自動編號：阿拉伯數字、羅馬數字、字母、固定符號；可建多層（1.、1.1、1.2）

Character Formats（字元格式）

用在段落內的一段字串，語法 <B>粗體</>。標準屬性：

  • Protected：整段字串不斷行，一定印在同一行。
  • Hidden：不列印。
  • Superscript／Subscript：上移／下移半行。
  • Barcode：把字串編碼成條碼列印（條碼種類在 SE73 維護，見 §15）。

字型屬性同段落，用 on/off 選鈕明確指定時會覆蓋段落與 Header 設定；選 Retain 或留空則沿用。

Documentation 與 Test Print

  • Form documentation 按鈕列出所有元件（頁、視窗、文字元素），可逐一寫說明長文字。改標準表單的副本時，把「改了什麼、為什麼」寫在這裡，是對下一任維護者最好的交代。
  • Utilities → Test print：不執行列印程式直接預覽。但它不等於實際輸出：程式符號顯示為一串 X、具名文字元素的順序與實際不同、控制命令會被印出來。4.6C 起預覽可顯示圖形。
真正驗證表單一定要用列印程式＋預覽（OPEN_FORM 的 OPTIONS-TDPREVIEW = 'X'，或 NACE 訊息的 Print Preview）。Test print 只適合快速檢查視窗位置與框線。

6. 符號（Symbols）與格式選項（Unit 5）

符號是排版當下才填值的佔位符，寫成 &名稱&。規則：不分大小寫、名稱不能有空白、整個符號必須在同一行內，不可跨行。可用 Include → Symbols 選取。四種符號的差別在「值從哪裡來」：

類型值的來源範例維護位置
System symbolsSAP 系統自動提供，任何文件可用&DATE&、&TIME&、&PAGE&、&NEXTPAGE&、&SAPSCRIPT-FORMPAGES&（本份文件總頁數）、&SAPSCRIPT-JOBPAGES&、&ULINE&、&SPACE&、&DEVICE&表 TTXSY（4.5A 起可查）
Standard symbols應用面定義、依語言維護的固定詞句&SGDH&（開頭稱謂 Dear Sir/Madam）、&MFG&（結尾敬語 Yours faithfully）表 TTDTG（SE71 → Settings／延伸表格維護）
Program symbols列印程式的資料物件&GS_BOOKING-FLDATE&、&VBDKR-VBELN&列印程式（Include → Symbols → Program Symbols 可列出；Goto → Print Program → Symbol Definition 跳到定義處）
Text symbols只在該文字模組內有效，以 DEFINE 指定/: DEFINE &COMPANY& = '台灣分公司'文字本身（DEFINE 的值隨文字存檔；從 Include → Symbols → Text symbols 給的值只是暫時的）
教材過時處修正：講義說程式符號要「在 ABAP Dictionary 定義、並在列印程式用 TABLES 宣告」。這是 R/3 時代的寫法。實際上 Composer 讀的是列印程式的全域資料物件，用 DATA 宣告的全域結構（型別參照 DDIC）一樣可用，而且欄位會依 DDIC 的屬性（轉換常式、小數位、幣別參考）格式化。依本圖書館規範新程式不再使用 TABLES。真正要記住的坑是：符號只能讀「全域」資料——方法裡的區域變數、類別屬性，Composer 都看不到，所以即使列印程式用類別寫，給表單的工作區仍必須是全域 DATA（§9 範例）。

7. 控制命令（一）：文字模組、DEFINE、地址與日期格式（Unit 5）

控制命令在 Tag 欄以 /: 開頭，由 Composer 解讀，用來：插入文字、給文字符號賦值、強制或禁止換頁、重設大綱編號、依條件輸出。一個命令不可超過一行。

Text Modules 與 SO10 標準文字

表單常有固定文字塊：公司頁尾（銀行帳號、董事名單）、物料清單說明、法律條款。這些應獨立存放，可在多張表單共用、改一處全部生效。文字的唯一鍵是 Client ＋ NAME ＋ LANGUAGE ＋ OBJECT ＋ ID：

  • Text Object：文字的業務情境，例如 TEXT（標準文字）、MATERIAL（物料文字）、VBBK（銷售單表頭）、EKKO（採購單表頭）。
  • Text ID：物件下的細分類，例如標準文字用 ST、物料的銷售文字 0001。
  • 文字物件與 ID 在 SE75 維護（表 TTXOB／TTXID），並設定儲存模式（§16）。
  • OBJECT = TEXT 的標準文字用 SO10（舊選單 Tools → SAPscript → Standard text）維護。
/*  ① 插入標準文字：頁尾（公司資訊），用表單的段落 FT 當預設格式

/*  ② 插入銷售單表頭文字（單據別長文字），名稱用程式符號組出

  • DEFINE：值「錨定」在文字裡，下次打開仍在；同一符號可多次 DEFINE 改值。
  • ADDRESS … ENDADDRESS：依 COUNTRY 參數的郵政規則排版，參考欄位在結構 ADRS；Composer 內部呼叫函數 ADDRESS_INTO_PRINTFORM。教材強調：一定要給 FROMCOUNTRY，否則寄件國被當成收件國，例如 COUNTRY = 德國且沒給 FROMCOUNTRY 時，郵遞區號會印成「D-80801」這種國際格式。實務上若有位址號碼（ADRNR），可改用 ADDRESSNUMBER 參數直接從中央地址管理（ADRC）讀。

8. 控制命令（二）：換頁、條件、框線、PERFORM 與除錯（Unit 5）

換頁與頁面保護

  • MAIN 滿了 SAPscript 會自動換頁。要手動換頁用 /: NEW-PAGE，可指定下一頁 /: NEW-PAGE NEXT；不指定就用 Form 定義的 Next Page。
  • /: PROTECT … /: ENDPROTECT：夾住的行一定印在同一頁。當頁放得下就照常印；放不下則 PROTECT 等同 NEW-PAGE，整塊移到下一頁。合計列、簽核欄一定要包。

條件輸出 IF／CASE

比較運算子：= EQ、< LT、> GT、<= LE、>= GE、<> NE，邏輯 NOT AND OR；可用 ELSE、ELSEIF。CASE 只能對「一個符號」做多值等值判斷。

SAPscript 的比較是「文字比較」，不是數值比較。教材的例子：DEFINE &VAR1& = '2'、DEFINE &VAR2& = '10'，直接寫 IF &VAR1& > &VAR2& 會成立（因為字元 '2' > '1'）。講義的解法是加長度 &VAR1(2)&；但要注意長度只會在右邊補空白，'2 ' 與 '10' 比較時靠的是對齊方式，數字要可靠比較，應同時用固定長度＋右對齊（例如 &VAR1(R5)&），或更好的做法——在列印程式算好一個旗標欄位再給表單判斷。這和 Casper 的第二條經驗同源：字典序不是業務語意，區間比較（BT）在號碼有前導零、長度不一時一樣會出錯，能列舉就列舉。

/:  ELSE

/:  CASE &GS_BOOKING-CLASS&

  • BOX [XPOS] [YPOS] [WIDTH] [HEIGHT] [FRAME] [INTENSITY]：以 POSITION 設定的原點為基準，在 (XPOS, YPOS) 畫寬 WIDTH、高 HEIGHT 的框；FRAME 是線粗，INTENSITY 是底色灰階百分比。不給位置大小就是整個視窗。
  • POSITION [XORIGIN] [YORIGIN] [WINDOW] [PAGE]：設定 BOX 的原點；WINDOW／PAGE 表示以目前視窗／頁面的左上角為原點。
  • SIZE [WIDTH] [HEIGHT] [WINDOW] [PAGE]：設定 BOX 預設的寬高。

PERFORM：不改列印程式也能多抓資料

標準列印程式沒讀你要的欄位（例如客戶 E-mail、倉管員名稱）時，不要先改列印程式——SAPscript 可以用 PERFORM 命令呼叫客製程式裡的副程式，讀完資料再傳回表單。表單端寫法如下（以行編輯器呈現）：

Tag內容
/:PERFORM GET_CUSTOMER_EMAIL IN PROGRAM ZBC460_SCRIPT_EXITS
/:USING &GS_CUSTOMER-ID&
/:CHANGING &LV_EMAIL&
/:ENDPERFORM
P1&'E-mail：'LV_EMAIL&

介面規則：被呼叫的副程式必須用結構 ITCSY（兩個欄位 NAME、VALUE）的內表接參數；USING 列出的符號（名稱與已格式化的值）進 IN_TAB，CHANGING 列出的符號以文字符號的身分從 OUT_TAB 收回。

REPORT zbc460_script_exits.
*&---------------------------------------------------------------------*
*& 給 SAPscript 表單「/: PERFORM」命令呼叫的副程式集（見上表）。
*& 介面由 SAPscript 規定（TABLES ... STRUCTURE itcsy），所以這裡是
*& 本圖書館「新程式不用 FORM」規範的合法例外；內容照樣寫現代 ABAP。
*&---------------------------------------------------------------------*
FORM get_customer_email TABLES in_tab  STRUCTURE itcsy
                               out_tab STRUCTURE itcsy.

  " IN_TAB-NAME 是符號名（大寫、不含 &），VALUE 是『已格式化』的字串（CHAR255）
  READ TABLE in_tab INTO DATA(ls_in) WITH KEY name = 'GS_CUSTOMER-ID'.
  IF sy-subrc <> 0.
    RETURN.
  ENDIF.

  " 格式化後的值可能有千分位、去零、左右空白 → 先還原成內部格式
  DATA(lv_custid) = CONV s_customer( condense( ls_in-value ) ).

  SELECT SINGLE email
    FROM scustom
    WHERE id = @lv_custid
    INTO @DATA(lv_email).

  READ TABLE out_tab ASSIGNING FIELD-SYMBOL(<ls_out>) WITH KEY name = 'LV_EMAIL'.
  IF sy-subrc = 0.
    <ls_out>-value = COND #( WHEN sy-dbcnt = 1 THEN lv_email ELSE `` ).
  ENDIF.
ENDFORM.
PERFORM 的三個坑：① USING 傳進來的是格式化後的字串，金額會帶千分位（依使用者設定可能是 1.234,50），數量會有小數點，直接 CONV 成數值型別會 DUMP；要嘛傳沒有格式的欄位，要嘛自己去掉分隔符。② OUT_TAB 名稱一律大寫、不含 &。③ 每印一次文字元素就執行一次，放在 ITEM_LINE 裡就是「每一行明細打一次資料庫」——大量列印時請改在列印程式一次讀好，或在副程式裡做靜態快取。

9. 列印程式（一）：函數模組與完整範例（Unit 6）

列印程式（ABAP 報表或 Module Pool）負責：從資料庫取資料、定義處理邏輯（文字元素的順序與重複）、選定表單、選定輸出裝置（印表機、螢幕、傳真、E-mail）與列印屬性（立即輸出、份數、頁範圍）。Composer 則負責換行換頁、控制命令與符號格式化、長文字插入、產生 Spool 的頁面描述（OTF）。

函數模組用途重點參數
OPEN_FORM開始表單列印，必須最先呼叫FORM、LANGUAGE、DEVICE（PRINTER／TELEFAX／SCREEN）、DIALOG、OPTIONS（結構 ITCPO）
START_FORM在同一個 Spool 裡開始一份表單（可換表單）FORM、LANGUAGE、STARTPAGE
WRITE_FORM輸出文字元素ELEMENT、WINDOW（預設 MAIN）、TYPE（TOP／BODY／BOTTOM，預設 BODY）、FUNCTION（SET／APPEND／DELETE，預設 SET）
WRITE_FORM_LINES直接把一個 TLINE 內表當文字輸出HEADER、LINES、WINDOW、TYPE、FUNCTION
CONTROL_FORM從程式送控制命令COMMAND（不含 /:）
END_FORM結束一份表單（不結束列印）RESULT
CLOSE_FORM結束列印，回傳結果RESULT（結構 ITCPP）、OTFDATA（ITCOO）

DEVICE：PRINTER 經 Spool 列印；TELEFAX 經 Spool 或 SAPconnect 傳真；SCREEN 只在 GUI 顯示、不能列印。DIALOG = 空白時不跳出印表機參數對話框（背景作業、NACE 輸出必須如此）。

ITCPO 常用欄位：TDDEST（輸出裝置）、TDIMMED（立即列印）、TDNEWID（新 Spool）、TDDELETE（列印後刪除）、TDCOPIES（份數）、TDPREVIEW（預覽）、TDGETOTF（回傳 OTF 不列印）、TDDATASET／TDSUFFIX1／TDSUFFIX2（Spool 名稱）、TDCOVER（封面頁）、TDRECEIVER（收件人）、TDARMOD（歸檔模式）。ITCPP 則回傳 TDSPOOLID（Spool 編號）、TDPAGES（頁數）、實際使用的裝置等。

下面是本章範例表單 ZBC460_BOOKING（視窗 HEADER、ADDRESS、MAIN、FOOTER）的完整列印程式。它照 BC460 的航空訂位情境，把客戶的訂位印成一份訂位確認函：

REPORT zbc460_booking_print.
*&---------------------------------------------------------------------*
*& SAPscript 程式符號只能讀【全域】資料物件：給表單用的工作區一定要
*& 宣告在這裡（不能放在方法的區域變數或類別屬性）。不再使用 TABLES。
*&---------------------------------------------------------------------*
DATA: gs_customer TYPE scustom,             " 表單：&GS_CUSTOMER-NAME&
      gs_booking  TYPE sbook,               " 表單：&GS_BOOKING-FLDATE&
      gv_total    TYPE sbook-loccuram,      " 表單：&GV_TOTAL&
      gv_currency TYPE sbook-loccurkey.     " 表單：&GV_CURRENCY&

PARAMETERS: p_cust TYPE scustom-id OBLIGATORY,
            p_form TYPE tdform DEFAULT 'ZBC460_BOOKING',
            p_dest TYPE rspopname,
            p_prev AS CHECKBOX DEFAULT abap_true.
SELECT-OPTIONS s_fldate FOR gs_booking-fldate.

CLASS lcl_print DEFINITION FINAL.
  PUBLIC SECTION.
    METHODS run.
  PRIVATE SECTION.
    DATA mt_booking TYPE STANDARD TABLE OF sbook WITH EMPTY KEY.
    METHODS get_data   RETURNING VALUE(rv_ok) TYPE abap_bool.
    METHODS open_form  RETURNING VALUE(rv_ok) TYPE abap_bool.
    METHODS print_body.
    METHODS close_form.
ENDCLASS.

CLASS lcl_print IMPLEMENTATION.
  METHOD run.
    IF get_data( ) = abap_false.
      MESSAGE |客戶 { p_cust ALPHA = OUT } 在指定期間沒有有效訂位| TYPE 'S' DISPLAY LIKE 'W'.
      RETURN.
    ENDIF.
    IF open_form( ) = abap_true.
      print_body( ).
      close_form( ).
    ENDIF.
  ENDMETHOD.

  METHOD get_data.
    SELECT SINGLE id, name, form, street, postcode, city, country, langu, email
      FROM scustom
      WHERE id = @p_cust
      INTO CORRESPONDING FIELDS OF @gs_customer.
    IF sy-subrc <> 0.
      RETURN.
    ENDIF.

    " HANA 沒有預設排序：明細順序一定要 ORDER BY，否則每次印出來順序不同
    SELECT carrid, connid, fldate, bookid, class, loccuram, loccurkey, passname
      FROM sbook
      WHERE customid  = @p_cust
        AND fldate    IN @s_fldate
        AND cancelled = @abap_false
      ORDER BY fldate, carrid, connid, bookid
      INTO CORRESPONDING FIELDS OF TABLE @mt_booking.

    rv_ok = xsdbool( mt_booking IS NOT INITIAL ).
  ENDMETHOD.

  METHOD open_form.
    DATA(ls_options) = VALUE itcpo( tddest    = p_dest
                                    tdpreview = p_prev
                                    tdimmed   = abap_true
                                    tdnewid   = abap_true
                                    tdcopies  = 1 ).
    CALL FUNCTION 'OPEN_FORM'
      EXPORTING
        device   = 'PRINTER'
        dialog   = xsdbool( p_dest IS INITIAL )   " 沒指定印表機才跳對話框
        form     = p_form
        language = COND syst_langu( WHEN gs_customer-langu IS NOT INITIAL
                                    THEN gs_customer-langu ELSE sy-langu )
        options  = ls_options
      EXCEPTIONS
        canceled = 1
        device   = 2
        form     = 3
        options  = 4
        unclosed = 5
        OTHERS   = 6.
    CASE sy-subrc.
      WHEN 0.
        rv_ok = abap_true.
      WHEN 1.
        MESSAGE '使用者取消列印' TYPE 'S'.
      WHEN 3.
        MESSAGE |表單 { p_form } 不存在或未啟用（SE71 Form → Activate）| TYPE 'S' DISPLAY LIKE 'E'.
      WHEN OTHERS.
        MESSAGE |OPEN_FORM 失敗，sy-subrc = { sy-subrc }| TYPE 'S' DISPLAY LIKE 'E'.
    ENDCASE.
  ENDMETHOD.

  METHOD print_body.
    " ① 非 MAIN 視窗：ADDRESS 視窗內容整個換成 ADDRESS 元素
    CALL FUNCTION 'WRITE_FORM'
      EXPORTING element  = 'ADDRESS'
                window   = 'ADDRESS'
                function = 'SET'
      EXCEPTIONS OTHERS  = 1.

    " ② MAIN：開場白（WINDOW=MAIN、TYPE=BODY 是預設值）
    CALL FUNCTION 'WRITE_FORM'
      EXPORTING element = 'INTRO'
      EXCEPTIONS OTHERS = 1.

    " ③ 第一頁表頭印在 BODY，同時設進 TOP → 換頁後自動重印表頭
    CALL FUNCTION 'WRITE_FORM'
      EXPORTING element = 'ITEM_HEADER'
      EXCEPTIONS OTHERS = 1.
    CALL FUNCTION 'WRITE_FORM'
      EXPORTING element  = 'ITEM_HEADER'
                type     = 'TOP'
                function = 'SET'
      EXCEPTIONS OTHERS  = 1.

    " ④ 明細：每圈把資料放進全域工作區，再叫 Composer 印 ITEM_LINE
    CLEAR gv_total.
    LOOP AT mt_booking INTO gs_booking.
      gv_total = gv_total + gs_booking-loccuram.   " 7.54+ 可寫 gv_total += ...
      CALL FUNCTION 'WRITE_FORM'
        EXPORTING element = 'ITEM_LINE'
        EXCEPTIONS OTHERS = 1.
    ENDLOOP.

    " ⑤ 明細結束 → 刪除 TOP 表頭（從下一頁起生效）
    CALL FUNCTION 'WRITE_FORM'
      EXPORTING element  = 'ITEM_HEADER'
                type     = 'TOP'
                function = 'DELETE'
      EXCEPTIONS OTHERS  = 1.

    " ⑥ 合計：不同航空公司的當地幣別可能不同，混幣別就不能加總
    gv_currency = VALUE #( mt_booking[ 1 ]-loccurkey OPTIONAL ).
    DATA(lv_mixed) = xsdbool( REDUCE i( INIT n = 0
                                        FOR b IN mt_booking
                                        WHERE ( loccurkey <> gv_currency )
                                        NEXT n = n + 1 ) > 0 ).
    IF lv_mixed = abap_false.
      CALL FUNCTION 'WRITE_FORM'
        EXPORTING element = 'TOTAL'
        EXCEPTIONS OTHERS = 1.
    ENDIF.
  ENDMETHOD.

  METHOD close_form.
    DATA ls_result TYPE itcpp.
    CALL FUNCTION 'CLOSE_FORM'
      IMPORTING
        result                   = ls_result
      EXCEPTIONS
        unopened                 = 1
        bad_pageformat_for_print = 2
        OTHERS                   = 3.
    IF sy-subrc = 0 AND ls_result-tdspoolid IS NOT INITIAL.
      MESSAGE |已產生 Spool { ls_result-tdspoolid }，共 { ls_result-tdpages } 頁| TYPE 'S'.
    ENDIF.
  ENDMETHOD.
ENDCLASS.

10. 列印程式（二）：MAIN 的 TOP／BODY／BOTTOM、非 MAIN 視窗、Composer 換頁（Unit 6）

MAIN 視窗的三個區域

MAIN 可分成 TOP、BODY、BOTTOM 三區。TOP、BOTTOM 的高度由其內容決定，佔用的空間從 BODY 扣掉；功能類似 ABAP 清單的頁首頁尾。三區內容都能在列印中動態設定、變更，SAPscript 會在每一頁有 MAIN 的地方自動輸出目前的 TOP／BOTTOM。

情境WRITE_FORM 參數生效時機與注意
MAIN 輸出本文ELEMENT、WINDOW = MAIN（預設）、TYPE = BODY（預設），FUNCTION 無關當頁 MAIN 滿就自動換頁
設定表頭TYPE = 'TOP'、FUNCTION = 'SET'BODY 還沒有內容 → 當頁就印；BODY 已有內容 → 下一頁才開始印
刪除表頭TYPE = 'TOP'、FUNCTION = 'DELETE'下一頁起生效；BODY 已有內容的當頁無法撤回
非 MAIN 視窗附加WINDOW = 視窗名、FUNCTION = 'APPEND'，TYPE 無關放不下的內容遺失，不會跨頁
非 MAIN 視窗取代FUNCTION = 'SET'（預設）該視窗原內容整個換掉
非 MAIN 視窗刪除FUNCTION = 'DELETE'刪掉指定元素

教材 Figure 98 解釋為什麼 §9 範例要把表頭「先印在 BODY，再設到 TOP」：很多應用表單第一頁先有稱謂與開場白，表頭要緊接在開場白後面，所以第一頁只能印在 BODY；從第二頁起才由 TOP 自動重印。

Composer 的運作規則（Figure 102）

  • MAIN 視窗主導換頁。非 MAIN 視窗的文字元素要等到換頁時才處理——所以「頁尾合計」若放在非 MAIN 視窗，要在換頁前把值準備好。
  • 換頁觸發只有兩種：MAIN 溢位（自動）、MAIN 中的 NEW-PAGE（手動）。
  • 非 MAIN 視窗開頭的預設文字元素，在視窗被處理時印一次；但 MAIN 開頭的預設文字元素，換頁後不會在下一頁的 MAIN 重印。

多份表單合併成一個 Spool：START_FORM／END_FORM

12. Styles：SE72 樣式（Unit 7）

Style 是獨立於表單的一組段落格式＋字元格式定義。系統內建多種樣式（例如給 E-mail、線上文件用的）。用途：

  • SO10 標準文字、長文字可在編輯器 Format → Change Style… 指定樣式，不必依附某張表單就有格式可用。

13. 下一代：SmartForms、Adobe Forms 與 S/4HANA Output Management（Unit 8）

講義 Unit 8 的重點：

  • SAP Smart Forms 用來簡化、現代化 SAPscript 的表單製作。在 SAP Form Builder（SMARTFORMS）中維護：左側導覽樹（節點＝頁、視窗、圖形…，下方可顯示欄位清單）、中間維護畫面（各頁籤屬性、文字編輯器、Table Painter）、右側 Form Painter（可 Utilities → Form Painter on/off）。
  • 啟用時系統自動產生函數模組，由資料擷取程式呼叫——不再需要維護「列印程式的排版邏輯」。SAPscript 的控制命令被節點概念取代；SAPscript 要在表單與列印程式做一大堆工作才能印的複雜表格，SmartForms 用 Table 節點（動態格線）就能做到；另支援 XML 輸出。
  • Table vs Template：兩者都用 Table Painter 設計、都有多種行類型；Table 的長度與版面到執行期才決定（依讀到的筆數），Template 則在 Form Painter 完全固定，儲存格數量不可變，多用於外部表單的固定格子。
  • The Future of SAPscript：SAPscript 可與 SmartForms 並存、SAP 仍支援，但不再發展，長期應轉成 SmartForms。4.6C 起 SMARTFORMS 的 Utilities 選單可「Migrate SAPscript form」，但表格等原本靠列印程式完成的邏輯，遷移後必須自己重做。
  • SAP Interactive Forms by Adobe（NetWeaver 2004 起）：離線情境（產生可填寫的 PDF，填完送回系統自動抽取資料）、線上情境（嵌入 Web Dynpro 等 Web 應用）、列印情境（概念同 SmartForms，但架構不同）。設計時在 SFP／SE80 建 Interface（定義程式可傳入的資料、全域資料與初始化程式碼）與 Form（Context 選用介面的哪些部分、加入文字模組與圖片；Layout 在 Adobe LiveCycle Designer 設計，Script Editor 可用 JavaScript 或 FormCalc），啟用後同樣產生函數模組。執行期由 Adobe Document Services（ADS）透過 SOAP Web Service 負責渲染。
講義過時處修正：① 講義說「PPF 是 Output Control（訊息控制）的後繼者」、「ADS 必須部署在 J2EE Engine」。在 S/4HANA 裡，SAP 推出的是以 BRF+ 決定輸出的 S/4HANA Output Management（又稱 Output Control，設定用 OPD 與 SPRO → Cross-Application Components → Output Control），PPF 仍用在 CRM、部分 TM／EWM 情境；ADS 則可用 on-premise Java 堆疊，或改用雲端的 SAP Forms Service by Adobe（BTP）。② 講義 Adobe 設計工具寫 Adobe LiveCycle Designer，新版名稱為 Adobe LiveCycle Designer for SAP／Adobe Experience Manager Forms Designer，概念相同。

14. 修改標準表單與列印程式（Unit 9）

表單可以由客戶單據自動觸發列印，例如客戶下單 → 系統建立訂單 → 存檔時產生訂單確認並寄給客戶。表單名稱與列印程式在 Customizing 中指定給應用元件（§17）；要換表單或列印程式，也是在 Customizing 改。

SAP 為所有應用提供標準表單與對應列印程式，大多數需求只改表單就夠，不必動列印程式。講義的判斷表（Table 1）：

需求是否要改 SAP 列印程式
結構性變更（新增視窗處理順序、改頁序邏輯）必須改
需要新的文字元素必須改（誰來呼叫 WRITE_FORM？）
只是用同一列印程式印（版面、字型、位置、固定文字）不必改
需要額外表單可視需要改
需要額外資料可視需要改（優先考慮 PERFORM）
講義此表原文最後一列重複了「Structural changes / Change necessary」，應是排版重複，已合併；「Print program will be used to print」一列語意不完整，依上下文應指「沿用原列印程式列印（只改表單）」。

改法的優先順序（與 Casper 的第三條經驗一致）

  1. 先看標準設定：Customizing 能不能換一張現成的標準表單？輸出條件（NACE 條件記錄）能不能解決？
  2. 只改表單：SE71 → Utilities → Copy from Client，把標準表單（預設來源 client 000）複製成 Z/Y 名稱，改副本。
  3. 表單＋PERFORM：缺資料時在表單用 PERFORM 呼叫 Z 程式的副程式（§8）。
  4. Customer Exit／Include：部分標準列印程式預留了給客戶用的 Include（升級不會覆蓋），例如 SD 單據列印程式的使用者出口。
  5. 複製列印程式：結構真的變了才把列印程式複製成 Z/Y（SE38 Copy，連同 Include），並在 Customizing 指向新程式。
  6. 修改 SAP 標準：Modification，升級時不受保護——幾乎沒有理由走到這一步。

動手前先盤點：到底要哪些額外欄位？在目前使用的資料表裡嗎？還是要讀新表？那些欄位真的有資料嗎？並在 Customizing 記下目前實際使用的表單與程式。改完後把新表單／程式登錄回 Customizing，一定要測試。增強的完整觀念見 5-14 章 BC425、3-3 章、3-4 章。

Client 相依與傳輸

  • SAPscript 表單、樣式、文字都是 Client 相依。但 client 000 有特殊地位：目前 Client 找不到表單時，系統會自動去 client 000 找；SAP 標準表單全部放在 client 000。
  • 傳輸：表單與樣式透過 Workbench Organizer（WBO），第一次存檔即要求傳輸單（物件 R3TR FORM、R3TR STYL）。匯出時從釋放傳輸單的那個 Client 取物件，所以要確定物件存在於該 Client。
  • 標準文字（SO10）等 SAPscript 文字不會自動進傳輸單，要手動加入 Customizing 傳輸單：物件 R3TR TEXT TEXT,ZBC460_FOOTER,ST,M（格式 R3TR TEXT <OBJECT>,<NAME>,<ID>,<語言>）；或用報表 RSTXTRAN 把標準文字掛進傳輸單（最常用）。
  • 跨系統搬移（沒有傳輸路徑時）可用 RSTXSCRP 把表單／樣式／標準文字匯出成本機檔案再匯入。
SO10 的標準文字常被當成「主資料」直接在 PRD 修改（例如公司地址、銀行帳號），結果 DEV／QAS 與 PRD 不一致，下次傳輸又把舊內容蓋回去。請與業務約定：標準文字要嘛一律走傳輸，要嘛明確劃為「PRD 直接維護」並從傳輸流程排除，不要兩種混用。

15. 維護：系統字型、印表機字型、條碼與 Print Controls（Unit 10）

所有 SAPscript 用的字型與條碼都在字型維護交易 SE73（舊選單 Tools → Form Printout → Administration → Font）管理：

  • Font Family：字型家族名稱，標示為等寬（non-proportional）或比例字（proportional）。
  • System Fonts：表單與樣式可選用的字型，與輸出裝置無關。
  • Printer Fonts：各裝置類型（印表機、螢幕、傳真…）實際可用的字型。
  • SAPscript 會自動把文件中的系統字型轉換成印表機字型；每個家族可設替代字型。可檢視「某系統字型在所有裝置類型上的轉換」或「某裝置類型上所有系統字型的轉換」。
  • 印表機驅動程式把 OTF 轉成印表機能懂的控制序列，控制序列多半以 Print Controls 定義；驅動程式在 Spool 管理 SPAD 指派給裝置類型。

條碼：字元格式的 Barcode 屬性讓 SAPscript 輸出條碼。System Bar Codes 與裝置無關；支援條碼的印表機類型用 Printer Bar Codes 對應到 Print Control。列印時依序送出：條碼前置 Print Control（prefix）→ 條碼資料（例如 8 位數）→ 條碼後置 Print Control（suffix）。

Print Control 是用符號名稱表示的裝置控制序列，在 SPAD（舊選單 Tools → CCMS → Print → Spool Administration）依裝置類型維護；字型維護裡只填 Print Control 的符號名稱。

新條碼需求（QR Code、DataMatrix、GS1-128）不要在 SAPscript 裡硬做：SAPscript 的條碼依賴印表機本身的條碼能力或條碼 DIMM；SmartForms 在較新的 NetWeaver 版本支援「新條碼技術」（在 SE73 建 System Bar Code 時選新技術，含 QR Code／DataMatrix，適用版本請查相關 SAP Note），Adobe Forms 則原生支援各種 2D 條碼。這也是「要大改就換 Adobe」的典型理由。

16. 文字 API：READ_TEXT、SAVE_TEXT 與更新機制（Unit 11 Lesson 1）

SAPscript 程式介面是一組建立、修改、管理 SAPscript 文字的函數模組：用編輯器初始化與修改文字、泛用搜尋、讀取／儲存／刪除、在資料庫中更新。每份文字由文字表頭 THEAD（管理資料：OBJECT、NAME、ID、SPRAS…）與行內表 TLINE（TDFORMAT＝Tag 欄、TDLINE＝內容）組成。

函數模組用途講義重點
INIT_TEXT初始化新文字的 HEADER／LINES只 CLEAR HEADER 不夠，一定要用 INIT_TEXT
EDIT_TEXT呼叫長文字編輯器可控制顯示／修改模式；按 Save 會自動呼叫 SAVE_TEXT，用 SAVE = SPACE 關閉
SELECT_TEXT依鍵值找出符合的文字表頭清單可用 * 泛用搜尋；文字依 Client 存放
READ_TEXT從文字記憶體或資料庫讀到 HEADER／LINESOBJECT、NAME、ID、LANGUAGE 四鍵不可泛用
SAVE_TEXT存到文字記憶體或資料庫回傳 FUNCTION：I 新增、U 修改、D 刪除
DELETE_TEXT刪除可泛用；依文字物件立即刪除或記在文字記憶體
COMMIT_TEXT把文字記憶體寫入更新程序執行後文字記憶體清空

儲存模式：V（Update）與 D（Direct）

  • 儲存模式是整個文字物件（text class）的屬性：V＝透過更新程序、D＝直接寫資料庫不經更新；由開發者在 SE75（舊選單 Tools → SAPscript → Administration → Settings）設定。
  • V 模式下所有函數都在文字記憶體中運作。要真正寫進資料庫必須同時：呼叫 COMMIT_TEXT，再執行 ABAP COMMIT WORK。兩者缺一，所有文字變更都遺失。COMMIT_TEXT 不能取代 COMMIT WORK；每個 LUW 只能各呼叫一次，而且要放在流程最後。
  • 大量處理（傳輸、Client 複製、組織重整）可在 SAVE_TEXT／DELETE_TEXT 用參數 SAVEMODE_DIRECT = 'X' 暫時以 D 模式寫入，只對該次呼叫有效。絕對不可以把一般更新與 SAVEMODE_DIRECT 混用。

    要點：沒給時寄件國被當成收件國，國內地址會被格式化成國際格式（例 D-80801）。
  8. （Unit 5）以 PERFORM 從表單呼叫副程式時，參數結構是什麼？USING 的值有什麼要注意？
    要點：ITCSY（NAME、VALUE），IN_TAB／OUT_TAB；USING 值是格式化後字串（千分位、小數點），要自行還原。
  9. （Unit 6）要讓明細表頭在每一頁都出現、明細結束後消失，WRITE_FORM 要怎麼下？
    要點：首頁 BODY 印一次；TYPE='TOP' FUNCTION='SET'；明細後 TYPE='TOP' FUNCTION='DELETE'（下一頁起生效）。
  10. （Unit 6）END_FORM 與 CLOSE_FORM 的差別？
    要點：END_FORM 結束一份表單（同一 Spool 可再 START_FORM），CLOSE_FORM 結束整個列印；END_FORM 不能取代 CLOSE_FORM。
  11. （Unit 6 延伸）如何把 SAPscript 輸出成 PDF 寄出？
    要點：ITCPO-TDGETOTF='X' → CLOSE_FORM 取 OTFDATA → CONVERT_OTF FORMAT='PDF' → CL_BCS 附件 → COMMIT WORK。
  12. （Unit 7）表單套用 Style 後，表單原本的段落格式還有效嗎？
    要點：無效，樣式定義覆蓋表單定義；/: STYLE * 切回。
  13. （Unit 8）SAPscript 與 SmartForms 在「流程邏輯放哪裡」有何不同？新開發該選哪個？
    要點：SAPscript 在列印程式；SmartForms／Adobe 在表單（產生函數模組）。新開發選 Adobe Forms，S/4 標準單據優先用新 Output Management 的標準範本。
  14. （Unit 9）客戶要求在標準採購單加印一個 Z 表的欄位，依「先標準再客製」列出你的處理步驟。
    要點：確認有無標準欄位／設定 → 複製 MEDRUCK 為 Z 表單 → 用 PERFORM 呼叫 Z 程式讀 Z 表 → 在 NACE（EF／NEU）改指 Z 表單 → 測試與傳輸（含 SO10、SE78）；不複製 SAPFM06P 除非結構變更。
  15. （Unit 9）為什麼 SO10 標準文字在 QAS 找不到？怎麼傳？
    要點：文字不自動進傳輸單；RSTXTRAN 或手動加 R3TR TEXT TEXT,名稱,ST,語言。
  16. （Unit 10）條碼列印時送給印表機的三段內容是什麼？
    要點：prefix Print Control → 條碼資料 → suffix Print Control；在 SPAD 依裝置類型維護。
  17. （Unit 11 L1）V 模式下只呼叫 SAVE_TEXT 會怎樣？
    要點：只在文字記憶體，必須 COMMIT_TEXT＋COMMIT WORK，否則變更全遺失；COMMIT_TEXT 不能取代 COMMIT WORK；SAVEMODE_DIRECT 不可與一般更新混用。
  18. （Unit 11 L2）NACE 的 Processing Routine 對應哪個資料表？列印程式怎麼取得 NAST？
    要點：TNAPR（PGNAM、RONAM、FONAM、SFORM）；RSNAST00 以外部 PERFORM 呼叫 ENTRY，NAST／TNAPR 經共用介面工作區（TABLES）傳入。
  19. （Unit 11 L3）公司 Logo 要依公司代碼切換，怎麼做？
    要點：SE78 匯入多張圖（GRAPHICS／BMAP／BCOL），表單用 /: BITMAP 搭配符號動態指定名稱；記得傳輸 SE78 圖形。
  20. （實務）某批次對帳單每次跑出來客戶順序不同，而且使用者說「1000 到 1999 的客戶有幾位沒印到」。請指出兩個根因。
    要點：① SELECT 未 ORDER BY，HANA 無預設排序；② 用 BT 區間選客戶，字典序與前導零造成漏抓，應改列舉清單並印出核對清單。
