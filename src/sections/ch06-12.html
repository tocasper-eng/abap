2. Universal Journal：ACDOCA 是什麼

在 ECC，同一筆業務會寫到很多張表：FI 的 BKPF／BSEG 與索引表（BSIS、BSAS、BSID、BSAD、BSIK、BSAK）、總帳彙總表 GLT0／FAGLFLEXT、CO 的 COEP／COSP／COSS、資產的 ANEP、物料分類帳的 ML 表等。表之間要靠對帳程式維持一致。

S/4HANA 把這些「行項目」收進同一張表 ACDOCA（Universal Journal Entry Line Items）：FI、CO、AA、ML 同一行，科目與成本要素合一（成本要素就是總帳科目，CO 不再另開主檔），彙總值不再另外存，需要時在 HANA 上即時加總。

  • 主鍵：用戶端 RCLNT、分類帳 RLDNR、公司代碼 RBUKRS、會計年度 GJAHR、憑證號碼 BELNR、行號 DOCLN（6 位）。
  • 分類帳 RLDNR：主分類帳預設是 0L（Leading Ledger）。若公司有平行會計（例如 IFRS 與當地準則），會有其他分類帳（常見命名如 2L、L1，依設定而定），同一筆業務在不同分類帳各有一組行項目。報表一定要指定分類帳，否則金額會重複。
  • 與 BKPF／BSEG 的關係：BKPF（表頭）與 BSEG（行項目）在 S/4HANA 仍然存在、仍會寫入，FB03 顯示的「輸入檢視」就是 BSEG；但 BSEG 只有「總帳檢視」前的憑證行，沒有 CO 細節、也不分類帳。ACDOCA 則是「總帳檢視」，而且是報表的單一真相來源。ACDOCA-BELNR 與 BKPF-BELNR 對得起來，ACDOCA 另有欄位 BUZEI 對應 BSEG 行號。
  • 原則：寫報表讀 ACDOCA（或其上的 CDS view）；只有要還原「輸入時的樣子」或特定清帳資訊時才回頭讀 BSEG。
  • 計畫資料：ACDOCA 只放實際值；S/4HANA 的計畫值在另一張表 ACDOCP（版本門檻與使用方式請依系統確認）。
期間欄位 POPER 是 3 位數：001～012 為一般期間，013～016 是特別期間（年結調整），000 在 ACDOCA 用來放餘額結轉（Balance Carryforward）。算「年初至今」餘額要把 000 期一併加進來，算「本期發生額」則要排除。

4. 幣別欄位核對：TSL／WSL／HSL／KSL

ACDOCA 每一行最多可以帶十種幣別金額，最常用的是下面四種。素材把 TSL 寫成「財報幣別」並不正確，財報通常看的是 HSL（公司代碼幣別）或 KSL（集團幣別）。

金額欄位幣別鍵SAP 名稱中文素材寫法
WSLRWCURAmount in Transaction Currency原始交易（憑證）幣別金額，相當於 BSEG-WRBTR交易幣別（方向正確）
TSLRTCURAmount in Balance Transaction Currency餘額交易幣別金額：總帳餘額以哪一種交易幣別累計。大多數情況與 WSL 相同，只有科目設定「只以某幣別管理餘額」時才會不同財報幣別（錯誤）
HSLRHCURAmount in Company Code Currency公司代碼（本位）幣別金額，相當於 BSEG-DMBTR（未列）
KSLRKCURAmount in Global Currency集團幣別金額集團幣別（正確）
其他幣別欄位（OSL、VSL、BSL、CSL、DSL、ESL、FSL、CO 物件幣別 CO_OSL 等）依公司代碼與分類帳的幣別設定而定，本書不一一列出；要用時以 SE11 看 ACDOCA 的欄位說明，並到 FINSC_LEDGER 等設定確認實際啟用哪些幣別（依 SAP 標準補充，不同版本設定路徑可能不同）。
加總金額時一定要連同幣別鍵一起 GROUP BY（例如 SUM( hsl ) 搭配 rhcur）。WSL 尤其不能跨幣別直接相加：同一科目可能同時有 USD、JPY、TWD 的行項目。

5. 相容性 view：BSIS、BSAS、GLT0 去哪了

為了讓舊程式不必全部重寫，S/4HANA 把 ECC 的索引表與彙總表改成相容性 view（Compatibility View）：原來的表名保留，但 SE11 的「Replacement Object」指向一個 CDS view，資料實際從 ACDOCA／BSEG 即時算出。原本存在實體表裡的舊資料被搬到加了 _BCK 字尾的備份表。

ECC 表用途S/4HANA 狀態
BSIS／BSAS總帳未清／已清索引相容性 view；舊資料在 BSIS_BCK／BSAS_BCK
BSID／BSAD客戶未清／已清索引同上（*_BCK）
BSIK／BSAK供應商未清／已清索引同上（*_BCK）
GLT0舊總帳彙總相容性 view；舊資料在 GLT0_BCK
FAGLFLEXT新總帳彙總相容性 view；舊資料在 FAGLFLEXT_BCK
COEP、COSP、COSS、ANEP 等CO 行項目、CO 彙總、資產行項目多數也改成相容性 view，實際名稱請以 SE11 的 Replacement Object 確認

舊程式照樣 SELECT … FROM bsis 可以跑，但每次都是「從 ACDOCA 現算」，大範圍讀取會比直接讀 ACDOCA 慢。新程式請直接讀 ACDOCA 或 released CDS view。下面是把「讀 BSIS 取某科目未清項」改寫成讀 ACDOCA 的方式：

" 舊程式：SELECT … FROM bsis WHERE bukrs = … AND hkont = …（相容性 view，可跑但慢）
" 新寫法：直接讀 ACDOCA，明確帶分類帳與年度
PARAMETERS: p_bukrs TYPE bukrs  OBLIGATORY,
            p_gjahr TYPE gjahr  OBLIGATORY,
            p_racct TYPE racct  OBLIGATORY.

SELECT rbukrs, gjahr, belnr, docln, budat, hsl, rhcur, augbl, augdt
  FROM acdoca
  WHERE rldnr  = '0L'
    AND rbukrs = @p_bukrs
    AND gjahr  = @p_gjahr
    AND racct  = @p_racct
    AND augbl  = @space                 " 尚未清帳
  ORDER BY budat, belnr, docln          " HANA 沒有預設排序，要自己排
  INTO TABLE @DATA(lt_open).

cl_demo_output=>display( lt_open ).
是否有 AUGBL／AUGDT（清帳憑證／清帳日期）等欄位、以及科目是否為「未清項管理」，會影響這種寫法是否正確；未清項管理的科目，最保險的仍是用標準報表 FAGLL03H 或其 CDS 來核對。

6. 範例：依公司代碼、年度、期間彙總科目餘額

在 HANA 上彙總應該「推到資料庫做」：用 ABAP SQL 的 GROUP BY 與 SUM，只把結果搬回應用伺服器。

REPORT zfi_acdoca_balance.

DATA: gv_poper TYPE poper,
      gv_racct TYPE racct.

PARAMETERS: p_rldnr TYPE acdoca-rldnr DEFAULT '0L' OBLIGATORY,
            p_bukrs TYPE bukrs  OBLIGATORY,
            p_gjahr TYPE gjahr  OBLIGATORY.
SELECT-OPTIONS: s_poper FOR gv_poper DEFAULT '001' TO '012',
                s_racct FOR gv_racct.

START-OF-SELECTION.
  " 依科目、期間彙總本位幣金額（幣別鍵一起分組）
  SELECT racct,
         poper,
         rhcur,
         SUM( hsl ) AS hsl_sum
    FROM acdoca
    WHERE rldnr  = @p_rldnr
      AND rbukrs = @p_bukrs
      AND gjahr  = @p_gjahr
      AND poper IN @s_poper
      AND racct IN @s_racct
    GROUP BY racct, poper, rhcur
    ORDER BY racct, poper
    INTO TABLE @DATA(lt_bal).

  TRY.
      cl_salv_table=>factory( IMPORTING r_salv_table = DATA(lo_alv)
                              CHANGING  t_table      = lt_bal ).
      lo_alv->get_functions( )->set_all( abap_true ).
      lo_alv->display( ).
    CATCH cx_salv_msg INTO DATA(lx).
      MESSAGE lx TYPE 'I' DISPLAY LIKE 'E'.
  ENDTRY.
參數型別直接參照 acdoca-rldnr，就不必記分類帳的資料元素名稱。期間預設 001～012 已排除 000 餘額結轉與 013～016 特別期間，要看年結調整時自行放寬。

若資料已經在內表（例如還要做其他計算），可以改用 LOOP AT … GROUP BY 在應用伺服器分組：

TYPES: BEGIN OF ty_line,
         racct TYPE racct,
         poper TYPE poper,
         rhcur TYPE waers,
         hsl   TYPE acdoca-hsl,
       END OF ty_line,
       tt_line TYPE STANDARD TABLE OF ty_line WITH EMPTY KEY.

SELECT racct, poper, rhcur, hsl
  FROM acdoca
  WHERE rldnr = '0L' AND rbukrs = @p_bukrs AND gjahr = @p_gjahr
    AND poper IN @s_poper
  INTO TABLE @DATA(lt_items).

" 依科目＋幣別分組，算出所選期間的合計
DATA(lt_sum) = VALUE tt_line(
  FOR GROUPS grp OF ls IN lt_items
      GROUP BY ( racct = ls-racct rhcur = ls-rhcur )
      ( racct = grp-racct
        rhcur = grp-rhcur
        hsl   = REDUCE #( INIT s TYPE ty_line-hsl
                          FOR m IN GROUP grp
                          NEXT s = s + m-hsl ) ) ).

SORT lt_sum BY racct rhcur.
金額型別直接用 TYPE acdoca-hsl 最穩。能在 SQL 彙總就不要在 ABAP 彙總——這個 LOOP GROUP BY 版本只適合資料已經在手上的情況。

7. 範例：依成本中心取實際成本

S/4HANA 的 CO 實際行項目也在 ACDOCA：成本中心放在 RCNTR，成本要素就是 RACCT。KSB1 的資料來源就是這裡。

PARAMETERS: p_kokrs TYPE kokrs OBLIGATORY,
            p_bukrs TYPE bukrs OBLIGATORY,
            p_gjahr TYPE gjahr OBLIGATORY,
            p_poper TYPE poper OBLIGATORY.
DATA gv_kostl TYPE kostl.
SELECT-OPTIONS s_kostl FOR gv_kostl OBLIGATORY.

" 成本中心 × 成本要素（科目）的實際成本，以控制範圍幣別 KSL 或本位幣 HSL 呈現
SELECT rcntr,
       racct,
       rhcur,
       SUM( hsl ) AS actual_cost
  FROM acdoca
  WHERE rldnr  = '0L'
    AND kokrs  = @p_kokrs
    AND rbukrs = @p_bukrs
    AND gjahr  = @p_gjahr
    AND poper  = @p_poper
    AND rcntr IN @s_kostl
  GROUP BY rcntr, racct, rhcur
  ORDER BY rcntr, racct
  INTO TABLE @DATA(lt_cost).

LOOP AT lt_cost ASSIGNING FIELD-SYMBOL(<c>).
  WRITE: / <c>-rcntr, <c>-racct, <c>-actual_cost CURRENCY <c>-rhcur, <c>-rhcur.
ENDLOOP.
成本中心範圍請盡量用列舉（多筆 EQ）或成本中心群組展開後的清單，不要隨手打 BT 區間：成本中心號碼有前導零、號碼段常不連續，BT 比的是字典序，會多抓或漏抓（Casper 實務坑之二）。控制範圍幣別與公司代碼幣別不同時，要確認報表該用哪一個幣別欄位。

8. 範例：依採購單追會計憑證

一張採購單會產生收貨（GR）與發票驗證（IR）的會計憑證，兩者在 ACDOCA 都帶 EBELN／EBELP。用 AWTYP（來源類型）區分：收貨來自物料憑證（AWTYP = MKPF），發票來自 MIRO（AWTYP = RMRP）。

PARAMETERS: p_ebeln TYPE ebeln OBLIGATORY,
            p_bukrs TYPE bukrs OBLIGATORY.

" 採購單號不是會計主鍵，所以一定要再加 RLDNR + RBUKRS 縮小範圍
SELECT gjahr, belnr, docln, ebelp, awtyp, awref, budat, blart,
       racct, ktosl, hsl, rhcur, matnr, werks
  FROM acdoca
  WHERE rldnr  = '0L'
    AND rbukrs = @p_bukrs
    AND ebeln  = @p_ebeln
  ORDER BY ebelp, budat, belnr, docln
  INTO TABLE @DATA(lt_doc).

" 依來源區分收貨與發票
DATA: lt_gr LIKE lt_doc,
      lt_ir LIKE lt_doc.
lt_gr = VALUE #( FOR d IN lt_doc WHERE ( awtyp = 'MKPF' ) ( d ) ).
lt_ir = VALUE #( FOR d IN lt_doc WHERE ( awtyp = 'RMRP' ) ( d ) ).

" GR/IR 對帳：交易鍵 WRX 的行項目加總，理想上收貨與發票互相沖銷
DATA(lv_grir) = REDUCE acdoca-hsl( INIT s TYPE acdoca-hsl
                                   FOR d IN lt_doc WHERE ( ktosl = 'WRX' )
                                   NEXT s = s + d-hsl ).

cl_demo_output=>write( lt_gr ).
cl_demo_output=>write( lt_ir ).
cl_demo_output=>display( |GR/IR（WRX）餘額：{ lv_grir }| ).
這個例子沒有帶 GJAHR，因為採購單的收貨與發票可能跨年度；資料量大的系統請改為帶上年度清單（例如採購單建立年度起算的兩個年度），或先確認 EBELN 上有可用的次要索引。AWKEY 的組成（物料憑證號＋年度、發票號＋年度）可用來回推 MIGO／MIRO 的原始憑證。

9. 範例：讀取 released CDS view I_JournalEntryItem

SAP 在 ACDOCA 上提供 VDM（虛擬資料模型）的 CDS view，I_JournalEntryItem 就是日記帳行項目的基本 view。欄位名是英文駝峰式，語意清楚，而且是 SAP 承諾相容的公開介面。在 S/4HANA Cloud 與 ABAP Cloud 開發模式下它是 released（C1）物件；在 1809 on-premise 也可以讀，但是否標示 released 依版本而異，請在 ADT 的 API State 確認。

PARAMETERS: p_bukrs TYPE bukrs OBLIGATORY,
            p_gjahr TYPE gjahr OBLIGATORY.

" 下面只用確定存在的欄位；其他欄位請在 ADT 開啟 I_JournalEntryItem 查看
SELECT CompanyCode,
       FiscalYear,
       AccountingDocument,
       Ledger,
       GLAccount,
       FiscalPeriod,
       PostingDate,
       AmountInCompanyCodeCurrency,
       CompanyCodeCurrency
  FROM i_journalentryitem
  WHERE Ledger      = '0L'
    AND CompanyCode = @p_bukrs
    AND FiscalYear  = @p_gjahr
  ORDER BY FiscalPeriod, AccountingDocument
  INTO TABLE @DATA(lt_jei)
  UP TO 1000 ROWS.

cl_demo_output=>display( lt_jei ).
CDS view 可能附帶 DCL 權限控制（access control）：同一段 SELECT，不同使用者可能看到不同筆數。這是正確行為，不是 bug。若要在 ABAP Cloud（7.5x 以上的 Steampunk／Embedded Steampunk）開發，只能讀 released view，不能直接讀 ACDOCA。
ACDOCA 是全系統最大的表之一。任何讀取都要帶齊 RLDNR、RBUKRS、GJAHR、POPER（至少前三個），並只列需要的欄位；不要 SELECT *，也不要在迴圈裡逐筆讀。
HANA 沒有預設排序。沒寫 ORDER BY 時，每次執行的順序可能不同；任何「取第一筆」「READ TABLE INDEX 1」的邏輯都要先明確排序（Casper 實務坑之一：成本評價同時有 item category H 與 cost component E 兩種角度，沒排序就一下抓到 H、一下抓到 E）。

14. 範例：讀取特定日期有效的員工資料

HR 報表最基本的條件就是「基準日有效」：BEGDA ≤ 基準日 ≤ ENDDA。下面讀出基準日時的組織指派（PA0001）與在職狀態（PA0000）。

REPORT zhr_active_employees.

DATA gv_bukrs TYPE bukrs.
PARAMETERS p_keydt TYPE datum DEFAULT sy-datum OBLIGATORY.
SELECT-OPTIONS s_bukrs FOR gv_bukrs.

START-OF-SELECTION.
  " PA0000 與 PA0001 各自取基準日有效的那一筆，再以 PERNR 相接
  SELECT p1~pernr, p1~bukrs, p1~werks, p1~btrtl, p1~persg, p1~persk,
         p1~kostl, p1~orgeh, p1~plans, p1~ename, p0~stat2
    FROM pa0001 AS p1
    INNER JOIN pa0000 AS p0
      ON p0~pernr = p1~pernr
    WHERE p1~bukrs IN @s_bukrs
      AND p1~begda <= @p_keydt AND p1~endda >= @p_keydt
      AND p0~begda <= @p_keydt AND p0~endda >= @p_keydt
      AND p0~stat2 = '3'                       " 3 = 在職
      AND p1~sprps = @space AND p0~sprps = @space   " 排除鎖定中的紀錄
    ORDER BY p1~pernr
    INTO TABLE @DATA(lt_emp).

  " 直接 SELECT 不會檢查 HR 權限：正式程式要逐筆做 P_ORGIN 檢查（見第 18 節）

  WRITE: / |基準日 { p_keydt DATE = USER } 在職人數：{ lines( lt_emp ) }|.
要讀「某期間內有效過的資料」（例如某月所有調動）則是區間重疊條件：BEGDA ≤ 期末 AND ENDDA ≥ 期初。一位員工在期間內可能有多筆，要依 BEGDA 排序後再處理。

15. HR_READ_INFOTYPE 的現代寫法

直接 SELECT PA 表最快，但不會檢查 HR 權限。標準函數 HR_READ_INFOTYPE 會依 P_ORGIN 等權限物件過濾資料，並處理緩衝，適合讀少量員工的完整資訊類型。它的 TABLES 參數要傳對應的結構表（例如 P0002 型別）。

DATA lt_p0002 TYPE STANDARD TABLE OF p0002 WITH EMPTY KEY.

PARAMETERS: p_pernr TYPE pernr_d OBLIGATORY,
            p_keydt TYPE datum   DEFAULT sy-datum.

CALL FUNCTION 'HR_READ_INFOTYPE'
  EXPORTING
    pernr           = p_pernr
    infty           = '0002'
    begda           = p_keydt
    endda           = p_keydt
  TABLES
    infty_tab       = lt_p0002
  EXCEPTIONS
    infty_not_found = 1
    OTHERS          = 2.

IF sy-subrc <> 0 OR lt_p0002 IS INITIAL.
  MESSAGE |人員 { p_pernr ALPHA = OUT } 在 { p_keydt DATE = USER } 無資料或無權限| TYPE 'S' DISPLAY LIKE 'W'.
  RETURN.
ENDIF.

" 取基準日有效的那一筆（先排序，不要依賴回傳順序）
SORT lt_p0002 BY begda DESCENDING.
DATA(ls_p0002) = lt_p0002[ 1 ].
WRITE: / ls_p0002-pernr, ls_p0002-begda, ls_p0002-endda.
介面參數：TCLAS（預設 'A' = 員工，'B' = 應徵者）、PERNR、INFTY、BEGDA、ENDDA、BYPASS_BUFFER 等；回傳在 TABLES INFTY_TAB。其他參數與例外請以 SE37 確認介面。沒有權限時，函數不一定丟例外，常見情況是回傳空表或 SUBRC 非 0，所以兩者都要檢查。另有物件導向的讀取類別（CL_HRPA_* 系列），介面依版本不同，使用前請以 SE24 確認。

16. PNP／PNPCE 邏輯資料庫

傳統 HR 報表用邏輯資料庫（LDB）：在程式屬性指定 PNP（舊）或 PNPCE（Concurrent Employment，建議新報表使用），就自動得到標準的 HR 選擇畫面（人員編號、期間、組織結構、人事範圍 …）與自動權限檢查。

REPORT zhr_ldb_demo.
" 程式屬性 → 邏輯資料庫：PNPCE（HR 報表類別依需求在屬性中設定）

NODES peras.                 " PNPCE 的節點；PNP 則為 NODES pernr
INFOTYPES: 0001, 0002.       " 自動產生內表 p0001、p0002

DATA gt_out TYPE STANDARD TABLE OF p0001 WITH EMPTY KEY.

START-OF-SELECTION.

GET peras.
  " 選擇畫面上的「資料選擇期間」為 pn-begda ～ pn-endda
  rp_provide_from_last p0001 space pn-begda pn-endda.
  IF pnp-sw-found = 1.
    APPEND p0001 TO gt_out.
  ENDIF.

END-OF-SELECTION.
  SORT gt_out BY pernr.
  TRY.
      cl_salv_table=>factory( IMPORTING r_salv_table = DATA(lo_alv)
                              CHANGING  t_table      = gt_out ).
      lo_alv->display( ).
    CATCH cx_salv_msg INTO DATA(lx).
      MESSAGE lx TYPE 'I' DISPLAY LIKE 'E'.
  ENDTRY.
LDB 是 HR 報表的特殊情況：INFOTYPES 敘述會隱含產生帶表頭行的內表 p0001、p0002，rp_provide_from_last 是 HR 的巨集（放在表頭行並設定 PNP-SW-FOUND）。這些是 LDB 框架要求的寫法，不是本書推薦的一般語法；自己的邏輯請寫在類別或內嵌宣告裡，只把 LDB 當作「選擇畫面＋權限＋取人」的入口。不想用 LDB 時，改用第 14 節的 SELECT 加第 18 節的權限檢查，或第 15 節的 HR_READ_INFOTYPE。

17. 讀 HRP1001 組織關係

組織管理（OM）的物件在 HRP1000（物件主檔：PLVAR 計畫版本、OTYPE 物件類型、OBJID、BEGDA、ENDDA、LANGU、SHORT、STEXT），物件之間的關係在 HRP1001（OTYPE／OBJID → RSIGN、RELAT → SCLAS／SOBID）。

物件類型意義常用關係
O組織單位O A002 O：上層組織；O B012 S：由某職位管理（主管職）
S職位S A003 O：隸屬組織；S A008 P：由某人擔任
P人員P B008 S：擔任某職位（方向相反）
C職務C A007 S：描述某職位
K成本中心O A011 K：成本中心指派

關係有方向：A 是由下往上、B 是由上往下，同一組關係在 HRP1001 會存兩筆（A 與 B 各一筆）。下面找出某組織單位底下，基準日時的職位與人員：

PARAMETERS: p_orgeh TYPE hrobjid OBLIGATORY,
            p_keydt TYPE datum   DEFAULT sy-datum.

CONSTANTS lc_plvar TYPE plvar VALUE '01'.   " 目前計畫版本（以 T778P 或設定確認）

" 1) 組織 O → 職位 S（O B003 S：包含職位）
SELECT sobid AS position
  FROM hrp1001
  WHERE plvar = @lc_plvar
    AND otype = 'O'
    AND objid = @p_orgeh
    AND rsign = 'B'
    AND relat = '003'
    AND sclas = 'S'
    AND istat = '1'                          " 1 = 啟用
    AND begda <= @p_keydt AND endda >= @p_keydt
  INTO TABLE @DATA(lt_pos).

IF lt_pos IS INITIAL.
  RETURN.
ENDIF.

" SOBID 是 45 碼通用欄位，先轉成 8 碼 OBJID 再做 FOR ALL ENTRIES
TYPES: BEGIN OF ty_pos, objid TYPE hrobjid, END OF ty_pos.
DATA lt_posid TYPE SORTED TABLE OF ty_pos WITH NON-UNIQUE KEY objid.
lt_posid = VALUE #( FOR p IN lt_pos ( objid = CONV hrobjid( p-position ) ) ).

" 2) 職位 S → 人員 P（S A008 P：由某人擔任）
SELECT objid AS position, sobid AS pernr
  FROM hrp1001
  FOR ALL ENTRIES IN @lt_posid
  WHERE plvar = @lc_plvar
    AND otype = 'S'
    AND objid = @lt_posid-objid
    AND rsign = 'A'
    AND relat = '008'
    AND sclas = 'P'
    AND istat = '1'
    AND begda <= @p_keydt AND endda >= @p_keydt
  INTO TABLE @DATA(lt_holder).

" 3) 職位名稱（HRP1000）
SELECT objid, stext
  FROM hrp1000
  FOR ALL ENTRIES IN @lt_posid
  WHERE plvar = @lc_plvar
    AND otype = 'S'
    AND objid = @lt_posid-objid
    AND langu = @sy-langu
    AND begda <= @p_keydt AND endda >= @p_keydt
  INTO TABLE @DATA(lt_postext).

SORT lt_holder BY position pernr.
SOBID 是 45 碼的通用欄位，裝得下任何物件類型的 ID，所以接回 OBJID（8 碼）時要先用 CONV 轉型；FOR ALL ENTRIES 前一定要確認驅動表非空，否則會讀出全部資料。要遞迴展開整棵組織樹，用標準函數 RH_STRUC_GET（評估路徑，例如 O-S-P）比自己寫迴圈可靠，參數請以 SE37 確認；評估路徑定義在 OOAW。

18. 權限與個資遮罩

HR 的讀取權限主要看 P_ORGIN（HR：主資料），欄位包括 INFTY（資訊類型）、SUBTY（子類型）、AUTHC（存取層級 R 讀、W 寫…）、PERSA（人事範圍）、PERSG（員工群組）、PERSK（員工子群組）、VDSK1（組織鍵）。另有 P_PERNR（自己的人員編號）、P_ORGINCON（依結構權限的擴充版本）與結構權限（OM 的 PLOG／結構設定檔），依公司設定而定。

CLASS lcl_hr_guard DEFINITION FINAL.
  PUBLIC SECTION.
    CLASS-METHODS can_read
      IMPORTING is_p0001      TYPE p0001
                iv_infty      TYPE infty
      RETURNING VALUE(rv_ok)  TYPE abap_bool.
    CLASS-METHODS mask
      IMPORTING iv_text        TYPE csequence
                iv_keep        TYPE i DEFAULT 1
      RETURNING VALUE(rv_mask) TYPE string.
ENDCLASS.

CLASS lcl_hr_guard IMPLEMENTATION.
  METHOD can_read.
    " 以員工在 PA0001 的組織屬性檢查 P_ORGIN 讀取權限
    AUTHORITY-CHECK OBJECT 'P_ORGIN'
      ID 'INFTY' FIELD iv_infty
      ID 'SUBTY' DUMMY
      ID 'AUTHC' FIELD 'R'
      ID 'PERSA' FIELD is_p0001-werks
      ID 'PERSG' FIELD is_p0001-persg
      ID 'PERSK' FIELD is_p0001-persk
      ID 'VDSK1' FIELD is_p0001-vdsk1.
    rv_ok = xsdbool( sy-subrc = 0 ).
  ENDMETHOD.

  METHOD mask.
    " 保留前 iv_keep 個字元，其餘以 * 取代，例如 A*******
    DATA(lv_len) = strlen( iv_text ).
    IF lv_len <= iv_keep.
      rv_mask = repeat( val = `*` occ = lv_len ).
    ELSE.
      rv_mask = substring( val = iv_text len = iv_keep )
             && repeat( val = `*` occ = lv_len - iv_keep ).
    ENDIF.
  ENDMETHOD.
ENDCLASS.

" 使用：沒權限的人員整筆排除；有權限也只顯示遮罩後的身分證號
" （DELETE … WHERE 不能呼叫方法，所以用迴圈過濾）
DATA lt_p0001 TYPE STANDARD TABLE OF p0001 WITH EMPTY KEY.   " 假設已依第 14 節讀入
LOOP AT lt_p0001 ASSIGNING FIELD-SYMBOL(<p>).
  IF lcl_hr_guard=>can_read( is_p0001 = <p> iv_infty = '0002' ) = abap_false.
    DELETE lt_p0001.
  ENDIF.
ENDLOOP.

DATA(lv_id_masked) = lcl_hr_guard=>mask( iv_text = 'X123456789' iv_keep = 2 ).  " X1********
HR 是個資。直接 SELECT PA／PB／PCL 表會繞過 HR 權限，所以：（1）自己寫 SELECT 時一定要補 AUTHORITY-CHECK P_ORGIN，或改用 HR_READ_INFOTYPE／LDB；（2）姓名、生日、身分證號（PERID）、地址、銀行帳號（PA0009-BANKN）、薪資（PA0008）等欄位，除非需求明確，否則輸出一律遮罩或不輸出；（3）程式本身要有交易代碼與 S_TCODE 控管，不要讓一般使用者用 SE38 直接執行；（4）測試資料用合成資料，不要把正式機人員資料複製到測試機或寄出；（5）使用者回報「看不到資料」時先看 SU53，不要直接放寬權限。
S/4HANA 上的 HCM：on-premise 的 HR 模組在 S/4HANA 可用「相容模式」執行，SAP 另提供 SAP HCM for SAP S/4HANA 作為後續方案，雲端則是 SuccessFactors。PA／HRP 表結構在這些 on-premise 方案中大致相同，但支援期限與移轉方式請以 SAP 官方公告為準。
