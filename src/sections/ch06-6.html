2. 缺料表的業務情境：為什麼不直接看 MD04

MD04（庫存／需求清單）一次只能看一顆料。生管要的是「整個工廠、某些 MRP 控制員、某些採購類型的料，未來哪一天、哪一張工單會缺料，缺多少，找哪個採購、哪個供應商」。ZPPB0002 的做法是：

  1. 從 MARC＋MARA 依選擇條件挑出物料，排除物料狀態 MMSTA = '01' / '05'（停用類狀態；以列舉排除，而不是用區間）。
  2. 逐料呼叫 MD_STOCK_REQUIREMENTS_LIST_API——這就是 MD04 背後的資料：MDPSX（MRP 元素項目，結構 MDPS）、MDEZX（MD04 畫面上每一列，結構 MDEZ）、MDSUX（期間彙總，結構 MDSU），以及表頭 E_MDKP（含採購群組 EKGRP）。
  3. 原樣落地到客製表 ZMDPS（WERKS、USNAM、CNT、MATNR、MATCNT ＋ INCLUDE MDPS）與 ZMDEZ（同鍵 ＋ INCLUDE MDEZ），供追查用（由參數 P_UPDT 決定是否寫入）。
  4. 把兩者合併、加工成缺料表 ZTPP0001（鍵：MANDT、WERKS、USNAM、MATNR、PLAAB、PLANR、CNT，共 45 欄），補上來源單據、父階料號、廠商交期、工單完工日、6 個月平均耗用、寄售／外包庫存等欄位。
  5. 顯示程式 ZPPR0003 再從 ZTPP0001 讀出、依條件篩選後用 ALV 呈現。

「版本」的概念：ZTPP0001／ZMDPS／ZMDEZ 的鍵含 USNAM。選擇畫面有兩個單選鈕——「工廠版」（USNAM 留空，大家共用一份）與「使用者版」（USNAM 預設 SY-UNAME），讓生管可以各自跑一份自己的物料範圍而不互相覆蓋。每次執行先 DELETE 該工廠＋版本的舊資料，再 MODIFY 新資料。

這種「批次預算好、落地成表、報表只讀表」的設計在 ECC 時代很合理：MD_STOCK_REQUIREMENTS_LIST_API 逐料呼叫很慢（每料都要讀 RESB、EKET、PLAF、AFPO、VBBE…），不可能讓使用者即時等。缺點是資料有時間差——報表上看到的是「上次批次跑的時點」，一定要把執行時間顯示在報表表頭。

4. 程式架構與缺料計算邏輯

ZPPB0002 的處理順序（原程式以 FORM 串接，下面用現代寫法說明）：

  1. PREPARE_DATA：MARC JOIN MARA 取料，排除 MMSTA 01／05。
  2. GET_DATA：逐料呼叫 API；FIX_GT_MDPSX 補列——對 PLAAB = '20' 的計劃段，若段首不是庫存列（DELKZ ≠ 'KB'）就補一列 KB（PLUMI = 'B'、VRFKZ = 'X'），讓每個計劃段都有「期初」列，再依 PLAAB、PLANR、DAT00、TAG00、SORT1、SORT2 重排。
  3. CRT_GT_ZTPP0001：以流水號 CNT 把 ZMDEZ 與 ZMDPS 對上，依 DELKZ 把單據號碼分派到 DEL12／DEL13／RSNUM 等欄位（見第 5 節表格），依 PLUMI 拆成收／發／期初三欄。
  4. UPD_GT_ZTPP0001_CACULATE_TTL：依 WERKS、MATNR、PLAAB、PLANR 分段累計，算缺料。
  5. UPD_MSLB、UPD_DAT02、UPD_SO：補外包庫存、交期／完工日、工單對應銷售訂單。
  6. UPDDATE_DB_DATA：刪舊寫新。

核心的缺料演算法其實很短：在同一個計劃段內，依 MD04 的時間順序逐列累加「期初庫存 + 收 − 發」，只累計可用性指標 VRFKZ = 'X' 的列；累計值一旦小於 0，該列就是缺料列，缺料量 = −累計值。

METHOD calc_shortage.   " CHANGING ct_rows TYPE tt_short
  " 累計的正確性完全取決於列的順序：CNT 是依 MD04 順序給的流水號
  SORT ct_rows BY werks matnr plaab planr cnt.

  LOOP AT ct_rows ASSIGNING FIELD-SYMBOL(<grp>)
       GROUP BY ( werks = <grp>-werks matnr = <grp>-matnr
                  plaab = <grp>-plaab planr = <grp>-planr )
       ASSIGNING FIELD-SYMBOL(<seg>).
    DATA(lv_balance) = CONV mng01( 0 ).
    LOOP AT GROUP <seg> ASSIGNING FIELD-SYMBOL(<row>).
      CHECK <row>-vrfkz = abap_true.            " 只算可用元素
      lv_balance = lv_balance + <row>-mng01_wb + <row>-mng01_gr - <row>-mng01_gi.
      IF lv_balance < 0.
        <row>-short       = abap_true.
        <row>-mng02_short = - lv_balance.
      ENDIF.
    ENDLOOP.
  ENDLOOP.
ENDMETHOD.
HANA 沒有預設排序——缺料累計尤其致命。這個演算法是「逐列滾動餘額」，順序一亂，缺料列就會跳到別的日期、別的工單。原批次程式在記憶體裡有 SORT，所以批次當下是對的；但顯示程式 ZPPR0003 從 ZTPP0001 讀回來時，若 SELECT 沒寫 ORDER BY werks, matnr, plaab, planr, cnt，在 HANA 上每次拿到的順序可能不同，任何「在報表端重新累計」或「取第一筆缺料日」的邏輯都會不穩定。同理，READ TABLE … BINARY SEARCH 前一定要有對應鍵的 SORT（原程式在 UPD_MSLB 裡先 SORT BY MATNR DELKZ 再二分搜尋，之後又 SORT 回原鍵，這種「借用排序」很容易在後人修改時被打斷）。

12. ZBQM003／ZBQM004：UD 迴轉的程式架構

ZBQM003「檢驗批 UD 庫存移轉迴轉作業」（選擇畫面：檢驗批必填、迴轉日期）與 ZBQM004「檢驗批 UD 判定迴轉作業」（選擇畫面：檢驗批＋ Select／Show 兩個按鈕，按鈕透過 SSCRFIELDS-UCOMM 判斷）必須依序執行：先把 UD 做的庫存過帳沖掉，再把 UD 本身重設成「未判定」。

步驟ZBQM003（沖銷 UD 庫存過帳）
1檢查迴轉日期：空白時自動帶入原 UD 過帳憑證的過帳日（QAMB TYP 3 JOIN MKPF）；有輸入時必須等於原過帳日
2鎖檢驗批 ENQUEUE_EQQALS1；以 QPSE_LOT_READ 讀 QALS
3CHECK_LOT：有收貨憑證參照（QALS-ZEILE）、非序號料（SERNP）、狀態檢查（I0203、BTEI I0219／BEND I0220、LSTO I0224／LSTV I0232 取消、ARSP／ARCH／REO1～3 封存、SPER I0043 凍結、I0443 HU 管理），每種不符回傳不同訊息
4讀 QAMB（TYP = '3'）取得 UD 過帳憑證；鎖 ENQUEUE_EMMKPF、讀表頭 MB_READ_MATERIAL_HEADER；若該憑證同時是產生檢驗批的憑證（QAMB TYP = '1'）則中止
5讀憑證行 MB_READ_MATERIAL_POSITION，刪除自動產生行（XAUTO）與 341／342；再查 MSEG-SMBLN 排除已被沖銷的行
6組 IMSEG：帶入 SMBLN／SJAHR／SMBLP（被沖銷憑證）、XSTOB = 'X'、QPLOS = 檢驗批；依 T156-XSTBW 決定工廠／儲位填在發出方或接收方
7暫停 QM（QAAT_QM_ACTIVE_INACTIVE），以 MB_CREATE_GOODS_MOVEMENT（CTCOD = 'QA11'）建立沖銷憑證、MB_POST_GOODS_MOVEMENT 過帳，再恢復 QM
8QAMB 以 TYP = '7' 記錄新憑證；QALS 清空 LMENGE01～09、把量加回 LMENGEZUB；狀態 BTEI／BEND 設為非作用；QPL1_UPDATE_MEMORY、QPL1_INSPECTION_LOTS_POSTING、STATUS_UPDATE_ON_COMMIT、QEVA_QAMB_CANCEL（IN UPDATE TASK）；COMMIT WORK AND WAIT
步驟ZBQM004（重設 UD）
1Select 按鈕呼叫 QELA_START_SELECTION_OF_LOTS 挑檢驗批；Show 按鈕呼叫 QSS1_LOT_SHOW
2鎖檢驗批、讀 QALS；LMENGE01～09 任一大於 0 就擋下（訊息 QA 082）——表示庫存過帳還沒被 ZBQM003 沖掉
3QAST_STATUS_CHECK 確認 I0218（已做 UD）；QEVA_UD_READ 讀 QAVE
4狀態：I0002（REL 已下達）設為作用，I0216、I0217、I0218 設為非作用；清 QALS-STAT14／STAT35 與 QAVE 的判定欄位（VCODE、VCODEGRP、VBEWERTUNG、VFOLGEAKTI、QKENNZAHL…）
5QEVA_UD_UPDATE IN UPDATE TASK，COMMIT WORK
兩支程式都大量呼叫未發佈（not released）的內部函數：MB_CREATE_GOODS_MOVEMENT、QPL1_*、QEVA_UD_UPDATE、STATUS_CHANGE_INTERN，還直接改 QAMB 與狀態。這等同於「修改標準」等級的風險——升級或套 Support Package 後介面可能改變，且 SAP 不支援因此產生的資料不一致。Casper 的第 3 條經驗在這裡最適用：先查 SAP Note 與新版本是否已有標準的 UD 取消方式，確定沒有、且業務頻率真的高，才考慮保留這種客製，並把它限定給極少數 QM 關鍵使用者。

13. 現代改寫：用 BAPI 做移動、用 MATDOC 追憑證

一般的收發轉（不涉及檢驗批內部狀態）一律用 BAPI_GOODSMVT_CREATE，成功後 BAPI_TRANSACTION_COMMIT、失敗 BAPI_TRANSACTION_ROLLBACK。GM_CODE：01 採購單收貨、02 工單收貨、03 發貨、04 轉移過帳、05 其他收貨、06 迴轉（舊 MB11）、07 外包。BAPI 通則見 4-1 章。

追查「某檢驗批的收貨憑證與 UD 過帳憑證、哪些已被沖銷」，在 S/4HANA 直接 JOIN QAMB 與 MATDOC，取代原程式的 MB_READ_MATERIAL_HEADER／POSITION 與額外的 SMBLN 查詢：

SELECT FROM qamb AS q
       INNER JOIN matdoc AS m
               ON m~mblnr = q~mblnr
              AND m~mjahr = q~mjahr
              AND m~zeile = q~zeile
  FIELDS q~prueflos, q~typ,
         m~mblnr, m~mjahr, m~zeile, m~bwart, m~matnr, m~werks, m~lgort,
         m~charg, m~menge, m~meins, m~shkzg, m~budat,
         m~smbln, m~sjahr, m~smblp                 " 若此行本身是沖銷行，指向原憑證
  WHERE q~prueflos = @p_lot
    AND m~record_type = 'MDOC'
    AND m~xauto = @space                          " 排除自動產生的對方行
  ORDER BY q~typ, m~mblnr, m~zeile                " HANA 無預設排序，明確排序
  INTO TABLE @DATA(lt_lot_docs).

" 哪些 UD 過帳行已經被沖銷？找「以它為 SMBLN 的行」
IF lt_lot_docs IS NOT INITIAL.
  SELECT FROM matdoc
    FIELDS mblnr, mjahr, zeile, smbln, sjahr, smblp
    FOR ALL ENTRIES IN @lt_lot_docs
    WHERE smbln = @lt_lot_docs-mblnr
      AND sjahr = @lt_lot_docs-mjahr
      AND smblp = @lt_lot_docs-zeile
      AND record_type = 'MDOC'
    INTO TABLE @DATA(lt_reversals).
ENDIF.

LOOP AT lt_lot_docs INTO DATA(ls_doc).
  DATA(lv_reversed) = xsdbool( line_exists( lt_reversals[ smbln = ls_doc-mblnr
                                                          sjahr = ls_doc-mjahr
                                                          smblp = ls_doc-zeile ] ) ).
  WRITE: / ls_doc-typ, ls_doc-mblnr, ls_doc-zeile, ls_doc-bwart,
           ls_doc-menge, ls_doc-meins, COND string( WHEN lv_reversed = abap_true THEN '已沖銷' ).
ENDLOOP.
S/4HANA：MKPF／MSEG 已由 MATDOC 取代。1511 起物料憑證的表頭與行項目都寫進單一實體表 MATDOC，MKPF、MSEG 變成相容性 view（NSDM_V_MKPF、NSDM_V_MSEG），MARD、MCHB、MSLB、MSKU 等庫存表的數量也改為從 MATDOC 即時彙總。影響：① 舊程式 SELECT MKPF／MSEG 仍可執行，但每次都在做 view 運算，大量讀取請直接讀 MATDOC 或 CDS；② 任何 INSERT／UPDATE／MODIFY MKPF、MSEG、MARD 都不再允許；③ MSEG 上的 BUDAT_MKPF 等冗餘欄位在 MATDOC 對應為 BUDAT；④ 讀 MATDOC 記得限定 RECORD_TYPE，並排除 XAUTO 自動行，否則轉移過帳會被算兩次。

14. 原程式問題與上線注意（檢驗批迴轉）

#問題影響與建議
1CHECK_PARAMETERS：使用者有輸入迴轉日期時，G_BUDAT 從未被讀取（初始值），接著 IF G_BUDAT NE P_BUDAT 必然成立只要手動輸入日期就一定報「迴轉日期和過帳日期不符」，實際上只能留空讓程式自動帶。應改為無論是否輸入都先讀原過帳日再比較
2迴轉日期強制等於原 UD 過帳日跨月後原期間已關帳就無法迴轉。業務上應允許「當期日期沖銷」，並提醒財務成本差異
3WE 凍結判斷條件寫成 L_IMSEG-UMLGO EQ L_IMSEG-UMLGO自己比自己，恆為真；本意應是 LGORT EQ UMLGO（同儲位）。行順序交換邏輯可能在跨儲位時誤判
4錯誤處理用 SUBMIT (SY-REPID) VIA SELECTION-SCREEN 重新叫起自己已經暫停 QM、已經呼叫過 MB_CREATE 的情況下直接跳走，記憶體中的過帳資料與 QM 開關狀態不確定。應先 ROLLBACK WORK、恢復 QM 再顯示訊息
5ZBQM004 的 ENQUEUE_EQQALS1 沒有接例外別人正在 QA11 處理同一檢驗批時仍會往下跑。依 5-11 章鎖物件規則處理 FOREIGN_LOCK
6兩支程式都依賴未發佈函數與直接改狀態升級風險；見第 12 節 warn。至少要在 SE38 程式說明中寫清楚依賴的函數清單，升級時列入回歸測試
7多處使用 TABLES、OCCURS、WITH HEADER LINE、MOVE、ADD／SUBTRACT、FORM語法全屬禁用清單；本章範例已改寫。若保留原程式，至少不要再在其上擴充

上線注意：

  • 權限：ZBQM003／ZBQM004 必須用獨立 TCODE ＋ 權限物件限制，只給 QM 主管；並記錄執行者與原判定（原程式清空 QAVE 後，原判定碼就不見了——建議迴轉前先把 QAVE 寫一份到客製日誌表）。
  • 迴轉後檢驗批回到「REL 已下達」、庫存回到品檢；使用者重新在 QA11 判定即可，缺料表中該量會重新以 DELKZ = 'QM' 出現。
  • 批次管理料：UD 可能同時改了批次狀態（341／342），ZBQM003 刻意排除這兩種移動，批次狀態要另外在 MSC2N 檢查。
  • 測試案例至少涵蓋：全數合格、部分合格部分凍結、含樣品量、跨月、批次料、HU 管理料（程式會擋）、已被他人沖銷的憑證。
