2. 清單基礎回顧：可執行程式的執行流程與事件

當使用者啟動一支可執行程式（類型 1）時，應用伺服器會為程式上下文與資料物件（變數、結構）配置記憶體，接著整個流程由 ABAP Runtime 控制：

  1. 若程式有選擇畫面，Runtime 在程式一開始就把它送到展示層（SAP GUI）。
  2. 使用者按「執行」後，選擇畫面上輸入的值自動放進對應的資料物件，控制權交回程式。
  3. 最簡單的情況下只有一個處理區塊：讀資料庫 → 資料庫回傳 → Runtime 把資料放進資料物件 → 程式用 WRITE 輸出到清單緩衝區（list buffer）。
  4. 處理區塊結束時，Runtime 把清單當作一個畫面送到展示層。

3. PARAMETERS 與 SELECT-OPTIONS 的附加選項

選擇畫面讓使用者輸入值的範圍，通常用來限定要從資料庫讀出的資料集合。它和一般 Dynpro 一樣有群組框、核取方塊、選項按鈕，並提供兩種輸入元素：PARAMETERS（單一欄位）與 SELECT-OPTIONS（範圍群組）。引用 ABAP 字典欄位時，字典的搜尋說明（Search Help）會自動帶到選擇畫面；選擇文字可以翻譯，依使用者登入語言顯示；可以建立變式（Variant）。

SELECT-OPTIONS 的本質是一個內表：SELECT-OPTIONS so FOR f 宣告一個名為 so 的內表，欄位為 SIGN、OPTION、LOW、HIGH，LOW／HIGH 的型別與 f 相同。

  • SIGN：I（包含）或 E（排除）。
  • OPTION：關係運算子 EQ、NE、LE、LT、GE、GT；模式運算子 CP、NP；範圍運算子 BT、NB。
  • 範圍的更多說明：選擇畫面選單「跳至 → 選擇畫面說明」（附錄 ILB-1）。

4. 互動式清單：細節清單、sy-lsind 與 HIDE 技術

基本清單顯示後，使用者可以進一步操作。細節清單把資訊分散在多張相關清單中，好讀又省效能——附加資料只在使用者真的要看時才讀資料庫。也可以再叫出額外的選擇畫面讓使用者輸入更多條件。

  • 每張基本清單最多可有 20 層細節清單，每層都有自己的清單緩衝區。
  • 按「返回」（綠箭頭）或「取消」（紅叉）回到上一層，並初始化剛離開那一層的清單緩衝區。
  • 按「結束」（黃箭頭）則中斷清單處理，回到標準選擇畫面。
  • START-OF-SELECTION、GET、END-OF-SELECTION、TOP-OF-PAGE、END-OF-PAGE 只能用來建立基本清單；細節清單用 AT LINE-SELECTION 與 AT USER-COMMAND，表頭用 TOP-OF-PAGE DURING LINE-SELECTION。
  • 每個細節清單事件在程式中只能出現一次，由所有層級共用，所以要用 CASE sy-lsind 判斷目前正在產生第幾層。

HIDE 技術：HIDE global_field 把全域欄位目前的值存進「目前這一行」的隱藏區域（hide area）。

  • 使用者選一行時，所有用 HIDE 存過的全域欄位會自動回填成該行存的值。
  • 要保留的值不必用 WRITE 顯示出來。
  • 欄位可以是結構，但不支援深層結構（含內表元件的結構）。
  • AT LINE-SELECTION／AT USER-COMMAND 依游標所在行（sy-lilli）回填；用 READ LINE 讀行時則依指定行號回填。

有效行檢查：隱藏區域只有「有效行」才有資料（表頭、分隔線沒有）。清單建立完畢後先把測試欄位清空；產生細節清單前檢查它有沒有被回填；細節清單建好後再清空一次，避免使用者返回後點到無效行時，還沿用上一次的值。

5. 進階選擇畫面：版面設計與多個選擇畫面

選擇畫面是程式與使用者之間的介面，可以用來限制從資料庫讀出的資料量。PARAMETERS 與 SELECT-OPTIONS 會自動產生預設選擇畫面 1000；此外可以用 SELECTION-SCREEN BEGIN OF SCREEN nnnn 定義額外的選擇畫面，再用 CALL SELECTION-SCREEN 呼叫。邏輯資料庫的選擇畫面長相取決於 NODES 指定的節點，選擇畫面版本則是預設選擇畫面的子集。

  • BEGIN OF BLOCK … WITH FRAME TITLE …：把邏輯上相關的欄位框成一組，最多巢狀五層。
  • BEGIN OF LINE … END OF LINE：同一行放多個參數與註解。
  • COMMENT：必須給位置與長度；位置可用 pos_low／pos_high（對應 SELECT-OPTIONS 的 LOW／HIGH 欄位位置）。COMMENT … FOR FIELD f 讓游標停在註解上按 F1 也出現 f 的說明，且 f 被變式隱藏時註解一起隱藏。
  • POSITION pos：設定下一個輸出位置（只能在 BEGIN OF LINE … END OF LINE 之間）。
  • 設計前可用交易 BIBS 看 SAP 的畫面設計規範範例。
  • CALL SELECTION-SCREEN nnnn：使用者按執行 sy-subrc = 0，按取消 sy-subrc = 4。加 STARTING AT left upper ENDING AT right lower 以對話框（modal dialog）顯示。

7. 選擇畫面上的子畫面與頁籤（Tabstrip）

頁籤可以把大型選擇畫面分成幾個邏輯群組，更好用。原教材列的前提是 GUI 4.0 以上、Windows 95／NT 3.51 以上（今天都不是問題）。要做頁籤選擇畫面需要三樣東西：

  1. 選擇畫面上一個容納頁籤的子畫面區域：SELECTION-SCREEN BEGIN OF TABBED BLOCK blk FOR n LINES，n 是子畫面區域的行數。
  2. 每一頁的標題：SELECTION-SCREEN TAB (len) name USER-COMMAND ucomm [DEFAULT [PROGRAM prog] SCREEN dynnr]。用了 DEFAULT 就必須指定 SCREEN；PROGRAM 只有子畫面來自別的程式時才要寫。
  3. 每一頁的內容，是一個定義成子畫面的選擇畫面：SELECTION-SCREEN BEGIN OF SCREEN nnnn AS SUBSCREEN [NESTING LEVEL m] [NO INTERVALS]。
  • 系統會自動產生 CONTROLS: blk TYPE TABSTRIP——不要自己寫，寫了會語法錯誤。
  • 頁籤標題變數（tab1、tab2）不用宣告，它們是頁籤控制的一部分，在 INITIALIZATION 給文字。
  • 系統也會自動產生與頁籤區塊同名的結構，含 prog、dynnr、activetab 三個欄位，可在執行時改變頁籤與子畫面的對應，或指定預設開啟的頁籤（附錄 SUB-2）。
  • 在 AT SELECTION-SCREEN 中，sy-ucomm 會是使用者點的那個頁籤的命令值（例如 UCOMM1／UCOMM2）。
  • NESTING LEVEL：縮小子畫面尺寸以免出現捲軸。頁籤外面沒有群組框就用 0；每多一層包住頁籤的群組框就加 1。
  • NO INTERVALS：隱藏這個子畫面上所有 SELECT-OPTIONS 的 HIGH 欄位。
  • 定義成子畫面的選擇畫面也能嵌進一般 Dynpro 的子畫面區域（CALL SUBSCREEN），見 5-9 章 BC410。

8. 程式介面（一）：GUI 標題與 GUI 狀態的觀念

GUI 狀態（GUI Status）由選單列、標準工具列、應用工具列、功能鍵設定組成；每個畫面可以有多個 GUI 狀態（例如編輯器有「顯示」與「修改」兩個狀態）。GUI 標題與狀態都在 Menu Painter（SE41，或從 SE80 物件清單／ABAP 編輯器導覽進入）維護，並併入程式的使用者介面；新增標題或狀態後必須重新產生（啟用）介面。

元素限制與規則
GUI 標題名稱最多 20 字元、內容最多 70 字元；可用 & 或 &1～&9 當佔位符，執行時用 SET TITLEBAR t WITH v1 … v9 代入；沒重設就一直沿用；目前標題在 sy-title；可翻譯，找不到登入語言時顯示原始語言
選單列最多 8 個選單，其中 6 個可自由分配；「系統」「說明」兩個選單自動附加在每個選單列，功能固定、不能修改或隱藏
選單每個選單最多 15 個項目（功能、分隔線、子選單）；最多串接 3 層，第 3 層只能放功能與分隔線；可用靜態文字或動態文字（程式中 20 字元欄位）
包含選單引用其他程式的選單，需在「短文件」欄位填來源程式與狀態名稱；只能從選單列存取
標準工具列所有畫面都一樣，圖示固定對應保留功能鍵；當前畫面不可用的功能自動變灰
應用工具列最多 35 個按鈕，可插入分隔線分組；按鈕上的功能必須先分配功能鍵；應該是選單功能的子集
功能鍵設定由「保留功能鍵」（SAP 固定，只能啟用／停用，不能改按鍵與文字）、「建議功能鍵」（符合 SAP 人因工程標準）、「自由分配功能鍵」組成

功能（Function）以功能碼唯一識別，可指派給功能鍵、按鈕、選單項目。重要屬性：

功能類型意義
' '（空白）一般應用功能，觸發 PAI／AT USER-COMMAND
EExit Command（Dynpro 中觸發 MODULE … AT EXIT-COMMAND，略過欄位檢查）
P頁籤的本地功能（在展示層切換頁籤，不回應用伺服器）

  • 靜態文字的功能可指定圖示名稱，放在應用工具列時顯示圖示；此時「功能文字」變成快速資訊（tooltip），「資訊文字」在按下時顯示於狀態列，「圖示文字」同時顯示在圖示旁。
  • 動態文字的功能用字典結構 SMP_DYNTXT 指定文字。
  • 選單只顯示「功能文字」；「快速路徑」屬性指定用鍵盤選取的字母。
  • 技術上，GUI 狀態只是對選單列、按鍵分配、應用工具列的引用；同一個選單列可被多個狀態共用。所有選單與按鍵都引用程式的功能清單（可用 F4 查）；狀態中的功能可以是啟用或未啟用。
  • 建議功能鍵清單：Menu Painter「公用程式 → 說明文字 → 標準／建議」（附錄 GUI-4）；內部按鍵號碼（例如 Ctrl+P 對應哪個號碼）見 GUI-3。

9. 程式介面（二）：建立與使用 GUI 狀態、AT USER-COMMAND

建立狀態有三個入口：物件瀏覽器的物件清單、Menu Painter、ABAP 編輯器的導覽（在 SET PF-STATUS 'LIST' 上雙擊）。狀態類型決定技術屬性：Dialog Status（全畫面）、Dialog Box（對話框）、Context Menu（右鍵選單）。

  • 引用技術：先建一個狀態的選單列、應用工具列、功能鍵，其他狀態引用它們。Menu Painter 維護這些引用，修改會自動套用到所有引用的狀態——大型應用確保一致性的利器。
  • 全新建立：自己建選單列、功能與其他元素，修改只影響自己。兩種技術可以混用。
  • 調整範本：「其他（Extras）→ 調整範本（Adjust Template）」可把清單或選擇畫面的標準功能碼、或其他程式的狀態合併進來。寫清單程式時通常從「清單狀態」範本開始。
  • 新加入的功能一開始都是未啟用，只啟用跟目前狀態相關的功能；建立新功能時可決定是否套用到所有指向同一物件的狀態。
  • 選單項目：左欄輸入功能碼，若功能已存在且有文字會自動帶出；在文字欄輸入「-」即分隔線；只輸入名稱不輸入功能碼即成子選單，雙擊展開。
  • 分配到標準工具列的功能會自動分配到對應的保留功能鍵；Menu Painter 的「資訊」圖示可以看目前狀態每個功能鍵對應什麼。

使用狀態：

  • 狀態名稱與標題名稱最多 20 字元，一律大寫；不重設就沿用原狀態。目前狀態在 sy-pfkey。
  • 清單沒設 GUI 介面時顯示標準介面；SET PF-STATUS space 強制回到標準清單狀態。
  • SET PF-STATUS 'XXX' OF PROGRAM 'YYY' 可借用別支程式的狀態。
  • EXCLUDING fcode 在執行時停用功能；停用多個時要用內表傳入。

功能碼的流程：使用者從清單選一個功能 → 觸發功能碼 → 功能碼觸發事件。系統功能碼（如 PRI 列印、%EX 結束）是保留的，不會觸發互動事件，系統直接執行；PICK 觸發 AT LINE-SELECTION；其他所有功能碼觸發 AT USER-COMMAND，在其中用 CASE 判斷 sy-ucomm。觸發時，游標所在行的 hide area 同樣會回填到全域欄位。

10. 多行選取：READ LINE 與 MODIFY LINE

使用者常需要一次看多筆記錄的細節（例如多位客戶的地址、多位員工的銷售量）。提供多行選取時，也要一併提供「全選」與「全不選」（例如兩個按鈕）。做法是在每一行輸出一個核取方塊（WRITE … AS CHECKBOX），再逐行讀回清單緩衝區。

READ LINE n：

  • 該行所有 hide area 的值回填到對應欄位；該行內容同時放進 sy-lisel——只有 255 字元，清單過寬時只拿得到前 255 字元。
  • INDEX i：讀第 i 層清單；省略則讀最後顯示的清單 sy-listi。
  • FIELD VALUE f1 [INTO g1]：從該行讀出欄位 f1 的畫面上的值放進 g1（省略 INTO 則填回 f1）。清單緩衝區裡一律是字元（型別 c），所以讀回的值會轉成 c。
  • LINE VALUE INTO wa：整行複製到工作區。
  • 行不存在時 sy-subrc ≠ 0，常用來當迴圈結束條件。

MODIFY LINE n ／ MODIFY CURRENT LINE：

  • MODIFY CURRENT LINE 修改最後一次用行選取或 READ LINE 讀到的那一行（即使它在另一層清單）。
  • LINE FORMAT fm1 fm2 …：改整行格式（顏色、INPUT OFF 等）。
  • FIELD VALUE f1 FROM g1：用變數 g1 取代該行欄位 f1 的內容（轉成 c）；同一欄位在行中出現多次時只換第一個。
  • LINE VALUE FROM wa：用工作區取代整行。

11. 清單排序：GET CURSOR 與動態 SORT

要讓清單更有彈性，就要提供動態排序——排序依據在執行時才知道。資料先緩存在內表，再用動態 SORT：SORT itab BY (f1) [ASCENDING|DESCENDING] (f2) …，括號內是存放欄位名稱的變數。使用者排序後通常不在乎原本的清單，所以新清單應顯示在同一層。

GET CURSOR FIELD f [VALUE v] [LINE l]：取得游標所在欄位的名稱（放在 f）與畫面上的值（放在 v）。

  • sy-subrc = 0：游標在欄位上；sy-subrc = 4：不在欄位上。
  • 回傳的是完整名稱，例如 WA_SBOOK-LUGGWEIGHT，要去掉工作區／內表名稱與連字號才能拿來排序。
  • 不要把 VALUE 取得的值當 SELECT 條件——非字元欄位會型別轉換，可能產生無法預期的結果，請改用 HIDE。
  • 其他參數見附錄 ILS-3。

14. 記憶體模型：外部會話、內部會話、ABAP Memory、SAP Memory

從程式的角度，主記憶體的組織如下（筆記 p80 的圖）：

層次內容數量限制
使用者終端會話（一次登入）SAP Memory：所有外部會話共用—
外部會話（一個 SAP GUI 視窗；「系統 → 建立會話」或 /o tcode）ABAP Memory：每個外部會話各自一份每次登入最多 6 個（2007 年的值；現行由參數 rdisp/max_alt_modes 控制，預設 6、上限 16）

程式呼叫與返回時堆疊的變化：

  • CALL TRANSACTION／SUBMIT … AND RETURN：開新的內部會話放在堆疊頂端；程式正常結束或 LEAVE PROGRAM 時，最上層內部會話被移除，呼叫端繼續。
  • LEAVE TO TRANSACTION：移除堆疊中全部內部會話，開一個含新程式的上下文；ABAP Memory 被清空。
  • SUBMIT（無 AND RETURN）：用被呼叫程式的內部會話取代呼叫端的內部會話。
教材修正：筆記 p85 的 SUBMIT 圖在「呼叫後」把新會話標成「程式 <t_code>」，應該是「程式 <program>」（被 SUBMIT 的程式），那是從 LEAVE TO TRANSACTION 的圖複製過來沒改到。

呼叫函數模組時：系統先檢查這次呼叫的函數模組跟之前呼叫過的是否屬於同一個函數群組。

  • 不是 → 把該函數群組載入呼叫端的內部會話，當作程式群組的附加，並初始化函數群組的全域資料。
  • 是 → 直接存取已載入的函數群組全域資料，不會重新載入。
  • 同一內部會話中，同一函數群組的所有函數模組共用全域資料；每個用到它的內部會話都要各自載入一次。
這就是為什麼某些 BAPI 在同一支程式裡連續呼叫時會「記得」上一次的資料（函數群組的全域緩衝區沒清）。連續建單時若出現怪現象，檢查該 BAPI 是否有提供 buffer refresh 的函數（例如物料的 MATERIAL_BUFFER_REFRESH_ALL 系列），或每筆呼叫後正確 BAPI_TRANSACTION_COMMIT（見 4-1 章）。

先找標準，再想客製。CALL TRANSACTION USING 是「模擬人按畫面」，在 S/4HANA 很脆弱：Fiori 化、畫面欄位調整、新增必填欄位都會讓它失效（例如 XD01／XK01 已被 BP 取代，錄好的 BDC 直接不能用）。有 BAPI 或 released API 時一律優先用 BAPI（4-1 章），其次才是 BDC（4-4 章）。另外 MODE／UPDATE 與 OPTIONS FROM 二選一，不能同時寫。

17. S/4HANA 現況：從 WRITE 互動式清單到 CL_SALV_TABLE 事件

BC406 的每一個互動技術，在 ALV 世界都有對應。新程式請直接用 SALV（完整教學見 2-3 章 ALV、需要編輯時用 3-2 章 OOALV）：

BC406 傳統清單CL_SALV_TABLE 對應
HIDE ＋ AT LINE-SELECTIONCL_SALV_EVENTS_TABLE 的 DOUBLE_CLICK（row、column）或 LINK_CLICK（熱點）
SET PF-STATUS ＋ AT USER-COMMANDset_screen_status( ) ＋ ADDED_FUNCTION 事件（e_salv_function）
WRITE AS CHECKBOX ＋ READ LINE 逐行讀get_selections( )->set_selection_mode( ) ＋ get_selected_rows( )
GET CURSOR ＋ 動態 SORT ＋ sy-lsind - 1ALV 工具列內建排序、篩選、小計，不必自己寫
多層細節清單（sy-lsind 1～20）在事件中再開一個 SALV（可用 set_screen_popup( ) 以彈出視窗顯示）
MODIFY LINE 改顏色內表加顏色欄位（LVC_T_SCOL）＋ get_columns( )->set_color_column( )
TOP-OF-PAGEset_top_of_list( )（CL_SALV_FORM_LAYOUT_GRID）
 
REPORT zbc406_salv.

PARAMETERS pa_car TYPE s_carr_id DEFAULT 'LH'.

CLASS lcl_app DEFINITION.
  PUBLIC SECTION.
    METHODS run.
  PRIVATE SECTION.
    TYPES tt_spfli TYPE STANDARD TABLE OF spfli WITH EMPTY KEY.
    DATA mt_spfli TYPE tt_spfli.
    DATA mo_alv   TYPE REF TO cl_salv_table.
    METHODS on_double_click FOR EVENT double_click OF cl_salv_events_table
      IMPORTING row column.
    METHODS on_added_function FOR EVENT added_function OF cl_salv_events
      IMPORTING e_salv_function.
    METHODS show_flights IMPORTING it_keys TYPE tt_spfli.
ENDCLASS.

CLASS lcl_app IMPLEMENTATION.
  METHOD run.
    SELECT * FROM spfli WHERE carrid = @pa_car
      ORDER BY carrid, connid                      " 畫面順序 = 內表順序，row 才對得上
      INTO TABLE @mt_spfli.
    TRY.
        cl_salv_table=>factory( IMPORTING r_salv_table = mo_alv
                                CHANGING  t_table      = mt_spfli ).
      CATCH cx_salv_msg INTO DATA(lx).
        MESSAGE lx TYPE 'E'.
    ENDTRY.
    " GUI 狀態：先用 SE41 從程式 SAPLSALV_METADATA_STATUS 複製狀態 SALV_STANDARD，
    " 再加自己的按鈕 DETL（相當於 BC406 的 SET PF-STATUS）
    mo_alv->set_screen_status( pfstatus      = 'SALV_STANDARD'
                               report        = sy-repid
                               set_functions = mo_alv->c_functions_all ).
    mo_alv->get_selections( )->set_selection_mode( if_salv_c_selection_mode=>row_column ).
    SET HANDLER on_double_click on_added_function FOR mo_alv->get_event( ).
    mo_alv->display( ).
  ENDMETHOD.

  METHOD on_double_click.                          " 取代 HIDE + AT LINE-SELECTION
    show_flights( VALUE tt_spfli( ( mt_spfli[ row ] ) ) ).
  ENDMETHOD.

  METHOD on_added_function.                        " 取代 AT USER-COMMAND
    CASE e_salv_function.
      WHEN 'DETL'.                                 " 取代 READ LINE 逐行讀核取方塊
        DATA(lt_rows) = mo_alv->get_selections( )->get_selected_rows( ).
        IF lt_rows IS INITIAL.
          MESSAGE '請至少選一行' TYPE 'S' DISPLAY LIKE 'W'.
          RETURN.
        ENDIF.
        show_flights( VALUE tt_spfli( FOR r IN lt_rows ( mt_spfli[ r ] ) ) ).
    ENDCASE.
  ENDMETHOD.

  METHOD show_flights.                             " 取代 sy-lsind = 1 的細節清單
    DATA(lt_keys) = it_keys.
    CHECK lt_keys IS NOT INITIAL.
    SELECT f~carrid, f~connid, f~fldate, f~seatsmax, f~seatsocc
      FROM sflight AS f
      INNER JOIN @lt_keys AS k                    " 內表當資料來源需 7.52
        ON f~carrid = k~carrid AND f~connid = k~connid
      ORDER BY f~carrid, f~connid, f~fldate
      INTO TABLE @DATA(lt_flights).
    TRY.
        cl_salv_table=>factory( IMPORTING r_salv_table = DATA(lo_popup)
                                CHANGING  t_table      = lt_flights ).
        lo_popup->set_screen_popup( start_column = 10 end_column = 110
                                    start_line   = 3  end_line   = 20 ).
        lo_popup->display( ).
      CATCH cx_salv_msg.
    ENDTRY.
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.

技術現況總結：
① 傳統 WRITE 互動式清單（HIDE、READ LINE、MODIFY LINE、GET CURSOR、sy-lsind）仍可執行，但新開發請用 SALV；在 Fiori 啟動台跑時 WRITE 清單只能透過 SAP GUI for HTML，體驗差。
② 選擇畫面、GUI Status、SUBMIT、CALL TRANSACTION、ABAP／SAP Memory 在 S/4HANA SAP GUI 程式中照常使用。
③ 若是要給 Fiori／雲端使用者的報表，方向是 CDS View ＋ Fiori Elements（List Report） 或 RAP，選擇畫面變成 Filter Bar、細節清單變成 Object Page、GUI 按鈕變成 Action。ABAP Cloud（Tier 1）中 WRITE、選擇畫面、SUBMIT、CALL TRANSACTION 都不可用。
④ 邏輯資料庫（GET 事件、NODES）已過時，改用 ABAP SQL 或 CDS。

練習與自我檢核

  1. AT LINE-SELECTION 與 AT USER-COMMAND 各由什麼觸發？PRI、%EX 會觸發哪一個？
    參考答案：AT LINE-SELECTION 由功能碼 PICK（雙擊／F2）觸發；AT USER-COMMAND 由 PICK 與系統功能碼以外的所有功能碼觸發。PRI、%EX 是系統保留功能碼，兩個都不觸發，系統直接執行。
  2. 為什麼產生細節清單後要 CLEAR HIDE 的欄位？
    參考答案：hide area 只有有效行才有值。若不清空，使用者返回後點到表頭或空白行時，全域欄位還保留上一次的值，程式會誤以為選到一筆有效資料。
  3. 一張基本清單最多幾層細節清單？按綠箭頭、紅叉、黃箭頭分別會怎樣？
    參考答案：20 層。綠箭頭／紅叉回上一層並初始化離開那層的清單緩衝區；黃箭頭中斷清單處理、回標準選擇畫面。
  4. 寫一個頁籤選擇畫面時，為什麼不能自己寫 CONTROLS？如何讓畫面預設開在第 2 頁？
    參考答案：系統自動產生 CONTROLS blk TYPE TABSTRIP，重複宣告會語法錯誤。在 INITIALIZATION 設 blk-prog = sy-repid、blk-dynnr 為第 2 頁子畫面號碼、blk-activetab 為第 2 頁的 USER-COMMAND。
  5. AT SELECTION-SCREEN ON pa_car 與 AT SELECTION-SCREEN 發 E 訊息的差別？
    參考答案：前者只讓 pa_car 重新可輸入；後者讓所有欄位重新可輸入。ON BLOCK 則是該區塊的欄位。
  6. 應用工具列最多幾個按鈕？選單列最多幾個選單、可自由分配幾個？選單最多幾個項目、幾層？
    參考答案：35 個按鈕；8 個選單，6 個可自由分配（系統、說明固定）；每個選單 15 個項目，最多 3 層。
  7. 在第 1 層細節清單中按排序鈕，想讓排序後的清單取代原本的第 1 層而不是變成第 2 層，要怎麼做？sy-lsind 要何時改？
    參考答案：重新輸出後設 sy-lsind = sy-lsind - 1，且放在輸出前的最後一個敘述（或事件最後）；新層級在事件結束、清單輸出完才生效，不能設成比現有層級更大的值。
  8. READ LINE 的 FIELD VALUE 讀回的值能直接當 SELECT 條件嗎？sy-lisel 有什麼限制？
    參考答案：不建議。清單緩衝區一律是字元型，讀回的是格式化後的顯示值，型別轉換可能出錯，應改用 HIDE 回填的欄位。sy-lisel 只有 255 字元。
  9. 在細節清單事件中發 E 訊息與在 START-OF-SELECTION 發 E 訊息的結果有何不同？實務上 START-OF-SELECTION 查無資料該怎麼寫？
    參考答案：細節清單中 E 會丟棄目前細節清單、回上一層；基本清單階段 E 會終止程式。查無資料慣用 MESSAGE … TYPE 'S' DISPLAY LIKE 'E' 加 LEAVE LIST-PROCESSING 回到選擇畫面。
  10. SUBMIT、SUBMIT AND RETURN、CALL TRANSACTION、LEAVE TO TRANSACTION 對內部會話堆疊與 ABAP Memory 的影響？
    參考答案：SUBMIT AND RETURN、CALL TRANSACTION 在堆疊頂端新增內部會話，ABAP Memory 保留；SUBMIT 取代呼叫端的內部會話；LEAVE TO TRANSACTION 移除全部內部會話並清空 ABAP Memory，因此不能用 ABAP Memory 傳資料。
  11. SAP Memory 與 ABAP Memory 的範圍各是什麼？同一使用者開兩個視窗，能用 EXPORT TO MEMORY 在兩個視窗間傳內表嗎？
    參考答案：SAP Memory 是整個登入（所有外部會話共用），只存參數 ID 的值；ABAP Memory 限單一外部會話內。兩個視窗是兩個外部會話，不能用 ABAP Memory 互傳（可改用資料庫表、共用物件或 SAP Memory 傳單一值）。
  12. 每次登入最多幾個外部會話？每個外部會話最多幾個內部會話？
    參考答案：外部會話預設 6 個（rdisp/max_alt_modes，上限 16）；內部會話 9 個。
  13. BDCDATA 五個欄位是什麼？畫面識別記錄要填哪幾個？怎麼表示按下「儲存」？
    參考答案：PROGRAM、DYNPRO、DYNBEGIN、FNAM、FVAL；畫面識別記錄填 PROGRAM、DYNPRO、DYNBEGIN = 'X'；以 FNAM = 'BDC_OKCODE'、FVAL = 功能碼（例如 SAVE 或 =BU）表示。訊息收在 BDCMSGCOLL。
  14. 實作題：把第 10 節的「核取方塊 ＋ READ LINE」程式改寫成 CL_SALV_TABLE 版本，支援多選、雙擊看航班、自訂按鈕 DETL，並確保 SELECT 有 ORDER BY。
    參考答案要點：見第 17 節範例；重點是 set_selection_mode( row_column )、get_selected_rows( )、DOUBLE_CLICK／ADDED_FUNCTION 事件；內表順序要與畫面一致，否則 row 會對到錯的資料（HANA 無預設排序）。
  15. 思考題：使用者要求「在清單上勾選客戶後，按鈕一鍵修改客戶主檔」，你會用 CALL TRANSACTION USING XD02 的 BDC 嗎？
    參考答案要點：不會。S/4HANA 客戶主檔改由 BP 維護，XD02 的 BDC 已不可行；依「先找標準再客製」原則，先找 BP 的 API（CL_MD_BP_MAINTAIN、CMD_EI_API，見 4-1 章），必要時再考慮其他做法。
