3. 先找標準：MM04、RSSCD100、SCDO，何時才需要 ZMMQ0003

依 Casper 經驗第 3 條「先找標準，再想客製」，寫程式前先確認標準功能做不到：

工具能做什麼限制
MM04（Display Material Changes）輸入一個料號，列出所有變更文件，可以展開到欄位、看新舊值；也可以依變更日期或使用者縮小範圍一次只能查一個料號；不能跨料號用使用者或日期撈、不能匯出成一張清單給稽核

SCDO查物件類別 MATERIAL 包含哪些表、產生的更新函數只是定義，不是查詢工具
SE16N 查 CDHDR／CDPOS開發者自己看原始資料兩張表要分開查；OBJECTID、TABKEY 要自己組

ZMMQ0003 值得寫的理由是業務的需求：「某段期間、某些使用者、多個料號改過哪些欄位，一張表看完，最好欄位是中文，還能點回 MM03」。如果需求只是偶爾查一個料號，教使用者用 MM04 就好。

包成交易碼比寫新程式便宜：如果 RSSCD100 就夠用，只是使用者沒有 SA38 權限，可以用 SE93 建一個參數交易碼，預填 OBJECTCLAS = MATERIAL 並隱藏該欄位。這樣零開發就能交付，也比給 SA38 權限安全。

6. 關鍵段落改寫（二）：CDHDR JOIN CDPOS，三個鍵都要對上

這是原程式最嚴重的錯誤。原本的 JOIN 條件只寫了 a~objectclas = b~objectclas，等於讓每一筆 CDPOS 對上所有物件類別同為 MATERIAL 的 CDHDR，形成笛卡兒積：一個料號改一個欄位，會配上全系統幾十萬筆物料變更檔頭，而異動人、日期全是別人的。原程式靠 UP TO 1000 ROWS 才沒有跑到逾時，但畫面上的 username、udate 幾乎都是錯的。正確的 JOIN 必須三個鍵都對上：OBJECTCLAS、OBJECTID、CHANGENR。

  METHOD get_data.
    " S/4HANA 的 CDPOS 是透明表，可以直接 JOIN（ECC 是 cluster table，見 6-8 章）
    SELECT h~objectid, h~changenr, h~username, h~udate, h~utime, h~tcode,
           p~tabname, p~tabkey, p~fname, p~chngind,
           p~value_old, p~value_new, p~unit_old, p~unit_new, p~cuky_old, p~cuky_new
      FROM cdhdr AS h
      INNER JOIN cdpos AS p
         ON p~objectclas = h~objectclas
        AND p~objectid   = h~objectid          " ← 原程式漏了
        AND p~changenr   = h~changenr          " ← 原程式漏了
      WHERE h~objectclas = 'MATERIAL'           " 一定要帶物件類別（主鍵第一欄）
        AND h~objectid  IN @s_matnr
        AND h~udate     IN @s_udate
        AND h~username  IN @s_uname
        AND p~tabname   IN @s_tabnm
      ORDER BY h~objectid, h~udate, h~utime, h~changenr, p~tabname, p~tabkey, p~fname
      INTO TABLE @DATA(lt_raw)
      UP TO @p_max ROWS.

    IF lines( lt_raw ) = p_max.
      MESSAGE |已達筆數上限 { p_max }，請縮小日期或料號範圍| TYPE 'I'.
    ENDIF.

    " MATNR 長度（S/4HANA 為 40）用 RTTS 取得，不寫死位移
    DATA(lv_len) = CAST cl_abap_elemdescr(
                     cl_abap_typedescr=>describe_by_name( 'MATNR' ) )->output_length.
    DATA(lv_off) = 3 + lv_len.        " MANDT(3) + MATNR

    rt_out = VALUE #( FOR r IN lt_raw
      ( VALUE ty_out( BASE CORRESPONDING #( r )
          matnr = CONV #( r-objectid )
          werks = COND #( WHEN r-tabname = 'MARC' OR r-tabname = 'MARD'
                          THEN substring( val = r-tabkey off = lv_off len = 4 ) ) ) ) ).
  ENDMETHOD.
關於 output_length：CHAR 型資料元素的 output_length 就等於欄位長度，但若料號用了特殊的轉換常式，輸出長度可能不同。保險的做法是用 cl_abap_elemdescr->length 除以 cl_abap_char_utilities=>charsize，或在 SE11 確認 MATNR 長度後定義成常數。這裡的重點是：不要把 18 或 40 散落在程式各處。
Casper 經驗第 1 條：HANA 沒有預設排序。原程式的 SET_SORT 只對 objectclas 排序，但所有資料都是 MATERIAL，排了等於沒排，每次執行的列序都可能不同。改寫版在 SQL 就用 ORDER BY … udate, utime, changenr 明確排序。如果之後要做「取某欄位最後一次的新值」，一定要依 CHANGENR 排序後再取最後一筆。

10. 插件位置報表：業務情境、程式編號差異與「標準真的沒有嗎？」

業務情境：電子組裝廠把印刷電路板組裝（PCBA）發包給加工廠（外包採購，ME23N 的項目類別 L），並把零件以 RESB 預留一起發料。加工廠除了零件與數量，還需要每顆零件在板子上的插件位置（reference designator，例如電容 C50、C53、C59、C70），才能設定置件機。這張報表就是給加工廠的作業清單：每個子階料號一列，下面接著列出它的所有插件位置。

程式編號差異：素材目錄寫「02-01．ZMMI0003 插件位置報表」，第 02 節的內文標題卻寫「ZMMI0005 插件位置報表」；程式碼本身是 REPORT zmmi0003，include 是 ZMMI0003TOP／ZMMI0003F01，而 TOP 的檔頭註解又寫 ZPPR0002TOP，訊息類別用 ZPP01。可以推測它是從 PP 報表 ZPPR0002 複製改名而來。本章依程式碼稱為 ZMMI0003，並以 ZMMI0005 為其交易碼或文件編號的別名；實際物件名稱請以 SE38 為準。

教材說法需要修正：講義 02-02 寫「SAP 標準功能沒有插件位置的功能，不得已才客製的」。這句話不精確。SAP 標準 BOM 有子項目（sub-item），存在 STPU，每個子項目有安裝點 EBORT（Installation point）與子項目數量 UPMNG，正是為電子業的插件位置設計的，在 CS02 的項目上按「Sub-items」就能維護。這家公司的插件位置之所以放在自建表 ZPPBOMDHD0001（表頭）／ZPPBOMDDE0001（明細，PLGIN1～PLGIN40A 共 80 個文字欄位），比較可能的原因是資料從 PLM 或 ECN 系統整批匯入，而且要附帶加工指令、備註 1～5 等標準沒有的欄位。
所以正確的說法是：「標準有 STPU-EBORT，但這家公司選擇了自建表」。§15 兩種寫法都會示範。STPO 本身沒有安裝點欄位；有人說「STPO-EBORT」，請以 SE11 確認，筆者所知的安裝點欄位在 STPU。

講義也列了兩個標準交易，供核對報表結果：CS11（多階 BOM 展開，依層次）與 CS14（BOM 比較，用來比 E-BOM 與 M-BOM、或兩個 ECN 之間的差異）。另外 CS12 是多階結構展開、CS15 是反查用途（where-used），CC03 可以查 ECN 變更號碼（AENNR）的內容。

14. 關鍵段落改寫（二）：抓對 BOM 版本與 ECN（2022-12 修正案的正解）

事件經過（講義 02-02 與程式註解 20221227）：報表用預留的 RESB-AENNR（ECN 號碼）去對自建表 ZPPBOMDHD0001 的表頭，找到該 ECN 版本的插件位置。當外包料號是半成品 PCA-XXXX-B-01，而它的上階是 PCA-XXXX-AS 時，就會對錯版本。截圖顯示：

料號生產版本（MM03 → MRP 4 → ProdVersions）講義註記
PCA-XXXX-B（成品）0001 M-BOM，2019 起有效「001 M-BOM（生產版本，正確）」

  3. 依料號命名規則判斷（CS '-AS'）。編碼規則一改就失效，和 Casper 經驗第 2 條同一類問題：用字串規則代替業務屬性。

16. 關鍵段落改寫（四）：多階展開時「物料群組下階不展開」

原程式的做法是：多階展開取得 CSCMAT，然後對每個組件呼叫 CSEP_MAT_BOM_SELECT_WHERE_USED 反查上階，再用遞迴的 PERFORM process_t_do 一層層往上找，看是否有祖先的物料群組落在 S_MATKL，有的話就放進 T_SKIP。這段有兩個問題：一是反查整個系統的 where-used，資料量隨 BOM 用途爆炸，而且沒有防循環；二是 process_where_used 裡 APPEND 的是 t_cscmat-matnr（外層 header line 的殘值），而不是正在檢查的 lt_tmp-matnr，所以跳過的料號可能是錯的。

改寫：不必反查。從上往下自己遞迴單階展開，遇到排除群組的組件就只列出、不往下展。

  METHOD explode.
    " iv_level：目前層次；it_path：從頂層到目前的料號，用來防止 BOM 循環
    DATA lt_stb TYPE STANDARD TABLE OF stpox  WITH EMPTY KEY.
    DATA lt_mat TYPE STANDARD TABLE OF cscmat WITH EMPTY KEY.

    DATA(lv_stlal) = get_stlal( iv_matnr = iv_matnr iv_werks = iv_werks iv_date = iv_date ).

    CALL FUNCTION 'CS_BOM_EXPL_MAT_V2'
      EXPORTING capid = 'PP01'  datuv = iv_date  emeng = iv_qty
                mehrs = space   mtnrv = iv_matnr werks = iv_werks
                stlan = iv_stlan stlal = lv_stlal
      TABLES    stb = lt_stb  matcat = lt_mat
      EXCEPTIONS OTHERS = 1.
    IF sy-subrc <> 0.
      RETURN.                                   " 沒有 BOM＝葉節點
    ENDIF.
    SORT lt_stb BY posnr alprf.

    LOOP AT lt_stb INTO DATA(ls_stb).
      APPEND VALUE #( level = iv_level  posnr = ls_stb-posnr  idnrk = ls_stb-idnrk
                      postp = ls_stb-postp  use = ls_stb-mnglg  aennr = ls_stb-aennr
                      stlty = ls_stb-stlty  stlnr = ls_stb-stlnr
                      stlkn = ls_stb-stlkn  stpoz = ls_stb-stpoz ) TO mt_out.

      " 排除群組：只列不展。S_MATKL 空白時不排除任何群組
      DATA(lv_matkl) = get_matkl( ls_stb-idnrk ).               " hashed buffer 讀 MARA
      DATA(lv_stop)  = xsdbool( s_matkl[] IS NOT INITIAL AND lv_matkl IN s_matkl ).

         OR line_exists( it_path[ table_line = ls_stb-idnrk ] )  " 防循環
         OR lv_stop = abap_true.
        CONTINUE.
      ENDIF.

      explode( iv_matnr = ls_stb-idnrk  iv_werks = iv_werks  iv_stlan = iv_stlan
               iv_date  = iv_date       iv_qty   = ls_stb-mnglg
               iv_level = iv_level + 1
               it_path  = VALUE #( BASE it_path ( ls_stb-idnrk ) ) ).
    ENDLOOP.
  ENDMETHOD.
