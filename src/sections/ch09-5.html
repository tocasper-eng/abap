2. ZDOWNLOAD_UPLOAD_TABLE：業務情境與風險定位

這支程式的原始需求很單純：把 A 系統某張表整張下載成 txt 或 xls，再上傳到 B 系統同名的表。常見用途是把開發機的自建對照表（例如科目對照、介面參數表）搬到測試機，或者把測試資料備份下來。原程式的選擇畫面有四個輸入：表名、檔案路徑、下載／上傳選項按鈕，以及「上傳前先清空整張表」的勾選框。

原程式的做法可以歸納成三步：

  1. 用 DDIF_FIELDINFO_GET 讀出表的欄位，組成 field catalog，再用 cl_alv_table_create=>create_dynamic_table 產生動態內表。
  2. 下載時執行 SELECT * FROM (p_tbma)。txt 格式用 GUI_DOWNLOAD 輸出，xls 格式用 OLE 一格一格寫進 Excel。
  3. 上傳時先把 txt 讀進來（GUI_UPLOAD），或者用自己複製的 ZALSM_EXCEL_TO_INTERNAL_TABLE 讀 Excel。如果有勾選清空，就執行 DELETE FROM (p_tbma)，最後用 MODIFY (p_tbma) FROM TABLE 寫入。
先講風險，再講程式。這種萬用上傳工具在任何系統都等於一把萬能鑰匙：
  • 它繞過業務邏輯。直接寫 MARA、BKPF、VBAK 之類的標準表時，不會經過檢查、不會更新相關表（例如總帳餘額、索引表、狀態表），也不會觸發工作流程或 BAdI，資料一致性會直接崩壞。
  • 它繞過變更文件。CDHDR／CDPOS 是由應用程式呼叫變更文件函數寫入的，直接 MODIFY 不會留下任何紀錄。稽核時查不到是誰在什麼時候改了資料。
  • 原程式沒有任何防護：沒有權限檢查、沒有鎖定、不限制表名。只要能執行這支程式，就能把整張標準表清空。
因此本章的結論是：這種工具只能用在自建的 Z／Y 表，而且只能在開發或測試系統執行。標準表的資料要改用 LSMW、Migration Cockpit 或 BAPI 匯入（見第 9 節）。

相關章節：只要「下載」的話，6-13 章有完整的 CSV／TXT 下載器（UTF-8 BOM、表頭、引號跳脫）。要找出資料在哪張表、列出表的欄位，請看 6-10 章（特別是第 12 節 DDIF_FIELDINFO_GET 與 RTTS）。

3. 選擇畫面：限制可輸入的表

原程式用 SELECTION-SCREEN COMMENT 加上在 INITIALIZATION 把中文字寫死的方式做畫面，表名欄位參照 tabname16，檔案路徑參照 rlgrap-filename（最多 128 字元）。現代寫法改用文字元素（SE38 → 跳到 → 文字元素 → 選擇文字）。表名在 AT SELECTION-SCREEN 就先擋掉，不讓使用者跑到後面才出錯。

5. 關鍵改寫（一）：RTTS 建立動態內表

原程式同一張表的結構建了兩次：get_tab_strc 用 cl_alv_table_create=>create_dynamic_table 建一次，download_table 又用 RTTS 建一次。create_dynamic_table 內部用 GENERATE SUBROUTINE POOL 產生程式，同一個 internal session 最多只能產生 36 次，而且 field catalog 只帶 inttype、intlen、decimals，會遺失資料元素的參照，包括轉換常式（ALPHA）、幣別參照與欄位文字。RTTS 直接依 DDIC 型別建立內表，完整保留這些資訊：

METHOD create_table_ref.
  " 1) 依名稱取型別描述；不存在或不是結構就拋例外
  cl_abap_typedescr=>describe_by_name(
    EXPORTING  p_name         = mv_tab
    RECEIVING  p_descr_ref    = DATA(lo_type)
    EXCEPTIONS type_not_found = 1 ).
  IF sy-subrc <> 0 OR lo_type->kind <> cl_abap_typedescr=>kind_struct.
    RAISE EXCEPTION NEW lcx_gate( |{ mv_tab } 不是資料字典中的表或結構| ).
  ENDIF.
  mo_line = CAST cl_abap_structdescr( lo_type ).

  " 2) 行型別 → 表型別 → 建立資料物件
  DATA(lo_tab) = cl_abap_tabledescr=>create( p_line_type = mo_line ).
  CREATE DATA mr_data TYPE HANDLE lo_tab.
ENDMETHOD.
欄位清單可以直接取 mo_line->get_ddic_field_list( )，回傳的是 DFIES 表，內容和 DDIF_FIELDINFO_GET 相同（含 fieldtext、convexit、reftable／reffield），不用再呼叫一次函數。詳見 6-10 章第 12 節。

6. 關鍵改寫（二）：動態 SELECT 與下載 TXT

原程式的寫法是 SELECT * FROM (p_tbma) INTO CORRESPONDING FIELDS OF TABLE，表名直接取自使用者輸入，而且沒有排序。改寫時要注意四件事：主機變數加 @；明確寫 ORDER BY PRIMARY KEY（HANA 沒有預設排序，同一張表下載兩次的順序可能不同，比對檔案時會很困擾）；設筆數上限；表名先經過 check_table_name_str 驗證（第 7 節）。輸出時自己把每一列組成 tab 分隔的字串，這樣欄位順序、表頭和編碼都由程式控制：

METHOD download.
  FIELD-SYMBOLS <lt_data> TYPE STANDARD TABLE.
  ASSIGN mr_data->* TO <lt_data>.

  DATA(lv_tab) = cl_abap_dyn_prg=>check_table_name_str(   " 防注入，見第 7 節
                   val = mv_tab packages = '' ).
  SELECT * FROM (lv_tab)
    ORDER BY PRIMARY KEY
    INTO TABLE @<lt_data>
    UP TO 500000 ROWS.

  " 表頭 = 技術欄位名（上傳時用來核對欄位順序）
  DATA(lt_fields) = mo_line->get_ddic_field_list( ).
  DATA(lv_tabch)  = cl_abap_char_utilities=>horizontal_tab.
  DATA(lt_out) = VALUE string_table(
    ( concat_lines_of( table = VALUE string_table( FOR f IN lt_fields ( CONV #( f-fieldname ) ) )
                       sep   = lv_tabch ) ) ).

  LOOP AT <lt_data> ASSIGNING FIELD-SYMBOL(<ls_row>).
    DATA(lv_line) = ``.
    DO lines( lt_fields ) TIMES.
      ASSIGN COMPONENT sy-index OF STRUCTURE <ls_row> TO FIELD-SYMBOL(<lv_val>).
      " 不加格式 = 內部格式：日期 YYYYMMDD、金額不乘幣別因子、保留前導零
      lv_line = COND #( WHEN sy-index = 1 THEN |{ <lv_val> }|
                        ELSE |{ lv_line }{ lv_tabch }{ <lv_val> }| ).
    ENDDO.
    APPEND lv_line TO lt_out.
  ENDLOOP.

  cl_gui_frontend_services=>gui_download(
    EXPORTING filename  = p_file
              filetype  = 'ASC'
              codepage  = '4110'          " UTF-8
              write_bom = abap_true
    CHANGING  data_tab  = lt_out
    EXCEPTIONS OTHERS   = 1 ).
  IF sy-subrc <> 0.
    RAISE EXCEPTION NEW lcx_gate( |下載失敗：{ p_file }| ).
  ENDIF.
  MESSAGE |{ mv_tab } 共下載 { lines( <lt_data> ) } 筆| TYPE 'S'.
ENDMETHOD.
內部格式與外部格式要分清楚。這支工具的目的是「A 系統的表搬到 B 系統的同一張表」，所以下載和上傳都要用內部格式（不做 ALPHA、不乘幣別因子、日期不加分隔符號），兩邊才會對稱。如果檔案是要給人看或給外部系統用，就必須轉成外部格式，否則台幣、日圓金額會差 100 倍（見第 10 節）。兩種用途不要共用同一個檔案。
原程式的 write_field_separator = g_tab（傳入 tab 字元）也能正常運作，因為這個參數只判斷有沒有值，有值就用 tab 分隔。正確寫法是傳 abap_true。原程式的 xls 格式其實是用 OLE 讓前端的 Excel 存檔，背景作業不能執行、速度極慢（每一格都要往返 GUI 一次），而且只支援 .xls。

7. 關鍵改寫（三）：上傳前的四道閘門

原程式完全沒有這一段。上傳是這支工具最危險的功能，所以在讀檔之前，要依序檢查四件事：

  1. 表名防注入與白名單：cl_abap_dyn_prg=>check_table_name_str 確認輸入的確實是一張資料庫表，不是夾帶 SQL 片段的字串。packages 參數可以把範圍限縮在指定套件（介面請以 SE24 確認）。
  2. DD02L 檢查：必須是透明表（TABCLASS = TRANSP），交付類別（CONTFLAG）只允許 A（應用資料）或 C（客戶設定），不允許 S、W 這類系統表。
  3. 系統角色：T000-CCCATEGORY = 'P'（生產用戶端）時一律拒絕。
  4. 權限：S_TABU_NAM（ACTVT 02 變更、TABLE = 表名）。沒有權限時，使用者可以用 SU53 看缺了哪一項。
METHOD check_gate.
  " 1) 防注入：不是 DB 表會拋 cx_abap_not_a_table
  TRY.
      DATA(lv_tab) = cl_abap_dyn_prg=>check_table_name_str(
                       val = mv_tab packages = '' ).
    CATCH cx_abap_not_a_table cx_abap_not_in_package.
      RAISE EXCEPTION NEW lcx_gate( |{ mv_tab } 不是可用的資料庫表| ).
  ENDTRY.

  " 2) 只允許 Z／Y 透明表，交付類別 A 或 C（列舉，不用區間）
  SELECT SINGLE tabclass, contflag FROM dd02l
    WHERE tabname  = @lv_tab
      AND as4local = 'A'
      AND as4vers  = '0000'
    INTO @DATA(ls_dd02l).
  IF sy-subrc <> 0
     OR ls_dd02l-tabclass <> 'TRANSP'
     OR NOT ( ls_dd02l-contflag = 'A' OR ls_dd02l-contflag = 'C' )
     OR NOT ( lv_tab(1) = 'Z' OR lv_tab(1) = 'Y' ).
    RAISE EXCEPTION NEW lcx_gate( |{ lv_tab } 不是可上傳的自建透明表| ).
  ENDIF.

  " 3) 生產用戶端一律拒絕
  SELECT SINGLE cccategory FROM t000 WHERE mandt = @sy-mandt
    INTO @DATA(lv_role).
  IF lv_role = 'P'.
    RAISE EXCEPTION NEW lcx_gate( '生產用戶端不可使用此工具上傳' ).
  ENDIF.

  " 4) 表層級權限
  AUTHORITY-CHECK OBJECT 'S_TABU_NAM'
    ID 'ACTVT' FIELD '02'
    ID 'TABLE' FIELD lv_tab.
  IF sy-subrc <> 0.
    RAISE EXCEPTION NEW lcx_gate( |沒有 { lv_tab } 的變更權限（S_TABU_NAM），請看 SU53| ).
  ENDIF.
ENDMETHOD.
下載一樣要檢查權限（S_TABU_NAM 的 ACTVT = 03），否則這支程式會變成「繞過 SE16 權限的後門」，可以讀到薪資（PA0008）或銀行帳號這類敏感表。實務上可以再加一張 Z 對照表，列出「允許用這支工具搬運的表」，用明確列舉的方式管理，比用前綴判斷更可靠。

8. 關鍵改寫（四）：讀檔、逐欄轉換、鎖定後寫入

原程式用 GUI_UPLOAD 直接把檔案讀進動態內表。這種讀法遇到欄位長度或型別不符時會整批失敗，而且看不出是第幾列、第幾欄出錯。原程式讀 Excel 的邏輯還有一個錯誤：每一列的第一格一律填成 sy-mandt，所以跨用戶端表（沒有 MANDT）的第一個鍵值欄位會被蓋成用戶端代號。改寫的做法是先讀成字串表，核對表頭，再逐欄指定並攔截轉換錯誤：

METHOD upload.
  FIELD-SYMBOLS <lt_data> TYPE STANDARD TABLE.
  ASSIGN mr_data->* TO <lt_data>.

  DATA lt_raw TYPE string_table.
  cl_gui_frontend_services=>gui_upload(
    EXPORTING filename = p_file filetype = 'ASC' codepage = '4110'
    CHANGING  data_tab = lt_raw
    EXCEPTIONS OTHERS  = 1 ).
  IF sy-subrc <> 0 OR lt_raw IS INITIAL.
    RAISE EXCEPTION NEW lcx_gate( |無法讀取 { p_file }| ).
  ENDIF.

  DATA(lv_tabch)  = cl_abap_char_utilities=>horizontal_tab.
  DATA(lt_fields) = mo_line->get_ddic_field_list( ).

  " 第 1 列必須是欄位名，而且順序要與 DDIC 完全一致
  SPLIT lt_raw[ 1 ] AT lv_tabch INTO TABLE DATA(lt_head).
  IF lines( lt_head ) <> lines( lt_fields ).
    RAISE EXCEPTION NEW lcx_gate( '檔案欄位數與資料表不符，請先重新下載範本' ).
  ENDIF.
  LOOP AT lt_fields INTO DATA(ls_f).
    DATA(lv_col) = replace( val = lt_head[ sy-tabix ] sub = cl_abap_char_utilities=>byte_order_mark_utf8 with = `` ).
    IF to_upper( condense( lv_col ) ) <> ls_f-fieldname.
      RAISE EXCEPTION NEW lcx_gate( |第 { sy-tabix } 欄應為 { ls_f-fieldname }| ).
    ENDIF.
  ENDLOOP.

  DATA(lv_err) = 0.
  LOOP AT lt_raw INTO DATA(lv_raw) FROM 2.
    DATA(lv_rowno) = sy-tabix.
    SPLIT lv_raw AT lv_tabch INTO TABLE DATA(lt_cells).
    APPEND INITIAL LINE TO <lt_data> ASSIGNING FIELD-SYMBOL(<ls_row>).
    LOOP AT lt_cells INTO DATA(lv_cell).
      ASSIGN COMPONENT sy-tabix OF STRUCTURE <ls_row> TO FIELD-SYMBOL(<lv_val>).
      CHECK sy-subrc = 0.
      TRY.
          <lv_val> = lv_cell.                     " 內部格式直接指定
        CATCH cx_sy_conversion_error INTO DATA(lx_conv).
          lv_err += 1.                            " += 需 7.54 以上；舊版寫 lv_err = lv_err + 1
          MESSAGE |第 { lv_rowno } 列第 { sy-tabix } 欄：{ lx_conv->get_text( ) }| TYPE 'I'.
      ENDTRY.
    ENDLOOP.
  ENDLOOP.

  IF lv_err > 0.
    RAISE EXCEPTION NEW lcx_gate( |有 { lv_err } 個欄位轉換失敗，已中止| ).
  ENDIF.
  MESSAGE |讀入 { lines( <lt_data> ) } 筆{ COND #( WHEN p_test = abap_true THEN '（模擬，未寫入）' ) }| TYPE 'S'.
ENDMETHOD.

寫入時一定要先鎖表。ENQUEUE_E_TABLE 是通用的表鎖，SM30 維護檢視也用同一個鎖物件，所以上傳期間別人無法在 SM30 修改同一張表。原程式用 CATCH cx_root 把所有錯誤都吃掉，而且沒有 ROLLBACK；如果 DELETE 成功、MODIFY 失敗，程式結束時的隱含 COMMIT 會讓整張表被清空。

METHOD write_db.
  FIELD-SYMBOLS <lt_data> TYPE STANDARD TABLE.
  ASSIGN mr_data->* TO <lt_data>.
  DATA(lv_tab) = cl_abap_dyn_prg=>check_table_name_str( val = mv_tab packages = '' ).

  CALL FUNCTION 'ENQUEUE_E_TABLE'
    EXPORTING  mode_rstable   = 'E'
               tabname        = lv_tab
    EXCEPTIONS foreign_lock   = 1
               system_failure = 2
               OTHERS         = 3.
  IF sy-subrc <> 0.
    RAISE EXCEPTION NEW lcx_gate( |{ lv_tab } 正被他人鎖定（SM12 查詢）| ).
  ENDIF.

  TRY.
      IF p_clear = abap_true.
        DELETE FROM (lv_tab).                     " 只清目前用戶端
      ENDIF.
      MODIFY (lv_tab) FROM TABLE @<lt_data>.
      COMMIT WORK AND WAIT.
      MESSAGE |{ lv_tab } 寫入 { lines( <lt_data> ) } 筆| TYPE 'S'.
    CATCH cx_sy_open_sql_db cx_sy_dynamic_osql_error INTO DATA(lx_sql).
      ROLLBACK WORK.                              " DELETE 與 MODIFY 一起還原
      CALL FUNCTION 'DEQUEUE_E_TABLE'
        EXPORTING mode_rstable = 'E' tabname = lv_tab.
      RAISE EXCEPTION NEW lcx_gate( |寫入失敗已還原：{ lx_sql->get_text( ) }| ).
  ENDTRY.

  CALL FUNCTION 'DEQUEUE_E_TABLE'
    EXPORTING mode_rstable = 'E' tabname = lv_tab.
ENDMETHOD.
自建表如果需要稽核軌跡，可以在 SE13（技術設定）勾選「Log data changes」，並確認系統參數 rec/client 已經開啟，之後就能在 SCU3 查到直接 MODIFY 的變更紀錄。這是唯一能讓這類工具留下紀錄的標準方法。

10. 幣別小數位：TCURX 與 CURRENCY_CONVERTING_FACTOR

SAP 的金額欄位（資料型別 CURR）在 DDIC 中大多定義為 2 位小數，例如 WRBTR 是 CURR 13,2。但日圓、韓圜沒有小數，SAP 的處理方式是：資料庫一律照 2 位小數存放，小數位數不同的幣別，存進去之前先換算。換算依據是 TCURX 表（OY04 維護）：

  • TCURX-CURRKEY 幣別、TCURX-CURRDEC 小數位數。
  • TCURX 沒有這個幣別時，視為 2 位小數（大多數幣別都不在 TCURX 裡）。
  • CURRDEC 大於 5 會報錯（例外 TOO_MANY_DECIMALS）。
  • 換算因子 = 100 ÷（10 的 CURRDEC 次方）：0 位 → 100，2 位 → 1，3 位（如 KWD、BHD）→ 0.1，4 位 → 0.01。
幣別CURRDEC因子畫面金額DB（SE16）看到的值
USD、EUR（不在 TCURX）2（預設）11,234.561234.56
JPY、KRW0100123,4561234.56
TWD（台灣專案多設為 0）010050,000500.00
KWD30.11.23412.34
下載或介面忘記轉換，台幣金額就會差 100 倍。台灣專案通常會在 TCURX（OY04）把 TWD 設為 0 位小數。這時 SE16 或直接 SELECT 看到的 500.00 其實是新台幣 50,000 元。直接寫到 CSV、Power BI 或外部資料庫，對方收到的金額就少了 100 倍；反方向從外部檔案寫進 SAP 沒有換算，金額就多 100 倍。請先用 SE16 查 TCURX，確認自己系統中 TWD 的設定。TCURX 上線之後絕對不能修改，改了之後既有資料的解讀全部會跟著改變。

素材中的兩段 FORM 可以改寫成一個靜態方法。取得因子的方式有兩種：呼叫標準函數，或直接讀 TCURX 自己計算。

CLASS lcl_curr DEFINITION.
  PUBLIC SECTION.
    CLASS-METHODS factor IMPORTING iv_waers         TYPE waers
                         RETURNING VALUE(rv_factor) TYPE decfloat34.
ENDCLASS.

CLASS lcl_curr IMPLEMENTATION.
  METHOD factor.
    " 做法 A：標準函數
    DATA lv_f TYPE p LENGTH 8 DECIMALS 5.   " 原筆記用 DECIMALS 3，4 位小數幣別（0.01）還夠；保守起見放大
    CALL FUNCTION 'CURRENCY_CONVERTING_FACTOR'
      EXPORTING  currency          = iv_waers
      IMPORTING  factor            = lv_f
      EXCEPTIONS too_many_decimals = 1
                 OTHERS            = 2.
    IF sy-subrc = 0 AND lv_f <> 0.
      rv_factor = lv_f.
      RETURN.
    ENDIF.

    " 做法 B：直接讀 TCURX（規則相同）
    SELECT SINGLE currdec FROM tcurx
      WHERE currkey = @iv_waers
      INTO @DATA(lv_dec).
    IF sy-subrc <> 0.
      lv_dec = 2.                           " 沒維護 = 2 位
    ENDIF.
    rv_factor = 100 / ipow( base = 10 exp = lv_dec ).
  ENDMETHOD.
ENDCLASS.

" 使用：DB 值 → 真實金額（外部）
DATA(lv_display) = CONV decfloat34( ls_bseg-wrbtr ) * lcl_curr=>factor( ls_bkpf-waers ).
" 真實金額 → DB 值（素材例 1 的「除以因子」就是這個方向）
DATA(lv_internal) = CONV wrbtr( lv_display / lcl_curr=>factor( ls_bkpf-waers ) ).
素材例 2 在函數失敗時把因子設成 1。這個預設沒有錯（2 位小數的因子就是 1），但會把 TOO_MANY_DECIMALS 這類設定錯誤默默吞掉。改寫時建議至少記錄一筆警告。

11. 內外部金額轉換函數與 BAPI 的外部格式

不想自己乘除因子的話，SAP 有兩組現成函數，差別在於用途：

函數方向用途
CURRENCY_AMOUNT_SAP_TO_DISPLAY內部 → 外部報表、下載、給人看的金額
CURRENCY_AMOUNT_DISPLAY_TO_SAP外部 → 內部上傳檔案寫回 SAP 前的換算
BAPI_CURRENCY_CONV_TO_EXTERNAL內部 → 外部BAPI／RFC 介面，外部欄位是 BAPICURR（23 位、4 位小數）
BAPI_CURRENCY_CONV_TO_INTERNAL外部 → 內部同上，另有位數上限檢查，回傳 RETURN
 
" 內部 → 外部（顯示用）
DATA lv_disp TYPE p LENGTH 15 DECIMALS 2.   " 外部值用較寬的欄位，避免 0 位小數幣別溢位
CALL FUNCTION 'CURRENCY_AMOUNT_SAP_TO_DISPLAY'
  EXPORTING  currency        = 'TWD'
             amount_internal = ls_item-wrbtr          " DB 值 500.00
  IMPORTING  amount_display  = lv_disp                " 50000.00
  EXCEPTIONS internal_error  = 1
             OTHERS          = 2.

" 外部 → 內部（上傳寫回前）
DATA lv_int TYPE wrbtr.
CALL FUNCTION 'CURRENCY_AMOUNT_DISPLAY_TO_SAP'
  EXPORTING  currency        = 'TWD'
             amount_display  = CONV wrbtr( '50000' )
  IMPORTING  amount_internal = lv_int                 " 500.00
  EXCEPTIONS internal_error  = 1
             OTHERS          = 2.
" BAPI 介面的金額是外部格式（BAPICURR_D），呼叫 BAPI 前後常用這一組
DATA lv_ext TYPE bapicurr_d.
CALL FUNCTION 'BAPI_CURRENCY_CONV_TO_EXTERNAL'
  EXPORTING currency        = 'JPY'
            amount_internal = ls_item-wrbtr           " 1234.56
  IMPORTING amount_external = lv_ext.                 " 123456.0000

DATA: lv_back TYPE wrbtr, ls_ret TYPE bapireturn.
CALL FUNCTION 'BAPI_CURRENCY_CONV_TO_INTERNAL'
  EXPORTING currency             = 'JPY'
            amount_external      = lv_ext
            max_number_of_digits = 13                 " 目標欄位的總位數
  IMPORTING amount_internal      = lv_back
            return               = ls_ret.
IF ls_ret-type = 'E'.
  MESSAGE ls_ret-message TYPE 'I'.                    " 位數超過上限
ENDIF.
多數標準 BAPI（例如 BAPI_ACC_DOCUMENT_POST 的 CURRENCYAMOUNT）的金額欄位本來就是外部格式，BAPI 內部會自己換算。呼叫這類 BAPI 時直接傳畫面上的金額，不要再自己除以因子，否則日圓、台幣會少 100 倍。上面兩個函數的參數型別請以 SE37 確認。

12. 金額輸出：WRITE CURRENCY、字串範本與 SALV

在清單或字串中顯示金額時，不必呼叫函數。語言本身就支援依 TCURX 放置小數點：

DATA(lv_amt)   = CONV wrbtr( '1234.56' ).   " DB 內部值
DATA(lv_waers) = CONV waers( 'JPY' ).

" 1) WRITE ... CURRENCY：依 TCURX 決定小數位並加千分位
DATA lv_text TYPE c LENGTH 20.
WRITE lv_amt TO lv_text CURRENCY lv_waers.     " → 123,456

" 2) 字串範本的 CURRENCY 格式選項（可與 NUMBER 搭配）
DATA(lv_msg) = |金額 { lv_amt CURRENCY = lv_waers NUMBER = USER } { lv_waers }|.
" → 金額 123,456 JPY（千分位符號依使用者設定）

" 3) SALV：指定幣別參照欄，ALV 會自動處理小數位與加總
TRY.
    lo_salv->get_columns( )->get_column( 'WRBTR' )->set_currency_column( 'WAERS' ).
  CATCH cx_salv_not_found cx_salv_data_error.
ENDTRY.
字串範本如果沒有加 CURRENCY =，|{ lv_amt }| 輸出的是 1234.56（內部值）。下載 CSV 時最常在這裡出錯。ALV 忘了設 currency 欄位時也一樣，日圓顯示成 1,234.56，而且加總時會把不同幣別的金額直接相加。另一個常見錯誤是把 WRITE 的結果存回數值欄位；WRITE 的結果只能用來顯示。

13. 匯率換算：CONVERT_TO_LOCAL_CURRENCY 與 TCURR

小數位的換算只是「同一個幣別的內外部表示」。不同幣別之間的換算要用匯率，匯率存在 TCURR（OB08 維護），主要欄位有：KURST 匯率類型（M 為平均匯率）、FCURR／TCURR 來源與目標幣別、GDATU 生效日、UKURS 匯率。換算比率（例如 100 JPY = x TWD）存在 TCURF。GDATU 是反轉日期（99999999 減去日期），所以不要自己寫 SELECT 查匯率，一律用函數處理：

DATA lv_local TYPE wrbtr.
CALL FUNCTION 'CONVERT_TO_LOCAL_CURRENCY'
  EXPORTING  date             = ls_bkpf-budat
             foreign_amount   = ls_item-wrbtr        " 內部值即可，函數會自己處理小數位
             foreign_currency = ls_bkpf-waers        " 例：USD
             local_currency   = 'TWD'
             type_of_rate     = 'M'
  IMPORTING  local_amount     = lv_local
             exchange_rate    = DATA(lv_rate)
  EXCEPTIONS no_rate_found    = 1
             overflow         = 2
             no_factors_found = 3
             no_spread_found  = 4
             derived_2_times  = 5
             OTHERS           = 6.
IF sy-subrc <> 0.
  MESSAGE |{ ls_bkpf-budat DATE = USER } 找不到 { ls_bkpf-waers }→TWD 匯率（OB08）| TYPE 'I'.
ENDIF.
反方向換算用 CONVERT_TO_FOREIGN_CURRENCY。FI 憑證本身已經有本位幣金額（BSEG-DMBTR、ACDOCA-HSL），報表應該直接讀這些欄位，不要用今天的匯率重算，否則會和總帳對不起來。CDS 有 CURRENCY_CONVERSION 函數可以在資料庫層換算，屬於 CDS 章節的主題。例外名稱 derived_2_times 等請以 SE37 確認。

15. QM 關鍵程式片段：讀檢驗批與記錄結果

報表類客製（02、06、08、11）的核心是一段 QALS ＋ QAVE 的查詢。QAVE 的鍵值是 PRUEFLOS ＋ KZART ＋ ZAEHLER，同一個檢驗批可能有多筆 UD（改過 UD 就會多一筆），取「最新的 UD」一定要排序。這和 Casper 的 H／E 成本案例是同一個坑。

SELECT q~prueflos, q~werk, q~art, q~herkunft, q~matnr, q~charg,
       q~losmenge, q~mengeneinh, q~enstehdat,
       q~mblnr, q~mjahr, q~zeile,
       v~vcodegrp, v~vcode, v~vdatum, v~vname, v~zaehler
  FROM qals AS q
  LEFT OUTER JOIN qave AS v
    ON v~prueflos = q~prueflos
   AND v~kzart    = 'L'                       " 檢驗批層級的 UD
  WHERE q~werk      IN @s_werks
    AND q~art       IN @s_art                 " 檢驗類型用列舉（01、04、05…），不用區間
    AND q~enstehdat IN @s_date
  ORDER BY q~prueflos, v~zaehler DESCENDING
  INTO TABLE @DATA(lt_lot).

" 每個檢驗批只留最新一筆 UD（已按 zaehler 由大到小排序）
DELETE ADJACENT DUPLICATES FROM lt_lot COMPARING prueflos.

cl_salv_table=>factory( IMPORTING r_salv_table = DATA(lo_salv)
                        CHANGING  t_table      = lt_lot ).
lo_salv->get_functions( )->set_all( abap_true ).
lo_salv->display( ).

16. QM 客製的上線注意

  • ZQMB0001 寫外部資料庫表 ZEXT_QALS：沿用 6-5 章的「中繼表 ＋ 狀態回寫」架構，以 QALS 的建立日期或 UD 日期（QAVE-VDATUM）做差異抽取，不要每次全量重寫。寫到外部系統的數量與單位要一起帶；如果有金額，記得第 10 節的幣別因子。
  • Z_QM_CREATE_INSPECTION_LOT 類的「自動產生檢驗批」：如果掛在 MB_DOCUMENT_BADI 這類過帳 BAdI，裡面不可以 COMMIT，也不可以呼叫會 COMMIT 的 BAPI。應該改成 IN BACKGROUND TASK 或事件觸發背景作業。先確認 OMJJ／QMAT 的標準設定能不能做到，「依儲位決定是否檢驗」通常才是需要客製的部分。
  • ZQME0001／0002 自動處理庫存或 UD：標準 QA10 自動 UD 可以排背景作業，UD 使用者會是作業的執行帳號。如果業務要求顯示實際負責人，請在報表中對照，不要回寫 QAVE。
  • 上傳類（ZBQM001、005）：先用 Migration Cockpit 的模擬功能跑一次；自己寫的話，一樣要做第 7 節的權限檢查與「模擬執行」勾選框。
  • 檢驗類型、工廠選擇條件用列舉：檢驗類型 01、0101、04、05、08 的編碼不連續，用 BT 01～08 會把不該抓的類型也抓進來。
