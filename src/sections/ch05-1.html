2. Unit 1：ABAP 程式的執行流程

SAP NetWeaver AS ABAP 的三層式主從架構（Client/Server，軟體導向）：

層內容重點
展示層（Presentation Server，最上層）SAP GUI、瀏覽器使用者輸入資料、接收工作程序（Work Process）的處理結果。强晟特別指出：SAP GUI 本身沒有預先畫好的畫面，所有版面都是應用伺服器傳過來的，工作方式很像瀏覽器，所以 SAP 也把展示層稱為「伺服器」。
應用層（Application Server，中間層）分派器（Dispatcher）＋工作程序ABAP 程式（SAP 標準與客製）都在這裡執行：讀資料庫、處理、必要時寫回。
資料庫層（最底層）RDBMS（S/4HANA 只有 SAP HANA）除了應用資料，SAP 系統運作所需的程式與中繼資料（Repository）也存在資料庫。

軟體的技術分佈與硬體位置無關：縱向三層可以裝在同一台機器，也可各自獨立；橫向展示層與應用層可以分散到任意多台機器；資料庫能否橫向分散取決於 DBMS 本身。課程為了聚焦「一個使用者與一支 ABAP 程式的互動」，後續圖示會省略分派器與工作程序。

對一般使用者來說，應用層與資料庫是一個黑盒子；技術上有三種畫面：一般螢幕（Dynpro）、選擇畫面（Selection Screen）、清單（List），開發者要依需求提供合適的畫面。

一支含選擇畫面與清單的程式，執行時的 7 個步驟（原廠 Figure 5–14，强晟 p16–27）：

  1. 程式啟動：使用者從選單路徑或交易碼啟動程式。
  2. 載入程式上下文（Program Context）：執行時系統把變數／複雜物件的記憶體區、使用者對話的畫面資訊、ABAP 處理區塊，從 Repository（資料庫中的特殊區域）載入應用伺服器。强晟筆記的原話是「上下文在漢語裡還真沒有合適的詞，只可意會」。
  3. 送出選擇畫面：在使用者輸入完成前，由展示層掌控流程；選擇畫面可做必填、日期／數值格式等基本檢查。
  4. 輸入值寫入資料物件：使用者按「執行」後，輸入值自動放進程式對應的資料物件，控制權回到執行時系統；型別不符（例如 2 月 30 日）會自動觸發錯誤訊息。
  5. 呼叫重用單元（Col18 新增）：處理區塊呼叫封裝資料庫存取的重用單元（範例是全域類別的方法）；該單元所在的程式也會被載入。呼叫是同步的，呼叫端會等它完成。
  6. 向資料庫要資料、資料庫回傳：讀哪個表、哪一列的資訊傳給資料庫；只讀一筆時，目標通常是一個包含所需欄位的結構。
  7. 送出清單：處理區塊結束後，執行時系統把清單當作畫面送回展示層。

Col18 在這裡提出整門課的中心思想：一支程式不是單一區塊，而是由多個單元組成（模組化，Modularization）；好的程式應把資料庫存取封裝在重用單元裡，讓同一段資料存取可以服務不同的使用者對話。

3. Unit 2-1：ABAP Repository 與 Object Navigator

Repository 包含所有開發物件：程式、函數模組、資料庫表定義……既有 SAP 交貨的，也有客戶自建的。它存在資料庫中，而且與用戶端無關（cross-client）：任何用戶端看到的都是同一份。相對地，應用資料與 Customizing 資料通常與用戶端相關（client-specific），表格第一個鍵欄位是用戶端欄位（MANDT）。

Repository 依應用元件（例如 MM）劃分，應用元件下再分成多個套件（Package，舊稱開發類別 Development Class）；每個 Repository 物件建立時都必須指定套件。物件可以有子物件，也可以參照其他物件。

4. Unit 2-2／2-4：套件、傳輸請求、交易碼與專案收尾

開發專案的組織：開發在開發系統進行，專案完成後把物件傳到後續系統（測試／正式）。專案開始時，專案經理在 Transport Organizer（SE09／SE10，舊版 SE01）或直接在 Workbench 建立變更請求（Change Request），並把成員列進去；系統為每位成員在請求下建立一個任務（Task）。成員編輯或建立物件時，把它指派到請求，物件就記在該成員的任務中。

用變更請求組織專案的好處：成員能掌握自己的專案活動；專案成員都能處理指派給專案的物件，非成員則被鎖住直到請求釋放；請求釋放時所有物件自動傳輸，傳到哪裡由套件的傳輸層（Transport Layer）決定。套件是邏輯／功能上的分類，請求則是「專案、時間上」的分類：一支程式只屬於一個套件，但在不同時期可以屬於不同專案。

5. Unit 2-3：ABAP 語言特性、語法原則、編輯器與啟用

建立程式：SE80 選 Program 輸入名稱；或在套件右鍵；或 Edit Object → Program 頁籤 → F5。不要勾 Create with TOP Include（否則原始碼會被拆成多支 Include；7.40 以前預設是勾選的，要手動取消）。課程中程式類型選 Executable Program。强晟的經驗：報表用 SE38 最快（只產生一支程式和文字元素），對話程式用 SE80（可一起建 GUI Title、GUI Status、Screen、交易碼）。

ABAP 語言的六大特性：有型別（typed，支援型別轉換與 casting）、多語系（可翻譯的文字元素）、SQL 存取（內嵌 Open SQL，7.50 起改稱 ABAP SQL）、物件導向擴充（ABAP Objects）、平台無關（語意與 DB／OS 無關）、向上相容。專為對話式商業應用設計。

語法規則：

  • 程式由個別敘述組成；敘述的第一個字是 ABAP 關鍵字；每個敘述以句點結束；兩個字之間至少一個空白。
  • 敘述可以縮排、可跨多行、一行也能放多個敘述（不建議）。
  • 不分大小寫；慣例是關鍵字大寫、運算元小寫，用 Pretty Printer 自動轉換（Utilities → Settings → ABAP Editor → Pretty Printer 做個人設定）。
  • 第 1 欄是星號 * 的整行是註解（前面不能有空白）；雙引號 " 之後到行尾是註解。
  • 鏈式敘述：開頭相同的連續敘述，寫一次開頭加冒號，後面用逗號分隔、最後句點。只是簡寫，不會提高效能，執行時仍逐一處理每個敘述。

6. Unit 3-1：資料型別與資料物件

資料型別（Data Type）是形式上的變數描述；依型別具體定義出來、真正存放資料的變數或常數叫資料物件（Data Object）。型別有三種用途：定義資料物件（決定技術屬性）、定義介面參數（決定呼叫時實參的型別）、定義輸入／輸出欄位（除技術屬性外還帶欄位說明與 F4 值說明）。

7. Unit 3-2：基本敘述——賦值、運算、分支、迴圈、系統欄位、訊息

賦值：程式啟動時每個基本資料物件都先給型別對應的初始值（除非用 VALUE）。舊教材的 MOVE a TO b. 與 b = a. 等價，但 MOVE 已過時，一律寫 =。型別不同時若存在轉換規則就自動轉換。CLEAR 把物件還原成型別初始值。

運算子：+ - * / **（次方）、DIV（整除）、MOD（餘數）。括號與運算子都是關鍵字，前後至少一個空白：(1+2)*3 要寫成 ( 1 + 2 ) * 3。內建函數的左括號是函數名稱的一部分，例如 strlen( gv_cityfrom )；優先順序：括號 → 函數 → 次方 → 乘除 → 加減。

教材修正：① Col18 p85 印成 STRLEN (gd_cityfrom)——函數名與左括號之間不可有空白，而且括號內側要有空白，正確是 strlen( gv_cityfrom )。② 强晟 p78 寫「參考 COMPUTER 語句」應為 COMPUTE（而且 COMPUTE 本身也已過時）。③ 强晟 p78 說「ABAP 字串不能用 & 或 + 連接，很麻煩」——這是 7.0 的情況；7.02 起有字串範本 |…{ }…| 與連接運算子 &&，舊的 CONCATENATE 已很少需要。

條件分支：IF … ELSEIF … ELSE … ENDIF 可寫任意邏輯運算式；CASE … WHEN … WHEN OTHERS … ENDCASE 用於明確區分值（第一個 WHEN 必要，其餘可選）。兩者都由上往下比對，第一個成立的分支執行完就跳到 ENDIF／ENDCASE。同一欄位比對多個值時，CASE 比 IF 清楚且效能較好。否定用 NOT；否定 IS INITIAL 請寫 IS NOT INITIAL，SAP 不建議 IF NOT var IS INITIAL（語法對但難讀）。

四種迴圈：DO … ENDDO（無條件／次數控制，沒給次數又沒 EXIT 就是無窮迴圈）、WHILE … ENDWHILE（先判斷，可能一次都不執行）、SELECT 迴圈（讀資料庫）、LOOP AT（讀內表）。sy-index 只在 DO／WHILE 中有意義；巢狀迴圈中它永遠是「目前這一層」的圈數，內層結束後自動恢復外層的值。

9. Unit 4-1／4-2：模組化技術與副程式

模組化單元是封裝某個功能的程式片段。好處：程式更易讀（變成功能導向，整體任務拆成子功能）、同一功能可多次使用不必重寫、只需在單元內修改（中央維護）、除錯時可把呼叫當成一個單位執行後看結果，容易找到錯誤源頭。

範圍技術特性
程式內（Local）副程式（FORM routine）、區域類別的方法只在定義它的程式內可用；不需載入其他程式；不同程式可同名不衝突
全系統（Global）函數群組中的函數模組、全域類別的方法集中存在 Repository，呼叫時載入呼叫端的程式上下文，任意多支程式可同時使用

資料封裝：理想上被呼叫的單元不直接使用呼叫端的資料，呼叫端也不直接改單元內的資料——所有資料只透過參數進出。參數的總合稱為介面（Interface）或簽章（Signature），分 Importing（傳入）、Exporting（傳回）、Changing（傳入、修改後傳回）。原廠舉例：處理一組發票時，若相關的發票項目被填了不同的發票號碼，沒有封裝就很難追出是誰改壞的。

副程式的三種傳遞方式：

傳遞方式FORM 寫法（舊）行為現代方法對應
Call by valueUSING VALUE(f1)複製一份給形參，改了不影響實參；大內表複製很耗時IMPORTING VALUE(iv_x)

其他規則：實參依 USING／CHANGING 的順序對應形參，與名稱無關；形參用 TYPE ANY 或不指定型別時為泛型，執行時繼承實參型別，敘述與型別不合就是執行時錯誤——只在動態程式設計時使用；用 C／N／P／X 等不完整型別時長度在執行時由實參帶入；結構與內表的形參一定要指定型別才能存取元件。主程式定義的是全域物件，副程式內定義的是區域物件（呼叫時配置、結束釋放）；區域物件與全域物件同名時，副程式內看到的是區域的——這叫遮蔽規則（shadowing）。

在 S/4HANA 新程式中不要再寫 FORM／PERFORM。FORM 自 7.02 起被 SAP 標為過時（obsolete），原廠 Col18 也明說「副程式只有 changing 與非常特殊的 using 參數，嚴重限制資料傳遞的控制，程式內模組化請盡量用區域類別」，並提醒不要從別的程式呼叫副程式（違反封裝）。維護舊程式時仍要看得懂 FORM 與其除錯方式（F5 進入、F6 跳過、F7 跳出；可從導覽區把 FORM 拖到編輯器自動產生 PERFORM）。下面用區域類別重寫原廠「百分比計算＋區域輔助變數四捨五入」範例。

10. Unit 4-3／4-4：函數模組——搜尋、測試、呼叫、建立

函數模組（Function Module）是集中存放在 Function Library 的程序，有傳入／傳出參數介面，目的是重用。函數模組一定屬於某個函數群組（Function Group）——功能相關或處理同一類資料的函數模組集合。函數群組可含與執行檔程式相同的元件：全域資料（群組內所有函數模組可見可改）、副程式、螢幕。

記憶體行為（重要）：程式呼叫函數模組時，整個函數群組被載入，並留在記憶體直到呼叫端程式結束；再呼叫同群組的其他函數模組不必重新載入，而且共用同一份群組全域資料。所以一個函數模組寫進全域資料的值，同一次執行中呼叫同群組的其他函數模組時看得到——很多標準函數群組（例如 BAPI 的 buffer）就是靠這個特性運作，也是「同一支程式連續呼叫兩次結果不同」的常見原因。

介面元素：Import（可設 optional）、Export（呼叫端永遠可選擇不接）、Changing、Exceptions；參數一般以 Dictionary 型別定義；一樣分 pass by value／by reference。

搜尋函數模組：依應用（SE81 應用階層）、與應用無關（SE84 資訊系統）、依程式（在原始碼搜尋 CALL FUNCTION；或 /h 後對 CALL FUNCTION 下斷點；或 F1 → Technical Information 找到螢幕號碼再做 Where-Used List）。找到後先看屬性的 Released——只有已釋放的函數模組享有支援與向上相容保證。文件分「函數模組文件」與「參數文件」（Long Text 欄的綠燈表示已有文件）。測試環境（SE37 F8）可填參數試跑、進除錯、看執行時間與例外；可存測試資料目錄與測試序列，執行時間請重複量幾次。

呼叫語法：函數名稱大寫加單引號；站在呼叫端看，EXPORTING 傳給函數的 Import 參數、IMPORTING 接函數的 Export 參數；左邊是形參、右邊是實參。用 Pattern 按鈕或把函數從導覽區拖到編輯器產生呼叫，避免拼錯（選用參數會被註解起來）。傳統例外：在 EXCEPTIONS 區塊列出例外並給回傳碼，發生時寫入呼叫端 sy-subrc；OTHERS 接住所有未列出的例外；未被接住的例外會造成執行時錯誤。

建立：先建函數群組（SE80 套件右鍵 Create → Function Group，或 SE37 Goto → Function Groups），再建函數模組；客戶命名空間是 Z_／Y_ 開頭。定義好 Import／Export 參數後切到 Source code 頁籤實作；FUNCTION 關鍵字下方的註解區塊由 Function Builder 自動產生與維護，不要手改。

*"*"Local Interface:

11. Unit 4-5：BAPI（Business Application Programming Interface）

Business Object Repository（BOR）存放商業物件型別：它是一支「行為像類別」的程式，代表一張 SAP 表或一組表的階層，BAPI 就是它的方法——BAPI 是存取 SAP 系統資料的一種方式。BAPI 的功能封裝在可遠端呼叫的函數模組中，所以同系統的 ABAP 程式與外部程式都能呼叫。强晟的說法很到位：SAP 設計 BAPI，是為了讓開發者依需求加入資料時「不違反資料相關性原則、不必直接寫表」。

標準 BAPI 方法名作用
GetList傳回符合選擇條件的物件清單
GetDetail傳回某物件的詳細屬性（必須給完整鍵）
Create／Change／Delete／Cancel建立、修改、刪除、取消物件
AddItem／RemoveItem增刪子物件（例如訂單項目）

BAPI 函數模組的技術條件：命名 BAPI_<商業物件名>_<方法名>；Remote-enabled；不得有使用者對話與訊息；介面參數以專為該 BAPI 建立、字首為 BAPI 的 Dictionary 結構定型；Release 4.6 以前不允許 Changing 參數；不觸發例外，錯誤一律透過特殊 Export 參數 RETURN 回報。找 BAPI 用 BAPI Explorer（BAPI，Tools → Business Framework → BAPI Explorer），雙擊顯示的函數模組可跳到 Function Builder。

金額格式陷阱：BAPI 介面是依「外部呼叫」的需求設計的，金額預期是外部格式（4 或 9 位小數），即使該幣別沒有小數（例如 JPY、TWD 在 TCURX 設為 0 位）也要轉換後再傳。轉換用套件 SBF_BAPI 中函數群組 BACV 的函數模組。

12. Unit 4-6～4-8：全域類別、靜態方法與區域類別

全域類別以方法提供功能；方法和函數模組一樣有簽章（import、export、changing、exceptions）。類別的全域資料叫屬性（Attribute），所有方法都可存取——就像函數群組的全域資料。差異在於：

比較函數群組全域類別
對外可見性全域資料一律不對外；所有函數模組都可從外部呼叫屬性與方法都可分 public／private；private 方法像函數群組內的副程式
載入次數每個主程式只載入一次，所有呼叫共用同一份全域資料可多重實例化：每個實例（物件）有自己的屬性值
元件種類—實例屬性／方法（要先建實例）與靜態（類別）屬性／方法（每個程式上下文只有一份，不用建實例即可呼叫）

Class Builder（SE24）：Attributes 頁籤看屬性；Methods 頁籤看方法，對方法按 Parameter 看參數（方法的參數不分三張表，而在 Type 欄標示 Importing／Exporting／Changing／Returning）、按 Exceptions 看例外（有勾選框表示是 class-based 或 classic——同一個方法只能二選一，不能混用）；Class Documentation 與各元件文件；啟用後可直接測試（靜態方法直接 Execute Method，實例方法要先按 Instance）。

Class-based exception 自 Basis 6.10 引入：用例外類別（CX_ 開頭）取代任意命名的例外 ID；呼叫必須包在 TRY … ENDTRY，由 CATCH 例外類別 處理；函數模組也能用。用 Pattern 或拖放產生呼叫時，系統會一併產生 CATCH 骨架。

建立全域類別與靜態方法（Unit 4-7）：套件右鍵 Create → Class Library → Class（或導覽區選 Class/Interface 輸入新名稱）→ 在 Methods 頁籤輸入方法名，Level 選 Static Method、Visibility 選 Public → Parameter 定義參數 → Source Code 在 METHOD … ENDMETHOD 之間實作；編輯時可按 Signature 顯示方法簽章。區域類別（Unit 4-8）直接寫在程式原始碼中，分 CLASS … DEFINITION（PUBLIC SECTION／PRIVATE SECTION、屬性與方法簽章）與 CLASS … IMPLEMENTATION（方法本體）；靜態方法用 CLASS-METHODS、實例方法用 METHODS；輸入參數可加 OPTIONAL 或 DEFAULT。

13. Unit 5：結構與內表

結構（Structure）把邏輯上相關的值組成一個資料物件，可巢狀（元件本身是結構或內表）。型別可參照 Dictionary 結構、透明表，或程式內用 TYPES: BEGIN OF … END OF 定義的區域結構型別；不需重用時可直接 DATA: BEGIN OF … END OF。元件以連字號存取 結構-元件，所以資料物件名稱不要含連字號（語法允許，但會混淆）。MOVE-CORRESPONDING 只複製同名元件、其他不變；7.40 起用 CORRESPONDING #( )（可加 BASE、MAPPING、EXCEPT）。

內表（Internal Table）是執行時可存多筆同結構資料的資料物件，大小由執行時系統動態管理，開發者不用管記憶體。每筆叫表列（row／entry），每個元件叫欄位（column）。用途：暫存 DB 或檔案資料再處理、為畫面／列印整理資料（排序等）、為其他服務（方法、函數、副程式）準備資料。一個內表由三個屬性完整描述：列型別（Line type）、主鍵（Primary key，唯一或不唯一，鍵欄位順序有意義）、表種類（Table kind）。

14. Unit 6-1：資料模型與 ABAP Dictionary（航班資料模型）

商業應用要把真實世界的相關部分表示成資料：業務單位是實體，實體間的關係固定在資料模型中（原廠稱 SERM，Structured Entity Relationship Model；强晟稱 ERM）。開發者依模型在 ABAP Dictionary 定義透明表及其關係，啟用時資料庫中自動建立同名的實體表。

SAP 航班資料模型是所有 ABAP 訓練課程、線上文件、關鍵字文件的共同範例，物件在套件 SAPBC_DATAMODEL（可在 SE80 查看，內含表、視圖、結構、資料元素、網域、搜尋說明、資料模型、實體型別⋯⋯）。實體：城市、機場、航空公司、航線、航班；關係：每條航線有一家航空公司、一個出發機場、一個目的機場；每個可訂位的航班屬於一條既有航線；城市與鄰近機場可以對應。旅客想知道「最直接的航線、出發當天的時間、最便宜／最快／時間最合適的選擇」，旅行社則依技術標準存放遠超過客戶需要的資料——開發者的任務就是寫程式把後者組成前者。

表內容主鍵
SCARR航空公司（名稱、幣別、URL）MANDT、CARRID
SPFLI航線／飛行時刻表（出發、目的城市與機場、時間）MANDT、CARRID、CONNID
SFLIGHT航班（日期、票價、座位數、已訂座位）MANDT、CARRID、CONNID、FLDATE

Dictionary 的描述性元素：資料元素描述欄位的語意（欄位標籤、F1 文件），技術屬性（資料型別、長度）通常放在它參照的網域（Domain），以提高重用與一致性。透明表是資料庫表的平台無關描述（不是表本身），欄位成為資料庫中同名的欄；除欄位清單外還包含主鍵、技術設定（預期大小、存取頻率）、加速存取的設定（次級索引、緩衝）。主鍵值在表內必須唯一；原廠建議用有意義的一個或多個欄位當主鍵，不要用自動遞增流水號。結構的定義幾乎與表相同，差別是不需要主鍵、元件可以再是結構（巢狀）甚至表格型別（deep structure）；透明表則只是一串基本欄位。

原廠 Col18 特別提醒：舊程式常把透明表隨意當資料型別用（DATA wa TYPE spfli），現在的建議是透明表只在存取資料庫時使用，尤其不要用來定義使用者介面，否則資料庫物件與 UI 之間會產生不必要的相依。當透明表用作型別時，只有欄位清單有意義，主鍵與技術設定都無關。字典的完整內容見 1-2 章 與 5-16 章 BC430。

在程式中用字典元素定義資料物件（强晟 p63–65）：DATA gv_carrid TYPE s_carr_id.（資料元素，CHAR 3）、DATA gv_connid TYPE sbc400focc-connid.（結構欄位；SBC400FOCC 是訓練系統專用結構，一般系統查不到）、DATA gs_spfli TYPE spfli.（表的一列）、PARAMETERS pa_car TYPE spfli-carrid.——用資料元素、結構欄位或表欄位定義選擇畫面欄位，就自動得到語意屬性：F1 帶出資料元素文件、F4 帶出搜尋說明。

15. Unit 6-2～6-4：讀取資料庫——單筆、多筆、用戶端、索引、緩衝、JOIN

Native SQL vs Open SQL：每種 RDBMS 都有自己的 Native SQL，寫在 ABAP 裡就不能在所有 SAP 系統通用；Open SQL（7.50 起稱 ABAP SQL）是 SAP 定義、與資料庫無關的標準，由資料庫介面在執行時轉成目標資料庫的 Native SQL，並先經過表緩衝。

找資料表的方法：依應用（應用階層中的套件）；依程式（在原始碼搜尋 SELECT、/h 後對 SELECT 下斷點、在畫面欄位 F1 → Technical Information 看所屬表／結構，再從資料元素做 Where-Used List in Table Fields）；或用 SE84 自由搜尋。强晟另提到「根據螢幕欄位找資料表的 18 種方法」一文。寫 SELECT 前先找重用元件：邏輯資料庫（SE36）、函數模組（SE37）、BAPI（BAPI）、全域類別方法（SE24）；都沒有才自己寫，而且寫完要封裝成函數模組或方法。

SELECT 四個子句：SELECT（讀哪些欄位）、FROM（表或視圖）、INTO（放到哪個目標資料物件）、WHERE（條件）。

  • SELECT SINGLE：讀一筆；要確保唯一，WHERE 要給全部主鍵（用戶端欄位除外，系統自動帶目前用戶端）。成功時 sy-subrc = 0。
  • 欄位清單與目標：目標結構要與欄位清單「靠左對齊」（名稱不管、型別要相容）；或用 INTO (f1, …, fn)；或 INTO CORRESPONDING FIELDS OF（依名稱對應，擴欄位時不用改程式，但同名欄位型別不同會做複雜轉換甚至截斷）。7.40 起最佳做法是明列欄位＋@DATA( ) 內嵌宣告，目標自動與欄位清單一致。
  • SELECT 迴圈（SELECT … ENDSELECT）：資料庫以封包傳到資料庫介面，再逐筆複製到工作區；結束後 sy-subrc = 0 表示至少一筆、sy-dbcnt 為筆數。本書禁用，改用 array fetch。
  • Array fetch（INTO TABLE）：整塊傳輸，效能高；不是迴圈，所以沒有也不能有 ENDSELECT；會覆蓋內表原內容，要附加用 APPENDING TABLE；sy-subrc／sy-dbcnt 行為相同。

用戶端相關表：第一個鍵欄位是 CLNT 型別（MANDT）。不指定用戶端時只讀目前用戶端（系統自動加進 WHERE）。跨用戶端讀取在 7.0 用 CLIENT SPECIFIED（放在 FROM 後，並在 WHERE 指定 MANDT），7.51 起改用 USING CLIENT——CLIENT SPECIFIED 已過時。實務上很少需要。

效能：依完整主鍵或前幾個鍵欄位存取最快；用非鍵欄位查詢最壞要循序掃描整張表。常用某組條件查詢時可建次級索引（SE11 表顯示模式 → Indexes 按鈕，啟用時在資料庫建立）；條件欄位要「靠左、無間隙」地符合索引欄位才會用上；是否使用由資料庫的最佳化器（Optimizer）決定，Open SQL 裡不需也不能指定索引；用戶端相關表的索引應把 MANDT 放第一個。SAP 表緩衝：資料放在每台應用伺服器上，讀取可快 10～100 倍；設定在 SE11 的 Technical Settings；適合「常讀、很少改」的表；多台應用伺服器之間的同步有時間差，短時間內可能讀到舊資料，所以要不要緩衝需由資深開發者與系統管理員共同決定。某些 SELECT 變體（例如 BYPASSING BUFFER、彙總、JOIN 在 7.0）會繞過緩衝，對已緩衝的表應避免。

讀多張表：效能最好的通常是 JOIN；定義時要決定：JOIN 哪些表、JOIN 條件、要哪些欄位。兩種做法：在 Dictionary 建資料庫視圖，或在 SELECT 中直接寫 ABAP JOIN（執行時由資料庫介面動態產生查詢）。JOIN 與視圖都不重複存資料，選取時從底層表讀；可以 JOIN 三張以上。寫入：Open SQL 還有 UPDATE、INSERT、DELETE、MODIFY，但 SAP 資料關聯性很強，直接改表極易造成不一致，必須先懂 SAP LUW 與鎖（5-11 章 BC414）。

16. Unit 6-5：權限概念與 AUTHORITY-CHECK

關鍵資料與功能必須防止未授權存取，因此要在程式中實作權限檢查。權限物件（Authorization Object）定義在物件類別（Object Class）之下，開發者定義物件時只指定欄位（不給值）；權限（Authorization）是給這些欄位填上值；權限透過權限參數檔（Profile）（今日由角色 PFCG 產生）進入使用者主記錄。一個權限物件可以建多個權限給不同使用者。以航班模型的 S_CARRID 為例：欄位 CARRID、ACTVT；權限 DISPLAY_ALL＝CARRID *、ACTVT 03；權限 CHANGE_LH＝CARRID LH、ACTVT 02。

分工：定義權限物件（通常是資料建模的一部分）與在程式中檢查是開發者的責任；定義權限、參數檔與使用者主記錄是管理員的工作。權限物件通常由 ACTVT（活動）加一個代表受保護資料的欄位組成（物料、航空公司⋯⋯）。SU20 建權限欄位、SU21 建物件類別與權限物件（含 ACTVT 時要維護可用值）；表 TACT 存 ACTVT 所有可能值、TACTZ 存各權限物件允許的活動值。

AUTHORITY-CHECK：執行時檢查目前使用者主記錄中是否有該權限；結果在 sy-subrc（0＝通過，非 0＝不足，給錯誤或警告訊息）。不需要列出物件的所有欄位——沒寫的欄位不檢查，也可以寫 DUMMY（不加引號的預定義字）明確表示忽略。用 Pattern 產生敘述避免拼錯物件名與欄位名。原廠提醒：用權限控制整支程式或交易碼只是補充，不能取代開發者在程式中的明確檢查。

17. Unit 7：傳統報表——清單、選擇畫面與事件

清單（List）用最少的程式碼輸出資料：支援多語系（文字與標題以登入語言顯示）、金額依幣別顯示；可輸出到螢幕（顏色、圖示）、印表機、網際網路（自動轉 HTML）、存檔（SAP 內或外部，例如試算表）。標準清單介面提供常用功能，可用 Menu Painter 調整。每個清單有一行清單標題與最多 4 行欄標題，沒定義標題就用程式標題。維護方式：初次維護要先啟用、執行出清單，再從 System → List → List Header 直接在清單上方編輯；後續修改不必再執行，從編輯器 Goto → Text Elements → List Headers；翻譯用 Goto → Translation（强晟提到 ECC 5.0 起建立並啟用程式後就能直接維護）。清單標題、欄標題、文字符號與選擇文字（Selection Texts）合稱程式的文字元素。

選擇畫面讓使用者輸入選擇條件，只讀真正需要的資料，減少記憶體與網路負擔。技術上它也是 Dynpro，但不用 Screen Painter 畫，而是由原始碼中的宣告式敘述自動產生。標準功能：多語系文字、自動型別檢查（型別不符的輸入 SAP GUI 不接受）、複雜選擇（區間、比較條件、樣式）、F1 欄位文件、F4 搜尋說明、存成變式（Variant）。

  • PARAMETERS（單值）：同時建立程式變數與畫面欄位；名稱最多 8 個字元；不能用 F、STRING、XSTRING 型別；預設值用 DEFAULT 而不是 VALUE。
  • SELECT-OPTIONS 名稱 FOR 資料物件（複雜選擇）：建立同名內表（含表頭），四欄 SIGN（I 包含／E 排除）、OPTION（EQ、NE、GT、GE、LT、LE、BT、NB、CP、NP）、LOW、HIGH。例：輸入 LH → I EQ LH；區間 AA～DL → I BT AA DL；排除 BA → E EQ BA。組合語意是 ( I1 OR … OR In ) AND ( NOT E1 ) AND … AND ( NOT Em )；內表是空的時條件恆成立（不過濾）。也可用在一般邏輯運算式 IF gs_spfli-carrid IN so_car。
  • 欄位以資料元素定型時：選擇文字可直接取 Dictionary 的長標籤（Dictionary reference）、F1 顯示資料元素文件、F4 用連結的搜尋說明；結構欄位自己定義的搜尋說明會覆蓋資料元素的。
  • 變式：背景執行帶選擇畫面的程式一定要有變式（背景沒有人輸入）。名稱以 CUS&（客戶）或 SAP&（SAP）開頭的是系統變式，與用戶端無關、自動連結傳輸系統；其他變式與用戶端相關，要在編輯器 Goto → Variants → Utilities → Transport Request 手動掛到請求上傳輸。

ABAP 事件：程式啟動時先在記憶體建立所有全域資料物件，然後執行時系統依序觸發事件，有對應處理區塊就執行。

LOAD-OF-PROGRAM程式載入時。4.6 起與 INITIALIZATION 並存，主要給函數群組、module pool 用；執行檔程式不要用

18. Unit 8：Dynpro 螢幕與 GUI 介面

螢幕（Screen／Dynpro）不只是版面上的輸入輸出欄位、按鈕等元素，還包括處理邏輯（顯示前後執行的程式片段）。與 Dictionary 整合帶來自動的一致性檢查：型別檢查、外鍵檢查、固定值檢查；也可在程式中自訂檢查，控制順序並在出錯時讓欄位重新可輸入。格式依使用者主記錄設定（日期、小數點、千分位），金額依幣別欄、數量依單位欄格式化。

啟動螢幕序列：在處理區塊中 CALL SCREEN nnnn，或建立參照程式與第一個螢幕的對話交易（dialog transaction）。哪些程式類型可以有螢幕：執行檔程式（可以，但為重用與封裝 SAP 建議用函數群組的螢幕）、函數群組（可用對話交易或在函數模組中 CALL SCREEN；SAP 建議）、Module pool（只能用對話交易，無法封裝、沒有明確的外部介面，SAP 建議改用函數群組）。

螢幕四元件：屬性（4 位數螢幕號、短文、螢幕類型如 Normal、預設下一螢幕）、版面（Screen Painter 圖形編輯器，可「Get from Dictionary」或「Get from program」建立欄位、維護元素屬性、顯示元素清單）、元素清單（每個元素的位置、大小、資料型別⋯⋯）、流程邏輯（PBO 與 PAI，只能引用 MODULE，不能直接寫 ABAP 敘述）。

  • Get from Dictionary：帶入 Dictionary 欄位的全部屬性（語意、外鍵相依），欄位名就是 Dictionary 欄位名。Get from program：帶入程式內資料物件的屬性，程式必須先啟用（要有產生版本）。必填欄位勾 Required。
  • 按鈕與功能碼：按鈕在屬性中指定名稱與功能碼（Function Code）；使用者按下時，執行時系統把功能碼放進 OK 類型的命令欄位（預設就在元素清單中，通常命名為 OK_CODE）；程式中若有同名資料物件（DATA ok_code TYPE sy-ucomm），值會自動傳入，然後觸發 PAI。
  • 執行時的 5 步驟：① PBO 模組依序執行 → ② 同名欄位從程式傳到螢幕 → ③ 螢幕送到 SAP GUI 顯示 → ④ 使用者動作後，螢幕欄位傳回程式同名欄位 → ⑤ PAI 模組依序執行。模組是沒有介面的處理區塊（MODULE … ENDMODULE）；MODULE … OUTPUT 只能被 PBO 呼叫、MODULE … INPUT 只能被 PAI 呼叫；模組中定義的變數永遠是全域的；一個模組可被多個螢幕呼叫。PAI 主模組慣例命名 USER_COMMAND_nnnn。
  • 下一螢幕：屬性填 0＝處理完回到 CALL SCREEN 的呼叫點（或結束對話交易；0 是初始值，在屬性畫面上會顯示成空白）；填自己的號碼＝關閉後再處理一次；PAI 中用 SET SCREEN nnnn 動態覆蓋。SAP 標準做法：Enter 停在同一螢幕、只有特定按鈕才跳走——Enter 預設不放功能碼，程式收到的是空白。

TABLES 結構作為螢幕介面：教材用 TABLES 宣告一個與 Dictionary 結構同名同型的結構變數（例如 SDYN_CONN 取自 SCARR、SPFLI、SFLIGHT；SDYN_BOOK 取自 SBOOK、SCUSTOM；Col18 用 BC400_S_DYNCONN），螢幕欄位參照同一結構，PBO 後由程式傳到螢幕、PAI 前由螢幕傳回程式。原廠範例在 PAI 模組中把 TABLES 結構複製到函數模組介面用的結構（gs_connection，型別 BC400_S_CONNECTION）再呼叫函數模組讀資料，刻意把「螢幕介面」與「函數介面」分開；在 PAI 發 E 訊息時螢幕會不經 PBO 直接重新顯示。

本書不用 TABLES。自動傳輸的真正條件是「程式中有與螢幕欄位同名的全域資料物件」，不一定要 TABLES：螢幕欄位用 Get from program 參照一個全域結構（例如 gs_dynconn-carrid）即可，效果相同又不會引入隱式的表工作區。重新處理同一螢幕時所有 PBO 模組會再跑一次，若在 PBO 填螢幕結構，要確保不會蓋掉使用者剛輸入的值。

19. Unit 9：SAP List Viewer（ALV Grid Control）

SAP 從 4.6 起提供大量 EnjoySAP Controls：Grid Control（在螢幕上顯示內表，含排序、篩選、合計）、Picture Control、HTML Viewer Control、Tree Control。程式透過標準類別的方法與 Control 溝通（Controls 詳見 5-10 章 BC412）。ALV Grid（SAP List Viewer／ABAP List Viewer）提供：使用者可調整欄寬（或依內容自動）、拖拉調整欄位順序、詳細資訊（Detail，以對話窗顯示游標所在列）、複雜排序、搜尋字串、對一或多個數值欄合計並依非數值欄做小計（控制層級清單）、列印與下載、存成顯示變式（Layout）重複使用。

MVC 架構：Model（商業互動層，與顯示無關的資料存取，可以是封裝資料存取的應用類別，也可沿用 BAPI、函數模組、Web Service）、View（使用者互動層，只管版面）、Controller（綁定層，格式化資料、處理輸入、控制流程）。View 由 UI 元素組成，執行時一次只顯示一個（相當於沒有流程邏輯的傳統螢幕），可用容器技術嵌入其他 View；每個 View 有自己的 View Controller（技術上是 ABAP 類別，大部分程式碼自動產生），其 Context 是資料容器。Window 綁定多個 View 並定義導覽；Component 含一或多個 Window 與自己的 Component Controller／Context；Application 指向某個 Window 的預設 View（啟動 View），是整個 View 序列的入口。

Code Inspector從程式碼角度檢查效能、安全與典型語意錯誤：效能（資料庫存取有沒有用到索引？SELECT 是否寫在迴圈裡？）、安全（是否讀其他用戶端的資料？SELECT 的表名或 WHERE 是否動態指定？）、典型語意錯誤（AUTHORITY-CHECK 之後有沒有檢查 sy-subrc？CLIENT SPECIFIED 後真的有指定用戶端嗎？是否連續使用 E 類訊息？）。

23. Unit 13：調整 SAP 標準軟體（概覽）

基本術語：

  • Original／Copy：物件在開發它的系統是原件，傳輸到其他系統的只是副本；原件系統（出生地）記錄在物件屬性中。原件永遠不會被傳輸覆蓋；只改副本會造成系統不一致（之後改原件傳過來又蓋掉），強烈建議只改原件。
  • Correction：修改原件，在開發／修正類型的任務中進行。
  • Repair：修改副本，在修補類型的任務中進行；例如正式機緊急修正後，必須到原件系統做相同修改。
  • Modification：在客戶系統修補 SAP 的 Repository 物件。
  • 升級時的修改調整：升級會用 SAP 新版覆蓋被修改的 SAP 物件，必須比對新舊版並把修改搬回來（SPDD 字典物件、SPAU 其他物件），費時又易錯；SAP 建議在開發系統做調整再傳輸。
調整方式說明
Customizing用維護交易設定系統屬性與功能（SPRO），是 SAP 設計好的調整方式，也是導入必經步驟
Enhancement不修改 SAP 物件就調整功能；與版本無關、升級免調整；但不是所有需求都有對應增強點
Customer Development在客戶命名空間自建 Repository 物件，標準沒有類似功能時使用
Modification沒有合適增強點、需求又必要時才做；維護負擔大。SAP R/3 4.6B 起有 Modification Assistant 協助組織修改與後續調整

增強類型：Program Exit（SAP 在程式中預留、客戶可掛自己程式碼的位置，執行時一起跑；非常重要的一類）有四種技術：User Exit、Customer Exit、Business Transaction Events（BTE）、Business Add-Ins（BAdI），每種都有專屬的搜尋方法（見 BC425）。其他：Menu Exit（SAP 選單中預留的項目）、Screen Exit（SAP 螢幕中的子螢幕區，可放自訂螢幕）、Field Exit（强晟版列出；在 SAP 螢幕欄位上做自訂輸入檢查，已過時）；Dictionary 中可覆寫資料元素的 F1 文件與欄位標籤；Append Structure 可加到大多數透明表、Dictionary 結構型別，Col18 新增也可加到 Database View（能從既有基表多選欄位，但不能加新的基表）；SAP 程式中註解掉的原始碼區段，SAP 建議時可取消註解啟用額外功能——技術上屬於修改。

SSCR（SAP Software Change Registration）：開發者第一次建立或修改 Repository 物件時，系統要求開發者金鑰（Developer Key），需一次性註冊，綁定使用者 ID 與系統授權號碼（Installation Number）；每個要修改的 SAP 物件另需物件金鑰（Object Key），註冊時提供物件名稱、物件類型、系統授權號碼與版本。

Casper 實務經驗③：先找標準，再想客製。順序是：標準設定（Customizing）→ BAdI／Enhancement Spot → Enhancement Point（隱式／顯式增強）→ 修改標準，每往右一步，升級成本高一個量級。S/4HANA 現況：Field Exit 早已停用；User Exit（例如 MV45AFZZ）與 Customer Exit（SMOD／CMOD）在 on-premise 仍可用但屬舊技術；新開發優先用 New BAdI（Enhancement Framework），在 S/4HANA Cloud／ABAP Cloud 只能用已釋放（released）的 BAdI 與 Key User Extensibility（自訂欄位與邏輯）。SSCR 金鑰在 on-premise 仍需要（透過 SAP for Me 申請），ABAP Cloud 則根本不允許修改。詳細內容見 3-3 章、3-4 章、5-14 章 BC425、5-15 章 BC427。

25.4 Col63 的過時說法與教材修正

  • RETURNING 參數的限制（p191）：Col63 寫「用 RETURNING 定義函數方法時，就不能再定義 EXPORTING 和 CHANGING 參數」。這是 7.0 的限制；依 ABAP Keyword Documentation 的版本說明，7.0 EhP2（7.02）起函數方法也可以有 EXPORTING／CHANGING 參數，S/4HANA 可以放心使用（見下例）。不過一般還是建議函數方法只回傳一個值，讓呼叫端可以寫在運算式裡。
  • 練習 20 用 module pool（p335）：課文（p313）才說過「函數群組是建立螢幕的建議程式類型，module pool 無法封裝，應盡量避免」，練習卻要學員建 TOP Include 的 module pool SAPMZBC400_##_A（類型 M）。教材前後說法不一；新程式請照課文建議放在函數群組，或直接改用 Fiori。
  • 除錯器版本（p84）：「SAP Web AS 6.40 及更低版本只有傳統除錯器」，與 Col18 說法相同，也印證第 8 節「以原廠說法為準」的結論。
  • 開發類（p35）：「SAP R/3 4.6 仍把套件稱為開發類（Development Class）」，4.6A/B 只能用其中一種方式建立。老系統的文件與 TADIR 欄位 DEVCLASS 還看得到這個舊名稱。
  • BAPI 結構前綴（p146）：Col63 寫介面結構前綴是 BAPI_，Col16／Col18 寫 BAPI。實際系統中兩種都有（BAPIRET2、BAPISFLDAT；BAPI_…），重點是「為 BAPI 專門建立的字典結構」，不要糾結底線。
  • 解答程式碼的德文殘留（p275）：函數模組註解區寫的是 *"*"Lokale Schnittstelle:——Function Builder 依登入語言產生這段註解，原廠系統是用德文登入產生的，不是錯誤。

SAP 官方簡中譯名的陷阱（查簡中資料時要特別小心）：
  • 「客户端」一詞兩義：同時指 client/server 架構的「用戶端」與 MANDT 的「用戶端（集團）」。台灣講 MANDT 多說「用戶端」或「集團」，不會跟前端混淆。
  • 「活动」三種意思：ACTVT 權限欄位（活动）、已啟用版本（活动版本）、Web Dynpro 的 Action（活动代码、活动处理器）。看到「活动」要先判斷是哪一個。
  • 「转机」其實是航線：Col63 把 flight connection（SPFLI 的一條航線）一律譯成「转机」（例：「单项转机的数据」p271），中文字面是「轉機航班」，是誤譯；本書一律稱「航線」。
  • 同一工具多種譯名：Screen Painter 有屏幕绘图器／屏幕制作器，Function Builder 有函数构建器／函数编制器，Class Builder 有类构建器／类制作器；exit 有時譯「出口」（程序出口）、有時譯「退出」（菜单退出、屏幕退出）；interface 在 BAPI 名稱裡譯「界面」，其他地方譯「接口」。
  • BAdI 譯成「附加商务」（p460）：看不出是什麼東西，實務上沒人這樣講，直接講 BAdI。「虚伪注释」（pseudo comment）也一樣，講 pseudo comment 或 "#EC 即可。
  • 「修正」被借用：建立函數群組、類別時的對話框寫「將…分配給包和修正」（p140、p174），這裡的「修正」其實是指變更請求（correction request），不是 25.5 表中「修改原件」的那個 Correction。
  • 課名錯字：第二單元第 2 課標題「工发程序与组织开发」（p33）應為「开发程序与组织开发」（Developing Programs and Organizing Developments）。

練習與自我檢核

前 12 題取自原廠 Col18 各單元 Learning Assessment（改寫成問答），後面為本章補充題。

  1. （Unit 1）哪一層包含使用者介面，讓使用者存取程式、輸入資料並接收工作程序的結果？一支程式由多個單元而非單一區塊組成，這個概念叫什麼？
    答：展示層（Presentation Server layer）；模組化（Modularity／Modularization）。
  2. （Unit 2）下列何者屬於 Repository：程式、函數模組、Object Navigator、資料庫表定義？
    答：程式、函數模組、資料庫表定義。Object Navigator 是工具，不是 Repository 物件。
  3. （Unit 2）套件類型有哪三種？傳輸在什麼時候觸發？
    答：Development package、Main package、Structure package（Application／Software Component 是屬性不是類型）。在請求（request）被釋放時觸發，不是存檔、啟用或釋放任務時。
  4. （Unit 2）「存檔時 Repository 會存兩個非啟用版本」對嗎？
    答：錯。只存一個非啟用版；物件可同時有一個啟用版與一個非啟用版，啟用後非啟用版成為新的啟用版。
  5. （Unit 2）怎麼寫整行註解？專案成員完成任務後應該做什麼？
    答：第 1 欄寫星號 *；在變更請求中釋放自己的任務。
  6. （Unit 3）T、C、N、INT8、D 哪些是完整型別？IF 中否定邏輯條件用哪個運算子？
    答：T、INT8、D（完整型別共有 D、T、I、INT8、F、STRING、XSTRING、DECFLOAT16、DECFLOAT34）；NOT，否定 IS INITIAL 寫 IS NOT INITIAL。
  7. （Unit 4）模組化的用途有哪些？呼叫時實參指定給形參的過程叫什麼？

    答：非完整主鍵的 SELECT SINGLE 會回傳「任一筆」，HANA 沒有預設排序，每次可能不同（Casper 經驗①的 H／E 案例）。改成 ORDER BY 明確排序加 UP TO 1 ROWS，並把業務規則（例如固定取 H）寫進 WHERE。
  15. （補充）選擇畫面上使用者輸入物料區間 1000～1999，結果漏了 ALPHA 轉換後的號碼、也多抓了 '1000A'。為什麼？
    答：BT 比較的是字典序；CHAR 欄位中 '1000A' 落在區間內，而前導零與編碼規則改變會讓看似連續的號碼不連續。改用列舉（多筆 I EQ）或以業務屬性（物料類型、物料群組）當條件（Casper 經驗②）。

  17. （補充）Dynpro 程式中，使用者存檔後回到清單、再進入螢幕按 Enter，資料又被存了一次。原因與兩種解法？
