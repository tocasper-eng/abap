1. 資料字典是什麼：六種基本物件

ABAP 資料字典是定義與管理「資料元素」與「資料庫元素」的中心工具。系統所有的全域資料型別、資料表結構都要在字典裡建立與維護；字典保證了資料的完整性、一致性與安全性。老師特別交代：這張表要會默寫，才會記得 DD 的威力有多強大。

物件說明要點
Table 資料表資料庫中真正存放資料的地方；字典裡定義的是「表的結構」，由列（記錄）與欄（欄位）組成表的欄位一律透過 Data Element 定義
View 視圖一張或多張資料表的邏輯呈現，本身不存資料共四種：Database／Projection／Maintenance／Help
Data Type 資料類型值的集合＋定義在該值集上的一組操作三種：Data Element／Structure／Table Type
Domain 域指定欄位的技術屬性（型別、長度、小數位）與允許的值不能直接拿 Domain 定義表的欄位，一定要透過 Data Element
Search Help 搜尋說明F4 說明，提升使用者友善度可掛在 Table／Structure／Data Element／Screen／Parameters
Lock Object 鎖物件對資料存取做並行控制；鎖資訊放在記憶體的 Lock Table名稱一律以 E 開頭，建立後自動產生 ENQUEUE_／DEQUEUE_ 兩支函數
口訣：Domain 管「長什麼樣、能填什麼」，Data Element 管「叫什麼名字、F4 給什麼、說明文件怎麼寫」，Table 只是把一堆 Data Element 排起來。這是 SAP 與其他系統最大的差別——別的系統直接在欄位上寫 CHAR(10)，SAP 是 Table → Data Element → Domain 三層。

四種 View 的差異，是本章最常被考的觀念：

View 類型資料來源連接條件能否維護資料
Database View一張或多張表自己定義；一律是 INNER JOIN單表視圖可維護（改視圖＝改表）；多表視圖只能顯示
Projection View只能一張表無用來「遮罩欄位」保護資料，可維護
Maintenance View多張表不能自訂，必須來自既有外來鍵可維護；需用「表格維護產生器」產生對話框；所有主鍵都要放進視圖欄位
Help View多張表必須存在外來鍵（LEFT OUTER JOIN 語意）不可維護；專供 Search Help 的 Selection Method 使用
S/4HANA 提醒：新開發不要再建 Database View。DDIC 的 Database View 只是把 SQL 固化在字典裡，沒有註解（annotation）、不能做參數、不能被 Fiori／OData 直接消費。請改用 ABAP CDS View（見本章第 11 節）。Maintenance View ＋ SE54 這條路則仍然有效，客製設定表（Z 開頭的 Customizing 表）到今天還是這樣做。

2. 用 SE11 建第一張 Z 資料表（含 Delivery Class 與 Maintenance）

講義的目標很明確：本節做完，要能用 SE16N 維護自己的資料。而且提醒「實作之前，請先學會建立 function group」，因為後面 SE54 產生維護畫面時一定會用到。

SE11 建表的標準步驟：（依講義步驟整理）

  1. SE11 → 選 Database table → 輸入 ZERP300_KNA1 → Create。
  2. Delivery and Maintenance 頁籤：
    • Delivery Class 選 A（Application table，主資料與交易資料）。老師強調：這個畫面一定要選 A，其他的不要選；C 雖然是客製，但那是 SPRO 的客製。
    • Data Browser/Table View Maint. 選 Display/Maintenance Allowed，否則 SE16N / SM30 進不去、也產不出維護畫面。
  3. Fields 頁籤：第一個欄位一律是 MANDT（Data Element MANDT，Domain MANDT，CLNT 3），並勾 Key，代表這是 client-dependent 的表。
  4. 逐欄輸入欄位名與 Data Element，勾選主鍵（Key）與 Initial Values。
  5. 幣別／數量欄位要設參考欄位：CURR 型別要指定 Reference table + Reference field（幣別欄位 CUKY），QUAN 型別要指定單位欄位（UNIT）。這是講義中「處理數量 QUAN 與金額 CURR 欄位」的重點。
  6. Extras → Enhancement Category 設為「Can Be Enhanced (Deep)」，否則激活時會一直跳警告。
  7. 按 Technical Settings（技術設定）填 Data Class / Size Category（見第 3 節）。
  8. 存檔 → 指定 Package 與 Request → Activate。老師提醒：要 ACTIVE 才可被 SE16N 使用。

4. Domain 與 Data Element：把「合法值」寫進字典

SE11 建 Domain 與 Data Element 是為了「一次定義、到處引用」。老師的話：建立資料表時，引用自定 Data Type 並綁定 Domain，可做好資料一致性的管理，這在大型系統上非常重要。

Domain（SE11 → Domain）重點頁籤：

  • Definition：Data Type（CHAR／NUMC／DEC／CURR／QUAN／DATS／TIMS／UNIT／CUKY…）、No. Characters、Decimal Places。
  • Sign：數值型 Domain 才有；不打勾＝只能輸入正數（講義特別提到這一點）。
  • Output Characteristics：Output Length、Conversion Routine（轉換常式）。例如 SPRAS 用 ISOLA 把內部 1 碼語言碼轉成 ISO 2 碼；物料號碼用 MATN1 做前置補零。轉換常式其實是一對 CONVERSION_EXIT_xxxxx_INPUT / _OUTPUT 函數。
  • Value Range：可填 Single Values（固定值）、Intervals（區間），或指定 Value Table（值表）。
Value Table 只是「候選」，它不會自動檢核。真正產生檢核的是欄位上的外來鍵；不過在 Data Element 引用有 Value Table 的 Domain 時，SE11 會主動建議你用該值表當 Check Table，按下去就自動產生外來鍵——這是老師說的「Domain 與 Data Element 能幫助業務顧問找問題」的實際機制。

Data Element（SE11 → Data type → Data element）重點：

  • Elementary Type：綁 Domain（建議）或直接給 Predefined Type。
  • Field Label：Short／Medium／Long／Heading——這是畫面與 ALV 抬頭的文字來源，一定要填，否則報表抬頭是空白。
  • Further Characteristics：Search Help（掛 F4）、Parameter ID（SET/GET PARAMETER 記憶值）、Default Component Name。
  • Documentation：使用者在畫面上按 F1 看到的說明。

講義練習 03-3：建立一個幣別欄位的 Data Element，並限定只能填 TCURC 內的內容。作法是 Domain 型別 CUKY 長度 5、Value Table 指定 TCURC，Data Element 引用它，再在表欄位上建立外來鍵到 TCURC。

固定值（Fixed Values）是放在 DD07L／DD07T，可以直接讀出來當下拉清單：

" 讀取某個 Domain 的固定值清單（DD07L 值、DD07T 文字），用來自製下拉或做檢核
DATA(lv_domname) = CONV domname( 'ZDSTATUS' ).

SELECT l~domvalue_l AS value,
       t~ddtext     AS text
  FROM dd07l AS l
  INNER JOIN dd07t AS t
    ON  t~domname    = l~domname
    AND t~valpos     = l~valpos
    AND t~as4local   = l~as4local
    AND t~ddlanguage = @sy-langu
  WHERE l~domname  = @lv_domname
    AND l~as4local = 'A'                  " 只取 Active 版本
  ORDER BY l~valpos
  INTO TABLE @DATA(lt_fixval).

" 用 REDUCE 組出一段可讀的說明字串
DATA(lv_hint) = REDUCE string(
  INIT s = ``
  FOR ls IN lt_fixval
  NEXT s = COND #( WHEN s IS INITIAL
                   THEN |{ ls-value }={ ls-text }|
                   ELSE |{ s } / { ls-value }={ ls-text }| ) ).

5. 外來鍵（Foreign Key）與 Text Table

定義：兩個表中有一個相同欄位，它在一個表中是主鍵，那麼這個公有欄位就是另一個表的外鍵。以另一個表的外鍵作關鍵字的表稱為主表（Check Table），具有此外鍵的表稱為從表（Foreign Key Table）。作用是保持資料一致性與完整性：外鍵只能引用主表中存在的值，或使用空值。

SE11 建外來鍵的步驟：（依講義步驟整理）

  1. Fields 頁籤，游標點在要建外鍵的欄位上（例如 Z2202_00_VBAK-KUNNR）。
  2. 按工具列的外來鍵圖示（鑰匙）。
  3. 輸入 Check table（例如 Z2202_00_KNA1）；系統會依 Domain 自動建議欄位對應（Check table field ↔ Foreign key field）。
  4. 設定 Cardinality（基數）：主表 1 或 C（C＝可為空），從表 1／C／N／CN。客戶 1 → 訂單 N 就是 1:CN。
  5. 設定 Foreign key field type（外鍵欄位類型）：
    • Non-key-fields/candidates：外鍵欄位不是主鍵
    • Key fields/candidates：是主鍵欄位或能唯一確定記錄
    • Key fields of a text table：這張表是主表的文本表
  6. 可勾 MsgClass/MsgNo 指定檢核失敗時的訊息。
外來鍵的檢核只在畫面輸入（Dynpro／SM30／Fiori）時自動生效，ABAP SQL 的 INSERT／UPDATE 不會檢核外鍵。所以你自己寫的上傳程式一定要自己檢核主表存在與否，不能靠字典。
" 上傳／過帳前自行檢核外來鍵：一次撈出所有主表 Key，再用 line_exists 判斷
SELECT kunnr
  FROM zerp300_kna1
  FOR ALL ENTRIES IN @lt_upload
  WHERE kunnr = @lt_upload-kunnr
  INTO TABLE @DATA(lt_valid_kunnr).

" FOR ALL ENTRIES 的空表陷阱：驅動表為空時會撈出「整張表」，務必先擋
IF lt_upload IS INITIAL.
  MESSAGE '無上傳資料' TYPE 'E'.
ENDIF.

" 轉成 HASHED 表，判斷才快
DATA lt_key TYPE HASHED TABLE OF kunnr WITH UNIQUE KEY table_line.
lt_key = VALUE #( FOR ls IN lt_valid_kunnr ( ls-kunnr ) ).

LOOP AT lt_upload ASSIGNING FIELD-SYMBOL(<ls_up>).
  IF NOT line_exists( lt_key[ table_line = <ls_up>-kunnr ] ).
    <ls_up>-msg = |客戶 { <ls_up>-kunnr } 不存在於主檔|.
  ENDIF.
ENDLOOP.

Text Table（文本表）：一張表是另一張表的文本表，條件是——文本表的主鍵＝主表主鍵 ＋ 語言欄位 SPRAS，除了這些欄位以外沒有其他能確定唯一性的欄位；而且要在 SPRAS 欄位上建立外來鍵、外鍵類型選 Key fields of a text table，Check table 填 T002。設定成功後，主表在 SE11 的 Delivery and Maintenance 頁籤就會顯示對應的 Text Table。

經典組合：MARA（物料主檔）↔ MAKT（物料說明）、TCURC（幣別）↔ TCURT（幣別說明）、T001W（工廠）↔ T001W 本身無文本表但有 NAME1。

  1. SE11 顯示 MAKT，在主鍵欄位 MATNR 上按「外來鍵關係」，就看得到 Check table = MARA。
  2. 看 Delivery and Maintenance 頁籤（舊版在 Further characteristics），會標註 Text Table／Master Data Table。
  3. 依 SAP 命名習慣猜（主表 + T，如 MARA→MAKT、TCURC→TCURT），但光憑名稱不一定準，最終仍要回 SE11 核對。
  4. 用 Data Element／Domain 的 Where-Used List，或直接查字典表 DD03L / DD08L。

7. SE54 表格維護產生器、SM30 與自訂 TCODE

光有表還不夠，使用者要能自己維護資料。這就是表格維護產生器（Table Maintenance Generator）的工作。入口有兩個：SE54，或 SE11 顯示該表 → Utilities → Table Maintenance Dialog（或 Table Maintenance Generator）。

產生步驟：（依講義步驟整理）

  1. Authorization Group：沒有特別需求填 &NC&。
  2. Function Group：填一個已存在且已激活的 Function Group（講義示範 ZFG2202_00_KNA1）。老師提醒：若無適合的 Function Group，可選 Z000，記得要按左上的新增鈕（像 A4 紙）；也可以用 SE37／SE80 先建一個，Function group 一定要激活。
  3. Maintenance type：
    • one step：只有一張總覽畫面（Overview），適合欄位少的表
    • two step：總覽 + 單筆明細畫面，欄位多時用
  4. Maint. Screen No.：按「Find Scr. Number(s)」讓系統自動配號（例如 0001 / 0002）。
  5. 按 Create，系統自動產生 Screen、PBO/PAI 模組與更新程式。
  6. 激活。若激活不完整，要用 SE80 打開該 Function Group 全部激活（老師 250501 特別註記過兩次的坑）。

產生後，使用者用 SM30 輸入表名／視圖名就能維護；SM31 是舊版入口；SM34 用來維護 View Cluster（多層設定表串成一個維護樹）。

為何要用 SM30 取代 SE16N？老師要學生想一下——因為 SE16N 是給開發／顧問用的原始資料瀏覽器，沒有欄位檢核順序、沒有外鍵 F4 的完整行為、沒有權限群組控管、也留不下客製檢核邏輯；SM30 走的是產生出來的 Dynpro，能掛外來鍵檢核、能寫事件（Events）做自訂驗證，才是給終端使用者用的。
改了表結構一定要重產維護畫面。老師原話：若日後又修改欄位或增加欄位時，為了讓 screen 也有這些新增欄位，必須進行修改。做法是 SE54 → Change → 先 Delete 產生的物件再重新 Create，或用「Generated Objects → Change → 調整 Screen」。忘了這一步，SM30 上就看不到新欄位。

SM30 也能變 TCODE（講義 02-4）：用 SE93 建立「Transaction with parameters（parameter transaction）」：

  1. SE93 → 輸入 ZKNA1M → Create → 選 Transaction with parameters (parameter transaction)。
  2. Transaction 填 SM30，勾 Skip initial screen。
  3. Default Values 區填：VIEWNAME = ZERP300_KNA1、UPDATE = X（X＝維護模式，空白＝顯示）。
  4. 存檔激活，使用者輸入 ZKNA1M 就直接進入維護畫面。

SM30 的 Events（SE54 → Environment → Modification → Events）可以掛自訂邏輯，例如存檔前檢核。以下是事件常式的現代化寫法（放在維護畫面所屬 Function Group 的 Include 中）：

" SE54 Event 21（Fill hidden fields）／01（Before saving the data in the database）
" 在存檔前補上異動人／異動日，並做自訂檢核
FORM zerp300_kna1_before_save.

  DATA: lv_error TYPE abap_bool.

  LOOP AT total ASSIGNING FIELD-SYMBOL(<ls_total>).

    " TOTAL 的前段就是視圖／資料表結構，後面才是維護畫面用的動作旗標
    ASSIGN <ls_total> TO FIELD-SYMBOL(<ls_row>) CASTING TYPE zerp300_kna1.
    IF sy-subrc <> 0.
      CONTINUE.
    ENDIF.

    " 自訂檢核：金額不可為負
    IF <ls_row>-zwert < 0.
      MESSAGE |客戶 { <ls_row>-kunnr } 的金額不可為負| TYPE 'E'.
      lv_error = abap_true.
    ENDIF.

  ENDLOOP.

  IF lv_error = abap_true.
    " sy-subrc 非 0 時，維護畫面會中止存檔
    sy-subrc = 4.
  ENDIF.

ENDFORM.

8. 建立 Database View / Projection View / Maintenance View

Database View（講義 05）：把 Z2202_00_VBAK ＋ Z2202_00_KNA1 建成 ZDV2202_00_VBAK。

  1. SE11 → View → Create → 選 Database view。
  2. Tables 區輸入兩張表 → 按 Relationships，系統會依既有外來鍵自動帶出 Join 條件（也可自己在 Join Conditions 手打）。
  3. View Fields 區按 Table fields 逐一挑欄位。
  4. Selection Conditions 可加固定過濾條件（例如 MANDT = 或某狀態碼）。
  5. Maintenance Status：多表視圖只能設 read only。
  6. 激活後，就可以在 ABAP SQL 直接 SELECT ... FROM ZDV2202_00_VBAK。
老師的兩句重點：Database View 是強制 INNER JOIN，而且（多表時）只能查看資料；選錯 View 型態，事後還可以換（SE11 → View → Change → 選單改型別），但「Database view 轉 Maintenance view 不見得能成功，反之則一定可以」。

練習題：ZDV300_VBAP_MARA（訂單明細 ＋ 物料）、ZDV300_VBAK_KNA1（訂單主檔 ＋ 客戶）。

Maintenance View（講義 06）：建 ZMV_2202_00_VBAK。

  • 參與的表必須已有外來鍵，連接條件不能自訂。
  • 所有參與表的主鍵都要放進視圖欄位，否則激活會報錯。
  • 每個欄位可設 R/O（唯讀）、Key。
  • 一定要建立螢幕——也就是要走 SE54 表格維護產生器，否則 SM30 進不去。
  • 練習題：ZMV300_VBAP_VBAK。

Projection View：只能一張表，用途是遮罩欄位（例如只讓某群使用者看得到客戶編號與名稱，看不到金額），可維護。

Help View：專供 Search Help 的 Selection Method；參與表必須有外來鍵，語意是 LEFT OUTER JOIN（主表沒有對應文字時仍會出現），這正是「物料 + 物料說明」F4 的標準做法。

" 不建 DB View，直接在 ABAP SQL 做 JOIN（S/4HANA 建議做法之一）
SELECT k~vbeln,
       k~erdat,
       k~kunnr,
       c~name1,
       k~netwr,
       k~waerk
  FROM zerp300_vbak AS k
  INNER JOIN zerp300_kna1 AS c
    ON c~mandt = k~mandt
   AND c~kunnr = k~kunnr
  WHERE k~erdat IN @s_erdat
    AND k~kunnr IN @s_kunnr
  ORDER BY k~vbeln
  INTO TABLE @DATA(lt_order).

" 需要「客戶沒訂單也要出現」時，改 LEFT OUTER JOIN
SELECT c~kunnr,
       c~name1,
       SUM( k~netwr ) AS total_netwr
  FROM zerp300_kna1 AS c
  LEFT OUTER JOIN zerp300_vbak AS k
    ON  k~mandt = c~mandt
    AND k~kunnr = c~kunnr
  GROUP BY c~kunnr, c~name1
  ORDER BY c~kunnr
  INTO TABLE @DATA(lt_sum).

9. Structure、Table Type、Type Group 與 SYST

Structure（講義 07）：SE11 → Data type → Structure。老師的注意事項：

  • 一般結構不需要放 MANDT（結構不落地，沒有 client 概念）。
  • 命名前三個字不能有底線，所以講義用 ZDV_ 這種寫法（Z + 兩碼 + 底線）。
  • 結構可以多層巢狀（欄位型別直接引用另一個結構，或用 .INCLUDE 包進來）。
  • 結構的用處是「寫程式時會方便很多」：ALV 的輸出結構、函數的介面參數、BDC 的資料容器，全都靠它。

Collective Search Help（複雜型）：由多個 Elementary Search Help 組成，使用者按 F4 時會看到多個頁籤（例如物料可用「依說明找」「依物料群組找」「依工廠找」）。建立時在 Included search helps 頁籤加入各個 Elementary，並按 Parameter assignment 把 Collective 的參數對應到各 Elementary 的參數。

講義 10-3：Collective Search Help 還可以再擴充——以 ME23 為例，把游標放在欄位上按 F1 → 技術資訊，可得知搜尋說明是 MEKK，就可以針對 MEKK 加入自己的 Elementary Search Help（Append Search Help，SE11 → Goto → Append Search Help，這樣升級不會被蓋掉）。

Search Help 連動的經典坑（講義原文的兩段對照）：
第一種寫法不會連動：P_1 TYPE T001W-WERKS, P_2 TYPE T001L-LGORT.
第二種寫法會連動：P_1 TYPE T001L-WERKS, P_2 TYPE T001L-LGORT.
原因：儲存地點 LGORT 的 Search Help 需要 WERKS 當 IMP 參數，而系統是靠「畫面上同名欄位」去抓值。當 P_1 宣告成 T001W-WERKS，畫面欄位的字典來源不同，F4 找不到對應的 WERKS 就不會過濾；改用 T001L-WERKS 之後，兩個欄位同屬 T001L，連動才成立。設計連動 F4 時，兩個欄位要來自同一張表／同一個 Search Help 的參數空間。

Search Help Exit：Search Help 也可以增強，用一支函數模組介入 F4 的每個階段。切記必須遵守 F4IF_SHLP_EXIT_EXAMPLE 的格式（複製它的介面），把函數名填在 Search Help 的 Search help exit 欄位。

FUNCTION z_shlp_exit_werks.
*"----------------------------------------------------------------------
*"  介面必須完全複製 F4IF_SHLP_EXIT_EXAMPLE：
*"  TABLES    shlp_tab   TYPE shlp_desct
*"            record_tab STRUCTURE seahlpres
*"  CHANGING  shlp       TYPE shlp_descr
*"            callcontrol LIKE ddshf4ctrl
*"----------------------------------------------------------------------

  " callcontrol-step 會依序被呼叫多次，用 CASE 分階段處理
  CASE callcontrol-step.

    WHEN 'SELONE'.
      " 選擇要用哪一個 Elementary Search Help（Collective 才會走到）
      RETURN.

    WHEN 'PRESEL'.
      " 進入選值畫面前：動態塞入額外的限制條件
      " 例如只允許使用者看自己有權限的工廠
      READ TABLE shlp-selopt ASSIGNING FIELD-SYMBOL(<ls_sel>)
           WITH KEY shlpfield = 'WERKS'.
      IF sy-subrc <> 0.
        APPEND VALUE ddshselopt( shlpfield = 'WERKS'
                                 sign      = 'I'
                                 option    = 'EQ'
                                 low       = '1000' ) TO shlp-selopt.
      ENDIF.
      RETURN.

    WHEN 'SELECT'.
      " 自己撈資料：撈完把 callcontrol-step 設成 'DISP' 可跳過標準選取
      RETURN.

    WHEN 'DISP'.
      " 清單顯示前：過濾掉不該讓使用者看到的列
      LOOP AT record_tab ASSIGNING FIELD-SYMBOL(<ls_rec>).
        IF <ls_rec>-string CS 'TEST'.
          DELETE record_tab INDEX sy-tabix.
        ENDIF.
      ENDLOOP.
      RETURN.

    WHEN 'RETURN'.
      " 使用者選定之後、回填畫面之前
      RETURN.

11. Lock Object 鎖物件與 ENQUEUE／DEQUEUE

鎖物件是對資料的存取進行並行控制。加鎖就是把使用者正在存取的資料登記在記憶體的 Lock Table（由 Enqueue Server 管理），解鎖就釋放。建立鎖物件會自動產生兩個函數，一個加鎖、一個解鎖；鎖物件名稱要以 E 開頭。

SE11 建立步驟：（依講義步驟整理）

  1. SE11 → Lock object → 輸入 EZERP300_VBAK → Create。
  2. Tables 頁籤：Primary table 填 ZERP300_VBAK；若要連明細一起鎖，可再加 Secondary table（要有外來鍵關係）。
  3. Lock mode 選：
    • E（Write lock，獨佔可累加）：最常用，同一交易可重複加鎖
    • S（Read lock，共享）：多人可同時讀，但不可有人寫
    • X（Exclusive，不可累加）
    • O（Optimistic）：先樂觀讀，存檔時才升級為寫鎖
  4. Lock parameter：預設是主表的所有 Key 欄位；可只挑部分（未挑的欄位視為萬用，會鎖更廣）。
  5. 激活 → 系統產生 ENQUEUE_EZERP300_VBAK 與 DEQUEUE_EZERP300_VBAK。

鎖物件三大坑：

Z 表在 HANA 上的設計原則：

  • SE11 建的表在 HANA 預設是 Column Store（欄式儲存），適合分析與大量掃描；只有極高頻單筆讀寫的小表才考慮 Row Store（技術設定的 Storage Type）。
  • 不要亂建 Secondary Index。Row Store 時代靠索引解決的問題，HANA 靠欄式壓縮＋平行掃描就夠了；多餘索引反而拖慢寫入、佔記憶體。真的要建，先用 ST05／SQL Monitor 證明有需要。
  • Code Pushdown：能在 SQL 做的（JOIN、彙總、CASE、字串處理）就不要撈回 ABAP 用 LOOP 做。
  • 大表避免 SELECT *——欄式儲存下，多讀一欄就多一份 I/O。
  • SELECT SINGLE 沒有排序保證：多筆符合時回傳哪一筆由 DB 決定，HANA 上結果可能與 AnyDB 不同。要指定就寫 ORDER BY ... UP TO 1 ROWS。
這正是專案上真實發生過的坑：某支成本報表因為資料同時存在兩種角度（例如 item category（H）與 cost component（E）），兩者的成本構成欄位數量不同，而程式沒有排序就取第一筆，於是「一下抓到 H、一下抓到 E」，成本結果不穩定。解法就是明確指定要哪一種（加 WHERE 條件）並加上 ORDER BY。另外相關經驗：條件用列舉（IN 明列值）比用區間（BETWEEN）安全，區間可能把不該納入的代碼一起掃進來。
