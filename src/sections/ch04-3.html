2. 動手前的三個前置設定（SPAD／RSCPSETEDITOR／SE78）

2-1　SPAD：輸出設備與紙張格式

Smart Form 要印，就一定要有輸出設備（Output Device）。SPAD 是 Spool 管理的總入口。（依講義步驟整理）

  • 進 SPAD → 切到 Full administration（完整管理）才看得到全部頁籤。
  • Devices / servers → Output devices：新增印表機。關鍵欄位是 Device Type（裝置類型）與 Host spool access method（存取方式，本機測試常用 L／C，前端印表機用 F）。
  • 裝置類型的選擇是中文能不能印出來的關鍵：Windows 前端印表機用 SWIN／SAPWIN；繁中／簡中環境用 CNSAPWIN、CNHP4；要輸出 Unicode PDF 用 PDFUC（一般 PDF 是 PDF1）。
  • Device types → Page formats：按 Display → 修改 → Page Formats → Create 可以新增特殊紙張格式（例如三聯式發票、A4 橫印、連續報表紙）。
  • A4 橫印＝在 Page Format 建一筆寬 297mm × 高 210mm 的格式，再建對應的 Format type（例如 X_65_255），Smart Form 的 Form Attributes 才選得到。
預設可用的紙張：DINA4（直）、DINA4 橫需要自建或用 LETTER／X_PAPER 系列。Smart Form 的 Page 節點只能選「已存在於該裝置類型」的格式，選不到就是 SPAD 沒建。

2-2　RSCPSETEDITOR：取消 MS Word 編輯器

SmartForms 的文字節點有兩種編輯器：PC Editor（SAP 內建）與 MS Word 編輯器。SAP HANA 平台之後預設強制走 MS Word。

老師的原話：「取消 MS Word 編輯器（SAP HANA 之後已強制預設為 MS Word，雖然網路上有教如何修改預設，但勿試）。」
意思是：知道有 RSCPSETEDITOR 這支程式（SE38 執行，可切換文字編輯器預設值）就好，正式系統不要亂動——它是 client 全域設定，改了全公司的 SO10、SmartForms、SAPscript 編輯器都跟著變，出問題很難回頭。真的要改請走變更流程並由 Basis 執行。

為什麼會想關掉 MS Word？因為用了 MS Word 編輯器之後：

  • 字體大小、段落格式會被 Word 蓋掉，不好設，跟 SMARTSTYLES 的段落格式打架。
  • 插入欄位（&FIELD&）的灰底標示行為不一樣，容易插成純文字而印不出值。
  • 沒裝 Office 或版本不合的 client 端會開不起來。
替代做法：在文字節點的編輯畫面選單 Goto → Change Editor，可以「當次」切回 PC Editor（行編輯器）。這比改系統參數安全得多，也是老師實際上課用的方法。

2-3　SE78：上傳 Logo 與背景圖

  • SE78（Form Graphics / SAPscript Graphics）→ 樹狀選 GRAPHICS → BMAP → BMAP（Bitmap Images） → 匯入按鈕。
  • 只吃 .BMP 與 .TIF；黑白（B/W）檔案小、印得快，彩色（Color）檔案大，會明顯拖慢列印。
  • 命名建議 ZLOGO_公司代碼，之後在 Smart Form 的 Graphic 節點選 Object=GRAPHICS、ID=BMAP、Name=ZLOGO_1000。
  • 另一條路是 OAER（Business Document Navigator）：Class Name = PICTURES、Class Type = OT，可以掛 JPG／GIF 等 SE78 不吃的格式，Smart Form 用 Graphic 節點的「Business Document」來源引用。
Logo 太大是列印變慢的頭號原因。300dpi 的彩色 BMP 動輒好幾 MB，每頁都要送一次到 Spool。建議：黑白 BMP、寬度不超過 600 px、檔案 < 100 KB。

3. SMARTSTYLES：樣式先做，表單才好做

SMARTSTYLES 是「為報表預先設定好樣式」，等同 Word 的樣式表。先做樣式、再做表單，否則你會在每個文字節點手動調字體，改一次要改幾十個地方。老師在課堂上建立的樣式叫 Z00_EKKO_EKPO（與表單同名，方便對應）。

3-1　樣式的三個組成

節點內容重點
Header Data（標題資料）Standard Paragraph（預設段落）、Tab Stop 預設值、First Page（第一頁樣式）一定要指定 Standard Paragraph，否則文字節點沒有預設格式，Active 會出錯
Paragraph Formats（段落格式）2 碼代號（如 HC、B1、L1、AS）。設定對齊、縮排、行距、段前段後、Tab、編號、外框對齊：LEFT／RIGHT／CENTER／BLOCK（左右對齊）
Character Formats（字元格式）2 碼代號（如 B1、B2、C1）。設定字體家族、大小、粗體、斜體、底線、上下標、條碼字元格式可以套在段落中的一部分文字上（<B1>粗體字</>）
老師的關鍵提醒：「段落不要設定字體大小，免得失去彈性。」
段落只管排版（對齊、縮排、行距），字體大小交給字元格式。這樣同一個段落可以印大標題也可以印小備註，改字級只改字元格式一處。

3-3　中文字型（最容易踩的坑）

  • Smart Style 的字體家族清單來自 SE73（SAPscript Font Maintenance）的 System font families。
  • Unicode 系統：中文用 ANDALE 系列（ANDALE_J／ANDALE_K／ANDALE_S／ANDALE_T，T 是繁體）或 SAPFONT；非 Unicode 中文系統傳統上用 CNSONG（中易宋體）。
  • 選了字型，還要看裝置類型有沒有掛這個字型——SE73 → Printer fonts → 選 Device Type → 看字型清單。沒掛就印出方框或空白。
  • 轉 PDF 中文變亂碼／方框，九成是輸出設備的 Device Type 用了 PDF1（非 Unicode），改成 PDFUC 或 CNSAPWIN 就好。
「螢幕預覽正常、印出來變方框」是最典型的字型問題：預覽走的是 SAPGUI 的字型，實體列印走的是 Device Type 掛的印表機字型。驗收一定要真的印一張出來，或至少用目標裝置轉一次 PDF。

3-4　條碼（Barcode）

  • 條碼在 SAP 是「特殊的字元格式」：SE73 → System bar codes 建條碼定義 → 在 SMARTSTYLES 的字元格式裡的 Barcode 欄位選它 → 文字節點把那段欄位套上這個字元格式。
  • 舊式條碼（BC_CD39、BC_EAN13…）是「印表機條碼」，靠 Device Type 的印表機指令產生，換印表機就可能印不出來。
  • 新式條碼（New Bar Code Technology）：SE73 建立時選 New，可用 BC_C128（Code128）、BC_C39、BC_EAN13、BC_PDF417、BC_QR（QR Code，需支援的 kernel）。新式條碼由 SAP 自己算出圖形（PDL barcode），跨印表機穩定得多，新專案一律用新式。
  • 條碼欄位常需要「不做轉換常式」，插入欄位時記得加 (K) 選項：&ls_head-ebeln(K)&，否則 ALPHA 轉換會把前導零吃掉，掃出來的號碼跟系統不一致。

6. Pages and Windows：頁面與視窗

Smart Form 的版面模型很簡單：一份表單有多個 Page，每個 Page 上擺多個 Window，Window 裡才放內容節點。老師的分法是三段：表頭 → 表身（Main Window，會 loop）→ 表尾。

6-1　Page 節點

屬性說明實務設定
Next Page這一頁印滿後跳到哪一頁單頁循環：%PAGE1 的 Next Page 填 %PAGE1（指向自己），這樣資料多就自動一直加頁
Page Counter → Mode頁碼行為：Increase（＋1）／Hold（不變）／Initialize（歸零重算）續頁用 Increase；附件頁若要獨立編號用 Initialize
Page counter → Numbering type阿拉伯數字／羅馬數字／字母一般 Arabic numerals
Output Options本頁的 Page format、Print mode（S=單面／D=雙面／T=Tumble）、Print attributes雙面列印才設 D
Conditions本頁在什麼條件下才輸出例如「只有 COPYCOUNT > 1 才印的存查聯」
「首頁不一樣、續頁只要表格」怎麼做：建 %PAGE1（有 Logo、有廠商資訊、有 Main Window）與 %PAGE2（只有簡化表頭 + Main Window + 表尾）。%PAGE1 的 Next Page = %PAGE2，%PAGE2 的 Next Page = %PAGE2。這是最常見的兩頁式結構。

Secondary（次視窗）固定位置固定大小，內容超出就被截掉，不會續頁表頭資訊、廠商地址、表尾簽核欄、備註
Copies Window（副本視窗）可設定「只在正本印」「只在副本印」「客戶聯／會計聯／存查聯」的差異文字
Final Window（最終視窗）整份表單處理完之後才輸出——此時總金額、總頁數才算得出來總計金額、「共 x 頁」、大寫金額
MAIN Window 的三條硬規則：
1. 一頁只能有一個 MAIN。
2. 所有頁面的 MAIN 寬度必須相同，高度可以不同——寬度不同會在 Active 時報錯。
3. 一個 Page 若沒有 MAIN Window，表單處理到它就停住，不會再往下一頁（因為續頁機制是靠 MAIN 觸發的）。這就是「最後一頁印不出來」「資料只印第一頁」的最常見原因。

6-3　精確調整位置

三個視窗（表頭 Secondary、MAIN、表尾 Secondary）拖曳只能粗調，精確調整要在 Window 的 Output Options 頁籤直接輸入數值：（依講義步驟整理）

  • Left Margin（左邊界）、Upper Margin（上邊界）、Window Width（寬）、Window Height（高）。
  • 單位建議統一用 MM（也可用 CM、TW、PT、CH、LN）。A4 直式可用範圍約 寬 190mm × 高 277mm（左右各留 10mm）。
  • 建議配置：表頭 Y=10 H=45、MAIN Y=57 H=180、表尾 Y=240 H=40。三者相加不要超過紙高，重疊會蓋字。
  • Window 的 Conditions 頁籤可設「只在第一頁顯示」（SFSY-PAGE = 1）、「只在最後一頁顯示」（配合 Final Window）。

7. Template 與 Table：兩個長得像、用途完全不同的節點

這是 SmartForms 最容易搞混的一組。兩個都畫格子，差別在「列數固不固定」。

比較項Template（範本）Table（表格）
列數固定，設計時就決定幾行幾列動態，隨內表筆數增減
是否會 LOOP不會會（自帶 Data 頁籤的 LOOP）
是否自動跨頁不會（放 MAIN 也不會續頁）會，而且會自動重印 Header
結構只有格子Header / Main Area / Footer 三段
典型用途表頭欄位框、簽核欄、固定格式的收據格明細清單
放哪個 WindowSecondary Window（表頭／表尾）MAIN Window
一句話記法：Template＝固定格子（表頭表尾），Table＝會長高的格子（明細）。老師的採購單就是這樣配：表頭 Secondary Window 放兩個 Template（報表抬頭、採購單頭），MAIN Window 放一個 Table。

7-1　Template 的操作要點

  • 建立：對 Window 按右鍵 → Create → Template。
  • Table Painter（表格繪製器）：按 Details 鈕可以逐行逐格輸入精確尺寸——這是老師強調的「每個 TEMPLATE 可以按 Details 鈕，做精確的尺寸設定」。
  • Line Type（%LTYPE1、%LTYPE2…）：定義「一種列的欄寬組合」。同一個 Template 可以有多種 Line Type，例如 %LTYPE1 是抬頭（一整欄），%LTYPE2 是明細（六欄）。
  • 每個格子（Cell）要指定 Line 與 Column，Template 才知道文字要放哪一格。老師：「記得標明 Line 與 Column」——漏填是「東西不見了」的頭號原因。
  • Pattern（框線）：在 Table Painter 用 Select Pattern 一次套用外框／內框／無框。

課堂案例的表頭四個欄位（在 Template 的格子裡各放一個 Text 節點）：

格位內容（& 括起來的就是欄位）

L1 C2公司代碼 &I_EKKO-BUKRS&
L2 C1單據類型 &I_EKKO-BSART& &I_EKKO-BATXT&

頁籤設定內容
DataInternal Table：I_EKPO INTO WA_EKPO（來源內表 → 工作區）。可加 WHERE 條件、Sort Criteria（排序欄位，勾 Event on Sort Begin/End 可做小計）

Table 節點樹狀下面固定有三個資料夾：

  • Header：表格抬頭。跨頁時會自動重印（可在 Header 資料夾的屬性關掉 At Start of Table only）。放六個 Text 節點：項次／物料編號／採購數量／單位／工廠／儲存位置。

1WA_EKPO-EBELPEBELP項次靠中
2WA_EKPO-MATNRMATNR物料編號靠左

數字沒對齊是驗收被退件的常見原因。解法有兩個，要一起用：
1. 段落格式設 RIGHT（靠右）；
2. 插入欄位時指定輸出長度並靠右：&WA_EKPO-MENGE(13)& 或 &WA_EKPO-MENGE(R)&。
只設段落靠右，遇到不同長度的數字仍會因為千分位與小數位而看起來歪。

8. Text 節點與「插入欄位」的完整規則

Text 節點是表單裡最多的節點。它有四種 Text Type：

Text Type說明使用場合
Text element直接在節點裡打字（PC Editor）絕大多數情況
Text module引用 SmartForms 的 文字模組（SMARTFORMS 的 Text Module 物件，Client 獨立、可翻譯）條款、注意事項、公司抬頭，多張表單共用
Include text讀 SAPscript 標準長文（SO10／單據長文）採購單抬頭文字、項目文字、客戶備註
Dynamic text執行期才決定要讀哪一段長文（名稱由變數給）依單據動態抓長文

8-1　Include Text 的四個關鍵欄位

Include Text 節點要填 Text Name / Text Object / Text ID / Language，這四個就是 STXH（長文抬頭表）的主鍵，也是 READ_TEXT 的四個參數。

參數意義採購單常見值
OBJECT文字物件（屬於哪個模組）EKKO（採購抬頭）、EKPO（採購項目）、TEXT（SO10 通用文字）、KNA1、VBBK
ID文字類型F01（Header text）、F02（Header note）、F03、ST（SO10 標準文字）
NAME文字名稱＝單據鍵抬頭：EBELN；項目：EBELN && EBELP（10+5＝15 碼）
LANGUAGE語言SY-LANGU

找不到 ID／OBJECT 時的標準做法：到單據的長文編輯畫面（例如 ME23N 的 Texts 頁籤）→ 選單 Goto → Header，畫面會直接顯示 Text Name／Language／Text ID／Text Object。

" === 在程式端自己讀長文（Smart Form 之外也常用）===
DATA lt_line TYPE STANDARD TABLE OF tline WITH EMPTY KEY.

DATA(lv_name) = CONV thead-tdname( ls_head-ebeln ).

TRY.
    CALL FUNCTION 'READ_TEXT'
      EXPORTING
        id                      = 'F01'          " 文字 ID
        language                = sy-langu
        name                    = lv_name        " 採購單號
        object                  = 'EKKO'         " 文字物件
      TABLES
        lines                   = lt_line
      EXCEPTIONS
        id                      = 1
        language                = 2
        name                    = 3
        not_found               = 4
        object                  = 5
        reference_check         = 6
        wrong_access_to_archive = 7
        OTHERS                  = 8.

    IF sy-subrc = 0.
      " 用 REDUCE 把多行長文串成一個字串
      DATA(lv_text) = REDUCE string(
                        INIT t = ``
                        FOR <ls_line> IN lt_line
                        NEXT t = COND #( WHEN t IS INITIAL
                                         THEN CONV string( <ls_line>-tdline )
                                         ELSE |{ t }{ cl_abap_char_utilities=>newline }{ <ls_line>-tdline }| ) ).
    ENDIF.
  CATCH cx_root INTO DATA(lx_err).
    MESSAGE lx_err->get_text( ) TYPE 'S' DISPLAY LIKE 'W'.
ENDTRY.
長文是 Client 相依的（STXH／STXL 有 MANDT）。SO10 建立的標準文字不會跟著 Request 自動傳輸，必須用 RSTXTRAN 把它掛進傳輸請求，或在目標環境重建。「開發機好好的，測試機文字不見了」九成是這個原因。
相對地，SmartForms 的 Text Module 是 Repository 物件、Client 獨立、會跟著 Request 走——能用 Text Module 就不要用 SO10。

8-2　插入欄位（Including Fields）的規則

這一段來自 SAP 官方文件，老師特別整段收錄，因為「畫報表是苦差事，若遇到要求細緻的表，一定要仔細閱讀原廠的文件」。

  • 欄位必須用 & 前後包起來：&I_EKKO-EBELN&。
  • 插入方式三選一：(1) 從左邊 Field List 拖曳（Drag&Drop）到游標處；(2) PC Editor 工具列的 Include field（另有 Change field／Delete field）；(3) 直接打字後做 local check。
  • 成功的唯一判準：欄位會顯示成灰底。 老師原話：「一定要變灰色，才表示有成功哦」「手冊上有些欄位的插入方法是錯誤的，記得只要是欄位一定要是灰色的，就是了」。
  • 你自己的欄位必須先定義成 Global Data 或 Form Interface 參數，才插得進去。
  • 名稱規則：不得含空白；不得含 '+()（這些是格式化選項的保留字元）；最長 130 字元但只有前 32 字元有辨識力；不分大小寫；結構欄位用 減號 連接（KNA1-NAME1）。
  • 如果 Text 節點引用了 Text module 或 Include text，被引用文字裡的欄位也會一起被複製進來並解析。

8-3　系統欄位 SFSY

表單內可用的欄位字串是 SFSY（不是 SY！）。規則：可以顯示任何 SFSY 欄位；不可以在 Program Lines 裡指派值給 SFSY；條件式可以查詢所有 SFSY 欄位，但 SFSY-FORMPAGES 只能在 Final Window 內查詢、SFSY-JOBPAGES 完全不能查詢。

欄位意義
&SFSY-DATE&日期（格式依使用者主資料）
&SFSY-TIME&時間 HH:MM:SS
&SFSY-PAGE&目前頁碼（格式由 Page 節點的 Page counter 決定）
&SFSY-FORMPAGES&本份表單總頁數 → 「第 x 頁／共 y 頁」
&SFSY-JOBPAGES&整個列印請求（多份表單合併）的總頁數
&SFSY-WINDOWNAME&目前 Window 名稱
&SFSY-PAGENAME&目前 Page 名稱
&SFSY-XSF&輸出格式是 XSF／HTML 時為 'X'。用來在條件式裡隱藏「只有畫面才需要」的元素（例如按鈕）
&SFSY-COPYCOUNT&1＝正本、2＝第一份副本、3＝第二份副本…
&SFSY-COPYCOUNT0&0＝正本、1＝第一份副本…（差 1）
SFSY-SUBRC可在 Program Lines 查詢。目前只對 include text／text module 有效：0＝找到並印出，4＝找不到
SFSY-USERNAME執行列印的使用者登入名稱
SFSY-FORMPAGES／SFSY-JOBPAGES 很吃記憶體：為了算出總頁數，系統必須把所有輸出頁面留在主記憶體中，直到整份表單／整個列印工作結束。大量列印（例如一次印五千張出貨單）用「第 x 頁／共 y 頁」可能直接把記憶體吃爆。大批次列印請避開 JOBPAGES。

8-4　欄位的格式化選項（Formatting Options）

選項寫在欄位名稱後面，大寫字母，部分可組合。數值欄位的評估順序：(<length>) → < → L → C → R → F；字元欄位：C → +<offset> 與 (<length>) → R → F。單一欄位輸出上限 255 字元。

語法作用
&f+<offset>&跳過前 n 個字元（僅字元欄位）。offset 大於值長度則不顯示
&f(<length>)&設定輸出長度
&f(*)&用 DDIC 定義的輸出長度
&f(S)&不印正負號
&f(<)&負號印在數字左邊（台灣報表必用，SAP 預設負號在右邊）
&f(.N)&限制小數位數為 N
&f(EN)&以固定指數 N 顯示
&f(T)&不印千分位（DEC／CURR／INT／QUAN）
&f(Z)&去除前導零
&f(I)&初始值不顯示（0 或空白就印空的）
&f(K)&停用 DDIC 的轉換常式（條碼、要原始值時用）
&f(R)&靠右對齊（必須同時指定輸出長度才有效）
&f(F*)&左側空白補上填充字元（例如 &f(F0)& 補零）
&f(C)&壓縮空白，效果同 ABAP 的 CONDENSE
&f(L)&日本地區日期格式（JPDAT），只在日文版用

常用組合實例：&WA_EKPO-MENGE(13.3<)&＝寬 13、三位小數、負號在左；&I_EKKO-EBELN(Z)&＝採購單號去前導零；&I_EKKO-LIFNR(K)&＝廠商編號印原始值。

9. 其他節點：Address / Graphic / Folder / Alternative / Loop / Command / Program Lines

節點用途關鍵設定
Address（地址）依各國郵政格式自動排版地址，不用自己拼字串Address type：Organization（給 ADRNR，例如廠商 LFA1-ADRNR）／Person（ADRNP）／Workplace。可設 Number of lines、Priority（哪幾行優先保留）、Recipient language
Graphic（圖形）Logo、印章、浮水印、背景Object=GRAPHICS、ID=BMAP、Name=SE78 上傳的名稱；Color/Black&White；Resolution；可選 Background picture（滿版背景）

Alternative（替代）IF-ELSE。底下自動產生 TRUE / FALSE 兩個資料夾Conditions 頁籤寫條件；比在每個節點各寫一次條件清楚得多

Complex SectionLoop + Program Lines + Template 的組合節點較少用，能用 Table 就用 Table
強制換頁的標準做法：在 MAIN Window 內插入 Command 節點 → 勾 Go to New Page → 指定 New page = %PAGE2。再把 Command 節點的 Conditions 設成「每 10 筆換一頁」或「客戶代碼改變時換頁」，就能做出「一個客戶一張單」的批次列印。

Program Lines 節點的典型內容（放在 Table 的 Main Area 之前，用來做逐列加工）：

" === Program Lines：明細列前的加工 ===
" Input  parameters: WA_EKPO, I_EKKO
" Output parameters: GV_ROW_COLOR, GV_AMT_TXT, LV_MENGE

" 1) 交錯底色（配合 Table Line 的兩種 Line Type 使用）
gv_row_color = COND char1( WHEN sy-tabix MOD 2 = 0 THEN 'X' ELSE space ).

" 2) 數量超量標紅字用的旗標
gv_over = COND char1( WHEN wa_ekpo-menge > 1000 THEN abap_true ELSE abap_false ).

" 3) 單位描述（用 T006A 取中文單位）
SELECT SINGLE msehl FROM t006a
  WHERE spras = @sy-langu
    AND msehi = @wa_ekpo-meins
  INTO @gv_unit_txt.

" 4) 若沒有物料名稱就補一段預設文字
gv_maktx = COND maktx( WHEN wa_ekpo-maktx IS INITIAL
                       THEN |（無物料主檔說明）|
                       ELSE wa_ekpo-maktx ).
Program Lines 裡不要下 SELECT 進迴圈！ 上面第 3 點的寫法是為了示範語法；真的要用，請在 Initialization 一次把 T006A 全撈進一個 HASHED TABLE，Program Lines 只做 lt_t006a[ msehi = wa_ekpo-meins ] 查表。1000 筆明細＝1000 次 DB 存取，列印會慢到被使用者投訴。

10. 產生的函數模組：為什麼一定要用 SSF_FUNCTION_MODULE_NAME

Smart Form 按 Active（啟動）時，系統會產生一支真正的函數模組，名稱長得像 /1BCDWB/SF00000009。你的程式其實是在呼叫這支函數。

老師的第一版程式（08-1）是直接寫死函數名稱——這是教學用的第一步，正式程式絕對不能這樣寫：

" 反例（錯誤示範）：寫死產生的函數名（僅供理解用，正式程式禁用）
CALL FUNCTION '/1BCDWB/SF00000009'   " ← 每張報表的函數都不相同
  EXPORTING i_ekko = ls_head
  TABLES    i_ekpo = lt_item
  EXCEPTIONS formatting_error = 1
             internal_error   = 2
             send_error       = 3
             user_canceled    = 4
             OTHERS           = 5.
為什麼寫死一定會出事：
1. 這個編號是各系統各自產生的流水號。表單傳輸到 QAS／PRD 之後，那邊重新產生的函數名幾乎一定不同（也可能相同，但你不能賭）。
2. 只要有人重新 Active 一次表單，函數就可能重新產生新編號。
3. 系統升級、SPAU 調整之後也會重生。
→ 結果就是「開發機好好的，上線就 dump：CALL_FUNCTION_NOT_FOUND」。
正確做法：一律用 SSF_FUNCTION_MODULE_NAME，用「表單名稱」換「函數名稱」。
" 正解：動態取得函數名稱
DATA lv_fm_name TYPE rs38l_fnam.

CALL FUNCTION 'SSF_FUNCTION_MODULE_NAME'
  EXPORTING
    formname           = 'Z00_EKKO_EKPO'   " ← 表單名稱（這個才是穩定的）
*   variant            = ' '
*   direct_call        = ' '
  IMPORTING
    fm_name            = lv_fm_name
  EXCEPTIONS
    no_form            = 1
    no_function_module = 2
    OTHERS             = 3.

IF sy-subrc <> 0.
  MESSAGE |找不到表單 Z00_EKKO_EKPO 或其函數尚未產生（RC={ sy-subrc }）| TYPE 'E'.
ENDIF.

" 之後就用變數呼叫
CALL FUNCTION lv_fm_name
  EXPORTING i_ekko = ls_head
  TABLES    i_ekpo = lt_item
  EXCEPTIONS formatting_error = 1
             internal_error   = 2
             send_error       = 3
             user_canceled    = 4
             OTHERS           = 5.
把表單名稱做成 PARAMETERS 或 TVARVC 常數，不要寫死在程式裡；這樣同一支列印程式可以切換「正式版／簡化版／英文版」三張表單，維運只要改變式。

11. 完整的呼叫程式（現代 ABAP 改寫版）

講義的原程式 Z202202_60 用了 SELECT *、INTO CORRESPONDING FIELDS OF TABLE、READ TABLE … MODIFY 這些舊寫法。以下是 S/4HANA 1809 以後的現代寫法，邏輯完全等價但更快也更安全。

*&---------------------------------------------------------------------*
*& Report Z00_SF_PO_PRINT ── 採購單 SmartForm 列印（現代版）
*&---------------------------------------------------------------------*
REPORT z00_sf_po_print.

CONSTANTS gc_formname TYPE tdsfname VALUE 'Z00_EKKO_EKPO'.

PARAMETERS: p_ebeln TYPE ekko-ebeln OBLIGATORY DEFAULT '4500000001',

    FROM ekko
    WHERE ebeln = @p_ebeln

    FROM t161t
    WHERE spras = @sy-langu
      AND bstyp = 'F'
      AND bsart = @gs_head-bsart
    INTO @gs_head-batxt.

    INNER JOIN adrc AS a ON a~addrnumber = l~adrnr

  SELECT ebelp, matnr, menge, meins, werks, lgort

老師原程式的三個陷阱，改寫時一定要處理：
1. SELECT SINGLE BATXT FROM T161T WHERE BSART = … 沒有帶 SPRAS！T161T 的主鍵是 SPRAS＋BSTYP＋BSART，不帶語言會隨機抓到英文或德文，也可能因為SELECT SINGLE 對非唯一鍵沒有排序保證而每次結果不同。
2. FOR ALL ENTRIES 前面必須確定驅動內表不是空的（原程式有做 IF LT_EKPO IS NOT INITIAL，很好，要保留）；空表會變成「無 WHERE 條件」全表掃描。
3. SELECT * FROM EKPO 在 S/4HANA 上 EKPO 有 300+ 欄位，全撈是嚴重浪費。一律明列欄位。

12. 輸出控制：CONTROL_PARAMETERS 與 OUTPUT_OPTIONS 完整對照

12-1　CONTROL_PARAMETERS（型別 SSFCTRLOP）

欄位作用
NO_DIALOG'X'＝不顯示列印對話框。背景執行必設
PREVIEW'X'＝顯示列印預覽
GETOTF'X'＝不真的印，把 OTF 資料回傳到 JOB_OUTPUT_INFO-OTFDATA。轉 PDF、寄信都靠它
NO_OPEN / NO_CLOSE多份表單合併到同一個 Spool 時使用，配合 SSF_OPEN／SSF_CLOSE
DEVICE'PRINTER'（預設）／'TELEFAX'／'MAIL'／'SCREEN'
LANGU表單輸出語言
REPLANGU1/2/3找不到指定語言時的替代語言
STARTPAGE指定從哪一頁開始輸出
GETOTF = 'X' 時，NO_DIALOG 也要一起設 'X'，否則背景執行會卡在對話框，Job 一直不結束。而且 GETOTF 開了就不會產生 Spool——想「既存 Spool 又拿 OTF」要跑兩次，或先拿 OTF 再自己用 RSPO_SR_OPEN／WRITE 建 Spool。

12-2　OUTPUT_OPTIONS（型別 SSFCOMPOP）

欄位作用
TDDEST輸出裝置（印表機代號，如 LOCL、LP01）
TDIMMED'X'＝立即列印（Print immediately）
TDDELETE'X'＝列印後刪除 Spool
TDNEWID'X'＝建立新的 Spool Request（不要跟前一份併在一起）
TDCOPIES份數
TDNOPRINT'X'＝只產生 Spool 不真的印
TDFINALSpool 是否標記為已完成
TDTITLESpool 標題（在 SP01 顯示，強烈建議帶單號方便追查）
TDLIFETIMESpool 保留天數（預設 8）
TDCOVER / TDCOVTITLE是否印封面頁與封面標題
TDARMOD1＝只印、2＝只歸檔、3＝印＋歸檔（ArchiveLink）
TDPRINTERDevice type（'SWIN'、'CNSAPWIN'、'PDFUC'…）
XSF / XSFFORMAT / XSFOUTMODE / XSFOUTDEVXSF／HTML 輸出用

12-4　幣別／數量欄位在不同表時的對應

SAP 官方規則：值欄位與幣別／單位欄位在同一張表時，Smart Forms 會自動辨識並正確格式化；不在同一張表時，你必須明講。做法（在 Global Definitions → Currency/Quantity Fields 頁籤）：

  1. 在 Global Data 定義一個與「存幣別的那張表」同型別的工作區，例如 WA_CURTAB；以及輸出值欄位的工作區 WA_VALTAB。
  2. 在 Currency/Quantity Fields 填：Field name = WA_VALTAB-VALUE，Reference field = WA_CURTAB-CURRENCY。
  3. Table／Loop 節點的 Data 頁籤用 WA_VALTAB 當工作區。
  4. 在輸出該欄位之前插入一個 Program Lines 節點，把幣別／單位指派給 WA_CURTAB-CURRENCY（值可在表單裡 SELECT，或由 Form Interface 傳進來）。
" === Program Lines：放在輸出金額欄位之前 ===
" Input parameters : I_EKKO
" Output parameters: WA_CURTAB

" 讓 WA_VALTAB-VALUE 依採購單的幣別格式化（小數位數才會對）
wa_curtab-currency = i_ekko-waers.
金額小數位印錯幾乎都是這個問題。JPY（0 位）、TWD（2 位）、KWD（3 位）的小數位數不同，SAP 內部一律存兩位，靠幣別欄位換算。沒掛幣別參考，日圓 1000 會印成 10.00。

        i_att_content_hex    = it_solix ).

      lo_send->add_recipient( i_recipient = lo_recipient
                              i_express   = abap_true ).

      lo_send->set_sender(
        cl_cam_address_bcs=>create_internet_address( 'noreply@company.com' ) ).

      " 6) 立即送出、要求狀態回報
      lo_send->set_send_immediately( abap_true ).
      lo_send->set_status_attributes( i_requested_status = 'N'   " 只在失敗時通知
                                      i_status_mail      = 'N' ).

      DATA(lv_sent) = lo_send->send( i_with_error_screen = abap_true ).

      IF lv_sent = abap_true.
        COMMIT WORK.                      " ← CL_BCS 一定要 COMMIT 才會真的寄出

14. NACE 輸出決定與 SPOOL 管理

正式專案裡，很少讓使用者「執行一支 Z 程式來印單據」，而是在單據存檔時自動觸發列印。這靠的是 Output Determination（輸出決定）。

14-1　NACE 的五層設定

層次內容說明
1. ApplicationEF＝採購訂單、V1＝銷售、V2＝送貨、V3＝帳單、M1/M2＝MM 收貨NACE 第一個畫面就是選它
2. Output Type（輸出類型）NEU（採購單）、BA00（訂單確認）、LD00（送貨單）、RD00（發票）可複製標準的改成 Z*
3. Processing Routines（處理程式）Medium（1＝印表機、5＝外部傳送/EMail、A＝ALE、6＝EDI）＋ Program ＋ FORM routine ＋ Form / PDF-FormSmartForm 填在「Form」旁的 Smart Form 欄位（不是 SAPscript 的 Form 欄位）
4. Access Sequence / Condition Table決定「什麼條件下要出這個輸出」例如「採購組織＋文件類型」
5. Condition Record（MN04/MN05 等）實際的輸出主資料：印表機、份數、時點（1＝立即、3＝手動、4＝批次）沒建 Condition Record，單據存檔就不會出輸出

NACE 呼叫的驅動程式（Print Program）介面是固定的——SAP 標準採購單用 SAPFM06P ＋ FORM routine ENTRY_NEU。客製時複製成 Z 程式：

*&---------------------------------------------------------------------*

17-2　Fiori／新輸出管理

  • S/4HANA 1610 起，部分應用（銷售訂單、交貨單、帳單、採購單）改走 Output Control（新輸出管理）：用 BRF+ 決定 Output Type、Channel（Printer／Email／XML／IDoc）、Receiver、Form Template。
  • 設定入口：OPD（Output Parameter Determination）、Fiori App「Manage Output Items」「Output Parameter Determination」、以及 SPRO 的 Cross-Application Components → Output Control。
  • 表單本體只支援 Adobe Forms（Form Template）與 Fragment；新輸出管理不支援 SmartForms／SAPscript。
  • NACE 並沒有被移除，很多模組（MM 的收貨單、PP 的工單）仍走 NACE。專案上要先確認該單據走的是哪一套，設定的地方完全不同。

不要在 S/4HANA 上把 SmartForms 全部改寫成 Adobe Forms。 遷移成本高、風險大，SAP 也明確表示 SmartForms 繼續支援。合理策略是：既有的維持、新的用 Adobe、走新輸出管理的單據只能用 Adobe。
