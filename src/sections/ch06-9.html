2. 原生基礎：型別 d／t、系統欄位與日期算術

ABAP 的日期型別 d 是 8 碼字元 YYYYMMDD，時間型別 t 是 6 碼 HHMMSS。它們看起來是字元，但放進算術運算時會自動換成數字：d 換成「從 0001-01-01 起算的天數」，t 換成「從 00:00:00 起算的秒數」。所以日期加減天數、兩日相減求天數，都不需要函數。

系統欄位意義什麼時候用
sy-datum／sy-uzeit系統日期與時間（系統時區，見 TTZCU-TZONESYS）和系統時間戳記對齊的技術用途
sy-datlo／sy-timlo使用者所在時區的當地日期與時間畫面預設值、過帳日期、給人看的日期
sy-zonlo使用者時區（SU01／SU3 預設值頁籤）時間戳記轉當地時間
sy-fdayw工廠日曆的星期幾少用
sy-tzone／sy-dayst和 UTC 的秒差、是否夏令時間已過時，改用時間戳記與時區
 
REPORT z_date_basics.

DATA(lv_today) = sy-datlo.                    " 型別 d，使用者當地日期
DATA(lv_now)   = sy-timlo.                    " 型別 t

DATA lv_d30 TYPE d.
lv_d30 = lv_today + 30.                       " 30 天後（自動跨月、跨年、閏年）

DATA lv_d7 TYPE d.
lv_d7 = lv_today - 7.                         " 一週前

DATA(lv_days) = lv_d30 - lv_today.            " 兩個 d 相減 → 整數天數 30

DATA lv_t90 TYPE t.
lv_t90 = lv_now + 90 * 60.                    " 90 分鐘後（超過午夜會自動折回 00:xx）

" 拆欄位：offset / length
DATA(lv_year)  = lv_today+0(4).
DATA(lv_month) = lv_today+4(2).
DATA(lv_day)   = lv_today+6(2).

" 比較：YYYYMMDD 的字元順序剛好等於時間順序
IF lv_d30 > lv_today.
  cl_demo_output=>write( |{ lv_d30 DATE = USER } 在今天之後| ).
ENDIF.

cl_demo_output=>write( |今天 { lv_today DATE = USER } { lv_now TIME = USER }，| &&
                       |年 { lv_year } 月 { lv_month } 日 { lv_day }，時區 { sy-zonlo }| ).
cl_demo_output=>display( ).
內嵌宣告的型別陷阱：DATA(lv_x) = lv_today + 30. 宣告出來的是 整數（算術運算的計算型別），不是日期。要日期就先 DATA lv_x TYPE d. 再賦值，或寫 CONV d( lv_today + 30 )。
時間相加會折回：t 型別加到超過 24 小時會取餘數，日期不會跟著進位。跨日的「日期＋時間」運算要用時間戳記（第 10 節）或 cl_abap_tstmp=>td_add。
無效日期：d 欄位可以放進 '20140230' 這種不存在的日期，語法不會擋。拿無效日期做運算的結果不可預期，外部來的日期（上傳檔、介面、Z 表的 CHAR 欄位）一定要先檢查，見第 12 節。

3. 取月初、月底

原生寫法

月初就是把日改成 01。月底的做法是：月初加 31 天一定會落在下個月，再把日改成 01 得到下月初，減 1 天就是本月底。這個方法自動處理大小月與閏年。

CLASS lcl_date DEFINITION FINAL.
  PUBLIC SECTION.
    CLASS-METHODS first_day IMPORTING iv_date        TYPE d
                            RETURNING VALUE(rv_date) TYPE d.
    CLASS-METHODS last_day  IMPORTING iv_date        TYPE d
                            RETURNING VALUE(rv_date) TYPE d.
ENDCLASS.

CLASS lcl_date IMPLEMENTATION.
  METHOD first_day.
    rv_date = iv_date.
    rv_date+6(2) = '01'.
  ENDMETHOD.

  METHOD last_day.
    DATA lv_next TYPE d.
    lv_next = first_day( iv_date ) + 31.      " 一定落在下個月
    lv_next+6(2) = '01'.                      " 下個月 1 號
    rv_date = lv_next - 1.                    " 本月最後一天
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  DATA(lv_date) = CONV d( '20240215' ).
  cl_demo_output=>write( |月初 { lcl_date=>first_day( lv_date ) DATE = ISO }| ).   " 2024-02-01
  cl_demo_output=>write( |月底 { lcl_date=>last_day( lv_date ) DATE = ISO }| ).    " 2024-02-29（閏年）
  cl_demo_output=>display( ).

4. 加減天數、月數、年數

原生寫法

加減天數直接 +／-。加減月數比較麻煩：1 月 31 日加一個月不存在 2 月 31 日，業界慣例是截到該月月底（2 月 28 或 29 日）。下面的 add_months 就是這個規則，年數等於月數乘 12。

CLASS lcl_date_calc DEFINITION FINAL.
  PUBLIC SECTION.
    CLASS-METHODS add_months IMPORTING iv_date        TYPE d
                                       iv_months      TYPE i
                             RETURNING VALUE(rv_date) TYPE d.
    CLASS-METHODS add_years  IMPORTING iv_date        TYPE d
                                       iv_years       TYPE i
                             RETURNING VALUE(rv_date) TYPE d.
ENDCLASS.

CLASS lcl_date_calc IMPLEMENTATION.
  METHOD add_months.
    " 換成「從西元 0 年起算的第幾個月」，加減後再拆回年、月
    DATA(lv_total) = CONV i( iv_date+0(4) ) * 12 + CONV i( iv_date+4(2) ) - 1 + iv_months.
    DATA(lv_year)  = lv_total DIV 12.
    DATA(lv_month) = lv_total MOD 12 + 1.

    DATA lv_first TYPE d.
    lv_first = |{ lv_year WIDTH = 4 ALIGN = RIGHT PAD = '0' }{ lv_month WIDTH = 2 ALIGN = RIGHT PAD = '0' }01|.

    " 目標月的月底
    DATA lv_last TYPE d.
    lv_last = lv_first + 31.
    lv_last+6(2) = '01'.
    lv_last = lv_last - 1.

    " 原日期的「日」超過目標月天數時，截到月底
    DATA(lv_day) = nmin( val1 = CONV i( iv_date+6(2) )
                         val2 = CONV i( lv_last+6(2) ) ).
    rv_date = lv_first + lv_day - 1.
  ENDMETHOD.

  METHOD add_years.
    rv_date = add_months( iv_date = iv_date iv_months = iv_years * 12 ).
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  DATA(lv_base) = CONV d( '20240131' ).
  cl_demo_output=>write( |+1 月 { lcl_date_calc=>add_months( iv_date = lv_base iv_months = 1 ) DATE = ISO }| ).  " 2024-02-29
  cl_demo_output=>write( |-3 月 { lcl_date_calc=>add_months( iv_date = lv_base iv_months = -3 ) DATE = ISO }| ). " 2023-10-31
  cl_demo_output=>write( |+1 年 { lcl_date_calc=>add_years( iv_date = lv_base iv_years = 1 ) DATE = ISO }| ).    " 2025-01-31
  cl_demo_output=>display( ).

函數：FIMA_DATE_CREATE（FI 版本，可同時加年月日並指定月底規則）

一次加上年、月、日，數值可以是負數表示往前。i_set_last_day_of_month = 'X' 時回傳結果所在月份的最後一天。素材範例：20140101 加 2 年、1 個月、23 天，再加 10 個日曆天，並設定取月底，回傳 e_date = 2016.03.31、e_flg_end_of_month = X、e_days_of_i_date = 24。

DATA lv_start TYPE vtbbewe-dvalut VALUE '20140101'.
DATA lv_date  TYPE vtbbewe-dvalut.
DATA lv_flag  TYPE trff_flg.
DATA lv_days  TYPE trff_type_n_2.

CALL FUNCTION 'FIMA_DATE_CREATE'
  EXPORTING
    i_date                  = lv_start
    i_flg_end_of_month      = ' '
    i_years                 = 2               " 加 2 年（負數表示往前）
    i_months                = 1               " 加 1 個月
    i_days                  = 23              " 加 23 天
    i_calendar_days         = 10              " 再加 10 個日曆天
    i_set_last_day_of_month = 'X'             " 結果取該月最後一天
  IMPORTING
    e_date                  = lv_date         " 2016.03.31
    e_flg_end_of_month      = lv_flag         " 設了 i_set_last_day_of_month 就回傳 X
    e_days_of_i_date        = lv_days.        " 素材輸出 24

函數：CCM_GO_BACK_MONTHS、MONTH_PLUS_DETERMINE

只處理月份的兩個函數：前者往前推 N 個月（20140101 往前 3 個月 → 20131001），後者往後推 N 個月（20140101 往後 3 個月 → 20140401；月數給負數也可以往前）。

DATA lv_base TYPE d VALUE '20140101'.
DATA lv_new  TYPE d.

CALL FUNCTION 'CCM_GO_BACK_MONTHS'
  EXPORTING
    currdate   = lv_base
    backmonths = 3                            " 往前幾個月
  IMPORTING
    newdate    = lv_new.                      " 20131001

CALL FUNCTION 'MONTH_PLUS_DETERMINE'
  EXPORTING
    months  = 3                               " 往後幾個月（可為負）
    olddate = lv_base
  IMPORTING
    newdate = lv_new.                         " 20140401

5. 兩日期間隔與比較

原生寫法

天數直接相減；月數用「年×12＋月」相減；日期大小直接用 <、=、> 比較。含時間的間隔用時間戳記相減（第 10 節）。

DATA(lv_from) = CONV d( '20130101' ).
DATA(lv_to)   = CONV d( '20141001' ).

DATA(lv_days)   = lv_to - lv_from.                                     " 638 天
DATA(lv_months) = ( CONV i( lv_to+0(4) ) * 12 + CONV i( lv_to+4(2) ) )
                - ( CONV i( lv_from+0(4) ) * 12 + CONV i( lv_from+4(2) ) ).   " 21 個月（只看年月）
DATA(lv_full_months) = COND i( WHEN lv_to+6(2) < lv_from+6(2) THEN lv_months - 1
                               ELSE lv_months ).                         " 滿月數

DATA(lv_relation) = COND string( WHEN lv_from < lv_to THEN 'LT'
                                  WHEN lv_from = lv_to THEN 'EQ'
                                  ELSE 'GT' ).

" 帳齡分組：用 COND 把天數分桶
DATA(lv_bucket) = COND string( WHEN lv_days <= 30 THEN '0-30'
                                WHEN lv_days <= 60 THEN '31-60'
                                WHEN lv_days <= 90 THEN '61-90'
                                ELSE '90+' ).

cl_demo_output=>write( |{ lv_days } 天、{ lv_months } 個月（滿 { lv_full_months } 個月）、{ lv_relation }、帳齡 { lv_bucket }| ).
cl_demo_output=>display( ).

函數：FIMA_DAYS_AND_MONTHS_AND_YEARS

同一組日期有兩種算法，差別在 i_flg_separate：空白時三個輸出各自是「總天數、總月數、總年數」；'X' 時是「幾年又幾個月又幾天」的拆解。素材範例（20130101 到 20141001）：空白回傳 638 天、21 個月、2 年；'X' 回傳 0 天、9 個月、1 年，也就是 1 年 9 個月整。

7. 週次：ISO 週與週起始日

「第幾週」有兩套規則，報表要先跟使用者講好：

  • ISO 8601（SAP 預設）：週一開始；包含該年第一個星期四的那一週是第 1 週。所以 2014-01-01（星期三）屬於 2014 年第 1 週，而該週的週一是 2013-12-30；反過來，某些年的 12 月底會屬於下一年的第 1 週。週次格式是 YYYYWW（型別 SCAL-WEEK）。
  • 週日起始（美式、部分 HR 報表）：HR_GBSSP_GET_WEEK_DATES 就是這一套，同一天算出來的週次可能和 ISO 差一週。

原生寫法：ISO 週次演算法

DATA(lv_date) = CONV d( '20140101' ).

DATA(lv_wotnr) = ( lv_date - CONV d( '19000101' ) ) MOD 7 + 1.   " 1 = 週一

DATA lv_monday   TYPE d.
DATA lv_sunday   TYPE d.
DATA lv_thursday TYPE d.
lv_monday   = lv_date - lv_wotnr + 1.         " 該週週一：2013-12-30
lv_sunday   = lv_monday + 6.                  " 該週週日：2014-01-05
lv_thursday = lv_monday + 3.                  " ISO：週四落在哪一年，這週就屬於哪一年

DATA lv_jan1 TYPE d.
lv_jan1 = |{ lv_thursday+0(4) }0101|.
DATA(lv_week_no) = ( lv_thursday - lv_jan1 ) DIV 7 + 1.

DATA(lv_week) = |{ lv_thursday+0(4) }{ lv_week_no WIDTH = 2 ALIGN = RIGHT PAD = '0' }|.   " 201401

cl_demo_output=>display( |週次 { lv_week }，{ lv_monday DATE = ISO } ～ { lv_sunday DATE = ISO }| ).

8. 工廠日曆、假日與工作天

「交期加 5 個工作天」「本月有幾個工作天」不能用日曆天算，要查工廠日曆（SCAL 維護）。架構是：假日日曆（國定假日，表 THOL 等）指派給工廠日曆（定義哪幾個星期幾上班，表 TFACD），工廠日曆再指派給工廠（T001W-FABKL）。工廠日曆會編好每一個工作天的序號（工廠日期，factory date），序號相減就是工作天數。

工廠日曆有有效年度範圍：TFACD 定義了日曆的起訖年，超出範圍時函數會拋 date_after_range／date_before_range。每年年底都要有人去 SCAL 把明年的假日補上並延長年度，否則一月初所有算交期的程式同時出錯，這是真實會發生的事故。S/4HANA 較新版本另提供 Fiori 的工廠日曆維護與新的日曆 API，1809 以 SCAL 為主，實際可用的工具請依系統版本確認。

函數：DATE_CONVERT_TO_FACTORYDATE ＋ FACTORYDATE_CONVERT_TO_DATE（加減工作天）

素材範例：日曆 'ZS'、日期 20140101（元旦）、correct_option = '+'。因為當天不是工作天，函數往後找到 20140102，factorydate 回傳工廠日期序號 1531，workingday_indicator 回傳 '+'。

  • correct_option：輸入日期不是工作天時往哪裡找，'+' 往後找下一個工作天，'-' 往前找上一個。
  • workingday_indicator：空白表示輸入日本來就是工作天；'+' 或 '-' 表示輸入日不是工作天，已依 correct_option 修正。素材把 '+' 解釋成「工作日計算方式」並不精確。

9. 時間與 12／24 小時制

時間型別 t 內部永遠是 24 小時制 HHMMSS。12 小時制只是「顯示格式」：字串範本的 TIME = USER 會依使用者設定（SU01 的時間格式）顯示成 24 小時制或 AM／PM。

DATA(lv_t) = CONV t( '190000' ).

" 24 → 12 小時制（原生）
DATA(lv_hour24) = CONV i( lv_t+0(2) ).
DATA(lv_ampm)   = COND string( WHEN lv_hour24 < 12 THEN 'AM' ELSE 'PM' ).
DATA(lv_hour12) = COND i( WHEN lv_hour24 = 0  THEN 12
                          WHEN lv_hour24 > 12 THEN lv_hour24 - 12
                          ELSE lv_hour24 ).
DATA(lv_text12) = |{ lv_hour12 WIDTH = 2 ALIGN = RIGHT PAD = '0' }:{ lv_t+2(2) }:{ lv_t+4(2) } { lv_ampm }|.  " 07:00:00 PM

" 12 → 24 小時制（原生）：輸入 06:00:00 PM
DATA(lv_in)    = CONV t( '060000' ).
DATA(lv_in_pm) = abap_true.
DATA lv_out TYPE t.
lv_out = COND #( WHEN lv_in_pm = abap_true  AND lv_in+0(2) <> '12' THEN lv_in + 12 * 3600
                 WHEN lv_in_pm = abap_false AND lv_in+0(2) =  '12' THEN lv_in - 12 * 3600
                 ELSE lv_in ).                                                     " 180000

cl_demo_output=>write( |{ lv_t TIME = ISO } = { lv_text12 }；06:00 PM = { lv_out TIME = ISO }；使用者格式 { lv_out TIME = USER }| ).
cl_demo_output=>display( ).

CL_ABAP_TSTMP：時間戳記的加減與相減

時間戳記是「看起來像日期的數字」，不能直接加 3600 當作加一小時（083000 加 3600 會變成 086600，不是合法時間）。一律用 CL_ABAP_TSTMP：

DATA lv_start TYPE timestampl.
GET TIME STAMP FIELD lv_start.

TRY.
    " 加減秒數（負數往前）
    DATA(lv_plus_90min) = cl_abap_tstmp=>add( tstmp = lv_start secs = 90 * 60 ).
    DATA(lv_minus_1day) = cl_abap_tstmp=>subtractsecs( tstmp = lv_start secs = 86400 ).

    " 兩個時間戳記相差幾秒
    DATA(lv_secs) = cl_abap_tstmp=>subtract( tstmp1 = lv_plus_90min tstmp2 = lv_start ).   " 5400

    " 日期＋時間直接加秒數（跨日自動進位，取代 t 型別的折回問題）
    DATA lv_res_date TYPE d.
    DATA lv_res_time TYPE t.
    cl_abap_tstmp=>td_add( EXPORTING date     = CONV d( '20141231' )
                                     time     = CONV t( '230000' )
                                     secs     = 2 * 3600
                           IMPORTING res_date = lv_res_date          " 20150101
                                     res_time = lv_res_time ).       " 010000

    " 系統時區的日期時間 → UTC 時間戳記（舊 Z 表只存 sy-datum／sy-uzeit 時用）
    DATA lv_utc TYPE timestamp.
    cl_abap_tstmp=>systemtstmp_syst2utc( EXPORTING syst_date = sy-datum
                                                  syst_time = sy-uzeit
                                        IMPORTING utc_tstmp = lv_utc ).

    cl_demo_output=>display( |差 { lv_secs } 秒；跨年結果 { lv_res_date DATE = ISO } { lv_res_time TIME = ISO }| ).
  CATCH cx_parameter_invalid_range cx_parameter_invalid_type INTO DATA(lx_ts).
    MESSAGE lx_ts->get_text( ) TYPE 'E'.
ENDTRY.

12. 日期格式與使用者設定：內部 ↔ 外部

日期在資料庫與變數裡永遠是 內部格式 YYYYMMDD；畫面、Excel、列印看到的是 外部格式，由每個使用者自己的設定決定（SU01／SU3 → 預設值 → 日期格式，存在 USR01-DATFM）。常見值：1＝DD.MM.YYYY、2＝MM/DD/YYYY、3＝MM-DD-YYYY、4＝YYYY.MM.DD、5＝YYYY/MM/DD、6＝YYYY-MM-DD，另有日本年號與伊斯蘭曆等格式。

13. 民國年（作業二解答）

作業二：將今天的日期顯示成民國年，例如「1110315」（民國 111 年 3 月 15 日＝2022-03-15）。規則：民國年＝西元年－1911，格式通常是 7 碼 YYYMMDD（民國 99 年以前補 0 成 3 碼，例如 0991231）。以本書寫作日 2026-09-26 為例，結果是 1150926。

解法一：字串範本（推薦）

REPORT z00_roc_date.

CLASS lcl_roc DEFINITION FINAL.
  PUBLIC SECTION.
    "! 西元 YYYYMMDD → 民國 YYYMMDD
    CLASS-METHODS to_roc   IMPORTING iv_date       TYPE d
                           RETURNING VALUE(rv_roc) TYPE string.
    "! 民國 YYYMMDD（或 YYMMDD）→ 西元日期
    CLASS-METHODS from_roc IMPORTING iv_roc         TYPE csequence
                           RETURNING VALUE(rv_date) TYPE d.
ENDCLASS.

CLASS lcl_roc IMPLEMENTATION.
  METHOD to_roc.
    IF iv_date IS INITIAL.
      RETURN.
    ENDIF.
    DATA(lv_roc_year) = CONV i( iv_date+0(4) ) - 1911.
    rv_roc = |{ lv_roc_year WIDTH = 3 ALIGN = RIGHT PAD = '0' }{ iv_date+4(4) }|.
  ENDMETHOD.

  METHOD from_roc.
    " 先補成 7 碼，相容 6 碼的舊資料（例如 991231）
    DATA(lv_roc) = |{ condense( val = iv_roc ) WIDTH = 7 ALIGN = RIGHT PAD = '0' }|.
    rv_date = |{ CONV i( lv_roc+0(3) ) + 1911 }{ lv_roc+3(4) }|.
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  DATA(lv_today) = sy-datlo.                  " 用使用者當地日期，不用 sy-datum
  DATA(lv_roc)   = lcl_roc=>to_roc( lv_today ).

  DATA(lv_back)  = lcl_roc=>from_roc( '1110315' ).                   " 20220315
  " 報表常見的「民國 115 年 09 月 26 日」
  DATA(lv_long)  = |民國 { CONV i( lv_roc+0(3) ) } 年 { lv_today+4(2) } 月 { lv_today+6(2) } 日|.

  WRITE: / '今天（西元）：', lv_today,
         / '今天（民國）：', lv_roc,                                          " 例：1150926
         / '民國 1110315 =', lv_back,
         / lv_long.

解法二：CONVERSION_EXIT（轉換常式）

SAP 標準沒有民國年的日期轉換常式（USR01-DATFM 也沒有民國年選項），所以做法是自建轉換常式 ZROCD：在函數群組裡建立兩個固定命名的函數 CONVERSION_EXIT_ZROCD_OUTPUT（內部 → 外部）與 CONVERSION_EXIT_ZROCD_INPUT（外部 → 內部），介面固定是 IMPORTING VALUE(INPUT)、EXPORTING VALUE(OUTPUT)。之後三種用法都會自動套用：

  1. 直接 CALL FUNCTION。
  2. WRITE ... USING EDIT MASK '==ZROCD'（兩個等號＋常式名）。
  3. 在 SE11 建一個網域（型別 DATS 長度 8），轉換常式欄填 ZROCD，資料元素參照它；凡是用這個資料元素的欄位，在選擇畫面、Dynpro、WRITE TO 都會自動顯示民國年。
FUNCTION conversion_exit_zrocd_output.
*"----------------------------------------------------------------------
*"  IMPORTING
*"     VALUE(INPUT)
*"  EXPORTING
*"     VALUE(OUTPUT)
*"----------------------------------------------------------------------
  DATA lv_date TYPE d.
  lv_date = input.
  IF lv_date IS INITIAL.
    CLEAR output.
    RETURN.
  ENDIF.
  DATA(lv_roc_year) = CONV i( lv_date+0(4) ) - 1911.
  output = |{ lv_roc_year WIDTH = 3 ALIGN = RIGHT PAD = '0' }{ lv_date+4(4) }|.
ENDFUNCTION.

FUNCTION conversion_exit_zrocd_input.
*"----------------------------------------------------------------------
*"  IMPORTING
*"     VALUE(INPUT)
*"  EXPORTING
*"     VALUE(OUTPUT)
*"----------------------------------------------------------------------
  DATA(lv_roc) = |{ condense( val = CONV string( input ) ) WIDTH = 7 ALIGN = RIGHT PAD = '0' }|.
  IF lv_roc CO '0'.
    CLEAR output.
    RETURN.
  ENDIF.
  DATA lv_date TYPE d.
  lv_date = |{ CONV i( lv_roc+0(3) ) + 1911 }{ lv_roc+3(4) }|.
  output = lv_date.
ENDFUNCTION.
REPORT z00_roc_date_exit.

DATA lv_roc TYPE c LENGTH 7.

" 用法 1：直接呼叫轉換常式
CALL FUNCTION 'CONVERSION_EXIT_ZROCD_OUTPUT'
  EXPORTING
    input  = sy-datlo
  IMPORTING
    output = lv_roc.
WRITE: / '民國（CALL FUNCTION）：', lv_roc.

" 用法 2：WRITE ... USING EDIT MASK 自動呼叫 CONVERSION_EXIT_ZROCD_OUTPUT
DATA lv_text TYPE c LENGTH 10.
WRITE sy-datlo TO lv_text USING EDIT MASK '==ZROCD'.
WRITE: / '民國（EDIT MASK）：', lv_text.

" 反向：民國 → 西元

CALL FUNCTION 'CONVERSION_EXIT_ZROCD_INPUT'
  EXPORTING
    input  = '1110315'
  IMPORTING

標準的日期轉換常式：SAP 本身也有日期類的 CONVERSION_EXIT，例如 TCURR 匯率表的 GDATU 用的 INVDT（反向日期，見第 16 節）、以及以月份縮寫顯示日期的 IDATE、SDATE 等；它們的輸出格式請以 SE37 測試為準。字串範本只支援 ALPHA 這種內建格式，不會自動呼叫轉換常式，要套用轉換常式就用 WRITE ... TO 或直接 CALL FUNCTION。
民國年的兩個坑：(1) 民國 100 年前後，舊系統常把民國年存成 2 碼或 6 碼字串（991231），和 7 碼（1000101）混在一起時字串比較會出錯（'991231' 大於 '1000101'），請先統一補成 7 碼；(2) 民國日期存成 CHAR 欄位後就不能再用日期算術，資料庫一律存西元 DATS，民國年只在輸出時轉換。

17. 陷阱總整理：時區、使用者格式、背景作業、BT 區間

(1) 時區：sy-datum 不等於使用者的今天

sy-datum 是系統時區的日期，sy-datlo 才是使用者時區（sy-zonlo）的日期。雲端或海外主機的系統時區常是 UTC：台灣早上 7 點（UTC 前一天 23 點）用 sy-datum 當過帳日，會過到昨天；月初第一天早上跑月報，還會抓到上個月。

" 系統時區
SELECT SINGLE tzonesys FROM ttzcu INTO @DATA(lv_sys_tz).

cl_demo_output=>write( |系統時區 { lv_sys_tz }：{ sy-datum DATE = ISO } { sy-uzeit TIME = ISO }| ).
cl_demo_output=>write( |使用者時區 { sy-zonlo }：{ sy-datlo DATE = ISO } { sy-timlo TIME = ISO }| ).

" 使用者沒維護時區時 sy-zonlo 是空白；CONVERT 的 TIME ZONE 為空白時會當成 UTC 處理
DATA(lv_tz) = COND tznzone( WHEN sy-zonlo IS NOT INITIAL THEN sy-zonlo ELSE lv_sys_tz ).

時區檢查清單：(1) 給人看的日期、畫面預設值、過帳日期用 sy-datlo；(2) 存檔的建立時間用 UTC 時間戳記（GET TIME STAMP）；(3) TIME ZONE 參數給空白等於 UTC，不是「系統時區」；(4) SU01 預設值頁籤要維護使用者時區，否則 sy-zonlo 為空；(5) 夏令時間地區的「凌晨 2:30」可能不存在或出現兩次，CONVERT DATE 要檢查 sy-subrc。

(2) 使用者日期格式

凡是「字串 → 日期」的地方（上傳 Excel／CSV、外部介面、Z 表的 CHAR 日期欄位）都不要依賴執行者的日期格式；見第 12 節。反過來，下載給外部系統的檔案也不要用 DATE = USER，否則換個人下載，格式就變了。對外一律 ISO 或 YYYYMMDD。

(3) 背景作業的日期

背景作業（SM36／SM37）裡的 sy-datum／sy-datlo 是執行當下的日期；sy-zonlo 是作業步驟使用者的時區。常見事故：

  • 變式存了固定日期：PARAMETERS p_date DEFAULT sy-datum 在前景每次都是今天，但存成變式後，日期就固定成存檔那天，每天的排程都在跑同一天。解法：變式屬性裡把欄位設為「選擇變數」，類型 D（動態日期計算，例如「今天」「上個月的第一天到最後一天」），或類型 T（讀 STVARV 維護的 TVARVC 變數）。
  • 跨午夜：23:50 開始的作業跑到隔天 00:10，程式中段再讀 sy-datum 會拿到不同日期。開頭取一次存進變數，全程用同一個值。
  • 時區不同：作業步驟使用者（常是系統帳號）若沒維護時區或時區和業務單位不同，sy-datlo 會和使用者預期不一樣。
REPORT z_daily_job.

PARAMETERS p_date TYPE d.                     " 空白＝昨天；變式可設選擇變數

START-OF-SELECTION.

(4) BT 區間的陷阱

Casper 的原則：條件用列舉（多筆 EQ）比用區間（BT）安全，因為區間比的是字典序不是業務語意。內部格式的 DATS 欄位，字典序剛好等於時間順序，所以 budat BETWEEN 月初 AND 月底 是安全的；但下面這些情況會出事：

  • 時間戳記欄位配日期上限：ts BETWEEN 20140101000000 AND 20140131000000 會漏掉 1 月 31 日整天。改用「半開區間」：ts >= 起日 00:00 AND ts < 迄日隔天 00:00，而且兩端都要先轉成 UTC。
  • CHAR 欄位存外部格式日期（MM/DD/YYYY、DD.MM.YYYY）：字典序和時間順序無關，BT 一定抓錯。
  • 民國年字串長度不一：'991231' 在字典序上大於 '1000101'。
  • 寫死月底 31 號：|{ lv_ym }31| 在 2 月、4 月是無效日期，要用第 3 節的方法算月底。
  • 會計期間不連續：特別期間 13～16、會計年度跨曆年時，期間 BT 常常多抓或漏抓；要列舉的期間用 EQ 一筆一筆列。

            p_to   TYPE d DEFAULT '20140131'.

" ... WHERE changed_at >= @lv_ts_from AND changed_at < @lv_ts_to

" 2) 會計期間：列舉（EQ）而不是區間（BT）
TYPES ty_poper_range TYPE RANGE OF poper.
DATA(lt_periods) = VALUE ty_poper_range( FOR p = 1 UNTIL p > 12
                                         ( sign = 'I' option = 'EQ' low = CONV poper( p ) ) ).

" 3) 月份清單：把期間內每個月列舉出來（例如逐月查 MARDH、S 表等以年月為鍵的表）
