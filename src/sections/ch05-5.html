2. SAP 為何用 Eclipse：ADT 的定位與好處

ADT（ABAP Development Tools，早期也叫 ABAP in Eclipse）是在開放的 Eclipse 平台上加一組 SAP 外掛（plug-in），後端仍然是 AS ABAP。講義 Figure 1 的架構：Eclipse 用戶端透過 RFC／REST 通訊協定連到 ABAP 後端，Repository 的存取方式和 SE80 等傳統 ABAP Workbench 完全相同（p13）。

講義列出的三大好處（p11–12）：

  • 全新的 ABAP 開發體驗：建立在 Eclipse 平台上。
  • 開放的工具平台：可以在上面開發新的 ABAP 相關工具。
  • 一組開放、與語言／平台無關的 API（ADT 的 REST 服務），開發人員可以用它做自己的工具。

生產力的來源：更好的重構、程式碼補全、自動插入（auto-insertion）、程式碼範本、非常好用的 Quick Fix，以及到處都能跳轉的導覽能力。另外，ADT 可以同時連多套 ABAP 系統，也有 session failover，斷線的影響比較小。ADT 還能和 SAP HANA Studio、SAPUI5 工具裝在同一個 IDE 裡做跨平台開發。

講義的測驗第 1 題：「Eclipse 是 SAP 開發的專有工具」，答案是錯，因為 Eclipse 是開源平台，SAP 只提供外掛。第 2 題問 SAP 對 Eclipse 的態度，答案是 A：Eclipse 是 SAP 開發工具策略的重要部分。到了 S/4HANA，這個「重要」已經變成「必要」：CDS、AMDP、RAP 在 SAP GUI 裡都沒有編輯器。

4. ABAP 專案、線上開發模型、偏好設定與我的最愛套件

4.1 ABAP 專案＝一次登入

ADT 和 ABAP Workbench 一樣採用線上開發模型（online development model）：打開 Eclipse 後必須先登入 SAP 系統，才能看或改任何物件。每一個登入 session（由系統＋用戶端＋使用者識別）在 ADT 裡就是一個 ABAP Project（p17）。

建立方式：File → New → ABAP Project → Browse 選 SAP Logon 裡的系統 → Next → 輸入 Client、User、Logon Language、Password → Finish。之後這個專案會一直留在你的 workspace 裡。

ABAP 專案的內容（p19）：

  • 專案名稱（預設 <SID>_<Client>_<User>_<Lang>）。
  • 系統資料：System ID、Client、User、Password。
  • 預設語言：這決定新建物件的原始語言，也決定訊息與 UI 文字的語言。
  • （選填）當作我的最愛顯示的套件清單。
登入語言就是物件的原始語言。用 EN 登入建立的資料元素，原始語言就是 EN，之後中文標籤只能靠翻譯（SE63）。Casper 的專案一律先約定好「開發一律用某一種語言登入」，不要一下 ZF、一下 EN。

4.2 線上開發模型 vs. 分散式開發

Java 開發者用 SAP NetWeaver Developer Studio 時，每個人本機都有自己的 runtime 與開發環境，最後才合併到中央系統。ADT 不是這樣（p18–19）：

  • 物件只存在後端。用戶端只有一個小小的唯讀快取，用來提升效能、降低伺服器負載。
  • 開啟物件編輯時，後端會對該物件設 enqueue 鎖，並取回最新版本；存檔或啟用時，變更直接寫回後端。
  • 沒有 check-out／check-in，也不用建本機副本。
  • 語法檢查、搜尋、where-used 全都在後端執行。
  • 用戶端沒有 ABAP runtime，所以不支援離線作業。

4.3 一個 workspace 可以有多個專案

一個 Eclipse workspace 可以同時放 DEV、QAS、PRD 的 ABAP 專案，一個 IDE session 就能跨系統工作。最常用的情境是比較同一支程式在開發系統和正式系統的版本（第 16 節的 Compare With）。Eclipse 本身由 plug-in 組成，一個 Eclipse 用戶端可以連不同版本的多個後端（p20）。

4.5 我的最愛套件

SE80 的 Object Navigator 可以選物件類型、輸入名稱，直接把任何程式或類別顯示在導覽區。ADT 的 Project Explorer 不能這樣做（要開任意物件請用第 15 節的 Ctrl + Shift + A）。常用的套件可以加進 Favorite Packages：展開專案節點 → 在 Favorite Packages 上按右鍵 → Add a Package → 用搜尋對話框找套件（p22–23）。講義也提到，7.52 起樹狀結構可以更有彈性地重組（Project Explorer 的 tree configuration）。套件與傳輸的觀念請回顧 1-1 章。

5. Eclipse Workbench：透視圖、編輯器、檢視、Trim Stack、Quick Access

Workbench 指的是 Eclipse 的整個桌面開發環境。一個 Workbench 視窗包含一或多個透視圖（Perspective），透視圖裡有編輯器（Editor）和檢視（View）。桌面上可以同時開多個 Workbench 視窗，例如一個跑 ADT、一個跑 HANA Studio（p25–26）。

5.1 透視圖

透視圖決定初始要開哪些 view、怎麼排，也決定某些選單和工具列要顯示哪些動作。你自訂之後可以另存。ADT 提供三個透視圖：

透視圖用途
ABAP（最重要）一般開發。必須連著 ABAP 專案；可以同時使用 Eclipse 型與 SAP GUI 型工具
Debug碰到中斷點時自動切換（第 8 節）
ABAP Profiling效能分析（第 19 節）

ABAP 透視圖預設的 view：Project Explorer、Outline、Task Repositories、Task List、Problems、Templates、Properties、Feed Reader、Transport Organizer（p26–27）。

測驗第 6 題「哪些是 ADT 的透視圖？」答案是 A ABAP、C Debug。Transport Organizer 是 view，Package 不是透視圖。這題很容易被 Transport Organizer 騙。

5.2 編輯器

  • 不同類型的物件有不同的編輯器，開啟物件時會自動選對應的編輯器。沒有原生編輯器的物件，會在編輯區裡開 SAP GUI。
  • 可以同時開很多個編輯器，但同一時間只有一個是作用中（active）；主選單和工具列只顯示對作用中編輯器有效的動作。
  • 頁籤上出現 * 表示有未存檔的變更。
  • 左邊界的圖示會標出語法錯誤、書籤、中斷點、task；滑鼠移上去可以看細節。
  • 拖曳頁籤可以左右或上下並排（出現綠框時放開）。編輯器不能拖進 view 區；最小化時整個編輯區會縮成 trim stack。
講義此處已過時。p27 寫「Eclipse Workbench 沒有結構與資料表等 ABAP Dictionary 物件的編輯器，雙擊會開 SAP GUI」。這是很早期的說法，同一本講義的 Unit 4 就自相矛盾：7.50 起資料元素和結構已有 ADT 原生編輯器，7.52 起資料庫資料表也有原始碼式編輯器（第 10 節）。S/4HANA 1809 以上請直接在 ADT 裡維護。

5.3 View、Trim Stack、Quick View、Pin、Quick Access

  • View：輔助編輯器並提供導覽，例如 Project Explorer 顯示專案階層。每個 view 有自己的選單（標題列的三角形）和工具列。View 可以單獨出現，也可以疊成頁籤群組；拖到透視圖外會變成獨立視窗，拖回來就還原。View 不能拖進編輯區。
  • Trim Stack：頁籤群組最小化後，在視窗邊緣出現的小工具列。點裡面的圖示，view 會以覆蓋（overlay）方式暫時顯示；按 Restore 回到原位。
  • Quick View（Quick Outline）：在編輯器按 Ctrl + O，會在原地彈出目前物件的大綱；再按一次 Ctrl + O，會連同所有父類別與實作介面的元件一起顯示（只適用於類別）。直接打字就能過濾。
  • Pin 住 View：工具列有 Pin 圖示的 view（例如 Search、Properties）可以固定住，再開一個新實例並排比較。
  • Quick Access（右上角，新版為 Ctrl + 3）：輸入 view、指令、偏好設定頁的名稱，直接開啟。

6. 建立儲存庫物件、語法檢查與啟用、SAP GUI 整合、傳輸

6.1 Repository 物件

Repository 包含所有 ABAP 開發物件：程式、函數模組、資料表定義等等，有 SAP 交付的，也有客戶自建的。「repository object」和「development object」兩個詞常常混用。建立時一定要指派套件，除非是不傳輸的本機物件（$TMP）。有些物件有子物件（函數模組屬於函數群組），物件之間也會互相參照（p37）。

在 ADT 可以建立與編輯的物件：ABAP 程式、ABAP Dictionary 物件（資料表定義、資料型別）、Screen、Web Dynpro 元件、函數群組與函數模組、ABAP 類別與介面。其中一部分是 Eclipse 原生工具，另一部分仍然在 SAP GUI 裡編輯（p38）。

建立方式：在套件上按右鍵 → New → ABAP Program／ABAP Class…；或用 Ctrl + N（File → New → Other → ABAP Repository Object），在過濾欄打字篩選物件類型。

6.2 兩個最基本的動作：檢查與啟用

6.3 Eclipse 型工具與 SAP GUI 型工具

ADT 整合了兩種工具（p39）：

  • Eclipse 型：各種 ABAP 原始碼編輯器、Outline、Tasks、Problems view。外觀和導覽方式一致。
  • SAP GUI 型：SAP GUI 和 Eclipse 用戶端一起裝在本機，泛指傳統 ABAP Workbench 的工具，例如 Package Builder、部分 ABAP Dictionary、文字元素（text elements）維護。

在 Project Explorer 開啟物件時，有 Eclipse 編輯器就用它，沒有就在編輯區開 SAP GUI；每個 SAP GUI 物件各佔一個頁籤。在 SAP GUI 頁籤裡可以輸入任何 TCODE 或 OK code，功能和傳統 Workbench 完全一樣。想單獨開一個 SAP GUI（例如改使用者設定）：按 Ctrl + 6 或工具列的 Open SAP GUI 按鈕 → 選 ABAP 專案 → OK。

測驗題「ADT 對哪些物件有原生 Eclipse 編輯器？」講義答案是 A ABAP 程式、B 資料元素、C ABAP 類別。在講義那個版本，套件（Package Builder）和文字元素仍走 SAP GUI。新版 ADT 已經陸續補上套件、訊息類別、文字元素等編輯器，實際以你的後端版本為準。

  • 建立、修改、刪除 request；變更 request 的擁有者。
  • 執行一致性檢查；釋放 request 與 task。
  • 需要進階功能時，雙擊 request 或 task 會在 Eclipse 裡開 SAP GUI 版的 Transport Organizer。

9. 函數群組與函數模組：原始碼式函數編輯器

SAP GUI 的 Function Builder（SE37）是表單式的：Import、Export、Changing、Tables、Exceptions、Source code 各一個頁籤。ADT 的函數編輯器則把整個函數模組當成一個原始碼單元，上半部是定義、下半部是實作，並搭配 Outline view 與 Quick Outline 導覽（p57）。

建立步驟（（依講義步驟整理））：在套件上按右鍵 → New → ABAP Function Group（名稱如 ZBC404_FG）→ 在函數群組上按右鍵 → New → ABAP Function Module → 輸入名稱與說明 → 指定 request → Finish。

定義部分的規則（p57）：

  • 參數寫在 FUNCTION 敘述的 IMPORTING、EXPORTING、CHANGING、RAISING、EXCEPTIONS 附加項裡，用法和類別的 METHODS 一樣：參數之間用空白分隔，不加逗號。
  • 為了清楚起見，每個參數都必須指定型別。
  • 打開舊的函數模組時，若 IMPORTING／EXPORTING／CHANGING 參數當初沒有型別，編輯器會自動補上 TYPE ANY；沒有型別的 TABLES 參數會補上 TYPE STANDARD TABLE。
  • 定義部分不能寫註解，啟用後會消失。
  • 定義部分和實作部分之間可能出現空行：編輯器會把實作的第一行對齊到和 SE37 相同的行號，這關係到導覽、語法檢查和錯誤標記的位置（p58）。

10. ABAP Dictionary 物件：資料元素與結構編輯器

10.1 資料元素編輯器（後端 7.50 以上）

New → ABAP Repository Object → Dictionary → Data Element → 輸入套件、名稱（遵守命名規則）→ Next → 指定 request（本機物件免）。在編輯器裡（p63–64）：

  • Category：通常是 Domain，也可以是內建 Dictionary 型別、參照 Dictionary 型別，或參照物件型別（類別／介面）。
  • Domain 名稱可以用 Ctrl + Space 叫出值說明；想新建 Domain，點欄位標籤 Type Name（超連結）即可。
  • Field Labels：Short、Medium、Long、Heading，和 SAP GUI 相同。
  • Additional Properties：Search Help、Set/Get Parameter（PID），同樣點標籤就能新建。

10.2 結構編輯器（後端 7.50 以上）：用 DDL 寫結構

結構不再是表單，而是原始碼。它具備 SAP GUI 版的所有功能：元件可以參照資料元素、內建型別（CHAR、DEC、NUMC…）、參照型別、其他結構、內表型別；也可以定義外部鍵檢查、指派 search help。語意資訊（例如 enhancement category、外部鍵的語意）用 @ 開頭的 annotation 描述，一樣可以用 Ctrl + Space 補全（p65–66）。

語法規則：

  • 整個結構的 annotation 放在定義之前；單一元件的 annotation 放在該元件之前。
  • 元件寫成 名稱 : 型別;，每個元件以分號結尾，全部放在大括號內。
  • 內建型別用命名空間 abap.：abap.char(10)、abap.numc(8)；dec 要寫「位數,小數位」：abap.dec(15,2)。
  • 結構的兩個 annotation：@EndUserText.label（短文字）與 @AbapCatalog.enhancement.category，可選值有 #NOT_EXTENSIBLE、#EXTENSIBLE_CHARACTER、#EXTENSIBLE_CHARACTER_NUMERIC、#EXTENSIBLE_ANY。
  • 引入其他結構用 include，元件名稱必須唯一。
  • 外部鍵：with foreign key，必要元素是檢查表（例如 scarr）和 where 條件的鍵值對應；選填的基數寫在中括號裡，[0..*,1] 表示「欄位值可以出現任意次（或不出現），且對應檢查表的一筆」，這是預設值，也最常見；外部鍵類型用 annotation 指定：#KEY、#NON_KEY、#TEXT_KEY。
  • 值說明：有外部鍵的欄位自動會有值說明；其他欄位可以用 with value help 指派 search help，並用 where 把結構元件對應到 search help 參數，讓值說明只顯示符合已輸入值的選項。
  • CURR 欄位一定要連到 CUKY 欄位（用 @Semantics.amount.currencyCode），否則系統無法決定小數位數，會直接語法錯誤。QUAN／UNIT 同理，用 @Semantics.quantity.unitOfMeasure。

12. 全域類別：原始碼式類別編輯器、Quick Fix 與例外類別

12.1 原始碼式類別編輯器

Java、C++ 的 Eclipse 類別編輯器都是原始碼式的，ADT 也一樣。它不用 SAP GUI 表單式的 Class Builder（SE24），而是在一個編輯器裡顯示整個類別，再用 Outline、導覽功能和 Quick Fix 輔助（p79）。建立：套件右鍵 → New → ABAP Class → 輸入名稱（命名規則 [Z|Y]CL_）、說明、父類別（若有）→ 指定 request → Finish，編輯器會顯示產生好的骨架。

類別編輯器下方的頁籤（p80）：

頁籤內容
Global Class存在中央 Repository 類別庫的全域類別本體

Local Types全域類別沒有參照的區域定義（區域輔助類別等）

12.2 Outline view

在原始碼編輯器開啟類別時，ABAP 透視圖會同時開啟 Outline view，列出屬性、型別、方法等結構元素，概念類似 SE80 的物件清單。即使還沒存檔，Outline 也會和編輯器內容同步。右鍵選單的重點功能：Navigate to Declaration、Navigate to Implementation、Run As → ABAP Unit Test（選到測試方法時）（p81–83）。

12.3 Quick Fix（Ctrl + 1）

Quick Fix 是編輯器自動提出的快速修正，用來完成常見工作或修正錯誤（p83–84）。在類別中常見的有：

  • 為已宣告的方法新增實作（Add implementation）。
  • 一次新增所有尚未實作的方法（例如介面的全部方法）。
  • 把方法移到另一個可見性區段。
  • （新版 ADT 另有）從未宣告的變數直接產生宣告、把區域變數升級成屬性、把字面值抽成常數等等。
測驗題：在 PUBLIC SECTION 剛寫完方法定義後按 Ctrl + 1，可用的修正是 A 新增方法實作、B 把定義移到 protected 或 private 區段；Quick Fix 不提供「刪除方法」。實務上最常用的流程：先寫 METHODS 定義 → Ctrl + 1 → Enter，實作骨架就產生好了，不用再切去 IMPLEMENTATION 手打。

12.4 特殊類別與例外類別

在 SAP GUI 的 Class Builder 建立 ABAP Unit 測試類別或例外類別時，會自動產生額外的程式碼；在 ADT 裡，這些程式碼要用程式碼範本加入（p84）。

例外類別代表應用程式可能發生的錯誤，有些是 SAP 預先定義的系統例外（例如 CX_SY_ZERODIVIDE），有些是開發時自建的應用例外。自建例外類別的兩個特徵：

  • 是抽象類別 CX_STATIC_CHECK（或其他例外類別）的子類別；名稱前綴 [Z|Y]CX_。
  • 包含一或多段描述錯誤的文字。在 ADT 裡，這些文字必須是訊息類別（SE91）裡的訊息。SAP GUI 的 Class Builder 可以直接定義文字（OTR），ADT 不行。

做法：建立類別時父類別填 CX_STATIC_CHECK → 在 PUBLIC SECTION 用 Ctrl + Space 插入範本 textIdExceptionClass → 範本會產生一個結構常數，把它的元件改成你的訊息：

元件意義
msgid訊息類別
msgno訊息號碼
attr1 ～ attr4第 1～4 個佔位符（&1～&4），填的是例外類別屬性的名稱

之後在實例建構子裡，用這個常數取代預設的 IF_T100_MESSAGE=>DEFAULT_TEXTID（p85–86）。

13. 重構（Refactoring）：改名、抽取方法、刪除未使用變數

重整程式碼（讓它好懂、好擴充、更有效率）時，最怕連帶影響讓相依關係斷掉。重構工具可以省掉手動修補這些斷點的麻煩（p87）。講義列出的重構種類：

  • 改名（Rename）、抽取方法（Extract Method）、刪除未使用變數。
  • 把區域變數轉成類別屬性（讓所有方法都能用）；抽取常數取代字面值、抽取變數（7.40 以上）。
  • 把元件定義在 public／protected／private 之間移動，也就是變更可見性。
  • 實作尚未實作的方法。

13.1 改名（Alt + Shift + R）

可以找出並改名變數、方法、副程式等元素，連 ABAP 類別與介面本身都能改名；範圍可以只在單一原始碼內，也可以跨多個 Repository 物件。講義的例子：類別 ZCL_BC404_REFACTOR 的方法 METHODA，DEFINITION、IMPLEMENTATION 和呼叫它的程式 ZBC404_REFACTOR 三處都要改。選取名稱 → Alt + Shift + R → 輸入新名稱 → 精靈列出所有受影響的物件 → 可勾選改完自動啟用所有物件 → Finish（p87–89）。

13.2 抽取方法（Alt + Shift + M）

把一段程式搬到新方法，原處換成對新方法的呼叫。條件（p90）：

  • 必須在全域類別或區域類別中（class pool、程式或其他 ABAP 程式裡的類別）；類別以外的程式碼不支援，而且只能在另一個方法的 METHOD…ENDMETHOD 範圍內抽取。
  • 程式碼必須沒有語法錯誤。
  • 選取程式碼 → 右鍵 Source → Extract Method，或按 Alt + Shift + M。
" ── 抽取前：run 方法又長又雜 ──────────────────────────
METHOD run.
  SELECT carrid, connid, fldate, seatsmax, seatsocc
    FROM sflight
    WHERE carrid IN @mt_carrid_range
    ORDER BY carrid, connid, fldate
    INTO TABLE @DATA(lt_flights).
  " ↓ 選取這一段，按 Alt+Shift+M
  DATA(lv_total_free) = REDUCE i( INIT s = 0
                                  FOR ls IN lt_flights
                                  NEXT s = s + ls-seatsmax - ls-seatsocc ).
  " ↑
  display( lv_total_free ).
ENDMETHOD.

" ── 抽取後：ADT 自動產生方法定義、參數型別與呼叫 ────────

  SELECT carrid, connid, fldate, seatsmax, seatsocc
    FROM sflight
    WHERE carrid IN @mt_carrid_range
    ORDER BY carrid, connid, fldate
    INTO TABLE @DATA(lt_flights).
  DATA(lv_total_free) = calc_free_seats( lt_flights ).
  display( lv_total_free ).

METHOD calc_free_seats.            " PRIVATE SECTION 也一併產生了定義
  rv_total_free = REDUCE i( INIT s = 0
                            FOR ls IN it_flights
                            NEXT s = s + ls-seatsmax - ls-seatsocc ).
ENDMETHOD.

13.3 刪除未使用變數

未使用的變數會隨時間累積：程式刪了變數沒刪，或抽取方法後留下已不在範圍內的宣告。ADT 可以自動找出並刪除：方法、函數模組、副程式裡未使用的區域變數，以及類別、函數群組、報表裡未使用的全域變數。要先在編輯器開啟程式；刪除的地方都會加上標記，滑鼠移上去可以看刪了什麼。PUBLIC 與 PROTECTED SECTION 宣告的變數不會被刪，因為外部可能在用（p91）。

重構是 ADT 相對 SE80 最大的優勢之一。跨物件改名前，建議先按 Ctrl + Shift + G 看 where-used（第 15 節），確認影響範圍；改名時如果有物件被別人鎖住，精靈會失敗。也可以另外安裝 SAP 開源的 ABAP Cleaner 外掛，一鍵把舊語法整理成現代寫法（例如把 MOVE 改成 =、補上內嵌宣告），和 附錄 舊語法對照 搭配使用。

14. Web Dynpro 開發

ADT 提供 Web Dynpro ABAP 的原生開發環境：Project Explorer 看得到所有 Web Dynpro 設計期物件，可以建立元件、視窗、視圖、控制器，也可以在 Eclipse 裡啟用、執行、除錯。後端需 7.03／7.31 SP07 以上（p97）。相對於 SE80 的優點：

  • 真正的 WYSIWYG 視圖編輯器，比 SE80 更接近實際執行的畫面。
  • Eclipse 編輯器只在需要時才連後端，編輯更流暢。
  • Context mapping 更圖形化。
  • SE80 Wizard 的部分程式碼範本（讀寫 context）在 ADT 也有。

建立 Web Dynpro 元件（p98）：

  1. Project Explorer → ABAP 專案右鍵 → New → Other → ABAP Repository Object。
  2. 過濾欄輸入 web → 選 Web Dynpro → Component → Next。
  3. 輸入 Name、Description、Package；勾 Create Window 並輸入視窗名、勾 Create View 並輸入視圖名 → Next。
  4. 指定 request → Finish → Ctrl + F3 啟用。
  5. 元件出現在套件的 Web Dynpro → Web Dynpro Components 資料夾。

視圖編輯器（雙擊 view 開啟）：Layout 頁設計 UI，UI 元素顯示在 Outline view，可以新增、重排、刪除；屬性在 Properties view 修改，預覽區會即時更新。Methods 頁定義自訂方法、參數與 action。Action 是一種事件，由使用者操作觸發（按按鈕、選表格列），只存在於 view controller。建立 action 時，ADT 會自動產生事件處理方法 ONACTION<ACTION_NAME>；action 也可以在 UI 元素 Properties 的 Events 區建立。在 Methods 頁選方法按 F3 跳到實作；Implementation 頁只允許在 METHOD…ENDMETHOD 之間寫程式（p98–101）。

程式碼精靈：ADT 的選項不如 SE80 Web Dynpro Code Wizard 完整，但在 controller 方法的新行按 Ctrl + Space，可以叫出讀取／寫入／附加 context 的操作，精靈會為選取的 context node、recursion node 或 attribute 產生程式碼。ADT 2.13 起，Templates view 另有：實例化使用中的元件（Instantiate a Used Component）、觸發 Plug（Fire a Plug）、用 Message Manager 產生訊息、觸發控制器事件（Raise a Controller Event）。測驗題答案：C Ctrl + Space。

15.4 Where-used（Ctrl + Shift + G）

ADT 可以訂閱來自 ABAP Repository 的各種 feed。建立 ABAP 專案時會自動設好幾個：系統訊息、自己產生的執行期錯誤、自己負責的物件發生的執行期錯誤（等於不用開 ST22 就會收到 dump 通知）。訂閱後 ADT 會定期更新，更新間隔可以在訂閱時調整。只有開啟中的 ABAP 專案才會自動更新，否則 feed 處於休眠狀態，在 Feed Reader 裡以灰字顯示（p120–121）。

16.4 ABAP Doc 註解

ADT 裡有兩種註解（p122–123）：

  • 一般註解：行首 *，或行中任意位置的 "，執行期忽略。
  • ABAP Doc 註解：以 "! 開頭，寫在宣告敘述的上一行；多行時每一行都要以 "! 開頭。內容會出現在 Code Element Information 彈出視窗（F2）、ABAP Element Info view，以及程式碼補全清單的 tooltip。7.40 起可以用在類別、介面、程式、函數群組中的類別、方法、區域變數等元素。
  • 語法檢查時會一併驗證 ABAP Doc 的位置與結構，放錯位置或語法不對，Problems view 會出現警告。
  • ABAP Doc 在 ADT 與 SAP GUI 的原始碼編輯器都看得到，但在 SAP GUI 的表單式編輯器裡看不到。

常用標記：@parameter 名稱 | 說明、@raising 例外 | 說明、<p class="shorttext synchronized">（和物件短文字同步）。範例見第 12 節的類別程式碼。測驗題答案：C "!。

17. 靜態測試：語法檢查與 ABAP Test Cockpit（ATC）

17.1 自動語法檢查

ADT 會自動檢查正在編輯的物件：停止打字時、開啟時、存檔時都會觸發；存檔會對所有已開啟的物件做語法檢查。可以在 Window → Preferences → ABAP Development → Editors → Source Code Editors 取消勾選 Automatic syntax check on all open ABAP source editors，之後改用 Ctrl + F2 手動檢查。錯誤列在 Problems view，雙擊跳到該行；有問題的行在程式碼中加底線、左邊界也有標記（p131–132）。

  • 直接在 ADT 對自己的程式做本機品質檢查。
  • Findings、細節與說明直接顯示在 Problems view（新版另有 ATC Problems view）。
  • 用 SE80 的 ATC Browser 集中管理 findings（可以在內嵌 SAP GUI 開啟）。
  • 品質經理通常在整合／合併系統做集中式檢查；ATC 本身在 SAP GUI 用 ATC 交易設定。

18. ABAP Unit 單元測試與測試覆蓋率

單元測試：由開發人員驗證程式中最小的可測單元（例如方法），讓品質保證、重構、迴歸測試和測試驅動開發（TDD）都更容易，應該是開發階段的一部分。單元測試寫成全域類別（class pool）主程式裡的區域測試類別，扮演類別的「使用者」，所以只能存取受測類別的 public 元件。每個測試是測試類別的一個方法，各自獨立執行。正式系統的 load 版本會排除測試類別，以縮小 load（p137）。

ABAP Unit 是內建在 ABAP 語言裡的測試框架，特點（p138）：

  • 測試跟著被測物件一起傳輸，所以每套開發、測試系統都有。
  • 開發時可以直接從 ADT 編輯器執行；覆蓋率量測已整合進來；也整合進 ATC，可以自動化、納入大量品質檢查。
  • 結果顯示在 ABAP Unit Runner view。
  • 測試方法沒有參數；不用特別的知識就能執行，任何人都可以跑，不限開發者本人。
  • 測試程式碼不是產生出來的，在正式系統中也不能執行。

寫法規則（p139–140）：

  • 測試類別的定義加 FOR TESTING；執行時系統會自動為每個測試類別建立實例，再執行測試方法。
  • 測試方法是沒有參數的實例方法（最好是 private），同樣加 FOR TESTING。
  • 檢查用 CL_ABAP_UNIT_ASSERT 的靜態方法，常見參數：act（實際值）、exp（期望值）、msg（不符時的訊息）、level（嚴重度：TOLERABLE／CRITICAL／FATAL）、quit（不符時中止範圍：NO／METHOD／CLASS／PROGRAM）；回傳參數 assertion_failed（'X'／空白）。
  • 測試類別與正式程式碼界線分明：編譯器不允許一般類別存取測試類別；正式系統甚至不會產生測試類別。

Fixture（特殊方法）：名稱保留、由執行環境自動呼叫，用來建立標準化的測試環境（p141）：

19. 用 ABAP Profiler 分析效能

ADT 的 ABAP Profiler 相當於 SAP GUI 的 ABAP Trace（SAT，舊版 SE30）。它能找出效能熱點，決定重構要花力氣在哪裡；分析程式流程時，有時比除錯器還有效。可以量測的對象：類別、程式、函數模組、Web Dynpro、交易（p143）。

  1. 先調設定：Window → Preferences → ABAP Development → Profiling。最重要的是要不要彙總（aggregate）：彙總後 trace 檔較小，但細節較少；要看 call tree 就必須關掉彙總。
  2. 量測：在編輯器開啟程式 → 右鍵 Profile As → 程式啟動後照常操作 → 完全關閉程式後，Profiler 才會彙整 trace。
  3. 看結果：ABAP Traces view（Window → Show View → Other → ABAP → ABAP Traces），依專案分組、依使用者過濾。剛量完要先 Refresh 才看得到。

Trace 的幾種呈現（p145–146）：

  • Hit List：所有處理過的事件，包括報表事件（START-OF-SELECTION 等）、PBO／PAI、副程式／函數模組／方法呼叫、Native SQL 的 PREPARE／OPEN／FETCH。每項有 Own time 和 Total time；Own 小於 Total，表示它還呼叫了其他被量測的單元。
  • Call Tree：呼叫關係。Call Timeline 是圖形版：時間由左往右，重點看兩件事：資料庫存取次數（預設橘色，一大堆細小尖峰代表 SQL 太多、應該合併成較少的敘述）和呼叫堆疊深度（方法呼叫是綠色，很深又重複出現，可能要合併幾個很小的方法，因為 ABAP 編譯器不會做 inline，一長串小方法相對沒效率）。
  • Database Accesses：存取了哪些資料表、讀的是 DB 還是 buffer、各花多少時間。要看資料庫層的執行細節或找出重複的相同 SELECT，請用 SQL Trace（ST05）。

某些分析仍然要在內嵌 SAP GUI 用 SAT：

Critical Processing Blocks（Module Tree）快速掃出超過時間門檻的方法、函數模組等處理區塊

20. Eclipse 的擴充性：HANA Studio、External View、DB Procedure Proxy 與 HANA Transport Container

Eclipse 架構：整個平台由 plug-in 組成。plug-in 是一包程式碼或資料，提供程式庫、平台擴充甚至文件；plug-in 可以定義 extension point，讓其他 plug-in 在明確的位置加入功能。所以 ADT 可以和 SAP HANA Studio 裝在同一個 Eclipse 裡，開發「使用 HANA 物件的 ABAP 程式」更方便，跨平台開發也更有效率（p151–152）。

  PUBLIC SECTION.
    INTERFACES if_amdp_marker_hdb.            " 標記：這是 HANA 用的 AMDP 類別
    TYPES: BEGIN OF ty_load,
             carrid   TYPE s_carr_id,
             connid   TYPE s_conn_id,
             load_pct TYPE p LENGTH 5 DECIMALS 2,
           END OF ty_load,
           tt_load TYPE STANDARD TABLE OF ty_load WITH EMPTY KEY.
    CLASS-METHODS get_load
      IMPORTING VALUE(iv_client) TYPE mandt
                VALUE(iv_carrid) TYPE s_carr_id
      EXPORTING VALUE(et_load)   TYPE tt_load.
ENDCLASS.

CLASS zcl_bc404_amdp IMPLEMENTATION.
  METHOD get_load BY DATABASE PROCEDURE FOR HDB
                  LANGUAGE SQLSCRIPT
                  OPTIONS READ-ONLY
                  USING sflight.
    et_load = SELECT carrid, connid,
                     ROUND( SUM( seatsocc ) * 100.0 / SUM( seatsmax ), 2 ) AS load_pct
                FROM sflight
               WHERE mandt  = :iv_client
                 AND carrid = :iv_carrid
               GROUP BY carrid, connid
               ORDER BY carrid, connid;      -- SQLScript 裡同樣要自己排序
  ENDMETHOD.
ENDCLASS.

練習與自我檢核

  1. （Unit 1）判斷對錯：「ADT 採用和 ABAP Workbench 相同的線上開發模型，登入後整個 session 都保持連線；而且因為有本機快取，可以離線編輯。」
    參考答案要點：前半句對（講義 Unit 1 測驗第 3、4 題都是 True）；後半句錯。本機只有提升效能用的唯讀快取，用戶端沒有 ABAP runtime，所以不支援離線。開啟物件時後端設 enqueue 鎖，存檔或啟用時直接寫回後端，沒有 check-out／check-in。
  2. （Unit 1）ABAP 專案由哪幾個要素識別？預設語言會影響什麼？
    參考答案要點：系統＋用戶端＋使用者（再加上語言）。預設語言決定新建物件的原始語言，以及訊息與 UI 文字的語言。
  3. （Unit 1）哪些是 ADT 的透視圖？Transport Organizer 算嗎？
    參考答案要點：ABAP、Debug、ABAP Profiling。Transport Organizer 是 view，不是透視圖。
  4. （Unit 2）用 Ctrl + Space 選中一個方法後，要按什麼鍵才會插入完整簽章？ADT 除錯器有、SAP GUI 除錯器沒有的功能是什麼？反過來呢？
    參考答案要點：Shift + Enter。ADT 獨有的是在除錯器裡直接改程式；SAP GUI 獨有的是記憶體分析、Debugger Scripting，以及複雜物件的 Diff 比較。兩者都有的是動態設中斷點、顯示內表（講義測驗答案 A、D）。
  5. （Unit 2）寫一個自訂程式碼範本 zloop：對內表跑 LOOP AT … ASSIGNING FIELD-SYMBOL( )，內表名稱只輸入一次就套用到所有位置，結束後游標停在迴圈內。
    參考答案要點：LOOP AT ${itab} ASSIGNING FIELD-SYMBOL(<ls_${itab}>). ${cursor} ENDLOOP. 同名佔位符會一起替換；${cursor} 決定結束後的游標位置；範本編輯器沒有語法檢查，存檔前要自己確認。
  6. （Unit 3）在 ADT 裡要怎麼定義函數模組的介面？定義部分寫的註解會怎樣？舊函數模組沒有型別的參數會被怎麼處理？
    參考答案要點：用 FUNCTION 敘述的 IMPORTING／EXPORTING／CHANGING／RAISING／EXCEPTIONS 附加項，參數以空白分隔、不加逗號（測驗答案 A）。定義部分的註解在啟用後會消失。沒有型別的參數補 TYPE ANY，TABLES 參數補 TYPE STANDARD TABLE。
  7. （Unit 4）用 ADT 結構編輯器寫一個含 CURR 欄位的結構，沒有連到 CUKY 會怎樣？講義說結構以什麼關鍵字開頭，對嗎？
    參考答案要點：CURR 沒有用 @Semantics.amount.currencyCode 連到 CUKY 欄位會語法錯誤，因為系統無法決定小數位數。講義寫 define type 是錯的，正確的是 define structure 名稱 { … }。
  8. （Unit 4）CDS View 和傳統 Database View 有哪三個差異？在 S/4HANA 2020 以上，新 CDS 應該用什麼語法？讀 CDS 的 SELECT 有哪兩條新語法規則？
    參考答案要點：各種 join（外部連接、union）、彙總函數、association／path expression；傳統 view 只能 inner join、沒有彙總。7.55 以上用 define view entity（不需 sqlViewName）。欄位清單用逗號分隔、ABAP 變數加 @。另外 CDS 本身沒有順序，讀取端要 ORDER BY。「CDS 只能 inner join」答案是錯。
  9. （Unit 5）在 ADT 建立一個會帶航空公司代碼的例外類別 ZCX_BC404_NO_DATA，步驟是什麼？文字從哪裡來？
    參考答案要點：New ABAP Class，父類別 CX_STATIC_CHECK → PUBLIC SECTION 用 Ctrl + Space 插入 textIdExceptionClass → 把 msgid／msgno 改成訊息類別（SE91）與號碼，attr1 填屬性名 MV_CARRID → 在建構子裡用這個常數取代 IF_T100_MESSAGE=>DEFAULT_TEXTID。ADT 裡文字必須是訊息類別的訊息，不能像 SE24 那樣直接寫 OTR 文字。
  10. （Unit 5）Extract Method 有哪些前提？刪除未使用變數時，哪些變數不會被刪？
    參考答案要點：程式碼必須在類別裡、在某個 METHOD…ENDMETHOD 範圍內，而且沒有語法錯誤；快捷鍵 Alt + Shift + M。PUBLIC 與 PROTECTED SECTION 的變數不會被刪。
  11. （Unit 6）在 ADT 建立 action 時，系統會自動產生什麼？要叫出讀寫 context 的精靈，按哪個鍵？S/4HANA 新 UI 還應該用 Web Dynpro 嗎？
    參考答案要點：自動產生事件處理方法 ONACTION<ACTION_NAME>；精靈是 Ctrl + Space（測驗答案 C）。新 UI 應該走 Fiori（CDS + RAP + Fiori Elements／SAPUI5、OData），Web Dynpro 只做維護。
  12. （Unit 7）要確認開發系統的修正是否已經傳到正式系統，該用哪一種 Compare With？為什麼比較同一系統的兩個 client 沒有意義？
    參考答案要點：Compare With → 另一個 ABAP 專案（PRD 的專案）。ABAP 程式碼跨用戶端，同一系統永遠是同一版。另外兩種是 Local History（存檔之間）和 Revision History（傳輸版本之間）。
  13. （Unit 7）F3、Ctrl + Shift + A、Ctrl + H、Ctrl + Shift + G 各是什麼？ABAP Doc 以什麼開頭？Feed 在專案關閉時會更新嗎？
    參考答案要點：定義／實作導覽（測驗答案 B）、開啟開發物件（測驗答案 D）、物件搜尋（不必指定類型，可用 *）、Where-used。ABAP Doc 以 "! 開頭（答案 C），多行時每行都要。Feed 只在開啟的專案會更新（答案：錯）。
  14. （Unit 8）ATC 可以沿用哪個工具的檢查變式？預設變式是什麼、在哪裡改？ABAP Unit 的四個 fixture 各在何時執行？
    參考答案要點：Code Inspector（SCI）；預設 DEFAULT，在專案 Properties → ABAP Development → ABAP Test Cockpit 更改。CLASS_SETUP（類別開始前一次）、SETUP（每個測試前）、TEARDOWN（每個測試後）、CLASS_TEARDOWN（類別結束後一次）。
  15. （Unit 8）Profiler 的 Call Timeline 出現大量橘色細尖峰代表什麼？要看 call tree 時設定要注意什麼？
    參考答案要點：SQL 次數太多（常見原因是迴圈內 SELECT），應該合併成 JOIN 或整批讀取；很深的綠色方法鏈則可能要合併小方法（ABAP 沒有 inline）。要看 call tree 必須關掉彙總。量測要等程式完全結束，並在 ABAP Traces view 按 Refresh。
  16. （Unit 9）External View 的語法檢查能保證什麼、不能保證什麼？在 S/4HANA 應該用什麼取代 External View 和 DB Procedure Proxy？
    參考答案要點：只能保證 external view 存在，不能保證底層 HANA view 仍然有效；它只能在 ADT 建立（答案：對）；HANA Transport Container 指向 Delivery Unit（答案 B）。S/4HANA 改用 CDS（資料模型）與 AMDP（SQLScript），全部是 ABAP 物件，走一般傳輸。
  17. （綜合・實務）你接手一支舊程式，「抓成本時取第一筆」的結果時好時壞。請說明你會怎麼用 ADT 的工具定位並防止再發生。
    參考答案要點：① 用 F3、Where-used 找到取值的 SELECT；② 用 Debug 透視圖或 Profiler 的 Database Accesses 確認 SQL；③ 發現沒有 ORDER BY：HANA 沒有預設排序，H 與 E 兩種角度的成本會隨機出現；④ 修正為明確排序或直接限定條件（固定抓 H）；⑤ 補上 ABAP Unit 測試（第 18 節的 first_cost_is_type_h），並用 ATC 找出其他「UP TO 1 ROWS 沒有 ORDER BY」的地方；⑥ 條件若有號碼範圍，優先改成列舉（多筆 EQ），不要用 BT 區間。
