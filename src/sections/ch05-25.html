2. Unit 1-1：第一支 ABAP 程式——SE38、命名空間、屬性與四個按鍵

原廠的教學哲學一句話：「學寫程式（任何語言）最好的方法就是開始寫程式。」BC100 用 ABAP Editor（SE38）當唯一工具，建立程式需要懂四件事：怎麼建立新程式、怎麼操作編輯器、最重要的編輯器功能、怎麼寫出一個正確的 ABAP 敘述。

  1. 命名：客製程式必須使用客戶命名空間，也就是以 Z 或 Y 開頭（練習題第 1 題的答案）。公司若有註冊的前綴命名空間（如 /ABC/）也可以，但 BC100 不談。
  2. 程式屬性（Attributes）：標題（Title，通常與技術名稱不同）與程式類型（Type）。BC100 只用 Executable Program（可執行程式，類型 1），也就是一般說的「報表」；其他類型（Include、Module Pool、Function Group、Class Pool…）在 BC400 介紹。
  3. 套件或本機物件：指派到套件（Package）→ 系統會要求指定傳輸請求（Transport Request），程式可以傳到 QAS／PRD；存成本機物件（Local Object，套件 $TMP）→ 不能傳輸、也不會問請求號碼。詳見 1-1 章。

3. Unit 1-2：ABAP 語言特性與語法規則、註解、F1 關鍵字說明

ABAP（Advanced Business Application Programming）是 SAP 為商業應用開發的語言，原教材列出六個特性：

特性意思
Typed（強型別）有多種數值型與字元型，資料依型別處理
Multi-lingual（多語言）用可翻譯的文字元素（text elements）做出多語系應用
SQL access內嵌 Open SQL（S/4HANA 稱 ABAP SQL）直接存取資料庫
Object-orientedABAP Objects 是 ABAP 的物件導向擴充
Platform-independent同一段語法在任何資料庫與作業系統上意義相同
Upward-compatible今天寫的程式在未來版本仍能執行

語法規則（原教材 Figure 4 與 p18 的清單）：

  • 程式由一個個敘述（statement）組成；敘述的第一個字是關鍵字（keyword）。
  • 每個敘述以句點結尾，沒有例外（練習題 2：答案是 Period，不是分號）。
  • 敘述可以有附加（additions）與運算元（operands），可以跨多行；字與字之間至少一個空白。
  • 可以縮排；執行時系統不分大小寫。慣例是關鍵字與附加大寫、運算元小寫（原廠教材採此慣例）。
  • 鏈式敘述（Chained Statement）：連續幾個敘述關鍵字相同時，寫一次關鍵字加冒號，後面各段用逗號分隔。原教材特別註明：鏈式敘述不會提升效能，只是語法簡寫。

註解兩種：行首 * 表示整行註解；" 可以放在任何位置，之後到行尾都是註解。原廠建議：整行註解放在它描述的敘述上一行；行尾註解最適合用在宣告，不適合用在可執行敘述。

* 整行註解：星號必須在第 1 欄
DATA gv_count TYPE i.          "行尾註解：最適合寫在宣告後面

" 鏈式敘述：WRITE 重複兩次 → 用冒號與逗號合併
WRITE 'Hello'.
WRITE 'World'.
WRITE: 'Hello', 'World'.       "與上面兩行完全等價，效能也一樣

" 一個敘述可以跨行，直到句點才結束
SELECT SINGLE FROM scarr
  FIELDS carrname
  WHERE carrid = 'LH'
  INTO @DATA(gv_carrname).

" 常見陷阱：鏈式敘述的冒號放錯位置
" WRITE: / 'A', / 'B'.   → 輸出兩行
" WRITE / : 'A', 'B'.    → 語法雖然過得了，但讀的人會誤會，不要這樣寫

F1 關鍵字說明（ABAP Keyword Documentation）兩種開法：游標停在關鍵字上按 F1（練習題 4 的答案），或按編輯器的 Help On 按鈕輸入關鍵字，也可以瀏覽 Glossary、ABAP Subject Directory 等目錄。

S/4HANA 時代的查法：交易碼 ABAPDOCU（含可執行範例程式 DEMO_*）、ABAPHELP；ADT 中游標停在關鍵字按 F1 會開出與系統版本相符的說明；線上版為 help.sap.com 的「ABAP Keyword Documentation」，務必選和你系統 SAP_BASIS 相同的版本（1809＝7.53），否則會查到你系統還不能用的新語法。

4. Unit 1-3：用 PARAMETERS 做出最簡單的對話——選擇畫面與選擇文字

「Hello World，還是更個人化一點？」——BC100 用這個問題引出輸入。PARAMETERS 在選擇畫面（Selection Screen）上產生一個輸入欄位，一個參數對應一個欄位，畫面自帶 Execute（F8） 按鈕。這裡不用 Screen Painter，畫面是依宣告自動產生的。

關鍵觀念（練習題 5 答案 B＋D）：PARAMETERS 同時定義了「畫面上的輸入欄位」與「程式記憶體中同名的變數」。使用者按執行時，輸入值被搬進這個變數，程式就能拿來運算或輸出。因為內容會變，所以叫「變數」；在寫程式的當下你不知道使用者叫什麼名字，所以參數也像是一個「佔位符」。

選擇畫面最常見的用途是讀資料庫前的篩選條件（例如只看某天的銷售訂單），只抓需要的資料，對效能與記憶體都有正面影響。

5. Unit 1-4：ABAP Editor 設定——新舊編輯器、Pretty Printer、Code Hint／Template、語法檢查與啟用

選擇編輯器：若看到的是舊式（Classic）編輯器，Utilities → Settings → ABAP Editor → Editor 頁籤，選 Front-End Editor (New)。新編輯器的功能：

  • 可設定不同元素（關鍵字、註解、字面值）的顏色、字型與字級。
  • Code Hint（程式提示）：輸入時建議關鍵字與最近用過的識別字。只有一個建議時黑字白底；多個建議時最相關的一個以白字黑底顯示；Ctrl+Space 列出全部建議。也可以開啟「變數也提示」。
  • Code Template（程式樣板）：提示中帶有 § 符號的是樣板，按 Tab 插入整段（例如 IF…ENDIF）。與 Code Hint 的差別：hint 針對單一關鍵字，template 針對一整塊常用程式；也可以自訂樣板。
  • 編輯器設定：右下角按鈕進入；設定是使用者個人的，不是全系統。

Pretty Printer（Shift+F1）：新舊編輯器都有，可做兩件事——關鍵字大小寫轉換、邏輯區塊縮排。設定在 Utilities → Settings → ABAP Editor → Pretty Printer，但設定不會自動套用，必須按 Pretty Printer 按鈕；原廠建議開發過程中經常按。

啟用的意義（p34）：每支新程式一開始都是非啟用；改了已啟用的程式會產生新的非啟用版，用 TCODE 執行的人看到的一直是上一個啟用版，直到你啟用新版。原廠提示：複製程式時只會複製啟用版。

教材過時處與 S/4HANA 現況：兩版教材都說「新編輯器是為 NetWeaver 7.0 開發、可透過 SP 匯入 AS 6.20（SP 18 或 SP 59）與 6.40」——這是 2006 年前後的資訊。S/4HANA 1809 的 SE38／SE80 預設就是新前端編輯器，不需再切換。更重要的是：CDS View、AMDP、RAP、Behavior Definition 等新物件只能在 ADT（Eclipse）中編輯，SAP 也已明確把 ADT 定為策略性工具。建議初學者 SE38 學會之後盡快轉到 ADT，見 5-5 章 BC404 ADT。ADT 對應的操作：Ctrl+S 存檔、Ctrl+F2 檢查、Ctrl+F3 啟用、F8（或 F9 Console）執行、Shift+F1 格式化（ABAP Formatter）、Ctrl+Space 內容輔助（Content Assist）。

6. Unit 2-1：資料型別、變數、字面值與常數

為什麼選擇畫面參數的型別重要？名稱可以隨便取，不影響能輸入什麼；型別決定能輸入什麼值（數字、字元、日期…）與多長，也決定程式裡能對它做什麼（i 可以運算；string 內容是 'ABC' 就不能算）。原廠比喻：型別是變數（輸入欄位）的「正式描述」。

型別意義用途與注意初始值
string變長字串任意字元、任意長度；不能也不需要指定長度空字串
c定長字串用 LENGTH 指定長度；未指定預設 1空白
d日期內部格式 YYYYMMDD，固定 8 位不能指定長度；使用者依個人設定格式（如 DD.MM.YYYY）輸入，系統自動檢查與轉換'00000000'
t時間內部格式 HHMMSS，固定 6 位'000000'
i整數長度固定（4 bytes），不能有小數0
p壓縮數（Packed）商業計算的主力；每 byte 放 2 位數，半個 byte 留給正負號；DECIMALS 指定小數；未指定長度預設 8（bytes）0
教材筆誤修正：Col18 p43 內文寫 t 型別「stored internally in the format HHMMTT」，同書 p42 的型別表卻寫 HHMMSS。正確是 HHMMSS（時、分、秒），HHMMTT 是筆誤。

Packed 的長度算法：p LENGTH 16 有 32 個半位元組，1 個給正負號，剩 31 位數字。p 變數不含千分位，1,000 的逗號只是輸出時自動加的顯示格式。

全域型別（Global Data Types）：物料號碼多長？能含英文字母嗎？答案在 ABAP Dictionary（SE11）的表格定義裡。例如物料主檔 MARA 的欄位 MATNR。最簡單的用法是 TYPE 表格-欄位，字典欄位是全系統可見的，任何程式都能引用。其他全域型別（資料元素、結構、表格型別）在 BC400 與 1-2 章。

S/4HANA 修正：MATNR 不是 18 碼。兩版教材的 Figure 28 都畫 MARA-MATNR CHAR 18，這是 ECC 的定義。S/4HANA（1511 起）MATNR 欄位長度已擴充為 CHAR 40（是否實際允許輸入 40 碼由 Customizing「Extended Material Number」決定）。這正是原廠要你用 TYPE mara-matnr 或資料元素 matnr、而不要自己寫 c LENGTH 18 的理由——升級時引用字典型別的程式自動跟著變長，寫死長度的程式則會截斷料號。

DATA vs PARAMETERS：PARAMETERS 是「選擇畫面上的輸入欄位＋同名變數」；DATA 只是程式內部使用的變數，不對應任何輸入欄位。型別可以用 ABAP 標準型別、字典全域型別，或用 LIKE 參照既有變數。

字面值（Literal）與常數（Constant）：'Hello World'、123 這種沒有名字、寫死的值叫字面值；數值字面值不加引號，文字字面值用單引號。文字字面值無法翻譯（→ 用文字符號，§7）。原廠建議避免在程式中直接寫字面值，改用常數：同一值出現多處時只需改一次；即使只用一次，取個有意義的名字也讓程式更好懂。常數在宣告時以 VALUE 給值，執行時不能改。

7. Unit 2-2：文字符號（Text Symbols）與多語言能力

多語言能力是 ABAP 開發的重要原則：畫面上的文字依使用者的登入語言顯示，英文登入看英文、法文登入看法文。因此原廠建議正式程式不要用文字字面值，因為字面值在原始碼裡只有一種語言；要用文字符號讓所有文字都可翻譯。

  • 文字符號屬於特定程式，以3 碼英數 ID 識別（如 001、abc）。

  • 翻譯：在文字元素畫面 Goto → Translation，輸入目標語言與譯文。

8. Unit 2-3：賦值與算術運算

程式啟動時系統替變數配置記憶體，每個變數依型別給初始值（除非用 VALUE 指定）：數值為 0、字元型為空白。之後可以用各種敘述改變它的值：

  • gv_num = 30.：等號左邊是目標、右邊的值覆蓋目標原本的值。
  • CLEAR gv_num.：把變數重設為該型別的初始值。
  • 原教材還介紹 MOVE a TO b.（等同 b = a.），以及 ADD／SUBTRACT／MULTIPLY／DIVIDE 四個關鍵字寫法（例如 ADD 1 TO gv_result.）。這些都是過時語法，本圖書館的程式碼一律不用，只在 §19 的對照表以文字列出。

算術運算子只有四個：+ − * /（練習題 2-4 的答案是 / 與 *；% 與 x 都不是 ABAP 運算子）。一個運算式要當另一個運算式的運算元時用括號，括號內外都要留空白。

10. Unit 2-5：ABAP Debugger——單步、中斷點、Watchpoint

Debugger 讓你在執行時「走進程式裡面」，看到正在執行哪一行、變數怎麼變化。啟動方式依需求不同：

  1. 從頭開始除錯：在 SE38 初始畫面按 Debugging 按鈕，從第一行跟到最後，適合理解一支陌生程式的全貌。
  2. 在某一行停下：在編輯器左側狀態欄點一下（再點一次取消），或游標停在該行按工具列的 Set/Delete Breakpoint，然後 F8 執行。原始碼必須是啟用狀態才能設中斷點。
  3. 從畫面啟動：先正常執行、把欄位填好，在命令欄輸入 /h 按 Enter（練習題 2-6 答案），系統顯示「Debugging switched on」，下一個使用者動作（例如按執行）就進入 Debugger。

看懂 Debugger：原始碼區中黃色箭頭指的是「下一個要執行」的行；雙擊原始碼中的變數把它加到 Variables 區，一邊執行一邊看值的變化，找出是哪個敘述把資料弄錯。

12. Unit 2-7：字串處理——CONCATENATE、FIND、REPLACE、SPLIT 與字串範本

這一課處理字元型資料（string、c、d、t）。四個核心敘述：

  • CONCATENATE：把兩個以上的字串接成一個；SEPARATED BY 插入分隔字元。目標變數太短時結果會被截斷，所以原廠建議目標用 string。
  • FIND：在字串中找子字串或樣式；找到 sy-subrc = 0。
  • REPLACE：找到並取代；成功 sy-subrc = 0。兩者原理相同，差別只在於是否取代。
  • SPLIT：依分隔字元把字串切成多個目標變數（練習題 2-8 答案）。目標變數不夠時，剩下的整段（含分隔字元）會全部放進最後一個變數。

13. Unit 3：流程控制——流程圖、IF／CASE、關係與布林運算子、DO／WHILE 迴圈

設計程式時常遇到「依條件執行不同敘述」。原廠建議先畫程式流程圖（Program Flowchart）——它不限於 ABAP，任何語言都適用，用符號表示動作、輸入與處理。大部分程式可拆成四種元件：

元件意義ABAP 寫法
Sequence 順序要執行的一或多個動作依序寫敘述
Branch 分支是／否的問題IF … ELSE … ENDIF
Case distinction 多重分支多種可能答案的問題IF … ELSEIF／CASE … WHEN
Loop 迴圈重複的一段動作DO／WHILE（內表用 LOOP AT）

IF 結構：IF 條件為真就執行該區塊；否則依序檢查各 ELSEIF，第一個為真的區塊執行後跳到 ENDIF；都不成立時執行 ELSE（若有）。ELSEIF 與 ELSE 都可省略，但每個 IF 一定要有 ENDIF（練習題 3-1 答案：IF 與 ENDIF）。原教材以「休假天數結轉」為例：剩餘天數 gv_remaining >= pa_roll（要結轉的天數）時，把結轉天數加到明年額度；否則輸出錯誤訊息。

CASE：把一個變數的內容與各 WHEN 比對，符合就執行；都不符合執行 WHEN OTHERS（若有）。

運算子縮寫意義
=EQ等於
<>NE不等於
>GT大於
>=GE大於等於
<LT小於
<=LE小於等於

原廠建議同一支程式只用一種寫法（全用符號或全用縮寫，不要混用）。布林運算子：AND（全部為真才真）、OR（任一為真即真）、NOT（反轉）。AND 與 OR 混用時要加括號表達意圖。

REPORT zbc100_flow.

PARAMETERS: pa_rem  TYPE i DEFAULT 10,   "今年剩餘休假天數
            pa_roll TYPE i DEFAULT 5,    "想結轉到明年的天數
            pa_grp  TYPE c LENGTH 1 DEFAULT 'A'.

START-OF-SELECTION.
  DATA gv_next_year TYPE i VALUE 14.

  " --- 分支：是／否 ---
  IF pa_rem >= pa_roll.
    gv_next_year = gv_next_year + pa_roll.
    WRITE / |結轉成功，明年共 { gv_next_year } 天|.
  ELSE.
    WRITE / |剩餘 { pa_rem } 天，不足以結轉 { pa_roll } 天|.
  ENDIF.

  " --- AND / OR 混用：括號表達意圖 ---
  IF pa_grp = 'A' AND ( pa_rem = 0 OR pa_roll = 0 ).
    WRITE / 'A 群組且無可結轉'.
  ENDIF.

  " --- 多重分支：CASE ---
  CASE pa_grp.
    WHEN 'A'.
      WRITE / '主管'.
    WHEN 'B' OR 'C'.
      WRITE / '一般員工'.
    WHEN OTHERS.
      WRITE / '未分類'.
  ENDCASE.

  " --- 7.40+ 運算式版本：把「判斷後賦值」寫成一行 ---
  DATA(lv_title) = SWITCH string( pa_grp WHEN 'A' THEN `主管`
                                         WHEN 'B' OR 'C' THEN `一般員工`
                                         ELSE `未分類` ).
  DATA(lv_ok)    = COND string( WHEN pa_rem >= pa_roll THEN `可結轉` ELSE `不可結轉` ).
  WRITE: / lv_title, / lv_ok.

迴圈：重複一段邏輯直到條件滿足。在 DO 與 WHILE 迴圈中，sy-index 自動記錄目前是第幾圈，不必自己維護計數器（練習題 3-2 答案）。原教材的 DO 範例：依使用者輸入的 pa_years 重複計算，但最多 5 次——在迴圈中用 IF 判斷後 EXIT 跳出。

PARAMETERS pa_years TYPE i DEFAULT 8.

START-OF-SELECTION.
  DATA gv_balance TYPE p LENGTH 16 DECIMALS 2 VALUE 1000.
  CONSTANTS gc_max TYPE i VALUE 5.

  " DO n TIMES：固定圈數；EXIT 提早離開
  DO pa_years TIMES.
    gv_balance = gv_balance * '1.02'.
    WRITE / |第 { sy-index } 年：{ gv_balance }|.
    IF sy-index >= gc_max.

    ENDIF.
  ENDDO.

  " WHILE：條件成立才繼續；條件寫錯就是無窮迴圈
  DATA(lv_n) = 1.
  WHILE lv_n <= 100.
    lv_n = lv_n * 2.
  ENDWHILE.
  WRITE / |第一個大於 100 的 2 的次方：{ lv_n }|.

  " 7.40+：用 REDUCE 在一個運算式內完成累加
  DATA(lv_sum) = REDUCE i( INIT s = 0 FOR i = 1 UNTIL i > 10 NEXT s = s + i ).
  WRITE / |1 到 10 的和：{ lv_sum }|.
沒有 EXIT 的 DO（不加 TIMES）是無窮迴圈，對話程式會卡到逾時（rdisp/max_wprun_time），背景作業則會一直佔用工作程序。寫 DO 之前先想清楚「怎麼出去」。CHECK／CONTINUE 以及 LOOP AT 內表見 2-1 章 §7，IF／CASE／COND／SWITCH 見 §6。

14. Unit 4：執行時錯誤（Short Dump）與錯誤處理（MESSAGE）

語法正確不代表執行一定成功。原教材 Figure 66 的程式語法完全正確，但使用者輸入 0 當除數時，執行環境無法執行該敘述，便終止程式並觸發執行時錯誤（runtime error）。每個執行時錯誤有名稱，對應特定錯誤情境；例子中的名稱是 BCD_ZERODIVIDE（壓縮數除以零）。

未被攔截的執行時錯誤會產生 Short Dump（錯誤記錄），內容包括：錯誤名稱、問題描述、發生當下的變數內容、造成終止的程式行；也可以從 dump 直接進 Debugger 看發生前的變數值。Short Dump 預設保留 14 天，用 ST22 查看。最有用的是「Source Code Extract」，出錯那一行以 >>>>>> 標示。

原廠的態度：開發時遇到 dump 很正常，但要想辦法預防——正式機使用者看到充滿技術資訊的 dump 畫面只會困惑。預防方法有兩層：

  1. 用條件邏輯預防（原教材 Figure 69／70）：除之前先判斷除數不為 0。
  2. 用例外類別攔截（BC100 未提，現代寫法必備）：TRY … CATCH cx_sy_zerodivide … ENDTRY。
REPORT zbc100_error.

MESSAGE 敘述：除了用 WRITE 告訴使用者出了什麼問題，更標準的方式是對話訊息（dialog message），顯示在對話框或畫面底部狀態列。格式：MESSAGE tnnn(訊息類別)，t 是訊息類型、nnn 是 3 碼訊息號碼。練習題 4-2 的順序：MESSAGE 關鍵字 → 訊息類型 → 訊息號碼 → 訊息類別。

15. Unit 5-1：從資料庫讀資料——SE11、SE16、資料庫介面與 SELECT SINGLE

大多數 ABAP 程式都要讀 SAP 資料庫中的主資料或交易資料。原廠提醒：讀資料是複雜的主題，對效能影響極大；BC100 只談最簡單的「讀單筆」。第一步永遠是找出資料存在哪個表。

  • SE11 ABAP Dictionary：集中管理所有資料庫表，可看欄位、型別、長度、哪些欄位組成主鍵。
  • SE16 Data Browser：看表的內容，測試程式時用來核對資料（S/4HANA 多用 SE16N／SE16H）。
  • 資料庫介面（Database Interface）：程式執行時把 SELECT 翻譯成資料庫的原生 SQL，送到資料庫，再把結果送回程式——這就是「平台無關」的來源。

SELECT 各子句的任務：

子句任務
SELECT（S/4 新語法可用 FIELDS）要讀哪些欄位（columns）
FROM資料來源：資料庫表或 View
INTO放到哪裡：變數、結構或內表（依資料種類與筆數而定）
WHERE要讀哪些列（rows）的條件
教材錯誤修正：Col18 p120 的清單中，SELECT 子句下方沒有說明文字（排版遺漏），而 WHERE 被寫成「Specifies the columns of the table that are to be selected」。這是錯的——決定欄位的是 SELECT（欄位清單），WHERE 決定的是哪些「列」。應理解為「WHERE：Specifies the rows（conditions）」。

SELECT SINGLE 讀一筆資料，通常在 WHERE 中給出完整的業務主鍵，確保拿到唯一那一筆。原教材 Figure 78：宣告與表 SCARR 同結構的 gs_carrier，讀 carrid、carrname、currcode 三個欄位，用 INTO CORRESPONDING FIELDS OF 放入同名欄位；找到資料時 sy-subrc = 0（練習題 5-1 答案），才輸出。

16. Unit 5-2／5-3：模組化與函數模組——SE37、介面、測試、CALL FUNCTION 與 Pattern

原廠的說法很實在：好的程式設計師有足夠時間可以從頭寫出任何程式，但聰明的程式設計師會假設「至少一部分功能已經有人寫好了」。從零開始既花時間又困難，應盡量用模組化技術重用程式碼。

  • 模組化單元（modularization unit）：封裝某個功能的一段原始碼，可以在許多地方重複使用而不必每次都寫完整程式碼。
  • 好維護：Figure 79——同一段 100 行的程式複製在 50 支程式中，要改就得改 50 次；Figure 80——這 100 行集中維護一次，各程式在需要時呼叫它。
  • 資料交換：Figure 81——呼叫端與模組化單元彼此不能直接存取對方的資料；Figure 82——兩者透過介面（interface）交換資料，介面由參數組成，分為「傳進去」與「傳回來」兩種（練習題 5-2 答案：Parameters）。

函數模組（Function Module）是 SAP 最常用的模組化單元之一，用 Function Builder（SE37）建立與分析。原教材情境：要算使用者剩餘休假天數，搜尋後發現 BC100_CALC_HOLS 可能合用（如何搜尋函數模組在 BC400 教）。評估步驟：

  1. Attributes 頁籤：看簡短說明，判斷是否合用。
  2. 介面：Import（函數需要呼叫端給的資料）、Export（函數傳回的資料）、Changing、Exceptions；必要（非 Optional）參數呼叫時一定要給值。若你的程式給不出它要的資料、或它傳回的不是你要的，就不合用。
  3. 測試（Test，F8）：在測試環境輸入 Import 值、執行、看 Export 結果；函數觸發例外時也會顯示。
  4. 文件：Function Module Documentation 按鈕（有登入語言的文件時）；參數旁 Long Text 欄位有綠燈表示該參數有說明。

呼叫語法：CALL FUNCTION '大寫函數名'。最容易搞混的方向問題（練習題 5-3 答案是 False）：

呼叫端寫的區塊對應函數的方向記法
EXPORTINGImport 參數程式 → 函數呼叫端「匯出」，函數「匯入」
IMPORTINGExport 參數函數 → 程式函數「匯出」，呼叫端「匯入」
CHANGINGChanging 參數雙向傳進去改完再帶回來
EXCEPTIONSExceptions函數 → sy-subrc傳統例外，靠 sy-subrc 判斷

每一行都是「左邊寫函數的參數名、右邊寫呼叫端的值或變數」。編輯器工具列的 Pattern 按鈕（ADT 用 Ctrl+Space 內容輔助）輸入函數名即可插入骨架，只要填值就完成。

17. 本書補充：從程序到物件——第一次呼叫類別與方法

BC100 只講到函數模組，但在 S/4HANA，新程式的模組化首選是類別的方法，而不是 FORM 或新的函數模組（函數模組仍是 RFC／BAPI／更新任務的載體）。初學者不必馬上懂繼承與多型，只要先建立三個觀念：

  • 類別（class）像是一個「函數的集合＋它們共用的資料」；方法（method）就是類別裡的函數，一樣有 IMPORTING／EXPORTING／RETURNING 參數介面。
  • 靜態方法（=>）不必建立物件就能呼叫；實例方法（->）要先用 NEW 建立物件。
  • RETURNING 參數讓方法可以直接寫在運算式裡：DATA(x) = zcl_x=>calc( ... ).——這是函數模組做不到的。

18. 綜合範例：休假天數試算報表（把 BC100 全部觀念串起來）

BC100 的範例貫穿「休假天數」這個情境（pa_hols、pa_roll、gv_remaining、BC100_CALC_HOLS）。下面把 16 個 Lesson 的觀念放進同一支程式：選擇畫面與選擇文字、字典型別、常數、文字符號、算術、系統變數、IF／CASE／DO、訊息類別與佔位符、例外處理、SELECT、模組化（區域類別）、ALV 輸出。

*---------------------------------------------------------------------*
* 需求：輸入全年天數、已休天數、想結轉天數，試算未來 N 年的休假額度
* 觀念：U1 PARAMETERS／U2 型別、常數、文字符號、SY-／U3 IF、DO

PARAMETERS: pa_total TYPE i DEFAULT 14 OBLIGATORY,
            pa_used  TYPE i DEFAULT 10,
            pa_roll  TYPE i DEFAULT 3,
            pa_years TYPE i DEFAULT 3.

           gc_max_roll  TYPE i VALUE 5.

         year      TYPE n LENGTH 4,
         allowance TYPE i,

CLASS lcl_planner DEFINITION FINAL.
  PUBLIC SECTION.
    CLASS-METHODS build
      IMPORTING iv_total       TYPE i
                iv_used        TYPE i
                iv_roll        TYPE i
                iv_years       TYPE i
      RETURNING VALUE(rt_rows) TYPE tt_rows.
ENDCLASS.

CLASS lcl_planner IMPLEMENTATION.
  METHOD build.
    DATA(lv_remaining) = iv_total - iv_used.
    " 分支：能不能結轉
    DATA(lv_roll) = COND i( WHEN lv_remaining >= iv_roll
                            THEN nmin( val1 = iv_roll val2 = gc_max_roll )
                            ELSE 0 ).
    DATA(lv_allow) = iv_total + lv_roll.

    " 迴圈：最多 gc_max_years 年
    DO iv_years TIMES.
      IF sy-index > gc_max_years.
        EXIT.
      ENDIF.
      APPEND VALUE #( year      = sy-datum(4) + sy-index
                      allowance = lv_allow
                      status    = COND #( WHEN sy-index = 1 AND lv_roll > 0
                                          THEN |含結轉 { lv_roll } 天|
                                          ELSE `標準` ) ) TO rt_rows.
      lv_allow = iv_total.            "結轉只算第一年
    ENDDO.
  ENDMETHOD.
ENDCLASS.

  " 輸入檢查放在這裡：E 訊息會讓選擇畫面維持可修改
  IF pa_used > pa_total.
    MESSAGE e004(zbc100_msgs) WITH pa_used pa_total.   "已休 &1 天超過全年 &2 天
  ENDIF.

                                      iv_used  = pa_used
                                      iv_roll  = pa_roll

B. 本書補充題

  1. 為什麼原廠要你寫 PARAMETERS pa_mat TYPE mara-matnr 而不是 TYPE c LENGTH 18？
    → 字典型別隨系統定義變動；S/4HANA 的 MATNR 已是 40 碼，寫死 18 會截斷料號。也順便得到欄位標籤、F4、轉換常式（ALPHA）。
  2. DATA(x) = 7 / 2. 的 x 是多少？怎麼得到 3.5？怎麼得到 3？
    → x 為 i 型別，值 4（四捨五入）；要 3.5 需目標為 p／decfloat34（如 DATA x TYPE p LENGTH 8 DECIMALS 1.）；要 3 用 7 DIV 2。
  3. 一支報表上線後，使用者反映「同樣條件每次跑出來的單價不一樣」，程式用的是沒有完整主鍵的 SELECT SINGLE。原因與修法？
    → 符合條件有多筆，HANA 沒有預設排序，回傳哪一筆不確定。改成明確排序＋取一筆（ORDER BY … INTO TABLE … UP TO 1 ROWS），或補齊條件到唯一。
  4. 選擇畫面的中文標籤在 DEV 正常、在 QAS 顯示 PA_NAME，最可能的原因？
    → 選擇文字是獨立物件，未啟用或未一起收進傳輸請求（或 QAS 登入語言沒有該語言的文字）。
  5. 把「群組 B 到 D」寫成 BETWEEN 'B' AND 'D' 有什麼風險？
    → 比的是字典序，'B1'、'C9' 等後來新增的代碼都會被包含；應列舉 WHEN 'B' OR 'C' OR 'D' 或 IN 明確值。
  6. 寫一段程式：輸入兩個整數，輸出兩數相除結果到小數兩位；除數為 0 時以資訊訊息提示，不可 dump。
    → 要點：結果變數 TYPE p LENGTH 8 DECIMALS 2；先 IF pa_num2 = 0 給 MESSAGE … TYPE 'I' 後 RETURN，運算放在 TRY … CATCH cx_sy_zerodivide cx_sy_arithmetic_overflow。
  7. 函數模組與類別靜態方法都能封裝邏輯，新程式為什麼建議用方法？
    → 方法可有 RETURNING 直接用在運算式中、支援 class-based exception、可做單元測試（ABAP Unit）、不必建立函數群組；函數模組保留給 RFC／BAPI／更新任務等必須用它的場合。
  8. Debugger 停在 watchpoint 時，應該分析哪一行？
    → 黃色箭頭上方那一行——變數在那裡已經被改變，箭頭指的是下一個要執行的敘述。
