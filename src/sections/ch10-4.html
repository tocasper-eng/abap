第 10-4 章 RAP 基礎：managed 情境從資料表到 Fiori Elements

RAP（ABAP RESTful Application Programming Model）是 SAP 目前唯一推薦、用來寫「可交易的 Fiori app 與 Web API」的程式設計模型。本章用一個自建的「報價單」（表頭 ZQUOTE_H、明細 ZQUOTE_I）從零走完 managed 情境的六個步驟：資料表 → interface view → behavior definition → behavior pool → projection 與 metadata extension → service definition 與 service binding，最後用 EML 從一般 ABAP 報表建立報價單。determination、validation、action、draft 與 unmanaged 放在 10-5 章。1809 沒有 RAP，1809 的讀者請直接看第 15 節的替代方案。

1. RAP 是什麼：定位、演進與版本門檻

定位：RAP 把一個業務物件拆成「資料模型（CDS）＋行為（behavior definition／implementation）＋服務（service definition／binding）」三塊，框架負責 OData 協定、交易緩衝、鎖定、ETag、儲存順序等技術細節，開發者只寫業務邏輯。SAP 官方說法是：RAP 是在 BTP ABAP environment、S/4HANA Cloud，以及從 1909 起的 S/4HANA（on-premise／Private Edition）上建置雲端就緒交易型 app、服務與擴充的推薦模型。

2. RAP 的組成：Business Object、Business Service、Consumption

RAP 把物件分成三層。下表是「架構圖的文字版」，由下往上讀：

層物件（ADT 類型）本章名稱職責
Business Object（BO）資料表（TABL）ZQUOTE_H、ZQUOTE_I持久層，managed 框架直接寫入
CDS 資料模型（DDLS，root view entity＋composition）ZI_Quote、ZI_QuoteItem定義 BO 的節點結構（composition tree）與欄位語意
Behavior Definition（BDEF，BDL 語言）ZI_Quote宣告可做哪些操作（create／update／delete）、鎖、權限、ETag、欄位控制
Behavior Implementation（ABAP behavior pool，類別）ZBP_I_Quote用 handler class／saver class 實作業務邏輯
Business ServiceProjection（CDS projection view＋projection BDEF＋metadata extension）ZC_Quote、ZC_QuoteItem針對某個服務挑出欄位、操作與 UI 註解
Service Definition（SRVD）ZUI_QUOTE_O4決定要對外公開（expose）哪些 entity
Service Binding（SRVB）ZUI_QUOTE_O4（V4 UI）綁定協定：OData V2／V4、UI 或 Web API
ConsumptionFiori Elements app、Web API 使用者、ABAP 程式（EML）—透過 OData 或 EML 使用 BO

3. 三種實作類型：managed、managed with unmanaged save、unmanaged

類型交易緩衝（buffer）儲存（save）適用情境
managed框架提供框架依 persistent table 自動寫表全新開發（greenfield），資料放在自己的 Z 表
managed with additional save框架提供框架寫表＋你在 saver 裡多做一段（寫變更文件、送事件、寫 log）標準儲存之外還要附加動作
managed with unmanaged save框架提供你自己寫 save_modified（例如呼叫既有更新函數）想用框架的 buffer 與 CRUD，但持久化要走既有程式
unmanaged你自己管你自己寫包裝既有 BAPI／函數／類別（brownfield），既有程式已有自己的 buffer 與 LUW

//    （7.55 起；7.56 以後也可以寫在 entity 層，位置請以 ADT 的 F1 說明為準）
managed with additional save implementation in class zbp_i_quote unique;

// 3) managed with unmanaged save：持久化完全自己寫
managed with unmanaged save implementation in class zbp_i_quote unique;

怎麼選：新開發、資料在自己的 Z 表 → managed；要把既有 BAPI（例如 BAPI_QUOTATION_CREATEFROMDATA2）包成 Fiori 服務 → unmanaged，做法見 10-5 章。卡在中間（想用框架但儲存要走舊程式）才考慮 managed with unmanaged save。
先找標準再客製：做報價單之前先確認 SAP 是否已有 released 的 RAP BO 或 API。例如銷售訂單已有 RAP BO interface I_SalesOrderTP，可以直接用 EML 建單；它在哪一版 on-premise 釋出未能確認，請在 ADT 的 Released Objects 樹或 SAP Business Accelerator Hub 查詢。本章自建 Z 報價單只是教學用，實務上請依「標準設定 → released API／BAdI → 自建」的順序評估。

4. 步驟 1：資料表 ZQUOTE_H／ZQUOTE_I

managed BO 的資料表要注意四件事：

  1. client 欄位放第一個鍵欄位。
  2. 鍵值：UUID key（sysuuid_x16，RAW 16）讓框架用 numbering : managed 自動產生；業務看的號碼（semantic key，如報價單號）另外放一個非鍵欄位。子表要有父節點 UUID 欄位，composition 才接得起來。
  3. 管理欄位：created_by、created_at、last_changed_by、last_changed_at、local_last_changed_at。其中 local_last_changed_at 是 ETag 的依據，每個節點都要有。
  4. SAP 提供管理欄位專用的資料元素（ABP_CREATION_USER 等）；如果系統查不到，用 syuname／timestampl 也可以（SAP openSAP 範例就是這樣寫）。

5. 步驟 2：interface view（root view entity＋composition）

BO 的節點樹用 CDS 的 composition 表達：根節點用 define root view entity，對子節點宣告 composition [0..*] of；子節點用 association to parent 指回父節點。管理欄位要在這一層加上 @Semantics 註解，managed 框架才會自動填值（只加在 projection 上是不會生效的）。

  association [0..1] to I_Customer   as _Customer on $projection.SoldToParty = _Customer.Customer

  • composition 的語意是「子節點的生命週期屬於父節點」：刪除表頭時框架會連帶刪除明細；建立明細只能透過 create by association（BDEF 的 association _Item { create; }）。
  • association to parent 的 ON 條件必須用子節點的父鍵欄位對父節點的鍵（這裡是 ParentUUID ＝ QuoteUUID）。
  • lastChangedAt 與 localInstanceLastChangedAt 不同：前者代表「本節點或其子樹最後異動」（draft 的 total ETag 會用到），後者只代表「本節點自己最後異動」，是一般 ETag 的依據。

6. 步驟 3：behavior definition（managed）

在 ADT 對 ZI_Quote 按右鍵 → New Behavior Definition，實作類型選 Managed，ADT 會產生骨架。完成後如下：

managed implementation in class zbp_i_quote unique;
strict ( 2 );

define behavior for ZI_Quote alias Quote
persistent table zquote_h
lock master
authorization master ( instance )
etag master LocalLastChangedAt
{
  create;
  update;
  delete;
  association _Item { create; }

  field ( numbering : managed, readonly ) QuoteUUID;
  field ( readonly ) CreatedBy, CreatedAt, LastChangedBy, LastChangedAt, LocalLastChangedAt;
  field ( mandatory : create, readonly : update ) QuoteID;
  field ( mandatory ) SoldToParty, SalesOrganization, Currency;

  mapping for zquote_h

    QuoteUUID          = quote_uuid;
    QuoteID            = quote_id;

語法意義
managed implementation in class zbp_i_quote unique;managed 類型；behavior pool 是 ZBP_I_QUOTE；unique 是必填，表示每個操作只能實作一次
strict ( 2 );啟用 strict mode 第 2 版：禁止過時語法、要求隱含操作明確宣告、檢查是否符合 RAP BO contract；projection BDEF 要用同一版
persistent table zquote_hmanaged 框架要寫入的資料表
lock master／lock dependent by _Quote根節點負責鎖；改明細時鎖的是整張報價單（框架用通用 lock 機制，不必自建 lock object）
authorization master ( instance )／authorization dependent by _Quote根節點做實例權限檢查（第 7 節實作）；明細的 update、delete、create-by-association 一律轉成「對表頭的 update 權限」
etag master LocalLastChangedAt樂觀鎖：OData 的 If-Match 比對這個欄位，別人先改過就擋下
create; update; delete;開放的標準操作（read 不用宣告，永遠可讀）；子節點不寫 create，只能經由 association _Item { create; } 建立
field ( numbering : managed, readonly )框架在 create 時自動產生 UUID，消費者不能填

Binding Type用途Fiori Elements Preview備註

10. EML 基本語法：READ ENTITIES 與 MODIFY ENTITIES

EML（Entity Manipulation Language）是 ABAP 裡操作 RAP BO 的語言，Fiori 透過 OData 做的事，ABAP 程式都能用 EML 做。四個核心語句：

語句作用寫到資料庫了嗎

READ ENTITIES OF zi_quote
  ENTITY Quote
    ALL FIELDS WITH VALUE #( ( QuoteUUID = lv_quote_uuid ) )
    RESULT DATA(quote_all)
  ENTITY Quote BY \_Item
    ALL FIELDS WITH VALUE #( ( QuoteUUID = lv_quote_uuid ) )

11. EML 完整範例：從一般 ABAP 報表建立報價單

下面是一支經典報表（Standard ABAP），用 EML 一次建立表頭與一筆明細：先 CREATE 表頭（%cid = 'QUOTE_1'），同一句再 CREATE BY \_Item（%cid_ref 指向 'QUOTE_1'），最後 COMMIT ENTITIES。這等於用 RAP BO 取代「自己 INSERT 兩張表」——鎖、權限、管理欄位、UUID 都由框架處理。

REPORT zquote_create_eml.

PARAMETERS: p_qid   TYPE n LENGTH 10 OBLIGATORY,
            p_kunnr TYPE kunnr OBLIGATORY,
            p_vkorg TYPE vkorg OBLIGATORY,
            p_matnr TYPE matnr OBLIGATORY,
            p_menge TYPE menge_d DEFAULT 10,
            p_meins TYPE meins DEFAULT 'EA',
            p_price TYPE netpr DEFAULT '1200.00',
            p_waers TYPE waerk DEFAULT 'TWD'.

START-OF-SELECTION.

  " 1. 表頭＋明細在同一個 EML 請求建立；%cid_ref 把明細掛到剛建立的表頭
  MODIFY ENTITIES OF zi_quote
    ENTITY Quote
      CREATE FIELDS ( QuoteID SoldToParty SalesOrganization QuoteDate ValidTo Currency OverallStatus )
      WITH VALUE #( ( %cid              = 'QUOTE_1'
                      QuoteID           = p_qid
                      SoldToParty       = p_kunnr
                      SalesOrganization = p_vkorg
                      QuoteDate         = sy-datum
                      ValidTo           = sy-datum + 30
                      Currency          = p_waers
                      OverallStatus     = 'N' ) )
      CREATE BY \_Item
      FIELDS ( ItemNo Material Quantity QuantityUnit NetPrice Currency )
      WITH VALUE #( ( %cid_ref = 'QUOTE_1'
                      %target  = VALUE #( ( %cid         = 'ITEM_10'
                                            ItemNo       = '000010'
                                            Material     = p_matnr
                                            Quantity     = p_menge
                                            QuantityUnit = p_meins
                                            NetPrice     = p_price
                                            Currency     = p_waers ) ) ) )
    MAPPED   DATA(mapped)
    FAILED   DATA(failed)
    REPORTED DATA(reported).

  " 2. MODIFY 階段失敗（權限、必填、欄位控制）：印訊息、丟棄 buffer
  IF failed IS NOT INITIAL.
    LOOP AT reported-quote ASSIGNING FIELD-SYMBOL(<rep_quote>) WHERE %msg IS BOUND.
      DATA(msg_text) = <rep_quote>-%msg->if_message~get_text( ).
      WRITE / |表頭：{ msg_text }|.
    ENDLOOP.
    LOOP AT reported-item ASSIGNING FIELD-SYMBOL(<rep_item>) WHERE %msg IS BOUND.
      DATA(item_text) = <rep_item>-%msg->if_message~get_text( ).
      WRITE / |明細：{ item_text }|.
    ENDLOOP.
    ROLLBACK ENTITIES.
    RETURN.
  ENDIF.

  " 3. 存檔：觸發 save sequence（validation 會在這裡跑，見 10-5 章）
  COMMIT ENTITIES
    RESPONSE OF zi_quote
      FAILED   DATA(commit_failed)
      REPORTED DATA(commit_reported).

  IF sy-subrc <> 0 OR commit_failed IS NOT INITIAL.
    LOOP AT commit_reported-quote ASSIGNING FIELD-SYMBOL(<c_rep>) WHERE %msg IS BOUND.
      DATA(commit_text) = <c_rep>-%msg->if_message~get_text( ).
      WRITE / |存檔失敗：{ commit_text }|.
    ENDLOOP.
    RETURN.
  ENDIF.

  " 4. MAPPED 帶回框架產生的 UUID（numbering : managed 是 early numbering，MODIFY 當下就有值）
  IF line_exists( mapped-quote[ %cid = 'QUOTE_1' ] ).
    DATA(new_uuid) = mapped-quote[ %cid = 'QUOTE_1' ]-QuoteUUID.
  ENDIF.

  " 5. 讀回結果；結果沒有保證順序，先排序再輸出
  READ ENTITIES OF zi_quote
    ENTITY Quote BY \_Item
      FIELDS ( ItemNo Material Quantity QuantityUnit NetPrice Currency )
      WITH VALUE #( ( QuoteUUID = new_uuid ) )
    RESULT DATA(items).

  SORT items BY ItemNo.
  WRITE / |報價單 { p_qid } 建立完成，明細 { lines( items ) } 筆|.
  LOOP AT items ASSIGNING FIELD-SYMBOL(<item>).
    WRITE / |{ <item>-ItemNo } { <item>-Material } { <item>-Quantity } { <item>-QuantityUnit }|.
  ENDLOOP.
和 BAPI 的差別：BAPI 回傳 RETURN 表、要自己呼叫 BAPI_TRANSACTION_COMMIT；EML 回傳 FAILED／REPORTED／MAPPED 三個結構、用 COMMIT ENTITIES 存檔。報價單號 p_qid 這裡由使用者輸入只是為了簡化，正式做法是在 determination 裡用號碼範圍取號（10-5 章）。
版本門檻：需 RAP BO 存在（本章 BDEF 需 7.57）。在 ABAP Cloud 語言版本下不能用 REPORT／WRITE，要改成實作 IF_OO_ADT_CLASSRUN 的類別；經典 ABAP 報表則兩者皆可。報表中若同時用 EML 又自己 COMMIT WORK，會把 RAP 交易切成兩半，請只用 COMMIT ENTITIES。
出處：abap-cheat-sheets：ABAP EML in RAP（CREATE BY \_assoc 的 %cid_ref／%target、COMMIT ENTITIES RESPONSE OF、sy-subrc 檢查）；abap-platform-rap-opensap（W3U4 MODIFY Create 與 MAPPED）。

12. FAILED、REPORTED、MAPPED 與交易控制

參數結構內容什麼時候看
MAPPED每個 entity alias 一個內表（mapped-quote、mapped-item）%cid 與框架產生的鍵值對照CREATE 之後取新鍵
FAILED每個 entity 一個內表失敗實例的 %tky（或 %cid）＋ %fail-cause（not_found、unauthorized、locked、conflict 等）判斷成功與否：IS INITIAL 才算全部成功
REPORTED每個 entity 一個內表，另有 %other訊息物件 %msg（IF_ABAP_BEHV_MESSAGE）與 %element（指向出錯欄位）顯示給使用者；Fiori 會自動把訊息貼到對應欄位
 
" 通用的錯誤處理：把 FAILED 的原因與 REPORTED 的訊息整理成一個字串表
DATA messages TYPE string_table.

MODIFY ENTITIES OF zi_quote
  ENTITY Quote
    UPDATE FIELDS ( OverallStatus )
    WITH VALUE #( ( QuoteUUID = lv_quote_uuid OverallStatus = 'C' ) )
  FAILED   DATA(failed)
  REPORTED DATA(reported).

LOOP AT failed-quote ASSIGNING FIELD-SYMBOL(<fail>).
  " %fail-cause 的值是 IF_ABAP_BEHV=>CAUSE 的常數
  DATA(cause) = SWITCH string( <fail>-%fail-cause
                  WHEN if_abap_behv=>cause-not_found  THEN `找不到資料`
                  WHEN if_abap_behv=>cause-unspecific THEN `未指定原因（看 REPORTED 的訊息）`
                  ELSE |原因代碼 { <fail>-%fail-cause }| ).
  APPEND |更新失敗：{ cause }| TO messages.
ENDLOOP.

LOOP AT reported-quote ASSIGNING FIELD-SYMBOL(<rep>) WHERE %msg IS BOUND.
  APPEND <rep>-%msg->if_message~get_text( ) TO messages.
ENDLOOP.

IF failed IS INITIAL.
  COMMIT ENTITIES RESPONSE OF zi_quote
    FAILED   DATA(c_failed)
    REPORTED DATA(c_reported).
  IF sy-subrc <> 0.
    APPEND `存檔失敗，變更未寫入` TO messages.
  ENDIF.
ELSE.
  ROLLBACK ENTITIES.
ENDIF.
  • 兩個階段各有一組 FAILED／REPORTED：MODIFY 階段（interaction phase）擋下的是權限、鎖、必填；COMMIT 階段（save sequence）擋下的是 validation。兩組都要看。
  • COMMIT ENTITIES 之後要檢查 sy-subrc：官方說明 COMMIT ENTITIES 不保證 COMMIT WORK 一定成功。
  • 批次處理多張報價單時，建議「一張一個 COMMIT ENTITIES」，一張失敗就 ROLLBACK ENTITIES 不影響其他張；全部塞同一個 commit，一張 validation 失敗會整批不存。
版本：if_abap_behv=>cause-not_found、cause-unspecific 取自 SAP openSAP 範例；其他原因（權限不足、被鎖定等）對應的常數名稱未能確認，請在系統對 IF_ABAP_BEHV 按 F2 查看。1809 沒有這些類別。
出處：abap-cheat-sheets：ABAP EML in RAP（RAP response 參數、COMMIT ENTITIES 與 sy-subrc、ROLLBACK ENTITIES）；RAP - Authorization（授權失敗回傳錯誤訊息的範例）。

16. 實務坑與上線檢查清單

  1. HANA 沒有預設排序：READ ENTITIES 的結果、Fiori 清單的預設順序都不能依賴資料庫。報表端「取第一筆明細」前要 SORT；Fiori 端用 presentationVariant 的 sortOrder 明確指定。
  2. 條件用列舉比區間安全：用 EML 批次讀報價單時，建議先用 ABAP SQL 讀 interface view 取得要處理的鍵，並以列舉的狀態值（例如 OverallStatus IN ('N','R')）篩選，不要用 BT 區間比號碼；報價單號有前導零（NUMC）或號碼段不連續時，區間會漏抓或多抓。
  3. 先找標準再客製：做 Z 報價單前先查 SAP 標準的報價單交易（VA21）與 released API；若只是要在標準單據加欄位或檢查，優先用 released BAdI 或 RAP BO 的擴充（BDEF extension，7.57 起），而不是自建一套 BO。
  4. 管理欄位沒填值：@Semantics 註解要加在 interface view（BO 層），只加在 projection 不會生效；BDEF 的 mapping 也要列出這些欄位。
  5. ETag 衝突：兩個人同時編輯，後存檔的會收到「資料已被變更」；這是正常的樂觀鎖行為。local_last_changed_at 每個節點都要有。
  6. 傳輸：service binding 的本機發布不能直接傳到 QAS／PRD，目標系統要用 /IWFND/MAINT_SERVICE（V2）或 /IWFND/V4_ADMIN（V4）啟用。
  7. 權限：本章 CDS 用 #NOT_REQUIRED 只為教學；上線前改 #CHECK 並寫 DCL（讀取權限），BDEF 的 authorization master 管的是「修改」權限，兩者要一起設計。
" 批次處理：先用 ABAP SQL 以「列舉」條件取鍵、明確排序，再逐張用 EML 更新
SELECT QuoteUUID, QuoteID
  FROM zi_quote
  WHERE OverallStatus IN ( 'N', 'R' )          " 列舉，不用 BT 區間
    AND ValidTo < @sy-datum

練習與自我檢核

  1. 版本判斷：客戶系統是 S/4HANA 1809，想做可編輯的 Fiori Elements 報價單 app，你會建議哪一種模型？升級到 2023 之後呢？
    要點：1809 沒有 RAP，只能用 CDS＋BOPF（@ObjectModel.transactionalProcessingEnabled、writeActivePersistence、@OData.publish）；升級後遷移到 RAP managed，資料表可沿用。
  2. 實作類型：公司已有一支穩定的報價單建立函數（含自己的 commit 與鎖），要包成 Fiori 服務，選 managed 還是 unmanaged？為什麼？
    要點：unmanaged（或至少 managed with unmanaged save），因為既有程式有自己的 buffer／LUW；新開發且資料在 Z 表才選 managed。
  3. BDEF 閱讀：解釋 lock dependent by _Quote、authorization dependent by _Quote、etag master LocalLastChangedAt 各自的效果。
    要點：改明細鎖整張報價單；明細的 update／delete／create-by-association 以表頭的 update 權限判斷；ETag 以明細自己的 local_last_changed_at 做樂觀鎖。
  4. strict 版本：同一份 BDEF 要放到 2021 系統，第二行要怎麼改？放到 2020 呢？
    要點：2021 改 strict;；2020 刪除整行，projection 的 provider contract 也要刪。
  5. 權限陷阱：只宣告 authorization master ( instance )，能不能擋住「沒有權限的人新建報價單」？
    要點：不能，根節點 create 沒有實例可檢查；要用 global 或 ( global, instance ) 並實作 FOR GLOBAL AUTHORIZATION。
  6. EML：改寫第 11 節範例，一次建立兩筆明細（10、20），並在建立後印出兩筆明細的 UUID。
    要點：%target 放兩行、各自 %cid；從 mapped-item 依 %cid 取 ItemUUID。
  7. FAILED 與 REPORTED：MODIFY 成功但 COMMIT ENTITIES 失敗，可能是什麼原因？要看哪個參數？
    要點：save sequence 的 validation 擋下（10-5 章）；看 COMMIT ENTITIES RESPONSE OF 的 FAILED／REPORTED 與 sy-subrc。
  8. service binding：開發機 Preview 正常，傳到 QAS 後 Fiori 打不開服務，最可能漏了什麼？
    要點：service binding 的本機發布不會隨傳輸生效，要在 QAS 用 /IWFND/MAINT_SERVICE（V2）或 /IWFND/V4_ADMIN（V4）啟用。
  9. HANA 排序：同事寫 READ ENTITIES … BY \_Item … RESULT DATA(items) 後直接取 items[ 1 ] 當「第一筆明細」，有什麼問題？
    要點：結果沒有保證順序，先 SORT items BY ItemNo；這和 SELECT 不寫 ORDER BY 是同一個坑。
  10. 先找標準：業務要求「報價單轉訂單」，你會先查哪些標準功能或 API，再決定是否用 EML 客製？
    要點：標準 VA21 參考建立 VA01、released 的銷售訂單 RAP BO（如 I_SalesOrderTP，版本需確認）或 BAPI；確認都不符合才客製。
