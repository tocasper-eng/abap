1. Dialog 程式的定位：Type 1 與 Type M 的界線其實是模糊的

很多 SAP 系統本身的功能，也是用 ABAP 寫出來的——SE11、VA03、ME21N 都是。螢幕（Screen／Dynpro）是 ABAP 設計最重要的工作之一，SAP 的單據、主資料維護等業務功能都靠螢幕，一支程式可以包含多個螢幕。

Dialog（對話）指的是使用者和程式之間任意形式的互動：輸入資料、選菜單項、按按鈕、單擊或雙擊清單條目。

老師的結論：Type 1 與 Type M 的界線其實是模糊的。 Type M 一開啟就是 Dialog，但必須包裝成 T-CODE；而 Type 1 也能透過 CALL SCREEN 讓程式一開始就進 Dialog。因此實務上都用 TYPE 1（REPORT）寫，比較方便——本章所有範例都採用這個策略：REPORT ＋ CALL SCREEN。

2. 程式骨架與 INCLUDE 命名慣例

Dialog 程式的程式碼會被拆成多支 INCLUDE，這不是規定而是SAP 的強慣例（SE80 建 Module Pool 時會自動照這個規則產生，Screen Painter 精靈也會照這個規則塞程式）。

INCLUDE 尾碼內容另一種常見寫法

ZXXX_O01PBO 的 MODULE … OUTPUTZXXX_PBO / ZXXX_O99
ZXXX_I01PAI 的 MODULE … INPUTZXXX_PAI / ZXXX_I99
ZXXX_F01FORM 副程式（Table Control 的標準 FORM 都放這）ZXXX_FRM / ZXXX_F99

*&---------------------------------------------------------------------*
REPORT ztc_mard_maint.

INCLUDE ztc_mard_maint_o01.    " PBO

  CALL SCREEN 0100.            " 再進入 Dialog
程式屬性、開發類別（Package）、傳輸請求都登記在 TADIR。查一支程式屬於哪個 Package、誰建的、是不是原廠物件，直接 SE16N 看 TADIR（OBJECT = 'PROG'、OBJ_NAME = 程式名）最快。
INCLUDE 寫在主程式的前面或後面效果相同（編譯時會全部串起來），但 TOP 一定要在最前面，因為宣告要先被看到。
Dialog 程式的所有 MODULE 與 FORM 都跑在同一個程式的全域資料區上。螢幕上的欄位名稱必須「等於某個全域資料物件的名稱」，例如螢幕欄位 GS_MARD-MATNR 對應到全域 DATA gs_mard TYPE mard.。這是 Dialog 程式跟 OO 封裝觀念最衝突的地方，也是它逐漸被 RAP 取代的原因之一。

3. SE51 Screen Painter：螢幕屬性與元素

設計一個螢幕固定四個步驟：

  1. 在屬性（Attributes）畫面設置常規螢幕屬性（編號、類型、Next Screen、大小）。
  2. 在佈局編輯器（Layout）設計版面，把元素拖上去。
  3. 在欄位清單（Element list）設置欄位屬性。
  4. 在流邏輯編輯器（Flow logic）寫 PBO／PAI。

螢幕編號的規則

  • 可通過「程式名 ＋ 螢幕編號」唯一識別一個螢幕。
  • 大於 9000 的螢幕編號為系統預留，不要用。
  • 1000～1010 保留給字典表的維護螢幕（SM30 產生的）以及可執行程式的標準選擇畫面。
  • 自己寫的建議從 0100 / 0200 / 2001 這類編號開始，並讓編號有規律（主畫面 0100、明細 0110、彈窗 0200…）。

4. 第一支 Dialog：Flow Logic、OK_CODE 與 CALL SCREEN

第 41 個練習：從螢幕設計到實作。目標：在螢幕上貼一個「NCU SAP！」的 Text 和一個按鈕，按下按鈕就退出整個程式。

  1. 建立螢幕：1. 定編號（2001）、2. 設 NORMAL 屬性、3. 設 Next Screen 屬性。
  2. 在 Layout 貼上 Text Field「NCU SAP！」與一個 Pushbutton，Pushbutton 的 FctCode = 'EXIT'。
  3. 在 Element list 加一個欄位 OK_CODE（型別 SY-UCOMM），這是接收功能碼的出口；同名變數也要在主程式宣告。
  4. Flow logic 裡把 MODULE USER_COMMAND_2001 的註解拿掉，雙擊建立模組。
  5. 主程式用 CALL SCREEN 2001. 進入畫面。
*&---------------------------------------------------------------------*
*& Report Z202202_41   " 第 41 練習：最小的 Dialog 程式
*&---------------------------------------------------------------------*
REPORT z202202_41.

DATA ok_code TYPE sy-ucomm.       " 螢幕上必須有一個同名的 OK_CODE 欄位
DATA gv_save_ok TYPE sy-ucomm.    " 慣例：先備份再清空，避免殘留

CALL SCREEN 2001.

*----------------------------------------------------------------------*
MODULE user_command_2001 INPUT.
  gv_save_ok = ok_code.
  CLEAR ok_code.                  " 一定要清，否則下一輪還會帶著舊值

  CASE gv_save_ok.
    WHEN 'EXIT'.
      MESSAGE '您可離開了' TYPE 'I'.
      LEAVE PROGRAM.
      " LEAVE TO SCREEN 9999. 也是一種寫法，但要看目前螢幕是否設定了 Next Screen
    WHEN OTHERS.
  ENDCASE.
ENDMODULE.

螢幕的 Flow logic 長這樣（雙引號的註解列是 SE51 預設產生的，要用哪一段就把星號拿掉）：

PROCESS BEFORE OUTPUT.
  MODULE status_2001.             " 設 PF-STATUS 與 Titlebar
  MODULE modify_screen.           " 動態控制欄位屬性
  MODULE initial.                 " 載入資料

PROCESS AFTER INPUT.
  MODULE cancel AT EXIT-COMMAND.  " ★ 一定放最前面，見第 5 節
  MODULE user_command_2001.
口訣：PBO 專職「螢幕的控制」（畫面長什麼樣）；PAI 專職「使用者輸入後的資料處理」（順序與邏輯）。 老師反覆強調這兩句，寫錯地方是初學者最常見的 bug 來源。
若程式很簡單，PAI 的 MODULE 可以直接寫在主程式裡，不必拆 INCLUDE；程式一長就務必拆。建議建立一支空程式，照著教材一步一步做一遍，才能理解每個章節要傳達的精神。

5. SE41 Menu Painter：PF-STATUS、Titlebar 與功能碼型別

Dialog 畫面的上方工具列、功能表、以及 F 鍵配置，都由 GUI Status（PF-STATUS）決定；視窗標題由 GUI Title（Titlebar）決定。兩者都可以在 SE80 的程式樹狀圖下建立，也可以用 SE41 單獨修改或複製。

*&---------------------------------------------------------------------*
*& Module STATUS_2001 OUTPUT     " PBO：畫面一出現就設定功能表與標題
*&---------------------------------------------------------------------*
MODULE status_2001 OUTPUT.
  SET PF-STATUS 'STATUS'.
  SET TITLEBAR  'TITLE'.
ENDMODULE.

" 進階：可以隱藏某些按鈕
" SET PF-STATUS 'STATUS' EXCLUDING VALUE #( ( 'DELE' ) ( 'INSR' ) ).
" 標題帶參數：GUI Title 內容寫成「銷售訂單 &1 明細」
" SET TITLEBAR 'TITLE' WITH lv_vbeln.

Status Type（狀態類型）

類型用在什麼螢幕
Normal screenDynpro Type = Normal 的全螢幕
Dialog boxDynpro Type = Modal Dialog Box 的彈出視窗（工具列會自動縮簡）
Context menu右鍵選單

Function Type（功能碼型別）——最容易被忽略卻最關鍵

Function Type行為用途
（空白）一般功能碼。會完整跑完 PAI（包含所有 FIELD 檢查）才進到 USER_COMMAND存檔、執行、查詢
EExit command。會跳過所有欄位檢查，直接執行 MODULE … AT EXIT-COMMANDBACK / EXIT / CANCEL
S系統功能（不進使用者程式）系統保留

最經典的坑：使用者填錯資料被 E 類訊息擋住，結果連「返回」都按不出去，只能砍掉 SAP GUI。 解法就是把 BACK／EXIT／CANCEL 的 Function Type 設成 E，並在 PAI 最前面寫 MODULE cancel AT EXIT-COMMAND.。講義原文明確寫著：「指定為 E 類的這一行應該移到前面，否則檢查不過時會無法跳離程式。」
*&---------------------------------------------------------------------*
*& Module CANCEL INPUT   " 掛在 AT EXIT-COMMAND，跳過所有欄位檢查
*&---------------------------------------------------------------------*
MODULE cancel INPUT.
  CASE ok_code.
    WHEN 'BACK'.   LEAVE TO SCREEN 0.   " 回上一層畫面
    WHEN 'EXIT'.   LEAVE PROGRAM.       " 離開整個程式
    WHEN 'CANCEL'. LEAVE TO SCREEN 0.
  ENDCASE.
ENDMODULE.

    WHEN 'MENU22'. MESSAGE '您點了 MENU22' TYPE 'I'.

    WHEN 'EXIT'.
      MESSAGE '您可離開了' TYPE 'I'.
      LEAVE PROGRAM.
    WHEN OTHERS.

重要觀念：若同時有多個 PF-STATUS，而 Function Code 同名時，代表它們會執行同一段程式（因為 CASE 判斷的是 ok_code 的值）。這是刻意設計——顯示模式與修改模式用兩個 STATUS，共用同一批功能碼。
系統保留鍵：F1（說明）、F2（形同雙擊）、F4（可能輸入值）、F9、Shift+F2、Shift+F4、Shift+F5，客製時勿佔用。另外選 Fiori 主題時，Function key 那一排（save / back / exit / cancel …）可能不顯示，只能靠鍵盤或功能表，設計時要留意。

6. 多螢幕的控制：SET SCREEN / LEAVE TO SCREEN / CALL SCREEN

螢幕的執行順序有兩種決定方式：

  • 靜態指定：在螢幕屬性的 Next Screen 欄位填下一個螢幕編號。填 0 表示「結束這一層、回到呼叫者」。
  • 動態指定：在 PAI 用指令改變流程。
指令行為備註
SET SCREEN n.把「下一個螢幕」暫時改成 n，但不會立刻跳，會把目前 PAI 跑完常與 LEAVE SCREEN 併用
LEAVE SCREEN.立刻結束目前螢幕，跳到 Next Screen
LEAVE TO SCREEN n.＝ SET SCREEN n ＋ LEAVE SCREEN最常用
LEAVE TO SCREEN 0.結束目前這一層，回到呼叫它的畫面（沒有上層就結束程式）BACK 鍵的標準寫法
CALL SCREEN n.堆疊式呼叫，n 結束後會回到原畫面的下一行做彈窗、做明細畫面
LEAVE PROGRAM.離開整支程式EXIT 鍵
LEAVE TO TRANSACTION 'XX'.跳到別的交易不回來
 
" ── 方式一：設定下一個 SCREEN ────────────────────────────────
SET SCREEN 300.
LEAVE SCREEN.
" 等價於： LEAVE TO SCREEN 300.

" ── 方式二：呼叫 SCREEN，結束後仍回到原 SCREEN ─────────────
CALL SCREEN 101.                     " 呼叫端
" …… 101 結束後，程式回到這一行的下一行

" 被呼叫的 101 要這樣結束：
"   SET SCREEN 0.
"   LEAVE SCREEN.          （或直接 LEAVE TO SCREEN 0.）

" ── 方式三：彈出視窗（螢幕屬性必須是 Modal Dialog Box）────────
CALL SCREEN 0200
  STARTING AT 10 5      " 左上角：column 10, row 5
  ENDING   AT 80 20.    " 右下角：column 80, row 20
彈出視窗必須同時滿足三個條件才會正常：(1) 螢幕屬性 Dynpro Type = Modal Dialog Box；(2) 呼叫時給 STARTING AT / ENDING AT；(3) 該畫面用的 GUI Status 的 Status Type = Dialog box。少一個就會變成怪怪的全螢幕或跑版。
不想自己畫彈窗時，先找標準 FM：POPUP_TO_CONFIRM（是／否）、POPUP_TO_DECIDE、POPUP_TO_INFORM、POPUP_WITH_TABLE_DISPLAY（選一列）、POPUP_GET_VALUES（臨時輸入欄位）。90% 的彈窗需求不必自己建 Screen。

7. 欄位動態控制：LOOP AT SCREEN 與 Group

第 03 節：單選按鈕 RADIO、框 BOX、輸入框的運用。 Radio 要兩個以上，貼好之後全選按右鍵 Define group 定成一群。把 FIELD2、FIELD3 的 Element list 中 Group1 設為 'SEL'，就可以在 PBO 一次控制整群。

*&---------------------------------------------------------------------*
*& Module MODIFY_SCREEN OUTPUT   " PBO：動態控制欄位屬性
*&---------------------------------------------------------------------*
MODULE modify_screen OUTPUT.
  LOOP AT SCREEN.
    IF screen-group1 = 'SEL'.        " GROUP1 = SEL 的整群不能輸入（FIELD2、FIELD3）
      screen-input = 0.
    ENDIF.

8. 在畫面上顯示與維護資料表

第 04 節。課程最開始建立了自己的資料表 Z00_VBAK，現在用 Screen 讓使用者維護它。從 Screen Painter 的「Get from Dictionary」把欄位拉上畫面時，欄位名稱會是 Z00_VBAK-XXXX，所以程式裡要有一個同名的全域結構。

寫法一：TABLES（講義原始寫法）

" 講義原寫法：TABLES 會產生一個同名全域工作區，剛好接上畫面欄位名
TABLES z00_vbak.

  SELECT SINGLE * FROM z00_vbak INTO @z00_vbak.  " 直接載入 TABLES 工作區
ENDMODULE.
SPEC 明訂 TABLES 屬於應淘汰的語法，在報表程式中一律不要用。但在 Dialog 程式中它有一個「無法完全避開」的用途：快速產生一個與資料表同名的全域工作區，好讓 Screen Painter 拉出來的欄位名對得上。現代做法是：自己宣告一個結構，並在 Screen Painter 中把欄位名改成該結構的名稱。

寫法二：自宣告工作區（現代寫法，建議）

*&---------------------------------------------------------------------*
*& Report Z202202_41   " 用自宣告的工作區承接畫面欄位
*&---------------------------------------------------------------------*

  " 只在第一次進畫面時載入，避免每次 PBO 都打 DB
  IF gs_vbak IS INITIAL.
    SELECT SINGLE vbeln, erdat, ernam, kunnr, netwr, waerk
      FROM z00_vbak
      INTO CORRESPONDING FIELDS OF @gs_vbak.

兩種寫法執行結果一樣。差別在於：用 TABLES 的工作區，Screen Painter 會自動帶出欄位抬頭（Label）；用自宣告的變數則不會自動顯示抬頭，要自己貼 Text Field 或在 Element list 手動指定 Dict. 參考。
老師的重要提醒：對筆數比較大的資料表，直接把整張表放在 Screen 上是不妥的做法——會影響效能，也會增加 LOCK 的機率。正確做法是「先用選擇畫面過濾 → 撈進內表 → 用 Table Control 分頁顯示」。

9. 欄位合理性檢查：FIELD、CHAIN、ON INPUT / ON REQUEST

第 05 節。PAI 裡最重要的兩個關鍵字是 FIELD 與 CHAIN。它們決定了「檢查失敗時，哪些欄位會保持可輸入狀態」——這是 Dialog 程式比選擇畫面強大的地方。

語法意義
FIELD f MODULE m.一律檢查。檢查失敗（E 訊息）時，只有 f 這個欄位保持可輸入
FIELD f MODULE m ON INPUT.欄位不為初始值時才觸發
FIELD f MODULE m ON REQUEST.欄位被改過（值與上次不同）時才觸發
CHAIN … ENDCHAIN.把多個欄位綁成一組；檢查失敗時整組都保持可輸入
MODULE m ON CHAIN-INPUT.CHAIN 中任一欄位不為空就觸發
MODULE m ON CHAIN-REQUEST.CHAIN 中任一欄位被改過就觸發（Table Control 的標準寫法）
MODULE m AT EXIT-COMMAND.只有 Function Type = E 的功能碼會觸發，跳過所有檢查
FIELD f VALUES (…).不寫程式的固定值檢查
FIELD f MODULE m AT CURSOR-SELECTION.游標停在該欄位並按 F2／雙擊時觸發
 
*----------------------------------------------------------------------*
*  Flow logic：PAI 的各種檢查寫法
*----------------------------------------------------------------------*
PROCESS AFTER INPUT.

  MODULE cancel AT EXIT-COMMAND.     " ★ E 類必須放最前面

  " 單個欄位檢查
  FIELD fld1 MODULE check1 ON REQUEST.   " 有修改才檢查
  FIELD fld2 MODULE check2 ON INPUT.     " 不為空就檢查
  FIELD fld3 MODULE check3.              " 一律檢查

  " 單個欄位、多個 MODULE
  FIELD fld1 MODULE check1a
             MODULE check1b.

  " 多欄位一起檢查：失敗時 FLD1~FLD4 都保持可輸入
  CHAIN.
    FIELD fld1.
    FIELD fld2, fld3, fld4.
    MODULE chk_all_1.
    MODULE chk_all_2.
  ENDCHAIN.

  " 只在「有輸入」時才檢查，避免不必要的檢查
  CHAIN.
    FIELD fld1.
    FIELD fld2, fld3, fld4.
    MODULE chk_all_1 ON CHAIN-INPUT.
    MODULE chk_all_2.
  ENDCHAIN.

  " 只在「有改變」時才檢查
  CHAIN.
    FIELD fld1.
    FIELD fld2, fld3, fld4.
    MODULE chk_all_1 ON CHAIN-REQUEST.
    MODULE chk_all_2.
  ENDCHAIN.

  MODULE user_command_2001.

*& 三個檢查模組（配合上面的 flow logic）
*&---------------------------------------------------------------------*
MODULE check1 INPUT.
  CASE fld1.
    WHEN 'NG'.  MESSAGE e005(ymess) WITH 'FLD1 ERROR'.     " E：停在本畫面
    WHEN 'NON'. MESSAGE i005(ymess) WITH 'FLD1 WARNING'.   " I：彈窗，按確定續行
    WHEN 'OK'.  MESSAGE s005(ymess) WITH 'FLD1 OK'.        " S：狀態列，續行
  ENDCASE.

MODULE check2 INPUT.
  CASE fld2.
    WHEN 'NG'.  MESSAGE e005(ymess) WITH 'FLD2 ERROR'.
    WHEN 'NON'. MESSAGE i005(ymess) WITH 'FLD2 WARNING'.
    WHEN 'OK'.  MESSAGE s005(ymess) WITH 'FLD2 OK'.

第 06 節。自定義訊息類別（Message Class）要以 Y 或 Z 起頭，用 SE91 建立，存在自己的 Package（課程是 ZP_CASPER）。

" 兩種等價的寫法

        DISPLAY LIKE 'I'                  " 只改「外觀」，行為仍是 E

TYPE意義在 Dialog（PAI）中的行為
SSuccess 成功訊息顯示在下一個畫面的狀態列。假設由 Screen 100 跳到 200，訊息會等到 200 開啟時才出現
IInformation 訊息即時彈出對話方塊，按確定後繼續原流程
WWarning 警告顯示在狀態列，欄位保持可輸入，按 Enter 可以繼續
EError 錯誤停在原畫面（Screen 100）且不重跑 PBO，只有 FIELD/CHAIN 涵蓋的欄位可再輸入
AAbend 異常終止終止交易，回到 SAP Easy Access（Dialog 少用）
XExit產生 short dump（Dialog 少用）
E 訊息不重跑 PBO是 Dialog 最容易誤判的行為：你在 PBO 裡設定的欄位屬性、下拉清單內容不會被重新計算，畫面停留在使用者剛剛看到的狀態。所以「E 訊息之後要順便改畫面」的需求做不到，要改用 W 或改用 SET SCREEN 重進。
前景／背景要區分訊息：背景（Batch）執行時 E／A 訊息會直接讓 Job 失敗，I／S 訊息只寫進 Job Log。程式要能前景也能背景執行的話，一定要用 IF sy-batch = abap_true. 分流，否則背景會在 E 訊息處掛掉。DISPLAY LIKE 'I' 只決定提示訊息的抬頭風格，不改變 E 的行為。

12. Subscreen 子畫面

第 08 節、第 19 節。Dynpro（Dynamic Program）＝ 一個螢幕 ＋ 它的 flow logic ＋ controls。Subscreen 讓你把畫面切成可替換的區塊，是 Tabstrip 與 SAP 標準增強（Screen Exit）的基礎。

作法

  1. 在主畫面 Layout 貼上 Subscreen Area（命名例如 SUB1）。
  2. 新增螢幕 2002，Dynpro Type 一定要選 Subscreen；貼上要顯示的元素後啟動。
  3. 同法建立第二個子螢幕 2003。
  4. 主程式宣告一個變數決定要顯示哪一個：DATA gv_screenid TYPE sy-dynnr VALUE '2002'.
  5. 主畫面 PBO 末尾加上 CALL SUBSCREEN；主畫面 PAI 對應加上 CALL SUBSCREEN（不帶 INCLUDING）。
*----------------------------------------------------------------------*
*  主畫面 2001 的 flow logic
*----------------------------------------------------------------------*
PROCESS BEFORE OUTPUT.
  MODULE status_2001.
  MODULE modify_screen.
  MODULE initial.
  MODULE list_values.
  " SY-REPID 表示當前主程式；gv_screenid 決定顯示哪一個子畫面
  CALL SUBSCREEN sub1 INCLUDING sy-repid gv_screenid.

PROCESS AFTER INPUT.
  MODULE cancel AT EXIT-COMMAND.
  CALL SUBSCREEN sub1.              " PAI 側只寫區域名，不帶 INCLUDING
  FIELD fld1 MODULE check1 ON REQUEST.
  FIELD fld2 MODULE check2 ON INPUT.
  FIELD fld3 MODULE check3.
  MODULE user_command_2001.
*&---------------------------------------------------------------------*
*& 由功能表決定顯示哪一個子畫面
*&---------------------------------------------------------------------*
DATA gv_screenid TYPE sy-dynnr VALUE '2002'.

MODULE user_command_2001 INPUT.
  DATA(lv_ok) = ok_code.
  CLEAR ok_code.

  gv_screenid = SWITCH #( lv_ok
                  WHEN 'MENU11' THEN '2002'      " 第一個子畫面
                  WHEN 'MENU12' THEN '2003'      " 第二個子畫面
                  ELSE gv_screenid ).

  CASE lv_ok.
    WHEN 'EXIT'. LEAVE PROGRAM.
    WHEN OTHERS.
  ENDCASE.
ENDMODULE.

呼叫 Subscreen 的鐵律（老師逐條列出）

  • 不可放在 LOOP … ENDLOOP 之內。
  • 不可放在 CHAIN … ENDCHAIN 之內。
  • 不必有自己的 OK_CODE。
  • Subscreen Area 的名稱不可重複。
  • 不會有 MODULE … AT EXIT-COMMAND。
  • 不會有自己的 Titlebar、PF-STATUS、SET SCREEN、LEAVE SCREEN。
  • Dynpro Type 必須是 Subscreen。

*  跨程式呼叫 Subscreen（Screen Exit / Enhancement 的核心機制）
*  情境：程式 A 的畫面 100，要嵌入程式 B（通常是 Function Group）的 0100
*----------------------------------------------------------------------*
PROCESS BEFORE OUTPUT.
  MODULE export_data.                              " 先把資料丟給 B
  CALL SUBSCREEN suba1 INCLUDING 'SAPLXXXX' '0100'.

PROCESS AFTER INPUT.
  MODULE user_exit_cmd AT EXIT-COMMAND.
  CALL SUBSCREEN suba1.
  MODULE import_data.                              " 再把 B 改過的值收回來
  FIELD f1 MODULE check_f1.
  CHAIN.
    FIELD f2, f3.

14. Table Control：觀念與精靈

第 12、13、20 節。Table Control 就是畫面上的「可編輯表格」。它跟 ALV Grid 的差別在於：Table Control 是 Dynpro 原生元件，欄位就是螢幕欄位，可以逐格控制屬性、逐格做 FIELD 檢查；而 ALV Grid 是 GUI Control（畫面外掛）。

比較Table ControlCL_GUI_ALV_GRID
本質Dynpro 元件GUI Control（Custom Container）
編輯天生可編輯，欄位級檢查最細要設 edit＝X，檢查靠事件
排序／篩選／匯出要自己寫內建
資料量幾百到幾千列還好（只送可見列）上萬列較佳
逐列不同屬性非常容易（迴圈內改 screen）要用 style 表
建議單據明細維護（表頭＋明細）報表、大量清單

什麼時候會觸動 PAI？（可用 /h Debug 實測）

  • 不會觸動 PAI：水平捲動、調整欄寬、移動欄位順序、選取行列。
  • 會觸動 PAI：垂直捲動、儲存版面設定（Save layout）、按任何功能鍵。
可以放進 Table Control 的資料來源，必須是 Transparent Table 或 Structure Type（DDIC 型別）。純程式內宣告的區域結構拉不進 Screen Painter，所以做 Table Control 之前，先在 SE11 建好一個 Structure——這是老師強調「設定較多，請善用精靈」的原因。

Table Control Wizard 的九個步驟

  1. 建立程式與螢幕，並在 Element list 加 OK_CODE。
  2. 在 Layout 拉出 Table Control Wizard（範圍不要拉太小，否則欄位塞不下）。
  3. Name of the table control：命名（例如 TC_MARD）。
  4. Table / Structure：指定 DDIC 來源（選 Dictionary），以及對應的內表名。
  5. Definition of Columns：選取要顯示在畫面上的欄位。
  6. Table control attributes：可否編輯、可否選取列、標題列等。
  7. Select additional table maintenance functions：勾選可捲動、插入列、刪除列、全選、取消全選——勾了精靈才會產生對應的 FORM。
  8. Set Includes：指定四支 INCLUDE（TOP／O01／I01／F01）。
  9. Finished：完成後回主程式，把資料撈進內表，再 CALL SCREEN。
老師的話：「Table Control Wizard 所產生的代碼也重要，必須仔細的閱讀。我們手動新增時會用到。」 第 13 節就是要你不靠精靈再做一次（貼 Table Control 而不是 Table Control Wizard），才會真的懂。

Table Control 的核心變數

CONTROLS: tc_mard TYPE TABLEVIEW USING SCREEN 0100.
" tc_mard 的型別實際上是 DDIC 結構 CXTAB_CONTROL，重要欄位：

" tc_mard-lines        總列數（決定捲軸長度）→ PBO 一定要設
" tc_mard-top_line     目前顯示的第一列在內表中的索引 → 控制捲動位置
" tc_mard-current_line PAI 迴圈中「目前這一列」在內表中的索引 → MODIFY 用
" tc_mard-cols[]       欄位屬性內表（可改順序、寬度、是否可見）
" tc_mard-invisible    整個 TC 隱藏
" tc_mard-v_scroll / h_scroll  是否顯示捲軸

" 另兩個系統欄位：
" sy-loopc  PBO 迴圈中：畫面上「實際可見的列數」→ 捲動計算必備
" sy-stepl  迴圈中：目前是畫面上的第幾列（1..sy-loopc）→ 逐列改屬性用

15. Table Control 的 Flow Logic 與同步機制

Table Control 最難懂的地方在「畫面的可見列」與「內表的所有列」是兩回事。PBO 的 LOOP 負責把內表倒進畫面，PAI 的 LOOP 負責把畫面倒回內表。

*----------------------------------------------------------------------*
*  PBO：把內表倒進畫面
*----------------------------------------------------------------------*
PROCESS BEFORE OUTPUT.
  MODULE status_0100.

*&SPWIZARD: PBO FLOW LOGIC FOR TABLECONTROL 'TC_MARD'
  MODULE tc_mard_change_tc_attr.       " 設定 lines（捲軸長度）
* MODULE tc_mard_change_col_attr.      " 需要時：整欄屬性（永久性修改）

  LOOP AT   gt_mard
       INTO gs_mard                    " ★ 沒有 header line 的現代寫法
       WITH CONTROL tc_mard
       CURSOR tc_mard-current_line.
    MODULE tc_mard_get_lines.          " 記住 sy-loopc
    MODULE tc_mard_change_field_attr.  " 逐列屬性（暫時性修改）
  ENDLOOP.
*----------------------------------------------------------------------*
*  PAI：把畫面倒回內表
*----------------------------------------------------------------------*
PROCESS AFTER INPUT.
  MODULE exit_0100 AT EXIT-COMMAND.    " ★ E 類放最前面

*&SPWIZARD: PAI FLOW LOGIC FOR TABLECONTROL 'TC_MARD'
  LOOP AT gt_mard.                     " 注意：PAI 的 LOOP 不帶 INTO
    CHAIN.
      FIELD gs_mard-matnr.
      FIELD gs_mard-werks.
      FIELD gs_mard-lgort.
      FIELD gs_mard-labst.
      MODULE tc_mard_modify ON CHAIN-REQUEST.   " 有改才寫回內表
    ENDCHAIN.
    FIELD gs_mard-mark
      MODULE tc_mard_mark ON REQUEST.            " 勾選欄單獨處理
  ENDLOOP.

  MODULE tc_mard_user_command.
*&---------------------------------------------------------------------*
*& PBO 的兩個模組
*&---------------------------------------------------------------------*
MODULE tc_mard_change_tc_attr OUTPUT.
  " ★ 一定要設 lines，否則捲軸長度不對、捲不到最後一列
  DESCRIBE TABLE gt_mard LINES tc_mard-lines.
ENDMODULE.

MODULE tc_mard_get_lines OUTPUT.
  " sy-loopc = 這一輪畫面上實際顯示了幾列，捲動計算要用
  g_tc_mard_lines = sy-loopc.
ENDMODULE.

*&---------------------------------------------------------------------*
*& PAI 的寫回模組：TC 與內表同步的關鍵一行
*&---------------------------------------------------------------------*
MODULE tc_mard_modify INPUT.
  MODIFY gt_mard
    FROM gs_mard
    INDEX tc_mard-current_line.        " ★ 用 current_line，不是 sy-tabix
ENDMODULE.
Table Control 三大經典 bug：
(1) 忘記 DESCRIBE TABLE … LINES tc-lines → 捲軸不動、只看得到第一頁。
(2) MODIFY 時用了 sy-tabix 而不是 tc-current_line → 改 A 列卻寫到 B 列，最常在捲動後爆出來。
(3) PAI 沒有 MODIFY → 使用者輸入的值在下一次 PBO 被內表原值蓋回去，看起來像「改了又跳回來」。

永久性 vs 暫時性屬性修改

PBO 中 LOOP 之前改 tc-cols 屬於永久性修改（整欄一致）；LOOP 之內改 screen-… 屬於暫時性修改（只影響當列）。善加利用，可以做到「不同列屬性不同」，例如第二、四列必填。

*&---------------------------------------------------------------------*
*& 永久性修改：整欄變唯讀 / 調整欄位順序
*&---------------------------------------------------------------------*
MODULE tc_mard_change_col_attr OUTPUT.
  LOOP AT tc_mard-cols ASSIGNING FIELD-SYMBOL(<ls_col>).
    CASE <ls_col>-screen-name.
      WHEN 'GS_MARD-MATNR' OR 'GS_MARD-WERKS' OR 'GS_MARD-LGORT'.
        <ls_col>-screen-input = 0.        " 主鍵欄整欄唯讀
      WHEN 'GS_MARD-LABST'.
        <ls_col>-index = 4.               " 調整這一欄的顯示順序
    ENDCASE.
  ENDLOOP.
ENDMODULE.

*&---------------------------------------------------------------------*
*& 暫時性修改：逐列不同（放在 PBO 的 LOOP 之內）
*&---------------------------------------------------------------------*
MODULE tc_mard_change_field_attr OUTPUT.
  LOOP AT SCREEN.
    " 已存在 DB 的列，主鍵不給改；新增列（NEW 旗標）才可以改
    IF gs_mard-newrow <> abap_true
       AND screen-name CS 'MATNR'.
      screen-input = 0.
    ENDIF.
    " 偶數列的數量欄設成必填（示範暫時性修改的威力）
    IF sy-stepl MOD 2 = 0 AND screen-name CS 'LABST'.
      screen-required = 1.
    ENDIF.
    MODIFY SCREEN.
  ENDLOOP.
ENDMODULE.

    FROM mard
    WHERE matnr IN @s_matnr
      AND werks IN @s_werks
      AND lgort IN @s_lgort
    ORDER BY matnr, werks, lgort
    INTO CORRESPONDING FIELDS OF TABLE @gt_mard
    UP TO 1000 ROWS.

  gt_orig = gt_mard.                    " 保留快照，存檔時比對
  CLEAR: gv_changed.
  tc_mard-top_line = 1.
ENDFORM.

*----------------------------------------------------------------------*
FORM save_data.
  " 只挑真的有變動的列
  DATA(lt_upd) = VALUE tt_zstc_mard(
    FOR ls IN gt_mard
    WHERE ( matnr IS NOT INITIAL )
    ( COND #( WHEN NOT line_exists( gt_orig[ matnr = ls-matnr
                                             werks = ls-werks
                                             lgort = ls-lgort
                                             labst = ls-labst
                                             insme = ls-insme
                                             speme = ls-speme ] )
              THEN ls ) ) ).
  DELETE lt_upd WHERE matnr IS INITIAL.

  IF lt_upd IS INITIAL.
    MESSAGE '沒有需要儲存的異動' TYPE 'S'.
    RETURN.
  ENDIF.

  " ── 鎖定 ──
  LOOP AT lt_upd INTO DATA(ls_upd).
    CALL FUNCTION 'ENQUEUE_EMMARD'
      EXPORTING
        mode_mard      = 'E'
        mandt          = sy-mandt
        matnr          = ls_upd-matnr
        werks          = ls_upd-werks
        lgort          = ls_upd-lgort
        _scope         = '2'
      EXCEPTIONS
        foreign_lock   = 1
        system_failure = 2
        OTHERS         = 3.
    IF sy-subrc <> 0.
      MESSAGE |物料 { ls_upd-matnr } 已被 { sy-msgv1 } 鎖定| TYPE 'E'.
      RETURN.
    ENDIF.
  ENDLOOP.

  " ── 寫回 ──
  " ★ 實務上庫存數量絕不可以直接 UPDATE MARD，必須走 MIGO / BAPI_GOODSMVT_CREATE。
  "   這裡僅示範 Table Control 的存檔骨架，請換成自建 Z 表或 BAPI。
  TRY.
      MODIFY zstc_stock FROM TABLE @lt_upd.
      IF sy-subrc = 0.
        COMMIT WORK AND WAIT.
        gt_orig = gt_mard.
        CLEAR gv_changed.
        MESSAGE |已儲存 { lines( lt_upd ) } 筆| TYPE 'S'.
      ELSE.
        ROLLBACK WORK.
        MESSAGE '存檔失敗' TYPE 'E'.
      ENDIF.
    CATCH cx_sy_open_sql_db INTO DATA(lx_db).
      ROLLBACK WORK.
      MESSAGE lx_db->get_text( ) TYPE 'E'.
  ENDTRY.

  PERFORM unlock_all.
ENDFORM.

*----------------------------------------------------------------------*
FORM unlock_all.
  CALL FUNCTION 'DEQUEUE_ALL'.          " 最省事的全解鎖
ENDFORM.

*----------------------------------------------------------------------*
FORM sort_tc USING p_dir TYPE c.
  " Table Control 沒有內建排序，要自己排內表
  IF p_dir = 'A'.
    SORT gt_mard BY matnr ASCENDING werks ASCENDING lgort ASCENDING.
  ELSE.
    SORT gt_mard BY matnr DESCENDING werks DESCENDING lgort DESCENDING.
  ENDIF.
  tc_mard-top_line = 1.                 " 排完回到第一列
ENDFORM.
絕對不要直接 UPDATE MARD / MARC / MBEW。 在 S/4HANA 中庫存主檔仍由 MM 模組維護，數量異動必須走 MIGO / BAPI_GOODSMVT_CREATE；物料主檔異動走 BAPI_MATERIAL_SAVEDATA。上面的範例只是拿 MARD 當「畫面上的資料來源」示範 Table Control 的骨架，實際存檔請改寫進自建的 Z 表或呼叫 BAPI。

17. Table Control 的標準 FORM：插入、刪除、捲動、全選

精靈產生的 TABLECONTROL_FORMS 這一段程式是 SAP 的標準寫法，用 Field Symbol ＋ 動態 ASSIGN 做到「一套 FORM 服務所有 Table Control」。手動建 Table Control 時，把這一段複製過去就好。

17.1 總入口 USER_OK_TC

*&---------------------------------------------------------------------*
*&      Form  USER_OK_TC   " 攔截所有 <TC 名稱>_<動作> 格式的功能碼
*&---------------------------------------------------------------------*
FORM user_ok_tc USING    p_tc_name    TYPE dynfnam
                         p_table_name
                         p_mark_name
                CHANGING p_ok         TYPE sy-ucomm.

  DATA: l_ok     TYPE sy-ucomm,
        l_offset TYPE i.

  " 功能碼必須以 TC 名稱開頭，例如 TC_MARD_INSR
  SEARCH p_ok FOR p_tc_name.
  IF sy-subrc <> 0.
    EXIT.                               " 不是 TC 的功能碼，交回主流程
  ENDIF.
  l_offset = strlen( p_tc_name ) + 1.
  l_ok = p_ok+l_offset.

  CASE l_ok.
    WHEN 'INSR'.                        " 插入列
      PERFORM fcode_insert_row USING p_tc_name p_table_name.
      CLEAR p_ok.

    WHEN 'DELE'.                        " 刪除列
      PERFORM fcode_delete_row USING p_tc_name p_table_name p_mark_name.
      CLEAR p_ok.

    WHEN 'P--' OR                       " 第一頁
         'P-'  OR                       " 上一頁
         'P+'  OR                       " 下一頁
         'P++'.                         " 最後一頁
      PERFORM compute_scrolling_in_tc USING p_tc_name l_ok.
      CLEAR p_ok.

    WHEN 'MARK'.                        " 全選
      PERFORM fcode_tc_mark_lines USING p_tc_name p_table_name p_mark_name.
      CLEAR p_ok.

    WHEN 'DMRK'.                        " 取消全選
      PERFORM fcode_tc_demark_lines USING p_tc_name p_table_name p_mark_name.
      CLEAR p_ok.

*   WHEN 'L--' OR 'L-' OR 'R+' OR 'R++'.   " 水平捲動（精靈預設註解掉）
*   WHEN 'SASCEND' OR 'SDESCEND'.          " 欄位排序（要自己實作）
  ENDCASE.
ENDFORM.
口訣：Table Control 的功能碼＝「TC 名稱 ＋ 底線 ＋ 動作」，例如 TC 叫 TC_MARD，插入列就是 TC_MARD_INSR、刪除是 TC_MARD_DELE、全選是 TC_MARD_MARK、下一頁是 TC_MARD_P+。在 SE41 建 GUI Status 時就照這個規則命名，USER_OK_TC 才攔得到。

17.2 插入列

*&---------------------------------------------------------------------*
*&      Form  FCODE_INSERT_ROW
*&---------------------------------------------------------------------*
FORM fcode_insert_row USING p_tc_name TYPE dynfnam
                            p_table_name.

  DATA: l_lines_name TYPE feld-name,
        l_selline    TYPE sy-stepl,
        l_lastline   TYPE i,
        l_line       TYPE i,
        l_table_name TYPE feld-name.

  FIELD-SYMBOLS: <tc>    TYPE cxtab_control,
                 <table> TYPE STANDARD TABLE,
                 <lines> TYPE i.

  ASSIGN (p_tc_name) TO <tc>.

  " 取得 TC 所對應的內表（加 [] 表示表體，不是 header line）
  l_table_name = |{ p_table_name }[]|.
  ASSIGN (l_table_name) TO <table>.

  " 取得畫面可見列數變數 G_<TC 名稱>_LINES
  l_lines_name = |G_{ p_tc_name }_LINES|.
  ASSIGN (l_lines_name) TO <lines>.

  " 游標在哪一列？
  GET CURSOR LINE l_selline.
  IF sy-subrc <> 0.                     " 游標不在表內 → 追加到最後
    l_selline = <tc>-lines + 1.
    IF l_selline > <lines>.
      <tc>-top_line = l_selline - <lines> + 1.
    ELSE.
      <tc>-top_line = 1.
    ENDIF.
  ELSE.                                 " 游標在表內 → 插在游標那一列
    l_selline  = <tc>-top_line + l_selline - 1.
    l_lastline = <tc>-top_line + <lines> - 1.
  ENDIF.
  l_line = l_selline - <tc>-top_line + 1.

  INSERT INITIAL LINE INTO <table> INDEX l_selline.
  <tc>-lines = <tc>-lines + 1.
  SET CURSOR LINE l_line.
ENDFORM.

17.3 刪除列（依 MARK 欄）

*&---------------------------------------------------------------------*
*&      Form  FCODE_DELETE_ROW
*&---------------------------------------------------------------------*
FORM fcode_delete_row USING p_tc_name TYPE dynfnam
                            p_table_name
                            p_mark_name.

  DATA l_table_name TYPE feld-name.
  FIELD-SYMBOLS: <tc>         TYPE cxtab_control,
                 <table>      TYPE STANDARD TABLE,
                 <wa>         TYPE any,
                 <mark_field> TYPE any.

  ASSIGN (p_tc_name) TO <tc>.
  l_table_name = |{ p_table_name }[]|.
  ASSIGN (l_table_name) TO <table>.

  DESCRIBE TABLE <table> LINES <tc>-lines.

  LOOP AT <table> ASSIGNING <wa>.
    ASSIGN COMPONENT p_mark_name OF STRUCTURE <wa> TO <mark_field>.
    IF <mark_field> = 'X'.
      DELETE <table> INDEX syst-tabix.
      IF sy-subrc = 0.
        <tc>-lines = <tc>-lines - 1.
      ENDIF.
    ENDIF.
  ENDLOOP.
ENDFORM.
SAP 這段標準碼在 LOOP 中 DELETE 同一張表。它之所以「能動」，是因為 DELETE 之後 sy-tabix 的後續處理剛好抵銷；但這是脆弱寫法。自己寫時建議改成一行：DELETE gt_mard WHERE mark = abap_true.，再重設 tc-lines，既安全又快。

17.4 垂直捲動

*&---------------------------------------------------------------------*
*&      Form  COMPUTE_SCROLLING_IN_TC   " 用標準 FM 算出新的 top_line
*&---------------------------------------------------------------------*
FORM compute_scrolling_in_tc USING p_tc_name
                                   p_ok.
  DATA: l_tc_new_top_line TYPE i,
        l_tc_name         TYPE feld-name,
        l_tc_lines_name   TYPE feld-name,
        l_tc_field_name   TYPE feld-name.

  FIELD-SYMBOLS: <tc>    TYPE cxtab_control,
                 <lines> TYPE i.

  ASSIGN (p_tc_name) TO <tc>.
  l_tc_lines_name = |G_{ p_tc_name }_LINES|.
  ASSIGN (l_tc_lines_name) TO <lines>.

  IF <tc>-lines = 0.                    " 沒有任何一列
    l_tc_new_top_line = 1.
  ELSE.
    CALL FUNCTION 'SCROLLING_IN_TABLE'
      EXPORTING
        entry_act      = <tc>-top_line
        entry_from     = 1
        entry_to       = <tc>-lines
        last_page_full = 'X'
        loops          = <lines>
        ok_code        = p_ok
        overlapping    = 'X'
      IMPORTING
        entry_new      = l_tc_new_top_line
      EXCEPTIONS
        OTHERS         = 0.
  ENDIF.

  " 捲動後把游標放回同一欄的第一列
  GET CURSOR FIELD l_tc_field_name AREA l_tc_name.
  IF syst-subrc = 0 AND l_tc_name = p_tc_name.
    SET CURSOR FIELD l_tc_field_name LINE 1.
  ENDIF.

  <tc>-top_line = l_tc_new_top_line.
ENDFORM.

17.5 全選 / 取消全選

*&---------------------------------------------------------------------*
*&      Form  FCODE_TC_MARK_LINES / FCODE_TC_DEMARK_LINES
*&---------------------------------------------------------------------*

ENDFORM.

18. Custom Control：把 ALV、編輯器、圖片、HTML 掛上畫面

第 10 節。Custom Control 是一塊「保留區」，執行時由 CL_GUI_CUSTOM_CONTAINER 接管，然後在裡面放任何 GUI Control。作法固定三步：建 Container → 建 Control → 餵資料，而且要用 IF gv_init IS INITIAL. 保證只建一次（PBO 每次都會跑）。

18.1 文字編輯器 CL_GUI_TEXTEDIT

*&---------------------------------------------------------------------*
*& TOP：宣告
*&---------------------------------------------------------------------*
DATA: gv_init      TYPE abap_bool,
      go_container TYPE REF TO cl_gui_custom_container,
      go_editor    TYPE REF TO cl_gui_textedit.

" 編輯器的內容用 80 碼的字元表承接
TYPES: ty_line TYPE c LENGTH 80.
DATA  gt_text TYPE STANDARD TABLE OF ty_line WITH EMPTY KEY.

INITIALIZATION.
  gt_text = VALUE #( ( '請在此開始輸入' ) ).
*&---------------------------------------------------------------------*
*& Module STATUS_2001 OUTPUT   " PBO：建立 Container 與文字編輯器
*&---------------------------------------------------------------------*
MODULE status_2001 OUTPUT.
  SET PF-STATUS 'STATUS'.
  SET TITLEBAR  'TITLE'.

  IF gv_init IS INITIAL.
    " ★ container_name 必須等於 Layout 上 Custom Control 的名稱
    go_container = NEW cl_gui_custom_container( container_name = 'CUSCON' ).

    IF go_container IS BOUND.
      go_editor = NEW cl_gui_textedit(
        parent                     = go_container
        wordwrap_mode              = cl_gui_textedit=>wordwrap_at_fixed_position
        wordwrap_position          = 80
        wordwrap_to_linebreak_mode = cl_gui_textedit=>true ).

      " 隱藏編輯器自己的工具列與狀態列（要更像 SAP 原生畫面時）
      go_editor->set_toolbar_mode( 0 ).
      go_editor->set_statusbar_mode( 0 ).

  ENDIF.

  go_editor->set_text_as_r3table( table = gt_text ).
ENDMODULE.

*&---------------------------------------------------------------------*
*& PAI：把使用者打的字取回來（★ 一定要先 flush，否則拿到舊值）
*&---------------------------------------------------------------------*
MODULE get_editor_text INPUT.
  cl_gui_cfw=>flush( ).
  go_editor->get_text_as_r3table( IMPORTING table = gt_text ).
ENDMODULE.
GUI Control 的黃金定律：所有 get_* 之前一定要 cl_gui_cfw=>flush( )，因為 Control 的值住在前端（SAP GUI），不 flush 就拿不到使用者最新輸入的內容。這是 Custom Control 最常見的「值抓不到」原因。

    WHEN 'CANCEL'. SET SCREEN 0.        " ← 第一次設計時就是漏了這段
  ENDCASE.
  CLEAR ok_code.
ENDMODULE.
講義原程式寫的是 name = ' ICON_FAILURE'，前面多了一個空白，會直接觸發 ICON_NOT_FOUND。這種「看不出來的空白」在 ICON_CREATE、SET PF-STATUS、CALL TRANSACTION 都很常見，抓不到圖示時第一個先檢查它。

Parameter ID 無所不在

20. S/4HANA 的定位：Dialog 程式還要不要寫？

這是 2025 年學 Module Pool 一定要先想清楚的問題。答案不是「不要寫」，而是「看情境選工具」。

情境建議做法理由
簡單的 Z 表維護SM30 / SE54 表維護產生器零程式碼，自動有鎖定、傳輸、變更記錄
查詢型報表SELECT-OPTIONS ＋ CL_SALV_TABLE不必畫 Screen，維護成本最低
報表 ＋ 少量編輯CL_GUI_ALV_GRID（可編輯 ALV）比 Table Control 好寫，內建排序篩選匯出
單據式維護（表頭 ＋ 多明細 ＋ 頁籤）且使用者只用 SAP GUIModule Pool ＋ Table Control ＋ TabstripDialog 仍是 GUI 上最完整的解
要在瀏覽器 / 手機上用RAP ＋ Fiori Elements（CDS ＋ Behavior Definition ＋ OData V4）Dialog 不可能上 Fiori Launchpad
要擴充標準交易的畫面Screen Exit / BAdI 的 Subscreen本章第 12 節的跨程式 Subscreen 機制
雲端 ABAP（BTP / Public Cloud）只能 RAPDynpro 相關語法在 ABAP Cloud 中不在白名單內，語法檢查直接擋掉
ABAP Cloud 的硬限制：在 S/4HANA Cloud、BTP ABAP Environment，或在 on-premise 用「ABAP for Cloud Development」語言版本時，CALL SCREEN、Dynpro、Table Control、CL_GUI_* 全部不可用。所以新專案若有「未來要上雲」的規劃，Dialog 就不該再開新的。反之，S/4HANA on-premise 的 Classic ABAP 版本仍完整支援 Dialog，SAP 也還在用（VA01、ME21N 至今仍是 Dynpro）。
老師的實務觀察：有些公司會用 ABAP 開發 SAP 模組以外的功能。 遇到這種情境，你還要繼續精進 Screen 設計技巧——例如 ME21N 的結構就包含「左側導航欄 ＋ 主階 HEADER ＋ 子階 ITEM OVERVIEW ＋ 子階再展開的 ITEM DETAIL」，那是 Subscreen ＋ Tabstrip ＋ Table Control 的綜合體。想學畫面設計，直接拆 ME21N 是最好的教材。
