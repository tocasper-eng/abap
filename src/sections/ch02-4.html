1. 為什麼要模組化：五種手法與選用原則

模組化就是「把程式中一段原始碼獨立出來、封裝成一個特定功能」。講義列的四大好處：提高程式透明度、提高程式碼重用、簡化程式維護、方便程式呼叫。最典型的例子就是「取得每月最後一天」「把檔案上傳成內表」這種到處都要用的小功能。

手法可見範圍參數可否 DebugS/4HANA 建議
METHOD（本地／全域類別）本地類別＝程式內；全域類別（SE24）＝全系統IMPORTING／EXPORTING／CHANGING／RETURNING／RAISING，強型別可，且可單元測試首選。新程式一律寫方法
FUNCTION MODULE全系統（必須放在 Function Group 內）IMPORT／EXPORT／CHANGING／TABLES／EXCEPTIONS可（SE37 可直接測）仍在用。RFC／Update／BAPI 目前只能用 FM
FORM（副程式 Subroutine）同程式內（可用 PERFORM ... IN PROGRAM 外部呼叫）USING／CHANGING／TABLES，型別可有可無可已宣告過時，只維護不新寫；ABAP Cloud 禁用
MACRO（DEFINE）同程式內（或 TRMAC 表的全域巨集）&1～&9，無型別不可 debug不建議。只在極短的重複賦值場合殘留
INCLUDE編譯期文字插入，不是真正的模組無參數（共用全域變數）可（就是主程式的一部分）可用，但只用來「切檔案」，不要當封裝手段

參數（Parameter）的用途是「在呼叫程式與模組單元之間交換資料」，定義模組時就決定了有哪些參數。講義的三分法：

  • 輸入參數（Importing／USING）：把資料傳給模組。
  • 匯出參數（Exporting／CHANGING 的回傳側）：把模組內的結果送回呼叫程式。
  • 變更參數（Changing）：傳進去、改完再傳回來。
老師的口訣（第 10-8 節）：「模組化共有五種手法：FUNCTION、FORM、DEFINE、CLASS、INCLUDE。」面試常問，記起來。真正要選的時候，順序是：CLASS > FUNCTION > FORM > DEFINE，INCLUDE 只是切檔案用的輔助。

講義開頭那段 FORM SET_AMOUNT 是很典型的「幣別換算後改寫內表」場景。以下是同一段邏輯改寫成 S/4HANA 現代語法的樣子（把 FORM 改成本地類別方法、內表用 FIELD-SYMBOL 就地修改）：

CLASS lcl_amount DEFINITION.
  PUBLIC SECTION.
    " 依幣別的小數位換算係數，就地調整 ACDOCA 的三個金額欄位
    METHODS set_amount
      IMPORTING iv_waers  TYPE waers
      CHANGING  ct_acdoca TYPE ty_t_acdoca.
ENDCLASS.

CLASS lcl_amount IMPLEMENTATION.
  METHOD set_amount.
    DATA(lv_factor) = CONV i( 1 ).           " 預設係數 1

    CALL FUNCTION 'CURRENCY_CONVERTING_FACTOR'
      EXPORTING  currency          = iv_waers
      IMPORTING  factor            = lv_factor
      EXCEPTIONS too_many_decimals = 1
                 OTHERS            = 2.
    IF sy-subrc <> 0.
      lv_factor = 1.                          " 取不到就當 1，不要讓金額變 0
    ENDIF.

    " 舊寫法是 LOOP ... MODIFY it FROM wa；現代用 FIELD-SYMBOL 就地改，快且不必 MODIFY
    LOOP AT ct_acdoca ASSIGNING FIELD-SYMBOL(<ls>).
      <ls>-wsl = <ls>-wsl * lv_factor.        " 交易貨幣金額
      <ls>-tsl = <ls>-tsl * lv_factor.        " 公司代碼貨幣金額
      <ls>-ksl = <ls>-ksl * lv_factor.        " 集團貨幣金額
    ENDLOOP.
  ENDMETHOD.
ENDCLASS.
S/4HANA：ACDOCA 是「通用日記帳（Universal Journal）」，FI（BSEG/BKPF）、CO（COEP/COBK）、AA、ML 的行項目全部落在這一張表。舊程式若還在讀 BSEG 做金額彙總，在 S/4 會抓不到 CO 的資料，也享受不到 HANA 的欄位式壓縮。

2. FORM／PERFORM：語法、USING、CHANGING、TABLES

副程式（Subroutine）是「原始碼裡具有一定獨立功能的模組單元」，用 FORM 開頭、ENDFORM 結尾。分兩類：

  • 內部副程式：原始碼與呼叫程式在同一支 ABAP 程式中。
  • 外部副程式：原始碼在別支程式裡，用 PERFORM form IN PROGRAM prog 呼叫。

基本規則（講義重點）：

  • 語法：FORM <subroutine> [<pass>]. ... ENDFORM.，參數段可以完全省略。
  • 副程式可以直接存取主程式宣告的所有全域變數 —— 這正是它最大的坑。
  • 同一程式的所有內部副程式，習慣集中放在程式最末端（或獨立成 F01 include）。
  • 副程式的定義不能互相巢狀（FORM 裡不能再寫 FORM），但可以互相呼叫、也可以遞迴。
  • 形式參數（formal parameters）＝ FORM 上宣告的；實際參數（actual parameters）＝ PERFORM 傳進去的。
REPORT zdemo_form.

PERFORM welcome.                 " 呼叫副程式

DATA(lv_str1) = |Hello|.
DATA(lv_str2) = |SAP|.
PERFORM con_str USING lv_str1 lv_str2.

*&--- 副程式定義 -------------------------------------------------------*
FORM welcome.
  WRITE / 'Subroutine'.
ENDFORM.

FORM con_str USING iv_s1 TYPE string
                   iv_s2 TYPE string.
  " 舊講義用 CONCATENATE，現代一律用字串範本
  DATA(lv_all) = |{ iv_s1 } { iv_s2 }|.
  WRITE / lv_all.
ENDFORM.

三種參數段的差別：

寫法傳遞方式語意
USING pCall by reference（傳址）語意上是「只讀」，但 ABAP 不會擋你改，改了外面真的會變
USING VALUE(p)Call by value（傳值）副程式內改動不影響外部變數
CHANGING pCall by reference明確表示「要改」
CHANGING VALUE(p)Call by value and result執行中不影響外部；ENDFORM 正常結束時才把值寫回
TABLES pCall by reference，內表已過時：參數會被當成帶表頭行（header line）的內表
CHANGING VALUE( ) 的隱藏陷阱：值是在 ENDFORM 正常結束時才回寫。如果副程式中途遇到 MESSAGE ... TYPE 'E'、EXIT 離開程式或發生例外，回寫不會發生，呼叫端拿到的還是舊值。這種 bug 非常難查。
TABLES 參數已過時：FORM f TABLES it STRUCTURE mara. 語法檢查會出現「過時」警告。改用型別化的 USING／CHANGING。注意 FORM f USING it TYPE TABLE OF mara 是錯的 —— FORM 的參數只能用「已存在的型別名稱」或泛型型別（TYPE STANDARD TABLE、TYPE INDEX TABLE、TYPE ANY TABLE），不能在參數列上就地 TABLE OF。正確寫法見下例。
*&--- 新方法：用 TYPES 先定義表型別，再給 FORM 參數強型別 -------------*
TYPES ty_t_mara TYPE STANDARD TABLE OF mara WITH EMPTY KEY.

DATA: lt_input  TYPE ty_t_mara,
      lt_output TYPE ty_t_mara.

PERFORM process_data USING lt_input CHANGING lt_output.

FORM process_data USING    it_input  TYPE ty_t_mara
                  CHANGING ct_output TYPE ty_t_mara.
  " 只挑出成品（FERT）
  ct_output = VALUE #( FOR ls IN it_input
                       WHERE ( mtart = 'FERT' )
                       ( ls ) ).
ENDFORM.

*&--- 舊方法（講義原文，S/4 請勿再寫）---------------------------------*
* FORM process_data TABLES it_input  STRUCTURE mara
*                          it_output STRUCTURE mara.
*   LOOP AT it_input INTO DATA(ls_input).
*     IF ls_input-mtart = 'FERT'.
*       APPEND ls_input TO it_output.
*     ENDIF.
*   ENDLOOP.
* ENDFORM.
* PERFORM process_data TABLES lt_input lt_output.
S/4HANA 與 ABAP Cloud 的定調：FORM／PERFORM 自 ABAP Objects 推出後就被 SAP 標示為 obsolete；在 ABAP Cloud（ABAP for Cloud Development、BTP ABAP Environment、S/4HANA Cloud 的開發模型）中被完全禁止，語法檢查直接報錯。原因：無法完整型別檢查、沒有 RETURNING、無法單元測試、全域變數污染。舊程式維護可以留，新程式一律改寫成類別方法。

3. 三種傳參方式的實證：傳址、傳值、傳值並回傳

講義用三支小程式（ZPU300_06、Z202202_29/30/31）示範同一件事，把三種方式的差異壓在同一個算式上。這裡合併成一支現代寫法的示範程式，一次跑完三種。

REPORT zdemo_pass_by.

DATA: lv_a TYPE i VALUE 1,
      lv_b TYPE i VALUE 2,
      lv_c TYPE i VALUE 0.

*--- 方式一：call by reference（傳址）------------------------------*
PERFORM frm_ref USING lv_a lv_b lv_c.
WRITE: / |方式一 main a={ lv_a } b={ lv_b } c={ lv_c }|.

*--- 方式二：call by value（傳值）----------------------------------*
lv_a = 1. lv_b = 2. lv_c = 0.
PERFORM frm_val USING lv_a lv_b lv_c.
WRITE: / |方式二 main a={ lv_a } b={ lv_b } c={ lv_c }|.

*--- 方式三：call by value and return result -----------------------*
lv_a = 1. lv_b = 2. lv_c = 0.
PERFORM frm_val_ret USING lv_a lv_b CHANGING lv_c.
WRITE: / |方式三 main a={ lv_a } b={ lv_b } c={ lv_c }|.

*------------------------------------------------------------------*
FORM frm_ref USING p_a TYPE i p_b TYPE i p_c TYPE i.
  p_c = p_a + p_b.          " 傳址：外面的 lv_c 真的變成 3
ENDFORM.

FORM frm_val USING VALUE(p_a) TYPE i VALUE(p_b) TYPE i VALUE(p_c) TYPE i.
  p_c = p_a + p_b.          " 傳值：副程式內 p_c=3，但外面的 lv_c 仍是 0
ENDFORM.

FORM frm_val_ret USING    VALUE(p_a) TYPE i
                          VALUE(p_b) TYPE i
                 CHANGING VALUE(p_c) TYPE i.
  " 這不是 call by address(reference)，
  " 而是讓 FORM 能 return 運算結果，稱為 call by value and return result
  p_c = p_a + p_b.
  p_a = 0.                  " 改 p_a、p_b 都不會影響外部
  p_b = 0.
ENDFORM.                    " <-- 執行到這一行，p_c 的 3 才寫回 lv_c

執行結果重點：方式一與方式三的 c 都是 3，但方式三的 a、b 保持原值；方式二的 c 仍是 0。

記法：USING = 我給你看；CHANGING = 我給你改；VALUE( ) = 我給你影本。影本在 CHANGING VALUE() 時，結束才貼回正本。

對照到現代方法（Method），這三件事變得一目瞭然，而且編譯器會幫你擋錯：

CLASS lcl_calc DEFINITION.
  PUBLIC SECTION.
    " IMPORTING 在方法內是「唯讀」，編譯器直接擋，比 FORM USING 安全
    CLASS-METHODS add
      IMPORTING iv_a          TYPE i
                iv_b          TYPE i
      RETURNING VALUE(rv_sum) TYPE i.     " RETURNING 必須是 pass by value
ENDCLASS.

CLASS lcl_calc IMPLEMENTATION.
  METHOD add.
    rv_sum = iv_a + iv_b.
    " iv_a = 0.   <-- 這一行會直接語法錯誤：IMPORTING 參數不可修改
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  " RETURNING 讓方法可以像函數一樣直接寫在運算式裡
  DATA(lv_total) = lcl_calc=>add( iv_a = 1 iv_b = 2 ) * 10.
  WRITE / |Total: { lv_total NUMBER = USER }|.

4. 區域變數、全域變數，與外部呼叫（IN PROGRAM／SUBMIT／CALL TRANSACTION）

  • 全域變數：在主程式宣告，主程式與它呼叫的每個副程式都看得到、改得動。
  • 區域變數：在副程式（或方法）內宣告，只活在該副程式中，每次呼叫重新建立在堆疊上 —— 所以遞迴是安全的。
  • 同名時區域變數優先，全域變數不受影響。
  • STATICS 宣告的變數例外：它跨呼叫保留值（可用來做計數器／快取），但也是 bug 溫床。
老師特別強調：「副程式中應避免使用主程式的變數，應使用參數。」這條規矩在寫方法時更嚴格 —— 方法只能透過參數與類別屬性溝通，這正是 OO 比 FORM 好維護的根本原因。

遞迴示範（副程式與方法都適用，這裡示範方法版）：

CLASS lcl_rec DEFINITION.
  PUBLIC SECTION.
    CLASS-METHODS factorial
      IMPORTING iv_n          TYPE i
      RETURNING VALUE(rv_res) TYPE p LENGTH 16 DECIMALS 0.
ENDCLASS.

CLASS lcl_rec IMPLEMENTATION.
  METHOD factorial.
    " 每一層呼叫都有自己的區域變數，所以遞迴安全
    rv_res = COND #( WHEN iv_n <= 1
                     THEN 1
                     ELSE iv_n * factorial( iv_n - 1 ) ).
  ENDMETHOD.
ENDCLASS.

5. Function Group 與 Function Module：SE37／SE80

Function Module（函數模組）是具有全域可見性的特殊程式，全系統任何程式都能呼叫。它只能在 Function Group（函數組）中定義 —— Function Group 是 FM 的「主程式」，一個 Group 可以包含多個 FM，通常放同一類物件的操作。

函數處理類型（Processing Type），在屬性頁籤選：

  1. Normal Function Module（一般函數模組）：只能在本系統使用。
  2. Remote-Enabled Module（遠端模組，RFC）：可被其他 SAP 或非 SAP 系統呼叫，呼叫時要指定 DESTINATION，目的地在 SM59 設定。
  3. Update Module（更新函數）：用於資料庫資料更新，講義註「常用於系統導入之初的大量數據更新」。

參數型別要怎麼填（講義的三個註記）：輸出結果若是一列資料，Associated Type 填結構（如 VBAK）；若要傳一整張表，用 TABLES 頁籤或在 Export/Changing 填表型別（如 SE11 建的 VBAP_T）。老師的提醒是：用表型別（Table Type）取代 TABLES 頁籤，才不會被系統標過時。
TABLES 參數在 SE37 已被標為過時：講義寫「用 TABLES 頁籤傳回 EKES，系統會提示過時，但強制 ENTER 仍會過」。可以過，但新 FM 請一律改用 Export／Changing ＋ Table Type。唯一例外：RFC FM 的相容性與部分外部系統（如舊版 JCo／pyrfc 呼叫端）仍習慣用 TABLES 參數，此時可保留。

6. 實作案例：ZFM_CASPER_VBAP 與 ZFM_GET_EBELP

講義的第一個 FM 練習：輸入銷售訂單號 I_VBELN，回傳表頭結構 E_VBAK 與表身內表 T_VBAP，找不到就拋 VBAK_NOT_EXIST 例外。

FUNCTION zfm_casper_vbak_vbap.
*"----------------------------------------------------------------------
*" IMPORTING  I_VBELN TYPE VBELN_VA
*" EXPORTING  E_VBAK  TYPE VBAK
*"            ET_VBAP TYPE ZTT_VBAP        " SE11 建的 Table Type
*" EXCEPTIONS VBAK_NOT_EXIST
*"----------------------------------------------------------------------

  CLEAR: e_vbak, et_vbap.

  " 表頭：明列欄位，主機變數加 @
  SELECT SINGLE vbeln, erdat, auart, vkorg, vtweg, spart, kunnr, netwr, waerk
    FROM vbak
    WHERE vbeln = @i_vbeln
    INTO CORRESPONDING FIELDS OF @e_vbak.

  IF sy-subrc <> 0.
    RAISE vbak_not_exist.        " 傳統例外：呼叫端用 sy-subrc 接
  ENDIF.

  " 表身
  SELECT vbeln, posnr, matnr, arktx, kwmeng, vrkme, netwr, werks
    FROM vbap
    WHERE vbeln = @i_vbeln
    ORDER BY posnr                " 一定要排序，否則順序不保證

ENDFUNCTION.

講義原程式的三個坑：

7. Function Group 的全域資料、SET/GET 樣式與 SE37 測試序列

同一個 Function Group 內的所有 FM，共用 LxxxTOP 裡宣告的全域資料，而且這份資料在整個使用者交談期間（roll area）持續存在，只要 Function Group 被載入就不會消失。這就是 SAP 標準大量使用的 SET/GET 樣式（例如 SET_PARAMETER／GET_PARAMETER、各種 *_INIT ／ *_SAVE 配對）。

SE37 測試序列（Test Sequence）：要驗證上面這種「先 SET 再 GET」的行為，不必寫呼叫程式。在 SE37 進入 FM 後，功能表 Function Module → Test → Test sequence（測試 → 測試序列），輸入要依序執行的 FM 名稱清單（例如 Z_CTX_SET、Z_CTX_GET），按執行，系統會在同一個 roll area 內依序跑，你就能看到全域資料真的被保留下來。這是測試 SET/GET 型 FM、以及測試 Update FM 的標準手法。
全域資料是雙面刃：好處是省下重複查詢（可以當 buffer），壞處是狀態殘留。如果某個 FM 忘了 CLEAR，下一次呼叫可能拿到上一張單據的資料 —— 批次處理時特別容易中招。習慣在每個 FM 開頭 CLEAR 掉輸出參數。

9. MACRO：DEFINE … END-OF-DEFINITION

巨集（Macro）是「一段獨立的程式碼，能實現資料的運算與輸出，功能與副程式類似，主要用於同一程式中重複的運算，以簡化程式碼」。語法：

REPORT z202202_32.

DATA lv_a TYPE i VALUE 1.
DATA lv_b TYPE i VALUE 10.

DEFINE increment.          " increment 為巨集名稱
  &1 = &1 + 1.             " &1 = 第 1 個參數，最多到 &9
  WRITE / &1.
  WRITE / &2.
END-OF-DEFINITION.

increment lv_a lv_b.       " 呼叫：不加逗號、不加括號，參數用空白隔開

規則（講義重點）：

  • 用 &1～&9 接收參數，最多九個，不需要也不能宣告型別。
  • 巨集只能被本程式中「定義於巨集之後」的敘述呼叫，所以巨集一律寫在程式最前面。
  • 展開發生在編譯期（純文字替換），所以巨集無法 debug —— 這是它最大的缺點，講義特別註明「marco 是無法被 debug 的，因此程式不宜太長」。
  • 另有存在 TRMAC 表的全域巨集，用 SE38 → 功能表 → 巨集維護，可跨程式使用（更不建議）。

老師示範的兩個實務用法都是「建 ALV Field Catalog」—— 這正是巨集最經典的使用場景，因為要重複填十幾個欄位：

10. INCLUDE：把程式切成 TOP／F01／O01／I01／E01

INCLUDE 的定位要先講清楚：它不是模組化封裝，而是「把一個檔案切成多個檔案」。編譯時系統把 include 的內容原地展開，執行期完全等同於寫在一起。用途是：共用資料宣告、讓大程式好維護、讓多人可以同時編輯不同 include。

  • 語法：INCLUDE <include 程式名>.
  • 被包含的程式不能有 PROGRAM 或 REPORT 敘述（其程式類型要設為 Include program，即 I 型）。
  • Include 不能包含自己（不可遞迴）。
  • Include 內必須是完整的敘述，不能把一句 ABAP 切成兩半放在兩個 include。

1. 先在原報表裡把 FORM 一個一個搬成本地類別的方法（先能跑、行為不變）。
2. 把全域變數改成類別的私有屬性，用 constructor 或 setter 帶入。

12. Class-Based Exception：三種基底類別與 TRY–CATCH–CLEANUP

FM 的傳統例外（RAISE <exception> ＋ sy-subrc）有兩個問題：例外沒有型別、沒有訊息內容、忘了寫 OTHERS 就 dump。方法用的是 class-based exception：例外本身是一個物件，可以攜帶訊息、屬性、甚至前一個例外（previous）。

基底類別是否必須在 RAISING 宣告使用時機
CX_STATIC_CHECK必須，語法檢查會擋呼叫端「應該要處理」的業務錯誤（訂單不存在、金額不合法）。自建例外的預設首選
CX_DYNAMIC_CHECK不必宣告，但沒接到就 runtime error理論上不該發生、呼叫端可自行避免的錯（如 CX_SY_ZERODIVIDE、CX_SY_CONVERSION_NO_NUMBER）
CX_NO_CHECK不必宣告，會自動往上層傳播無法在區域處理的系統性錯誤（如 CX_SY_NO_HANDLER、資源不足）

三者都繼承自 CX_ROOT；CX_SY_* 是 SAP 的系統例外。

*--- 完整的 TRY / CATCH / CLEANUP 範例 ------------------------------*
DATA lo_file TYPE REF TO if_x.

TRY.
    " (1) 主邏輯

    DATA(lo_order)  = NEW zcl_sd_order( p_vbeln ).

    " (2) 抓特定例外

  CATCH zcx_sd_order_not_found INTO DATA(lx_nf).
    MESSAGE lx_nf->get_text( ) TYPE 'I'.

  CATCH cx_root INTO DATA(lx_root).
    " (3) 最後防線：cx_root 一定要放最後，因為 CATCH 由上往下比對
    MESSAGE |未預期的錯誤：{ lx_root->get_text( ) }| TYPE 'E'.

  CLEANUP.
    " (4) 只有在「例外往外層傳播」時才執行，用來釋放資源
    "     注意：被本 TRY 的 CATCH 接住時，CLEANUP 不會執行
    CLEAR lo_file.

ENDTRY.

15. 超級 Debug 模式 /H：追出程式用了哪些資料表

講義第 6 節這一招非常實用：第一次上課時我們想盡辦法要找到「畫面上的欄位來自哪張表」，學會 ABAP 之後只要用 /H 就能直接看。

  1. 進入交易碼（例如 VA03）。
  2. 在指令欄輸入 /H → Enter，畫面出現「Debugging switched on」。
  3. 再按 Enter 執行下一個動作，就會進入 Debugger。
  4. 按 F9（設中斷點）→ 選 Breakpoint at Statement → 輸入 SELECT。
  5. 按 F8 執行，每遇到一句 SELECT 就停下來，看它讀哪一張表。
  6. 用 F5（單步）、F6（略過副程式）、F7（執行完目前副程式返回）、F8（繼續）搭配追蹤。
  7. 查完記得取消中斷點（Breakpoints 頁籤 → 刪除），否則之後每支程式都會停。
其他常用的 Debugger 中斷點類型（Breakpoint at …）：
Statement（如 SELECT、CALL FUNCTION、MESSAGE、AUTHORITY-CHECK）／Function Module（追某支 FM 被誰呼叫）／Method／Subroutine／Exception（抓 dump 的來源）。
Watchpoint（監視點）：對某個變數設條件，「當 sy-subrc <> 0」或「當 lv_matnr = '123'」時才停；若不指定條件，則該變數值一被改變就停下來。這是抓「值被誰改掉了」的唯一有效手段。
Debug 也可以事後補勾：進了 Debugger 才決定要不要進某段程式。
兩種 Debugger：Classic Debugger（同一個視窗，功能少）與 New Debugger（獨立視窗、多頁籤、可看物件與內表全貌）—— 在 Debugger 內 Settings 可切換。
作業（第 6 節）：找出 VA03 用了多少個資料表？（抓到感覺即可）
提示：VA03 → /H → Enter → F9 → SELECT → F5/F6/F7/F8 → 取消斷點。
會看到 VBAK、VBAP、VBUK/VBUP（S/4 已併入 VBAK/VBAP 的狀態欄位）、VBEP、VBKD、KONV（S/4 改為 PRCD_ELEMENTS）、KNA1、MARA、TVAK… 幾十張表。這個練習的目的是體會「一個標準交易背後有多複雜」。

16. SE91 Message：模組化的錯誤訊息管理

寫死在程式裡的中文字串無法翻譯、無法統一維護。SE91 的訊息類別（Message Class）就是「訊息的模組化」。

類型名稱行為顯示位置
IInformation使用者確認後，程式從 MESSAGE 敘述之後繼續對話框
SStatus程式正常繼續下一個畫面的狀態列
WWarning視程式情境，出現錯誤對話框、程式停止或終止，使用者須採取行動狀態列
EError視程式情境，程式停止或終止，使用者須採取行動狀態列或對話框
ATermination使用者確認後程式終止，控制權回到上層區域功能表對話框
XExit程式以 short dump 終止，不顯示訊息；dump 內含訊息 ID—
