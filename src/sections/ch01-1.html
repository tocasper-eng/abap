2. 開發環境：SE38、SE80 與 ADT（Eclipse）

ABAP 有三種主要的開發入口，功能有重疊但定位不同：

  • SE38（ABAP Editor）：最直接的入口，適合寫可執行報表（Type 1）。初學者從這裡開始。
  • SE80（Object Navigator 物件瀏覽器）：以「Package／程式／Function Group／Class／Screen」為樹狀結構管理，可以一次看到一個開發物件底下的所有 Include、畫面、文字元素。建 Function Group、Module Pool、Class 建議走 SE80。
  • ADT（ABAP Development Tools for Eclipse）：S/4HANA 時代的正式開發工具。CDS View、AMDP、RAP（Restful ABAP Programming Model）、ABAP Unit 的完整體驗只有 ADT 有，SE80 在 S/4 已被 SAP 標示為「不再增強」。
S/4HANA 注意：CDS View（DDLS）、Behavior Definition、Service Binding 等物件無法在 SE80 建立，必須用 Eclipse + ADT。SE80 仍可用來看舊物件，但新開發建議一律 ADT。SE80 在 SAP BTP ABAP Environment（雲端）更是完全不存在。
GUI 端仍然需要：Debug、SM30 維護、SE93 建 TCODE、STMS 傳輸這些工作在 GUI 做比較順。實務上是「Eclipse 寫程式 + GUI 做運維」兩邊並用。

3. 寫程式的四步驟與命名規則（Z／Y 命名空間）

講義把建立第一支程式拆成四個動作，這四步在 S/4HANA 依然完全一樣：

  1. 程式名稱一定要 Z 開頭（或 Y 開頭）。
  2. 設定屬性：Title、Type、Status、Application。
  3. 指定 Package：練習環境可選 Local Object（$TMP）；正式開發要放進自己的 Package（例如講義用的 Z600_2409_ERP000）。
  4. 執行程式：F8，或用 SA38／SE93 建成 TCODE 執行。

命名空間規則：SAP 保留了所有不以 Z／Y 開頭的名稱給標準物件。客戶自建物件只能用 Z* 或 Y*；若公司有向 SAP 申請的專屬命名空間，則是 /ABCDE/ 這種斜線包起來的形式。表格、資料元素、Domain、Class、Function Module 全部適用同一規則。

4. 用 SE16N／SE16H 學寫 SQL

老師的心法：不會寫 SQL 就先去 SE16N 點一遍。SE16N 的選擇畫面本質上就是一句 SELECT，把條件填一填、按執行，你要的 WHERE 條件就成形了。

  • SE16N 進入後在指令列輸入 &SAP_EDIT 可開啟編輯模式（正式機嚴禁使用，會繞過所有業務邏輯與變更文件）。
  • SE16N 支援「技術欄位名稱／描述」切換、可指定輸出欄位、可設定筆數上限。
  • SE16H（HANA 版）更強：可直接做 Group By、Sum、Count、以及多表 JOIN，等於在畫面上做出一份聚合報表，很適合先驗證邏輯再寫成 ABAP。
作業 2-01：用 SE16H 把作業 1-01 找到的 FI、CO、SD、MM、PP 重大雙檔做成關聯（在 SE16H 的 Table Join 區塊填入第二張表與關聯欄位，例如 VBAK-VBELN = VBAP-VBELN）。
SE16H 的 Group By／Sum 功能是「不寫程式就能出報表」的最快路徑，很多臨時性的查數需求根本不必開發。這也呼應本章最後一節「解決企業問題的手段與順序」。

5. 第一支 SELECT：從講義的舊寫法到 S/4HANA 現代寫法

講義的第一支程式 Z2202_00_01（取出料號為 DXTR1000 的訂單明細）原本是這樣寫的（此處刻意保留作為反例）：

" ===== 反例：講義原始寫法，S/4HANA 請勿再這樣寫 =====
REPORT z2202_00_01.
TABLES: vbap.                          " 宣告了整張表當共用工作區
SELECT * INTO CORRESPONDING FIELDS OF vbap
  FROM vbap
  WHERE matnr = 'DXTR1000'.            " 主機變數沒有 @、寫死常數
  WRITE: / vbap-vbeln, vbap-posnr, vbap-matnr,
           vbap-meins, vbap-kwmeng.
ENDSELECT.                             " 一筆一筆丟回 AP Server，效能最差
上面這段有四個 S/4HANA 的地雷：
1. TABLES: 會產生全域工作區，在 OO 環境與現代 ABAP 中已被視為 obsolete（ABAP Objects 語法檢查會直接報錯）。
2. SELECT ... ENDSELECT 是逐筆迴圈，每一圈都在 DB 與 AP Server 間往返，違反 S/4HANA「Code Push-Down」原則。
3. SELECT * 在 HANA 的欄式儲存上代價極高——只取 5 個欄位卻讀了 VBAP 全部兩百多欄。
4. WHERE 條件的主機變數沒有逸出字元 @，在嚴格語法模式下無法通過。

改寫成 S/4HANA 1809 之後的現代 ABAP：

REPORT z2202_00_01.

" 第一支 SELECT 的現代寫法：明列欄位 + 內嵌宣告 + 一次抓進內表
SELECT vbeln, posnr, matnr, meins, kwmeng
  FROM vbap
  WHERE matnr = 'DXTR1000'          " 常數不需要 @；只有主機變數才要
  INTO TABLE @DATA(lt_vbap).

IF lt_vbap IS INITIAL.
  MESSAGE '查無資料' TYPE 'S' DISPLAY LIKE 'W'.
  RETURN.
ENDIF.

LOOP AT lt_vbap ASSIGNING FIELD-SYMBOL(<ls_vbap>).
  WRITE: / <ls_vbap>-vbeln,
           <ls_vbap>-posnr,
           <ls_vbap>-matnr,
           <ls_vbap>-meins,
           <ls_vbap>-kwmeng.
ENDLOOP.
講義標註的「進化三段」正是這支程式的學習路徑：1. UP TO n ROWS（限制筆數） → 2. Field List（明列欄位） → 3. WHERE（加條件）。開發時養成習慣：先 UP TO 10 ROWS 試跑，確認欄位與資料對了，再拿掉限制。
" 開發階段的安全寫法：先限制筆數再放大
SELECT vbeln, posnr, matnr, meins, kwmeng
  FROM vbap
  WHERE matnr = 'DXTR1000'
  ORDER BY vbeln, posnr                 " 沒有 ORDER BY 就沒有順序保證
  INTO TABLE @DATA(lt_vbap)
  UP TO 10 ROWS.
HANA 沒有「預設排序」這回事。舊 DB 常常剛好照主鍵回傳，HANA 是平行處理，不下 ORDER BY 的結果順序完全不保證，同一支程式跑兩次可能不同。凡是「抓第一筆」「比對前後筆」的邏輯，一定要明確 ORDER BY。SELECT SINGLE 若 WHERE 不是完整主鍵，回傳的是任意一筆，不是「第一筆」。

口訣：「型態要接到 DDIC，F4 才會來」。
TYPE c LENGTH 40 → 沒有 Search Help；
TYPE matnr（Data Element）→ 有 Search Help（Data Element 掛了 Search Help 或 Domain 有 Value Table）；
TYPE mara-matnr（表-欄位）→ 有 Search Help，且欄位說明、外鍵檢查一起繼承。
關聯鏈要記住：VBAP-MATNR → Data Element MATNR → Domain MATNR → Value Table MARA。Search Help 與外鍵檢查就是沿著這條鏈走出來的。
S/4HANA 的 MATNR 長度已由 18 碼延伸為 40 碼（Extended Material Number）。所有自訂欄位、介面結構請一律 TYPE matnr，不要自己寫 CHAR18，否則在 S/4 上會被截斷。講義寫 ty_matnr(40) 正是為了配合 S/4 的長度，但仍建議直接用 DDIC 型態。

7. 工作區與內表：從 TYPES 到 Internal Table

講義 Z2202_00_04 的重點在於建立四層概念：TYPES（型態） → STRUCTURE（結構） → WORK AREA（工作區） → INTERNAL TABLE（內表）。這是所有 ABAP 程式的骨架。

" ① 定義結構型態（只是藍圖，不佔記憶體）
TYPES: BEGIN OF ty_vbap,

TYPES: ty_t_vbap TYPE STANDARD TABLE OF ty_vbap WITH EMPTY KEY.

" ③ 真正配置記憶體：工作區（一列）與內表（多列）

      lt_vbap TYPE ty_t_vbap.         " Internal Table = 多列

" ④ 建構式寫法：直接生出一列 / 一張表，不必逐欄位搬
ls_vbap = VALUE #( vbeln = '0000000001'
                   posnr = '000010'
                   matnr = 'DXTR1000'
                   meins = 'PC'
                   kwmeng = 10 ).

lt_vbap = VALUE #( ( vbeln = '0000000001' posnr = '000010' matnr = 'DXTR1000' )
                   ( vbeln = '0000000001' posnr = '000020' matnr = 'DXTR2000' ) ).
ABAP 的基本資料型態（講義列出的）：C（字元）、D（日期 YYYYMMDD）、P（壓縮十進位，金額數量用）、N（數字字串）、I（整數）、F（浮點）、STRING（變長字串）。另外還有 X（十六進位）、T（時間 HHMMSS）、XSTRING、以及 S/4 新增的 INT8（8-byte 整數）與 DECFLOAT16/34。
金額欄位一律用 CURR（DDIC）／P DECIMALS 2（ABAP），絕不要用 F 浮點數算錢。
內表三種型態的選擇：STANDARD TABLE（順序存取，APPEND 快，READ 需線性掃描）、SORTED TABLE（自動維持排序，二分搜尋）、HASHED TABLE（唯一鍵，READ 為 O(1)，不能 APPEND 只能 INSERT）。做「大表對照查值」時用 HASHED，效能差距是數量級的。

8. 關鍵案例：用內表取代 ENDSELECT 提升效率

講義 Z2202_00_05 是整章最重要的觀念題：把 SELECT ... ENDSELECT 換成「一次抓進內表 + LOOP」。老師把它拆成十個編號步驟，建議直接背成模板。

作業 3-01（講義解答 Z2202_00_06）：請找出多餘的程式碼並刪除，並讓選擇螢幕的料號可下拉選單。
要刪的是 TABLES: VBAP.（用不到了）、TYPES: TY_MATNR(40) TYPE C. 與 DATA: W_MATNR（沒被用到）；要改的是把 PARAMETERS p_matnr TYPE ty_matnr 改成 TYPE mara-matnr，Search Help 就出來了。
老師說這支「可以用背的，久了就成習慣」。實務上 90% 的報表都是這個骨架：選擇畫面 → 一次 SELECT 進內表 → 加工 → 輸出。差別只在中間加工多複雜、輸出用 WRITE 還是 ALV。
效能觀念：SELECT ... ENDSELECT 每圈一次 DB 往返；一萬筆就是一萬次網路來回。改成 INTO TABLE 只有一次。這在傳統 DB 上就已經是常識，在 S/4HANA（DB 與 AP 分離、且 HANA 擅長批次回傳）差距更大。另外 INTO CORRESPONDING FIELDS OF TABLE 是「依名稱對應」，會多一層搬移成本且容易因欄位改名而靜默出錯——明列欄位 + INTO TABLE 才是首選。

9. 傳票案例：主子檔 JOIN 與 S/4HANA 的 ACDOCA

講義第 4 節用 FI 傳票示範「怎麼把主檔與子檔關聯起來」。原始寫法是兩支 SELECT ... ENDSELECT 各印各的，再進化成一句 JOIN。以下是現代化改寫。

REPORT z20211109_ncu.

" 舊 ECC 觀念：BKPF（表頭）與 BSEG（行項目）用 BUKRS + BELNR + GJAHR 關聯
PARAMETERS: p_gjahr TYPE bkpf-gjahr DEFAULT '2021',
            p_budat TYPE bkpf-budat DEFAULT '20211109'.

START-OF-SELECTION.
  SELECT h~gjahr, h~budat, h~cputm, h~usnam, h~belnr,
         h~tcode, h~blart,
         d~buzei, d~koart, d~valut, d~prctr, d~dmbtr,
         d~shkzg, d~pargb, d~bschl, d~kokrs, d~kostl,
         d~menge, d~werks
    FROM bkpf AS h
    INNER JOIN bseg AS d
      ON  h~bukrs = d~bukrs        " 三個鍵都要接，少一個就是笛卡兒乘積
      AND h~belnr = d~belnr
      AND h~gjahr = d~gjahr
    WHERE h~gjahr = @p_gjahr
      AND h~budat = @p_budat
    ORDER BY h~usnam, h~belnr, d~buzei
    INTO TABLE @DATA(lt_accts).

  LOOP AT lt_accts ASSIGNING FIELD-SYMBOL(<ls>).
    WRITE: / <ls>-gjahr, <ls>-budat, <ls>-cputm, <ls>-usnam,
             <ls>-belnr, <ls>-buzei, <ls>-tcode, <ls>-blart,
             <ls>-bschl, <ls>-dmbtr, <ls>-werks.
  ENDLOOP.
初學者最常見的語法錯誤：ABAP 每一句敘述都以「句點 .」結束，不是分號；冒號「:」是「鏈式敘述（chained statement）」的縮寫符號，例如 WRITE: a, b, c. 等同三句 WRITE。JOIN 時三個關聯鍵（BUKRS、BELNR、GJAHR）少接一個，就會變成笛卡兒乘積，筆數暴增且金額全錯——這是 FI 報表最常見的災難。
S/4HANA 重大變更：BSEG 在 S/4 仍存在但已非唯一真相來源，總帳的完整明細落在 ACDOCA（Universal Journal）。

  FROM mara AS a
  LEFT OUTER JOIN makt AS t
    ON  a~matnr = t~matnr

LEFT JOIN 的兩個經典陷阱：
1. 右表的過濾條件寫在 WHERE 就會退化成 INNER JOIN（因為 NULL 不滿足條件而被濾掉），必須寫在 ON 子句裡。
2. 若右表對同一鍵有多筆（例如 MAKT 沒限定 SPRAS），LEFT JOIN 會把左表的列數放大，金額類欄位再做 SUM 就會重複計算。這是報表金額對不起來最常見的原因。

13. RANGES／SELECT-OPTIONS：區間與列舉

講義 08-8 標註「有點難，可半年後再學」，但它是 ABAP 選擇條件的底層原理，早懂早受益。

REPORT zrange.

" 現代寫法：用 RANGE OF 型態（不要再用 RANGES: 敘述，它會產生帶表頭列的舊物件）
DATA lt_carrid TYPE RANGE OF spfli-carrid.

" ① 區間（BT）：low 到 high 之間
lt_carrid = VALUE #( ( sign = 'I' option = 'BT' low = 'AA' high = 'HH' ) ).

" ② 列舉（EQ）：逐一列出，最精準
lt_carrid = VALUE #( sign = 'I' option = 'EQ'
                     ( low = 'AA' )
                     ( low = 'LH' )
                     ( low = 'UA' ) ).

SELECT carrid, connid, cityfrom, cityto
  FROM spfli
  WHERE carrid IN @lt_carrid          " IN 一律搭配 @
  ORDER BY carrid, connid
  INTO TABLE @DATA(lt_spfli).

LOOP AT lt_spfli ASSIGNING FIELD-SYMBOL(<ls>).
  WRITE: / <ls>-carrid, <ls>-connid, <ls>-cityfrom, <ls>-cityto.
ENDLOOP.

RANGE 表固定有四個欄位：

欄位型態意義
SIGNCHAR 1I＝Include 包含（一般用這個）；E＝Exclude 排除
OPTIONCHAR 2EQ 等於、NE 不等、GT 大於、GE 大於等於、LT 小於、LE 小於等於、BT 區間、NB 非區間、CP 樣式包含（可用 * ）、NP 樣式排除
LOW同來源欄位低值（單值時只用這個）
HIGH同來源欄位高值，只有 OPTION 為 BT／NB 時才參與運算
老師實戰血淚：條件用「區間」與用「列舉」答案會不一樣，用列舉的才正確。
原因有三：
1. BT 是字串比較，不是數值比較。CHAR 型欄位 '003' BT '007' 看似 003~007，但如果值域裡出現 '0035'、'01A' 這種長度或格式不一致的資料，會意外被包含或排除。
2. 值域不連續時，區間會把中間你不想要的代碼一併撈進來（例如成本要素區間中夾雜了不該加總的科目）。
3. 帶前導零的 NUMC／CHAR 欄位若未經 ALPHA 轉換，畫面輸入的 100 與資料庫的 0000000100 比較結果會出乎意料。
結論：涉及金額彙總、成本歸集這類「不能多也不能少」的邏輯，寧可用 EQ 逐一列舉，也不要圖方便用 BT 區間。
定義 Range 的兩種方式：
1. DATA lt_x TYPE RANGE OF <型態>.（型態可以是基本型態或表欄位）—— 建議用這種。
2. RANGES: g_x FOR spfli-carrid.（此處的參考只能是表欄位，不能是 Data Element；且會產生帶表頭列的舊式物件）—— 已 obsolete。
另外 SELECT-OPTIONS s_matnr FOR mara-matnr. 本身就是一張 RANGE 表，加上選擇畫面，這是實務上最常用的做法。
" 實務標準骨架：SELECT-OPTIONS 直接餵進 WHERE ... IN
TABLES mara.   " 注意：SELECT-OPTIONS 的 FOR 需要一個宣告過的欄位；
               " 現代寫法可改為先 TYPES 再用 RANGE，或維持此處最小範圍的宣告

SELECT-OPTIONS: s_matnr FOR mara-matnr,
                s_mtart FOR mara-mtart.
PARAMETERS:     p_max   TYPE i DEFAULT 100.

START-OF-SELECTION.
  SELECT matnr, mtart, meins
    FROM mara
    WHERE matnr IN @s_matnr
      AND mtart IN @s_mtart
    ORDER BY matnr
    INTO TABLE @DATA(lt_out)
    UP TO @p_max ROWS.
若要完全避開 TABLES:，可以先在程式中宣告一個結構型態的變數，再對它 SELECT-OPTIONS ... FOR：
DATA gs_mara TYPE mara. → SELECT-OPTIONS s_matnr FOR gs_mara-matnr.
這樣既有選擇畫面，也不會產生 TABLES 的全域工作區。

14. Package、SE21、SE80 與程式類型

Package（舊稱 Development Class 開發類）是 ABAP 所有開發物件的歸屬單位。講義的定義：

  • 儲存 SAP 系統開發過程中的所有相關物件（程式、表結構定義、資料類型等），方便管理與查詢。
  • 透過 Package 可以方便地把它所包含的物件批量傳輸到不同伺服器。傳輸是透過請求號（Request）進行，請求號是一份文件，記錄所有物件的修改記錄。
  • 不屬於任何開發類的物件，可分配給本地開發類 $TMP；該類中的物件不能進行系統間傳輸，主要用於測試。

建立步驟（SE21 或 SE80）（依講義步驟整理）：

  1. 執行 SE21（Package Builder），或 SE80 → 下拉選 Package。
  2. 輸入 Package 名稱（必須 Z／Y 開頭，例如講義的 Z600_2409_ERP000），按 Create。
  3. 填入 Short Description、Software Component（客戶物件選 HOME）、Transport Layer（選系統的標準傳輸層，例如 ZDEV 或 SAP；此欄決定物件會被傳到哪條傳輸路徑）。
  4. Package Type 一般選 Not a Main Package（不是主套件）。
  5. 存檔 → 系統要求指定 Workbench Request → 建立或選一個既有的請求號 → 完成。
Transport Layer 若選錯（例如選成 SAP 或留空），物件可能無法沿著客戶的 DEV→QAS→PRD 路徑傳輸，或被歸為「不可傳輸」。建 Package 前先問 Basis 這套系統的客戶傳輸層代碼。

SE80 物件瀏覽器：同一個 Package 底下可組織多個物件——程式、Function Group、Class、Table、Screen、Transaction、Message Class 全都掛在樹上。開發時把 SE80 開著，比反覆切 SE38／SE11／SE37 快得多。

15. 傳輸請求 SE09／SE10 與 STMS 傳輸路徑

ABAP 的每一次修改都會被記錄在傳輸請求（Transport Request，TR）裡。這是 SAP 變更管理的核心。

兩種請求：

  • Workbench Request（工作台請求）：跨 Client 的開發物件——程式、Table、Class、Function、Screen。編號形式 DEVK900123。
  • Customizing Request（客製化請求）：Client 相關的設定資料（SPRO 的配置）。編號形式 DEVK900124。

請求的結構：一個 Request（主請求）底下掛數個 Task（任務），每位開發者一個 Task，物件實際登記在 Task 上。

TCODE用途
SE09Transport Organizer（Workbench 請求，講義用這支查請求號）
SE10Transport Organizer（含 Customizing 請求，功能與 SE09 幾乎相同）
SE01Transport Organizer（擴充視圖，可看傳輸日誌、建立各類請求）
SE03Transport Organizer Tools（改物件的 Package、搜尋請求中的物件、鎖定/解鎖）
STMSTransport Management System，匯入佇列、執行傳輸

請求狀態（講義原文）：Modifiable＝可修改（還在開發中，物件被鎖住）；Released＝已釋放（已寫出檔案，可以被匯入下一個系統，內容不能再改）。

釋放與傳輸的完整流程（依講義步驟整理）：

  1. 開發完成 → SE09 找到自己的 Request。
  2. 先釋放 Task（子項）：選中 Task → 按卡車圖示（Release Directly）。
  3. 再釋放 Request（主項）：同樣按卡車圖示。此時系統會做語法／一致性檢查，並把物件寫成傳輸檔案（cofiles + data files）。
  4. STMS → Import Overview → 進入 QAS 的 Import Queue → 找到剛才的請求號 → Import Request。
  5. 在 QAS 測試通過後，再從 STMS 的 PRD 佇列匯入。

STMS 的觀念（講義 10-5）：標準三層架構是 DEV → QAS → PRD，「有時不只這三區」。常見的變化包括：

系統全名角色
DEVDevelopment唯一可以改程式的地方（其他系統通常鎖住）
QAS / QA / TSTQuality Assurance使用者測試 UAT、整合測試
PRD / PROProduction正式生產環境
SBXSandbox沙箱，通常不在傳輸路徑上
TRNTraining教育訓練機
PRE / PPDPre-Production上線前最後演練（含真實資料副本）
傳輸的三大鐵律：
1. 傳輸順序不能亂。請求號是依釋放時間編號的，匯入時若跳號（先匯 900130 再匯 900125），舊的請求會覆蓋新的，造成「明明修好了卻又壞掉」。務必依序匯入或用 Import All。
2. 相依物件要同一批傳。Table 改了欄位、程式用了新欄位，兩者若分在不同 Request 且分批傳，QAS 會出現「欄位不存在」的短暫錯誤。
3. $TMP 的東西傳不出去。上線前用 SE03 → Change Object Directory Entry 把 Package 從 $TMP 改成正式 Package，系統會要求指定 Request。
查「這支程式是被哪個請求號傳出去的」：SE03 → Search for Objects in Requests/Tasks，輸入物件名稱即可。或直接查資料表 E070（請求表頭）、E071（請求內物件）、E07T（請求說明）。
" 查某個物件被登記在哪些傳輸請求裡（E071 = 傳輸請求物件明細）

SELECT e071~trkorr, e071~pgmid, e071~object, e071~obj_name,
       e070~trstatus, e070~as4user, e070~as4date, e07t~as4text
  FROM e071
  INNER JOIN e070 ON e070~trkorr = e071~trkorr
  LEFT OUTER JOIN e07t ON  e07t~trkorr = e071~trkorr
                       AND e07t~langu  = @sy-langu
  WHERE e071~obj_name = @p_obj
  ORDER BY e070~as4date DESCENDING
  INTO TABLE @DATA(lt_tr).

LOOP AT lt_tr ASSIGNING FIELD-SYMBOL(<ls>).
  " TRSTATUS: D=Modifiable L=Modifiable(protected) R=Released O=Release started
  WRITE: / <ls>-trkorr, <ls>-trstatus, <ls>-as4user, <ls>-as4date, <ls>-as4text.
ENDLOOP.

18. 除錯入門（Debug）

講義以截圖為主，這裡整理成可操作的文字步驟（依講義步驟整理）。

進入 Debugger 的四種方法：

  1. 設中斷點：在 SE38 編輯器中，游標停在該行 → 點左側「停止」圖示，或按 Ctrl+Shift+F12。執行到該行就會停。
  2. 指令列輸入 /h：在任何畫面的指令列輸入 /h 按 Enter，畫面顯示 "Debugging switched on"，接著按下一個動作就會進入偵錯。這招對標準程式最好用。
  3. 程式中寫死：加一行 BREAK-POINT.（所有人都會停，絕不能傳到正式機）或 BREAK <使用者名稱>.（只有指定使用者會停）。
  4. SE80／SAT：對背景 Job 用 SM37 → 選 Job → 指令列 JDBG 進入偵錯。

Debugger 的操作鍵：

鍵動作用途
F5Single Step（單步進入）會鑽進 FORM／FUNCTION／METHOD 內部
F6Execute（單步跳過）把整個子程式當一行執行完
F7Return（跳出）執行完目前子程式後回到呼叫端
F8Continue（繼續）跑到下一個中斷點或結束

常用技巧：

  • Watchpoint（監看點）：不知道變數在哪裡被改壞時，設 Watchpoint（新 Debugger 的 Break./Watchpoints 頁籤），變數值一變就停。這是抓「金額為什麼變成 0」這類問題的利器。
  • 看內表：在 Variables 區輸入內表名稱，雙擊即可展開所有列；可用上方的篩選功能找特定列。
  • 改值：在 Debugger 裡雙擊變數值 → 修改 → 按鉛筆／Change 圖示，可以即時改變執行結果，用來模擬各種情境（正式機請小心，這會真的影響過帳結果）。
  • Call Stack：看目前的呼叫堆疊，快速找出「是誰呼叫我的」。
  • SY-SUBRC 是第一嫌疑犯：每個 SELECT、READ TABLE、CALL FUNCTION 之後都先看 SY-SUBRC，多數 bug 在這裡就抓到了。

19. 解決企業問題的手段與順序

講義最後一節只有三句話，但它是整套課程的價值觀，也是資深顧問與新手最大的差別：

  1. 能配置的就用後台配置（SPRO）解決。
  2. 一定要改程式就用增強（Enhancement／BAdI／User Exit）。
  3. 非不得已才寫程式。
為什麼？因為維護成本。配置在升級時原封不動；增強有標準的接點，升級時 SAP 會提示；自建程式在每次升級（例如 ECC → S/4HANA，或 S/4 年度版本升級）都要重新測試、可能要重寫。
延伸順序（S/4HANA 版）：標準功能 → 配置 → Fiori 標準 App → CDS View / Custom Field（Key User Extensibility） → BAdI / Enhancement → 自建 ABAP 程式 → Side-by-side（BTP）。Clean Core 是 S/4HANA 的核心原則：核心越乾淨，升級越輕鬆。
S/4HANA 的「Clean Core」還有一個現實理由：SAP 已宣告修改核心的客製會影響雲端遷移路徑。若公司未來打算上 RISE with SAP 或 Public Cloud，所有非標準的核心修改都會變成阻礙。開發前先問：「這個需求標準有沒有？Fiori 有沒有？CDS 能不能做？」

練習與自我檢核

  1. 作業 1-01：找出 FI、CO、SD、MM、PP 五大模組的重大雙檔。
    要點：BKPF/BSEG（S/4→ACDOCA）、COBK/COEP、VBAK/VBAP、EKKO/EKPO、MKPF/MSEG（S/4→MATDOC）、AUFK+AFKO/AFPO。
  2. 作業 2-01：用 SE16H 把上題找到的雙檔做成關聯，並試著加上 Group By 與 Sum。
  3. 作業 3-01：把 Z2202_00_05 的多餘程式碼刪掉，並讓選擇螢幕的料號能下拉選單。
    要點：刪 TABLES: VBAP.、未使用的 TYPES 與 DATA；PARAMETERS p_matnr TYPE mara-matnr。
  4. 作業 4-01：說明 MARA、MARC、MARD、MAKT 的關聯性。
    要點：MATNR → +WERKS → +LGORT 的三層結構，MAKT 是 MATNR+SPRAS 的多語系描述。
  5. 作業 5-01：列出你認為最重要的 MATDOC 二十個欄位，並照第 9 節寫成 JOIN 報表程式。
  6. 作業 7-01：檢查自己的 SE21，確認 Package 已建立、程式已歸屬、Request 已產生。
