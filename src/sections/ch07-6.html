2. 動態建立資料與物件、動態呼叫方法（8.1、8.2）

觀念：靜態寫法 NEW lcl_x( )、DATA lv TYPE i 要求型別在「編譯時」就知道。當型別名、類別名、方法名要到「執行時」才知道（例如從設定表讀出、從選擇畫面輸入），就要用動態寫法：

  • CREATE DATA dref TYPE (name)：依型別名建立資料物件，拿到的是 REF TO data，要透過 ASSIGN dref->* TO <fs> 才能操作。
  • CREATE OBJECT oref TYPE (name)：依類別名建立物件。這是少數仍必須用 CREATE OBJECT 的場合——NEW 運算子不接受動態類別名。
  • CALL METHOD oref->(meth)：依方法名呼叫。動態呼叫只能用 CALL METHOD 敘述，不能寫成函數式 oref->(meth)( )；參數多的時候用 PARAMETER-TABLE（型別 ABAP_PARMBIND_TAB）。

與原範例的差異

  • 原範例把本地類別命名為 ZLCL_CLASS、ZCL_PRODUCT。Z 字首是給全域物件用的命名空間；本地類別慣例是 LCL_。更糟的是若系統剛好有全域類別 ZCL_PRODUCT，程式內的本地類別會把它「遮蔽」，動態建立時拿到哪一個會讓人困惑。改寫一律用 LCL_。
  • 8.1 原寫 CREATE DATA gv_dref TYPE ('ty_i')（小寫）、註解說「類別名必須大寫」。動態指定的名稱建議一律大寫，SAP 文件對動態類別名明確要求大寫；改寫統一成 'TY_I'。
  • 8.1 原本 gv_dref 宣告成 REF TO ty_i（已完整型別），CREATE DATA … TYPE ('ty_i') 其實沒發揮動態的意義；改寫用泛型 REF TO data＋ASSIGN，才是動態建立的真正用法。
  • 8.2 原本只 CATCH cx_sy_create_object_error，方法名打錯時 CX_SY_DYN_CALL_ILLEGAL_METHOD 沒人接，直接短傾印（ST22）。改寫加上父類別 CX_SY_DYN_CALL_ERROR。
  • 8.2 原範例把 lo_product 宣告成 REF TO zcl_product，那就不必動態建立了。改寫用 REF TO object，才能示範「編譯時完全不知道類別」。
  • WRITE 清單改為 CL_DEMO_OUTPUT（示範用）；正式報表請用 SALV。
實務提醒：動態建立別支程式裡的本地類別要用絕對型別名，例如 '\PROGRAM=ZREP_CLS_C06\CLASS=LCL_CLASS'。另外，動態程式碼繞過了編譯器檢查，拼錯字要到執行時才爆；能用「介面＋工廠」解決的（見 7-5 章設計模式），就不要用字串拼類別名。真正適合動態建立的場景是：類別名來自設定表（策略模式的註冊表）、外掛式框架。

3. Field-Symbols：基本型別、結構與泛型內表（8.3）

觀念：Field-Symbol 是「別名」而不是複本——ASSIGN 之後對 <fs> 的任何讀寫都直接作用在原資料物件上。三種典型型別：完整型別（TYPE i）、結構（TYPE ty_struc）、泛型（TYPE any、TYPE ANY TABLE、TYPE INDEX TABLE、TYPE STANDARD TABLE）。泛型內表的差別：ANY TABLE 可以指向 HASHED 表但不能用索引；INDEX TABLE 可用索引但不接受 HASHED 表。觀念細節見 5-3 章「資料參考與欄位符號」。

4. 跨程式存取：ASSIGN ('(程式)變數') 與 PERFORM IN PROGRAM（8.4、8.5）

觀念：8.4 在 ZREP_CLS_D04 建立全域類別 ZCL_VALUES 的物件、設定 m_value_1 = 1356，再以 PERFORM call_ref IN PROGRAM zrep_cls_d05 呼叫另一支程式的子程序；8.5 的 CALL_REF 用 ASSIGN ('(ZREP_CLS_D04)go_value->m_value_1') TO <ref> 直接「伸手」讀取呼叫端的全域變數，再把整個物件參照指派給 REF TO object，動態呼叫 SET_VALUE。這種「(程式名)變數名」的寫法俗稱 dirty assign，只要兩支程式載入在同一個內部工作階段（internal session 的同一個程式群組）就能互相存取全域資料。

S/4HANA 現況：dirty assign 是 SAP 未公開保證的技巧——對方程式的全域變數名稱一改、或載入順序不同，就 sy-subrc = 4 或讀到錯的東西，編譯器與「使用處清單」都查不到這層依賴。它唯一的合理用途是在 User Exit／增強裡「偷看」標準程式的資料（例如 '(SAPMV45A)XVBAP[]'），而且要把它當成最後手段，並寫明升級時要回歸測試（見 3-3 章）。自己寫的兩支 Z 程式之間，絕對不要這樣傳資料。PERFORM … IN PROGRAM 也屬於舊式模組化，新程式不應再使用 FORM。

5. 泛型參數：一支方法比較整數、浮點與字元（8.6～8.8）

觀念：8.6 MAX_I 只接 TYPE i、8.7 MAX_F 只接 TYPE f，邏輯完全相同卻要寫兩次；8.8 MAX_G 把參數改成泛型 TYPE any，同一支程序就能比較三種型別。這是 ABAP 的「泛型」：型別在呼叫時由實參決定。泛型型別的層級：any（任何）> data > simple（基本型別＋純字元結構）> numeric／clike／csequence 等。

API可用版本建立方式說明
CL_HTTP_CLIENT／IF_HTTP_CLIENTNetWeaver 6.20 起，1809 可用CREATE_BY_URL（網址寫死在程式）或 CREATE_BY_DESTINATION（引用 SM59 類型 G 目的地）1809 的標準選擇；ABAP Cloud 中不可用

系統設定清單（交給 Basis，但 ABAPer 要知道）：

  • SM59 建 類型 G（HTTP 連線到外部伺服器）目的地，例如 Z_SINA_HQ：主機 hq.sinajs.cn、埠 80 或 443、路徑前綴留空；需要時在「特殊選項」設 Proxy 主機與埠；按「連線測試」確認。用目的地而不是把網址寫死，換環境（DEV／QAS／PRD）、換 Proxy、換憑證都不必改程式，也能用權限物件 S_ICF 控管誰能用這個目的地。
  • HTTPS：SM59 的「登入與安全性」頁啟用 SSL，選 SSL 用戶端 PSE（通常 ANONYM 匿名或 DFAULT 標準）；再到 STRUST 把對方網站的根憑證與中繼憑證匯入同一個 SSL client PSE 並儲存。沒匯憑證的典型錯誤是 SSL handshake 失敗、ICM_HTTP_SSL_ERROR。
  • SMICM：確認 ICM 在執行、HTTPS 服務與 SSL 函式庫（CommonCryptoLib）已載入；錯誤追蹤看 ICM 的 dev_icm 追蹤檔。
  • 防火牆：應用伺服器對外 80／443 要開；很多企業的 SAP 伺服器完全不能直接上網，一定要走公司 Proxy。

  • 基底代理類別 ZCB_PERSIST_MARA_KEY（系統維護，不要改）；
  • 代理類別 ZCA_PERSIST_MARA_KEY（Singleton，靜態屬性 AGENT），提供 CREATE_PERSISTENT、GET_PERSISTENT、DELETE_PERSISTENT 等方法，參數依鍵欄位產生（I_MATNR…）；
  • 持久類別本身的 GET_／SET_ 存取方法（GET_MAKTX( )…）。

練習與自我檢核

  1. 為什麼動態建立物件時仍必須用 CREATE OBJECT … TYPE (name)，而動態呼叫方法時必須用 CALL METHOD oref->(name)？
    參考答案要點：NEW 運算子與函數式方法呼叫都要求編譯時已知型別／方法；動態名稱只有敘述形式支援。參數用 PARAMETER-TABLE（ABAP_PARMBIND_TAB），KIND 以呼叫端角度填寫。
  2. FIELD-SYMBOLS <t> TYPE ANY TABLE 與 TYPE INDEX TABLE 差在哪？哪一種可以指向 HASHED 表？
    參考答案要點：ANY TABLE 可指向三種表但不能用索引存取；INDEX TABLE 可用索引，只接受 STANDARD／SORTED。
  3. 8.5 的 ASSIGN ('(ZREP_CLS_D04)go_value') 有什麼風險？如果兩支 Z 程式需要共用資料，應該怎麼設計？
    參考答案要點：未保證的技巧、名稱改了就失效、Where-Used 查不到；改成物件參數、全域類別靜態屬性／Singleton、MEMORY ID、Shared Objects 或資料表。
  4. 8.8 的 MAX_G 為什麼不能改成 RETURNING 參數？ABAP 有什麼內建函數可取代它？
    參考答案要點：RETURNING 必須完整型別；可用 nmax／nmin（數值）、cmax／cmin（字元），7.02 起。
  5. 寫一支「輸入資料表名、顯示前 100 筆」的程式時，至少要做哪三項檢查？
    參考答案要點：表名存在且為透明表（DD02L 或 CL_ABAP_DYN_PRG）、權限 S_TABU_NAM、筆數上限＋ORDER BY PRIMARY KEY。
  6. 用 RTTC 組出只含 CARRID、CONNID、PRICE 三欄的內表，需要哪幾個類別與敘述？

  7. BAL 應用日誌的設定與查詢分別用哪些 TCODE？為什麼一定要排 SLG2？
    參考答案要點：SLG0 定義物件／子物件、SLG1 查詢、SLG2 刪除；否則 BALHDR／BALDAT 無限成長。
  8. 8.12 的「日誌級別」解決什麼問題？為什麼不建議用巨集包裝？
    參考答案要點：正式環境只記重點、除錯時調高門檻不必改程式；巨集無法逐步除錯、無型別檢查，Clean ABAP 不建議。

    參考答案要點：Function ALV 只維護不新寫；CL_GUI_ALV_GRID 用於可編輯／細部控制／多 ALV 同畫面；CL_SALV_TABLE 用於唯讀報表。註解寫成不存在的 CL_GUI_SALV_TABLE。

  11. 在 1809 呼叫外部 HTTPS 服務，需要 Basis 做哪些設定？程式用哪個類別？
