「把 SAP 的資料弄出去」是顧問最常接到、也最容易被低估的需求。本章拆解某製造業客戶三份實戰素材：ZMMI0001 物料主檔下傳 MES／ECN 外部資料庫、ZPPI0001 生產工單（表頭、作業、元件）下傳，以及「把 MARD 庫存下載成 Excel」的需求與三個網路範例。前兩支名為「下載」，實際上是透過 DBCO 連線用 Native SQL 寫進外部資料庫；第三個才是真正的檔案輸出。讀完你會知道：什麼時候該寫檔、什麼時候該寫 DB、什麼時候根本不該寫程式，以及 Excel 在 S/4HANA 上有哪些標準做法。

2. 共同骨架：中繼表 ＋ DBCO 外部 DB ＋ 狀態回寫

ZMMI0001 與 ZPPI0001 是同一位開發者的同一套模式，看懂一支就看懂另一支：

  1. 選資料：依日期（物料的建立／變更日；工單的建立／變更日）取出要傳的主鍵。
  2. 寫 SAP 中繼表：把要送的欄位（含文字、單位換算、評價資料）整理進 Z 表，保留一份「最後送出的樣子」。
  3. 連外部 DB：DBCO 定義的次要資料庫連線（原程式註解為「Connect ETL System」），EXEC SQL CONNECT TO → SET CONNECTION。
  4. 先刪後插：外部表以主鍵 DELETE 再 INSERT（全量覆蓋單一物料／工單）。
  5. 狀態回寫：成功把中繼表表頭 UPSTS = 'S'、錯誤訊息清空；失敗 UPSTS = 'E'，DB_ERRO_MESS 存 Native SQL 例外文字。
  6. 結果 ALV：流水號 SEQ、主鍵、STATUS（TEXT-S21 成功／TEXT-S22 失敗）、錯誤訊息。

中繼表的價值：出問題時先比對「SAP 中繼表」與「外部表」，就能立刻分辨是 SAP 取數錯、還是寫入外部失敗——這是本案例最值得保留的設計。缺點是它讓資料多了一份，必須有重送（UPSTS = 'E' 再跑一次）的機制，ZPPI0001 就是用 UPSTS IN ('', 'E') 挑出待送資料。

4. ZMMI0001 程式架構與欄位對照

主流程：SELECT_MARA_RTN → PROCESS_T_MARA_RTN（逐筆物料）→ OUTPUT_ALV_RTN。逐筆物料時：

  1. SELECT_SINGLE_ZMMFILEHD0001：中繼表已有此料號 → W_EXIST_FG = 'Y'。

5. ZMMI0001 關鍵段落現代改寫（一）：一次取數與語言 fallback

原程式在 LOOP 裡對每筆物料、每個工廠做十幾次 SELECT SINGLE *（MAKT、TSPAT、T023T、T001K、T001、MBEW、T025T…），1,000 筆物料 × 5 個工廠就是數萬次資料庫往返。改寫原則：先一次取回，再在記憶體查。

METHOD select_data.
  SELECT matnr, ersda, laeda, mtart, mbrsh, matkl, meins, bismt, spart, mstae,
         brgew, gewei, ntgew, laeng, breit, hoehe, meabm, volum, voleh,
         groes, ean11, numtp, magrv, rmatp, raube, prdha
    FROM mara
    WHERE matnr IN @mt_matnr
      AND ( laeda = @mv_date OR ersda = @mv_date )
    ORDER BY matnr
    INTO TABLE @mt_mara.
  IF mt_mara IS INITIAL.
    RETURN.
  ENDIF.

  " 工廠層：MARC + 評價範圍 → 公司代碼 → 幣別，一次 JOIN
  SELECT c~matnr, c~werks, c~ekgrp, c~mmsta, c~beskz, c~sobsl, c~plifz,
         b~bklas, b~stprs, b~peinh, b~vprsv, t~waers
    FROM marc AS c
    INNER JOIN t001k AS k ON k~bwkey = c~werks
    INNER JOIN t001  AS t ON t~bukrs = k~bukrs
    LEFT OUTER JOIN mbew AS b ON b~matnr = c~matnr
                             AND b~bwkey = c~werks
                             AND b~bwtar = @space
    FOR ALL ENTRIES IN @mt_mara
    WHERE c~matnr = @mt_mara-matnr
    INTO TABLE @mt_plant.
  SORT mt_plant BY matnr werks.          " FOR ALL ENTRIES 不保證順序，明確排序

  SELECT matnr, vkorg, vtweg
    FROM mvke
    FOR ALL ENTRIES IN @mt_mara
    WHERE matnr = @mt_mara-matnr
    INTO TABLE @mt_sales.
  SORT mt_sales BY matnr vkorg vtweg.

  SELECT matnr, spras, maktx
    FROM makt
    FOR ALL ENTRIES IN @mt_mara
    WHERE matnr = @mt_mara-matnr
    INTO TABLE @mt_makt.
  SORT mt_makt BY matnr spras.          " 讓「任一語言」變成「代碼最小的語言」，結果可重現
ENDMETHOD.
評價層級假設：T001K 以 BWKEY = WERKS 串接，前提是評價層級設在工廠（絕大多數客戶如此）。若評價層級是公司代碼，BWKEY 會是公司代碼，此 JOIN 會整批落空——上線前在 SE16N 看一眼 T001K 即可確認。

語言 fallback 是這支程式最大的隱性風險。原程式第三層寫的是「SELECT SINGLE * FROM makt WHERE matnr = …」（不指定語言），HANA 沒有預設排序，同一支程式今天拿到德文、明天拿到日文都有可能——這正是 Casper 在成本評價 H／E 案例踩過的坑。改寫時把「優先序」寫成資料，而不是寫成 IF 巢狀：

CONSTANTS: c_lang_en TYPE spras VALUE 'E',
           c_lang_zf TYPE spras VALUE 'M'.     " ZF 繁體中文的內部代碼

METHOD get_maktx.
  " 優先序：英文 → 繁中 → 其他語言中代碼最小者（mt_makt 已依 matnr spras 排序）
  rv_maktx = COND #(
    WHEN line_exists( mt_makt[ matnr = iv_matnr spras = c_lang_en ] )
      THEN mt_makt[ matnr = iv_matnr spras = c_lang_en ]-maktx
    WHEN line_exists( mt_makt[ matnr = iv_matnr spras = c_lang_zf ] )
      THEN mt_makt[ matnr = iv_matnr spras = c_lang_zf ]-maktx
    ELSE VALUE #( mt_makt[ matnr = iv_matnr ]-maktx OPTIONAL ) ).
ENDMETHOD.

METHOD get_domain_text.
  " 取代 FORM call_dd_domvalue_text_get：VPRSV（價格控制）、BESKZ（採購類型）
  DATA ls_dd07v TYPE dd07v.
  CALL FUNCTION 'DD_DOMVALUE_TEXT_GET'
    EXPORTING
      domname  = iv_domname
      value    = CONV domvalue_l( iv_value )
      langu    = c_lang_en
    IMPORTING
      dd07v_wa = ls_dd07v.
  rv_text = ls_dd07v-ddtext.
ENDMETHOD.
TSPAT、T023T、T141T、TNTPB、TVEGRT、T142T、T025T、T460T 都是同一模式：一次把需要的鍵全部讀回、依鍵＋語言排序、再用同一個優先序方法取值。原程式 T023T 的第三層寫 spras = ''（空白語言），其他表則是不指定語言，兩者行為不同，改寫時統一成「其他語言中代碼最小者」並在規格書寫明。

6. ZMMI0001 關鍵段落現代改寫（二）：長文字與寫入外部 DB

原程式用 thead-tdspras = 'EN' 呼叫 READ_TEXT。TDSPRAS 是 1 碼的內部語言代碼，'EN' 被截成 'E' 才「剛好能用」；另外 CONCATENATE … INTO 不加 RESPECTING BLANKS，每行 TDLINE 尾端的空白被吃掉，英文字會黏在一起。

METHOD read_long_text.
  " iv_object / iv_id：MATERIAL/GRUN、MATERIAL/IVER、MVKE/0001
  DATA lt_lines TYPE STANDARD TABLE OF tline WITH EMPTY KEY.

  CALL FUNCTION 'READ_TEXT'
    EXPORTING
      id        = iv_id
      language  = c_lang_en                 " 1 碼內部代碼，不是 'EN'
      name      = iv_name
      object    = iv_object
    TABLES
      lines     = lt_lines
    EXCEPTIONS
      not_found = 1
      OTHERS    = 2.
  IF sy-subrc <> 0.
    RETURN.                                  " 沒有文字是正常情況，不當錯誤
  ENDIF.

  " 行與行之間補一個空白，避免英文單字黏在一起
  rv_text = concat_lines_of( table = VALUE string_table( FOR l IN lt_lines ( CONV string( l-tdline ) ) )
                             sep   = ` ` ).
ENDMETHOD.

METHOD sales_text_name.
  " MVKE 銷售文字的 TDNAME = 料號(40 碼補空白) + 銷售組織 + 配銷通路
  rv_name = |{ iv_matnr WIDTH = 40 }{ iv_vkorg }{ iv_vtweg }|.
ENDMETHOD.
原程式寫 thead-tdname+40(4) = vkorg，偏移 40 是 S/4HANA 的 40 碼料號；在 ECC（18 碼料號）同樣的文字鍵偏移是 18。這支程式若要回頭在 ECC 用就會讀不到銷售文字——在 S/4 上則是正確的。

寫外部 DB 改用 ADBC（CL_SQL_CONNECTION），取代禁用的 EXEC SQL。重點是把「刪舊＋插新」放在外部 DB 的同一個交易裡，任一句失敗就 ROLLBACK，外部資料維持原樣：

CONSTANTS c_dbcon TYPE dbcon-con_name VALUE 'ETL_DB'.   " DBCO 連線名（佔位符）

METHOD push_material.

7. ZMMI0001 原程式問題與上線注意

#原程式寫法問題改法
1TABLES:、OCCURS 0 WITH HEADER LINE、MOVE-CORRESPONDING、全 FORM禁用語法；全域 header line 讓每個 FORM 都偷偷依賴「目前這一筆」區域類別＋方法，參數明確傳遞
2EXEC SQL Native SQL禁用；錯誤只在 TRY 裡記文字，CONNECT 失敗的 error_text 被丟掉，後面照樣 INSERTADBC（第 6 節），連線失敗直接中止該筆
3DELETE_MODE_SAP 先刪中繼表並 COMMIT WORK，再 INSERT若後續組資料失敗，中繼表這筆物料已被永久刪除，也沒有 UPSTS 可重送中繼表用 MODIFY … FROM TABLE 覆蓋，並刪除「已不存在的明細」；全部成功才 COMMIT
4外部 DB 先 DELETE、INSERT 失敗再 DELETE失敗時外部資料被清空（MES 查不到料號），比「舊資料」更糟同一交易＋ROLLBACK（第 6 節）
5SAP 端失敗（W_ERROR_FG = 'X'）時 CHECK 跳過 INSERT_MODE_DBUPSTS 沒被更新，ALV 顯示失敗但訊息空白，使用者不知道為什麼每一種失敗都要寫入訊息
6不指定語言的 SELECT SINGLE、SELECT SINGLE * FROM marm WHERE matnr = …（停用的 SELECT_MEINH_RTN）HANA 無預設排序，取到哪一筆不固定明確鍵或明確 ORDER BY（第 5 節）
7WRITE mbew-stprs TO l_stprs CURRENCY … NO-GROUPINGWRITE 依執行者的小數點格式（SU01 設定）：背景作業使用者若設 1.234,56 格式，送出去的是逗號小數外部欄位用數值型別；必須是文字時用 |{ stprs NUMBER = RAW }|，幣別小數位另行處理（如 JPY、TWD）
8CONVERSION_EXIT_CUNIT_OUTPUT 傳 language = sy-langu單位外部碼依登入語言不同（例如 PC／ST），前景與背景跑出來的單位碼可能不一樣固定語言（如 'E'）並寫進介面規格
9程式開頭把 AEDAT = ERSDA、ERDAT = LAEDA（看起來寫反），隨後又被 IF W_EXIST_FG 覆蓋死碼造成誤讀；ERTIM 用 MARA-LAST_CHANGED_TIME 當建立時間也不精確刪除死碼；建立時間取 SAP 實際寫入中繼表的時間戳記
10REUSE_ALV_GRID_DISPLAY禁用CL_SALV_TABLE（見 2-3 章第 2 節）
上線注意：(1) DBCO 連線的帳號密碼存在 SAP，不要寫在程式或變式；連線名用常數或客製設定表。(2) 背景作業使用者的語言、小數格式、日期格式要與規格一致。(3) S_MATNR 若要指定一批料號，請用多筆 EQ，不要用 BT 區間：區間比的是字典序，料號混用英數（如 A-100 與 A-99）或有 ALPHA 前導零時，就會多抓或漏抓（Casper 的第 2 條經驗）。(4) 外部 DB 端的欄位長度要按 S/4HANA 40 碼料號開。
先找標準：物料主檔下傳本來就有標準做法——ALE／IDoc MATMAS 訊息類型＋變更指標（BD52、BD21、WE20），或 S/4HANA 的 released CDS／OData（如 API_PRODUCT_SRV）讓 MES 主動來讀。自寫 DB 直連是最右端的選項，採用前要說得出為什麼標準不行（Casper 的第 3 條經驗）。

8. ZPPI0001 業務情境、選擇畫面與程式架構

業務情境：MES 需要 SAP 生產工單的表頭（計畫數量、完工數量、日期、狀態、銷售訂單）、作業（工作中心、確認號碼、標準值）與元件（需求數量、儲存地點）。工單建立或變更時，中繼表 ZPPPRORHD0001 由其他程式（例如工單存檔出口，本素材未附）寫入並清空 UPSTS；本程式負責補上完工資訊並推到外部 DB。

欄位定義說明
S_AUFNRFOR AUFK-AUFNR工單
S_AUARTFOR AUFK-AUART訂單類型
S_WERKSFOR AUFK-WERKS工廠
S_ERDATFOR AUFK-ERDAT DEFAULT SY-DATLO日期（CHECK_DATE 強制必填，否則訊息「日期必填」並 STOP）

程式架構：

  1. CHECK_DATE：S_ERDAT 空白就停止。
  2. SELECT_AFPO_RTN（名稱是 AFPO，實際讀 MSEG）：S_ERDAT 期間內 CPUDT_MKPF 輸入的物料憑證，條件 AUFNR 非空、XAUTO 空白、SMBLN 空白、BWART = '101'（工單入庫）。
  3. UPDATE_ZPPPRORHD0001_RTN：每筆 MSEG 呼叫 BAPI_PRODORD_GET_DETAIL（ORDER_OBJECTS 的 HEADER、POSITIONS = 'X'）；中繼表有此工單且表頭 SYSTEM_STATUS CS 'DLV' 時，STAT = 'I0012'、TXT04 = 'DLV'；若 WEMNG ≠ 第一個項目的 DELIVERED_QUANTITY，更新 WEMNG，AEDAT／AETIM 以較晚的 CPUDT_MKPF／CPUTM_MKPF 取代，清空 UPSTS（變成待送）後 MODIFY。
  4. SELECT_ZPPPRORHD0001_RTN：AUFNR／AUART／WERKS 符合、(ERDAT IN S_ERDAT OR AEDAT IN S_ERDAT)、UPSTS IN ('', 'E')。
  5. 逐筆工單：作業 ZPPPRORDE0001（工作中心 ARBPL 從 S022 依 AUFNR＋VORNR 補）；元件 ZPPPRORDE0002（先找 AEDAT／AETIM 與表頭相同的版本，找不到就從 RESB 重建：POSNR、RSPOS、MATNR、MATXT＝MAKT 英文說明，無料號時用 POTX1、BDMNG、MEINS、LGORT、SORTF、XLOEK）。
  6. AEDAT IN S_ERDAT → 先刪外部再插入；否則直接插入。外部表 POHEADER 欄位：MANDT、AUFNR、AUART、WERKS、PLNBEZ、GAMNG、WEMNG、GMEIN、GSTRP、GLTRP、TERKZ、TXT、ABLAD、LGORT、KDAUF、KDPOS、KDEIN、VDATU、EDATU、STAT、TXT04、CLSTS 與四個時間欄；POOPERATIONS：VORNR、ARBPL、LTXA1、RUECK、VGW01、VGE01、VGW02、VGE02；POCOMPONENT：POSNR、RSPOS、MATNR、MATXT、BDMNG、MEINS、LGORT、SORTF、XLOEK。單位欄（GMEIN、VGE01、VGE02、MEINS）一樣先轉外部碼。
  7. 狀態回寫與結果 ALV 同 ZMMI0001。

9. ZPPI0001 關鍵段落現代改寫

第一段：找出「期間內有入庫或入庫沖銷的工單」，去重後再逐張讀狀態。原程式每一筆 MSEG 都呼叫一次 BAPI，同一張工單分十次入庫就讀十次。

METHOD select_gr_orders.
  " S/4HANA：MSEG 是相容性 view，讀取會導向 MATDOC；新開發也可直接讀 MATDOC
  " 或 released CDS I_MaterialDocumentItem_2
  SELECT DISTINCT aufnr
    FROM mseg
    WHERE cpudt_mkpf IN @mt_date
      AND aufnr      <> @space
      AND xauto       = @abap_false
      AND bwart      IN ( '101', '102' )      " 102 沖銷也要觸發，否則完工數永遠不會減回來
    ORDER BY aufnr
    INTO TABLE @DATA(lt_orders).

  LOOP AT lt_orders INTO DATA(ls_order).
    update_delivered( ls_order-aufnr ).
  ENDLOOP.
ENDMETHOD.

第二段：判斷 DLV 狀態。原程式 system_status CS 'DLV' 是子字串比對，「PDLV（部分交貨，I0074）」也會命中，部分入庫的工單會被誤標成 I0012 已交貨。改成直接查狀態表 JEST 的 I0012：

METHOD update_delivered.
  SELECT SINGLE a~objnr, p~wemng
    FROM aufk AS a
    INNER JOIN afpo AS p ON p~aufnr = a~aufnr
    WHERE a~aufnr = @iv_aufnr
      AND p~posnr = '0001'                    " 明確指定主產出項目，不用「INDEX 1」
    INTO @DATA(ls_order).
  IF sy-subrc <> 0.
    RETURN.
  ENDIF.

  " I0012 = DLV（已交貨）；INACT 空白才是目前有效的狀態
  SELECT SINGLE @abap_true
    FROM jest
    WHERE objnr = @ls_order-objnr
      AND stat  = 'I0012'
      AND inact = @space
    INTO @DATA(lv_dlv).
  IF lv_dlv = abap_false.
    RETURN.                                   " 業務規則：只有 DLV 才回寫完工數
  ENDIF.

  SELECT SINGLE * FROM zppprorhd0001
    WHERE aufnr = @iv_aufnr
    INTO @DATA(ls_hd).
  IF sy-subrc <> 0 OR ls_hd-wemng = ls_order-wemng.
    RETURN.
  ENDIF.

  ls_hd-stat  = 'I0012'.
  ls_hd-txt04 = 'DLV'.
  ls_hd-wemng = ls_order-wemng.
  GET TIME STAMP FIELD DATA(lv_ts).
  CONVERT TIME STAMP lv_ts TIME ZONE sy-zonlo INTO DATE ls_hd-aedat TIME ls_hd-aetim.
  CLEAR ls_hd-upsts.                          " 標記為待送
  MODIFY zppprorhd0001 FROM @ls_hd.
ENDMETHOD.
原程式用 READ TABLE it_position INDEX 1 取 DELIVERED_QUANTITY。聯產品或多項目工單時「第一筆」取決於 BAPI 回傳順序，屬於 Casper 的第 1 條經驗：任何「取第一筆」都要先說清楚依什麼排序。改寫直接讀 AFPO 並指定 POSNR（或加總所有項目，依業務決定）。AFPO-WEMNG 就是該項目的已入庫量。

第三段：作業的工作中心。原程式從 S022（LIS 資訊結構「工單作業」）補 ARBPL，S022 需要 LIS 更新有開才有資料，S/4HANA 也不建議再依賴 LIS。改從工單途程本身讀：

METHOD select_operations.
  SELECT o~vornr, o~ltxa1, o~rueck, w~arbpl,
         v~vgw01, v~vge01, v~vgw02, v~vge02
    FROM afko AS k
    INNER JOIN afvc AS o ON o~aufpl = k~aufpl
    INNER JOIN afvv AS v ON v~aufpl = o~aufpl
                        AND v~aplzl = o~aplzl
    LEFT OUTER JOIN crhd AS w ON w~objid = o~arbid
                             AND w~objty = 'A'          " A = 工作中心
    WHERE k~aufnr = @iv_aufnr
    ORDER BY o~vornr
    INTO TABLE @rt_ops.
ENDMETHOD.

METHOD select_components.
  SELECT r~rsnum, r~rspos, r~posnr, r~matnr, r~bdmng, r~meins, r~lgort,
         r~sortf, r~xloek, r~potx1,
         t~maktx
    FROM resb AS r
    LEFT OUTER JOIN makt AS t ON t~matnr = r~matnr
                             AND t~spras = 'E'
    WHERE r~aufnr = @iv_aufnr
    ORDER BY r~rspos
    INTO TABLE @DATA(lt_resb).

  rt_comp = VALUE #( FOR r IN lt_resb
                     ( mandt = sy-mandt
                       aufnr = iv_aufnr
                       posnr = r-posnr
                       rspos = r-rspos
                       matnr = r-matnr
                       matxt = COND #( WHEN r-matnr IS INITIAL THEN r-potx1 ELSE r-maktx )
                       bdmng = r-bdmng
                       meins = r-meins
                       lgort = r-lgort
                       sortf = r-sortf
                       xloek = r-xloek ) ).
ENDMETHOD.

11. 真正的「檔案下載」：前景 gui_download 與背景 OPEN DATASET

講義把 ZMMI0001 放在「檔案下載」單元，是因為很多客戶的 MES 只收檔案。若對方要的是檔案而不是 DB，同一份中繼資料的輸出方式如下。規則只有一條：前景（有 SAP GUI）存到使用者電腦；背景作業（sy-batch = abap_true）只能寫應用伺服器——背景沒有 GUI，呼叫前端服務會直接失敗。舊的 WS_DOWNLOAD／GUI_DOWNLOAD 函數一律改用 CL_GUI_FRONTEND_SERVICES。

METHOD build_csv.
  " 數值用 NUMBER = RAW：不受使用者小數點格式影響；料號去前導零
  rt_lines = VALUE #( ( `MATNR;WERKS;LGORT;LABST;INSME;SPEME` ) ).
  LOOP AT it_stock INTO DATA(ls).
    APPEND |{ ls-matnr ALPHA = OUT };{ ls-werks };{ ls-lgort };| &&
           |{ ls-labst NUMBER = RAW };{ ls-insme NUMBER = RAW };{ ls-speme NUMBER = RAW }|
      TO rt_lines.
  ENDLOOP.
ENDMETHOD.

METHOD save_file.
  IF sy-batch = abap_false.
    " 前景：讓使用者選路徑
    DATA: lv_name TYPE string, lv_path TYPE string, lv_full TYPE string,
          lv_action TYPE i.
    cl_gui_frontend_services=>file_save_dialog(
      EXPORTING default_extension = `csv`
                default_file_name = |stock_{ sy-datum }.csv|
                initial_directory = `C:\temp\`
      CHANGING  filename = lv_name  path = lv_path
                fullpath = lv_full  user_action = lv_action
      EXCEPTIONS OTHERS = 1 ).
    IF sy-subrc <> 0 OR lv_action <> cl_gui_frontend_services=>action_ok.
      RETURN.
    ENDIF.
    cl_gui_frontend_services=>gui_download(
      EXPORTING filename  = lv_full
                filetype  = 'ASC'
                codepage  = '4110'          " UTF-8
                write_bom = abap_true       " Excel 直接開啟中文不亂碼
      CHANGING  data_tab  = it_lines
      EXCEPTIONS OTHERS   = 1 ).
    IF sy-subrc <> 0.
      MESSAGE ID sy-msgid TYPE 'S' NUMBER sy-msgno DISPLAY LIKE 'E'
              WITH sy-msgv1 sy-msgv2 sy-msgv3 sy-msgv4.
    ENDIF.
  ELSE.
    " 背景：寫應用伺服器，路徑由邏輯檔名（TCODE FILE）決定，不寫死
    DATA(lv_file) = |/interface/out/stock_{ sy-datum }.csv|.
    TRY.
        OPEN DATASET lv_file FOR OUTPUT IN TEXT MODE ENCODING UTF-8
             WITH BYTE-ORDER MARK.
        LOOP AT it_lines INTO DATA(lv_line).
          TRANSFER lv_line TO lv_file.
        ENDLOOP.
        CLOSE DATASET lv_file.
      CATCH cx_sy_file_open cx_sy_file_authority cx_sy_file_io INTO DATA(lx_file).
        MESSAGE lx_file->get_text( ) TYPE 'E'.
    ENDTRY.
  ENDIF.
ENDMETHOD.
應用伺服器檔案用 AL11 查看、CG3Y 下載到本機；正式環境請用 FILE 定義邏輯路徑並以 FILE_VALIDATE_NAME 驗證，避免使用者或變式把檔案寫到任意目錄（目錄穿越）。細節見 4-4 章第 11 節。

13. 三個網路案例評析：SMW0 範本、SAP_CONVERT_TO_XLS_FORMAT、abap2xlsx

案例做法評析
一SMW0 上傳 Excel 範本（WWWDATA，RELID = 'MI'，SRTF2 = 0）→ file_exist 檢查、POPUP_TO_CONFIRM 詢問覆蓋 → file_save_dialog → DOWNLOAD_WEB_OBJECT 下載只下載「空白範本」，並沒有把資料填進去，本身不解決需求；適合「給使用者一份上傳用範本」。預設副檔名 .xls、檔名 = 範本描述＋日期。file_exist 檢查的是沒有路徑的檔名，實際上判斷不到使用者選的位置——應在 file_save_dialog 之後檢查
二先用某部落客自寫的類別從 SMW0 下載「儲存格設為文字格式」的範本，WAIT UP TO 2 SECONDS 等檔案落地，再以 SAP_CONVERT_TO_XLS_FORMAT（I_LINE_HEADER = 'X'）把全 CHAR 欄位的內表寫進去；表頭列用 RTTS（CL_ABAP_STRUCTDESCR）動態塞欄位名該類別不是 SAP 標準；靠 WAIT 等檔案是競態條件；SAP_CONVERT_TO_XLS_FORMAT 依賴前端 Excel（OLE），背景作業不能用、產生的是舊 .xls 格式。「全部轉 CHAR 防止格式跑掉」的觀念值得保留（料號前導零、長數字不被 Excel 轉成科學記號）
三abap2xlsx：ZCL_EXCEL 建活頁簿、ZCL_EXCEL_STYLE 設粗體／置中／細框線，lo_style->get_guid( ) 取樣式鍵給 set_cell( ip_style = … )，set_merge 合併儲存格，ZCL_EXCEL_WRITER_2007 輸出 XSTRING，再轉二進位 gui_download( filetype = 'BIN' )功能最完整（樣式、合併、公式、多工作表、圖表），不需要前端 Excel，背景也能產生 .xlsx。但要注意下方說明

14. SAP 標準替代方案：SALV 匯出、CL_SALV_BS_LEX、XCO_CP_XLSX

不裝任何套件也能在伺服器端產生真正的 .xlsx。依「越標準越好」排序：

方案 A：直接用 ALV 的匯出。把 GT_STOCK 以 CL_SALV_TABLE 顯示，使用者按工具列「匯出 → 試算表」即可（見 2-3 章第 14 節）。需求若只是「使用者要一份 Excel」，這就是答案，一行額外程式都不用寫。

方案 B：程式產生 xlsx（前景下載或背景寄信）——CL_SALV_TABLE 的 to_xml：

METHOD export_xlsx_salv.
  TRY.
      cl_salv_table=>factory( IMPORTING r_salv_table = DATA(lo_salv)
                              CHANGING  t_table      = gt_stock ).
      DATA(lv_xlsx) = lo_salv->to_xml( xml_type = if_salv_bs_xml=>c_type_xlsx ).
    CATCH cx_salv_msg INTO DATA(lx_salv).
      MESSAGE lx_salv->get_text( ) TYPE 'S' DISPLAY LIKE 'E'.
      RETURN.
  ENDTRY.

  DATA(lt_bin) = cl_bcs_convert=>xstring_to_solix( lv_xlsx ).
  cl_gui_frontend_services=>gui_download(
    EXPORTING bin_filesize = xstrlen( lv_xlsx )
              filename     = |C:\\temp\\mard_{ sy-datum }.xlsx|
              filetype     = 'BIN'
    CHANGING  data_tab     = lt_bin
    EXCEPTIONS OTHERS      = 1 ).
ENDMETHOD.

方案 C：CL_SALV_BS_LEX——SALV 匯出背後的引擎，可自訂欄位目錄（欄名、隱藏欄）：

METHOD export_xlsx_lex.
  TRY.
      cl_salv_table=>factory( IMPORTING r_salv_table = DATA(lo_salv)
                              CHANGING  t_table      = gt_stock ).
    CATCH cx_salv_msg.
      RETURN.
  ENDTRY.

  DATA(lt_fcat) = cl_salv_controller_metadata=>get_lvc_fieldcatalog(
                    r_columns      = lo_salv->get_columns( )
                    r_aggregations = lo_salv->get_aggregations( ) ).
  " 例：改欄名
  LOOP AT lt_fcat ASSIGNING FIELD-SYMBOL(<ls_fcat>).
    <ls_fcat>-coltext = SWITCH #( <ls_fcat>-fieldname
                                  WHEN 'LABST' THEN '良品數'
                                  WHEN 'INSME' THEN '品檢中'
                                  WHEN 'SPEME' THEN '鎖定中'
                                  ELSE <ls_fcat>-coltext ).
  ENDLOOP.

  DATA(lo_result) = cl_salv_ex_util=>factory_result_data_table(
                      r_data         = REF #( gt_stock )
                      t_fieldcatalog = lt_fcat ).
  cl_salv_bs_lex=>export_from_result_data_table(
    EXPORTING is_format            = if_salv_bs_lex_format=>mc_format_xlsx
              ir_result_data_table = lo_result
    IMPORTING er_result_file       = DATA(lv_xlsx) ).
  " lv_xlsx：前景用 gui_download(BIN)、背景用 OPEN DATASET … IN BINARY MODE 或 CL_BCS 寄出
ENDMETHOD.

15. 選型總結：先標準、再檔案、最後才是 DB 直連

需求第一選擇（標準）其次最後手段
看庫存、偶爾匯出MB52、MMBE、Fiori「Stock – Multiple Materials」＋匯出客製 SALV 報表＋工具列匯出客製程式產生 xlsx
每天定時給外部一份檔案標準 IDoc 檔案埠（WE21 File port）背景作業 OPEN DATASET ＋ 外部 SFTP 取檔—
物料主檔給 MESMATMAS IDoc＋變更指標／OData API中繼表＋檔案DBCO 直寫外部 DB（ZMMI0001）
工單給 MESLOIPRO／LOIROU IDoc、Digital Manufacturing 整合中繼表＋檔案DBCO 直寫外部 DB（ZPPI0001）
DB 直連的三個代價：(1) 對方改欄位，SAP 這邊就壞，而且要到執行時才知道；(2) 兩邊交易無法一起 COMMIT（SAP 中繼表成功、外部失敗的情況一定會發生），必須有 UPSTS 與重送；(3) 網路或外部 DB 停機時，背景作業卡在連線逾時。能用 IDoc／API 就不要直連。
三個實務坑在本章的對應：HANA 無預設排序 → 語言 fallback 的「任一語言」、BAPI 項目「INDEX 1」、MARD 下載未排序；列舉優於區間 → S_MATNR、S_AUFNR 指定清單時用多筆 EQ；先標準再客製 → MATMAS／LOIPRO／MB52 與 ALV 匯出。
