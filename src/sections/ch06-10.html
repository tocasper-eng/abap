3. 技巧 1：F1 → 技術資訊（F9）→ SE11 判斷物件類型

（依講義步驟整理）

  1. 在交易畫面把游標放在目標欄位，按 F1（或 ? 按鈕）開說明視窗。
  2. 在說明視窗按 F9 或「技術資訊（Technical Information）」按鈕。
  3. 看「Field data」區塊：Table name、Field name、Data element；「Screen data」區塊：Program name、Screen number（技巧 5 要用）。
  4. 雙擊 Table name 進 SE11，畫面標題會寫明是 Transparent table、View 或 Structure。

原文範例：銷售訂單（VA01）初始畫面的「售達方」，技術資訊是 KUAGV-KUNNR（也可能看到 RV45S-KUNNR，版本不同結構名不同）。4.0B 以前的技術資訊一律把物件叫「表」，4.5B 以後會標示 KUAGV 是結構；原圖三對照了表 VBAK、視圖 VIVEDA、結構 KUAGV 三種 SE11 畫面。

看到結構名別灰心：像 RV45A、KUAGV、KOMV、MSEGO2 這類結構是「畫面工作區」，程式在 PBO／PAI 把真正的表欄位搬進搬出。字首也有線索：R*（如 RV45A、RM07M）多半是交易畫面專用結構；*K／*P 成對（VBAK／VBAP、EKKO／EKPO、LIKP／LIPS）是表頭／項目（德文 Kopf＝表頭、Position＝項目）。
S/4HANA 的 Fiori 畫面沒有 F1 技術資訊。Fiori app 請改看 app 的 OData 服務與背後的 CDS view（瀏覽器 F12 看 $metadata，或到 Fiori Apps Reference Library 查 app 的技術資料），再從 CDS 往下找表（第 13 節）。

4. 技巧 2～4：文字欄位、INCLUDE 表、既有報表／Query

技巧 2：文字欄位

畫面標籤是「Short text」、欄位名 STTXT、資料元素 CO_STTXT，或欄位尾巴有一個「紙＋筆」的「維護長文本」圖示時，資料多半不在一般表裡，而是 SAPscript 文字：表頭 STXH、文字行 STXL（原文說 raw 格式、非 ASCII，所以不能直接 SELECT，要用 READ_TEXT）。（依講義步驟整理）

  1. 點欄位後的「維護長文本」圖示進長文本畫面。
  2. 選單 Goto → Header，記下 Text name、Language、Text ID、Text object 四個參數。
  3. 把四個參數交給 READ_TEXT。
" 讀銷售訂單表頭文字（Text object VBBK、Text ID 0001 為常見設定，依系統實際 Goto → Header 為準）
PARAMETERS p_vbeln TYPE vbak-vbeln OBLIGATORY.

START-OF-SELECTION.
  DATA lt_lines TYPE STANDARD TABLE OF tline WITH EMPTY KEY.

  CALL FUNCTION 'READ_TEXT'
    EXPORTING
      id                      = '0001'
      language                = sy-langu
      name                    = CONV tdobname( p_vbeln )
      object                  = 'VBBK'
    TABLES
      lines                   = lt_lines
    EXCEPTIONS
      id                      = 1
      language                = 2
      name                    = 3
      not_found               = 4
      object                  = 5
      reference_check         = 6
      wrong_access_to_archive = 7
      OTHERS                  = 8.
  IF sy-subrc <> 0.
    MESSAGE |訂單 { p_vbeln ALPHA = OUT } 沒有表頭文字（subrc = { sy-subrc }）| TYPE 'S' DISPLAY LIKE 'W'.
    RETURN.
  ENDIF.

  " 文字行合併成一個字串
  DATA(lv_text) = REDUCE string( INIT s = ``
                                 FOR ls_line IN lt_lines
                                 NEXT s = |{ s }{ ls_line-tdline } | ).
  WRITE / lv_text.
要知道某筆單據「有哪些文字」，可以先 SELECT tdobject, tdname, tdid, tdspras FROM stxh WHERE tdname = @lv_name 列出清單——STXH 的表頭欄位可以直接查，只有 STXL 的內文要用 READ_TEXT。

技巧 3：INCLUDE 表

結構可能 .INCLUDE 其他結構或表。如果被 include 的正好是含該欄位的透明表，就找到了。原文範例：銷售訂單項目概覽的「條件類型」是 KOMV-KSCHL，KOMV 是結構，但它 include 了表 KONV，所以資料在 KONV-KSCHL。在 SE11 裡 .INCLUDE 列的「Component type」就是被包含的物件名，被包含的欄位以藍字顯示，雙擊即可進入。

S/4HANA 修正：定價條件已從 KONV 搬到 PRCD_ELEMENTS（KONV 在 S/4 不再寫入）。所以在 S/4 用技巧 3 看到 KOMV → KONV 時，實際要查的是 PRCD_ELEMENTS（以 KNUMV 串 VBAK／VBRK）。

技巧 4：既有報表、Query、資訊結構

在「找現成報表」階段看過、但不完全符合需求的報表或 ABAP Query（SQ01／SQVI）、LIS 資訊結構，如果剛好也顯示這個欄位，打開它的程式碼或 InfoSet，看它從哪張表取值，搜尋就結束了。這也是 Casper「先找標準」原則的延伸：標準報表已經幫你把表找好了。

5. 技巧 5：Debugger 觀察點（以及 IMPORT、SELECT 中斷點）

（依講義步驟整理，並換成新版 Debugger 的操作）

  1. 從技術資訊記下 Program name 與畫面欄位名（例如 SAPMV45A、RV45A-KWMENG）。
  2. 進交易，在要輸入的前一刻於命令欄輸入 /h 開啟除錯（原文走 ABAP Editor → Debugging，現在不必）。
  3. 在 Debugger 的 Breakpoints／Watchpoints 頁籤建立 Watchpoint：變數填畫面結構欄位（全域變數可寫成 (SAPMV45A)RV45A-KWMENG）。
  4. 按 F8 讓程式自己跑——變數值一改變就停在「改值那一行的下一行」。譯者一開始以為要按 F5 一步一步追，三個月後才發現直接 F8 即可。
  5. 往上讀幾行程式碼，通常就能看到 rv45a-kwmeng = vbap-kwmeng 這類搬值敘述，右邊就是字典物件（仍可能是表、視圖或結構，但已經非常接近）。

觀察點不觸發的唯一常見例外是值由 IMPORT 從記憶體帶進來：此時改用 Breakpoint at Statement IMPORT，原文說最多三步就能找到。新版 Debugger 還可以設 Breakpoint at Statement SELECT（或 OPEN SQL 相關敘述），每次讀資料庫就停一次，對「值是從 DB 讀進來」的欄位特別有效。

原文限制：3.1I 以前的 Debugger 沒有觀察點功能，技巧 5 不能用。Debugger 的其他實戰技巧（Breakpoint at Message、Watchpoint SY-MSGNO）見 第 6-2 章。

6. 技巧 6～8：值表、資料元素 Where-used、Z_DATA_ELEMENT

技巧 6：值表（Value Table）

從技術資訊雙擊 Data element → 再進它的 Domain → Value Range 頁籤最下方的 Value Table。主數據欄位（如 KUNNR）通常有值表（KNA1），直接就是答案；交易數據（如訂單數量 KWMENG）沒有值表，要繼續找。

譯本修正：譯者在 ECC5 找不到 Value Table，猜測「可能就是檢查表或搜尋說明」。正確說法是——值表定義在 Domain 上（Value Range 頁籤），檢查表定義在表欄位上（Entry help/check 頁籤，透過外來鍵）。建立外來鍵時，系統會把 Domain 的值表當成建議的檢查表。兩者相關但不是同一個東西，搜尋說明（Search Help）又是另一回事。

技巧 7：資料元素的 Where-used

SAP 在表之間搬資料時，目標欄位常常（不是總是）用同一個資料元素。（依講義步驟整理）：技術資訊雙擊 Data element → Utilities → Where-used List → 勾 Table fields → Enter。清單會列出所有用這個資料元素的表、視圖、結構；常用欄位清單會很長（原文：4.0B 的 KUNNR 出現在 743 個物件、KUNAG 在 276 個表），不常用的欄位則很快就能看出來。譯者的經驗：在「在哪些物件中找」的選項裡不勾結構，剩下的就都是表。

技巧 8：自建視圖 Z_DATA_ELEMENT

原文建議在 SE11 建一個資料庫視圖 Z_DATA_ELEMENT，只列出「真的存資料的表」。原圖十的定義如下：

項目內容
Base tablesDD03L、DD02L、DD02T、DD04T
JoinsDD03L-TABNAME = DD02L-TABNAME；DD03L-TABNAME = DD02T-TABNAME；DD03L-ROLLNAME = DD04T-ROLLNAME
View fieldsTABNAME、FIELDNAME、TABCLASS、FLD_POSNR（DD03L-POSITION）、KEYFLAG、MANDATORY、DATA_ELEM（DD03L-ROLLNAME）、CHECKTABLE、NOTNULL、TBL_DESCR（DD02T-DDTEXT）、D_E_DESCR（DD04T-DDTEXT）

使用方式：SE11 顯示該視圖 → Utilities → Table contents → DATA_ELEM = 要找的資料元素 → F8。今天不必真的建一個 Z 視圖（還要進傳輸），用一段 ABAP SQL 就能得到同樣結果，語言也能改成登入語言：

" Z_DATA_ELEMENT 的程式版：列出使用某資料元素、且真的存資料的表
PARAMETERS p_roll TYPE rollname OBLIGATORY DEFAULT 'KUNNR'.

START-OF-SELECTION.
  SELECT l~tabname,
         l~fieldname,
         t~tabclass,
         l~position   AS fld_posnr,
         l~keyflag,
         l~mandatory,
         l~rollname   AS data_elem,
         l~checktable,
         l~notnull,
         x~ddtext     AS tbl_descr,
         e~ddtext     AS d_e_descr
    FROM dd03l AS l
    INNER JOIN dd02l AS t
      ON  t~tabname  = l~tabname
      AND t~as4local = l~as4local
      AND t~as4vers  = l~as4vers
    LEFT OUTER JOIN dd02t AS x
      ON  x~tabname    = l~tabname
      AND x~ddlanguage = @sy-langu
      AND x~as4local   = l~as4local
      AND x~as4vers    = l~as4vers
    LEFT OUTER JOIN dd04t AS e
      ON  e~rollname   = l~rollname
      AND e~ddlanguage = @sy-langu
      AND e~as4local   = 'A'
    WHERE l~rollname = @p_roll
      AND l~as4local = 'A'
      AND t~tabclass IN ( 'TRANSP', 'CLUSTER', 'POOL' )
    ORDER BY l~tabname, l~position              " HANA 沒有預設排序，一定要排
    INTO TABLE @DATA(lt_hit).

  TRY.
      cl_salv_table=>factory( IMPORTING r_salv_table = DATA(lo_alv)
                              CHANGING  t_table      = lt_hit ).
      lo_alv->get_functions( )->set_all( ).
      lo_alv->get_columns( )->set_optimize( ).
      lo_alv->display( ).
    CATCH cx_salv_msg INTO DATA(lx_salv).
      MESSAGE lx_salv TYPE 'I' DISPLAY LIKE 'E'.
  ENDTRY.
S/4HANA 上 pool／cluster 表幾乎都已轉成透明表（BSEG、KONV、CDPOS、A0xx 條件表等），所以條件寫 tabclass = 'TRANSP' 就夠；在 ECC 上才需要把 CLUSTER、POOL 一起納入。

技巧 9：視圖

交易資料通常存在幾張分層連結的表，SAP 常替它們定義視圖。原文範例：「銷售訂單：單行概覽」的訂單數量顯示為 RV45A-KWMENG（結構）；已知訂單號是 VBAK-VBELN，就去看 VBAK 的 Where-used 裡的視圖——VIVEDA 連結了 VBAK、VBUK、VBAP，於是在 VBAP 找到 KWMENG。（譯注：ECC5 的 VIVEDA 只剩 VBAK、VBAP；S/4 已無 VBUK，見第 17 節。）用程式列出「含某張表的所有字典視圖」：

" 列出所有以某張表為基底表的 DDIC 視圖（DD26S＝視圖基底表，DD25L＝視圖表頭）
PARAMETERS p_tab TYPE tabname OBLIGATORY DEFAULT 'VBAK'.

START-OF-SELECTION.
  SELECT s~viewname,
         h~viewclass,          " D=資料庫視圖 C=投影視圖 M=維護視圖 H=說明視圖
         s~tabpos,
         x~ddtext
    FROM dd26s AS s
    INNER JOIN dd25l AS h
      ON  h~viewname = s~viewname
      AND h~as4local = s~as4local
      AND h~as4vers  = s~as4vers
    LEFT OUTER JOIN dd25t AS x
      ON  x~viewname   = s~viewname
      AND x~ddlanguage = @sy-langu
      AND x~as4local   = s~as4local
      AND x~as4vers    = s~as4vers
    WHERE s~tabname  = @p_tab
      AND s~as4local = 'A'
    ORDER BY s~viewname, s~tabpos
    INTO TABLE @DATA(lt_views).

  " 同一視圖的其他基底表，就是「跟 p_tab 有關的表家族」
  LOOP AT lt_views INTO DATA(ls_view) GROUP BY ls_view-viewname INTO DATA(lv_view).
    SELECT tabname FROM dd26s
      WHERE viewname = @lv_view AND as4local = 'A'
      ORDER BY tabpos
      INTO TABLE @DATA(lt_base).
    DATA(lv_line) = |{ lv_view } → { concat_lines_of(
                        table = VALUE string_table( FOR b IN lt_base ( CONV string( b-tabname ) ) )
                        sep   = `, ` ) }|.
    WRITE / lv_line.
  ENDLOOP.
CDS view 的基底表不在 DD26S。S/4 上要找「哪些 CDS view 讀了 VBAK」，請用 ADT 對表按 Get Where-used List，或 ADT 的 Dependency Analyzer（第 13 節）。

技巧 10：邏輯資料庫

業務相關的表常被串在同一個邏輯資料庫（SE36）。原文：VBAK 的 Where-used 選「邏輯資料庫」，會看到一個銷售單據相關的 LDB（原文寫作 AAV），它的結構樹直接顯示 VBAK → VBAP 的連結。譯者補注：這其實是「從已知表找另一張表」，跟欄位本身關係不大。LDB 在 S/4 已不建議新開發使用，但拿來當「表關係圖」看仍然有用（例如 BRF、PNP、DDF 等）。

技巧 11：同畫面其他欄位

同一交易的其他欄位可能直接連到資料庫表，而表頭表往往就含你要的欄位。原文範例：銷售訂單初始畫面的售達方是 RV45S-KUNNR（結構，資料元素 KUNAG 在 4.0B 被 276 張表使用，很難從 Where-used 找），但同畫面的「訂單」欄位是 VBAK-VBELN，打開 VBAK 就看到它也有 KUNNR。譯注：甚至不限目前畫面，同程式的其他畫面也可以找。

技巧 12：應用階層

原文路徑：Data Browser（SE16）→ 表名欄位按 F4 → SAP Applications → Application Hierarchy，沿選單樹找到你的應用，底下的表可能就有你的欄位。現在直接用 SE81（應用階層）或在 SE84 以「應用元件（Application Component）」過濾。

技巧 13：圖形

SE11 顯示一張你認為相關的表 → Utilities → Graphic（舊版在 Extras 下），會畫出該表與其他表的外來鍵關係，可以看到整個業務物件的表家族。譯注：圖常常過大，而且連結多半是指向主數據，實用性一般。

3.1I 以前沒有應用階層與圖形功能，技巧 12、13 不能用。

8. 技巧 14～15：變更紀錄與 CDHDR／CDPOS

技巧 14：交易內的變更紀錄

很多單據開了變更文件記錄，變更資訊裡就含「受影響的表名與欄位名」。做法：在測試機把目標欄位改一下存檔，再看變更紀錄。原文列出的選單路徑 （依講義步驟整理，選單名稱依版本略有差異）：

模組／物件選單路徑
PM／客服技術物件Extras → [Display Changes 或 Environment] → Display Changes
PM／客服工單Extras → Order documents → [Changes 或 Extras] → Display Changes
通知單Extras → Notification documents → Changes
合約與計畫Environment → Changes
SD 銷售訂單Environment → Changes
SD 交貨單Environment → Changes

有多筆變更時點進你關心的那一筆（通常是最新的）。TCDOB、TCDOBT 列出所有變更文件物件類別（Object class）及其表，可以先查你的應用有沒有支援變更文件；現在用 SCDO 看更方便。

技巧 15：直接查 CDHDR／CDPOS

交易裡找不到變更紀錄時，直接查變更文件表：CDHDR（Change Document Header）與 CDPOS（Change Document Position，原文笑稱英德混搭命名）。原做法是改完存檔後 SE11 → CDHDR → Table contents，用今天日期、時間範圍、自己的帳號找出那一筆，複製 CHANGENR 再去 CDPOS 查——CDPOS 那一筆就有表名、欄位名、新值與舊值。譯者問「有沒有 TCODE 可查？」——一段 SQL 就一次到位：

" 我今天改了什麼？→ 直接看到表名 TABNAME、欄位名 FNAME、新舊值
SELECT h~objectclas,
       h~objectid,
       h~changenr,
       h~udate,
       h~utime,
       h~tcode,
       p~tabname,
       p~fname,
       p~chngind,          " U=修改 I=新增 D=刪除
       p~value_old,
       p~value_new
  FROM cdhdr AS h
  INNER JOIN cdpos AS p
    ON  p~objectclas = h~objectclas
    AND p~objectid   = h~objectid
    AND p~changenr   = h~changenr
  WHERE h~username = @sy-uname
    AND h~udate    = @sy-datum
  ORDER BY h~utime DESCENDING, p~tabname, p~fname
  INTO TABLE @DATA(lt_chg)
  UP TO 200 ROWS.

LOOP AT lt_chg INTO DATA(ls_chg).
  WRITE: / ls_chg-utime, ls_chg-tcode, ls_chg-tabname, ls_chg-fname,
           ls_chg-value_old, '→', ls_chg-value_new.
ENDLOOP.
ECC 上 CDPOS 是 cluster 表，不能 JOIN，只能先查 CDHDR 再以 FOR ALL ENTRIES 讀 CDPOS；S/4HANA 已轉成透明表，上面的 JOIN 可直接用。CDHDR 在正式機是大表，WHERE 一定要帶 UDATE／USERNAME 或 OBJECTCLAS＋OBJECTID。

9. 技巧 16～18：SQL 追蹤、執行時間分析、資料內容比對

技巧 16：SQL 追蹤（ST05）

原文稱為「嚴肅的考古」，譯者則說這是他最常用的方法——而且實務上確實如此。（依講義步驟整理，改寫成現行 ST05 畫面）

  1. 開兩個視窗：視窗 A 進交易但先不執行；視窗 B 進 ST05。
  2. 視窗 B 勾 SQL Trace → Activate Trace（建議用 Activate Trace with Filter，限定自己的帳號，避免錄到別人）。
  3. 切回視窗 A 執行交易（要找「寫入」就存檔；要找「讀取」就把畫面開到該欄位出現為止）。
  4. 視窗 B → Deactivate Trace → Display Trace。
  5. 在清單裡搜尋欄位名；看 SELECT 的 WHERE 與 INSERT／UPDATE 的表。選取一列可按 Display Table（顯示該表的字典定義；依版本按鈕名稱可能是「DDIC Information」），或按 Explain 看執行計畫。
  6. 原文要 System → List → Save → Local file 存成 doc 再用 Word 搜尋；現在清單是 ALV，直接 Export → Spreadsheet，存到 C:\temp\ 用 Excel 篩選即可。

譯注的關鍵心法：修改一個值再看追蹤裡的資料庫更新（UPDATE／INSERT），總能找到目標欄位——讀取可能讀很多表，但寫入只會寫真正存資料的那幾張。03 號素材的 AGR_DEFINE（角色定義，含複合／衍生角色關係）與 AGR_TCODES（角色與 TCODE 的對應，可查「某角色含哪些 TCODE」或「某 TCODE 被哪些角色使用」）就是作者用 ST05 追到的。ST05 追蹤清單每一欄的意義見 6-3 章第 8 節。

技巧 17：執行時間分析（SE30 → SAT）

原文路徑是 System → Utilities → Runtime Analysis（SE30），現在改用 SAT：輸入交易碼或程式名 → 執行並完成交易 → 回到 SAT 評估。看 資料庫表（DB Tables） 的命中清單，就是交易過程中存取過的透明表與 pool 表；Hit List 列出所有呼叫過的程式。原文還提到：對結構做 Where-used 並勾「Programs」，有時會列出把該欄位跟資料庫連起來的程式，拿來跟 Hit List 的程式交叉比對，可以縮小範圍。

10. 技巧 19：ZTABLEFIND——用欄位名找表（現代改寫）

03 號素材與 PDF 的技巧 19 是同一支小程式 ZTABLEFIND（由一位顧問提供）。它的意圖是：輸入一個或多個欄位名，找出同時含有這些欄位的表，並可依表類別（TABCLASS）篩選。原程式的寫法與問題：

原寫法問題現代寫法
TABLES: dd02t, dd03l, dd02l全域工作區，禁用DATA 宣告型別＋內嵌宣告
BEGIN OF … OCCURS 0 ＋ INCLUDE STRUCTURE dd03l帶表頭行的內表；把整個 DD03L 結構（數十欄）搬進記憶體只 SELECT 需要的欄位
SELECT * FROM dd03l … 不帶 AS4LOCAL會把非啟用版本也算進來WHERE as4local = 'A'
LOOP AT ified 取 sy-tabix 當「欄位數」只在選擇條件全是單值 EQ 時才對；輸入 CP 萬用字元或區間就算錯COUNT( DISTINCT fieldname ) ＋ HAVING
AT END OF tabname ＋ COLLECT在 ABAP 端分組計數，資料量大時很慢SQL 端 GROUP BY（HANA 下推）
LOOP 內兩個 SELECT SINGLE（DD02T、DD02L）典型 N+1 查詢一次 JOIN
WRITE 清單不能排序、篩選、匯出CL_SALV_TABLE

原文另提到先用 SE16 查 DD03L、再到 DD02L 篩「透明表」，並建議做成 Query 方便重用；相關表有 DD02T（表說明）、DD04T（資料元素說明）、DDFTX（原文說「也有部分對應關係，但不清楚用在哪」——它是欄位說明的文字表，一般不必用）。

REPORT ztablefind.
" 用欄位名找表：輸入多個欄位名，找出「同時含有」這些欄位的表
DATA gv_field TYPE dd03l-fieldname.
DATA gv_class TYPE dd02l-tabclass.

SELECT-OPTIONS: s_field FOR gv_field NO INTERVALS OBLIGATORY,   " 列舉比區間安全
                s_class FOR gv_class NO INTERVALS DEFAULT 'TRANSP'.
PARAMETERS p_all AS CHECKBOX DEFAULT abap_true.                 " 勾：所有欄位都要有

START-OF-SELECTION.
  " 需要命中的欄位數：勾選「全部」時＝輸入的欄位數，否則任一個即可
  DATA(lv_need) = COND i( WHEN p_all = abap_true THEN lines( s_field ) ELSE 1 ).

  SELECT l~tabname,
         t~tabclass,
         x~ddtext,
         COUNT( DISTINCT l~fieldname ) AS hits
    FROM dd03l AS l
    INNER JOIN dd02l AS t
      ON  t~tabname  = l~tabname
      AND t~as4local = l~as4local
      AND t~as4vers  = l~as4vers
    LEFT OUTER JOIN dd02t AS x
      ON  x~tabname    = l~tabname
      AND x~ddlanguage = @sy-langu
      AND x~as4local   = l~as4local
      AND x~as4vers    = l~as4vers
    WHERE l~fieldname IN @s_field
      AND l~as4local  = 'A'
      AND t~tabclass  IN @s_class
    GROUP BY l~tabname, t~tabclass, x~ddtext
    HAVING COUNT( DISTINCT l~fieldname ) >= @lv_need
    ORDER BY l~tabname
    INTO TABLE @DATA(lt_tab).

  IF lt_tab IS INITIAL.
    MESSAGE '找不到同時含有這些欄位的表' TYPE 'S' DISPLAY LIKE 'W'.
    RETURN.
  ENDIF.

  TRY.
      cl_salv_table=>factory( IMPORTING r_salv_table = DATA(lo_alv)
                              CHANGING  t_table      = lt_tab ).
      lo_alv->get_functions( )->set_all( ).
      lo_alv->get_columns( )->set_optimize( ).
      lo_alv->get_display_settings( )->set_list_header( |含 { lines( s_field ) } 個欄位的表：{ lines( lt_tab ) } 張| ).
      lo_alv->display( ).
    CATCH cx_salv_msg INTO DATA(lx_salv).
      MESSAGE lx_salv TYPE 'I' DISPLAY LIKE 'E'.
  ENDTRY.
實用組合：同時輸入 VBELN、POSNR、MATNR 並勾「全部」，就能快速列出「以銷售單據項目為主鍵又帶物料」的表（VBAP、LIPS、VBRP、VAPMA……），是找「項目層」表最快的方法。s_field 用 NO INTERVALS 只允許列舉單值——欄位名比大小（BT）沒有業務意義，正是 Casper「列舉比區間安全」的原則。

11. 用資料元素或網域找表，以及 SE84

欄位名在不同表可能不同（售達方在 VBAK 叫 KUNNR、在 VBRK 叫 KUNAG、在 VAKPA 叫 KUNDE），但資料元素或網域往往相同。技巧 7 的 Where-used 是互動版，下面是程式版，可切換「依資料元素」或「依網域」：

REPORT zfind_table_by_type.
PARAMETERS: p_name TYPE ddobjname OBLIGATORY DEFAULT 'KUNNR',
            p_dom  AS CHECKBOX.                      " 勾＝依網域 DOMNAME 找

START-OF-SELECTION.
  DATA lv_text TYPE as4text.
  DATA lr_roll TYPE RANGE OF dd03l-rollname.     " 空的 RANGE＝不限制
  DATA lr_dom  TYPE RANGE OF dd03l-domname.

  " 先顯示資料元素（或網域）的說明，確認沒打錯；同時決定用哪個條件
  IF p_dom = abap_false.
    SELECT SINGLE ddtext FROM dd04t
      WHERE rollname = @p_name AND ddlanguage = @sy-langu AND as4local = 'A'
      INTO @lv_text.
    lr_roll = VALUE #( ( sign = 'I' option = 'EQ' low = p_name ) ).
  ELSE.
    SELECT SINGLE ddtext FROM dd01t
      WHERE domname = @p_name AND ddlanguage = @sy-langu AND as4local = 'A'
      INTO @lv_text.
    lr_dom = VALUE #( ( sign = 'I' option = 'EQ' low = p_name ) ).
  ENDIF.
  DATA(lv_head) = |{ COND string( WHEN p_dom = abap_true THEN `網域` ELSE `資料元素` ) } { p_name }：{ lv_text }|.
  WRITE / lv_head.
  ULINE.

  SELECT l~tabname, l~fieldname, l~rollname, l~domname, l~keyflag, x~ddtext
    FROM dd03l AS l
    INNER JOIN dd02l AS t
      ON  t~tabname  = l~tabname
      AND t~as4local = l~as4local
      AND t~as4vers  = l~as4vers
    LEFT OUTER JOIN dd02t AS x
      ON  x~tabname    = l~tabname
      AND x~ddlanguage = @sy-langu
      AND x~as4local   = l~as4local
      AND x~as4vers    = l~as4vers
    WHERE l~rollname IN @lr_roll
      AND l~domname  IN @lr_dom
      AND l~as4local = 'A'
      AND t~tabclass = 'TRANSP'
      AND t~tabname NOT LIKE '/%'                  " 排除命名空間表，清單短一點
    ORDER BY l~tabname, l~position
    INTO TABLE @DATA(lt_hit).

  LOOP AT lt_hit INTO DATA(ls_hit).
    DATA(lv_key) = COND string( WHEN ls_hit-keyflag = abap_true THEN `主鍵` ELSE `` ).
    WRITE: / ls_hit-tabname, ls_hit-fieldname, ls_hit-rollname, lv_key, ls_hit-ddtext.
  ENDLOOP.
用「空的 RANGE 等於不限制」這個特性，一段 SELECT 就能切換兩種查法，不必寫兩個幾乎一樣的 SELECT。

不寫程式的做法：SE84。SE84（Repository Information System）→ ABAP Dictionary → Fields → Table Fields，可以用欄位名、資料元素、網域任一條件查，還能限制「只看透明表」與套件、應用元件。這是技巧 7 與技巧 19 的標準 GUI 版本，給顧問用最方便。

12. 找到表之後：列出表的欄位（DDIF_FIELDINFO_GET 與 RTTS）

找到表後，下一步是「這張表有哪些欄位、主鍵是什麼、檢查表是誰」。SE11 當然看得到；要在程式裡動態取得有兩種標準做法。

做法一：DDIF_FIELDINFO_GET

PARAMETERS p_tab TYPE ddobjname OBLIGATORY DEFAULT 'VBAP'.

START-OF-SELECTION.
  DATA lt_dfies TYPE ddfields.          " DFIES 的表型別

  CALL FUNCTION 'DDIF_FIELDINFO_GET'
    EXPORTING
      tabname        = p_tab
      langu          = sy-langu
    TABLES
      dfies_tab      = lt_dfies
    EXCEPTIONS
      not_found      = 1
      internal_error = 2
      OTHERS         = 3.
  IF sy-subrc <> 0.
    MESSAGE |{ p_tab } 不是字典表或結構| TYPE 'S' DISPLAY LIKE 'E'.
    RETURN.
  ENDIF.

  " 主鍵排前面（DDIF_FIELDINFO_GET 已把 .INCLUDE 展開成實際欄位）
  DATA(lt_out) = lt_dfies.
  SORT lt_out BY keyflag DESCENDING position.

  LOOP AT lt_out INTO DATA(ls_f).
    WRITE: / ls_f-position, ls_f-fieldname, ls_f-keyflag, ls_f-rollname,
             ls_f-datatype, ls_f-leng, ls_f-checktable, ls_f-fieldtext.
  ENDLOOP.

做法二：RTTS（CL_ABAP_STRUCTDESCR）

PARAMETERS p_tab TYPE tabname OBLIGATORY DEFAULT 'VBAP'.

START-OF-SELECTION.
  cl_abap_typedescr=>describe_by_name(
    EXPORTING  p_name         = p_tab
    RECEIVING  p_descr_ref    = DATA(lo_type)
    EXCEPTIONS type_not_found = 1
               OTHERS         = 2 ).
  IF sy-subrc <> 0 OR lo_type->kind <> cl_abap_typedescr=>kind_struct.
    MESSAGE |{ p_tab } 不是結構型別| TYPE 'S' DISPLAY LIKE 'E'.

  lo_struct->get_ddic_field_list(
    EXPORTING  p_langu      = sy-langu
    RECEIVING  p_field_list = DATA(lt_fields)
    EXCEPTIONS not_found    = 1
               no_ddic_type = 2
               OTHERS       = 3 ).
  IF sy-subrc = 0.
    DATA(lv_keys) = REDUCE string( INIT k = ``
                                   FOR f IN lt_fields WHERE ( keyflag = abap_true )
                                   NEXT k = |{ k } { f-fieldname }| ).

    WRITE / lv_msg.
  ENDIF.

  " 沒有 DDIC 來源（程式內自訂型別）時，用 components 也能拿到欄位名與型別

    WRITE: / ls_comp-name, ls_comp-type_kind, ls_comp-length.
  ENDLOOP.

DATA gv_vbeln TYPE vbak-vbeln.
SELECT-OPTIONS s_vbeln FOR gv_vbeln NO INTERVALS OBLIGATORY.   " 列舉訂單號，不用區間

START-OF-SELECTION.
  " 訂單 → 出貨（LIPS-VGBEL/VGPOS）→ 請款（VBRP-VGBEL/VGPOS）
  SELECT a~vbeln  AS order_no,
         a~posnr  AS order_item,
         a~matnr,
         a~kwmeng,
         k~gbstk,                              " S/4：整體狀態在 VBAK（ECC 在 VBUK）
         l~vbeln  AS delivery,
         l~posnr  AS delivery_item,
         l~lfimg,
         r~vbeln  AS billing,
         r~posnr  AS billing_item,
         r~fkimg,
         r~netwr
    FROM vbak AS k
    INNER JOIN vbap AS a
      ON a~vbeln = k~vbeln
    LEFT OUTER JOIN lips AS l
      ON  l~vgbel = a~vbeln
      AND l~vgpos = a~posnr
    LEFT OUTER JOIN vbrp AS r
      ON  r~vgbel = l~vbeln
      AND r~vgpos = l~posnr
    WHERE k~vbeln IN @s_vbeln
    ORDER BY a~vbeln, a~posnr, l~vbeln, l~posnr, r~vbeln, r~posnr
    INTO TABLE @DATA(lt_flow).

  " 還沒請款的出貨項目（VALUE # 要從左邊推型別，所以先宣告目標）
  DATA lt_open LIKE lt_flow.
  lt_open = VALUE #( FOR f IN lt_flow WHERE ( delivery IS NOT INITIAL AND billing IS INITIAL ) ( f ) ).

  TRY.
      cl_salv_table=>factory( IMPORTING r_salv_table = DATA(lo_alv)
                              CHANGING  t_table      = lt_flow ).
      lo_alv->get_columns( )->set_optimize( ).
      lo_alv->get_display_settings( )->set_list_header( |未請款出貨項目：{ lines( lt_open ) } 筆| ).
      lo_alv->display( ).
    CATCH cx_salv_msg INTO DATA(lx_salv).
      MESSAGE lx_salv TYPE 'I' DISPLAY LIKE 'E'.

VALUE #( FOR … ) 的 # 會從左邊推型別，左邊若是內嵌宣告 DATA( ) 就無從推導、編譯失敗，所以上例先 DATA lt_open LIKE lt_flow. 再賦值。

19. 實務心法：找對表之後的三件事

  1. 先找標準，再想客製。找到表只是起點。確認需求是否已有標準報表（技巧 4）、released CDS view 或 BAPI 可用；要在交易上加欄位或加檢查，接著照 第 6-2 章 找 BAdI／Enhancement Spot，而不是直接改標準程式。每往「修改標準」多走一步，升級成本就高一個量級。
  2. HANA 沒有預設排序。本章每一段 SELECT 都寫了 ORDER BY：DD03L 不排序時欄位順序會亂；訂單流程不排序時「第一筆出貨」每次不同。Casper 在成本評價案遇過同一個坑——item category H 與 cost component E 兩種角度同時存在，沒排序就一下抓到 H、一下抓到 E，結果不穩定，最後固定抓 H（見 6-3 章第 16 節）。
  3. 條件用列舉，不用區間。找表程式的欄位名、訂單號都用 NO INTERVALS。欄位名、單據號做 BT 比的是字典序，不是業務意義；遇到號碼段不連續、ALPHA 前導零（訂單號內碼是 10 碼補零）就會漏抓或多抓。
找表口訣：F1 看技術資訊 → 結構就開 ST05 → 改一個值看 UPDATE → 找到表再找 CDS。另外要記住 S/4 的「四大搬家」：MKPF／MSEG → MATDOC；BSEG 等索引與總計 → ACDOCA；KONV → PRCD_ELEMENTS；VBUK／VBUP → 單據表頭／項目；客戶／供應商主檔 → BP（BUT000）。
