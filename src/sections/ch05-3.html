2. ABAP 程式的結構與執行環境

程式的組成（强晟 p8）：一支 ABAP 程式可包含下列元件——

  • 處理區塊（Processing Blocks）：包含 ABAP 敘述；不可再細分或巢狀。
  • 屬性（Attributes）：程式類型、定點運算開關等技術設定。
  • 畫面（Screens）：畫面佈局＋流程邏輯（Screen Painter）；選擇畫面與清單則是用 ABAP 敘述產生的特殊畫面。
  • GUI 介面（GUI Status／Title）：選單、標準工具列、應用工具列、功能鍵設定。
  • 文字（Text Elements）與文件（Documentation）：與語言相關、可翻譯。文件要從使用者角度寫；技術說明請寫在程式註解裡。
  • 變式（Variants）：選擇畫面的預設輸入值。

原始碼分為全域宣告與處理區塊兩部分。處理區塊有兩種：事件區塊（以事件關鍵字開頭，遇到下一個處理區塊即結束）與對話模組和程序（MODULE、METHOD、FUNCTION 等，以成對關鍵字包住）。所有處理區塊的集合稱為處理邏輯。

可執行程式的事件順序（强晟 p17–19）：LOAD-OF-PROGRAM → INITIALIZATION → 顯示標準選擇畫面（之前觸發 AT SELECTION-SCREEN OUTPUT，使用者按 Enter／執行後觸發 AT SELECTION-SCREEN）→ START-OF-SELECTION（預設事件：沒歸屬任何事件的敘述都算它的）→ 邏輯資料庫的 GET node／GET node LATE → END-OF-SELECTION。清單事件：TOP-OF-PAGE、END-OF-PAGE、AT LINE-SELECTION（功能碼 PICK＝F2／雙擊）、AT USER-COMMAND，細部清單最多 20 層。

對話式交易的執行：LOAD-OF-PROGRAM → 畫面處理器處理 TCODE 定義的初始畫面 → PROCESS BEFORE OUTPUT（PBO 模組）→ 同名欄位由 ABAP 傳到畫面 → 顯示 → 使用者按功能 → 畫面欄位傳回 ABAP 同名欄位 → PROCESS AFTER INPUT（PAI）→ 下一個畫面。詳見 4-2 章 Dialog、5-9 章 BC410。

開發版、非啟用版、啟用版與 LOAD（强晟 p11–13；Col18 p62–65）：

  • 開發版存在 Repository，是 Workbench 唯一看得到的版本；要執行必須先由 ABAP Compiler 產生（Generate）成執行期物件，也就是 LOAD。
  • 筆記作者在 p13 寫下「LOAD 是什麼？不解」。答案（Col18 p63）：LOAD 是程式的執行期物件，主要是連結到 C 函數的位元組碼（byte code），存在資料庫並緩衝在應用伺服器，避免每次執行都重新編譯。
  • LOAD 自動重新產生的時機：尚無 LOAD、或 LOAD 已過期（開發版被改過、或程式用到的 ABAP Dictionary 物件被改過）。也可手動：ABAP Editor 選單「程式 → 產生」。
  • 修改並儲存已啟用的物件，系統會另建一個非啟用版；儲存非啟用版不影響 LOAD，所以語法不必正確。從編輯器直接執行可執行程式時用的是非啟用版（臨時產生、不緩衝不存檔）；其他所有情況都執行啟用版。
  • 啟用的步驟：① 儲存（產生新的非啟用版）並做語法檢查 → ② 覆蓋目前的啟用版（之後就沒有非啟用版了）→ ③ 產生新的執行期版本、更新 LOAD。
傳輸之後跑 SGEN。系統間傳輸的永遠是開發版；匯入後目標系統會丟棄受影響的 LOAD，但不會自動重新產生，要等第一個使用者呼叫時才產生，所以上線當下使用者會感覺「第一次很慢」。大量傳輸（例如 Support Package、升級）後請 Basis 執行 SAP Load Generator（SGEN）。傳輸流程見 1-1 章。

工作程序（Work Process）的組成（强晟 附錄一 p196）：畫面處理器（處理 SAP GUI 通訊、畫面流程邏輯、欄位傳遞）、ABAP 處理器（執行處理邏輯、與資料庫介面溝通）、資料庫介面（存取資料表與 Repository 物件、控制交易、管理表緩衝）。工作程序就像「虛擬機器」，讓 ABAP 程式與硬體／作業系統無關。

3. 從敘述到運算式：7.02 與 7.40 的語法演進

Col18 第一課（p11–19）說明 ABAP 從「純敘述語言」走向「運算式導向」的歷程：

  • 早期每個敘述都是「關鍵字＋運算元＋附加項＋句點」。後來 COMPUTE 變成可省略、CALL METHOD 被函數式寫法取代、MOVE 被「=」取代；Web AS 6.10 用 lines( ) 部分取代 DESCRIBE TABLE。
  • NetWeaver 7.02：運算式可以出現在更多位置（例如 IF lv_date > sy-datum + 7、方法參數直接放算式、READ TABLE ... INDEX 後放算式），並新增字串運算式與字串函數；函數式方法可以串接（-> 左邊可以是方法呼叫）。
  • NetWeaver 7.40：型別轉換與轉型（CONV、CAST）、條件指派（COND、SWITCH）、建構運算式（VALUE、NEW、REF、CORRESPONDING、EXACT、REDUCE、FILTER）、表運算式、內嵌宣告。

內嵌宣告（Inline Declaration，7.40+）的規則（Col18 p31–35）：

  • 型別由上下文推導；生命週期與可見範圍和「在同一位置用 DATA 靜態宣告」完全相同。放在事件區塊或對話模組裡的 DATA( ) 就是全域變數；放在方法裡才是區域變數。變數在執行期從程式（或方法）一開始就存在，但在宣告位置之前不能被靜態引用。
  • 右側運算式的型別必須是靜態已知；泛型回傳值（any、simple、numeric…）不能內嵌宣告；CONV #( ) 放在內嵌宣告右側也不行（左邊沒有型別可推）。
  • LOOP／READ TABLE 的內嵌工作區範圍會超出迴圈：同一程序中第二個 LOOP ... INTO DATA(ls_line) 會語法錯誤。
原廠的四條建議：① 不要因為懶得查型別就用內嵌宣告；② 不要重複使用內嵌宣告的變數（兩個 TRY、兩個迴圈要用同一變數就老實用 DATA 宣告）；③ 不要在離宣告很遠的地方使用；④ 避免用內嵌宣告建立全域資料物件。

資料物件分類：依內部結構分為基本欄位、結構、內表、參考；依記憶體管理分為扁平（flat）與深（deep）——string、xstring、內表、參考都是 deep；只要含一個 deep 元件（含 include 與子結構）的結構就是深結構。深結構有許多限制：不能整個放在 SELECT 的 INTO 裡（要列出元件）、不能用位移（offset）存取（筆記引用 SAP Note 176336、176337）。

字面值（Literals）三種：

  • 數值字面值：數字序列（可帶正負號），在 i 值域內就是 i，否則是 p（最多 31 位）。
  • 文字欄位字面值 '...'：型別 c，1～255 字元，尾端空白會被忽略。
  • 字串字面值 `...`（反引號）：型別 string，最長 255，保留尾端空白，可以是長度 0。字面值內要放同種引號時連打兩次。

可見範圍與生命週期（强晟 p25–28；Col18 p28–31）：

  • FORM、FUNCTION、METHOD 內的 DATA 是區域變數，生命週期＝該程序執行期間；同名時區域遮蔽全域。
  • MODULE 與事件區塊內的 DATA 仍是全域變數——SAP 建議不要在模組和事件區塊中寫 DATA。TABLES 宣告的結構不論寫在哪裡都是全域。
  • 類別屬性的生命週期從實例化開始，到最後一個參考被刪除為止；全域變數與程式同壽。
  • STATICS：可見範圍仍限於該程序，但生命週期延長到整個程式（可用於函數模組、子程式、靜態方法）。
  • 初始值的建立時機：全域資料在程式開始時；屬性在實例化時；函數群組的全域資料在該群組第一個函數模組被呼叫時；區域資料在程序被呼叫時。

5. 數值運算：整數、壓縮數、浮點與十進位浮點

ABAP 會依運算式裡出現的型別決定用哪一種算術，同一個算式換了型別結果就可能不同。

算術何時使用（Col18 p127 規則，由上往下判斷）特性
十進位浮點任一運算元或結果欄位是 decfloat16／decfloat34「紙筆」算法；decfloat16 溢位時自動以 decfloat34 重算；精度同 p、值域比 f 大
二進位浮點有 f 且沒有 decfloatIEEE-754 雙精度；二進位誤差難以估計，不適合商業計算
定點（預設）有 p 且沒有 f、decfloat小數點對齊、中間結果用最大長度 p；適合金額
整數全部都是 i（或 int8）最快；非整數結果四捨五入（不是截斷！），中間結果也會四捨五入

其他規則：字元型運算元會先轉成數值（有效能成本，儘量讓運算元與結果同型）；三角、雙曲、exp、log、log10、sqrt、以及 ** 次方，一律用浮點（f 或 decfloat）計算；程式屬性「定點運算（Fixed Point Arithmetic）」預設勾選，關掉後 p 的 DECIMALS 只影響輸出、內部當整數算——商業程式不要關。

lv_i = 5 / 10.                    " 1   ← 四捨五入，和 Java/C 的截斷不同

lv_i = ( 10 * 4 ) / 10.           " 4
lv_i = 7 DIV 2.                   " 3   整數除法
lv_i = 7 MOD 2.                   " 1   餘數
lv_i = ( 1 / 4 ) * ( 2 * 2 ).     " 0   整數運算
lv_i = ( 1 / 4 ) * ( 2 ** 2 ).    " 1   ** 使整個式子改用浮點運算

6. 字元字串、日期時間與正規表示式

字元型與位元組型：c、n、d、t、string 是字元型；x、xstring 是位元組型。字元的值域取決於字碼頁（筆記提到用 SPAD → 完全管理 → 字元集查詢系統可用字碼頁；S/4HANA 一律是 Unicode）。n 型別指派字串時會忽略字母、只留數字並右對齊補 0；d、t 只在畫面輸入時才檢查合法性（效能考量），程式裡可以塞進非法日期。

傳統敘述（强晟 p46）作用S/4HANA 建議寫法
SEARCH搜尋字串（不分大小寫）FIND（7.0 起取代 SEARCH）或 find( )、contains( )
REPLACE取代第一次出現REPLACE ALL OCCURRENCES OF、replace( )
TRANSLATE大小寫或字元對換to_upper( )、to_lower( )、translate( )
SHIFT位移shift_left( )、shift_right( )
CONDENSE壓縮空白condense( )
OVERLAY覆蓋仍可用（少用）
CONCATENATE串接字串範本 | |、&&、concat_lines_of( )
SPLIT拆分仍用 SPLIT ... INTO TABLE，或 segment( )

傳統敘述把所有運算元當成 c 處理（不是轉型）；除了 TRANSLATE、CONDENSE 之外都會設定 sy-subrc；除了 SEARCH 之外都區分大小寫。處理 x／xstring 時（CONDENSE、OVERLAY 除外）要加 IN BYTE MODE。

比較運算子（强晟 p92–93；Col18 p132）：

運算子意義（str1 op str2）
CO／CNstr1 只含 str2 裡的字元／不只含（CN ＝ NOT CO）
CA／NAstr1 至少含 str2 中一個字元／完全不含
CS／NSstr1 含有子字串 str2（不分大小寫）／不含
CP／NPstr1 符合樣式 str2／不符合：* 任意字串、+ 任意單一字元、# 跳脫字元

sy-fdpos 存放符合條件的位移（不符合時為 str1 長度）。CO、CN、CA、NA 區分大小寫且會考慮尾端空白。位元組型有對應的 BYTE-CO、BYTE-CN、BYTE-CA、BYTE-NA、BYTE-CS、BYTE-NS。

日期與時間欄位：d 參與算術或指派給數值時，轉成「西元 0001-01-01 起的天數」；t 轉成「午夜起的秒數」。所以 lv_date + 30 就是加 30 天、兩個日期相減就是天數差。日期起始值一定要用文字字面值（VALUE '20250101'），因為數值字面值是 i，會被解讀成天數。

正規表示式要點（Col18 p142–147；7.0 起支援）：

  • 單一字元：. 任意字元、\d 數字、\u 大寫字母、[ABC] 集合、[^ABC] 否定集合、[A-D] 範圍、[[:digit:]]、[[:upper:]] 字元類別。特殊字元 \ ^ [ ] . 前面要加 \ 跳脫。

7. 結構：巢狀、深結構、具名 Include 與指派規則

結構可用 TYPES BEGIN OF ... END OF 先定義型別再宣告，也可直接 DATA BEGIN OF（同時隱含建立型別）。元件用 結構-元件 存取，所以變數名稱不能含連字號。元件可以是另一個結構（巢狀結構，可無限層），也可以是 string、xstring、內表（深結構）。

具名 Include（强晟 p58–59）：資料庫表只能是扁平結構、ALV 與 Table Control 也只吃簡單結構，此時若仍想把欄位「分組」並整體存取，就用 INCLUDE TYPE ... AS 名稱。技術上它仍是扁平結構；同一結構 include 兩次時用 RENAMING WITH SUFFIX 避免名稱衝突。

TYPES: BEGIN OF ty_address,
         city    TYPE s_city,
         country TYPE land1,
       END OF ty_address.

*& 具名 Include：仍是扁平結構，可整組存取也可直接存取欄位
TYPES BEGIN OF ty_customer.
TYPES   id   TYPE s_customer.
TYPES   name TYPE s_custname.
INCLUDE TYPE ty_address AS home   RENAMING WITH SUFFIX _h.
INCLUDE TYPE ty_address AS office RENAMING WITH SUFFIX _o.
TYPES END OF ty_customer.

ls_cust-city_o    = 'HSINCHU'.         "以改名後的欄位直接存取

         carrid  TYPE s_carr_id,
         carrname TYPE s_carrname,
         flights TYPE STANDARD TABLE OF sflight WITH EMPTY KEY,

結構指派的規則與危險（强晟 p60–65）：

  • 兩個結構型別相容（元件型別逐一相同，名稱可不同）才應整體指派；子結構也一樣。深結構只能指派給相容的結構。
  • 為了相容舊程式，扁平結構到不相容結構、基本欄位到扁平結構、扁平結構到基本欄位的指派仍被允許：系統把結構當成字元序列，由左到右逐 byte 複製、不轉型，多出的部分補空白。
  • 如果來源含數值欄位，除非兩個結構在數值欄位前的字元數完全一樣，否則數值會被錯誤解讀；目標含 i 欄位時，還會因為 4 byte 對齊（alignment）被塞入補位的 0。
  • 結論：永遠避免不相容結構的整體指派，除非兩邊都是全字元欄位；要複製就逐欄或用 CORRESPONDING。位移存取也只該用在全字元結構上。
  • MOVE-CORRESPONDING／CORRESPONDING 依名稱逐欄複製、套用基本型別的轉換規則，不檢查同名欄位型別是否相同，轉換失敗會發生執行期錯誤。
Unicode 系統（S/4HANA 一定是）對不相容結構指派的限制比 4.6C 嚴格很多：結構的「Unicode 片段視圖（fragment view）」不同時，語法檢查直接報錯。舊程式升級時最常見的錯誤之一就是這類指派，改法就是逐欄或 CORRESPONDING。

結構的比較（强晟 p91）：相容的結構逐元件比較；不相容的結構會被當成字元欄位整段比較——結果往往不是你想的，請只比較相容型別。

8. 全域型別與全域常數

ABAP Dictionary 管理整個系統共用的資訊：全域型別（資料元素、結構、表型別）、搜尋說明、資料庫表、視圖、鎖物件。全域型別的好處（强晟 p68–71）：

9. 控制敘述、跳出處理區塊與執行期錯誤

控制結構（IF、CASE、DO、WHILE）只在一個處理區塊內部分支，可以巢狀，但不能跨越事件關鍵字（IF 與 ENDIF 之間不能放事件關鍵字）。

  • IF／ELSEIF／ELSE：依序評估，第一個為真的區塊執行後跳到 ENDIF。
  • CASE／WHEN：WHEN 之後可以用 OR 串多個值；都不符合時執行 WHEN OTHERS。
  • 邏輯運算優先順序：NOT 強於 AND，AND 強於 OR。NOT f1 = f2 OR f3 = f4 AND f5 = f6 等於 ( NOT f1 = f2 ) OR ( f3 = f4 AND f5 = f6 )。即使不需要也請加括號，易讀又安全。
  • 非數值比較規則：能轉數值就轉（例如十六進位）；日期時間比早晚；其他字元依字碼字典序比較，短的一方尾端補空白；參考只能比是否相等（比位址與型別）。
  • DO（可加 TIMES n，n ≤ 0 就不執行）與 WHILE：迴圈次數在 sy-index；LOOP AT 的列號在 sy-tabix。

次要鍵（Secondary Keys，7.0 EhP2+）（Col18 p182–187）：

  • 種類：SORTED（UNIQUE 或 NON-UNIQUE）、HASHED（只能 UNIQUE）；每個次要鍵要有名稱，每個內表最多 15 個次要鍵。Dictionary 表型別有「Secondary Key」頁籤。主鍵的預設名稱是 primary_key。
  • 次要鍵不會自動被選用：必須以 USING KEY 名稱（LOOP、DELETE、MODIFY、READ 的索引存取）或 WITH KEY 名稱 COMPONENTS ...（READ、表運算式）指定；若你寫的條件剛好是某次要鍵的欄位卻沒指定，語法檢查會發警告。
  • 不能用次要鍵的敘述：APPEND、INSERT、READ TABLE ... WITH TABLE KEY、DELETE TABLE ... WITH TABLE KEY。
  • 延遲更新（lazy update）：NON-UNIQUE 次要鍵只在第一次被使用時才建立，寫入後也要等下次用到才更新——所以效能工具中「第一次透過次要鍵存取」看起來特別貴。UNIQUE 次要鍵在新增／刪除列時立即更新，違反唯一性丟可捕捉的 CX_SY_ITAB_DUPLICATE_KEY；MODIFY 改到唯一次要鍵欄位造成重複則是不可捕捉的錯誤。
  • 用排序次要鍵做索引存取時，sy-tabix 是「該次要鍵」中的位置，後續索引存取也要指定同一個鍵。

  • SELECT-OPTIONS 與範圍表：SELECT-OPTIONS 產生帶表頭的選擇表；4.6 起可用 TYPE RANGE OF 宣告沒有表頭的範圍表，現代寫法常用 VALUE #( FOR ... ) 動態組出範圍表（下一節範例）。

12. 表運算式與建構運算式

表運算式 itab[ ... ]（7.40+）是 READ TABLE 的運算式版本，可放在讀取位置（運算元、ASSIGN、line_exists／line_index 的引數）也可放在寫入位置（直接改列內容）。列的指定方式：itab[ n ] 索引、itab[ KEY 鍵名 INDEX n ]、itab[ col1 = … col2 = … ] 自由鍵、itab[ KEY 鍵名 col = … ]。

  • 找不到時丟 CX_SY_ITAB_LINE_NOT_FOUND；例外：ASSIGN 中設 sy-subrc＝4、line_exists( ) 回傳假、line_index( ) 回傳 0。7.40 SP08 起可在 VALUE／REF 中加 OPTIONAL 或 DEFAULT。
  • 表運算式不會改 sy-tabix；多列符合時取第一列（又是「第一列」——排序問題同上一節的警告）。
  • 空方括號 itab[] 不是表運算式，而是舊式「表身」寫法。
  • 可以串接：lt_deep[ 1 ]-flights[ 2 ]-fldate；但每一層都要可能丟例外，串太長難除錯。

13. 資料參考與欄位符號

欄位符號（Field Symbol）是「已解參考的指標」：對它的所有存取都直接作用在被指派的資料物件上（值語意）。名稱中的角括號是語法的一部分（<fs>）。宣告 FIELD-SYMBOLS <fs> TYPE ...（强晟 p131 寫成「FIELDS-SYMBOLS」是筆誤），用 ASSIGN dobj TO <fs> 指派，執行期可以重新指向別的物件；型別宣告得越精確，編譯器越能幫你擋錯。

資料參考（Data Reference）：4.6A 起 ABAP 具備完整的參考語意。TYPE REF TO type 或泛型 TYPE REF TO data；存取參考變數本身是存取「位址」，用 ->* 解參考才是存取內容。7.40 起以 REF #( ) 取代 GET REFERENCE OF。

*& 欄位符號：指派、檢查、轉型存取

FIELD-SYMBOLS <lv_d> TYPE d.

IF <lv_d> IS ASSIGNED.
  <lv_d> = <lv_d> + 1.                     "直接改到 lv_date
ENDIF.
UNASSIGN <lv_d>.

*& 資料參考：REF #( ) 取代 GET REFERENCE；->* 解參考
DATA lr_date TYPE REF TO d.

lr_date->* = sy-datum.
IF lr_date IS BOUND.                        "參考有效（指向存在的物件）
ENDIF.

  • 在自己的程式插入呼叫請用編輯器的 Pattern（樣式）按鈕，系統會帶出完整的參數與例外骨架。

15. ABAP Objects 入門：從函數群組到類別

强晟第九單元是 4.6C 版的 OO 簡介（現在已獨立成 BC401，完整內容見 5-2 章）。它的切入點很好：一個程式可以同時使用多個函數群組的「實例」，但同一個函數群組只能有一個實例；類別解決的正是「同一種東西要多個獨立實例」的問題。函數群組被呼叫時隱式載入，類別則要明確以 NEW／CREATE OBJECT 建立實例，每個實例有唯一身分並經由物件參考存取。

  • 可見區段：PUBLIC（類別外部介面）、PROTECTED（自己與子類別）、PRIVATE（只有自己的方法）。所有方法都必須在 IMPLEMENTATION 中實作。
  • 建構子：constructor（實例）與 class_constructor（靜態）由系統自動呼叫，用來設定初始狀態（可類比函數群組的 LOAD-OF-PROGRAM）；實例建構子可有輸入參數與例外。
  • 參考語意：TYPE REF TO class；參考變數互相指派只複製位址，多個參考可指向同一物件；CLEAR 參考變數後，沒有任何參考指向的物件由垃圾回收器釋放。方法內存取自己的屬性可省略 me->，但筆記建議寫出來，除錯時比較清楚。
  • ABAP Objects 的語法限制：只能用 TYPE 引用 Dictionary 型別（不能 LIKE Dictionary 物件）、介面參數必須指定型別、元件名只能含字母數字底線且不能以數字開頭、不能用帶表頭的內表與 TABLES。
  • 介面（Interface）：只有宣告、與類別獨立定義；類別在 PUBLIC SECTION 以 INTERFACES 實作，存取介面元件用 intf~comp；介面參考可以指向任何實作該介面的類別實例——同一呼叫、不同行為，就是多型。介面可以巢狀。
  • 事件：類別在定義部分宣告 EVENTS（輸出參數只能傳值），方法中 RAISE EVENT 觸發；處理方法以 FOR EVENT ... OF 宣告，可接收隱含參數 sender；執行期用 SET HANDLER 註冊（FOR 實例 或 FOR ALL INSTANCES，後者連尚未建立的實例也包含），ACTIVATION space 取消註冊。觸發者與接收者互相不知道對方存在。
  • Class Builder（SE24）：全域類別存在類別池（類型 K），全域介面存在介面池（類型 J），和函數群組一樣不能直接執行。

16. 程式呼叫與記憶體管理

同步程式呼叫（Col18 p53–60；强晟第十單元）：同一個使用者工作階段中，完整的程式只能依序執行。兩種方式：① 插入——暫停呼叫端，被呼叫程式結束後回來（SUBMIT ... AND RETURN、CALL TRANSACTION）；② 取代——結束呼叫端、啟動新程式（SUBMIT 不加 AND RETURN、LEAVE TO TRANSACTION）。要平行執行必須用函數模組 CALL FUNCTION ... STARTING NEW TASK（見 4-1 章 aRFC）。

  • SUBMIT：VIA SELECTION-SCREEN 顯示被呼叫程式的選擇畫面；WITH 逐一給參數或選擇條件（運算子 EQ、NE…與 SIGN I／E 同 SELECT-OPTIONS）；多值請給範圍表（WITH so_x IN lt_range）；USING SELECTION-SET 指定變式。編輯器的 Pattern 按鈕會自動帶出所有參數名稱。
  • CALL TRANSACTION：AND SKIP FIRST SCREEN 不顯示第一個畫面（但第一個畫面的流程邏輯仍會執行）；USING bdcdata 以批次輸入格式餵資料（BDCDATA：PROGRAM 40、DYNPRO 4、DYNBEGIN 1、FNAM 132、FVAL 132；每個畫面第一列只填 PROGRAM、DYNPRO、DYNBEGIN＝'X'，其後每個欄位一列；特殊欄位 BDC_OKCODE、BDC_CURSOR）；MODE A 全顯示（預設）／E 錯誤才顯示／N 不顯示；UPDATE A 非同步（預設）／S 同步／L 本地；MESSAGES INTO 型別 BDCMSGCOLL 的內表。BDC 詳見 4-4 章、5-13 章 BC420。
  • LEAVE PROGRAM：在被 CALL TRANSACTION 或 SUBMIT ... AND RETURN 呼叫的程式中執行時，回到呼叫端下一行；其他情況回到使用者啟動程式的應用選單。

記憶體的邏輯模型（Col18 p66–79）：

  • PXA（Program Execution Area）：存放程式不可變的部分——位元組碼、常數與字面值、程式文字、畫面定義；整台應用伺服器共用一份並儘量長期緩衝。Roll Area：每次執行各自一份，存放可變的部分（資料物件）；同一使用者執行同一程式兩次也各有各的 Roll Area。
  • 外部工作階段＝一個 SAP GUI 視窗；NetWeaver 7.0 起最多 16 個，實際上限由參數 rdisp/max_alt_modes 決定（預設 6）。內部工作階段：每次 SUBMIT、CALL TRANSACTION 等程式呼叫都建立新的內部工作階段，以堆疊存放，最多 9 層。
  • 插入（SUBMIT AND RETURN／CALL TRANSACTION）：新內部工作階段疊在上面，呼叫端保留；結束後刪除最上層。SUBMIT（無 RETURN）：刪掉最上層（呼叫端）再放入新程式，下層保留。LEAVE TO TRANSACTION：刪掉整個堆疊、重新開始，連 ABAP Memory 也被初始化。
  • 程式群組：呼叫外部 FM 或全域類別時，不開新的內部工作階段，而是在同一內部工作階段中建立（或沿用）程式群組；每個群組一個主程式，資料只在群組內可見。同一內部工作階段裡，同一個函數群組或類別只載入一次。
函數群組（與類別靜態屬性）造成的「隱形資料交換」。主程式與函數群組 AB 都呼叫函數群組 XY 時，XY 只載入一次，所以主程式在 XY 緩衝的資料可能被 AB 不經意地覆寫或清空，造成程式中止甚至資料不一致；若 AB 是透過其他 FM 間接呼叫 XY，這種錯誤極難追查。全域類別只有靜態屬性有這個風險——最好的避免方式是改用實例屬性，並讓每個使用者各自建立實例。外部子程式呼叫（呼叫別的程式的 FORM）更糟：被呼叫程式直接載入呼叫端的程式群組、共用 TABLES 工作區與 CALL SCREEN 範圍——原廠建議完全避免。

程式之間傳資料的方式：被呼叫程式的介面（選擇畫面、畫面）、ABAP Memory、SAP Memory、資料庫表、簡報伺服器檔案（GUI_UPLOAD／GUI_DOWNLOAD、CL_GUI_FRONTEND_SERVICES）；另有 EXPORT／IMPORT 到資料庫叢集或 SHARED BUFFER。

動態資料物件的記憶體管理（Col18 p83–87）：

  • string 與內表（以及參考、含 deep 元件的結構）是深資料物件，系統以內部參考管理：載入時靜態宣告的深資料物件只佔 8 byte 參考；實際使用時才配置表頭（header，約 100 byte，依平台而異）與資料本體，並會多配一些以避免頻繁擴充。單一字串或內表的上限由最大連續記憶體區塊決定（最多 2 GB，通常被參數 ztta/max_memreq_MB 限制得更低）。
  • 內表：CLEAR、REFRESH 只刪資料；FREE 在表頭佔太多時連表頭都釋放。INITIAL SIZE n 可指定第一個記憶體區塊的列數——只在確知列數時才指定（超過時反而會多配置）；最適合巢狀表中「每個內層表只有幾列」的情況。Dictionary 表型別的「Initial Number of Lines」欄位同義。
  • 共享（Sharing，寫入時複製）：字串或內表互相指派時先只複製管理資訊、共用同一份資料，直到其中一方被修改才真正複製（內表各有自己的表頭；列型別本身含表型別的內表不共享）。所以傳值給程序時，只要程序內不修改該參數，成本與傳參考幾乎一樣；一旦在程序內修改傳值參數，就會發生昂貴的複製。

17. Shared Objects：跨工作階段共用記憶體

應用伺服器上的 Shared Memory 是所有在該伺服器上執行的 ABAP 程式都能存取的區域。以前只能用 EXPORT／IMPORT ... SHARED BUFFER／SHARED MEMORY；6.40 起多了 Shared Objects Memory，可以把類別的實例放進去（資料物件只能以類別屬性的形式存放，參考變數除外）。SAP 自己就用它加速 Workbench 導覽：每個登入約省 3 MB，首次導覽最多快 100 倍。

  • 適用：跨程式緩衝「讀很多、寫很少」的資料（例如目錄、設定、主檔快取）；支援同時多人讀取、以鎖機制控制存取；寫入成本高，寫入不能頻繁；記憶體不足會發生執行期錯誤，要捕捉。
  • Area（區域）：在 SHMA 定義（尚未整合進 SE80，要直接呼叫），系統產生同名、FINAL 的全域區域類別（Area Class），是 CL_SHM_AREA 的子類別——所以區域名稱請照類別命名規範，例如 ZCL_…。程式只能透過區域類別的方法存取區域。
  • Area Root Class：必須在 SE24 勾選 Shared Memory-Enabled（本地類別加 SHARED MEMORY ENABLED）；區域類別會產生型別為該根類別的 ROOT 屬性。每個區域實例版本至少要有一個根物件，其他物件都經由它參考。
  • Area Instance 與版本：一個區域可有多個以名稱區分的實例；每個實例可有多個版本（屬性 NUMBER OF VERSIONS）。其他屬性：Client-dependent（預設跨 Client，可設為依 Client，方法以 CLIENT 參數指定其他 Client）、Transactional（DETACH_COMMIT 後要等下一次資料庫 COMMIT 才生效，適合購物車）。
  • 版本生命週期：寫入者設變更鎖 → 產生「建置中版本」與目前的啟用版本並存 → 完成後新版本成為啟用版，舊版標為 OUTDATED（已持有讀鎖的讀者繼續讀舊版，新讀者一律讀啟用版，所以兩個讀者可能讀到不同結果）→ 舊版最後一個讀鎖釋放後變成 EXPIRED，由垃圾回收刪除，也不再計入版本數。
  • 監控：SHMM Shared Memory Monitor，依序檢視 Areas → Area Instances → Versions → Locks，可切換 Overview、Locks、Users、Control（記憶體用量）、All Columns 等檢視；程式中可用 CL_SHM_UTILITIES 查詢。

18. 動態程式 I：動態記號、動態 SQL 與動態呼叫

ABAP 支援的動態程度（Col18 p211–212）：內表與字串的動態擴充、動態位移與長度、動態指定程式物件名稱（資料表、程序、排序條件、控制層級…）、動態型別與資料宣告，最極端是在執行期產生程式。手段有：動態語言元素、執行期產生程式、欄位符號（動態 ASSIGN、CASTING）、資料參考與 CREATE DATA、RTTS（RTTI＋RTTC）。

動態記號（Tokens）的兩種情況：

  • 取代字面值：直接放資料物件即可（數值字面值換成 i 變數、文字字面值換成 c 或 string 變數），例如 CALL FUNCTION lv_fname、CALL TRANSACTION lv_tcode。
  • 取代識別字：要用括號標明「用它的內容」，且括號內不能有空白，例如 SELECT (lt_fields) FROM (lv_table)、SORT itab BY (lv_col)、SUBMIT (lv_prog)、CALL METHOD lo_obj->(lv_meth)、CREATE OBJECT lo TYPE (lv_class)。
  • 並非所有敘述都支援動態記號，以各敘述的關鍵字文件為準。靜態寫法會被語法檢查抓到的錯，動態寫法都變成執行期錯誤——這是動態程式最大的代價。

動態 Open SQL：SELECT 幾乎所有部分（欄位清單、FROM、WHERE、ORDER BY、GROUP BY、HAVING）都可以用字元型變數或字元型內表動態指定，只有 INTO 子句不行（但 INTO 可以用欄位符號或解參考的資料參考，達到同樣效果）。寫入敘述也支援動態表名。

動態呼叫的括號規則：函數模組與交易代碼不加括號（取代的是字面值）；子程式、方法、可執行程式要加括號（取代的是識別字）。參數可以靜態傳（前提是所有候選程序介面相同）或動態傳：

19. 動態程式 II：泛型型別、動態存取、RTTI 與 RTTC

泛型參數要「剛好夠泛」（Col18 p228–229）：形式參數型別太寬（例如 any），程序內的敘述就可能在執行期失敗——例如把內表或非字元扁平結構傳給一個會 WRITE 的 any 參數，得到不可捕捉的 OBJECTS_NOT_CHARCONV。在只接受內表的位置（SELECT ... INTO TABLE、LOOP AT）語法檢查只接受泛型表型別。原則：選能涵蓋所有預期實參、又足以讓程序內每個敘述都合法的最窄泛型（例如 simple、csequence、index table）。除了內建泛型，也可以在程式或 Dictionary 定義「只指定列型別、不指定表種類與鍵」的自訂泛型表型別。

  • 泛型欄位符號：可以在同一個敘述位置動態指向不同型別的資料物件。
  • CASTING：ASSIGN dobj TO <fs> CASTING [TYPE t | TYPE (name) | TYPE HANDLE rtti] 以另一個型別看待同一塊記憶體（例如把 sy-datum 看成年月日結構）。
  • 以名稱動態存取資料物件：ASSIGN (lv_name) TO <fs>；存取屬性時優先用「靜態物件參考＋動態屬性名」：ASSIGN lo_obj->(lv_attr) TO <fs>、ASSIGN (lv_class)=>(lv_attr) TO <fs>——靜態部分有語法檢查，比較不容易錯。
  • 動態存取結構元件：ASSIGN COMPONENT name_or_index OF STRUCTURE struc TO <fs>；以位置迴圈就能逐欄處理任意結構。若欄位符號型別是 simple 而結構含不相容元件，得到不可捕捉的 ASSIGN_TYPE_CONFLICT。
  • 泛型資料參考：只有 TYPE REF TO data（資料）與 TYPE REF TO object（物件）兩種泛型。7.40 以前泛型參考唯一能解參考的地方是 ASSIGN（ASSIGN lr_data->* TO <fs>）；也可以向下轉型成具體型別的參考（CAST 或 ?=，型別不符丟 CX_SY_MOVE_CAST_ERROR）。常見用途：動態呼叫的參數表、CREATE DATA。

20. Open SQL 的技術背景：資料庫介面、索引與 SAP 表緩衝

架構（Col18 p38、p276–278）：Open SQL 是完整整合進 ABAP 的標準 SQL 子集，讓程式不必管底層是哪個資料庫；應用層與資料庫之間由 SAP 資料庫介面（DBSS）負責——它把 Open SQL 轉成資料庫專屬 SQL、管理 SAP 表緩衝、處理游標與資料傳輸。資料庫端另有自己的資料緩衝與游標快取（存取路徑），ABAP 開發者無法影響，只能透過 Dictionary 技術設定影響 SAP 表緩衝。7.50 起官方名稱改為 ABAP SQL（見 2-2 章）。

三種讀取型態（Col18 p39–42，三者互斥）：SELECT SINGLE（單筆，WHERE 應填滿主鍵）、SELECT 迴圈（逐筆，整個迴圈期間要維持資料庫游標，4.6C 筆記也提醒會降低效能——新程式禁用）、SELECT ... INTO TABLE（Array Fetch，推薦）。sy-subrc＝0 表示至少讀到一筆，sy-dbcnt 是筆數。

新語法（7.40 SP05 起）：主機變數一律加 @、欄位清單用逗號分隔、嚴格模式（以前的警告多數變錯誤）；7.40 SP08 起 INTO 可以（也應該）放在最後、可在 INTO 內嵌宣告 @DATA( )；7.50 起可先寫 FROM 再用 FIELDS 列欄位（利於程式碼補全）。同一個敘述不能混用新舊語法。

資料庫最佳化器與索引（Col18 p278–282）：

  • 最佳化器依 WHERE 條件、索引與統計資訊決定存取策略（全表掃描或走哪個索引）。
  • 主索引由主鍵欄位（含 MANDT）組成、唯一；可在 Dictionary 另建次要索引。索引是排好序的 B-tree（根、分支、葉），葉節點指向表中的實際記錄（Oracle 稱 ROWID）。MS SQL Server 的主索引與表資料是一體的。
  • 索引搜尋字串：WHERE 由左到右連續限定越多索引欄位，搜尋越省力。SFLIGHT 主索引＝MANDT、CARRID、CONNID、FLDATE；限定前三個欄位時搜尋字串是「802AA0017%」，左邊沒有缺口，效率很好；若缺了 CARRID、CONNID，搜尋字串中間出現萬用字元，索引幾乎失效。
  • 索引欄位不要太多；某些運算子（NOT、<>、前置 % 的 LIKE…）會讓最佳化器找不到好策略。
HANA 是欄式記憶體資料庫，大部分查詢不需要次要索引也夠快；在 S/4HANA 上新建次要索引前請先確認真的有需求（ST05／SQLM 的證據），並與 Basis 討論。但「WHERE 條件儘量用鍵欄位、儘量少傳資料」的原則在 HANA 上依然成立。

SAP 表緩衝（Col18 p283–289）：應用伺服器共用記憶體中的表內容副本。讀取時間約為：應用伺服器緩衝 0.1 ms／筆、資料庫資料緩衝 1 ms／筆、資料庫磁碟 10 ms／筆。

緩衝類型技術名載入方式命中條件
全表緩衝（n＝0）TABL第一次存取時載入整張表任何讀取（含非鍵條件）
泛用緩衝（0 < n < 鍵欄位數）TABL依前 n 個鍵欄位的值，整個「泛用區域」一起載入WHERE 以 = 填滿前 n 個鍵欄位
單筆緩衝（n＝鍵欄位數）TABLP只載入讀到的那一筆只有 SELECT SINGLE 且 WHERE 填滿所有鍵欄位
  • 緩衝同步：寫入緩衝表時，本機伺服器緩衝立即失效或更新，並在資料表 DDLOG 寫一筆同步記錄；其他伺服器每隔 rdisp/bufreftime 秒（60～3600，建議 60～240）讀 DDLOG，使自己的緩衝失效。在那之前，其他伺服器讀到的是舊資料——所以只能緩衝「可以容忍短暫不一致」的表。
  • 失效範圍：工作區模式（單筆 UPDATE／INSERT／MODIFY／DELETE dbtab FROM wa）依緩衝類型分別讓全表、泛用區域或該筆失效；集合模式（UPDATE ... SET ... WHERE、DELETE ... WHERE）通常讓整張表失效。
  • 適合緩衝的表：小（< 10 MB）、讀多寫少（變更 < 讀取的 1%）、可容忍暫時不一致、主要以鍵欄位存取；新增緩衝前須請系統管理者確認記憶體。
  • 會繞過緩衝的寫法：BYPASSING BUFFER、SELECT FOR UPDATE、聚合函數、DISTINCT、IS NULL、JOIN、子查詢、非主鍵的 ORDER BY、單筆緩衝表卻不用 SELECT SINGLE 完整鍵……Code Inspector 有專門檢查「繞過表緩衝的 SELECT」。

21. Open SQL 進階：排序、聚合、WHERE、INTO、JOIN 與 FOR ALL ENTRIES

排序與壓縮（Col18 p292–300）：

  • ORDER BY PRIMARY KEY 的前提：FROM 只有一張資料表（不能是視圖或 JOIN），欄位清單包含所有主鍵欄位（含 MANDT，最常被忘記）。ORDER BY col1, col2 DESCENDING 可排任意欄位；排序欄位不是索引欄位且結果集很大時代價高。不能排序 Pooled／Cluster 表（S/4HANA 已多轉為透明表）。
  • SELECT DISTINCT：以結果集所有欄位去重；欄位不能是 LCHR、LRAW、STRING、RAWSTRING。
  • 聚合函數：MIN、MAX、SUM（結果型別同欄位）、AVG（結果為 f；7.50 起可 AVG( col AS type )）、COUNT(*)（i）、COUNT( DISTINCT col )。
  • 只有聚合函數時結果永遠是一列：即使沒資料也回傳一列（COUNT＝0、其他為初始值），sy-subrc＝0、sy-dbcnt＝1——所以不能用 sy-subrc 判斷「有沒有資料」。例外：只有 COUNT(*) 且省略 INTO 時，沒資料會 sy-subrc＝4、sy-dbcnt＝0。另外 MIN／MAX 沒資料時回傳初始值，要小心與真實的 0 混淆（可用 COUNT 一併判斷）。
  • 欄位＋聚合時結果是多列，必須 GROUP BY 所有非聚合欄位；不能 SELECT *；GROUP BY 欄位不能是 STRING、RAWSTRING。HAVING 在分組後再篩選（可用 COUNT(*) > 1 等聚合條件，不必出現在 SELECT 清單）；HAVING 用了 GROUP BY 以外的欄位不會語法錯誤，而是執行期丟 CX_SY_OPEN_SQL_DB。

WHERE 運算子（Col18 p301–304）：比較運算子、IN ( v1, v2, … ) 值清單、BETWEEN a AND b 區間（字元欄位的結果可能依資料庫字碼頁而異）、LIKE（_ 單一字元、% 任意字串；要找 _ 或 % 本身用 ESCAPE '!'，例如 LIKE '%!_%' ESCAPE '!'）、IN seltab（選擇表）、IS [NOT] NULL、AND／OR／NOT（AND 先於 OR，用括號改變順序）。同一張表的兩個欄位可以互相比較，欄位要寫成 表名~欄位 或用 AS 別名。注意：SQL 用 _ 與 %，ABAP 的 CP 與選擇表用 + 與 *。

列舉優於區間（Casper 實務經驗二）在 SQL 層一樣適用。WHERE matnr BETWEEN 'A100' AND 'A199' 比的是字典序：ALPHA 前導零（內部 18／40 碼補零）、編碼規則中途改過、號碼段不連續，都會多抓或漏抓。知道要哪些值就用 IN ( ... ) 或以 EQ 組成的範圍表 IN @lt_range。

INTO 的目標（Col18 p305–308）：單列目標（SELECT SINGLE）可以是結構，也可以是欄位清單 INTO (@lv_a, @lv_b)（比 INTO CORRESPONDING FIELDS OF 更穩健）；多列目標是內表，APPENDING TABLE 取代 INTO TABLE 就不會先清空（排序表會插到正確位置、雜湊表也可用）。PACKAGE SIZE n：結果集大到內表放不下時，每次取 n 筆處理——它決定資料庫介面每次交給程式的筆數，對資料庫與網路負載影響不大。新程式請用游標搭配 FETCH NEXT CURSOR ... PACKAGE SIZE（下例）。

新 Open SQL 補齊的功能（Col18 p309–316）：字串運算子 &&（7.40 SP05；結果最長 255、只能串基本字元欄位）與函數 CONCAT（恰兩個運算元、最長 1333）、LENGTH、LPAD、LTRIM、RTRIM、RIGHT、REPLACE、SUBSTRING（7.50）；算術 +、−、*、/ 與 ABS、CEIL、FLOOR、DIV、MOD（7.40 SP05，DIV／MOD 只接受整數）、ROUND（7.50）；CAST（7.40 SP05 只能轉 FLTP，7.50 起支援多數 Dictionary 型別）；欄位清單中的常值（存在檢查用）；簡單與複雜 CASE；以及 UNION（7.50）、RIGHT OUTER JOIN、ON 條件可用 BETWEEN 與大於小於。

讀多張表（Col18 p317–327）：

  • 巢狀 SELECT（在主表迴圈裡逐筆讀副表）是最耗資源的做法，好的設計一律避免。
  • JOIN：INNER JOIN 只保留內表有對應資料的外表記錄；LEFT OUTER JOIN 保留外表全部，右表沒資料的欄位為 NULL（進 ABAP 變初始值）。7.40 SP05 以前 OUTER JOIN 有許多限制（右邊只能是單表或視圖、ON 只能 AND、每個比較都要含右表欄位、右表欄位不能出現在 WHERE），新語法已大多解除，也支援 RIGHT OUTER JOIN 與任意括號順序。JOIN 與 Dictionary 視圖都只能用在透明表。
  • Dictionary 視圖的優點：可重用、可用 SE84／SE81 搜尋與 where-used、可以緩衝、共同欄位只傳一次；Dictionary 視圖是 INNER JOIN——讀文字表時若不想因缺文字而丟掉主資料，請改用 LEFT OUTER JOIN。S/4HANA 新開發請改用 CDS View（見 1-3 章）。
  • 子查詢：寫在 WHERE 或 HAVING；回傳單一值可用一般比較運算子（LIKE、BETWEEN 除外）；回傳多列單欄時用 IN、或 ALL／ANY／SOME；EXISTS 檢查存在。JOIN 常能得到相同結果且較易讀，兩者效能沒有定論，關鍵查詢請用真實資料各做一次效能量測。
  • 程式內緩衝：JOIN 不可行時（例如來源是 Pooled 表），把讀過的資料存在內表，每次讀資料庫前先查內表（筆記以 STRAVELAG 的靜態內表為例）；現代寫法是類別的私有 HASHED 表屬性。
  • FOR ALL ENTRIES：產生於資料庫還不普遍支援 JOIN 的年代；現在常用在「部分資料已在內表、再補讀資料庫」的情境，取代 LOOP 裡的 SELECT SINGLE。資料庫介面會把驅動表拆成多組、各送一個原生 SQL，再合併結果並自動去除重複（每組大小由設定參數控制）。

ABAP Trace（SAT，取代 SE30）（Col18 p349–354）：量測程式的執行時間分佈。結果受系統負載、網路、表緩衝狀態影響，要在測試系統以相近資料量量測並保守解讀。SAT 的優點：新介面、新分析工具、工具之間可互相導覽、能顯示內表的真實名稱（SE30 只顯示 IT_nn）、trace 存在資料庫（任一伺服器都看得到）。

  • 測量變式：做效能量測時用 Per Call Position 聚合（同一呼叫位置只記一筆，含次數與總時間，檔案小）；要追程式流程時用不聚合（得到呼叫階層）。用「明確開關量測」只量需要的區段（在除錯器或以 /ron、/roff 切換）；在 Program Components 頁籤指定要追蹤的程式、類別、函數群組甚至單一方法。
  • 評估工具：Hit List（依時間排序的事件清單）、Profile（依元件、套件往下鑽，找出最大消耗者）、Call Hierarchy、Call Stack、Database Tables（耗時的資料庫存取與緩衝表存取）、Times。建議：Profile 找熱點 → Hit List 看細節 → Database Tables 查 SQL。
  • SAT 初始畫面的 Tips & Tricks 提供不同寫法的效能對照範例。

SQL Trace（ST05）（Col18 p355–359）：

  • 開追蹤前先把程式跑一次，避免把表緩衝、程式緩衝的載入動作也錄進去。可以在正式系統開（不會造成錯誤或不一致）；限定使用者與物件，並確認該使用者沒有在別的視窗或背景作業同時執行，否則結果難讀。每台應用伺服器一次只有一個啟用中的 trace 檔。
  • 清單欄位：Duration（微秒，受負載影響）、Object Name（表或視圖）、Records（筆數）、Statement（SQL 文字）。
  • Display Execution Plan（Explain）：顯示原生 SQL、最佳化器策略、成本、使用的索引與統計資訊；綁定變數（bind variables）按兩下可看實際值。畫面內容依資料庫而異。
  • Summarize Trace by SQL Statement：看每個敘述的執行次數、總時間、以及「完全相同（含綁定值）」的比例；選單 Trace → Value-Identical Statements 列出值完全相同的重複 SQL——這些通常可以用程式內緩衝消除，是最直接的最佳化機會。

SQL Monitor（SQLM／SQLMD，7.40+）（Col18 p361–363）：擷取整個系統或特定交易的 SQL Profile——每個 SQL 的執行次數、存取的表、總執行時間、讀取筆數，並對應到原始碼位置與觸發的請求（交易、報表、RFC、URL、Web Dynpro）。設計目標是能在正式系統長期開啟：核心以檔案非同步記錄，額外負擔極小，資料約每 24 小時彙整進 SQLM 資料表（可手動更新）。在 SQLM 啟用（全部或指定伺服器、可設到期日與記錄上限），在 SQLMD 以套件、物件、請求、資料表等條件查詢。搭配 SWLT（SQL Performance Tuning Worklist）可把 SQLM 的執行期資料與 Code Inspector 的靜態檢查結果交叉比對，找出「又慢又常被執行」的敘述優先處理。

練習與自我檢核

以下題目取材自强晟筆記各單元重點與 Col18 各 Unit 的 Learning Assessment，並加入 S/4HANA 實務題。

  1. LOAD 是什麼？什麼情況下會失效？為什麼大量傳輸後要跑 SGEN？
    要點：LOAD＝程式的執行期物件（連結 C 函數的位元組碼），存於資料庫並緩衝在應用伺服器；開發版被改或所用的 Dictionary 物件被改時過期；傳輸只帶開發版，匯入後 LOAD 被丟棄、首次呼叫才產生，SGEN 預先產生避免上線初期變慢。
  2. 寫出下列結果：lv_i = 5 / 10.、lv_i = 10 * ( 4 / 10 ).、lv_i = ( 1 / 4 ) * ( 2 ** 2 ).（lv_i TYPE i）
    要點：1（四捨五入）、0（中間結果先四捨五入）、1（** 使整式改用浮點運算）。
  3. 為什麼 73050 × 7.27% 用 f 計算再存入 p 會得到 5310.73？商業計算該用什麼？
    要點：二進位浮點無法精確表示 0.0727，得到 5310.7349999…，捨入成 .73；金額用 p（定點運算）或 decfloat34，並用 round( ) 指定捨入模式。
  4. 三種表種類各在什麼情況下能被最佳化？LOOP ... WHERE 對雜湊表有幫助嗎？
    要點：STANDARD 鍵存取一律循序（除非自行排序後 BINARY SEARCH）；SORTED 在完整鍵或左起無缺口、全用 = 的部分鍵時二分；HASHED 只在完整鍵時常數時間；LOOP WHERE 對雜湊表是全表掃描，不比標準表快。
  5. 一個內表最多可以有幾個次要鍵？NON-UNIQUE 次要鍵何時被建立與更新？為什麼原廠建議優先用 NON-UNIQUE？
    要點：15 個；第一次明確使用時才建立，寫入後延遲到下次使用才更新（lazy update）；延遲更新成本低、且不會因重複鍵發生執行期錯誤。
  6. 表運算式找不到列時會怎樣？有哪三個例外情況？
    要點：丟 CX_SY_ITAB_LINE_NOT_FOUND；ASSIGN 時設 sy-subrc＝4、line_exists 回傳假、line_index 回傳 0（另可用 VALUE ... OPTIONAL／DEFAULT）。
  7. 主程式與它呼叫的函數群組 AB 都呼叫函數群組 XY，會有什麼風險？全域類別呢？
    要點：同一內部工作階段中 XY 只載入一次，全域資料被共用，可能互相覆寫；類別只有靜態屬性有此風險，改用實例屬性並各自建實例即可避免。
  8. SUBMIT、SUBMIT ... AND RETURN、CALL TRANSACTION、LEAVE TO TRANSACTION 對內部工作階段堆疊與 ABAP Memory 的影響？
    要點：AND RETURN 與 CALL TRANSACTION 疊一層（插入）；SUBMIT 取代最上層；LEAVE TO TRANSACTION 清空整個堆疊並初始化 ABAP Memory；ABAP Memory 只能在插入的情況下傳資料給交易。
  9. Shared Objects 讀取端釋放讀鎖用哪個方法？寫入端完成建立用哪個方法？版本的 OUTDATED 與 EXPIRED 差在哪？
    要點：DETACH；DETACH_COMMIT（交易型區域還要等資料庫 COMMIT）；OUTDATED＝已有新啟用版但仍有讀者持有讀鎖；最後一個讀鎖釋放後變 EXPIRED 並被垃圾回收。
  10. 動態呼叫時哪些名稱要加括號？ABAP_FUNC_PARMBIND_TAB 與 ABAP_PARMBIND_TAB 的表種類各是什麼？
    要點：子程式、方法、可執行程式（取代識別字）要加；函數模組與交易代碼（取代字面值）不加；前者 SORTED（不要 APPEND）、後者 HASHED。
  11. RTTI 可以實例化的描述類別有哪六個？要動態建立一個任意資料表的內表，步驟為何？
    要點：ELEMDESCR、REFDESCR、STRUCTDESCR、TABLEDESCR、CLASSDESCR、INTFDESCR；describe_by_name 取得結構 → cl_abap_tabledescr=>create → CREATE DATA ... TYPE HANDLE → ASSIGN 到 TYPE STANDARD TABLE 的欄位符號 → SELECT ... INTO TABLE @<fs>。
  12. 只含聚合函數的 SELECT 在查無資料時 sy-subrc 是多少？為什麼不該用 COUNT(*) 做存在檢查？
    要點：0（且 sy-dbcnt＝1，只有純 COUNT(*) 省略 INTO 時才是 4）；COUNT 會掃完所有符合列，存在檢查用 SELECT SINGLE @abap_true 或 UP TO 1 ROWS。
  13. FOR ALL ENTRIES 的三大注意事項？
    要點：驅動表空時會讀整張表；結果自動去重，欄位要含完整鍵；先壓縮驅動表、結果不保證順序（HANA 必須自行排序）。
  14. 哪種 SELECT 才會命中單筆緩衝？緩衝同步靠哪張表與哪個參數？
    要點：SELECT SINGLE 且 WHERE 填滿所有鍵欄位；DDLOG 與 rdisp/bufreftime（60～3600 秒，建議 60～240）。
  15. 斷言在 SAAB 中有哪四種狀態？ST05 開追蹤前為什麼要先執行一次程式？
    要點：Inactive、Log、Break、Abort；避免把表緩衝與程式緩衝的初次載入錄進 trace。
  16. 實務題：某成本報表在 HANA 上每次執行結果不同，程式是 SELECT 後 READ TABLE ... WITH KEY matnr = … 取第一筆。請說明原因與修正方式，並說明若條件是「料號 A100～A199」該怎麼寫比較安全。
    要點：HANA 沒有預設排序，同一料號有多筆（例如 H 與 E 兩種成本角度）時取到哪一筆不固定；SELECT 加 ORDER BY 或改用 SORTED 表並明確指定要哪一種（固定抓 H）；料號條件改用列舉值（IN 清單或 EQ 範圍表），避免 BT 字典序比較造成多抓漏抓。
