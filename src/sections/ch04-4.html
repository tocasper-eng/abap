1. 這一章的地圖：一支程式串起五件事

講義開頭老師就說了：「這支工時回報上傳，應該算寫得非常好，有 FTP、有發 MAIL、有 EXCEL 上傳，也是先放暫存檔 T_XLS，然後才用 BDC 做完整的檢查，連訊息也回寫得很清楚。」這句話其實就是介面程式的標準骨架，值得抄下來當口訣：

  1. 取得來源：從 FTP 抓檔，或從 PC 上傳 Excel／CSV。兩條路走完都倒進同一張暫存內表。
  2. 暫存 + 正規化：全部先進 T_XLS 這種「寬鬆型別（全部字元欄）」的暫存表，再做去引號、ALPHA 補零、日期轉換。
  3. 驗證：查主檔存不存在（工單查 AUFK）、必填欄位、數值可不可轉。錯的先標 STATUS = 'E'，不要丟掉。
  4. 過帳：只處理 STATUS = SPACE 的那些，用 BDC 呼叫 CO11N，訊息收回來寫進 MSG。
  5. 留痕與通知：整批結果寫進自建紀錄表 ZPPWORKMA0001、顯示 ALV、必要時把 Spool 轉 PDF 寄給群組。
老師口訣：「先落地、再驗證、最後才過帳；錯的不要刪，標起來。」 介面程式最怕的是「跑一半死掉、不知道跑到哪」。所有資料先落到暫存表／紀錄表，就算中途中斷也能查、能重跑。

3. BDC 是什麼：三種批次輸入作法

BDC＝Batch Data Communication（批次輸入）。原理很直白：把「使用者在畫面上敲鍵盤」的整個過程錄成資料，再讓程式重播一遍。它不呼叫任何 API，而是真的去跑那支交易的畫面邏輯（PBO/PAI），所以所有標準檢查、Enhancement、User Exit 都會照跑——這是 BDC 最大的優點，也是它慢的原因。

作法怎麼做執行時機錯誤處理適用
SHDB 錄製TCODE SHDB 錄一次操作，再由系統產生程式範本只是「產生程式碼」的工具—取得畫面編號與欄位名的最快方式
CALL TRANSACTION USING程式內組 BDCDATA，直接呼叫交易同步（線上就跑完）MESSAGES INTO 收訊息，自己判斷筆數不多、要即時知道結果、要把訊息回寫給使用者
SESSION（批次輸入群組）BDC_OPEN_GROUP → BDC_INSERT → BDC_CLOSE_GROUP非同步，之後在 SM35 執行SM35 自動保留錯誤 session，可補跑大量資料、夜間跑、需要人工介入修正
LSMW / LTMC設定式工具，底層仍可能用 BDC/BAPI/IDoc專案期一次性搬資料工具本身管導入期主檔／期初資料遷移
兩者的關鍵差異：CALL TRANSACTION 出錯了資料就在那邊，你得自己記錄、自己重跑；SESSION 出錯的那筆會留在 SM35 的 session 裡，管理員可以用「顯示錯誤（Display errors only）」模式一筆一筆修好再送出——這是 SESSION 唯一無可取代的價值。

4. SHDB 錄製與 BDCDATA 結構

不會寫 BDC 的人，第一步永遠是 SHDB。（依講義步驟整理）

  1. SHDB → New recording，輸入錄製名稱（例：Z_CO11N）與要錄的交易碼（CO11N）。
  2. 按 Start recording，系統就會把你接下來的每一個畫面、每一個欄位、每一次按鍵記下來。像真的使用者一樣把單開完、按存檔。
  3. 回到 SHDB 清單，選這筆錄製 → Program，系統直接吐出一支含 bdc_dynpro / bdc_field 的完整程式範本。
  4. 把裡面固定的值換成內表欄位，就完成了 90%。

錄製結果就是一張 BDCDATA 表。它只有四個欄位，非常好記：

欄位長度意義
PROGRAM40畫面所屬的程式名（例：SAPLCORU_S）
DYNPRO4畫面編號（例：0100）
DYNBEGIN1'X' 表示「這一列是新畫面的開頭」
FNAM132欄位名（結構-欄位，例 AFRUD-AUFNR）或控制欄位
FVAL132欄位值（一律是「使用者會敲進去的那個字串」）

三個特殊控制欄位一定要背：

  • BDC_OKCODE：這個畫面按的功能碼。'=BU' 存檔、'/00' Enter、'=BACK' 或 '/EBACK' 返回、'/EE' 離開、'=P+' 下一頁、'=P-' 上一頁。前面加 /E 代表用 系統功能碼（相當於在指令列打）。
  • BDC_CURSOR：游標停在哪個欄位。看起來沒用，其實在 Table Control、在「輸入後才展開子畫面」的場合非常關鍵——很多欄位是游標移過去才會觸發 PAI 檢查。
  • BDC_SUBSCR：子畫面（Subscreen）區域。值是「子畫面程式 + 畫面編號」，用來指定接下來的欄位屬於哪一塊子畫面。錄製時系統會自動產生，不要手動刪掉。

兩個 helper FORM 是 BDC 的標準配備。講義用的是舊寫法（WITH HEADER LINE 的全域 BDCDATA），現代寫法改成把內表當參數傳：

*&--- 開一個新畫面
FORM bdc_dynpro USING iv_program TYPE bdcdata-program
                      iv_dynpro  TYPE bdcdata-dynpro
             CHANGING ct_bdc     TYPE ty_t_bdcdata.

  APPEND VALUE bdcdata( program  = iv_program
                        dynpro   = iv_dynpro
                        dynbegin = abap_true ) TO ct_bdc.

ENDFORM.

*&--- 塞一個欄位值
FORM bdc_field USING iv_fnam TYPE bdcdata-fnam
                     iv_fval TYPE any
            CHANGING ct_bdc  TYPE ty_t_bdcdata.

  DATA lv_fval TYPE bdcdata-fval.

  lv_fval = |{ iv_fval }|.
  CONDENSE lv_fval.                      " BDC 的值前面不可以有多餘空白

  APPEND VALUE bdcdata( fnam = iv_fnam
                        fval = lv_fval ) TO ct_bdc.

ENDFORM.
如果你用的是 ABAP 7.40 以上，其實連 FORM 都可以省掉，直接用 VALUE #( ) 一次把整張 BDCDATA 寫出來，可讀性反而更好（見下一節）。老師的舊寫法要保留是因為錄製產生的範本長那樣，你要看得懂。

5. CALL TRANSACTION USING：MODE / UPDATE / MESSAGES INTO

講義的 CO11N 報工就是 CALL TRANSACTION。先看資料怎麼組——注意 SAPLCORU_S 的 0100 畫面、OKCODE '=BU'（Save），以及四組工時是「有值才塞」：

*&--- 組 CO11N 的 BDC 資料（現代寫法：一次 VALUE 完成）
FORM build_bdc_co11n USING    is_xls TYPE ty_xls
                     CHANGING ct_bdc TYPE ty_t_bdcdata.

  CLEAR ct_bdc.

  " 過帳日期：外部字串 YYYYMMDD → 依使用者格式的外部顯示字串
  DATA(lv_budat) = conv_date_to_external( is_xls-budat ).

  ct_bdc = VALUE #(
    ( program = 'SAPLCORU_S' dynpro = '0100' dynbegin = abap_true )
    ( fnam = 'BDC_OKCODE'  fval = '=BU' )        " 存檔

接著呼叫。CALL TRANSACTION 的三個附加語法必須清楚：

附加值意義
MODE（畫面顯示）'A'All screens：全部畫面都顯示，一步一步跑。除錯用
'E'Errors only：正常時不顯示，出錯時停在那個畫面。找錯最好用
'N'No display：完全不顯示。背景作業一定要用這個
'P'不顯示，但允許中斷點（可在被呼叫的交易裡下斷點除錯）
UPDATE（更新模式）'S'Synchronous 同步：更新完成才回來，sy-subrc 才真正可信
'A'Asynchronous 非同步：丟給更新工作程序就回來，快但無法確認結果
'L'Local update：在同一個工作程序內更新（不進 update task），速度快
MESSAGES INTOBDCMSGCOLL 內表把交易產生的所有訊息（S/W/E/A/X）收下來
 
FORM call_co11n CHANGING cs_xls TYPE ty_xls.

  DATA: lt_bdc TYPE ty_t_bdcdata,
        lt_msg TYPE STANDARD TABLE OF bdcmsgcoll WITH EMPTY KEY.

  PERFORM build_bdc_co11n USING cs_xls CHANGING lt_bdc.

  CALL TRANSACTION 'CO11N'
       USING            lt_bdc
       MODE             p_mode          " A / E / N
       UPDATE           'L'             " Local update
       MESSAGES INTO    lt_msg.

  DATA(lv_subrc) = sy-subrc.

  COMMIT WORK AND WAIT.                 " local update 之後要自己 commit

  PERFORM eval_bdc_messages USING lt_msg lv_subrc CHANGING cs_xls.

ENDFORM.

如果要一次控制更多細節，改用 OPTIONS FROM 傳一個 CTU_PARAMS 結構，這是比 MODE/UPDATE 更完整的介面：

DATA(ls_opt) = VALUE ctu_params(
    dismode  = p_mode        " 顯示模式 A/E/N/P
    updmode  = 'S'           " 更新模式 S/A/L
    cattmode = ' '           " CATT 模式
    defsize  = abap_true     " 用預設畫面大小，避免因螢幕解析度不同而失敗
    racommit = abap_true     " 被呼叫交易內的 COMMIT WORK 不中止 CALL TRANSACTION
    nobinpt  = abap_false    " abap_true 時 sy-binpt 不設為 X，交易表現得像線上
    nobiend  = abap_false ). " 資料用完後仍留在批次輸入模式

CALL TRANSACTION 'CO11N'
     USING         lt_bdc
     OPTIONS FROM  ls_opt
     MESSAGES INTO lt_msg.
三個一定要記的陷阱：
  • defsize = 'X' 幾乎一定要開。不開的話，BDC 會用「目前使用者的畫面大小」跑；不同人的 SAP GUI 視窗大小不同，Table Control 可見列數就不同，同一支程式在你電腦上跑得過、在別人電腦上就掛掉。
  • UPDATE 'A'（非同步）時 sy-subrc 不可信。更新失敗會變成 SM13 的 update terminate，你的程式卻以為成功了。要確定結果就用 'S'。
  • 被呼叫的交易裡如果有 COMMIT WORK，預設會直接結束 CALL TRANSACTION，後面的畫面就不跑了。要繼續就設 racommit = 'X'。
S/4HANA 語法檢查：新版 ABAP 對「純呼叫交易」的形式（CALL TRANSACTION 'XX'，不帶 USING）要求明示 WITH AUTHORITY-CHECK 或 WITHOUT AUTHORITY-CHECK，否則語法檢查會出警告。CALL TRANSACTION ... USING bdcdata 這種 BDC 形式本身就會做交易權限檢查（除非用 AUTHORITY-CHECK 相關附加關掉），但呼叫者仍必須擁有該 TCODE 的 S_TCODE 與底層物件權限。BDC 不會幫你繞過權限。

6. 錯誤訊息：從 BDCMSGCOLL 變成看得懂的中文字

BDCMSGCOLL 收回來的是「訊息代號」，不是文字。要變成人看得懂的句子有三條路：

FORM eval_bdc_messages USING it_msg   TYPE bdcmsgcoll_tab
                             iv_subrc TYPE sy-subrc
                    CHANGING cs_xls   TYPE ty_xls.

  DATA lv_text TYPE string.

  cs_xls-status = 'S'.
  cs_xls-msg    = TEXT-s01.        " 「過帳成功」

  LOOP AT it_msg INTO DATA(ls_msg).

    " 作法一（最推薦）：MESSAGE ... INTO，語法內建、不用呼叫 FM
    MESSAGE ID     ls_msg-msgid
            TYPE   ls_msg-msgtyp
            NUMBER ls_msg-msgnr
            WITH   ls_msg-msgv1 ls_msg-msgv2 ls_msg-msgv3 ls_msg-msgv4
            INTO   lv_text.

    " 只要出現一筆 E/A/X 就算失敗，且以第一筆錯誤為主
    IF ls_msg-msgtyp CA 'EAX'.
      cs_xls-status = 'E'.
      cs_xls-msg    = |{ ls_msg-msgid }{ ls_msg-msgnr } { lv_text }|.
      EXIT.
    ENDIF.

  ENDLOOP.

  " CALL TRANSACTION 本身回傳非 0，但訊息表卻是空的 → 也要當失敗
  IF iv_subrc <> 0 AND cs_xls-status <> 'E'.
    cs_xls-status = 'E'.
    cs_xls-msg    = |CALL TRANSACTION failed, RC={ iv_subrc }|.
  ENDIF.

ENDFORM.

FORM modify_log_table.

  DATA lt_log TYPE STANDARD TABLE OF zppworkma0001.

  " 1) 同一批的鍵值先刪掉，讓程式可以重跑而不會殘留舊結果
  DELETE FROM zppworkma0001
    FOR ALL ENTRIES IN @gt_xls
    WHERE aufnr = @gt_xls-aufnr
      AND vornr = @gt_xls-vornr.

  LOOP AT gt_xls ASSIGNING FIELD-SYMBOL(<ls_xls>).

    DATA(ls_log) = VALUE zppworkma0001( ).

    TRY.
        " 字元 → 型別欄位的轉換都可能爆，包起來
        ls_log = CORRESPONDING #( <ls_xls> ).

      CATCH cx_sy_conversion_no_number cx_sy_conversion_error INTO DATA(lx_conv).
        CLEAR ls_log.
        ls_log-aufnr  = <ls_xls>-aufnr.
        ls_log-vornr  = <ls_xls>-vornr.
        ls_log-status = 'E'.
        ls_log-msg    = |轉碼失敗：{ lx_conv->get_text( ) }|.
        <ls_xls>-status = 'E'.
        <ls_xls>-msg    = '轉碼失敗'.
    ENDTRY.

    ls_log-ora   = |{ <ls_xls> }|.       " 原始整列，出事時的證據
    ls_log-erdat = sy-datlo.
    ls_log-ertim = sy-timlo.
    ls_log-ernam = sy-uname.
    APPEND ls_log TO lt_log.

  COMMIT WORK AND WAIT.

FOR ALL ENTRIES 空表陷阱：gt_xls 若為空，上面的 DELETE ... FOR ALL ENTRIES 會變成「沒有 WHERE 條件」，整張表被清空！凡是 FOR ALL ENTRIES，前面一定要加 IF gt_xls IS NOT INITIAL. 這條規矩對 SELECT 一樣適用（SELECT 空表會抓回全表）。

      queue_error = 2
      OTHERS      = 3.

SM35 的三種執行模式，跟 CALL TRANSACTION 的 MODE 是對應的：

  • Process/Foreground（前景）：一個畫面一個畫面走，用來看 BDC 到底卡在哪。
  • Display errors only（僅顯示錯誤）：正常畫面自動跑過，出錯才停下來讓你改。日常補跑最常用。
  • Background（背景）：完全不顯示，交給背景作業跑。
要讓 session 自己在背景被消化，排一支標準程式 RSBDCSUB 的背景作業，指定 group 名稱即可。SM35 的 Log 按鈕可以看到每一筆的訊息，錯誤 session 會保留，修完再送。相關資料表：APQI（群組表頭）、APQD（資料）。
Session 沒有「即時回饋」。你的程式跑完只知道「已建立群組」，不知道成功幾筆。如果業務要求「上傳完馬上告訴我哪幾筆錯」，就必須用 CALL TRANSACTION；或用 Session 但另外寫一支程式去讀 SM35 的 log（BDC_... 相關 FM／APQI）回報，複雜度高很多。

8. BDC 的九個坑（老師特別強調）

#坑解法
1日期格式：BDC 的值等同「使用者敲進去的字」。同一支程式，A 使用者 SU3 設 DD.MM.YYYY、B 設 YYYY/MM/DD，結果就不同用 WRITE lv_date TO lv_char 或 FM CONVERSION_EXIT_DATUM_OUTPUT 轉成「目前使用者的外部格式」再送；或在背景作業指定一個格式固定的技術帳號
2小數點格式：SU3 的 Decimal notation 有 1,234,567.89 / 1.234.567,89 / 1 234 567,89 三種數量金額也要用 WRITE ... TO 轉外部格式；或全公司統一 SU3 設定並寫進上線 checklist
3SU3 使用者參數：Parameter ID 會自動帶預設值進畫面欄位（例如工廠 WRK、公司代碼 BUK）BDC 要明確送出每一個欄位值，不要依賴預設值；或替背景作業建立參數乾淨的專用帳號
4前導零 / ALPHA：Excel 的 1000123 和資料庫的 001000123 對不起來丟進 BDC 前先跑 CONVERSION_EXIT_ALPHA_INPUT；顯示回使用者時用 ..._OUTPUT
5Excel 帶來的引號與空白：CSV 匯出常變成 "1000123"講義用 TRANSLATE t_xls-aufnr USING '" ' 把雙引號換成空白，再 CONDENSE。現代寫法用 REPLACE ALL OCCURRENCES OF '"' IN lv_x WITH space
6Table Control 捲動：畫面一次只顯示 N 列，第 N+1 列必須先翻頁見下方程式；核心是每 N 筆送一次 BDC_OKCODE = '=P+'，並用 BDC_CURSOR 定位
7畫面大小：Table Control 可見列數隨 GUI 視窗大小改變defsize = 'X'，或改用「每頁固定第 1 列輸入」的定位欄位（很多交易有 Position 欄）
8Enhancement / User Exit 跳出額外畫面：正式機有客製檢查，開發機沒有錄製一定要在「有客製的環境」錄；上線前用 MODE 'A' 在 QAS 完整跑一次
9SAP 升級後畫面改版：欄位改名、畫面編號改變 → BDC 全部失效這是 BDC 的原罪。所以 S/4HANA 一律「先找 BAPI，找不到才 BDC」
 
*&--- Table Control 捲動的標準寫法（以每頁可輸入 lc_rows 列為例）
CONSTANTS lc_rows TYPE i VALUE 5.        " 該畫面每頁可輸入列數

DATA(lv_idx) = 0.

LOOP AT lt_item INTO DATA(ls_item).

  DATA(lv_row) = lv_idx MOD lc_rows + 1.   " 本頁的第幾列（1..lc_rows）

  IF lv_row = 1.
    " 每頁的第一列 → 先開新畫面
    APPEND VALUE bdcdata( program  = 'SAPMV45A'
                          dynpro   = '4001'
                          dynbegin = abap_true ) TO lt_bdc.
    " 游標放在本頁第一列，確保系統認得目前的捲動位置
    APPEND VALUE bdcdata( fnam = 'BDC_CURSOR'
                          fval = |VBAP-POSNR({ lv_row WIDTH = 2 ALIGN = RIGHT PAD = '0' })| ) TO lt_bdc.
  ENDIF.

  APPEND VALUE bdcdata(
    fnam = |RV45A-MABNR({ lv_row WIDTH = 2 ALIGN = RIGHT PAD = '0' })|
    fval = ls_item-matnr ) TO lt_bdc.
  APPEND VALUE bdcdata(
    fnam = |VBAP-KWMENG({ lv_row WIDTH = 2 ALIGN = RIGHT PAD = '0' })|
    fval = |{ ls_item-kwmeng }| ) TO lt_bdc.

  lv_idx = lv_idx + 1.

  " 本頁塞滿了，或已是最後一筆 → 決定按什麼鍵
  IF lv_idx MOD lc_rows = 0.
    APPEND VALUE bdcdata( fnam = 'BDC_OKCODE' fval = '=P+' ) TO lt_bdc.   " 翻下一頁
  ENDIF.

ENDLOOP.

" 最後補一次 Enter 與存檔
APPEND VALUE bdcdata( fnam = 'BDC_OKCODE' fval = '/00'  ) TO lt_bdc.
APPEND VALUE bdcdata( fnam = 'BDC_OKCODE' fval = '=SICH' ) TO lt_bdc.
Table Control 欄位名的寫法：結構-欄位(列號)，列號固定兩位、右靠、補零，例如 VBAP-KWMENG(03)。這是 BDC 新手最常寫錯的地方（寫成 (3) 就找不到欄位）。字串範本 WIDTH = 2 ALIGN = RIGHT PAD = '0' 剛好可以生出來。

9. BDC vs BAPI：S/4HANA 的選用原則

這是本章最重要的觀念題。老師的立場很明確：能用 BAPI 就不要用 BDC。但 BDC 沒有死，它在 S/4HANA 上仍有無可取代的場合。

比較BDC（CALL TRANSACTION）BAPI / Function ModuleOData / RAP
執行對象畫面（PBO/PAI）函數介面服務介面
效能慢（每筆都跑一次畫面）快快
檢查完整度最完整（含所有 Exit、客製）只有該 BAPI 實作的檢查依 Behavior Definition
升級穩定度差，畫面一改就壞好，SAP 保證介面相容好
能否背景執行可（MODE 'N'）可可
Fiori 畫面完全不能錄—原生支援
回傳訊息BDCMSGCOLLBAPIRET2Message container
S/4HANA 三個必須知道的變化：
  • Fiori／SAP GUI for HTML 的畫面錄不了 BDC。SHDB 只能錄傳統 SAP GUI Dynpro。如果那支交易在 S/4HANA 只剩 Fiori App，就沒有 BDC 這條路，只能找 OData 或 BAPI。
  • 很多經典交易在 S/4HANA 被廢止或改版（例如客戶／供應商主檔統一成 Business Partner，XD01／MK01 已不建議使用，改用 BP 與 BAPI_BUPA_* / CVI）。舊系統轉過來的 BDC 程式一定要重驗。
  • 資料遷移改用 Migration Cockpit（LTMC / Fiori「Migrate Your Data」），LSMW 在 S/4HANA 已不受支援（SAP Note 2287723）。期初資料不要再寫 BDC。

以 CO11N 報工為例，S/4HANA 的建議寫法是改用 BAPI，錯誤處理乾淨得多：

編碼與 BOM 是 CSV 的兩大殺手（尤其中文）。
  • codepage 傳錯，中文會變亂碼。常見 SAP codepage：1100 Latin-1、4110 UTF-8、4103 UTF-16LE、8300 繁體中文 BIG5。實際可用值請查 TCP00 / TCP0C。
  • Excel 另存 CSV UTF-8 時會在檔頭放 BOM（EF BB BF），第一個欄位會多三個看不見的字元，比對永遠不相等。用 cl_abap_char_utilities=>byte_order_mark_utf8 清掉。
  • 反過來，SAP 產生給 Excel 開的 UTF-8 CSV，要主動加上 BOM，否則 Excel 用 ANSI 解讀，中文變亂碼。

12. FTP：SAP 標準函數群完整流程

講義的 FTP 流程設計得很完整，值得整套背下來：連線 → 檢查來源／備份目錄 → 設 binary 模式 → 列檔名 → 逐檔 get → 備份到 BAK 目錄 → 刪來源 → 斷線。這個「取走後立刻搬到備份目錄並刪除來源」的設計，可以保證同一個檔不會被處理兩次。

函數用途重點參數
HTTP_SCRAMBLE把密碼加擾（FTP_CONNECT 只吃加擾過的密碼）source／sourcelen／key（慣用 26101957）
FTP_CONNECT建立連線user／password（已加擾）／host／rfc_destination → 回 handle
FTP_COMMAND下任意 FTP 指令：cd、bin／asc、nlist／dir、get、put、del、mkdirhandle／command，結果回 TABLES data
FTP_SERVER_TO_R3把 FTP 上的檔案抓進 ABAP 內表fname；TABLES blob（二進位）或 text（文字）；回 blob_length
FTP_R3_TO_SERVER把 ABAP 內表寫回 FTPfname／blob_length／TABLES blob
FTP_DISCONNECT斷線handle
RFC_CONNECTION_CLOSE釋放 RFC 連線（斷線後一定要做）destination
兩個 RFC destination（SM59 建立，類型 T / TCP-IP，程式 sapftp）：
  • SAPFTP：走前端（使用者的 PC），只能在有 GUI 時用。
  • SAPFTPA：走應用伺服器，可以在背景作業執行。介面程式一律用這個。講義的註解也特別標了：「需至 TOP 區設定 w_ftp_dest = 'SAPFTPA'（可 background 執行）」。

CLASS lcl_ftp IMPLEMENTATION.

  METHOD connect.

    DATA lv_pwd TYPE scms_ftppw.

    lv_pwd = iv_pwd.

    " 密碼必須先加擾，FTP_CONNECT 不吃明碼
    CALL FUNCTION 'HTTP_SCRAMBLE'
      EXPORTING
        source      = lv_pwd
        sourcelen   = strlen( lv_pwd )
        key         = gc_key
      IMPORTING
        destination = lv_pwd.

    CALL FUNCTION 'FTP_CONNECT'
      EXPORTING
        user            = iv_user
        password        = lv_pwd
        host            = iv_host
        rfc_destination = gc_dest
      IMPORTING
        handle          = gv_handle
      EXCEPTIONS
        not_connected   = 1
        OTHERS          = 2.

    IF sy-subrc <> 0.
      RAISE EXCEPTION TYPE cx_sy_conversion_error.   " 實務上換成自建例外
    ENDIF.

  ENDMETHOD.

  METHOD command.

    CALL FUNCTION 'FTP_COMMAND'
      EXPORTING
        handle        = gv_handle
        command       = iv_cmd            " 'cd /CO01/'、'bin'、'nlist'、'del x.csv'
      TABLES
        data          = rt_result
      EXCEPTIONS
        tcpip_error   = 1
        command_error = 2
        data_error    = 3
        OTHERS        = 4.

  ENDMETHOD.

  METHOD get_file.

    DATA: lt_blob TYPE STANDARD TABLE OF ty_x255,
          lv_len  TYPE i.

    CALL FUNCTION 'FTP_SERVER_TO_R3'
      EXPORTING
        handle        = gv_handle
        fname         = iv_fname
      IMPORTING
        blob_length   = lv_len
      TABLES
        blob          = lt_blob            " 二進位；文字檔可改用 text 參數
      EXCEPTIONS
        tcpip_error   = 1
        command_error = 2
        data_error    = 3
        OTHERS        = 4.

    CHECK sy-subrc = 0.

    CALL FUNCTION 'SCMS_BINARY_TO_XSTRING'
      EXPORTING
        input_length = lv_len
      IMPORTING
        buffer       = rv_xstr
      TABLES
        binary_tab   = lt_blob.

  ENDMETHOD.

  METHOD put_file.

    DATA: lt_blob TYPE STANDARD TABLE OF ty_x255,
          lv_len  TYPE i.

    CALL FUNCTION 'SCMS_XSTRING_TO_BINARY'
      EXPORTING
        buffer        = iv_xstr
      IMPORTING
        output_length = lv_len
      TABLES
        binary_tab    = lt_blob.

    CALL FUNCTION 'FTP_R3_TO_SERVER'
      EXPORTING
        handle        = gv_handle
        fname         = iv_fname
        blob_length   = lv_len
      TABLES
        blob          = lt_blob
      EXCEPTIONS
        tcpip_error   = 1
        command_error = 2
        data_error    = 3
        OTHERS        = 4.

  ENDMETHOD.

  METHOD disconnect.

    CALL FUNCTION 'FTP_DISCONNECT'
      EXPORTING handle = gv_handle.

    " 這一步很多人忘記：不做會累積 RFC 連線
    CALL FUNCTION 'RFC_CONNECTION_CLOSE'
      EXPORTING destination = gc_dest
      EXCEPTIONS OTHERS = 1.

  ENDMETHOD.

ENDCLASS.

13. 寄信：CL_BCS 完整樣板

講義用的是舊 API SO_DOCUMENT_SEND_API1（更舊的還有 SO_NEW_DOCUMENT_ATT_SEND_API1）。這兩支要自己組 packing list、算 doc_size，很容易算錯導致附件壞掉。S/4HANA 一律建議改用 CL_BCS（Business Communication Services），物件導向、附件用一行 add_attachment 就好。

*&--- CL_BCS 完整樣板：HTML 本文 + PDF 附件 + XLSX 附件 + 多收件人
FORM send_mail_bcs USING it_recv   TYPE ty_t_email
                         iv_pdf    TYPE xstring
                         iv_xlsx   TYPE xstring.

  TRY.
      "--- 1) 建立傳送請求
      DATA(lo_send) = cl_bcs=>create_persistent( ).

      "--- 2) 本文（HTM 或 RAW）
      DATA(lt_body) = VALUE bcsy_text(
        ( line = '<p>各位好：</p>' )
        ( line = |<p>MES 工時回報上傳 SAP 已於 { sy-datum DATE = USER } { sy-uzeit TIME = USER } 完成。</p>| )
        ( line = |<p>成功 { lines( VALUE ty_t_xls( FOR w IN gt_xls WHERE ( status = 'S' ) ( w ) ) ) } 筆，| &&
                 |失敗 { lines( VALUE ty_t_xls( FOR w IN gt_xls WHERE ( status = 'E' ) ( w ) ) ) } 筆，明細請見附件。</p>| )
        ( line = '<p>（本信件由系統自動發出，請勿直接回覆）</p>' ) ).

      DATA(lo_doc) = cl_document_bcs=>create_document(
                       i_type    = 'HTM'                 " RAW=純文字 HTM=網頁
                       i_text    = lt_body
                       i_subject = CONV so_obj_des( 'MES 工時回報上傳 SAP' ) ).

      IF iv_pdf IS NOT INITIAL.
        lo_doc->add_attachment(
          i_attachment_type    = 'PDF'
          i_attachment_subject = CONV so_obj_des( |工時上傳結果_{ sy-datum }| )   " 最長 50 字元
          i_att_content_hex    = cl_bcs_convert=>xstring_to_solix( iv_pdf ) ).
      ENDIF.

      "--- 4) 附件：XLSX
      IF iv_xlsx IS NOT INITIAL.
        lo_doc->add_attachment(
          i_attachment_type    = 'XLS'
          i_attachment_subject = CONV so_obj_des( |明細_{ sy-datum }.xlsx| )
          i_att_content_hex    = cl_bcs_convert=>xstring_to_solix( iv_xlsx ) ).
      ENDIF.

      lo_send->set_document( lo_doc ).

      "--- 5) 寄件者（用 SAP 使用者，或指定一個對外的位址）
      lo_send->set_sender( cl_sapuser_bcs=>create( sy-uname ) ).
      " 或：cl_cam_address_bcs=>create_internet_address( 'sapnoreply@company.com' )

      "--- 6) 收件者
      LOOP AT it_recv INTO DATA(lv_mail).
        lo_send->add_recipient(
          i_recipient = cl_cam_address_bcs=>create_internet_address( CONV adr6-smtp_addr( lv_mail ) )
          i_express   = abap_true ).
      ENDLOOP.

      "--- 7) 立即送出（不等 RSCONN01 排程）
      lo_send->set_send_immediately( abap_true ).

    CATCH cx_bcs INTO DATA(lx_bcs).

  ENDTRY.

CL_BCS 的五個必踩坑：
  • 忘了 COMMIT WORK：create_persistent 是走 update task 的，沒有 COMMIT 就完全沒動作，而且不會報錯。這是「程式說成功、信卻沒到」的第一名原因。
  • i_attachment_subject 最多 50 字元，超過會被截斷、附檔名跑掉。
  • 附件檔名的副檔名由 i_attachment_type 決定（'PDF'／'XLS'／'CSV'／'TXT'／'BIN'），不是由 subject 決定。
  • 不呼叫 set_send_immediately( 'X' ) 的話，信件只會排進佇列，要等背景程式 RSCONN01 跑到才送。
  • SCOT 沒設定就永遠寄不出去。SCOT 設定 SMTP node 與網域路由，SOST 查每一封信的狀態（等待／已送／失敗），這兩個交易碼一定要會。

      WHEN 'USR'.       " 內部 SAP 使用者 → 查 SU01 的 e-mail
        SELECT SINGLE smtp_addr
          FROM adr6
          INNER JOIN usr21 ON usr21~persnumber = adr6~persnumber
                          AND usr21~addrnumber = adr6~addrnumber
          WHERE usr21~bname = @ls_mem-memnam
          INTO @DATA(lv_smtp).
        IF sy-subrc = 0.
          APPEND lv_smtp TO ct_recv.
        ENDIF.
    ENDCASE.
  ENDLOOP.

ENDFORM.
舊 API 還會遇到，要看得懂：SO_DOCUMENT_SEND_API1 的四張表——PACKING_LIST（描述每個「包」是本文還是附件、從第幾列到第幾列、型別 RAW/PDF/XLS）、CONTENTS_TXT（本文，255 字元一列）、CONTENTS_BIN（附件二進位）、RECEIVERS（rec_type = 'U' 外部位址 / 'B' 內部使用者，com_type = 'INT'）。它最容易錯的是 doc_size：必須算成 ( 列數 - 1 ) * 255 + 最後一列的實際長度，算錯附件就毀了。這正是改用 CL_BCS 的理由。

15. 背景作業：SM36 / SM37 與 JOB_OPEN / SUBMIT / JOB_CLOSE

介面程式的終點是「排成背景作業，每天／每小時自己跑」。兩條路：手動用 SM36 排，或程式自己建 Job。

手動排程（SM36）的步驟：（依講義步驟整理）

  1. SM36 → 輸入 Job Name、Job Class（A 最高／B 中／C 一般，一般客製程式用 C）、Target server（可指定跑在哪台 App Server）。
  2. Step：選 ABAP program，填程式名 + Variant（變式）。背景作業一定要有變式，因為沒有人可以在畫面上輸入條件。變式在 SE38 →「以變式執行」→ Save 建立。
  3. Start condition：Immediate（立即）／Date-Time（指定時間）／After job（某個 Job 跑完之後）／After event（事件觸發，SM62 定義事件、SM64 手動觸發）／At operation mode change。
  4. 勾 Periodic job 並設定週期（每小時／每天／每週／每月）。
  5. Save。到 SM37 查狀態：Scheduled／Released／Ready／Active／Finished／Cancelled；點進去看 Job log 與 Spool。
*&--- 程式內建立背景作業（例如：使用者按下按鈕後排一支長時間的程式去背景跑）

寫背景程式的六條紀律：

  • 不可有任何畫面互動：MESSAGE ... TYPE 'I'、POPUP_TO_CONFIRM、CALL SCREEN、WRITE 之後的互動式清單，全部不行。背景遇到 TYPE 'I'／'A' 會直接讓 Job Cancel。
  • 不可用任何 CL_GUI_* / GUI_UPLOAD / GUI_DOWNLOAD / OLE。用 sy-batch = abap_true 判斷分流。
  • ALV 在背景會自動印到 Spool：CL_SALV_TABLE 的 display( ) 在背景會輸出成清單，可從 SM37 → Spool 看到。
  • 用 WRITE 寫執行記錄：背景執行時 WRITE 的內容會進 Spool，是最省事的 log。重要訊息另外用 MESSAGE ... TYPE 'S'（會進 Job log）。
  • 長交易要分批 COMMIT：避免 update table 爆掉、避免鎖太久。
  • 要能重跑（idempotent）：同一個檔案再跑一次不可以變成雙重過帳。做法是「處理完立刻移走檔案」或「紀錄表用 MODIFY 而非 INSERT」。

16. S/4HANA 補充：Application Jobs 與 Fiori 排程

SM36／SM37 是「技術人員」的工具，需要 S_BTCH_JOB 權限。S/4HANA 另外提供一套給業務使用者用的排程機制：

  • Application Jobs（Fiori App「Application Jobs」/ F1240）：使用者在 Fiori 上選一個 Job Template、填參數、設定週期，就能自己排程，不必進 SAP GUI，也不需要 SM36 的權限。
  • Job Catalog Entry：開發端要做的事。建立一個實作 IF_APJ_DPC_RUN（定義參數與預設值）與 IF_APJ_RT_RUN（實際執行邏輯）的 ABAP 類別，再在 ADT/SE80 建立 Job Catalog Entry 與 Job Template 指向它。之後這支程式就會出現在 Fiori 的可排程清單裡。
  • SJOBREPO（Technical Job Repository）：SAP 標準的技術背景作業（例如 SAP_APPLICATION_LOG_DELETE、各種 housekeeping）改由 Job Repository 自動註冊與啟用，不再需要人工一個一個排。SJOBREPO 可以看到哪些標準 Job 已啟用。
  • SAP Job Scheduling Service / BTP：跨系統的排程，屬於雲端方案。
什麼時候該做成 Application Job？當「使用者自己想決定什麼時候跑、跑哪些條件」時。例如月結報表、對帳檔產出。純技術性的介面（每 10 分鐘抓 FTP）用傳統 SM36 即可，不必包成 Application Job。
ABAP Cloud（RAP / Steampunk）不允許 BDC。CALL TRANSACTION USING、BDC_* 函數、GUI_*、OPEN DATASET 全部不在允許的 API 清單裡。如果你的開發要往 Clean Core 走（S/4HANA Cloud、Embedded Steampunk），這一章的技巧只能用在傳統 ABAP 開發模型（Classic ABAP）的自建程式上。
