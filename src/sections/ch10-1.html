1. 第十部導覽：Code Pushdown → 資料模型 → 交易模型

前面各部教的是「在 ABAP 應用伺服器上處理資料」。第十部處理的是 S/4HANA 時代的另一條主線：把運算推到 HANA（Code Pushdown），把資料表包裝成有業務語意的資料模型（CDS），再在資料模型上加上新增、修改、刪除等交易行為（RAP）。三者是一層疊一層的關係，不是互相取代：

層次技術解決什麼問題一句話定位
① Code PushdownABAP SQL 運算式、CDS、AMDP（SQLScript）JOIN、彙總、計算搬到 HANA 做，只傳結果回來能用 ABAP SQL／CDS 的就不要寫 AMDP；AMDP 是最後手段

3. CDS 是什麼：跟 SE11 資料庫 view 差在哪

ABAP CDS（Core Data Services）是 ABAP 的資料模型層。你用一種類似 SQL 的 DDL（資料定義語言）在 ADT 裡寫出「這個實體有哪些欄位、從哪些表來、跟誰有關聯、每個欄位是什麼語意」，啟用後它就是一個全域的結構型別，可以在 ABAP SQL 裡當資料來源讀取，也可以當別的 CDS 的資料來源、當 OData 服務的基礎。

比較項目SE11 Database ViewCDS view
建立工具SE11 表單只能在 ADT（SE11／SE80 只能顯示）
JOIN只有 inner joininner、left outer、right outer，另有 association
運算沒有CASE、CAST、算術、字串與日期函數、幣別與單位換算
彙總沒有SUM、COUNT、MIN、MAX、AVG、GROUP BY、HAVING
參數沒有可以（with parameters）
語意只有 DDIC 型別註解：幣別參照、單位參照、文字、權限、UI、分析
權限程式自己 AUTHORITY-CHECKDCL role，ABAP SQL 讀取時自動套用（7.50 起）
重用性低CDS 可以疊 CDS，形成分層的資料模型（VDM）

CDS 與 HANA 原生的 calculation view 不同：ABAP CDS 由 ABAP 管理（有傳輸、有版本、有語法檢查），在所有 SAP 支援的資料庫上都能用；只是 S/4HANA 一律跑在 HANA 上，所以 CDS 的運算最後都在 HANA 執行。

" 最小的 CDS view（1809 可用的 DDIC-based 寫法）
@AbapCatalog.sqlViewName: 'ZVSOHEADMIN'
@AbapCatalog.compiler.compareFilter: true
@AccessControl.authorizationCheck: #NOT_REQUIRED
@EndUserText.label: '銷售訂單表頭（最小範例）'
define view ZI_SalesOrderMin
  as select from vbak
{
  key vbeln as SalesOrder,
      erdat as CreationDate,
      auart as SalesOrderType,
      vkorg as SalesOrganization,
      kunnr as SoldToParty
}
" 在 ABAP 讀 CDS 跟讀表一樣，而且 CDS 名稱本身就是 DDIC 結構型別
SELECT SalesOrder, CreationDate, SoldToParty
  FROM zi_salesordermin
  WHERE SalesOrganization = @p_vkorg
  ORDER BY SalesOrder
  INTO TABLE @DATA(lt_head).

DATA ls_head TYPE zi_salesordermin.   " 用 CDS 實體名稱當型別

4. VDM：S/4HANA 的標準 CDS 分層與命名

S/4HANA 的 VDM（Virtual Data Model）就是 SAP 用 CDS 建出的整套標準資料模型。它分層，而且從名稱前綴就看得出是哪一層：

前綴類型@VDM.viewType說明
I_Interface view（basic 或 composite）#BASIC／#COMPOSITE可重用層。basic 直接讀資料表、把欄位改成有語意的名稱；composite 由 basic 組合而成。例如 I_SalesOrder 是銷售訂單業務物件的 root，I_SalesOrderItem 是它的明細
C_Consumption view#CONSUMPTION最上層，為特定 app 或分析報表設計；唯一可作為 analytical query 的 VDM 類型
R_Restricted reuse view#BASIC／#COMPOSITE跟 I_ 一樣是重用層，但不開放給客戶與夥伴重用
P_Private view—內部輔助用
A_Remote API view—對外 API 的基礎
X_View extend—SAP 提供的產業別、國家別欄位擴充
E_Extension include view#EXTENSIONKey user 欄位擴充的技術載體
F_、D_Derivation function、abstract entity#DERIVATION_FUNCTION／—較少直接接觸

@VDM.viewType 允許的值（依註解定義）：#BASIC、#COMPOSITE、#CONSUMPTION、#DERIVATION_FUNCTION、#EXTENSION、#TRANSACTIONAL。其中 #TRANSACTIONAL 是定義交易執行期（含 draft）的特殊 composite view。VDM 註解不影響執行期，只是讓 view browser 之類的工具正確分類。常見後綴：Query／Q（分析查詢）、Cube、Text（語言相關文字）、TP（transactional processing）、VH（value help）。

" 自建 CDS 也建議跟著 VDM 命名：Z + 前綴 + 語意名稱
@AbapCatalog.sqlViewName: 'ZISDSOTYPE'
@AccessControl.authorizationCheck: #NOT_REQUIRED
@EndUserText.label: '銷售訂單類型'
@VDM.viewType: #BASIC                    // 只是分類，不影響執行
@ObjectModel.representativeKey: 'SalesOrderType'
define view ZI_SalesOrderType
  as select from tvak
{
  key auart as SalesOrderType,
      vbtyp as SalesDocumentCategory
}
先找標準，再想客製。要讀銷售訂單之前，先在 ADT 用 Ctrl+Shift+A 搜尋 I_SalesOrder*，看標準 VDM 有沒有現成的 view。標準 view 是否可以讓客戶直接使用，要看它的 release 狀態（stability contract，例如 C1 表示可在系統內部重用）：在 ADT 開啟該 view，看 Properties → API State。有 released 的就直接用，沒有才自己從 VBAK 建。
出處：SAP Help – VDM Layers and View Types；SAP Help – Naming Conventions in the Virtual Data Model；SAP Help – Stability Contracts for CDS Views；VDM.viewType 註解定義。

5. 兩種 CDS view：DDIC-based view 與 view entity

CDS view 有兩代。1809、1909 只有第一代；2020 起有第二代，SAP 建議新開發一律用第二代。

比較項目DDIC-based view（第一代）CDS view entity（第二代）
語法define viewdefine view entity
可用版本7.40 SP05 起（1809 可用）；7.57 起標為 obsolete7.55（S/4HANA 2020）起
SQL view 物件必須寫 @AbapCatalog.sqlViewName（最多 16 字元），啟用時在 DDIC 產生一個「CDS-managed DDIC view」，SE11 看得到不產生 DDIC view，不寫也不能寫 sqlViewName
名稱三個名稱：DDL source、CDS 實體、SQL view一個名稱：DDL source 與實體名稱必須相同
啟用CDS 實體、DDIC view、資料庫 view 都要啟用只啟用 CDS 實體與 HANA 上的 view，啟用較快
Client 處理用 @ClientHandling.type、@ClientHandling.algorithm 控制；client 欄位可以寫在 SELECT 清單全自動（依 session 變數 $session.client 過濾），不允許 client 註解，SELECT 清單也不能放 client 欄位
@AbapCatalog.compiler.compareFilter建議設 true（不寫時預設 false：相同過濾條件的 path 會各自產生 JOIN）不需要也不允許，一律自動比對
語法檢查較寬鬆較嚴格，例如多個資料來源時欄位要加來源別名、CURR 欄位必須有幣別參照註解
參數引用:p_x 或 $parameters.p_x只能 $parameters.p_x
SELECT *可以不支援
AMDP 的 USING不行（DDIC-based view 不是 client-safe）可以

6. 從 DDIC-based view 遷移到 view entity

升級到 2020 以上之後，既有的第一代 CDS 照樣能用，不必急著全部改；但新開發用第二代，舊的可以分批遷移。可用的工具依版本而定：

版本工具用途
2020（7.55）無官方工具手動改寫（見下方檢查清單）
2021（7.56）起程式 RUTDDLS_MIGRATION_CANDIDATES分析哪些 DDIC-based view 可以遷移
2021（7.56）起程式 RUTDDLSV2MIGRATION實際遷移：自動做大部分調整，產生未啟用的新版本，確認後再手動啟用
2022（7.57）起程式 RUT_WHERE_USE_SQLVIEW列出所有還在使用 CDS-managed DDIC view（SQL view 名稱）的 repository 物件
2023 FPS00（7.58）起ADT 精靈 Migrate to CDS View Entity...在 Project Explorer 選 Data Definition → 右鍵 → Migrate to CDS View Entity...；可選 Simulation（只檢查）或 Migration（產生未啟用版本，要手動啟用），可指定傳輸請求，結果可匯出 CSV
名稱更正：常被提到的「RUT_WHERE_USE_SQLVIEW」不是遷移工具，它是 7.57 起用來找出「誰還在用 SQL view 名稱」的清單程式；真正做遷移的是 7.56 起的 RUTDDLSV2MIGRATION，分析可否遷移的是 RUTDDLS_MIGRATION_CANDIDATES。

遷移前一定要先查的事：第二代沒有 SQL view。任何程式、SE11 物件、查詢若用的是 sqlViewName（例如 SELECT … FROM zvsogen1），遷移後就會失效。所以先用 RUT_WHERE_USE_SQLVIEW（7.57 起）或 where-used 找出這些使用者，改成用 CDS 實體名稱。

手動遷移檢查清單（7.55 沒有工具時照這個做）：

  1. define view 改成 define view entity；DDL source 名稱與實體名稱必須一致。
  2. 刪除 @AbapCatalog.sqlViewName、@AbapCatalog.compiler.compareFilter、@ClientHandling.*（第二代不允許）。
  3. SELECT 清單如果有 mandt，刪掉。
  4. 參數引用 :p_x 全部改成 $parameters.p_x。
  5. 多個資料來源時，每個欄位都加上來源別名（vbak.vbeln）。
  6. CURR、QUAN 欄位補上 @Semantics.amount.currencyCode／@Semantics.quantity.unitOfMeasure，而且要指向同一個 view 裡的幣別／單位欄位。
  7. 有 UNION 的 view 要 7.56 以上才能遷移；有 SELECT * 的要改成明列欄位。
  8. 把所有使用 SQL view 名稱的地方改成實體名稱，再啟用並測試。
" 遷移前（DDIC-based）
@AbapCatalog.sqlViewName: 'ZVSOAMT'
@AbapCatalog.compiler.compareFilter: true
@AccessControl.authorizationCheck: #NOT_REQUIRED
@EndUserText.label: '訂單金額'
define view ZI_SoAmount
  with parameters p_vkorg : vkorg
  as select from vbak
{
  key vbeln as SalesOrder,
      @Semantics.amount.currencyCode: 'Currency'
      netwr as NetAmount,
      @Semantics.currencyCode: true
      waerk as Currency
}
where vkorg = :p_vkorg

" 遷移後（view entity，7.55+）：去掉 sqlViewName／compareFilter，
" :p_vkorg 改成 $parameters.p_vkorg，幣別參照指向同一 view 的 Currency
@AccessControl.authorizationCheck: #NOT_REQUIRED
@EndUserText.label: '訂單金額'
define view entity ZI_SoAmount
  with parameters p_vkorg : vkorg
  as select from vbak
{
  key vbak.vbeln as SalesOrder,
      @Semantics.amount.currencyCode: 'Currency'
      vbak.netwr as NetAmount,
      vbak.waerk as Currency
}
where vbak.vkorg = $parameters.p_vkorg
遷移精靈的文件明講：遷移後的 view entity 一旦啟用，就不能還原成 DDIC-based view。正式遷移前先跑 Simulation，並在開發機用 SE16N／Data Preview 對照遷移前後的筆數與金額。
出處：ABAP CDS in 7.56（第 16、17 項：RUTDDLS_MIGRATION_CANDIDATES、RUTDDLSV2MIGRATION）；ABAP CDS in 7.57（RUT_WHERE_USE_SQLVIEW、DDIC-based views obsolete）；SAP Help – Migrating CDS DDIC-Based Views to CDS View Entities（ADT 精靈）；CDS View Entity, parameter。

7. 在 ADT 建立、啟用與預覽 CDS

CDS 只能在 Eclipse ADT 建立，SAP GUI 沒有 CDS 編輯器（SE11 只能顯示 DDIC-based view 產生的 SQL view）。ADT 的安裝與專案建立見 5-5 章。

  1. 在 Project Explorer 選好套件（例如 $TMP 或 Z 套件）→ 右鍵 New → Other... → Core Data Services → Data Definition。
  2. 輸入 Name（例如 ZI_SALESORDER）、Description。可選填 Referenced Object（例如 VBAK），精靈會把該表所有欄位預先帶進來。
  3. Next → 指定傳輸請求 → Next → Templates 頁：1809 選 Define View（DDIC-based），2020 以上選 Define View Entity。ADT 會記住上次選的範本。
  4. Finish。系統建立一個未啟用的 data definition，放在套件的 Core Data Services 資料夾，並開啟編輯器。
  5. 寫好之後按 Ctrl+F3 啟用（或 Project Explorer 右鍵 Activate）。兩支互相 association 的 view 可以一起選取後一起啟用。
  6. 按 F8 開啟 Data Preview（或右鍵 Open Data Preview）。有參數的 view 會先跳出輸入參數的視窗；可以過濾、改筆數，也能沿著 association 往下看關聯資料。

8. SELECT 清單：key、別名、CAST、CASE、函數與運算

大括號 { } 裡是 SELECT 清單。規則：

  • key 欄位要放在清單最前面、連續排列。它是給 ABAP SQL 語法檢查與框架看的語意鍵，不會在資料庫建立唯一性限制。
  • as 給別名，用 VDM 風格的 CamelCase（SalesOrder、SoldToParty）。ABAP 端讀取時不分大小寫。
  • cast( x as abap.char(8) ) 轉成內建型別，或 cast( x as kunnr ) 轉成資料元素（7.50 起），後者會帶上資料元素的語意（標籤、轉換常式）。
  • case … when … then … else … end：簡單與搜尋式兩種都有。
  • 字串函數：concat( a, b )、concat_with_space( a, b, 空格數 )、substring( s, 起始位置, 長度 )、left、right、length、lpad、replace。

9. JOIN 與 association

CDS 有兩種把表連起來的方法：

  • JOIN（inner join、left outer join、right outer join）：跟 SQL 一樣，每次讀這個 view 都一定會 JOIN。
  • association：宣告「我跟誰有關聯、基數多少、用什麼條件」，只有真的用到時才會 JOIN（on-demand）。

association 什麼時候真的產生 JOIN（依 SAP 文件的分析）：

用法資料庫上發生什麼
只定義並曝露（SELECT 清單寫 _Customer），沒有取目標欄位不產生 JOIN，SQL 裡根本不出現目標表
在 SELECT 清單用 path expression 取目標欄位（_Customer.name1）產生 left outer join
在 WHERE 用 path expression產生 left outer join（many to one）
在 FROM 用 path expression 當資料來源產生 inner join
上層 view 或 ABAP SQL 透過曝露的 association 取欄位在「使用端」產生 left outer join，不在定義端

基數寫法 [0..1]、[1..1]、[0..*]、[1..*]，省略時預設 [0..1]。ON 條件裡引用自己的欄位用 $projection.別名，被 $projection 引用的欄位必須在 SELECT 清單裡。association 名稱習慣以底線開頭（_Item）。

define view ZI_SalesOrderJoin
  as select from vbak

10. WHERE、GROUP BY、HAVING、聚合函數與 UNION

子句的位置在大括號之後：where → group by → having，最後才是 union。聚合函數有 sum、count(*)、count( distinct x )、min、max、avg( x as 型別 )（view entity 的 avg 必須寫 as 型別）。SELECT 清單中所有非聚合欄位都要出現在 group by，聚合欄位都要有別名。

CDS 沒有 ORDER BY。CDS view 的 SELECT 語法只有 WHERE、GROUP BY、HAVING 與集合運算（UNION 等），沒有 ORDER BY。排序一律在使用端處理：ABAP SQL 加 ORDER BY，ALV 設排序。HANA 沒有預設排序，同一個 view 每次回傳順序都可能不同；「取第一筆」前一定要先排序（Casper 的成本評價 H／E 案例，見 5-21 章第 24 節）。

11. 參數：with parameters、$parameters 與 @Environment.systemField

參數讓呼叫端在讀取時傳值進來，常用於「基準日」「目標幣別」「語言」這類必須先知道才能算的條件（純粹過濾用的條件交給 ABAP SQL 的 WHERE 即可，不必做成參數）。

13. 在 ABAP 中使用 CDS：ABAP SQL、參數與 path expression

ABAP SQL 讀 CDS 的規則：

  • FROM 後面寫CDS 實體名稱（ZI_SALESORDER），不要寫 SQL view 名稱（ZISDSO）。讀 SQL view 名稱在 7.56 起已是 obsolete，遷移成 view entity 後更會直接失效。
  • 用 CDS 名稱讀取時，ABAP SQL 自動進入 strict mode：主機變數一定要加 @、欄位用逗號分隔。
  • 傳參數：FROM zi_x( p_a = @lv_a, p_b = @lv_b )。
  • path expression：用反斜線開頭 \_association-欄位，在 SELECT 清單中預設是 left outer join，在 FROM 中預設是 inner join。只有 CDS view 有曝露的 association 才能這樣用。1809（7.53）已可使用。
  • CDS view 若有 DCL role，ABAP SQL 讀取時會自動套用權限（7.50 起）。
" 明細 view 曝露 _SalesOrder（to-one）時，ABAP SQL 可沿路徑取表頭欄位
SELECT SalesOrder,
       SalesOrderItem,
       Material,
       \_SalesOrder-SoldToParty       AS SoldToParty,
       \_SalesOrder-SalesOrganization AS SalesOrganization
  FROM zi_salesorderitem
  WHERE SalesOrder IN @s_vbeln
  ORDER BY SalesOrder, SalesOrderItem
  INTO TABLE @DATA(lt_item).
path expression 盡量走 to-one（明細 → 表頭、訂單 → 客戶）。從表頭沿 to-many 的 \_Item 取欄位，會讓結果列數變成明細筆數，ABAP SQL 也會對基數不符給出語法警告；需要明細就直接讀明細 view。
ABAP SQL 的 SELECT SINGLE 或 UP TO 1 ROWS 讀 CDS 時，只要條件不是完整主鍵，就等於「取第一筆」。HANA 沒有預設排序，一定要先 ORDER BY，或改用 MIN／MAX 彙總，否則結果每次可能不同。
出處：ABAP 7.53 – ABAP SQL Path Expressions；ABAP SQL – SQL Path Expressions（最新版）；DEFINE VIEW ENTITY（用實體名稱讀取時為 strict mode）；ABAP CDS in 7.56（使用 CDS-managed DDIC view 為 obsolete）。

15. 實作範例（1809 版）：ZI_SalesOrder 與 ZI_SalesOrderItem

先找標準：S/4HANA 已有 I_SalesOrder（銷售訂單 root）與 I_SalesOrderItem（明細）。如果你的系統中它們是 released 狀態、欄位也夠用，直接讀標準 view，不必自己建。只有標準沒有、或需要大量 Z 欄位時，才照下面自建。

" 先試標準 view（欄位名稱以系統中的定義為準；可在 ADT 用 F2 看元素清單）
SELECT SalesOrder, SalesOrderType, SalesOrganization, SoldToParty,
       TotalNetAmount, TransactionCurrency
  FROM i_salesorder
  WHERE SalesOrganization = @p_vkorg
  ORDER BY SalesOrder
  INTO TABLE @DATA(lt_std)
  UP TO 100 ROWS.
上例 I_SalesOrder 的欄位名稱（SalesOrderType、SoldToParty、TotalNetAmount、TransactionCurrency）依 VDM 命名慣例撰寫，各版本可能不同，未能逐版確認，請以系統為準。標準 view 若掛有 DCL role，讀取結果會依使用者權限過濾。

17. 常見錯誤與除錯

症狀原因處理
啟用時說 SQL view 名稱已存在或太長sqlViewName 最多 16 字元，且在 DDIC 命名空間中不可重複取短而唯一的名稱（例如 ZISDSO、ZISDSOITEM）；傳輸後就不能改
view entity 啟用失敗：DDL source 名稱不符view entity 的 DDL source 名稱與實體名稱必須相同名稱照 define view entity 後的名字建立
view entity 不能放 mandtview entity 的 client 處理全自動，SELECT 清單不可有 client 欄位刪掉 mandt；也不要寫 @ClientHandling
「元素需要幣別／單位參照」view entity 的 CURR／QUAN 欄位必須有 @Semantics 註解，且參照欄位在同一個 view補註解，並把 waerk／vrkme 一起選出來
「欄位不明確」view entity 在多個資料來源時要求加別名寫成 vbak.vbeln
比較 NUMC 欄位時型別不符或查不到NUMC（例如 POSNR 6 碼）要和相同長度的字元常數比較寫 vbap.posnr = '000010'，不要寫 '10'
用單號過濾查不到資料VBELN 在資料庫存的是內部格式（ALPHA 前導零），CDS 不會幫你轉換CDS 內的常數寫內部格式 '0000012345'；ABAP 端先用 |{ lv_vbeln ALPHA = IN }| 轉換再傳入
讀 CDS 的筆數比 SE16N 少CDS 掛了 DCL role，依使用者權限過濾檢查 @AccessControl.authorizationCheck 與 role；比較時用同一個使用者
表頭金額加總變成好幾倍表頭 view JOIN 了明細，或在表頭用 to-many path表頭與明細分開 view，明細用 association 曝露
同一報表兩次執行結果順序不同、「第一筆」不一樣CDS 沒有 ORDER BY，HANA 沒有預設排序使用端一律 ORDER BY；取第一筆前先排序或用 MIN／MAX
換算結果是 NULL 或 0error_handling 設成 SET_TO_NULL，而 TCURR／T006 沒有對應匯率或換算規則到 OB08、CUNI 檢查；開發時可先用 FAIL_ON_ERROR 看出錯原因
 
" ALPHA 前導零：ABAP 端先轉成內部格式，再用列舉（IN）而不是區間
DATA lt_vbeln TYPE RANGE OF vbeln_va.

lt_vbeln = VALUE #( FOR lv_ext IN VALUE string_table( ( `12345` ) ( `12350` ) )
                    ( sign = 'I' option = 'EQ' low = |{ lv_ext ALPHA = IN WIDTH = 10 }| ) ).

SELECT SalesOrder, SoldToParty, TotalNetAmount, TransactionCurrency
  FROM zi_salesorder
  WHERE SalesOrder IN @lt_vbeln
  ORDER BY SalesOrder                       " CDS 沒有順序，使用端一定要排序
  INTO TABLE @DATA(lt_result).

除錯工具：

  • Data Preview（F8）：啟用後先在 ADT 看資料，確認筆數與欄位。
  • ADT 的 SQL 顯示：在 DDL 編輯器右鍵可以看產生出來的 CREATE 陳述式（選單名稱依 ADT 版本而異，未能逐版確認），用來確認 association 有沒有被展開成 JOIN、client 條件是怎麼加的。
  • ST05 SQL trace：看 ABAP SQL 讀 CDS 時實際送到 HANA 的語句與執行時間。
  • SE11：DDIC-based view 可以用 SQL view 名稱在 SE11 顯示產生的 DDIC view（只能看，不能改）。
HANA 沒有預設排序，這一點在 CDS 最容易被忽略。Casper 在成本評價專案上遇過：資料同時存在 item category「H」與 cost component「E」兩種角度，程式沒排序就取第一筆，結果一下抓到 H、一下抓到 E，成本忽高忽低。CDS 本身不能排序，所以「取第一筆」的邏輯要嘛在 CDS 裡用條件固定只留一種（該案最後固定抓 H），要嘛在使用端明確 ORDER BY。
出處：Client Handling for CDS View Entities（不允許 client 欄位）；DEFINE VIEW ENTITY（名稱規則）；AbapCatalog.sqlViewName（16 字元）；SAP Help – Previewing Data Records（DCL 會過濾預覽結果）；Unit and Currency Conversion Functions（error_handling）。
