14. 生產訂單退料單（二）：可退量計算、號碼範圍與 262 過帳

原程式以 MSEG「料號＋訂單」讀出所有物料憑證行，再逐行回找 RESB（有 RSNUM 用預留鍵，沒有就用料號＋訂單），已投料量 = abs( mseg-erfmg )；最後刪掉「已投料量 = 0 且為 261」的行。問題是 MSEG 沒有過濾移動類型與沖銷：一筆 261 發料若被 262 退過或被沖銷，原 261 行和反向行都會各自出現在清單上，可退量就被高估。

正確的「可退量」應該以預留行＋批次為單位計算：可退量 = Σ(261) − Σ(262) − 已開未過帳的退料單數量。在 S/4HANA 讀 MATDOC：

  FIELDS mblnr, mjahr, zeile,                 "完整鍵：避免 FOR ALL ENTRIES 去重
         aufnr, rsnum, rspos, matnr, werks, lgort, charg,
         bwart, shkzg, menge, meins, budat
  FOR ALL ENTRIES IN @lt_resb
  WHERE rsnum = @lt_resb-rsnum
    AND rspos = @lt_resb-rspos
    AND bwart IN ( '261', '262' )
  INTO TABLE @DATA(lt_mdoc).

" 可退量：依 預留行＋批次 彙總（261 為 H 加、262 為 S 減）

         rsnum TYPE rsnum,

17. ZFIF001（二）取數改寫：以 ACDOCA 為準、行項目條件用 EXISTS

原程式的取數分兩條路：憑證數 ≤ 1,000 時 BSEG 用 FOR ALL ENTRIES、另外 ACDOCA 只取 BSTAT = 'U'；> 1,000 時以每 1,000 張切批（DO … TIMES＋RANGES＋%_HINTS HDB '&MAX_BLOCKING_FACTOR 20&…'），ACDOCA 則不限 BSTAT。兩條路的結果合併時用 READ TABLE lt_bseg WITH KEY … buzei = ls_acdoca-buzei+3（DOCLN 6 碼取後 3 碼對 BUZEI）判斷是否已存在，不存在才把 ACDOCA 行轉成 BSEG 格式（HSL 正負轉 SHKZG S/H、金額取絕對值、RCNTR→KOSTL、RFAREA→FKBER）。

行項目條件（B2 區塊）的語意是「這張憑證只要有任何一行符合各條件就整張印出」，原程式用九個旗標在 AT END OF BELNR 判斷。在 S/4HANA 可以一次在資料庫完成：

CONSTANTS lc_leading_ledger TYPE fins_ledger VALUE '0L'.

原程式的旗標沒清乾淨：AT END OF BELNR 時只 CLEAR 了 RK_HKONT、RK_DMBTR、RK_PRCTR、RK_SGTXT、RK_KOSTL、RK_RSTGR、RK_ZUONR 七個旗標，漏了 RK_KUNNR 與 RK_LIFNR。只要前面某張憑證命中過客戶或供應商條件，之後每一張憑證的這兩個條件都會被當成「已符合」，篩選結果就不正確。這種錯誤測試時很難發現（只輸入一個條件時看不出來），是用 EXISTS 或每組重新 VALUE #( ) 初始化結構的好理由。另外兩條取數路徑對 ACDOCA 的 BSTAT 條件不一致（≤1000 張只取 U、>1000 張全取），同一批憑證分開查與一起查會得到不同結果。

18. ZFIF001（三）科目合併、摘要組字與「用區間判斷訂單類別」的坑

傳票上一行 = 一個「科目＋成本中心（＋內部訂單）」的組合，同組合的多行要合併金額、摘要以換行串接。原程式的規則：

  • 合併鍵 HKONT_KOSTL：一般為「科目＋成本中心」；五組特定科目（某存貨、某應付、四個主營業務收入科目）不論成本中心一律合併；沒有成本中心的行不合併（鍵後加 XX＋流水號）。
  • 會計科目欄 ACCOUNT_TXT：功能範圍描述＋成本中心＋成本中心描述＋科目＋科目名稱＋客戶名／供應商名。
  • 摘要 CONTEXT：行文字 SGTXT，空白時用抬頭文字 BKTXT；若有內部訂單再接「/訂單描述」。
