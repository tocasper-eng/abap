2. 第一單元：報表工具的共同原理與航班資料模型

三種工具（QuickViewer、SAP Query、InfoSet Query）的原理相同，使用者只要做三件事：

  1. 指定資料基礎（例如從哪幾張表讀）。
  2. 決定清單長相。
  3. 定義選擇畫面，預先限縮資料。

真正被執行的是系統產生（generate）出來的一支 ABAP 報表程式，所以報表工具又稱為「報表產生器（report generator）」。使用者不必會 ABAP；但下一節起你會看到，設計 InfoSet 的人必須會 ABAP。

在 SQVI 裡用 SCARR ＋ SPFLI 做 Join，產生器做的事其實就是下面這種 ABAP SQL。先看懂它，後面講 Inner／Left Outer Join 與別名時就不會迷糊：

*&---------------------------------------------------------------*
*& QuickView「SCARR + SPFLI」背後等價的 ABAP SQL（7.52 寫法）
*&---------------------------------------------------------------*
DATA gv_carrid TYPE s_carr_id.
SELECT-OPTIONS s_carr FOR gv_carrid.

START-OF-SELECTION.
  " ① Inner Join：只有「至少有一條航線」的航空公司會出現
  SELECT c~carrid, c~carrname, p~connid, p~cityfrom, p~cityto
    FROM scarr AS c
    INNER JOIN spfli AS p ON p~carrid = c~carrid
    WHERE c~carrid IN @s_carr
    ORDER BY c~carrid, p~connid
    INTO TABLE @DATA(lt_inner).

  " ② Left Outer Join：沒有航線的航空公司也會出現，右表欄位為初始值
  "    左右順序有意義：畫面上放在左邊的表 = SQL 的左表
  SELECT c~carrid, c~carrname, p~connid, p~cityfrom, p~cityto
    FROM scarr AS c
    LEFT OUTER JOIN spfli AS p ON p~carrid = c~carrid
    WHERE c~carrid IN @s_carr
    ORDER BY c~carrid, p~connid
    INTO TABLE @DATA(lt_outer).

  " ③ 別名（Alias）：同一張表在一個 Join 只能出現一次，
  "    要用第二次就取別名——出發與抵達機場名稱都要讀 SAIRPORT
  SELECT p~carrid, p~connid,
         a1~name AS airport_from,
         a2~name AS airport_to
    FROM spfli AS p
    LEFT OUTER JOIN sairport AS a1 ON a1~id = p~airpfrom
    LEFT OUTER JOIN sairport AS a2 ON a2~id = p~airpto
    WHERE p~carrid IN @s_carr
    ORDER BY p~carrid, p~connid
    INTO TABLE @DATA(lt_airport).

  cl_demo_output=>write( lt_inner ).
  cl_demo_output=>write( lt_outer ).
  cl_demo_output=>display( lt_airport ).
HANA 沒有預設排序。報表工具產生的程式若沒有指定排序，清單順序在 HANA 上可能每次不同。上面每個 SELECT 都明寫 ORDER BY，就是 Casper 在成本評價案踩過的坑：H 與 E 兩種成本構成同時存在時，「取第一筆」的結果會漂移。用 SQVI／SQ01 也一樣：一定要在清單定義裡指定排序欄位，不要依賴「看起來有排好」。

3. 第二單元：QuickViewer 的資料來源、Join 規則與輸出方式

SQVI 的基本操作請看 1-4 章第 2 節，這裡補齊原廠課程強調的規則與限制：

  • 三步驟：定義資料來源 → 設計清單與選擇畫面 → 執行。不存檔也能直接執行。
  • 資料來源五選一：單一表格、Table Join、InfoSet（只能用標準區的）、DDIC 資料庫視圖、邏輯資料庫。選「表格」就只能用那一張，事後不能再加表。
  • 私人、不可複製、不可傳輸：每位使用者只看得到自己的 QuickView；因為不接傳輸系統，不需要 Z／Y 命名空間，名稱只限字母、連字號、底線。但可以轉成 SAP Query。
  • 執行方式：直接執行、帶變式執行、背景執行。
  • Join 定義是 QuickView 專屬，不能給別人重用（這點跟 DB View、InfoSet、邏輯資料庫不同）。系統會依 ABAP Dictionary（相同 Domain 的欄位）提出 Join 條件建議，可修改。
  • 每張表在一個 Join 只能出現一次，要重複用就取別名（Alias）。
  • 只能 Join 透明表，不能 Join Pool／Cluster Table。
  • 新加入的表預設是 Inner Join；要改成外連接，在連線上按右鍵選 Left Outer Join。拖放兩個欄位即可建立連線，右鍵 Delete Link 刪除。
S/4HANA 注意：原本在 ECC 是 Cluster／Pool 的表（例如 BSEG、KONV 所屬的 KOCLU）在 S/4HANA 已轉成透明表或被新表取代（定價條件改存 PRCD_ELEMENTS），所以「BSEG 不能 Join」這條限制在 S/4HANA 已不成立；但財務明細請優先用 ACDOCA（Universal Journal），不要再 Join BSEG。

基本模式（Basic Mode）畫面四區（依講義步驟整理）：左側資料來源欄位樹、左下操作說明、右上 QuickView 設定（標題、備註、輸出方式、清單欄位、排序、選擇欄位）、右下線上文件。右上用兩個 Table Control 操作：從右邊「可用欄位」傳到左邊「清單欄位」；游標放在清單欄位上按綠色＋會在該欄位前插入換行（多行清單），紅色－移除換行。排序頁籤與選擇欄位頁籤操作方式相同。

若沒有定義選擇畫面、或執行時選擇畫面全部空白，系統會跳出對話框要你輸入最大筆數。這不是 bug，是保護機制——在正式機上請老實設條件。

輸出方式分三大類：SAP 系統內輸出、直接轉到外部工具（Word、Excel）、直接存檔（本機檔案）。系統內最重要的三種：

輸出特性
SAP List Viewer（原名 ABAP List Viewer, ALV）最有彈性，QuickViewer 的預設值
Table（表格控制）以 Table Control 顯示，可排序、可再轉 ALV
List output（ABAP List）傳統清單，最適合階層式／多行清單；可儲存清單，之後在 SQVI 初始畫面直接開啟同一份資料，不必重新選取

執行時選擇畫面上方是 Program Selections（你定義的選擇欄位），下方可以臨時改選輸出方式，不必跟定義時一樣。選擇欄位可輸入多個單值或區間、也可排除；有多重選擇時箭頭由白變綠；右鍵可選比較運算子（Options）、刪行（Delete Lines）或全部清除。

4. 第二單元（續）：SAP List Viewer 操作與對應的 SALV 程式

原廠花了好幾頁講 ALV 的滑鼠與工具列操作（强晟筆記也吐槽「用文字說明操作確實難受」）。重點整理：

  • 左鍵：點欄標題選欄（Ctrl 可多選，再點一次取消）、點列選列、拖曳欄標題移動欄位、拖曳欄標題交界改欄寬。
  • 欄標題右鍵：隱藏欄位（Show 可再叫回）、最佳欄寬（Optimum Width）、設為最後固定欄（橫向捲動時左邊欄位不動）。
  • 工具列：Details 顯示游標所在列的全部欄位（含隱藏欄）；選欄後升冪／降冪排序，不選欄則跳出多層排序對話框，排序欄的標題會有紅色小三角；排序是小計的前提；數值欄可合計，標題出現Σ。
  • 小計五步驟：① 選要合計的數值欄 → ② 按 Σ（小計按鈕才會出現）→ ③ 簡單小計：選非數值欄 → ④ 按小計按鈕；⑤ 複雜小計：跳過第 ③ 步，在對話框左邊放排序欄、逐欄設升降冪與是否小計，用箭頭調整排序層級。
  • 列印與下載永遠處理整份清單，不是只處理畫面上看到的部分。
  • 欄位設定可存成版面配置（Layout），下次在選擇畫面直接選用。ALV 的所有功能只影響顯示、不影響資料選取。
  • 計數欄（Counter Field，Col18 新增）：ALV 欄位集合裡永遠有一個「筆數」欄，預設隱藏，用 Show 叫出來即可。

自己寫程式時，這些功能在 CL_SALV_TABLE 都有對應的 API（詳見 2-3 章）：

*&---------------------------------------------------------------*
*& 用 CL_SALV_TABLE 重現 QuickViewer 的 ALV 功能
*&---------------------------------------------------------------*
SELECT carrid, connid, fldate, seatsmax, seatsocc, paymentsum, currency
  FROM sflight
  WHERE carrid IN @s_carr
  ORDER BY carrid, connid, fldate
  INTO TABLE @DATA(lt_flight).

TRY.
    cl_salv_table=>factory( IMPORTING r_salv_table = DATA(lo_alv)
                            CHANGING  t_table      = lt_flight ).

    lo_alv->get_functions( )->set_all( abap_true ).      "完整工具列

    DATA(lo_cols) = lo_alv->get_columns( ).
    lo_cols->set_optimize( abap_true ).                   "＝右鍵「最佳欄寬」

    " 固定欄：＝右鍵「設為最後固定欄」
    lo_cols->set_key_fixation( abap_true ).
    CAST cl_salv_column_table( lo_cols->get_column( 'CARRID' ) )->set_key( abap_true ).
    CAST cl_salv_column_table( lo_cols->get_column( 'CONNID' ) )->set_key( abap_true ).

    " 排序＋小計：排序是小計的前提
    lo_alv->get_sorts( )->add_sort( columnname = 'CARRID' subtotal = abap_true ).
    lo_alv->get_sorts( )->add_sort( columnname = 'CONNID' ).

    " 合計（Σ）
    lo_alv->get_aggregations( )->add_aggregation(
      columnname  = 'SEATSOCC'
      aggregation = if_salv_c_aggregation=>total ).

    " 版面配置：允許使用者儲存、可設預設
    DATA(lo_layout) = lo_alv->get_layout( ).
    lo_layout->set_key( VALUE #( report = sy-repid ) ).
    lo_layout->set_save_restriction( if_salv_c_layout=>restrict_none ).
    lo_layout->set_default( abap_true ).

    lo_alv->display( ).
  CATCH cx_salv_msg cx_salv_not_found cx_salv_existing cx_salv_data_error INTO DATA(lx_salv).
    MESSAGE lx_salv->get_text( ) TYPE 'E'.
ENDTRY.
講義的「計數欄」在 SALV 對應 CL_SALV_COLUMNS_TABLE->SET_COUNT_COLUMN( )，前提是內表結構中真的有一個整數欄位當計數欄；若只是要看筆數，直接在 SELECT 用 COUNT(*) 或 lines( ) 更直接。

5. 第三單元第一課：SAP Query 的組織環境與基本原則

SAP Query 比 QuickViewer 多了一整套「組織」，目的就是讓你能按使用者分權：

  • 使用者必須屬於至少一個使用者群組（User Group）才能建立與執行 Query；一人可屬多個群組。
  • 使用者群組掛 InfoSet；InfoSet 決定 Query 能讀哪些表、哪些欄位；一個 InfoSet 可分配給多個群組。
  • InfoSet 的欄位再分成欄位群組（Field Group）方便瀏覽。
  • Query 永遠建在「某個使用者群組 ＋ 某個 InfoSet」底下；使用者可存取自己群組內的所有 Query。
  • 兩個查詢區（Query Area），4.0 版起：全域區（Global）跨 client、有物件目錄條目、自動接傳輸；標準區（Standard）依 client、不自動接傳輸。兩區互相獨立，同名物件可以在兩區代表不同東西。詳見 1-4 章第 4 節。

與 QuickViewer 的差別：SAP Query 的資料來源只能是 InfoSet（但 InfoSet 技術上可以包任意多張表或邏輯資料庫）；每個 Query 最多 1 個基本清單 ＋ 9 個統計 ＋ 9 個分級清單（講義另一處寫「1 個基本清單或 18 個彙總清單」，意思相同：統計與分級各 9 個，合計 18 個）；可在 InfoSet 選擇畫面之外再加選擇欄位；可串接多個清單。

起始畫面設定：SQ01（或 SQVI 初始畫面的 SAP Query 按鈕）→ Environment → Query Areas 切換查詢區；Edit → Change User Group 切換群組。常用的使用者參數（SU3／System → User Profile → Own Data）：

參數 ID值效果
AQWG預設進入全域區；空白 = 標準區（强晟：ECC 5.0 預設就是全域區，要用標準區才把 AQW 清空）
AQB使用者群組名預設使用者群組

產生的程式名：執行時內部報表產生器產生 AQ + mm + 群組 12 碼 + Query 14 碼，共 30 碼；mm 是編碼後的 client（標準區）或 ZZ（全域區），空白以「=」取代。查法：SQ01 → Query → More Functions → Display Report Name。强晟筆記把 Query 段寫成 pppp… 而說明卻寫 qqqq…，是筆誤；正確格式如下（全域區才能用這個規則算出名稱，標準區的 client 編碼請以系統顯示為準）：

*&---------------------------------------------------------------*
*& 依規則組出全域區 Query 的產生程式名，並確認它是否已產生
*&---------------------------------------------------------------*
PARAMETERS: p_ugrp  TYPE c LENGTH 12 OBLIGATORY,   "SQ03 使用者群組
            p_query TYPE c LENGTH 14 OBLIGATORY.   "SQ01 Query 名稱

START-OF-SELECTION.
  " WIDTH 保證補足固定長度；再把空白換成 '='
  DATA(lv_prog) = |AQZZ{ p_ugrp WIDTH = 12 }{ p_query WIDTH = 14 }|.
  lv_prog = translate( val = lv_prog from = ` ` to = `=` ).

  SELECT SINGLE name FROM trdir
    WHERE name = @lv_prog
    INTO @DATA(lv_found).

  IF sy-subrc = 0.
    MESSAGE |產生程式 { lv_prog } 已存在| TYPE 'S'.
  ELSE.
    " 尚未產生（或曾被重新產生刪除）：請先在 SQ01 執行一次
    MESSAGE |找不到 { lv_prog }，請先在 SQ01 執行一次讓系統產生| TYPE 'S' DISPLAY LIKE 'W'.
  ENDIF.
AQ 程式是「產生物」，InfoSet 重新產生、升級或 client 不同時都可能重建，不要把它當成穩定的程式名寫死在其他程式或 TCODE 裡。要掛 TCODE 請用 1-4 章第 10 節的 START_REPORT 參數交易。

6. 第三單元第二課：欄位選擇、區域欄位與附加選擇欄位

在 SQ01 選好 InfoSet（雙擊）後，就不能再換 InfoSet——因為資料讀取邏輯已經從 InfoSet 帶進 Query。接著依序經過四個畫面：

畫面做什麼必要性

區域欄位（Local Field）是 SAP Query 獨有的「只存在於這個 Query 的計算欄位」，等於對 InfoSet 的補強：

  • 先開短名稱：Edit → Short Names → Switch On/Off，替要參與計算的欄位取短名。以短名引用欄位本身（例如 FLDATE），以 &短名引用欄位內容（例如在頁首用 &FLDATE）。

  • 計算規則：一般四則運算式；按 Complex Calculation 可設多重條件，條件都不成立時取預設值。
  • 公式可用特殊欄位：%NAME（執行者）、%DATE（執行日期）、%TIME（執行時間）。强晟筆記寫成「%DATA」是筆誤，正確是 %DATE。

TYPES: BEGIN OF ty_out,
         carrid   TYPE s_carr_id,
         connid   TYPE s_conn_id,
         fldate   TYPE s_date,
         seatsmax TYPE s_seatsmax,
         seatsocc TYPE s_seatsocc,
         free     TYPE i,
         load     TYPE p LENGTH 5 DECIMALS 1,
         light    TYPE icon_d,
       END OF ty_out,
       tt_out TYPE STANDARD TABLE OF ty_out WITH EMPTY KEY.

DATA(lt_out) = VALUE tt_out(
  FOR ls IN lt_flight
  LET lv_load = COND decfloat34( WHEN ls-seatsmax > 0
                                 THEN ls-seatsocc * 100 / ls-seatsmax
                                 ELSE 0 )
  IN ( carrid   = ls-carrid
       connid   = ls-connid
       fldate   = ls-fldate
       seatsmax = ls-seatsmax
       seatsocc = ls-seatsocc
       free     = COND #( WHEN ls-seatsmax > 0 THEN ls-seatsmax - ls-seatsocc ELSE 0 )
       load     = lv_load
       light    = COND #( WHEN lv_load >= 90 THEN icon_red_light
                          WHEN lv_load >= 70 THEN icon_yellow_light
                          ELSE                    icon_green_light ) ) ).

附加選擇欄位（Selection Fields 畫面）的規則：

  • 先看 InfoSet 已經提供哪些選擇欄位，只把 InfoSet 沒有的欄位加成附加選擇。
  • 欄位若在 DDIC 設了 SET/GET 參數（Parameter ID），會自動帶入使用者上次輸入的值；不要的話可以在這裡關掉預帶。
  • 可自訂選擇畫面文字，不填就用標準文字。
  • 屬性 SV（Single Value）：畫面上只先給單值欄位（多重選擇仍可用）；1L（Single Line）：可輸入單值或一個區間，但不能多重選擇；SV＋1L：只能一個單值、無多重選擇。

7. 第三單元第二課（續）：Query Painter、控制層級與存到全域區

基本清單用圖形化的 Query Painter 設計，它就是 QuickViewer 的「版面模式（Layout Mode）」。畫面四區：左上欄位樹、右上清單版面、左下目前元素資訊、右下文件連結與格式警告。

  • 在左上勾選欄位，會自動加到目前這一行的尾端；版面上顯示的是從資料來源讀出的範例資料，讀不到就模擬值。多行階層清單會讀多筆範例。
  • 拖放可調整欄位順序；拖到垃圾桶即刪除（也可從垃圾桶拖回來）；拖邊框改輸出長度，或在左下直接填位置／長度再按 Apply。
  • 工具箱：拖表格圖示插入欄分隔線（紅叉刪除）；拖＋號在下方加一行；刪行時該行不能有欄位，把垃圾桶拖到該行上；拖顏色到欄位上改顏色。Tools → All Tools On/Off 可隱藏工具。
  • 雙擊行內空白處顯示行選項：依其他行存在才輸出、前後空行、換頁、印在頁首；點尺規可設清單寬度與框線。欄位選項：輸出長度、位置、編輯遮罩。

控制層級（Control Level）只在輸出格式為 ABAP List 時由 Query Painter 定義：把欄位拖到 Sort 工具成為排序欄、逐欄設升／降冪，決定層級結束時要不要印小計、改小計文字、層級前空行或換頁、層級表頭表尾文字。外幣金額合計時系統會自動依幣別分開合計。

合計溢位：合計值印在與欄位相同的欄位、相同輸出長度；數字變大放不下時，第一碼會出現星號 *。解法是把要合計欄位的輸出長度調大。

頁首頁尾（ABAP List 輸出才有）可用變數：

&%DATE日期
&%TIME時間
&%PAGE頁碼
控制層級也可以在執行時用 SAP List Viewer 做，而且更彈性：同一個 Query 定義可以做任意多種排序與小計組合，存成不同的 ALV 版面。實務上除非客戶一定要 ABAP List 的列印格式，否則把排序小計交給 ALV 版面，Query 定義保持單純。

存到全域區：第一次儲存全域區的 Query 物件會要求指定套件（Package，舊稱開發類），套件須在 SE80 建立並符合客戶命名空間（Z／Y 開頭）；選「本機物件」即 $TMP，就不會被傳輸。還要指定工作台請求（Workbench Request），由專案負責人在 SE09 建立請求與每位成員的工作（Task）。一個物件永遠只屬於一個套件，但不同時間可以屬於不同請求。標準區的物件不自動接傳輸，參見報表 RSAQR3TR 的說明（第 18 節）。套件與傳輸的基本觀念見 1-1 章。

自己寫程式時，「統計」就是 GROUP BY，「分級清單」就是 GROUP BY ＋ ORDER BY ＋ UP TO n ROWS。重點是：不同幣別不能直接加總，要先依幣別分組、換算成參考貨幣，再排名：

*&---------------------------------------------------------------*
*& 分級清單：營收最高的 10 條航線（參考貨幣 EUR）
*&---------------------------------------------------------------*
CONSTANTS gc_ref_curr TYPE s_currcode VALUE 'EUR'.

" ① 先依「鍵 + 幣別」彙總：統計（Statistics）的本質就是 GROUP BY
SELECT carrid, connid, currency,
       SUM( paymentsum ) AS revenue,
       SUM( seatsocc )   AS seats_occ,
       COUNT(*)          AS flights
  FROM sflight
  WHERE carrid IN @s_carr
  GROUP BY carrid, connid, currency
  ORDER BY carrid, connid, currency
  INTO TABLE @DATA(lt_stat).

" ② 換算成參考貨幣（對應講義「參考貨幣」設定）
TYPES: BEGIN OF ty_rank,
         carrid  TYPE s_carr_id,
         connid  TYPE s_conn_id,
         rev_ref TYPE s_sum,
       END OF ty_rank.
DATA lt_rank TYPE SORTED TABLE OF ty_rank WITH UNIQUE KEY carrid connid.
TYPES tt_rank_std TYPE STANDARD TABLE OF ty_rank WITH EMPTY KEY.   "SORTED 表不能改排序，排名時轉成 STANDARD

LOOP AT lt_stat INTO DATA(ls_stat).
  DATA(lv_ref) = CONV s_sum( ls_stat-revenue ).
  IF ls_stat-currency <> gc_ref_curr.
    CALL FUNCTION 'CONVERT_TO_FOREIGN_CURRENCY'
      EXPORTING
        date             = sy-datum
        foreign_currency = gc_ref_curr
        local_amount     = ls_stat-revenue
        local_currency   = ls_stat-currency
      IMPORTING
        foreign_amount   = lv_ref
      EXCEPTIONS
        OTHERS           = 1.
    IF sy-subrc <> 0.
      " 換算失敗：講義說系統會記錄並標色，這裡記下來另外列示
      MESSAGE |{ ls_stat-carrid } { ls_stat-connid } 幣別 { ls_stat-currency } 無匯率| TYPE 'I'.
      CONTINUE.
    ENDIF.
  ENDIF.
  " 同一航線可能有多種幣別：累加
  IF line_exists( lt_rank[ carrid = ls_stat-carrid connid = ls_stat-connid ] ).
    lt_rank[ carrid = ls_stat-carrid connid = ls_stat-connid ]-rev_ref =
      lt_rank[ carrid = ls_stat-carrid connid = ls_stat-connid ]-rev_ref + lv_ref.
  ELSE.
    INSERT VALUE #( carrid = ls_stat-carrid connid = ls_stat-connid rev_ref = lv_ref )
      INTO TABLE lt_rank.
  ENDIF.
ENDLOOP.

" ③ 排名：分級準則 = rev_ref 降冪（Top list）；同分再用鍵值排，確保結果穩定
DATA(lt_top) = CORRESPONDING tt_rank_std( lt_rank ).
SORT lt_top BY rev_ref DESCENDING carrid ASCENDING connid ASCENDING.
DELETE lt_top FROM 11.                                  "只留前 10 名
同分時的排序一定要補鍵值。「前 10 名」若第 10、11 名同分，沒有第二排序鍵時 HANA 每次可能回傳不同的那一筆——這就是 Casper 強調的「HANA 沒有預設排序」。SAP Query 的分級清單同樣有這個問題，對結果有爭議時請改用程式並明確排序。

9. 第三單元第四課：子清單組合、互動功能、RRI 與儲存清單

子清單組合（Sublist Combination）：一個 Query 要同時輸出多個清單（例如 1 個基本清單＋2 個統計＋1 個分級清單），輸出格式必須選 ABAP List；在 Title, Format 畫面用按鈕設定輸出順序。執行時各清單依序上下排列，用捲軸或 List Overview、Previous Section／Next Section 切換；互動功能作用在游標所在的那個子清單。

清單上的互動功能：List Overview（子清單可分別顯示、分別列印）、Selections（查看選擇畫面輸入值）、Drilldown（展開／收合）、Totaling、報表／報表介面（RRI）、Table display（4.6A 起多行清單可壓成一行以表格顯示）、存成展示伺服器檔案或私人儲存區、轉 Word／Excel、SAP 圖形、ABC 分析、EIS（Executive Information System）。

報表／報表介面（Report/Report Interface, RRI）：

  • 「報表」在這裡是上位詞，涵蓋 Query、ABAP 報表與交易碼。
  • 使用者在 Query 清單上雙擊一行 → 呼叫第二個 Query，系統把第一個 Query 的選擇畫面欄位與被雙擊那一行的所有欄位，填進第二個 Query 的（隱藏）選擇畫面，直接顯示結果。
  • 發送端與接收端欄位靠技術屬性（資料元素相同）對應；細節見 SAP Note 50629。
  • 一個 Query 可掛多個接收報表，雙擊時系統會問要呼叫哪一個。設定：SQ01 → Goto → Report Assignment → ＋號新增 → Enter 回總覽 → 存檔。

自己寫 SALV 時，RRI 就是「雙擊事件 ＋ SUBMIT 帶選擇條件」：

*&---------------------------------------------------------------*
*& 用 SALV 雙擊事件模擬 RRI：航線清單 → 雙擊 → 該航線的訂位清單
*&---------------------------------------------------------------*
CLASS lcl_rri DEFINITION FINAL.
  PUBLIC SECTION.
    METHODS constructor IMPORTING it_conn TYPE ty_conn_tab.
    METHODS on_double_click FOR EVENT double_click OF cl_salv_events_table
      IMPORTING row column.
  PRIVATE SECTION.
    DATA mt_conn TYPE ty_conn_tab.
ENDCLASS.

CLASS lcl_rri IMPLEMENTATION.
  METHOD constructor.
    mt_conn = it_conn.
  ENDMETHOD.

  METHOD on_double_click.
    DATA(ls_conn) = VALUE #( mt_conn[ row ] OPTIONAL ).
    IF ls_conn IS INITIAL.
      RETURN.
    ENDIF.
    " 發送端欄位 → 接收端選擇條件（講義：依資料元素相同自動對應）
    DATA(lt_sel) = VALUE rsparams_tt(
      ( selname = 'S_CARR' kind = 'S' sign = 'I' option = 'EQ' low = ls_conn-carrid )
      ( selname = 'S_CONN' kind = 'S' sign = 'I' option = 'EQ' low = ls_conn-connid ) ).
    SUBMIT zbc407_bookings WITH SELECTION-TABLE lt_sel AND RETURN.
  ENDMETHOD.
ENDCLASS.

" 掛上事件（lo_alv 為 CL_SALV_TABLE 實體，lt_conn 為航線清單）
DATA(lo_rri) = NEW lcl_rri( lt_conn ).
SET HANDLER lo_rri->on_double_click FOR lo_alv->get_event( ).
範例中的 ty_conn_tab、接收端報表 ZBC407_BOOKINGS（有 S_CARR、S_CONN 兩個 SELECT-OPTIONS）為示意名稱。注意這裡刻意用單值 EQ 傳遞條件，不是 BT 區間——符合「列舉比區間安全」的原則。

儲存清單（Saved Lists）：ABAP List 輸出的清單可以跟 Query 一起存（List → Save），系統自動記錄日期時間。再次開啟不讀資料庫，比重跑快得多；大多數互動功能仍可用（ALV、下載），但 RRI 不能用。從 SQ01 → Goto → Saved Lists 開啟；在儲存的清單裡按 Selections 可看當時的選擇條件。若 Query 被放進角色（PFCG），所有儲存清單會自動帶到角色，從右鍵選單開啟。

10. 第四單元：InfoSet Query——從角色出發的即席報表

InfoSet Query 與 SAP Query 共用 InfoSet、使用者群組、查詢區，差別在「怎麼把使用者接進來」與「介面」：

  • 使用者不直接放進使用者群組，而是透過角色（Role）。一個人可以有多個角色，但每個角色只能掛一個使用者群組。强晟筆記把這句譯成「每個人可以有多個角色但只能有一個用戶組」是誤譯，以原廠原文為準。
  • 可從角色選單、SAP 選單或 SQ01 啟動；依角色設定，系統會拿一個既有 Query 當範本、或只提供一個 InfoSet 讓你新建。Extras → Template Information 可查目前的 InfoSet 與 Query 名。
  • 畫面三區：左上 InfoSet 欄位樹（勾選 = 放進清單或選擇畫面，也可拖放）、右上選擇畫面、下方以 ALV 呈現的結構與輸出預覽。
  • 欄位樹有三種顯示：欄位群組樹（預設，若 InfoSet 有選擇畫面，其欄位列在最上面）、欄位目錄（不分群組）、邏輯資料庫結構（InfoSet 基於 LDB 時）。
  • 圖示帶 T 的欄位有自動文字辨識（例如航空公司代碼自動帶出名稱），右鍵可選只要值、只要文字或兩者都要；用勾選方式加入則套用預設值。右鍵也可看欄位技術資訊。

下方預覽區的兩個用途：① 用 ALV 功能決定版面（拖放欄位順序、設定值／文字），這些版面設定會延續到其他輸出格式（例如傳統清單）；② 預覽——按 Refresh Data 才真的依選擇條件讀資料庫，第一次刷新前看到的是假的範例資料。另兩個重要按鈕：Delete（選欄刪欄；沒選欄會刪整張清單）、Initialize Formatting（取消排序合計、恢復預設欄寬）。

選擇畫面：跟標準選擇畫面不同，只有一個輸入欄、沒有區間，要輸入區間得開 Multiple Selection。欄位多半是 SELECT-OPTIONS；若是 InfoSet 定義成 PARAMETERS 的單值欄位，Option 按鈕不會啟用。沒填任何條件就執行，系統會要求限制筆數。

清單類型與設定（Edit → Settings，或預覽區的 Basic List／Statistics／Ranked List 按鈕）：

  • 一個 InfoSet Query 只能選基本清單、統計、分級清單其中一種，不能組合（這是跟 SAP Query 最大的差別）。
  • Statistics/Ranked List 頁籤指定參考貨幣與參考單位、分級清單的筆數；可加計數器，但InfoSet 基於邏輯資料庫時沒有這個勾選框。
  • 統計可在 ALV 欄位右鍵加上 Output Mean Value、Output Proportion in %、Output Total Number。
  • 分級清單：在 ALV 選一個數值欄（即分級準則）後按排序——降冪產生 Top list（最高值在前），升冪產生 Flop list（最低值在前）。强晟筆記把這段寫成「值小於／大於標準的項目」，語意不清，以原廠「Top／Flop list」為準。分級清單至少要選一個數值欄輸出。
  • Output 頁籤的輸出方式（預設 ALV，也可 ABAP List）只在全螢幕執行時生效；可設定全螢幕執行時要不要顯示選擇畫面。Default: Value/Text 頁籤決定帶 T 欄位預設顯示值或文字；「值與文字同時顯示」只能在欄位右鍵個別設定。
不要用 InfoSet Query 去編輯含有下列特性的 SAP Query：多個清單、多行基本清單、區域欄位。InfoSet Query 只會顯示單行、無區域欄位的清單，一旦覆蓋存檔，SAP Query 的這些特性就永久遺失。

13. 第六單元（續）：事件概念與邏輯資料庫（LDB）

可執行程式（類型 1）的流程由執行環境依事件控制。與 Query 有關的事件只有：AT SELECTION-SCREEN、START-OF-SELECTION、GET／GET LATE、END-OF-SELECTION（Col18 另外補充 InfoSet 可用 INITIALIZATION 與 AT SELECTION-SCREEN OUTPUT，見第 14 節）。事件區塊由事件關鍵字開始，碰到下一個事件關鍵字、程式結尾或副程式定義就結束。

  • START-OF-SELECTION 是標準事件：沒放在任何事件區塊裡的敘述都自動歸它；用來輸出清單開頭文字、讀資料、寫清單。
  • GET <node>：只有程式屬性掛了邏輯資料庫才能用；LDB 依階層逐筆把資料交給程式，一個 GET 通常執行很多次。
  • GET <node> LATE：該階層處理完後觸發，適合輸出該層的合計或平均（在 GET 中累計）。
  • END-OF-SELECTION：所有 GET 都處理完後觸發，之後才顯示清單；可輸出結尾文字或為互動報表初始化變數。

邏輯資料庫（Logical Database, LDB）是一支專門讀資料、再提供給其他程式的 ABAP 程式，階層結構決定交付順序；它也提供選擇畫面、檢查輸入與錯誤對話——只有用到的表對應的那部分選擇畫面會出現。維護用 SE36（Logical Database Builder），Help → Application Help 有說明。R/3 4.6C 約有 200 個 LDB。BC4xx 課程用 F1S：SPFLI（航線）→ SFLIGHT（航班）→ SBOOK（訂位）。

LDB 的特殊規則：用 LDB 就不必自己寫 SELECT；但程式另外加的 SELECT-OPTIONS，LDB 無法轉成 WHERE 條件（它的 SELECT 早就寫死了），使用者卻會以為有過濾——所以必須在對應表的 GET 事件第一行寫 CHECK <選擇表> 自己過濾。若 LDB 對該表提供了「動態選擇（Free Selections）」，而你的 SELECT-OPTIONS FOR 的正是那張表的欄位，就不必再 CHECK。

教材修正：Col18 講義此處寫「use the ABAP command CHECK <node>」，這是錯的——CHECK 後面接的是選擇表（CHECK SELECT-OPTIONS／CHECK seltab），不是 LDB 節點；强晟 2007 版寫「CHECK <seltab>」才是正確的。
S/4HANA 現況：邏輯資料庫已被 SAP 列為過時技術，ABAP 關鍵字文件明言新開發不應再使用，ABAP Cloud 中完全不可用。S/4HANA 裡 HR 的 PNP／PNPCE 等 LDB 仍在運作，舊程式照跑；但新的 InfoSet 請用 Table Join 或 DDIC/CDS View 當資料來源，新程式用 ABAP SQL Join 或 CDS View 取代 GET 事件。

16. 第八單元：使用者群組、角色與 InfoSet Query 選單

  • SQ03 建使用者群組（SAP 命名空間 /SAPQUERY/），指定屬於標準區或全域區，並把 InfoSet 分配給群組；一個 InfoSet 可給多個群組。
  • SAP Query：在 SQ03 直接把使用者加進群組。使用者可執行群組內所有 Query；權限夠的話可新建或修改。群組內可針對個別使用者取消「變更」勾選，即使他有 S_QUERY 變更權限，在這個群組也不能改。
  • InfoSet Query：整合在角色概念裡。PFCG → 角色 → Personalization 頁籤 → 雙擊「Assign User Group to SAP Query」→ 輸入群組名與查詢區。一個角色只能掛一個使用者群組；不必把使用者加進群組，角色裡的使用者就自動屬於該群組。

  2. 在 ABAP Workbench 建立專用的報表交易（Report Transaction）呼叫產生的程式——只有全域區的 Query 可以，因為交易碼一定是跨 client 的；使用者需要該交易的 S_TCODE 權限。

18. 第九單元：傳輸 Query 元件（AQLDB／AQGDB／AQTDB）

要懂 Query 的傳輸，先懂它存在哪裡：

表內容傳輸方式
AQLDB標準區物件（依 client）不自動接傳輸；用 RSAQR3TR 匯出／匯入或複製到全域區
AQGDB全域區物件（跨 client）屬於套件，由傳輸組織器（SE09）傳輸
AQTDB傳輸資料集（匯出暫存）匯出時寫入並掛上傳輸請求，目標系統再匯入
教材修正：强晟筆記 p142 有一處把 AQTDB 打成「AQTAB」，正確是 AQTDB。

全域區物件因為屬於某個套件而自動接傳輸；彼此有相依性的 Query 元件（群組、InfoSet、Query）應放同一個請求一起傳。以變更請求組織開發專案的好處：全員同一時間起跑、每人可追蹤自己的工作（Task）、專案外的開發者在專案結束前無法修改被鎖定的物件、所有相關物件一起觸發傳輸。

RSAQR3TR 的動作（在任一 SQxx 初始畫面按 Transports，或直接 SA38 執行 RSAQR3TR）：

  • Export：在 AQTDB 建立傳輸資料集（並掛傳輸請求）。
  • Import：從 AQTDB 讀入傳輸資料集。
  • Display／Delete：顯示／刪除 AQTDB 中的傳輸資料集。
  • Copy Standard Area → Global Area：AQLDB → AQGDB。
  • Copy Global Area → Standard Area：AQGDB → AQLDB。

把標準區物件搬到另一個 client／系統的標準區，有兩條路：① 匯出到 AQTDB（連同傳輸請求）→ 目標端從 AQTDB 匯入；② 先複製到全域區（等同標準區匯出＋全域區匯入），隨傳輸到目標系統，再從全域區複製回目標 client 的標準區。複製到全域區時的套件規則：覆蓋既有物件 → 沿用被覆蓋物件的套件；全新物件 → 跳窗要求指定套件。

實務建議：要上正式機的 Query 一律建在全域區（配合 1-4 章的查詢區說明），標準區只給使用者在 PRD 自己做臨時報表。這樣就不必每次跑 RSAQR3TR 手動搬運，也不會出現 DEV 與 PRD 版本對不起來的問題。

19. 第十單元：套件、變式與背景執行

TCODE 速查（原廠 Table 14）：SQVI QuickViewer、SQ01 Queries、SQ02 InfoSets、SQ03 User Groups、PFCG 角色維護、SE09 傳輸組織器、SE36 邏輯資料庫建構器、SM36 定義作業、SE80 Object Navigator。

建立套件（SE80 → 左側選 Package → 輸入名稱 → 不存在時確認建立）要確認的屬性：Transport Layer（客戶開發須有客戶用的傳輸層）、Person Responsible（預設為自己）、Software Component（客戶開發通常填 HOME）、Application Component（決定在應用階層中的業務歸屬，之後可在 SE81 找到）。存檔時要指定變更請求，做法同儲存全域區 Query 物件。詳見 1-1 章。

變式（Variant）：

  • 把選擇條件存起來，不用每次重填；背景執行 Query 必須指定變式。
  • 變式只能建在選擇畫面上，不能在 InfoSet Query 的選擇畫面控制項裡建；要讓 InfoSet Query 用變式，請用 Output 或在 SQ01 執行。
  • 屬性：名稱與說明必填；預設可線上與背景共用，也可設「只限背景」；可保護整個變式或個別欄位；「只在目錄顯示」則不出現在 F4 清單；欄位類型 S = SELECT-OPTIONS、P = PARAMETERS；「保護欄位」不可輸入、「隱藏」可縮短選擇畫面。
  • 選擇變數（Selection Variable）三種動態取值：T 從表 TVARV 取值、D 動態日期計算（例如今天、上月第一天）、以及用 MEMORY ID 定義的使用者參數值。
TVARV 已過時：講義提到的 TVARV 是不分 client 的舊表，現在請用依 client 的 TVARVC（以 STVARV 維護）。變式的 T 類型選擇變數在新系統中讀的就是 TVARVC。

背景處理：資料量大、執行時間長的程式應放背景跑。背景作業由專用的背景工作程序執行，不佔對話程序，可與線上作業平行。流程：定義作業（SM36：名稱、優先等級／作業類別、目標主機）→ 定義步驟（程式＋變式、列印參數：存 Spool 或直接列印）→ 設定開始時間 → 儲存即釋放（Release）→ 用 SM37 看狀態。Query 最簡單的做法是在 SQ01 初始畫面按 Execute in Background；QuickView 也可從 SQVI 初始畫面排背景。也可用函數群組 BTCH、BTC2 的函數自動排程（更多背景作業細節見 4-4 章）：

先標準、再客製：Casper 的升級順序在報表上一樣適用——先找標準報表與標準 released CDS View → 用 Query／Custom Analytical Query 這類設定型工具 → 最後才寫 Z 程式。每往右一步，維護成本高一個量級。

練習與自我檢核

  1. QuickViewer 可以讓同事也使用嗎？要怎麼讓它可傳輸？
    參考答案要點：不行，QuickView 是使用者私有、不可複製、不接傳輸（所以不需 Z 命名空間）。可轉成 SAP Query，放在全域區並指定套件與傳輸請求。
  2. SQVI 用 SCARR 左外連接 SPFLI，結果比 Inner Join 多了哪些資料？表的左右順序重要嗎？
    參考答案要點：多出沒有任何航線的航空公司（SPFLI 欄位為初始值）；重要，畫面左側的表是 SQL 的左表。
  3. 一個 SAP Query 最多可以有幾個清單？InfoSet Query 呢？
    參考答案要點：SAP Query 最多 1 基本＋9 統計＋9 分級，要組合多清單須用 ABAP List 輸出；InfoSet Query 只能三選一。
  4. 全域區 Query「ZFLIGHT」群組、Query「ZQ_SEATS」產生的程式名為何？為什麼不建議把它直接掛 TCODE？
    參考答案要點：AQZZ ＋ 「ZFLIGHT=====」＋「ZQ_SEATS======」共 30 碼；AQ 程式是產生物，會被重建，應改用 START_REPORT 參數交易。
  5. 區域欄位與 InfoSet 附加欄位差在哪？
    參考答案要點：區域欄位只存在於單一 SAP Query、用公式與條件定義、需短名與欄位群組、InfoSet Query 不支援；附加欄位定義在 InfoSet、以 ABAP 程式碼賦值，所有使用該 InfoSet 的 Query 都能用。
  6. 頁首要印出執行者與頁碼，用哪些變數？公式中要用執行日期，用哪個特殊欄位？
    參考答案要點：&%NAME、&%PAGE（另有 &%DATE、&%TIME）；公式用 %DATE（强晟筆記的 %DATA 是筆誤）。
  7. 分級清單要列出「空位最少的 5 班」，在 InfoSet Query 怎麼設？寫程式時要注意什麼？
    參考答案要點：Settings → Output 選 Ranked List，Statistics/Ranked List 頁籤設筆數 5，ALV 選空位欄按升冪（Flop list）；程式要 ORDER BY 空位 ASCENDING 並補鍵值作第二排序，否則同分時 HANA 結果不穩定。
  8. RRI 的欄位是怎麼從發送端傳到接收端的？儲存的清單可以用 RRI 嗎？
    參考答案要點：依資料元素相同自動對應選擇畫面欄位（SAP Note 50629），設定在 SQ01 Goto → Report Assignment；儲存清單不能用 RRI。
  9. InfoSet 基於邏輯資料庫 F1S，你另外加了 SELECT-OPTIONS 過濾 SBOOK-CUSTOMID，為什麼使用者輸入後沒效果？怎麼修？
    參考答案要點：LDB 的 SELECT 已寫死，無法把額外選擇轉成 WHERE；須在 GET sbook 第一行 CHECK 該選擇表（除非 LDB 對該表提供 Free Selections）。長期解法是改 Table Join 或 CDS View。
  10. InfoSet 的 PARAMETERS 選擇欄位為什麼原廠不建議拿來當資料條件？
    參考答案要點：PARAMETERS 不會被轉進 WHERE，必須自己在程式碼中檢查；適合用於流程控制。
  11. 業務使用者只要執行 Query、不准改定義，要怎麼給權限？
    參考答案要點：放進使用者群組但不給 S_QUERY（或用報表交易／角色選單直接執行，需 S_TCODE），並讓他用 SQ00；要在 InfoSet 寫 ABAP 的人才需要 S_DEVELOP（PROG、AQ*）。
  12. S_QUERY 的 ACTVT 02、23、67 各代表什麼？02＋23 呢？
    參考答案要點：02 建立／變更 Query；23 維護使用者群組與 InfoSet；67 翻譯；02＋23 為超級使用者。
  13. 標準區的 Query 要搬到 PRD 的同一 client，有哪兩種做法？對應哪些表？
    參考答案要點：RSAQR3TR 匯出到 AQTDB（掛傳輸請求）再匯入；或複製到全域區（AQLDB → AQGDB）隨傳輸過去再複製回標準區。
  14. 稽核要求記錄誰查過 HR 薪資 Query，怎麼做？
    參考答案要點：SQ02 → Extras 把 InfoSet 接上日誌，寫入 AQPROT（查詢區、InfoSet、使用者、時間、選擇值、輸出欄位）；Customizing 維護 AQPROTCUST；SQ02 → Extras → Manage Logs 清理。
  15. 要讓 Query 每天早上 7 點自動跑，選擇條件的日期要是「昨天」，怎麼設？
    參考答案要點：建變式，日期欄用 D 類型選擇變數（動態日期）；SQ01 Execute in Background 或 SM36 排程（或 JOB_OPEN／SUBMIT VIA JOB／JOB_CLOSE），SM37 監控；固定值改放 TVARVC（T 類型）而非舊的 TVARV。
  16. S/4HANA 專案上，哪些情況應該用 CDS View 取代 InfoSet？
    參考答案要點：需要業務層級權限（DCL）、要給 Fiori／Excel／BI 使用、資料量大需要下推 HANA、要進 ABAP Cloud；InfoSet 若 Join 舊表（BSEG、MSEG、KONV）也應改寫。
