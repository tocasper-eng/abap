第 1-4 章 不寫程式的報表開發：SQVI QuickViewer / SQ01 SQ02 SQ03 InfoSet Query / SQ99

這一章的教學重點只有一句話：在不寫一行程式的狀況下，完成二階（多表聯結）報表的查詢。你會學到 SQVI 快速檢視器（三分鐘出報表、但只屬於你自己），以及 SQ03 使用者群組 → SQ02 InfoSet → SQ01 Query 這套「三件套」的正確建立順序、資料來源怎麼選、附加欄位怎麼補、產生出來的 AQ 程式名怎麼解碼、怎麼掛成 TCODE、怎麼傳輸到 QAS/PRD，最後是什麼時候該放棄 Query 直接寫 ABAP，以及 S/4HANA 時代改用 CDS View ＋ Fiori Embedded Analytics 的時機。老師說這門課三小時可以教完，但它能幫你擋掉一半以上的臨時報表需求。

1. 三層工具的定位：SE16H → SQVI → SAP Query → 自己寫程式

使用者丟一個報表需求過來，先問自己「非得寫程式不可嗎？」。SAP 給了一整排不寫程式的工具，成本由低到高排序如下：

層級工具能做什麼不能做什麼
0SE16N / SE16H單表瀏覽；SE16H 在 HANA 上可做群組加總、排序、甚至多表聯結沒有固定版面、不能給一般使用者當正式報表、不易掛 TCODE
1SQVI QuickViewer個人用的多表聯結報表，ALV 輸出，五分鐘完成只屬於建立者本人、無法傳輸、無法給別人執行
2SQ03＋SQ02＋SQ01 SAP Query可分享、可授權、可掛 TCODE、可傳輸；支援附加欄位與 ABAP 程式碼區段複雜邏輯、效能調校、單元測試、對外介面都很吃力
3SE38 自己寫 ABAP什麼都能做成本最高，要走完整開發與傳輸流程
3+CDS View ＋ Fiori（S/4HANA）可重用、可 OData 曝露、可進 Analytical List Page／Embedded Analytics需要 Eclipse ADT 與較完整的建模概念
老師的三小時總結：「教學重點：在不寫程式的狀況下，完成二階報表的查詢。」所謂「二階」就是主檔＋子檔兩張表聯結，例如 KNA1＋KNB1、VBAK＋KNA1、VBAP＋QALS。這正是 90% 臨時報表需求的形狀。
講義建議的練習命名原則（把同一個需求用六種工具做一遍，名字就看得出來是誰做的）：
SE16H → ZERP###H；SQVI → ZERP###V；SQ03 使用者群組 → ZERP###U；SQ02 InfoSet → ZERP###I；SQ01 Query → ZERP###Q；SE38＋TCODE → ZERP###P；START_REPORT 參數交易 → ZERP###A。

2. SQVI QuickViewer：最快的個人報表（但不可傳輸）

SQVI 是 SAP Query 的「單人簡化版」。它不需要使用者群組、不需要 InfoSet，一個畫面內就把「選哪些表、怎麼聯結、要哪些欄位、要哪些選擇條件」全部做完。（依講義步驟整理）

  1. 進入 SQVI，輸入 QuickView 名稱（最長 14 碼，建議 ZERP###V），按「建立」。
  2. 輸入抬頭說明（Title）、備註，選擇資料來源：
    • 表格（Table）：只查一張表，最單純。
    • 表格聯結（Table join）：多表聯結，二階報表就選這個。
    • 邏輯資料庫（Logical database）：沿用 SAP 標準的取數樹（含權限檢查）。
    • InfoSet：直接沿用 SQ02 已經做好的 InfoSet。
  3. 選擇「表格聯結」後進入 Join 畫面，按「插入表格」加入第二張表；SAP 會依外鍵自動連線，務必檢查自動連上的欄位是否正確，多餘的連線用滑鼠右鍵刪除。
  4. 回到基本清單（Basis mode）畫面，左邊是欄位群組樹，勾選 清單欄位（List fields） 與 選擇欄位（Selection fields）。
  5. 存檔後按 執行（F8），出現選擇畫面 → 再 F8 → ALV 報表。
SQVI 的三個硬限制，一定要先跟使用者講清楚：
1. QuickView 是使用者私有的，別人登入看不到，也不能執行。
2. 無法掛傳輸請求，DEV 做好不會自己跑到 QAS／PRD；老師的說法是「一般是不傳輸，直接就地使用」。
3. 不支援附加欄位的 ABAP 程式碼區段（那是 SQ02 InfoSet 才有的功能）。
要正式化，就在 SQ01 用「Query → 由 QuickView 轉換（Convert QuickView）」把它升級成 Query，之後才有使用者群組、授權與傳輸。
SQVI 的定位是「可取代 SQ01/SQ02/SQ03 的個人版」。自己查資料、驗證 Join 是否正確時用 SQVI 最快；確定邏輯 OK 再花時間做成 Query。

講義第 11 節的實作是 SQVI 品質檢驗：把 VBAP（銷售訂單行項目）與 QALS（檢驗批記錄）聯結，做出「待出貨訂單對應成品檢驗狀態」的清單。Join 條件通常走物料與工廠（VBAP-MATNR = QALS-MATNR、VBAP-WERKS = QALS-WERK），必要時再加交貨單（QALS 的檢驗批來源可為交貨 LIKP/LIPS）。（依講義步驟整理）

3. SQ03 使用者群組：三件套的第一步

SAP Query 的建立順序是固定的，講義特別提醒：「設計之前，要先將 INFOSET、USER_GROUP 指定正確。」

順序TCODE物件做什麼
1SQ03使用者群組 User Group決定「誰可以用這組報表」，並把 InfoSet 掛進來
2SQ02InfoSet決定「資料從哪來、有哪些欄位」（Join／LDB／程式）
3SQ01Query 查詢決定「報表長什麼樣子」（選擇欄位、輸出欄位、小計、排序）
4SQ00執行SQ00 與 SQ01 畫面幾乎一樣，SQ00 定位是「執行」、SQ01 是「維護」

SQ03 建立步驟（依講義步驟整理）：

  1. 進 SQ03，先看畫面上方的查詢區（Query Area）是不是你要的（見下一節），必要時用「環境 → 查詢區」切換。
  2. 輸入使用者群組名稱（講義用 ZCERPS、ZVBAP_QALS、ZVBAK_KNA1、Z000），按「建立」，輸入說明文字後存檔。
  3. 按 「指定使用者與 InfoSet」：
    • 指定使用者：把要執行報表的 SAP 帳號加進來。有勾「Change authorization」的人才能改 Query。
    • 指定 InfoSet：把 SQ02 做好的 InfoSet 打勾掛進這個群組（InfoSet 還沒建時先跳過，建完再回來掛）。
講義的三個實作使用者群組：ZCERPS（對應 Query QUE_KNV1）、ZVBAP_QALS（出貨檢驗）、ZVBAK_KNA1 / Z000（訂單主檔，對應 Query QUE_VBAK_KNA1）。

4. 查詢區 Standard Area 與 Global Area：能不能傳輸的關鍵

SAP Query 的所有物件（使用者群組、InfoSet、Query）都存在某個查詢區裡，這決定了它的可見範圍與傳輸方式。講義第 01-3 節的「AREA 群組範圍」講的就是這件事。

查詢區代碼範圍傳輸方式
標準區 Standard Area（空白）依 Client 分離，只在建立它的 client 看得到；不屬於任何 Package不會自動進傳輸請求，要用程式 RSAQR3TR 匯出／匯入
全域區 Global AreaG跨 Client，整個系統共用屬於 Package、可掛傳輸請求，像一般開發物件一樣走 STMS
要讓報表跟著傳輸走，就把使用者群組／InfoSet／Query 建在全域區。這也是為什麼講義的 START_REPORT 參數裡，使用者群組後面第 13 碼是一個 G：那個 G 就是在告訴系統「這個 Query 在全域區」。

如何切換查詢區：在 SQ01／SQ02／SQ03 任一畫面，選單「環境（Environment） → 查詢區（Query Areas）」，選「標準區」或「全域區」。切錯區最典型的症狀是「明明建好了卻在清單裡找不到」。

SU01 參數 AQW（講義 10-1）：在 SU01（或使用者自己用 SU3）的「參數」頁籤加一筆參數 ID AQW，就能指定該使用者預設進入的查詢區；填 G 代表預設進全域區。講義的說法是「maintain AQW parameter in SU01 for required user ID and SAVE，This will enable that particular User to see all ABAP Queries」——實際效果是讓該使用者一登入 SQ01 就看到全域區的 Query，不必每次手動切換。

標準區的 Query 是 client-specific：你在 DEV 100 建的，DEV 200 看不到，PRD 更看不到。實務上很多「報表不見了」的求救單，答案都是查詢區或 client 不對。跨系統搬運標準區 Query 要跑 RSAQR3TR（SE38 執行，選 Export／Import，會產生 transport dataset）。

5. SQ02 InfoSet：資料來源怎麼選

InfoSet 是三件套裡最重要、也最需要動腦的一層。它回答兩個問題：資料從哪裡來、使用者可以看到哪些欄位。

建立 InfoSet 時，SAP 會要你四選一：

資料來源說明什麼時候用
表格聯結 Table join over table自己拉 DDIC 表格做 Join（可設 inner／left outer join）最常用。二階報表、主檔＋子檔都走這個
邏輯資料庫 Logical database沿用 SAP 標準的取數程式樹（例如 SD 的 VAV、MM 的 MEPOLDB、HR 的 PNP），自帶選擇畫面與權限檢查需要標準權限檢查、或資料結構是階層式（抬頭→項目→排程行）時
使用程式讀取的表格 Table + read program指定一張表，再自己寫取數程式填值資料要先加工才進表的情況
資料檢索程式 Data retrieval program（Sequential dataset）完全自己寫 ABAP 取數，把資料丟進定義好的結構來源是檔案、外部系統、或邏輯太複雜時

SQ02 建立步驟（依講義步驟整理）：

  1. 進 SQ02，確認查詢區，輸入 InfoSet 名稱（講義：ZKNA1_KNB1、ZVBAP_QALS、ZVBAK_KNA1），按「建立」。
  2. 輸入說明文字，選「表格聯結」並填第一張表（主表），Enter。
  3. 在 Join 畫面按「插入表格」加入第二張表；SAP 依外鍵自動畫連線，手動核對每一條連線；按右鍵可切換 Inner／Left Outer Join。
  4. 回上一頁時，SAP 問「欄位群組（Field Groups）」要怎麼建，通常選 「每個表格一個欄位群組，只含清單欄位／關鍵欄位」 或「包含所有表格欄位」。欄位群組決定使用者在 SQ01 看到的欄位分類。
  5. 把需要的欄位從右邊的表格樹拖進左邊的欄位群組（沒有拖進去的欄位，SQ01 就選不到）。
  6. 存檔 → 產生（Generate，Ctrl+F3）。沒有按產生，Query 端不會看到你的修改。
  7. 按「角色／使用者群組指派」，把這個 InfoSet 掛給 SQ03 建好的使用者群組。
口訣：「InfoSet 改完一定要 Generate；Generate 完一定要回頭看 Query 有沒有壞掉。」InfoSet 改欄位群組或刪欄位，會讓已經在用該欄位的 Query 出現「欄位不存在」的錯誤。

講義的三個 InfoSet 實作：

  • ZKNA1_KNB1（02-1）：客戶一般資料 KNA1 ＋ 公司代碼資料 KNB1，Join 條件 KNA1-KUNNR = KNB1-KUNNR。用來查「客戶編號與帳號（統馭科目 AKONT）關聯」。
  • ZVBAP_QALS（02-2）：銷售訂單行項目 VBAP ＋ 檢驗批 QALS，用來查「待出貨訂單與成品檢驗」。
  • ZVBAK_KNA1（02-3）：銷售訂單抬頭 VBAK ＋ 客戶主檔 KNA1，Join 條件 VBAK-KUNNR = KNA1-KUNNR，即「訂單主檔＋客戶名稱」。

6. Join 的陷阱：Inner Join、Left Outer Join 與效能

InfoSet 的 Join 就是 ABAP SQL 的 Join，所有 SQL 的坑它一個都不會少。以下三個是最常踩的。

坑一：該用 Left Outer 卻用了 Inner，資料整批消失。例如 VBAP ＋ QALS，如果某些訂單行項目還沒有檢驗批，Inner Join 會把它們整批濾掉，使用者就會說「我的訂單少了一半」。

" 用 ABAP SQL 表達 InfoSet 裡那條 Join：VBAP + QALS（出貨檢驗）
" Left Outer Join：沒有檢驗批的訂單行項目也要留下來
SELECT a~vbeln,
       a~posnr,
       a~matnr,
       a~werks,
       a~kwmeng,
       a~vrkme,
       b~prueflos,          " 檢驗批號
       b~herkunft,          " 檢驗批來源（01 進料、03 生產、04 交貨…）
       b~stat34,            " 使用決策已作成
       b~lmengezu           " 允收數量
  FROM vbap AS a
  LEFT OUTER JOIN qals AS b
    ON  b~matnr = a~matnr
    AND b~werk  = a~werks
 WHERE a~vbeln IN @s_vbeln
   AND a~matnr IN @s_matnr
  INTO TABLE @DATA(lt_out).

IF lt_out IS INITIAL.
  MESSAGE '查無資料' TYPE 'S' DISPLAY LIKE 'W'.
  RETURN.
ENDIF.
Left Outer Join 的 WHERE 條件位置很關鍵。如果把「b~stat34 = 'X'」寫在 WHERE，Left Outer 會退化成 Inner Join（因為 NULL 不符合條件）；要保留左表全部資料，條件必須寫在 ON 子句裡。SQ02 的 Join 畫面沒有辦法漂亮地表達這件事，這正是 Query 做不下去、該改寫 ABAP 的訊號之一。

坑二：Join 太多張表，HANA 上照樣慢。InfoSet 裡拉五、六張表很容易，但每多一張表就是一次 Join。實務建議：主表加 1～2 張參照表就好，文字（MAKT、T001W 之類）盡量用「附加表格」在 RECORD PROCESSING 裡單筆讀，或改用有內建文字的 CDS View。

坑三：沒有給有索引的選擇欄位。Query 的選擇畫面是使用者自己填的，如果沒有把 MANDT 以外的主鍵／索引欄位放進選擇欄位，使用者就會用一個沒有索引的欄位掃全表。做 InfoSet 時，一定要把主表的關鍵欄位（VBELN、MATNR、KUNNR、WERKS、日期）都放進欄位群組。

7. 附加欄位 Additional Field 與 InfoSet 的 ABAP 程式碼區段

InfoSet 比 SQVI 強大的地方，就在於它可以加欄位、寫程式。在 SQ02 的 Join／欄位畫面，選單「附加項（Extras）」可以新增三種東西：

類型用途要不要寫程式
附加欄位 Additional Field自己算出來的欄位：金額換算、天數差、狀態中文化、單價 = 金額 / 數量要，寫在該欄位的 Code 區
附加表格 Additional Table用目前這筆資料的鍵值去讀另一張表（例如用 MATNR 讀 MAKT 取品名）不用，指定表名即可，系統自動做 SELECT SINGLE
附加結構 Additional Structure把一組附加欄位包成一個結構，方便管理依內含欄位而定

新增附加欄位的步驟（依講義步驟整理）：Extras → 建立 → 選「附加欄位」→ 輸入欄位名稱（建議 Z 開頭）→ 指定長度、輸出長度、資料型態（或直接「Like 參考欄位」指向某個 DDIC 欄位）→ 輸入抬頭文字（Header）→ 存檔 → 切到 Code 頁籤寫程式 → 回主畫面把它拖進欄位群組 → Generate。

InfoSet 的程式碼區段（Code 頁籤上方的下拉選單）依執行時機分成幾段，觀念跟一支 ABAP 報表的事件一樣：

區段執行時機典型用途
DATA全域宣告區宣告暫存變數、緩衝用的內表
INIT / INITIALIZATION選擇畫面顯示前給選擇欄位預設值
AT SELECTION-SCREEN使用者按執行後檢核輸入值
START-OF-SELECTION取數開始前，只跑一次一次把要用的參照資料撈進緩衝內表
RECORD PROCESSING每讀到一筆資料就跑一次計算附加欄位、過濾資料（可用 CHECK／REJECT）
END-OF-SELECTION全部讀完後收尾、統計

下面是一段實用的 RECORD PROCESSING 範例，示範「算出未交量、把狀態轉成中文、算出交期逾期天數」。InfoSet 的程式碼區段裡，表格欄位是以工作區形式直接引用（例如 VBAP-KWMENG），這是 SAP Query 產生器的規定寫法，不能改成內嵌宣告的變數名。

" ===== 區段：DATA（宣告）=====
TYPES: BEGIN OF ty_makt,
         matnr TYPE makt-matnr,
         maktx TYPE makt-maktx,
       END OF ty_makt.
DATA gt_makt TYPE HASHED TABLE OF ty_makt WITH UNIQUE KEY matnr.

" ===== 區段：START-OF-SELECTION（只跑一次，先把品名一次撈進緩衝）=====
SELECT matnr, maktx
  FROM makt
 WHERE spras = @sy-langu
  INTO TABLE @gt_makt.

" ===== 區段：RECORD PROCESSING（每一筆資料都會跑）=====
" 1. 未交數量 = 訂單量 - 已交量
ZOPEN_QTY = VBAP-KWMENG - VBAP-KLMENG.

" 2. 用緩衝內表取品名，避免在迴圈裡下 SELECT
ZMAKTX = COND #( WHEN line_exists( gt_makt[ matnr = VBAP-MATNR ] )
                 THEN gt_makt[ matnr = VBAP-MATNR ]-maktx
                 ELSE '' ).

" 3. 檢驗狀態中文化（QALS-STAT34 = 'X' 代表已作使用決策）
ZQM_STATUS = SWITCH string( QALS-STAT34
                            WHEN 'X' THEN '檢驗完成'
                            ELSE          '檢驗中／未檢驗' ).

" 4. 交期逾期天數（負數代表尚未到期）
ZDELAY_DAYS = sy-datum - VBAP-EDATU.

" 5. 過濾：只留下有未交量的資料（CHECK 不成立就跳過這一筆）
CHECK ZOPEN_QTY > 0.
RECORD PROCESSING 裡千萬不要下 SELECT。它是每筆資料跑一次，一萬筆資料就是一萬次 DB round trip，在 HANA 上一樣會被 DB 連線成本拖垮。正確做法是上面示範的：START-OF-SELECTION 一次撈進 HASHED TABLE 緩衝，RECORD PROCESSING 只做記憶體查表。真的需要單筆讀取時，改用「附加表格 Additional Table」讓系統幫你做（它有做內部緩衝）。
附加欄位若要出現在選擇畫面，在建立附加欄位時要勾選讓它可以當選擇欄位；但要記得，附加欄位是在資料讀出來之後才算的，用它當條件等於「先全撈再過濾」，資料量大時很慢。能用原生欄位篩選就用原生欄位。

8. SQ01 設計報表：從欄位到版面

InfoSet 準備好、使用者群組也掛好之後，才輪到 SQ01。步驟（依講義步驟整理）：

  1. 進 SQ01，先按「使用者群組（Shift+F7）」選定群組（例如 ZVBAP_QALS）——沒選群組就建不出 Query。
  2. 輸入 Query 名稱（講義：QUE_KNV1、ZVBAP_QALS、QUE_VBAK_KNA1），按「建立」，選 InfoSet。
  3. 第 1 頁：抬頭與備註——填 Query 標題、備註，以及輸出格式（SAP List Viewer／ALV Grid 最常用，也可選 ABAP List、Excel、Word 合併列印、下載檔案）。
  4. 第 2 頁：選擇欄位群組——勾選這個 Query 要用到哪些欄位群組。
  5. 第 3 頁：選擇欄位——勾選要出現在報表上的欄位。
  6. 第 4 頁：選擇（Selections）——勾選哪些欄位要出現在選擇畫面上，並可指定是 SELECT-OPTION 還是 PARAMETER、是否必填。
  7. 基本清單（Basic List）——排欄位順序（Line/Sequence）、排序（Sort）、小計（Total／Counter）、群組小計。
  8. 還可再做 統計清單（Statistics）與排名清單（Ranked List），做出「前 10 大客戶」這種報表。
  9. 存檔 → 執行（F8）→ 測試 → 回頭調整。
老師的命名習慣是 QUE_ 開頭（QUE_KNV1、QUE_VBAK_KNA1）。講義在第 09-2 節特別註記「最好還是命名成 QUE_」，因為 Query 名稱會被編進產生的程式名裡，前綴一致才好在 SE38 用萬用字元找到它們。
Query 的執行結果如果選 ALV，使用者可以自己拉版面（Layout）並儲存成 /變式名稱，等於免費得到一套個人化報表。另外 SQ01 選單「Query → 執行並列印」、「Query → 背景執行」都支援排程。

9. 產生的程式：AQ 開頭的程式名怎麼解碼

存檔 Query 時，SAP 會偷偷幫你產生一支真的 ABAP 程式，名字是 AQ 開頭的 30 碼怪名字。講義列出的三個實例：

產生的程式名使用者群組Query 名稱
AQZZZCERPS======QUE_KNV1======ZCERPSQUE_KNV1
AQZZZVBAP_QALS==ZVBAP_QALS====ZVBAP_QALSZVBAP_QALS
AQZZZ000========QUE_VBAK_KNA1=Z000QUE_VBAK_KNA1

名稱結構：第 1～2 碼固定是 AQ；第 3～4 碼是查詢區／工作區識別；第 5～16 碼（12 碼）是使用者群組，不足以 = 補滿；第 17～30 碼（14 碼）是 Query 名稱，不足一樣以 = 補滿。所以看到 AQZZZCERPS======QUE_KNV1======，去掉等號就知道是「使用者群組 ZCERPS 的 Query QUE_KNV1」。

不用自己數格子，SAP 有現成的函數 RSAQ_DECODE_REPORT_NAME：在 SE37 直接測試執行，輸入程式名就會回傳 Query、InfoSet 與使用者群組。這在「PRD 出現 dump 只知道程式名是 AQ 開頭」時特別好用。

REPORT zaq_decode.

PARAMETERS p_prog TYPE progname OBLIGATORY
           DEFAULT 'AQZZZVBAP_QALS==ZVBAP_QALS===='.

START-OF-SELECTION.

  DATA lv_query     TYPE aqadef-quname.
  DATA lv_usergroup TYPE aqadef-bgname.
  DATA lv_infoset   TYPE aqadef-isname.
  DATA lv_workspace TYPE aqadef-wsid.

  " 用標準函數把 AQ 程式名還原成 Query / InfoSet / 使用者群組
  TRY.
      CALL FUNCTION 'RSAQ_DECODE_REPORT_NAME'
        EXPORTING
          program   = p_prog
        IMPORTING
          workspace = lv_workspace
          usergroup = lv_usergroup
          query     = lv_query
          infoset   = lv_infoset.
    CATCH cx_root INTO DATA(lx_err).
      MESSAGE lx_err->get_text( ) TYPE 'E'.
  ENDTRY.

  WRITE: / |查詢區 Workspace : { lv_workspace }|,
         / |使用者群組 Group : { lv_usergroup }|,
         / |InfoSet         : { lv_infoset }|,
         / |Query           : { lv_query }|.
另一個方向（由 Query 找程式名）：在 SQ01 選單「Query → 其他功能（More Functions） → 顯示報表名稱（Display Report Name）」，SAP 會直接把 30 碼程式名秀給你，複製即可貼到 SE38／SE93。

產生的程式長成下面這樣。它是系統自動產生的骨架，只是把工作丟給幾支同樣自動產生的 Function Module（...EXTR 取數、...SHOW 顯示）：

REPORT AQZZZVBAP_QALS==ZVBAP_QALS====.

INCLUDE /1BCDWB/IQG000000000008DAT.          " 資料宣告（自動產生）
DATA %dtab TYPE STANDARD TABLE OF /1BCDWB/IQG000000000008 WITH HEADER LINE.
DATA %subrc TYPE sy-subrc.
INCLUDE /1BCDWB/IQG000000000008SSCR.         " 選擇畫面（自動產生）
INCLUDE /1BCDWB/IQG000000000008SSCRAT.       " 選擇畫面事件（自動產生）

START-OF-SELECTION.
  IF %runmode-extr_on <> space.
    CALL FUNCTION '/1BCDWB/IQG000000000008EXTR'   " 取數
      TABLES     %selopt = %seloptions
                 %dtab   = %dtab
      CHANGING   %rtmode = %runmode
      EXCEPTIONS no_data = 1
                 OTHERS  = 2.
    %subrc = sy-subrc.
    CALL FUNCTION 'RSAQRT_CHECK_EXTR'
      EXPORTING extr_subrc = %subrc
      TABLES    dtab       = %dtab
      CHANGING  rtmode     = %runmode.
  ENDIF.

END-OF-SELECTION.
  IF %runmode-show_on <> space.
    CALL FUNCTION '/1BCDWB/IQG000000000008SHOW'   " 顯示（ALV）
      TABLES   %dtab   = %dtab
      CHANGING %rtmode = %runmode.
  ENDIF.
這支程式絕對不能手動修改。它是 Query 的產物，只要有人在 SQ01／SQ02 存檔或系統升級後重新產生，你的修改就會全部消失。它用了 WITH HEADER LINE 這種在自寫程式中已被禁止的舊語法，也不代表你可以照抄——那是產生器的內部實作。
另外，S/4HANA 升級後常見的 LOAD_PROGRAM_NOT_FOUND dump，原因就是 AQ 程式尚未重新產生；解法是在 SQ01 重新產生該 Query，或執行標準的 Query 重產生程式（RSAQGENQ 系列）。

10. 把 Query 掛成 TCODE：方式一（直接掛程式）與方式二（START_REPORT 參數交易）

方式一：SE93 直接掛 AQ 程式

最直覺的做法：SE93 → 建立交易碼（講義：ZQUE_KNV1、ZVBAP_QALS、ZVBAK_KNA1）→ 選「使用選擇畫面的程式與變式（Report Transaction）」→ 程式名填那 30 碼的 AQ...。

方式一有風險：AQ 程式名裡「編」進了使用者群組與 Query 名，但不同系統／不同 client 產生出來的 /1BCDWB/IQG0000000000xx 內部編號不一樣；且升級或重產生後程式可能被刪除重建。所以 TCODE 掛在 AQ 程式上，在 DEV 好好的，傳到 PRD 可能就找不到程式。這正是講義要教「方式二」的原因。

方式二：START_REPORT 參數交易（推薦）

SAP 提供標準程式 START_REPORT，它接受三個參數，執行時動態算出該叫哪支 Query，就不受 AQ 程式名變動影響。先在 SE38 執行 START_REPORT 試跑，確認參數填對，再去 SE93 做成 TCODE。講義的原話是：「確保可以試行成功，再做 SE93。」

參數（Screen Field）填什麼講義實例
D_SREPOVARI-REPORTTYPE報表類型，SAP Query 固定填 AQAQ
D_SREPOVARI-REPORTSQ03 使用者群組，補空白到 12 碼；第 13 碼填查詢區（全域區填 G）ZCERPS G
ZVBAP_QALS G
ZVBAK_KNA1 G
D_SREPOVARI-EXTDREPORTSQ01 的 Query 名稱QUE_KNV1
ZVBAP_QALS
QUE_VBAK_KNA1
老師特別提醒：「參數的長度要注意。」D_SREPOVARI-REPORT 是「12 碼使用者群組 ＋ 第 13 碼查詢區」。用講義的尺規對照：
1234567890123
ZCERPS G（ZCERPS 6 碼 ＋ 6 個空白 ＋ G）
ZERP300 G（ZERP300 7 碼 ＋ 5 個空白 ＋ G）
ZVBAP_QALS G（ZVBAP_QALS 10 碼 ＋ 2 個空白 ＋ G）
空白數算錯，執行時就會說找不到 Query。用 SE38 試跑時，把游標放到欄位上按 F1 → 技術資訊，可確認欄位長度。

SE93 建立參數交易的步驟（依講義步驟整理）：

  1. SE93 → 輸入交易碼（講義：ZVBAP_QALS2、ZQUE_VBAK_KNA1，建議命名 ZERP###A）→ 建立。
  2. 選 「具有參數的交易（Transaction with parameters / parameter transaction）」。
  3. Transaction 填 START_REPORT；勾選 「Skip initial screen（略過起始畫面）」與 「Inherit GUI attributes」。
  4. 下方參數表填入三行：D_SREPOVARI-REPORTTYPE = AQ、D_SREPOVARI-REPORT = <使用者群組>+G、D_SREPOVARI-EXTDREPORT = <Query 名>。
  5. 存檔、掛傳輸請求、測試。
講義 08 節的兩組完整設定：
ZVBAP_QALS2：REPORTTYPE = AQ、REPORT = ZVBAP_QALS G、EXTDREPORT = ZVBAP_QALS（2024/11/07）
ZQUE_VBAK_KNA1：REPORTTYPE = AQ、REPORT = ZVBAK_KNA1 G、EXTDREPORT = QUE_VBAK_KNA1（2025/03/21）
另有一組示範 REPORT = ZERP300 G、EXTDREPORT = ZERP300。

11. 從 Query 畢業：把它變成自己的 Z 程式

Query 做到一個程度就會撞牆：要加複雜判斷、要串多個資料來源、要效能、要寫測試。這時有三條路。

路一：直接 SUBMIT 那支 AQ 程式，把結果撈回來加工。適合「Query 已經對了，只是要多做一點事」。

REPORT zque_wrapper.

SELECT-OPTIONS s_vbeln FOR vbak-vbeln.

START-OF-SELECTION.

  " 把選擇條件組成 RSPARAMS，動態丟給 Query 產生的程式
  DATA(lt_seltab) = VALUE rsparams_tt(
    FOR ls_r IN s_vbeln (
      selname = 'SP$00001'          " Query 選擇畫面上的欄位名，可在 SE38 顯示程式時查到
      kind    = 'S'
      sign    = ls_r-sign
      option  = ls_r-option
      low     = ls_r-low
      high    = ls_r-high ) ).

  SUBMIT ('AQZZZ000========QUE_VBAK_KNA1=')
    WITH SELECTION-TABLE lt_seltab
    AND RETURN.
用 SUBMIT 呼叫 AQ 程式的最大問題，是程式名與選擇欄位名（SP$00001、SP$00002…）都不穩定，Query 一改就可能對不上。只適合短期救急。

路二：用標準函數 RSAQ_QUERY_CALL 取得 Query 的資料。比 SUBMIT 乾淨得多，因為你傳的是「使用者群組 ＋ Query 名 ＋ 查詢區」這種穩定的邏輯名稱，而不是 30 碼的實體程式名。

REPORT zque_call.

START-OF-SELECTION.

  DATA lt_seltab  TYPE TABLE OF rsparams.
  DATA lt_listdsc TYPE TABLE OF rsaqldesc.
  DATA lr_data    TYPE REF TO data.

  TRY.
      CALL FUNCTION 'RSAQ_QUERY_CALL'
        EXPORTING
          workspace       = 'G'                 " 'G' = 全域區；空白 = 標準區
          query           = 'QUE_VBAK_KNA1'     " SQ01 的 Query 名
          usergroup       = 'ZVBAK_KNA1'        " SQ03 的使用者群組
          skip_selscreen  = 'X'                 " 不顯示選擇畫面
          data_to_memory  = 'X'                 " 資料放記憶體，不直接輸出清單
        IMPORTING
          ref_to_ldata    = lr_data             " 指向結果內表的參考
        TABLES
          selection_table = lt_seltab           " 選擇條件
          listdesc        = lt_listdsc.         " 欄位描述

      " 用 Field Symbol 接住動態產生的結果內表
      ASSIGN lr_data->* TO FIELD-SYMBOL(<lt_result>).
      IF <lt_result> IS ASSIGNED.
        cl_salv_table=>factory(
          IMPORTING r_salv_table = DATA(lo_alv)
          CHANGING  t_table      = <lt_result> ).
        lo_alv->get_functions( )->set_all( ).
        lo_alv->display( ).
      ENDIF.

    CATCH cx_root INTO DATA(lx_err).
      MESSAGE lx_err->get_text( ) TYPE 'E'.
  ENDTRY.

路三（正解）：把 InfoSet 的 Join 直接改寫成一支自己的 ABAP 報表。Query 只是幫你想清楚了資料模型，真正要長期維護的東西，還是自己寫比較好。下面把講義的 ZVBAK_KNA1（訂單抬頭＋客戶主檔）寫成現代 ABAP：

REPORT zsd_order_customer.

TABLES: vbak.   " 僅為了讓 SELECT-OPTIONS 取得型別參考

SELECT-OPTIONS: s_vbeln FOR vbak-vbeln,
                s_kunnr FOR vbak-kunnr,
                s_erdat FOR vbak-erdat.
PARAMETERS: p_vkorg TYPE vbak-vkorg.

START-OF-SELECTION.

  " InfoSet ZVBAK_KNA1 的 Join：VBAK-KUNNR = KNA1-KUNNR
  SELECT h~vbeln,
         h~erdat,
         h~auart,          " 訂單類型
         h~vkorg,          " 銷售組織
         h~vtweg,
         h~spart,
         h~kunnr,          " 售達方
         h~netwr,          " 淨值
         h~waerk,          " 幣別
         c~name1 AS cust_name,
         c~ort01 AS city,
         c~land1 AS country
    FROM vbak AS h
    INNER JOIN kna1 AS c ON c~kunnr = h~kunnr
   WHERE h~vbeln IN @s_vbeln
     AND h~kunnr IN @s_kunnr
     AND h~erdat IN @s_erdat
     AND ( @p_vkorg IS INITIAL OR h~vkorg = @p_vkorg )
   ORDER BY h~vbeln
    INTO TABLE @DATA(lt_order).

  IF lt_order IS INITIAL.
    MESSAGE |查無符合條件的訂單| TYPE 'S' DISPLAY LIKE 'W'.
    RETURN.
  ENDIF.

  TRY.
      cl_salv_table=>factory(
        IMPORTING r_salv_table = DATA(lo_alv)
        CHANGING  t_table      = lt_order ).

      lo_alv->get_functions( )->set_all( ).
      lo_alv->get_columns( )->set_optimize( abap_true ).
      lo_alv->get_display_settings( )->set_list_header( |訂單主檔與客戶清單（共 { lines( lt_order ) } 筆）| ).
      lo_alv->display( ).

    CATCH cx_salv_msg INTO DATA(lx_salv).
      MESSAGE lx_salv->get_text( ) TYPE 'E'.
  ENDTRY.

同樣的邏輯套用在講義第一個實作 ZKNA1_KNB1（客戶編號與帳號關聯）：

REPORT zfi_customer_account.

TABLES kna1.

SELECT-OPTIONS: s_kunnr FOR kna1-kunnr.
PARAMETERS      p_bukrs TYPE knb1-bukrs OBLIGATORY.

START-OF-SELECTION.

  " InfoSet ZKNA1_KNB1：KNA1（一般資料）＋ KNB1（公司代碼資料）
  SELECT a~kunnr,
         a~name1,
         a~land1,
         a~ort01,
         b~bukrs,          " 公司代碼
         b~akont,          " 統馭科目（客戶對應的總帳科目）
         b~zterm,          " 付款條件
         b~zwels,          " 付款方式
         b~loevm AS del_flag
    FROM kna1 AS a
    INNER JOIN knb1 AS b ON b~kunnr = a~kunnr
   WHERE a~kunnr IN @s_kunnr
     AND b~bukrs = @p_bukrs
   ORDER BY a~kunnr
    INTO TABLE @DATA(lt_cust).

  cl_salv_table=>factory(
    IMPORTING r_salv_table = DATA(lo_alv)
    CHANGING  t_table      = lt_cust ).
  lo_alv->get_functions( )->set_all( ).
  lo_alv->display( ).
實務流程建議：SQVI 驗證 Join → SQ02/SQ01 做成正式 Query 給使用者先用 → 需求穩定後再改寫成 Z 程式或 CDS View。這樣既快又不會做白工。

12. SQ00、SQ99 與 Query 家族 TCODE 一覽

TCODE名稱說明
SQ00SAP Query: Start Queries執行 Query。講義原話：「Sq00 : to start queries and Sq01 : to maintain queries，其實畫面長得一樣」
SQ01SAP Query: Maintain Queries建立與維護 Query（主戰場）
SQ02SAP Query: Maintain InfoSet建立資料來源與欄位群組
SQ03SAP Query: Maintain User Groups使用者群組與 InfoSet 指派
SQ07SAP Query: Language ComparisonQuery 文字的多語言比對／翻譯
SQVIQuickViewer個人用快速報表
SE93Maintain Transaction把 Query 掛成 TCODE
SE16HGeneral Table Display (HANA)HANA 版資料瀏覽器，支援群組、加總、多表關聯
關於 SQ99：講義標題把 SQ99 與 QuickViewer、InfoSet Query 並列。要注意的是，SAP Query 家族的標準交易碼是 SQ00～SQ03、SQ07～SQ11 與 SQVI，SQ99 在多數標準系統中查不到；若你的系統有 SQ99，通常是客戶自建、指向 InfoSet Query（Ad Hoc Query）的捷徑。要用 InfoSet Query，正規入口是在 SQ01 選定 InfoSet 後按「InfoSet Query」按鈕（HR 模組則是 Ad Hoc Query／PQAH）。InfoSet Query 的特色是「拖拉欄位、即時看筆數」的探索式介面，不需要先設計版面。

Query 跳轉（Drill-down，講義 10-2）：在 SQ01 的「基本清單」設計畫面，可以用選單「Goto → 報表指派（Report assignment）」把某個欄位連結到另一支報表或交易（例如點訂單號跳 VA03、點客戶號跳 XD03）。這樣使用者從清單可以直接鑽進單據，是 Query 最受歡迎的功能之一。（依講義步驟整理）

13. Report Painter / Report Writer：另一條不寫程式的路

SAP 還有另一套「不寫程式」的報表工具，方向完全不同，常被拿來跟 SAP Query 混淆。

比較項目SAP Query / SQVIReport Painter / Report Writer
TCODESQ00～SQ03、SQVIGRR1／GRR2／GRR3（Painter）、GR31／GR32／GR33（Writer）、GS01 建 Set、GR21 建 Library
資料來源任意 DDIC 表格、View、邏輯資料庫只讀「報表表格（Report Table）」——FI-SL／CO 的彙總表，如 GLPCT、COSP、COSS、CCSS
輸出形狀清單式（一列一筆明細）矩陣式（列＝科目／成本要素，欄＝期間、實際／預算／差異）
典型用途訂單清單、客戶清單、檢驗批清單損益表、成本中心報表、預算 vs 實際差異分析
學習難度低中高（要懂 Library、Set、Characteristic、Key Figure）
選擇口訣：「要看明細清單用 SAP Query；要看期間對比的財務矩陣用 Report Painter。」Report Writer 是 Report Painter 的底層（Painter 是所見即所得的介面，Writer 是原始的列／欄定義），Painter 做不出來的才降到 Writer。
S/4HANA 上 CO/FI 的資料集中到 ACDOCA，很多舊的 Report Painter 報表（讀 COSP／COSS／GLT0）在 Migration 後會抓不到資料或抓錯。S/4 的建議路線是 FGI0／FGI1（Drilldown Report）或直接用 Fiori 的 Embedded Analytics（例如 Financial Statement 系列 App），而不是繼續加 Report Painter。

14. S/4HANA 補充：什麼時候該改用 CDS View ＋ Fiori

SAP Query 在 S/4HANA 1809 之後仍然可以用，SAP 也沒有宣告停用，但它已經是「classic」工具。S/4 的官方報表路線是 CDS View → OData → Fiori Elements，也就是 Embedded Analytics。

把 InfoSet 的 Join 改寫成 CDS View（用 ADT／Eclipse 建立 Data Definition）：

@AbapCatalog.sqlViewName: 'ZVSDORDCUST'
@AbapCatalog.compiler.compareFilter: true
@AccessControl.authorizationCheck: #CHECK
@EndUserText.label: '銷售訂單 + 客戶（取代 InfoSet ZVBAK_KNA1）'
define view Z_I_SalesOrderCustomer
  as select from vbak as SalesOrder
    inner join   kna1 as Customer
      on SalesOrder.kunnr = Customer.kunnr
{
  key SalesOrder.vbeln          as SalesOrderId,
      SalesOrder.erdat          as CreationDate,
      SalesOrder.auart          as OrderType,
      SalesOrder.vkorg          as SalesOrganization,
      SalesOrder.kunnr          as SoldToParty,
      Customer.name1            as CustomerName,
      Customer.land1            as Country,
      @Semantics.amount.currencyCode: 'Currency'
      SalesOrder.netwr          as NetAmount,
      @Semantics.currencyCode: true

16. 傳輸、授權與運維檢查表

  • 傳輸：全域區物件 → 掛傳輸請求走 STMS；標準區物件 → 用 RSAQR3TR 匯出／匯入。傳輸順序一定是 使用者群組 → InfoSet → Query，順序反了會因為找不到相依物件而失敗。
  • 授權：核心權限物件是 S_QUERY（02＝維護、23＝傳輸），加上使用者要被指派到對應的 SQ03 使用者群組；此外報表讀到的資料表仍受 S_TABU_DIS／S_TABU_NAM 與模組權限（如 V_VBAK_VKO）管制。權限出問題先跑 SU53。
  • 使用者參數：AQW＝預設查詢區（填 G 進全域區）。
  • 升級後：Query 產生的 AQ 程式需要重新產生，否則 TCODE 會 dump LOAD_PROGRAM_NOT_FOUND。
  • 命名：使用者群組、InfoSet、Query 一律 Z 開頭，Query 建議 QUE_ 前綴，TCODE 用 Z 開頭。
  • 文件化：把「TCODE ↔ Query ↔ InfoSet ↔ 使用者群組 ↔ AQ 程式名」做成一張對照表存起來。這張表在別人接手時價值連城。

最後給一段小工具程式，把系統裡所有 AQ 開頭的程式列出來並解碼，一次盤點所有 Query：

REPORT zaq_inventory.

START-OF-SELECTION.

  " 找出所有由 SAP Query 產生的報表程式
  SELECT name AS progname
    FROM trdir
   WHERE name LIKE 'AQ%'
     AND subc = '1'                 " 1 = 可執行報表
   ORDER BY name
    INTO TABLE @DATA(lt_prog).

  TYPES: BEGIN OF ty_out,
           progname  TYPE progname,
           usergroup TYPE aqadef-bgname,
           query     TYPE aqadef-quname,
           infoset   TYPE aqadef-isname,
         END OF ty_out.
  DATA lt_out TYPE STANDARD TABLE OF ty_out.

  LOOP AT lt_prog ASSIGNING FIELD-SYMBOL(<ls_prog>).
    CLEAR: DATA(lv_grp), DATA(lv_qry), DATA(lv_iset).
    CALL FUNCTION 'RSAQ_DECODE_REPORT_NAME'
      EXPORTING program   = <ls_prog>-progname
      IMPORTING usergroup = lv_grp
                query     = lv_qry
                infoset   = lv_iset
      EXCEPTIONS OTHERS    = 1.
    CHECK sy-subrc = 0.
    APPEND VALUE #( progname  = <ls_prog>-progname
                    usergroup = lv_grp
                    query     = lv_qry
                    infoset   = lv_iset ) TO lt_out.
  ENDLOOP.

  cl_salv_table=>factory(
    IMPORTING r_salv_table = DATA(lo_alv)
    CHANGING  t_table      = lt_out ).
  lo_alv->get_functions( )->set_all( ).
  lo_alv->get_display_settings( )->set_list_header( |系統內 SAP Query 盤點（{ lines( lt_out ) } 支）| ).
  lo_alv->display( ).
上面的 CLEAR: DATA(...) 只是為了示意；實務上請把三個變數在 LOOP 外用 DATA lv_grp TYPE aqadef-bgname. 宣告好，迴圈內用 CLEAR 即可。舊式 Function Module 的 IMPORTING 參數不支援內嵌宣告。
