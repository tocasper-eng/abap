2. SAP Smart Forms 概覽：為什麼要有它、文件怎麼產生

每家公司都需要大量列印格式固定的文件：發票、交貨單、催款函⋯⋯可以送印表機、傳真或 E-mail。SAP 從 R/3 4.6C 開始提供 Smart Forms，同時包含「設計表單」與「定義表單和應用程式之間介面」兩套工具。SAP 也隨產品交付大量標準表單（SD、FI、HR、CRM、SRM、各國專用表單），總覽請查 SAP Note 430621。原廠特別說明：本課程不教任何模組知識，只教表單開發基礎。

Smart Forms 相對於 SAPscript 的優勢（强晟 p9–p11、原廠 p18）：

  • 客製更容易：有 Table Painter 可以畫表格；表單與程式之間的介面重新設計過。
  • 在表單內補抓資料不必再學 SAPscript 的腳本指令，直接寫一般 ABAP（Program Lines 節點）。
  • Smart Forms 是 Repository 物件，接上傳輸系統，可以測試後一路送到 PRD。
  • 直接整合在應用程式中，和外部系統交換資料不會浪費時間；可在背景大量產生文件（例如大批催款）。
  • 所有 SAP 支援的平台都能執行，但編輯表單需要 Windows 版 SAP GUI。
  • 多語言：版面只定義一次，文字交給翻譯工具翻譯。
  • Web AS 6.10 起可輸出 HTML；支援把 SAPscript 表單、樣式移轉過來；SAPscript 文字可直接在 Smart Forms 中使用；SAP 仍會持續支援 SAPscript。

文件產生：簡化視圖——應用程式要輸出文件只需兩步：① 取資料（程式核心，可以任意複雜、可有使用者互動）；② 啟動表單處理，把讀到的資料寫進表單。

文件產生：完整視圖（這三步背起來，後面 Customizing 與除錯都靠它）：

  1. 交易碼先查 Customizing，決定要呼叫哪一支列印程式，列印程式負責讀資料。
  2. 交易碼再從 Customizing 得知這個情境用哪一張 Smart Form，呼叫該表單產生的函數模組，把讀到的資料填進介面。
  3. 表單處理開始後，背景自動呼叫表單處理器（Composer，排版器）：依版面資訊排版文字、在執行期填入欄位值、控制換頁，最後把成品放進 Spool。

維護 Smart Forms 的工作因此分三類：① 調整表單（主要工作）；② 調整應用程式（只在特殊情況，例如要改 Spool 設定、或要讀一次就用在整批文件的額外資料）；③ 在 Customizing 中登記修改結果。

Casper 口訣「先找標準，再想客製」在表單上的具體做法：先複製 SAP 標準表單（例如 LB_BIL_INVOICE）到 Z 命名空間改版面 → 需要額外資料時先試 Program Lines 或全域初始化 → 真的不行才複製列印程式 → 絕不直接改 SAP 原表單或原程式，升級時會被覆蓋。

3. Form Builder：初始畫面、三個區域與表單屬性

交易碼 SMARTFORMS（選單「工具 → 表單列印輸出 → Smart Forms」），初始畫面用單選鈕選要編輯的物件：表單（Form）、樣式（Style，第 14 節）、文字模組（Text Module，第 6 節）。建立、顯示、修改後進入圖形化工具 SAP Form Builder。初始畫面也能更名、刪除、測試表單；「公用程式 → 移轉 → 匯入 SAPscript 表單」可從 SAPscript 表單產生 Smart Form（第 18 節）。

永遠不要改 SAP 原始表單，下次升級修改會遺失。複製到客戶命名空間（Y 或 Z 開頭）再改。複製或更名後的表單狀態一律是未啟用。

Form Builder 三區：

位置名稱用途
左導覽樹（Navigation Tree）以節點表示表單階層；下方可開欄位清單（Field List）。檢查錯誤訊息顯示在中間區下方，點訊息可跳到該節點。
中維護畫面（Maintenance Screen）多個頁籤編輯目前節點屬性；內建文字編輯器、Table Painter。

導覽樹的處理規則（非常重要，所有流程控制都建立在上面）：

  • 子節點繼承上層節點的屬性（例如樣式）。
  • 某節點若不被處理，其所有子節點也不處理；但後繼節點（同層下一個）與它無關，照樣在它之後處理。
  • 頂層節點下固定有兩個節點：全域設定（Global Settings）＝表單屬性、表單介面、全域定義；以及頁面與窗口（Pages and Windows）。

表單屬性（Form Attributes）：

  • 一般屬性：名稱、描述、狀態（啟用／未啟用）。應用程式只用啟用版，所以可以暫存修改而不影響正在跑的業務。表單必須指派套件（4.6C 稱開發類），第一次存檔時指定，之後可在初始畫面「跳至 → 物件目錄項目」改。每張表單有一個原始語言，可設定要翻譯成哪些語言；6.20 起多了 Restricted Languages（第 17 節）。
  • 輸出選項：頁面格式取自 Spool 管理（SPAD）；新表單預設頁面格式在初始畫面「公用程式 → 設定 → 一般」設定。每張表單都必須指定樣式，多數子節點可另指樣式覆蓋。
  • CPI／LPI：CPI 決定水平單位 CH 的長度（預設 10，即 1 CH＝1/10 英吋，約 2.5 mm）；LPI 決定垂直單位 LN。
  • 輸出格式：標準列印格式是 OTF（Output Text Format）；另有經認證的 XML 介面 XSF（SAP Smart Forms XML Interface，只含內容不含排版）；6.10 起可輸出 HTML；另有 XDF（連介面參數的字典型別都帶上的 XML 格式）。勾「XSF 輸出啟用」即可（强晟註：應用程式不會考慮此設定——意指程式可用 OUTPUT_OPTIONS 動態覆蓋，見第 13 節）。

命名規則：頁面與所有節點都有技術名稱與描述，只能用字母（不可有變音字母）、數字、底線，首字須為字母；百分號 % 可當首字，但那是 Form Builder 自動產生名稱用的，自己不要用。

4. 頁面、窗口類型、Form Painter 與啟用測試

頁面（Page）：每張表單至少一頁，可定義多種版面不同的頁。導覽樹中最上面的頁先處理，之後依頁面「一般屬性」的下一頁（Next Page）決定順序（預設是自己）；也可以用條件或 Command 節點動態決定下一頁（第 11 節）。一個頁面在文件中可依資料量被重複使用多次。刪除頁面時其下所有子節點一併刪除。

  • 頁碼：一般屬性可設阿拉伯或羅馬數字、大小寫，以及頁碼計數器模式（遞增、初始化、不變）。設了頁碼格式不代表頁面就有頁碼——必須在某個文字窗口輸出 &SFSY-PAGE&。
  • 輸出選項：頁面格式套用整張表單，只有方向（直式／橫式）能逐頁設定；可逐頁指定紙匣（例如第一頁用信封紙）；雙面列印（需印表機支援）。
  • 背景圖：圖形須先用 SE78 匯入；Object／ID 預設 GRAPHICS／BMAP，F4 可查；可選黑白或彩色；可填欄位名稱在執行期動態決定（但不適合拿來重繪套印範本，因為 Form Painter 看不到）。解析度以 dpi 為單位，值越小圖越大，空白或 000 用圖檔預設值。輸出模式可選「只在 Form Painter 顯示」（重繪掃描表單但不想印）、「列印預覽」、「列印預覽與列印」；預覽畫面送 Spool 前還能再選是否印背景。文字會印在圖上面。

輸出區域：頁面上必須建立輸出區域才能輸出資訊——一般窗口、地址窗口（用中央地址管理 CAM）、圖形窗口。導覽樹中頁面子節點的順序不影響輸出位置，但決定處理順序（由上而下，想像全部展開），用到執行期才填值的變數時順序就很關鍵。拖放移動（左鍵）、Ctrl＋左鍵複製子樹；把 A 拖到 B 上會插在 B 之後，可能時系統會問「在節點下」還是「在節點後」。

同一個窗口放在多個頁面上：內容（含刪除子節點）的修改會影響所有頁上同技術名稱的節點，但各頁位置可不同，且每頁各有自己的「輸出選項」與「條件」頁籤。同一窗口在同一頁放多次：系統會建立不同技術名稱的副本，改一個只影響那一個。

窗口類型特性原教材強調的限制

Copies Window（原廠 Unit 11 Lesson 5）：處理時機三選一——正本與副本都印、只印副本、只印正本；前兩者再選 Copies Differ 或 Copies Identical。Identical 時窗口內容只進 Spool 一次（其他頁以參照方式列印），對圖形效能改善明顯；Differ 時可在條件中查 SFSY-COPYCOUNT0（正本＝0、第一份副本＝1⋯）或 SFSY-COPYCOUNT（正本＝1、第一份副本＝2⋯）。副本份數由列印程式的 OUTPUT_OPTIONS-TDCOPIES 決定。

窗口輸出選項：左上邊界＋高寬（在 Form Painter 畫的會自動回寫）；邊框與陰影；「垂直／水平間距」控制文字與框線距離（細框線可能壓到字，要留間距）；「永遠繪製框線與陰影」讓無內容時也印框。度量單位：CM、MM、IN（≈2.54 cm）、PT（1/72 英吋）、TW（twip＝1/20 點），垂直可用 LN、水平可用 CH。

Form Painter：點選輸出區域即同步到維護畫面，拖拉改大小與位置；右鍵選單可建立／刪除／剪貼，小窗口被大窗口蓋住時用「到背景（Into background）」——只影響編輯畫面，列印時重疊的元素會一個疊一個全部印出，不會互相遮蔽。設定：「畫窗口」模式、自動縮放、細網格與主網格、貼齊網格、十字游標（一般頁籤）、Tracker 頁籤設定選取高亮、「圖形佔位符」（電腦慢時只畫框不畫圖）。6.10 起 Form Painter 與導覽樹都支援 Ctrl-C／X／V、方向鍵展開收合、Home／End。

啟用與測試：可在節點層級做局部檢查或檢查整張表單。啟用（「表單 → 啟用」，工具列第二個按鈕）＝整張檢查＋存檔＋產生函數模組；函數名稱用「環境 → 函數模組名稱」查。「公用程式 → 回到啟用版本」會刪掉你正在編的未啟用版本。測試（「表單 → 測試」，第三個按鈕）會跳到 Function Builder（SE37），可填介面值 → 單一測試 → 執行 → 輸入輸出裝置 → 列印預覽。

原廠與强晟都提到的捷徑：在 Form Builder 中連按 4 次 F8 就直接到列印預覽。另外 6.10 起 Form Builder 會記錄上次存檔以來的變更，可 Undo／Redo（按 Enter 或呼叫功能時才存中間狀態，所以每次動作後導覽樹會收合）；超大表單若覺得卡，可在「公用程式 → 設定 → 一般」關掉 Undo/Redo Form Changes。

5. 文字節點：連接方式、格式、欄位與系統欄位

除了地址之外，所有文字都用文字節點（Text）輸出。文字節點應放在窗口之下，或表格、範本等節點之下；文字節點本身不能有子節點。次窗口（以及 6.10 起的 Copies／Final Window）放不下的文字會被丟棄，只有主窗口會把剩下的文字接到下一頁。文字節點三個頁籤：

  • 一般屬性：文字類型——Text Element（存在表單內）、Text Module（Smart Forms 文字模組）、Include Text（SAPscript 文字）、6.30 起還有 Dynamic Text（第 6 節）；以及與前一個文字節點的連接方式。
  • 輸出選項：位置、大小、框線、陰影、指定樣式；在主窗口中可勾頁面保護（Page Protection），整段放不下就整段移到下一頁。
  • 條件：見第 11 節。
連接方式行為編輯器對應
新段落（New Paragraph）第二個節點從新行開始，套用自己的段落格式，兩者完全獨立Enter＝新段落
新行（New Line）從新行開始，但沿用前一節點最後一段的段落格式Shift＋Enter＝換行不換段
直接追加（Append Directly）無空白無空行直接接上，後段套用前一段格式—
例外：前一個節點有框線或陰影時，第二個節點一律以「新段落」接上，不管你選什麼。

格式：編輯器是所見即所得。每段從清單選段落格式（定位點、對齊⋯）；選取文字可套一或多個字元格式（字型、上標⋯），「重設字元格式」回到段落格式。清單內容取決於樣式，套用順序：節點樣式覆蓋表單屬性樣式；下層節點覆蓋上層；文字節點先看自己，沒有就往上找；沒選段落格式就用樣式的標準段落。游標所在位置的格式會自動顯示在清單中（4.6C SP9 起，見 SAP Note 327636），所以「顯示格式」只在要看細節或多重字元格式時才需要。Unicode 系統全螢幕模式可改用 Microsoft Word 當編輯器（SAP Note 742662）。

插入欄位：最簡單是從欄位清單拖放；清單包含：透過表單介面進來的 Import／Export／Tables 參數、全域定義中的全域資料與 Field Symbol、系統欄位。也可按「插入欄位」手打，名稱放在兩個 & 之間，大小寫不分，還能用 SYST 系統欄位（例如 &SY-UNAME&）。欄位在編輯器裡是灰色，不能直接改，要用「修改欄位」「刪除欄位」。編輯器的檢查會找出語法錯誤（紅三角，無法啟用）；Form Builder 工具列第一個按鈕的完整檢查才會做資料流分析，找出可能尚未賦值的欄位（黃圈警告，仍可啟用）。

6. 文字模組、Include Text 與 Dynamic Text

有些文字不該存在表單裡，而是集中存放、表單只放參照：寫一次、到處用；改一次、所有表單生效（原教材的例子：銀行帳戶資訊變更）。切換文字類型時系統會警告已輸入的文字將遺失。段落與字元格式名稱存在文字中，實際外觀依文字節點的樣式解譯。

文字模組（Text Module）：從 SMARTFORMS 初始畫面選「文字模組」維護，可複製、更名、刪除；名稱須在客戶命名空間；和表單一樣接傳輸系統，需指派套件。文字模組編輯器沒有欄位清單也沒有檢查（因為它會被插進介面各不相同的表單），可以插入欄位，但所有使用它的表單都必須定義並填好這些欄位。「管理」頁籤必須指定樣式，預設是 SYSTEM。

  • 在表單中：文字節點選類型「文字模組」並輸入名稱；也可輸入以 & 包住的欄位名稱，執行期動態決定文字模組——這時編輯器無法顯示內容，也無法檢查；執行期找不到就中止本次輸出請求。6.10 起可勾「No error if no text exists」避免中止，並用 SFSY-SUBRC（找到＝0、找不到＝4）判斷；也可為每個文字模組設定替代語言。
  • 按「複製（Copy）」會把文字模組內容變成表單內的 Text Element，切斷參照，之後改文字模組不再影響此表單。
  • 預設用文字節點或上層節點的樣式；勾「永遠從文字複製樣式」則改用文字模組自己的樣式。

Include Text（SAPscript 文字）：文字節點選「Include Text」，在文字鍵群組填 Text Name、Text Object、Text ID、語言（都可用 &欄位& 動態指定）；勾「文字不存在時不報錯」可避免函數模組中止。Smart Forms 會忽略 SAPscript 文字中的所有控制指令，需要的邏輯要自己改寫成 Smart Forms 節點。

覆蓋 Include Text 的段落格式（L29 2006 版 p79 補充；Col18 p61 也這樣寫）：Include Text 裡的段落與字元格式一律依文字節點當時適用的 Smart Style 解讀（例如 SAPscript 裡段落 B 是粗體，Smart Style 裡 B 卻是小字，印出來就是小字）。文字節點可以覆蓋段落格式：Standard Paragraph 欄位指定樣式中的一個段落格式，套用到 Include Text 裡所有用標準段落（*）的段落，相當於 SAPscript INCLUDE 指令的 PARAGRAPH 附加；First Paragraph 則只指定第一段的格式，相當於 NEW-PARAGRAPH 附加（Standard Paragraph 空白時，其餘標準段落也會跟著用這個格式）。4.6C 要到 Support Package 23 才有這個功能，更早的版本可參考 SAP Note 422120 的預先修正。

勘誤：本節原本寫「4.6C 之後不能在段落格式群組覆蓋 SAPscript 文字的段落格式」，這句是錯的。L29 2006 版與 Col18 都明寫可以覆蓋，只有 4.6C SP23 之前不行，以此為準。
新文字請一律建 Smart Forms 文字模組，不要建 SAPscript 標準文字，原因（强晟 p77）：① Smart Forms 內無法維護或預覽 SAPscript 文字（只能到 SO10）；② 無法檢查文字中的欄位是否在表單中有定義；③ SAPscript 文字不會自動進傳輸；④ SAPscript 文字是 Client 相依的，Smart Forms 不是——每個生產 Client 都要有。

Dynamic Text（6.30+）：第三種長文字來源。指定一個行類型為 TLINE 的內表，執行期裡面放 ITF 格式文字：TDFORMAT 放段落格式名稱、TDLINE 放內容（最多 132 字元）。填 * 代表樣式的標準段落；要連續文字就只在第一行填段落格式。字元格式用尖括號包起來：<AB>要加格式的字</>。表單內建立文字節點，類型選「Dynamic Text」，Field Name 填內表名稱。

*&---------------------------------------------------------------*
*& 列印程式端：組出 Dynamic Text 用的 TLINE 內表
*& 表單介面 Import 參數 IT_REMARK 以 TLINE 行類型的字典表類型定義
*& （例如 TSFTEXT，請在你的系統 SE11 確認）
*&---------------------------------------------------------------*
TYPES tt_tline TYPE STANDARD TABLE OF tline WITH EMPTY KEY.

DATA(lv_due_date) = CONV d( sy-datum + 30 ).        "先算成日期型別再格式化
DATA(lv_due)      = |{ lv_due_date DATE = USER }|.

DATA(lt_remark) = VALUE tt_tline(
  ( tdformat = '*'  tdline = |親愛的客戶，感謝您選擇 Fly & Smile。| )
  ( tdformat = ' '  tdline = |本發票付款期限為 <B>{ lv_due }</>，逾期將依約加計利息。| )
  ( tdformat = 'L1' tdline = |如有疑問請洽客服專線。| ) ).
" '*' ＝ 樣式的標準段落；空白 ＝ 連續文字（接在上一行之後，只有第一行需要段落格式）
" <B>…</> 的 B 必須是樣式中已定義的字元格式（一或兩碼）

" 若同一段文字要隨條件切換，直接在程式中組好，比在表單裡做十個 Alternative 好維護
IF gs_customer-custtype = 'B'.
  APPEND VALUE #( tdformat = 'L1' tdline = |企業客戶請於匯款備註填寫發票號碼。| ) TO lt_remark.
ENDIF.

7. 地址節點與圖形節點

地址（Address）：許多應用不再用自己的地址表，而改用中央地址管理 CAM（新版稱 Business Address Services，BAS），以地址號碼識別地址。Smart Forms 的地址節點會依各國慣例（ISO 11180 與萬國郵政聯盟準則）自動排版，空間不足時自動省略次要欄位，細節見函數 ADDRESS_INTO_PRINTFORM 的文件。地址節點通常直接放在頁面下當地址窗口（可在 Form Painter 擺位置），也可放在窗口、Loop、表格、範本之下。

地址類型識別方式例子
組織地址（Organization）地址號碼送達方、公司代碼地址
個人地址（Person）地址號碼＋人員號碼（一人可有多地址）自然人，含稱謂
工作場所地址（Workplace）地址號碼＋人員號碼公司內個人，含部門、房號
動態以 &欄位& 在執行期決定類型—
  • 地址號碼與人員號碼也可動態指定；執行期 CAM 找不到該號碼時，表單函數模組帶錯誤訊息中止。
  • 「Start paragraph」設定段落格式（填 * 用樣式標準段落）；「Number of lines to be used」少於完整地址所需行數時，CAM 會壓縮次要部分（州、職稱⋯）。
  • 一定要填寄件國家（Sender Country），系統才能判斷國內或國外地址，國外地址才會印國家名稱。同時有郵政信箱與街道地址時用單選鈕決定印哪一個。
  • 非 CAM 地址：建一個 Program Lines 節點自己呼叫 ADDRESS_INTO_PRINTFORM。
*&---------------------------------------------------------------*
*& Program Lines 節點：格式化「非 CAM」地址（航班模型 SCUSTOM）
*& Input  參數：GS_CUSTOMER    Output 參數：GT_ADDR_LINES
*&---------------------------------------------------------------*
DATA ls_adrs  TYPE adrs.
DATA ls_print TYPE adrs_print.

ls_adrs = VALUE #( anred = gs_customer-form
                   name1 = gs_customer-name
                   stras = gs_customer-street
                   pfach = gs_customer-postbox
                   pstlz = gs_customer-postcode
                   ort01 = gs_customer-city
                   land1 = gs_customer-country ).

CALL FUNCTION 'ADDRESS_INTO_PRINTFORM'
  EXPORTING
    adrswa_in         = ls_adrs
    sender_country    = 'TW'          "寄件國家：決定國內／國外格式
    number_of_lines   = 6             "可用行數不足時自動壓縮次要欄位
  IMPORTING
    address_printform = ls_print.

" ADRS_PRINT 有 LINE0～LINE9 十個欄位，轉成內表方便在 Loop 節點輸出
gt_addr_lines = VALUE #( ( CONV #( ls_print-line0 ) ) ( CONV #( ls_print-line1 ) )
                         ( CONV #( ls_print-line2 ) ) ( CONV #( ls_print-line3 ) )
                         ( CONV #( ls_print-line4 ) ) ( CONV #( ls_print-line5 ) ) ).
DELETE gt_addr_lines WHERE table_line IS INITIAL.     "GT_ADDR_LINES 型別為 STRING_TABLE

圖形（Graphic）：除了背景圖，也可建成獨立圖形窗口（頁面直屬子節點，Form Painter 看得到、可拖放，前提是沒勾「圖形佔位符」），或當窗口／範本等的子節點（Form Painter 看不到、不能拖放，輸出依附上層節點，且要在「輸出位置」頁籤指定水平位置）。名稱、Object／ID、黑白或彩色、解析度的設定與背景圖相同；最重要的是可以輸入欄位名稱，執行期動態決定圖名（例如依公司代碼換 Logo）。圖形會自動調整成正確大小。

圖形都要先在 SE78 匯入（第 16 節），而且不會自動進傳輸，要在 SE78 按卡車圖示加入請求。多公司代碼共用一張表單時，把 Logo 名稱設成 &GV_LOGO&，在全域初始化依 BUKRS 決定，比做 N 個有條件的圖形節點好維護。

8. 表單中的資料：介面、全域定義、型別、初始化、Field Symbol

Smart Forms 內有四種資料：① 介面參數（程式與表單之間傳遞）；② 全域資料（所有節點可見）；③ 系統欄位（SFSY-）；④ Program Lines 中用 DATA 宣告的區域資料（課程不談，屬一般 ABAP）。

表單介面在全域設定中定義，所有參數都是全域的。四類：Import、Export、Tables、Exceptions。

  • Import：有一批固定的標準參數（輸出選項等，欄位不可輸入，見第 12 節），其餘是各表單自訂、幾乎所有要印的東西。名稱須符合 ABAP 命名（不可有變音、空白、特殊字元）；必須定型，用 TYPE、LIKE、TYPE REF TO，可參照 ABAP 型別（C、N、D、T、X、I、P、F、STRING、XSTRING）、字典型別（資料元素、結構、表類型）。可設預設值；勾「傳值（Pass by value）」則傳副本。
  • Export：勾傳值時，函數結束才把值寫回程式；不勾就是傳參照——表單中改了會直接改到程式的變數，表單中途中止時，之前的修改也已經生效；傳參照的 Export 參數實際上變成 Import/Export 雙向參數。
  • Tables：必須是非巢狀表類型（巢狀表請改用 Import 參數傳），永遠傳參照，表單中改內容會直接影響程式端。
  • Exceptions：讓應用程式在呼叫後判斷表單處理錯誤。

9. 表格（Table）：行類型、Table Painter、資料、排序、控制層級、表頭表尾與計算

表格與範本都用 Table Painter 設計、都有行類型，但最大差異：表格的長度與版面要到執行期依資料筆數決定；範本的版面完全固定，執行期不能改儲存格類型與數量，主要用於預印表單（支票、稅單，也就是「套打」）。

表格是窗口的子節點；因為長度可變，應該只放在主窗口，放在次窗口會被截斷。

  • 行類型（Line Type）：在「表格」頁籤定義，指定每行有幾個儲存格與寬度（高度自動決定）。需要：名稱、預設類型（只能有一個，子節點沒指定行類型時使用）、防分頁保護、儲存格數量與寬度。表格總寬＝每個行類型所有儲存格寬度的合計。水平對齊可選靠左、靠右、置中（靠左右可設與窗口邊界的距離）。簡單表格一種行類型就夠；階層表格、小計、多行明細（例如下一行印訂位數）才需要多種。
  • Table Painter：鉛筆游標垂直拖出新儲存格，或右鍵「分割 → 儲存格」；水平拖出新行，或右鍵「插入 → 行」；拖邊界改寬度（雙向箭頭）。行類型不能設高度——這是和範本最大的差別。設定：「畫行與列」、自動縮放、網格／貼齊、十字游標、Tracker、隱藏工具列。
  • 表格樣式（Pattern）：從預設樣式挑格線：第一／最後／所有行之間要不要水平線、第一／最後／所有欄之間要不要垂直線，有無外框，並設線寬。樣式套用整張表格，不能依行類型各自設定（强晟吐槽：中國的表格變化多端，這點很痛苦——實務上用多個行類型搭配儲存格框線設定來補）。

技術背景：表格就是對內表逐行 LOOP，每行複製到與表格結構相同的工作區（或指派給 Field Symbol）。內表通常在應用程式中填好、經介面傳入，也可在表單內填。資料（Data）頁籤：

  • 勾「內表」並填內表與工作區／Field Symbol（都必須在介面或全域定義中存在）；指派方式 INTO（複製）或 ASSIGNING（Field Symbol，大表建議）。沒勾就不會 LOOP——想在並排欄位中輸出文字時就這麼用。舊式有表頭行的內表：工作區名稱填得和表名一樣（仍會複製行）。
  • 可只處理某段行號（Line … to …），或設 WHERE 條件（等同 LOOP AT … WHERE），運算子同選擇畫面：萬用字元、=、≠、≥、>、≤、<；不填運算子預設等於；多條件以 AND 連接，可插入 OR。
  • 排序準則：依清單順序排序，可升降冪；系統無法判斷內表是否已排序，若程式端已排好，填排序準則並勾「已排序（Already sorted）」，否則會再排一次。

表格中的文字：至少建一個文字（或地址、圖形）子節點。輸出選項多了行儲存格控制：新行（New Line）＋選行類型（不選用預設類型，有表格樣式時會畫格線）；新儲存格（New Cell）＝輸出到下一格，可跳過多格，行類型已沒有空格可用時執行期報錯。一格可放多個節點；一個表格行最多跨兩頁；同一行的節點建議包進資料夾（Folder）並標記，導覽樹才好認。

控制層級（Control Level）：在排序準則上勾「Event on Sort Begin」及／或「Event on Sort End」，導覽樹中就會插入對應的事件節點——不能直接在導覽樹建立控制層級。事件節點只有「輸出選項」頁籤（可設樣式、行類型、儲存格），底下可放文字、計算小計的 Program Lines、手動換頁的 Command。每個排序欄位都能設控制層級，因此可做出「航空公司 → 航線」的多層階層表。一般只有需要小計或分組小標時才排序。

表頭與表尾：在表格的「事件」頁籤勾 Header／Footer，自動產生事件節點（同樣不能直接建立）。表頭可在表格開始及／或換頁後輸出，常放欄標題；表尾可在表格結束及／或換頁前輸出，常放小計，而且必須指定表尾高度，排版器才會預留空間。取消勾選表頭或表尾時，其下所有節點會遺失。

計算（Calculations，6.10+）：表格多一個頁籤，不寫程式就能計算：Number（每行目標欄位 +1）、Total（加總）、Mean value（平均）。時點選 Before loop／After loop 代表逐行計算；Before/After sorting 主要用來數子層級，此時「For field name」只填欄位名稱（例如 CARRID，不要寫 WA-CARRID）。勾 Initialize 表示表格開始時歸零；Reset 選 Sort Criterion 並在 For 欄填欄位，則每次控制層級變更就歸零——前提是資料頁籤勾了 Event on Sort Begin。

L29 2006 版補充（版本差異）：上面「預設類型」「新行／新儲存格」是 4.6C 舊式表格的做法。6.10 起表格改成「表頭／主區域／表尾」三區，內容要先建 Table Line 並選行類型，系統自動產生對應的儲存格節點，所以原廠註明 6.10 起「Default type: without relevance（預設類型已不重要）」。6.20 另外多了 Minimum Height（目前窗口剩下的高度不夠時，整張表格從下一頁開始）。兩種模型的逐步對照見第 20 節。
Calculations 不考慮幣別與單位。原廠例子：訂位價格有歐元也有美元時不能用它加總，因為不會自動換算，只能改用 Program Lines 手動計算（下例）。

10. 範本（Template）與套印表單的重繪

範本用來輸出版面與尺寸固定的表格，典型用途是把資料印到預先印好的單據上，例如機票、報稅表。和其他節點一樣從導覽樹右鍵建立成窗口的子節點。

  • 範本不能巢狀。
  • 範本下可放各種節點，但儲存格放不下的文字不會輸出（版面固定）。
  • 範本下的圖形在 Form Painter 看不到，只有列印預覽看得到。
  • 寬度不可超過所在窗口；水平對齊靠左／置中／靠右（靠左右時可填與邊界距離，沒填就貼邊）。
  • 垂直對齊：「絕對（從頂端）」可在同一窗口挨著放多個範本（印標籤、或疊幾個範本組出複雜行結構時很有用）；「目前（Current）」則緊接在導覽樹前一個節點之後，垂直位置取決於前面處理了多少節點。
  • 每一行都要描述：唯一的行名稱、行範圍（From–To）、高度、任意數量的儲存格寬度（合計必須等於範本寬度）。不連續的多行共用同一行定義時，只定義一次，其他地方用「參照（Reference）」欄位指過去。
  • 範本也可選樣式，規則同表格，不能逐行逐格設不同樣式。
  • 內容子節點的「輸出選項 → 輸出結構」指定要輸出到第幾行第幾格；沒指定就輸出到目前儲存格（上一筆輸出的那格）。一格可放多個節點，輸出順序依導覽樹順序。

以重繪方式建立範本（複雜套印單據的標準做法）（依講義步驟整理）：

  1. 把外部表單掃描成圖，用 SE78 匯入，設成頁面的背景圖；輸出模式：要印到已預印的紙上就留空（只在畫面顯示），要在白紙上連格線一起印就選「列印預覽與列印」。按 Enter 更新 Form Painter。
  2. 在 Form Painter 畫一個窗口蓋住圖。
  3. 在窗口中建立範本，寬度＝窗口寬度；垂直對齊選「絕對（從頂端）」；從範本頁籤開 Table Painter，勾「顯示背景圖」，並在 Table Painter 設定一般頁籤勾透明表格（Transparent Tables），再按 Form Painter 工具列最後一個圖示。
  4. 照著掃描圖重繪；為了畫得準，可以取消「對齊表格到網格」。原表單很複雜時，可建多個範本互相疊放或連續排列。
套印的真正難點不在畫，而在印表機：不同機型的進紙誤差、印表機驅動的邊界都會讓整張偏移。定稿前務必用實際印表機、實際預印紙對位，並把偏移量記在窗口位置上；換印表機時重新校一次。

11. 流程控制：條件、Alternative、Program Lines、Final Window、Command、Loop、Folder

導覽樹預設由上而下處理，但有些部分要到執行期才能決定（例如表格長度）。Smart Forms 提供的流程控制手段：

節點條件（Conditions 頁籤）：許多節點都有，條件不成立時該節點與所有子節點都不處理。兩種：

  • 欄位比較：每行一個欄位名稱（不加 &），中間按鈕選關係運算子（預設等於），比較值可以是欄位或常數。欄位必須在介面、全域定義中，或是 SFSY- 系統欄位。多行以 AND 連接，按上方按鈕可插 OR。
  • 事件：例如「只在第一頁」「不在第一頁」；表頭表尾等特定節點才有「只在段落開始／結束」這類事件。
  • 有條件的節點在導覽樹前會多一個圖示；每頁上的同名窗口各有自己的條件頁籤。
教材勘誤與版本差異：强晟筆記 p132 寫「系統欄位（SYSF-...）」，應為 SFSY-。同頁又說「不要在條件中使用 FORMPAGES 與 JOBPAGES，因為它們的值要整張表單處理完才知道」——這是 4.6C 的說法；新版原廠教材改為：這兩個欄位只能在 Final Window 的條件中使用，其他地方值尚未決定。

Alternative（二選一）：有 TRUE、FALSE 兩個子節點，一般屬性頁籤的條件成立處理 TRUE 分支，否則處理 FALSE，相當於 IF…ELSE；可巢狀。注意區分：一般屬性頁籤的條件決定走哪一支；條件頁籤的條件決定整個 Alternative 要不要處理。

Program Lines（程式行）：在表單中嵌 ABAP 而不必改應用程式，用途：程式沒直接提供但可由既有資料算出的值、清空計數器、計算小計與合計。它沒有輸出、沒有子節點，所以沒有輸出選項頁籤；像副程式一樣必須宣告 Input／Output 參數，否則只能用自己 DATA 的區域變數；參數必須是表單全域可見的（介面或全域定義）。Input 與 Output 只是語意上的區分——兩者都是傳參照，改 Input 參數的值也會持續生效。SFSY- 與 SY- 不必宣告就能用，但應唯讀。程式行的結果只影響在它之後處理的節點。想用舊的逐行編輯器：「公用程式 → 設定 → 編輯器 → 表格控制編輯器」。

Form Routines（全域副程式）：多個 Program Lines 共用的程式碼，可在全域定義的 Form Routines 頁籤寫 FORM…ENDFORM，再從程式行呼叫；Program Lines 內自己寫的副程式只在該節點內有效。

Form Routines 頁籤是 Smart Forms 的既定框架，只能用 FORM 語法。依本館規範，新開發請把共用邏輯寫成全域類別的靜態方法（SE24，可單元測試、可在列印程式重用），Program Lines 裡只留一行呼叫，例如 gv_class_text = zcl_bc470_form_util=>class_text( gs_booking-class ).，Form Routines 頁籤保持空白。

Final Window 與「總頁數」問題：有時第一頁就需要知道總頁數（例如裝信封機器要讀的條碼），或要在前面的頁印出最後才算出的合計。SFSY-FORMPAGES 要到表單處理結束才知道，是在第二輪才由排版器補進去的；一般窗口無法評估尚未決定的值。

  • 6.10 起：把窗口類型設成 Final Window，它只在第二輪處理，屆時所有欄位值都已知。
  • 4.6C（SP12 起）的舊做法（强晟 p139–p140）：在第一個處理的頁面建一個次窗口當最上層節點，內含 Program Lines，對每個要後處理的窗口以 PERFORM set_late_window IN PROGRAM saplstxbc 並傳入窗口名稱（詳 SAP Note 359009）。原廠明講：升級到 6.10 後這類表單必須改寫——刪掉這段程式碼，把次窗口改標成 Final Window。這段舊碼在 S/4HANA 不該再出現，本館不收錄程式碼。
效能代價：只要用了 SFSY-FORMPAGES 或 SFSY-JOBPAGES，所有輸出頁都要留在記憶體裡直到表單（或整個列印請求）結束。大量批次列印（例如數千封催款函）時，「第 X 頁共 Y 頁」可能讓記憶體暴增；JOBPAGES 的影響比 FORMPAGES 更大。

Command 節點：

  • Go to new page：主窗口填滿時自動換頁到「下一頁」；想依條件換到別頁（例如正文結束後印封底、或自我循環的頁結束後改印條款頁）就用它。只能用在主窗口，否則函數模組報錯；手動換頁後主窗口中之後的節點不在本頁處理，但本頁的次窗口在換頁前仍會處理。
  • Reset paragraph numbering：把指定大綱段落（須存在於樣式中）及其所有下層編號重設；沒有大綱屬性的段落格式被忽略（第 14 節）。
  • Include printer control：送印表機控制給輸出裝置，使用特殊功能；列印控制在 Spool 管理維護，輸出時轉成機型專屬指令（第 15 節）。
  • Spool 屬性：可自由定義 Spool 請求的屬性與值，事後從表 TSP02A 或報表 RSOPRNT 讀取（SAP Note 359379）。

Loop：和表格一樣逐行讀內表（資料頁籤：內表、INTO 工作區或 ASSIGNING Field Symbol、行範圍、WHERE、排序；排序是控制層級的前提），但沒有表格頁籤、沒有行類型，不決定輸出位置，所以內容節點直接掛在 Loop 下。事件頁籤可建表頭表尾（規則同表格，表尾要給高度）。Loop 可巢狀，Loop 裡也可以放表格或範本。用途例：依幣別排序輸出金額、輸出某客戶所有訂位。

Folder（資料夾）：表單越大節點越複雜，用資料夾分組：範本每格或每行一個資料夾方便辨識搬移；催款函依逾期天數只印其中一段文字，把各段（含條件）收進資料夾；多個節點共用同一條件時，把條件設在資料夾上而不是每個節點各設一次。資料夾也有事件頁籤，可做表頭表尾。

12. 整合到應用程式：產生的函數模組與標準參數

從 Smart Forms 的角度，應用程式分三部分：

  1. 取資料——目前最大宗的部分。
  2. 決定產生的函數模組名稱——名稱因表單、因系統而異（形如 /1BCDWB/SF00000xxx），所以要呼叫 SSF_FUNCTION_MODULE_NAME，傳入表單名稱（型別 TDSFNAME），取回函數名稱（型別 RS38L_FNAM）。
  3. 開始表單處理——每一份要產生的文件呼叫一次產生的函數，例如每個要開發票的客戶各呼叫一次。

取得正確的呼叫樣板：在 Form Builder「環境 → 函數模組名稱」，Ctrl-Y、Ctrl-C 複製名稱 → ABAP 編輯器「模式（Pattern）→ CALL FUNCTION」貼上，就會插入帶完整介面的呼叫 → 最後把函數名稱換成 SSF_FUNCTION_MODULE_NAME 取回的變數。

PARAMETERS p_form TYPE tdsfname DEFAULT 'Z_BC470_INVOICE'.
DATA gv_custid TYPE s_customer.
SELECT-OPTIONS s_cust FOR gv_custid.

START-OF-SELECTION.

  SELECT id, name, form, street, postbox, postcode, city, country, custtype
    FROM scustom
    WHERE id IN @s_cust
    ORDER BY id
    INTO TABLE @DATA(lt_customer).

  SELECT carrid, connid, fldate, bookid, customid, class,
         forcuram, forcurkey, luggweight, wunit
    FROM sbook
    WHERE customid IN @s_cust
      AND cancelled = @space
    ORDER BY customid, carrid, connid, fldate, bookid
    INTO TABLE @DATA(lt_booking_all).

  IF lt_customer IS INITIAL.
    MESSAGE '沒有符合條件的客戶' TYPE 'S' DISPLAY LIKE 'E'.
    RETURN.
  ENDIF.

  " ② 取得產生的函數模組名稱（因表單、因系統而異，絕不寫死）
  DATA lv_fm TYPE rs38l_fnam.

    EXPORTING  formname           = p_form

               OTHERS             = 3.

什麼時候要改應用程式：① 需要額外資料、且整批文件都要用——基於效能不要在表單裡查（表單每份文件都會跑一次）；② 要做輸出相關設定，例如禁止列印預覽。要改哪一段（函數或副程式）由交易決定；原則上只在極特殊情況才改 SAP 原程式，用自己的副本（程式、表單、文字）就必須在 Customizing 中登記（第 16 節）。

HTML Web Form 的輸入元素（原廠 Unit 11 Lesson 5）：文字元素或文字模組中可放讓使用者在瀏覽器填寫、再由程式評估的欄位：核取方塊、單選鈕群組（每組只能選一個）、文字欄位（最多 255 字元）、Submit 按鈕（跳到表單輸出選項靜態指定、或 OUTPUT_OPTIONS-XSFACTION 動態指定的頁面，欄位值就是按鈕文字）、Reset 按鈕、隱藏欄位、清單方塊、多行文字區（6.10 SP5 起），也可把文字標成 URL。步驟：① 輸入欄位要先定義成全域欄位（或用介面欄位）；② 照常插入文字節點；③ 在文字節點的 Web Attributes 頁籤設定輸出方式（只影響 HTML 輸出；其他格式要隱藏時查 SFSY-XSF = 'X'）。清單方塊與單選鈕要填 Group name，同組欄位輸入類型須一致，可用 Std Val 標預設選項。

Web Form 透過 BSP 顯示：瀏覽器以 URL 呼叫 BSP → OnInitialization 事件呼叫表單產生的函數（HTML 輸出須啟用）→ 從 JOB_OUTPUT_INFO 取 HTML → 轉換後以 response 物件 SET_DATA 回傳 → 瀏覽器顯示。每張 Smart Form 只有一個 HTML 表單、只能指定一個後續頁；在後續 BSP 的 OnInitialization 用 request 物件的 GET_FORM_FIELDS 取使用者輸入。範例 BSP：SF_WEBFORM_01／02／03；Web Form 一般問題見 SAP Note 445605。

S/4HANA 現況：Smart Forms 的 HTML Web Form＋BSP 是 2000 年代初的技術，BSP 已不是 SAP 的 UI 策略方向。要讓使用者在線上填寫表單，請改用 Fiori（SAPUI5／Fiori Elements＋OData/RAP）；要產生可填寫的 PDF，用 Adobe Forms 的互動式表單（5-20 章 BC480）。XSF 作為資料交換介面也已被 IDoc、OData、SOAP 取代（5-22 章、4-1 章）。

14. Smart Styles：樣式、段落格式與字元格式

文字格式清單的內容取決於樣式，規則：每張表單必須指定一個樣式（表單屬性 → 輸出選項，新表單預設 SYSTEM）；多數節點可在輸出選項另指樣式，套用到其下所有節點。樣式是字元格式與段落格式的集合（類似 Word 的樣式範本），不能選樣式中沒有的格式，這保證同樣式的表單外觀一致。Include Text 裡的 SAPscript 樣式（不論靜態或動態指定）一律不理會；Include Text 用到的格式若不在套用的 Smart Style 中，就被忽略。

交易碼 SMARTSTYLES（或從 SMARTFORMS 初始畫面選 Style）。只在客戶命名空間改樣式，需要時用「Smart Styles → 複製」把 SAP 樣式複製過來；樣式同樣接傳輸系統、首次存檔要指派套件，「管理」頁籤可看套件、建立者、修改者（樣式變體與 4.6C 無關）。維護工具叫 Style Builder：左邊導覽樹、右邊明細與預覽；樣式也有啟用與未啟用版本。

表頭資料（Header Data） → 標準設定頁籤：

  • 標準段落：文字沒指定格式時使用，在編輯器格式清單中標 *。要啟用樣式就必須設標準段落（與樣式描述），而設之前至少要先定義一個段落格式。
  • 定位點：標準定位點間距（永遠靠左）；CPI／LPI：樣式中 CH、LN 的大小。
  • 字型群組套用到所有段落與字元格式（除非各自覆蓋）：字型族（依字型維護設定，第 15 節）、字型大小（以 PT 為單位，預設 12；强晟註：中文即「小四」）、粗體／斜體。
  • 底線：間距（0＝壓在基線上，負值會變成刪除線）、粗細（預設 1 點）、亮度（0%＝全色）。各種底線在 Style Builder 與編輯器預覽中看不出差別，只有列印預覽或實際列印才看得到；不是所有印表機都支援。4.6C 的「允許標準格式」核取方塊沒有作用。

段落格式與字元格式技術名稱都是兩個字元，另有描述；以編輯選單、按鈕或右鍵建立、複製、更名。

段落格式頁籤設定
縮排與間距左右縮排（窗口與文字的距離）、首行縮排；段前、段後間距；行距——改用大字型時行距不會自動調整，要自己改以免重疊；文字流：頁面保護（整段放不下就在段前自動換頁）、「下段同頁」
字型同表頭資料的標準設定；沒設就用表頭；顏色與字型族等標準設定不會顯示在段落預覽中
定位點各自的定位點；「符號（Sign）」對齊：靠右對齊數值並考慮尾端負號或隱含空白；「小數點」對齊：依小數點對齊；最後一個定位點之後沿用表頭標準定位點
編號與大綱項目符號或自動編號。多層編號（1、1.1、1.2.1⋯）要每一層各建一個段落（建議用複製），指定最上層大綱段落，各層在導覽樹中成為其子節點。編號類型：清單字元（最多 8 個字元）、阿拉伯數字、羅馬數字大小寫、字母大小寫，可設左右定界符如「a)」；位置欄位是與左窗口邊界的距離（4.6C 參考點固定為左邊界），段落縮排要夠大以免重疊；勾「編號鏈（Chain）」多層編號會帶上層號碼。編輯器預覽不是精確所見即所得，要測試函數才準；重設編號用 Command 節點的 Reset Paragraph Numbering

字元格式有兩個頁籤：「字型」（覆蓋表頭或段落格式的字型族、大小、樣式、底線、顏色；表頭或段落的字型設定不會顯示在字元格式預覽中）、「標準設定」（上標、下標、條碼）。條碼的高度與寬度自動取自字型維護；條碼不能與上下標併用；條碼不會出現在 Style Builder 預覽，應用程式的列印預覽也只以正確尺寸粗略畫出線條圖樣。

SAPscript 樣式可以在 SMARTSTYLES 初始畫面「Smart Styles → 轉換 SAPscript 樣式」直接轉成 Smart Style。樣式做好先啟用再給表單用，實作步驟與命名建議見 4-3 章第 3 節。

15. 字型與條碼：設備類型、列印控制、SE73

從表單到裝置的輸出（SAPscript 與 Smart Forms 共通）：表單與樣式中選字型與印表機無關；到列印時才選印表機，也就決定了設備類型（Device Type）。設備類型指定用哪個印表機驅動排版、需要哪個印表機字元集；Spool 的中介格式 OTF 已考慮印表機（例如換頁），但印表機控制字元仍是符號名稱（列印控制），由輸出請求轉成機型專屬指令。設備類型描述一整個機型，可被多個輸出裝置共用，例如所有 HP LaserJet 4 相容印表機都用 HPLJ4。

不要直接改 SAP 標準設備類型，升級時會被覆蓋；一律先複製。

案例：字印不出來——問題 1：發票部分字型印錯，原因是買了 SAP 尚未支援的印表機；問題 2：印表機有的字型選不到，原因是印表機裝了新字型模組而標準設備類型沒設定。解法：建立帶有額外字型／字級的設備類型，六步驟：

  1. 在 SPAD（工具 → CCMS → Spool → Spool 管理）「公用程式 → 設備類型 → 複製設備類型」，例如 HPLJ4 → ZHPLJ4。
  2. 為新設備類型建立新的列印控制（SPAD 或 SE73）。
  3. 必要時建立新字型族。
  4. 為字型族定義系統字型（需要的字級、粗體斜體組合）。
  5. 為新設備類型定義對應的印表機字型，並指派列印控制。
  6. 把新設備類型指派給印表機（輸出裝置），例如 P280 從 HPLJ4 改成 ZHPLJ4。

複製設備類型的「使用參照（Use References）」：勾選時不複製格式動作與字型度量，而是參照來源設備類型——好處是 SAP 更新標準設備類型時新類型自動跟上；但只有在確定所有用到目標類型的系統都有來源類型時才勾；來源若已是客戶副本（Y/Z 開頭）就不要勾。複製的內容：設備類型定義、列印控制（之後可再加）、格式類型、字型度量／字級、Smart Forms 與 SAPscript 的印表機字型與印表機條碼。

新增列印控制：SPAD → 完整管理 → 設備類型頁籤 → 輸入 ZHPLJ4 → 列印控制 → 修改模式 → 編輯 → 插入行，建立 SFxxx（xxx 編號任意）。控制字元序列要查印表機手冊並參考設備類型既有的列印控制，可輸入十六進位或文字——前提是懂該印表機語言。

字型維護 SE73（工具 → 表單列印輸出 → 管理 → 字型）：

物件定義
字型族（Font Family）可用字型名稱，須標明等比例或非等比例；可指定替代字型族（目標設備類型沒有該字型時使用）與 SAP 字元集（Code Page）
系統字型（System Font／SAP Font）字型族＋字級＋粗體／斜體的組合；Smart Forms 文字中選的字型都是系統字型
印表機字型（Printer Font）設備類型＋字型族＋字級＋粗斜體；要維護度量資料（字元寬度）與切換字型的控制資料。建立時要填：設備類型、字型族、字級、粗斜體、CPI、列印控制
系統條碼（System Bar Code）與設備無關的條碼類型，要在 Smart Forms 使用，選一個啟用條碼屬性的字元格式
印表機條碼（Printer Bar Code）連結到設備類型專屬的條碼控制序列
教材勘誤：强晟筆記 p186 寫印表機字型大小單位為「1/20 點，例如 240」。原廠 Col18 寫的是 1/10 點（240＝24 點），SE73 的字級也是以 1/10 點為單位，以原廠為準。可縮放字型的驅動程式則填 000。比例字型（如 Times）必須維護 AFM 檔（每個字元的寬度）：游標放在印表機字型上按「編輯度量」，或「編輯 → 複製度量」從既有字型複製。

條碼原理：條碼是自動識別技術，由平行的條與空白組成，以預定寬度樣式編碼，掃描器配合解碼器讀取。在 Smart Forms 裡條碼資料就是一般文字（例如字串 4<AMCDPQ=ghijab>），只是要用條碼字元格式排版——例如樣式中字元格式 B1 定義為使用 EAN13 系統條碼。列印時先送條碼前置列印控制（命名 SBPxx），再送條碼資料（例如 8 位數字），最後送條碼後置（SBSxx）；這些機型專屬序列維護在印表機條碼中，維護方式同系統字型／印表機字型。

17. 多語言表單與翻譯（SE63）

文字元素：列印語言由程式在 CONTROL_PARAMETERS-LANGU 指定，REPLANGU1～3 可指定最多三個替代語言。找語言的順序：LANGU → REPLANGU1～3 → 登入語言 → 表單原始語言。6.20 起表單一般屬性可勾 Restricted Languages，文字不存在於處理語言時，不再退回登入語言與原始語言。

  • 文字模組：以表單的輸出語言輸出；6.10 起每個文字模組可設替代語言。
  • Include Text：可在文字節點明確指定語言；沒指定就用表單輸出語言，找不到再依序找登入語言、表單原始語言。
  • 地址：用地址節點（Business Address Services）或 Program Lines 呼叫 ADDRESS_INTO_PRINTFORM，才會依各國格式排版。

19. Interactive Forms by Adobe 與 S/4HANA 的表單策略

原廠 Col18 最後一課介紹 SAP Interactive Forms by Adobe（SAP NetWeaver 2004 起）：部分應用改用它取代或補充 SAPscript／Smart Forms。三種情境：

  • 離線（Offline）：產生帶 Reader 權限、可填寫的 PDF，使用者填好後隨時寄回，系統抽出資料。
  • 線上（Online）：可填寫的表單嵌在 Web 應用（例如 Web Dynpro，見 5-23 章）中，使用者填完送出，資料直接進系統。
  • 列印（Print）：理念與 Smart Forms 列印相同，但架構不同。

列印情境的執行期架構：ABAP 應用程式透過 PPF（Post Processing Framework）判斷是否需要輸出、輸出什麼——PPF 為應用提供依條件產生動作（列印交貨單、傳真訂單確認、觸發核准）的統一介面，動作可立即或稍後處理，PPF 是傳統輸出控制的後繼者。表單處理執行期負責開關 PDF 表單的 Spool Job，再以 Web Service（SOAP over HTTP）呼叫 ADS（Adobe Document Services），由 ADS 負責渲染：填欄位、換頁、套版面；ADS 部署在 J2EE Engine 上。

設計期（SFP 或 SE80）：先建介面（Interface）——決定程式能傳哪些資料，也可放全域資料與初始化程式碼；再建表單——Context 決定此表單實際用介面中的哪些部分（可再加文字模組、圖片），Layout 在內嵌的 Adobe LiveCycle Designer 設計（以特殊 XML 格式儲存）。啟用時一樣產生函數模組。LiveCycle Designer 工作區分四區，上方 Script Editor 可用 JavaScript 或 FormCalc 寫計算，左右是可自行配置的 Palette 視窗。

*&---------------------------------------------------------------*
*& ZBC470_00_PROGS：原廠解答 SAPBC470_PROGS 的 S/4HANA 改寫
*& 表單介面（沿用課程表單 BC470_FLOWS2）：
*&   Import  WA_CUSTOMERS TYPE SCUSTOM、COLOR TYPE CHAR4
*&   Tables  IT_BOOKINGS  TYPE TY_BOOKINGS（行結構 SBOOK）

REPORT zbc470_00_progs.

DATA gv_custid TYPE s_customer.          "取代原解答的 TABLES 工作區，只供 SELECT-OPTIONS 參照
DATA gv_carrid TYPE s_carr_id.

SELECTION-SCREEN COMMENT /1(45) TEXT-se1.
SELECT-OPTIONS: so_cust FOR gv_custid DEFAULT 1 TO 3,
                so_carr FOR gv_carrid.
PARAMETERS pa_prnt TYPE tsp03-padest DEFAULT 'P280' OBLIGATORY VISIBLE LENGTH 4.
SELECTION-SCREEN COMMENT /1(30) TEXT-se2.
PARAMETERS: pa_col RADIOBUTTON GROUP col,
            pa_mon RADIOBUTTON GROUP col DEFAULT 'X'.

  " 原解答預設 so_carr = 'AA' TO 'LH'：區間比的是字典序，
  " AZ、BA、DL、JL… 全部會被夾帶進來。改成明確列舉
  so_carr[] = VALUE #( sign = 'I' option = 'EQ'
                       ( low = 'AA' ) ( low = 'LH' ) ( low = 'UA' ) ).

START-OF-SELECTION.
  " 圖形節點的「動態決定」只認 BCOL（彩色）／BMON（黑白）
  DATA(lv_color) = COND char4( WHEN pa_col = abap_true THEN 'BCOL' ELSE 'BMON' ).

  DATA lt_customers TYPE ty_customers.
  DATA lt_bookings  TYPE ty_bookings.

  SELECT id, name, form, street, postbox, postcode, city, region,
         country, langu, custtype, discount
    FROM scustom
    WHERE id IN @so_cust
    ORDER BY id                            "HANA 沒有預設排序，發票順序要自己定
    INTO CORRESPONDING FIELDS OF TABLE @lt_customers.

  SELECT carrid, connid, fldate, bookid, customid, class,
         forcuram, forcurkey, luggweight, wunit, cancelled
    FROM sbook

      AND carrid   IN @so_carr

    INTO CORRESPONDING FIELDS OF TABLE @lt_bookings.

    EXPORTING  formname           = 'BC470_FLOWS2'

原廠解答的兩個隱患：① 原解答在每次呼叫之後無條件設 no_open = 'X'。如果第一位客戶就失敗（例如格式錯誤），Spool 根本沒開，後面每一次都帶 NO_OPEN = 'X' 呼叫，會一路失敗。上例改成「第一次呼叫成功後才設 NO_OPEN」。最後一位失敗時 Spool 沒關的問題，第 12 節的提醒同樣適用。② 表格 WHERE 篩選在課堂上方便示範，但正式程式應在程式端先篩好再傳。另外原解答用 ORDER BY PRIMARY KEY 排序是對的，HANA 上一定要明確排序，否則發票與明細的順序每次都可能不一樣。

FLOW 選做題「依幣別合計」的兩種寫法：原廠解答在表格主區域放 Program Lines ADD_PRICES，每一行用 MOVE-CORRESPONDING＋COLLECT 累加到 IT_SUM（型別 IT_BC470_FORCUR，行結構 BC470_FORCUR＝FORCURAM＋FORCURKEY），再用 Loop SUM_LOOP 以 FORCURKEY 排序輸出。這是第 9 節「Calculations 不能跨幣別加總」的標準解法。改寫如下，兩種擇一：

*& 寫法 A：保留原廠結構。Program Lines 節點 ADD_PRICES
*&   位置：表格 BOOKINGS 的主區域，價格文字節點之後

*&---------------------------------------------------------------*
*& 寫法 B：一次算完。Global Definitions → Initialization
*&   Input 參數：IT_BOOKINGS、WA_CUSTOMERS    Output 參數：IT_SUM

it_sum = VALUE #(
  FOR GROUPS grp OF b IN it_bookings
      WHERE ( customid = wa_customers-id )
      GROUP BY b-forcurkey ASCENDING
  ( forcurkey = grp
    forcuram  = REDUCE #( INIT s = CONV bc470_forcur-forcuram( 0 )
                          FOR m IN GROUP grp
                          NEXT s = s + m-forcuram ) ) ).

練習與自我檢核

  1. Main Window 規則：一張表單可以有幾個主窗口？各頁的主窗口哪些屬性必須一致、哪些可以不同？沒有主窗口的頁面若把「下一頁」設成自己會怎樣？
    參考答案要點：只能一個；寬度必須相同，高度與位置可不同；無窮迴圈，系統處理三頁後終止。
  2. 次窗口與主窗口的差異：次窗口放不下的文字會怎樣？哪兩種 6.10 新窗口類型也有相同行為？
    參考答案要點：直接截斷不輸出；Final Window 與 Copies Window。只有主窗口會把剩餘文字接到下一頁。
  3. 頁碼：頁面屬性設了阿拉伯數字頁碼，為什麼列印出來還是沒有頁碼？要印「第 X 頁共 Y 頁」有什麼效能代價？
    參考答案要點：必須在文字節點輸出 &SFSY-PAGE&；用 SFSY-FORMPAGES 會讓所有輸出頁留在記憶體直到表單結束（JOBPAGES 則到整個列印請求結束）。
  4. 勘誤題：强晟筆記說「不要在條件中使用 FORMPAGES、JOBPAGES」，新版原廠教材怎麼說？4.6C 的 set_late_window 技巧升級後該怎麼處理？
    參考答案要點：這兩個欄位只能在 Final Window 的條件中使用；刪除 set_late_window 程式碼，把該次窗口改成 Final Window（SAP Note 359009）。
  5. 文字連接：兩個連續文字節點，第二個選「直接追加」，第一個有框線，結果為何？
    參考答案要點：前一節點有框線或陰影時，一律以「新段落」接上。
  6. 文字類型選擇：公司銀行帳號要印在 20 張表單上，應該用哪種文字類型？為什麼不建議建 SAPscript 標準文字？
    參考答案要點：Smart Forms 文字模組；SAPscript 文字無法在 Smart Forms 維護預覽、無法檢查欄位、不自動進傳輸、Client 相依。
  7. 介面參數：Export 參數沒勾「傳值」、表單中途中止，程式端會看到什麼？Tables 參數可以用巢狀表嗎？
    參考答案要點：傳參照，中止前的修改已反映到程式端；Tables 參數必須是非巢狀表類型且永遠傳參照，巢狀表改用 Import 參數。
  8. 表格 vs 範本：列出三個差異，並說明表格為什麼只能放主窗口。
    參考答案要點：表格長度執行期決定、行類型不能設高度、範本版面固定需設行高、範本不可巢狀、範本儲存格放不下的內容不輸出；表格長度可變，放次窗口會被截斷。
  9. 控制層級與表尾：如何在表格中做「依航空公司小計」？表尾為什麼要設高度？取消勾選表尾會怎樣？
    參考答案要點：資料頁籤設排序準則 CARRID 並勾 Event on Sort End，在事件節點下放 Program Lines 計算與文字節點輸出；排版器需預留空間；表尾下所有節點遺失。
  10. Calculations 限制：訂位金額有 EUR 和 USD，可以用 Calculations 頁籤的 Total 嗎？For field name 要填 WA-CARRID 還是 CARRID？
    參考答案要點：不行，它不做幣別換算，要用 Program Lines 依幣別分組加總；填 CARRID（不含輸出區名稱）。
  11. Alternative 的兩個條件：Alternative 節點的一般屬性條件和條件頁籤的條件各控制什麼？
    參考答案要點：一般屬性決定走 TRUE 或 FALSE；條件頁籤決定整個 Alternative 是否處理。
  12. Command 節點：在次窗口中放「Go to new page」會怎樣？手動換頁後本頁次窗口還會處理嗎？
    參考答案要點：只能用在主窗口，否則函數模組報錯；主窗口中其後節點不在本頁處理，但本頁次窗口在換頁前仍會處理。
  13. 同一 Spool：寫出 100 位客戶的發票放進同一個 Spool 時，第 1、第 2～99、第 100 次呼叫的 NO_OPEN／NO_CLOSE 值。
    參考答案要點：第一次 space／X；中間 X／X；最後 X／space。
  14. 傳輸：表單從 DEV 傳到 PRD 後，產生的函數模組名稱一樣嗎？哪些物件必須手動加入傳輸請求？
    參考答案要點：不一定一樣，函數不隨傳輸，在目標系統第一次呼叫時產生，因此必須用 SSF_FUNCTION_MODULE_NAME；Include Text（SE09 或 RSTXTRAN）與 SE78 圖形要手動加。
  15. Customizing：發票表單換成 Z 版本要到哪裡設定？Form 欄位要填什麼？催款設定時「表單不存在」的警告要怎麼處理？
    參考答案要點：VOK2 → 輸出 → 處理程式 → 發票，RD00／V3，填程式、FORM routine、Smart Form 欄位；Form 欄位留空（SAPscript 用）；催款警告可忽略，系統只檢查 SAPscript 表單。
  16. 字型：新印表機部分字型印不出來，列出六個處理步驟；SE73 的印表機字型字級 240 代表幾點？
    參考答案要點：SPAD 複製設備類型（HPLJ4→ZHPLJ4）、建列印控制 SFxxx、必要時建字型族、定義系統字型、定義印表機字型並指派列印控制、把新設備類型指派給輸出裝置；24 點（單位 1/10 點，强晟筆記寫 1/20 點有誤）。
  17. SAPscript 轉換：移轉 SAPscript 表單後，哪些東西會遺失？列印程式要怎麼改？
    參考答案要點：段落與字元格式定義（改用樣式轉換）、文字元素的段落格式與 SAPscript 指令；欄位要明確定義；OPEN_FORM／START_FORM／END_FORM／CLOSE_FORM 換成產生函數的一次呼叫，WRITE_FORM 的邏輯搬進表單。
  18. 實作題：用航班資料模型做一張 Fly & Smile 發票：地址窗口（SCUSTOM）、Logo 依國別動態決定、主窗口表格列出 SBOOK 並依航空公司小計（注意多幣別）、Final Window 在第一頁印「共 Y 頁」、Copies Window 在副本印「COPY」。列印程式依本章第 12 節改寫成同一 Spool 輸出多位客戶，並在程式與表單初始化兩處都明確排序。
    參考答案要點：Copies Window 的條件查 SFSY-COPYCOUNT0 > 0 或選「只在副本」；小計用 Program Lines 依 FORCURKEY 分組；排序原因是 HANA 沒有預設排序，不排序時小計分組與列印順序會不穩定。
  19. L29 4.6C 與 6.10 表格：同樣要印「航班／日期／價格」三欄，4.6C 舊式表格和 6.10 表格各自怎麼決定文字落在哪一格？為什麼 6.10 起「預設行類型」變得不重要？
    參考答案要點：4.6C 在文字節點輸出選項勾 New Line＋行類型、New Cell；6.10 在表頭／主區域／表尾建 Table Line 並選行類型，系統自動產生儲存格節點，文字掛在儲存格下。每個 Table Line 都明確指定行類型，所以預設類型已不重要。
  20. L29 PROG 解答找碴：原廠解答 SAPBC470_PROGS 每次呼叫後都無條件設 NO_OPEN = 'X'，選擇畫面預設 so_carr = 'AA' TO 'LH'。各有什麼風險？
    參考答案要點：第一位客戶就失敗時 Spool 沒開，後續帶 NO_OPEN 的呼叫會全部失敗，要改成第一次成功後才設；區間比的是字典序，會把 AZ、BA、DL 等夾在中間的航空公司一起選進來，改用列舉（EQ 多筆）。
  21. L29 FLOW 練習：WHICH_CLERK 的 Alternative 為什麼一定要放在 GREETINGS 之前？SHOW_TERMS 從 PROTECT 資料夾右鍵建立後還要做什麼？
    參考答案要點：Program Lines 的結果只影響之後處理的節點，GREETINGS 輸出職員名之前必須先算出 CLERK；從資料夾右鍵建立的節點預設在資料夾之下，要拖到資料夾之後，否則換頁指令會變成受頁面保護的內容之一。
  22. 勘誤題：Include Text 的段落格式能不能在 Smart Forms 覆蓋？Standard Paragraph 與 First Paragraph 各對應 SAPscript INCLUDE 的哪個附加？
    參考答案要點：可以（4.6C 需 SP23，Note 422120）；Standard Paragraph 對應 PARAGRAPH，套用到所有標準段落；First Paragraph 對應 NEW-PARAGRAPH，只管第一段。
