3. 開發前的三個提醒

一、HANA 沒有預設排序。同一支 SELECT 不加 ORDER BY，在 HANA 上兩次執行可能回傳不同順序。任何「取第一筆」的邏輯（SELECT SINGLE、UP TO 1 ROWS、READ TABLE ... INDEX 1）都必須先明確排序，否則結果會時對時錯。實務上就發生過成本評價同時存在 item category「H」與 cost component「E」兩種角度、程式沒排序而一下抓到 H、一下抓到 E，導致成本忽高忽低的案例。
二、條件用「列舉」比用「區間」安全。選擇條件用區間（BT）時，比較的是字典序而非業務語意，號碼段不連續、有 ALPHA 前導零、編碼規則改過的時候就會漏抓或多抓；改成逐項列舉（多筆 EQ）結果才正確。詳見 3-1 選擇畫面。
三、先找標準，再想客製。順序永遠是：標準設定 → BAdI／Enhancement Spot → Enhancement Point → 修改標準（Modification）。每往右一步，升級時的維護成本就高一個量級。
