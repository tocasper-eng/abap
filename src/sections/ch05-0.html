1. 專區緣起：强晟是誰，這批筆記為什麼值得留

强晟（筆記署名 qiangsheng，部落格 qiangsheng.cnblogs.com）是 2006 年前後進入 SAP 領域的中國大陸企業內部開發人員。他在 BC400 筆記前言中說明了寫這套筆記的原因，重點整理如下（原文為簡體，已轉為台灣用語）：

  • 他從「去年 5 月」開始接觸 SAP，一年多下來發現網路上的資料很少，中文資料更少；最好的學習來源是 SAP Help 與 標準教材。
  • SAP Help 是隨軟體發布的完整線上說明，但太龐大，讓人望而卻步；標準教材則是以教學為目的編寫，分 Level 100、200、300 三個難度等級（100 最基礎、200 較深入、300 最進階），反而更適合學習。
  • SAP 自稱標準教材不適合自學，主因是課堂示範要在 SAP 專用訓練伺服器上進行、教材本身不附範例原始碼；但他認為教材本身寫得清楚易懂。
  • 「假如一開始顧問公司就提供標準教材的訓練，我們內部團隊的實力會強得多。」——為了讓後來的入門者不重蹈覆轍，他把自學筆記公開分享。

從各本前言的日期可以還原他的學習節奏：2007 年 5 月 29 日完成 BC400，接著 BC401（6/23）、BC402（6/23）、BC404（7/1）、BC405（7/2）、BC406（7/9）、BC407（7/13）、BC410（7/19）、BC412 與 BC414（9/19）、BC415（11/9）、BC430（12/9）、BC470（12/17）、BC480（12/23），2008 年再完成 BC420（3/18）、BC425（4/6）、BC490（5/5）、BC440（6/18）、BC427（6/23）。一年多、19 本、約 3,900 頁。他在 BC402 前言自承：原廠教材一半篇幅是原始碼，筆記不可能全抄，實際教學內容約佔一半，一本大約 5～8 天讀完。

這批筆記的時代背景是 R/3 4.6C／R/3 Enterprise 4.7 過渡到 ECC 6.0（SAP NetWeaver 7.0）的時期：他手上的 BC401 是 2002 年針對 R/3 4.6A 的版本，BC402 是 2001 年針對 4.6C 的版本；BC427 前言則說明 Enhancement Framework 是「SAP NetWeaver 7.0 平台新增」。所以筆記裡的程式碼大量使用 TABLES、WITH HEADER LINE、SELECT … ENDSELECT、REUSE_ALV_* 這類寫法——本專區各章一律改寫成 S/4HANA 可用的現代 ABAP，舊寫法只在對照表中以文字說明。

資料夾中另附 SAP 原廠英文 Participant Handbook：版次標示為 Col15～Col19（Course Version 15～19，BIT750 為 03），版權年多為 2022（BC425 為 2023）。Col 版次是原廠教材的改版序號，數字越大越新；這批 Col18 教材的內容已經是 NetWeaver 7.5x／S/4HANA 時代的觀點——例如 Col18 BC402 第一單元就在講「從敘述句走向運算式與函數」、inline declaration 與新版 Open SQL 語法，BC404 已改教 Eclipse（ADT），SAPNW 概覽第一課就是 SAP HANA 與 S/4HANA。一邊是 2007 年的中文入門視角，一邊是 2022 年的原廠現況，兩者對照，正好看得出 ABAP 十五年來變了什麼、沒變什麼。

筆記的價值不在語法（語法已經過時），而在觀念的完整度：LUW 與 SAP 鎖、PBO/PAI、資料字典的相依關係、增強的層級、效能分析的方法論——這些原理從 R/3 到 S/4HANA 幾乎沒變。强晟在 BC406 前言引用中國 SAP 圈前輩 w39〈自學 SAP 三道坎〉的一句話：「堅持！就這樣堅持下去！給自己兩年的時間。」這句話今天一樣適用。

在系統裡確認版本，不要憑印象。以下程式讀取軟體元件版本表 CVERS（也可用 SAP GUI 選單「系統 → 狀態」看元件清單）：

REPORT zr_show_release.

" 讀取關鍵軟體元件版本：SAP_BASIS 決定可用的 ABAP 語法，S4CORE 表示 S/4HANA
SELECT component, release, extrelease, comp_type
  FROM cvers
  WHERE component IN ( 'SAP_BASIS', 'SAP_ABA', 'SAP_GWFND', 'S4CORE' )
  ORDER BY component
  INTO TABLE @DATA(lt_comp).

IF lt_comp IS INITIAL.
  MESSAGE '讀不到 CVERS，請確認權限' TYPE 'I'.
  RETURN.
ENDIF.

DATA lv_basis TYPE cvers-release.
lv_basis = VALUE #( lt_comp[ component = 'SAP_BASIS' ]-release OPTIONAL ).
DATA(lv_is_s4) = xsdbool( line_exists( lt_comp[ component = 'S4CORE' ] ) ).

cl_demo_output=>write( lt_comp ).
cl_demo_output=>write( |SAP_BASIS = { lv_basis }；S/4HANA = { COND string( WHEN lv_is_s4 = abap_true THEN '是' ELSE '否' ) }| ).
cl_demo_output=>display( ).
SAP_BASIS 的 release 欄位是「753」這種三位數字串，而不是「7.53」。程式裡若要依版本走不同邏輯，比較的是字串，也就是「字典序」：三位數時還看不出問題，一旦遇到支援套件字串或格式不同的元件版本就會出錯。版本判斷請寫明確的列舉清單（例如 '753'、'754'、'755'），不要寫「大於等於某值」的區間。這就是 Casper 第二條經驗的縮小版（見 §12）。

5. TAW 組合課與 ABAP 認證

TAW 系列是 SAP 把多門 BC 課程濃縮成「學院（Academy）」形式的組合課，專為準備開發者認證而設計。本資料夾沒有 TAW 教材本身，但 Col18 各課的測驗解答會註明「本題內容請參閱 BCxxx 或 TAWxx 的哪一單元」，從這些交叉引用可以還原對應關係（以下皆為教材中實際出現的標註）：

組合課教材中出現的對應 BC 課程主題範圍

BC401、BC403、BC404、BC407、BC460、BC470、BC480、BC490、BIT750、SAPNW 的測驗解答沒有 TAW 標註，本專區不臆測它們屬於哪一門 TAW。

認證考試：

  • C_TAW12（例如 C_TAW12_750，SAP Certified Development Associate – ABAP with SAP NetWeaver 7.50）：傳統 ABAP 開發者認證，範圍對應上表 TAW10／TAW11e／TAW12，也就是工作台、字典、報表、Dynpro、OO、增強、Web Dynpro 這一整套「經典 ABAP」。
  • C_ABAPD（SAP Certified Associate – Back-End Developer – ABAP Cloud，考試代碼後綴為版本年月）：新一代認證，重點轉向 ABAP Cloud 開發模型——ABAP SQL、CDS、RAP（RESTful ABAP Programming Model）、物件導向與 ADT，已不考 Dynpro、SAPscript 這類經典技術。
認證的考試代碼、題數、及格分數與是否停考，SAP 每年都會調整。本節只描述兩者的定位差異；實際報名前請以 SAP Learning 官方網站當下公告為準，不要依本頁或任何舊講義的數字備考。

6. 學習路線 A：報表開發者

目標：接到「幫我出一張報表」的需求時，能判斷該用標準報表、Query、CDS 還是自寫程式，寫出來的程式正確、夠快、使用者看得懂。這是大多數 ABAPer 的第一份工作，也是 Casper 課程的主軸。

順序第五部（原廠觀點）搭配第一～四部（實作）讀完要會什麼

路線 A 的終點形態是這樣的程式：選擇畫面 → 一次 SQL 取回 → CL_SALV_TABLE 輸出。它取代了强晟筆記中「邏輯資料庫＋GET 事件＋WRITE 清單」的寫法：

REPORT zr_flight_occupancy.

DATA gv_fldate TYPE sflight-fldate.
PARAMETERS     p_carr TYPE s_carr_id OBLIGATORY DEFAULT 'LH'.
SELECT-OPTIONS s_date FOR gv_fldate.

START-OF-SELECTION.
  " 明列欄位、主機變數加 @、明確 ORDER BY（HANA 沒有預設排序）
  SELECT f~carrid, f~connid, f~fldate, p~cityfrom, p~cityto,
         f~seatsmax, f~seatsocc
    FROM sflight AS f
    INNER JOIN spfli AS p ON p~carrid = f~carrid
                         AND p~connid = f~connid
    WHERE f~carrid = @p_carr
      AND f~fldate IN @s_date
    ORDER BY f~carrid, f~connid, f~fldate
    INTO TABLE @DATA(gt_flight).

  IF gt_flight IS INITIAL.
    MESSAGE '查無資料' TYPE 'S' DISPLAY LIKE 'W'.
    RETURN.
  ENDIF.

  TRY.
      cl_salv_table=>factory( IMPORTING r_salv_table = DATA(go_alv)
                              CHANGING  t_table      = gt_flight ).
      go_alv->get_functions( )->set_all( abap_true ).
      go_alv->get_columns( )->set_optimize( abap_true ).
      go_alv->get_display_settings( )->set_striped_pattern( abap_true ).
      go_alv->display( ).
    CATCH cx_salv_msg INTO DATA(gx_salv).
      MESSAGE gx_salv TYPE 'I' DISPLAY LIKE 'E'.
  ENDTRY.
報表若要加「載客率」這類計算欄位，可在 SQL 中用 division( ) 等 SQL 函數（7.50 以上）推給資料庫算。資料量大到 SALV 吃不下時，改用 ALV with IDA（CL_SALV_GUI_TABLE_IDA），把分頁與彙總推給 HANA，詳見 5-6 章 與 5-21 章。

介面程式的條件請一律用列舉：要拋轉哪些工廠、哪些單據類型，就在設定表裡一筆一筆列出來（多筆 EQ），不要寫「工廠 1000～1999」這種區間。號碼段有缺口、編碼規則改過、ALPHA 前導零，區間都會悄悄多抓或漏抓——而介面多抓一筆，對方系統就多一張單。

以 BC405／BC407 常用的航班邏輯資料庫 F1S（SPFLI → SFLIGHT → SBOOK）為例，S/4HANA 的替代是一支 CDS View。以 1809 為基準寫 DDIC-based 版本：

@AbapCatalog.sqlViewName: 'ZVFLTBOOK'
@AbapCatalog.compiler.compareFilter: true
@AccessControl.authorizationCheck: #NOT_REQUIRED
@EndUserText.label: '航班訂位（取代 LDB F1S 的 GET 巢狀讀取）'
define view Z_I_FlightBooking
  as select from spfli   as p
    inner join   sflight as f on  f.carrid = p.carrid
                              and f.connid = p.connid
    inner join   sbook   as b on  b.carrid = f.carrid
                              and b.connid = f.connid
                              and b.fldate = f.fldate
{
  key p.carrid,
  key p.connid,
  key f.fldate,
  key b.bookid,
      p.cityfrom,
      p.cityto,
      b.customid,
      b.forcuram,
      b.forcurkey
}
版本門檻：define view entity（不需 @AbapCatalog.sqlViewName）要 ABAP 7.55（S/4HANA 2020）以上；在 1809 請用上面的 DDIC-based 寫法。實務上正式環境請把 authorizationCheck 設為 #CHECK 並建立 DCL 權限；此處示範資料為訓練用航班模型，所以設 #NOT_REQUIRED。

BC440 的 WebRFC 在今天由 ICF 服務取代。最小可用的 HTTP 處理類別如下（在 SICF 建立服務節點並指定此類別）：

CLASS zcl_http_connections DEFINITION PUBLIC FINAL CREATE PUBLIC.
  PUBLIC SECTION.
    INTERFACES if_http_extension.
ENDCLASS.

CLASS zcl_http_connections IMPLEMENTATION.
  METHOD if_http_extension~handle_request.
    DATA(lv_carrid) = CONV s_carr_id( to_upper( server->request->get_form_field( 'carrid' ) ) ).

    SELECT carrid, connid, cityfrom, cityto, deptime
      FROM spfli
      WHERE carrid = @lv_carrid
      ORDER BY connid
      INTO TABLE @DATA(lt_conn).

    DATA(lv_json) = /ui2/cl_json=>serialize(
                      data        = lt_conn
                      pretty_name = /ui2/cl_json=>pretty_mode-camel_case ).

    server->response->set_content_type( 'application/json; charset=utf-8' ).
    server->response->set_cdata( lv_json ).
    server->response->set_status( code = 200 reason = 'OK' ).
  ENDMETHOD.
ENDCLASS.
自寫 ICF 處理類別適合小型、內部的整合。正式對外的 API 在 S/4HANA 請優先用 OData（SEGW，或 7.54 以上以 RAP 的 Service Definition／Binding 發布），權限、CSRF 防護、分頁與中繼資料都由框架處理。詳見 5-17 章。

11. 如何使用本專區

  1. 先讀每章 §1「課程定位與教材對照」：每一章第一節都有一張對照表，列出「單元 ↔ 强晟筆記頁碼 ↔ 原廠教材 Unit／Lesson 與頁碼 ↔ 本章小節」。想看原文圖表或完整練習題，照頁碼打開原始 PDF 即可。
  2. 頁碼是 PDF 頁碼：表中的「p27」是 PDF 閱讀器裡的第 27 頁（含封面），不是教材印刷頁碼（原廠教材前幾頁用羅馬數字 i、ii…，因此兩者會差幾頁）。
  3. 先查第一～四部，再查第五部：第一～四部是 Casper 課程的實作路線（照著做就能跑）；第五部是原廠課程的規則全集（為什麼、有哪些限制、面試會問什麼）。兩邊互相連結，建議兩者對照看。
  4. 用搜尋框找課號或 TCODE：輸入「BC414」「SM13」「ENQUEUE」都能直接跳到相關小節。
  5. 程式碼都已現代化：專區內所有程式都是 S/4HANA 1809 以上能直接用的寫法；原教材的舊語法只在各章的對照表中以文字說明。要把舊程式翻新，請搭配 附錄 舊語法速查。
  6. 每章最後的「練習與自我檢核」附有參考答案要點，可當作讀書會或新人訓練的題庫。
建議的查閱姿勢：遇到專案問題 → 先在第一～四部找「怎麼做」→ 做不出來或結果怪怪的 → 到第五部對應章找「原廠怎麼規定」→ 還不夠 → 依 §1 對照表的頁碼翻原始 PDF。三層由淺到深，通常第二層就能解決。

12. 貫穿全專區的三條實務經驗

原廠教材教的是「規則」，但專案上真正出事的往往是規則之間的縫隙。Casper 在專案上踩過的三個坑，會在第五部各章反覆出現：

  • HANA 沒有預設排序（BC400、BC402、BC490、BC414）：舊資料庫常「剛好」照主鍵回傳，HANA 不會。成本評價同時存在 item category「H」與 cost component「E」兩種角度，兩者的成本構成欄位數量不同；程式沒排序時一下抓到 H、一下抓到 E，成本就不穩定——該案最後的結論是固定抓 H。任何「取第一筆」都必須先明確 ORDER BY，或乾脆在 WHERE 條件中鎖定唯一值。
  • 條件用列舉（多筆 EQ）比用區間（BT）安全（BC405、BC407、BC415、BC420）：區間比的是字典序，不是業務語意。
  • 先找標準，再想客製（BC407、BC425、BC427）：標準設定 → BAdI／Enhancement Spot → Enhancement Point → 修改標準，每往右一步，升級成本高一個量級。
" (1) 取「最新一筆」成本估算：先明確排序，再取第一筆
SELECT matnr, werks, kalka, kadky, tvers, kalnr
  FROM keko
  WHERE matnr = @lv_matnr
    AND werks = @lv_werks
    AND kalka = @lv_kalka                 " 鎖定成本估算類型，不要讓系統「隨便挑」
  ORDER BY kadky DESCENDING, tvers DESCENDING, kalnr DESCENDING
  INTO TABLE @DATA(lt_keko)
  UP TO 1 ROWS.

IF lt_keko IS NOT INITIAL.
  DATA(ls_latest) = lt_keko[ 1 ].
ENDIF.

" (2) 條件用列舉：每個公司代碼明確列出，而不是 BT '1000' AND '1999'
DATA lt_bukrs TYPE RANGE OF bukrs.
lt_bukrs = VALUE #( sign = 'I' option = 'EQ'
                    ( low = '1000' )
                    ( low = '1100' )
                    ( low = '1300' ) ).

SELECT bukrs, butxt, waers
  FROM t001
  WHERE bukrs IN @lt_bukrs
  ORDER BY bukrs
  INTO TABLE @DATA(lt_company).
SELECT SINGLE 在條件不足以唯一定位一筆時，回傳哪一筆是「未定義」的——HANA 上真的會每次不同。SELECT SINGLE 只用在 WHERE 已涵蓋完整主鍵的情況；其他「取一筆」一律寫 ORDER BY … UP TO 1 ROWS。

  1. 筆記：2007～2008，R/3 4.6～ECC 6.0（NetWeaver 7.0）時代，手上教材有 2001／2002 的 4.6C／4.6A 版；Col18：2022 年版，NetWeaver 7.5x／S/4HANA 觀點。筆記程式大量使用 TABLES、HEADER LINE、SELECT…ENDSELECT、REUSE_ALV，不可直接照抄。

  3. ABAP Platform 1809，SAP_BASIS 7.53；程式碼以 ABAP 7.52 語法為下限，7.54 以上的語法（如 +=、View Entity）會另標版本門檻。
  4. BC410 → TAW10 Part II；BC414 → TAW11e；BC425 → TAW12。
  5. C_TAW12：經典 ABAP（工作台、字典、報表、Dynpro、OO、增強、Web Dynpro）；C_ABAPD：ABAP Cloud 開發模型（ABAP SQL、CDS、RAP、ADT）。代碼與規則以 SAP Learning 官網為準。
  6. 5-1 BC400（配 1-1、2-1）→ 5-16 BC430（配 1-2、1-3）→ 5-8 BC407（配 1-4）→ 5-3 BC402（配 2-2）→ 5-6／5-7（配 3-1、2-3）→ 5-2（配 3-2、2-4）→ 5-4、5-21（除錯與效能）。
  7. LDB → SQL／CDS＋SALV；WebRFC → ICF／OData；SAPscript → Adobe Forms；Classic BAdI → New BAdI；LSMW → Migration Cockpit；SE30 → SAT；REUSE_ALV → CL_SALV_TABLE；ITS WebTransaction → Fiori＋OData；Web Dynpro → Fiori Elements＋RAP；EXEC SQL → AMDP。
