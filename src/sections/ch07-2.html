2. 本地類別：定義、實作、實例屬性與靜態屬性（4.1）

觀念：類別分成「定義部分」（CLASS … DEFINITION，宣告屬性、方法、事件與可見性）與「實作部分」（CLASS … IMPLEMENTATION，寫方法本體）。寫在程式裡的叫本地類別（local class），只有這支程式看得到；用 SE24 或 ADT 建的叫全域類別（global class），整個系統都能用。

  • 實例屬性（DATA）：每個物件各一份，要先建立物件才能存取，寫法 lo_obj->mv_value。
  • 靜態屬性（CLASS-DATA）：整個類別只有一份，所有物件共用，不必建立物件即可存取，寫法 zlcl_class_local=>gv_cl_value。
  • 書中的命名慣例：實例屬性 mv_（member variable）、靜態屬性 gv_、參數 iv_／ev_／cv_／rv_、物件參考 lo_／go_。
REPORT zrep_class_local_01.

與原範例的差異：

  • 原範例用 DATA … TYPE REF TO 先宣告、再 CREATE OBJECT、再 CALL METHOD … EXPORTING；改寫為 NEW ＋內嵌宣告＋函數式呼叫，一行完成。
  • 原範例本地類別取名 ZLCL_CLASS_LOCAL。本地類別不進 TADIR、不受客戶命名空間約束，SAP 慣例是 LCL_ 開頭；加 Z 反而容易讓人誤以為是 SE24 全域類別，本章改為 LCL_CLASS_LOCAL。
  • 原範例的 display_value 直接 WRITE；改成回傳字串，由呼叫端決定怎麼輸出（清單、ALV、Log），類別才能重用、也才能寫單元測試。
  • 原範例只建一個物件，看不出「靜態屬性共用」的效果；改寫版建兩個物件對照。
靜態屬性等於「披著類別外衣的全域變數」，在同一個內部階段（internal session）內所有物件都看得到、都改得到。只拿來放常數、快取（buffer）或計數器；業務資料放實例屬性。

3. 全域類別（SE24）與四種方法參數（4.2）

觀念：方法參數的方向是從方法的角度命名的——IMPORTING 是方法收進來、EXPORTING 是方法送出去、CHANGING 是進來再出去、RETURNING 是唯一回傳值（必須 VALUE( ) 傳值）。呼叫端的關鍵字方向剛好相反：傳入用 EXPORTING、接收用 IMPORTING、回傳值用 RECEIVING。

全域類別 ZCL_CLASS_MATL 在書中是用 SE24 的表格式編輯器建的（（依講義步驟整理）：SE24 → 輸入類別名 → Create → Class Type 選 Usual ABAP Class → Methods 頁籤新增 TEST_PARAMETER → Parameters 按鈕逐一輸入參數與 Type → 雙擊方法寫本體 → Activate）。下面是切到「Source Code-Based」或在 ADT 中看到的等價原始碼：

CLASS zcl_class_matl DEFINITION PUBLIC FINAL CREATE PUBLIC.
  PUBLIC SECTION.
    METHODS test_parameter
      IMPORTING iv_name        TYPE char30
      EXPORTING ev_name        TYPE char30
      CHANGING  cv_name        TYPE char30
      RETURNING VALUE(rv_name) TYPE char30.
ENDCLASS.

CLASS zcl_class_matl IMPLEMENTATION.
  METHOD test_parameter.
    ev_name = |E:{ iv_name }|.          "送出去
    cv_name = |C:{ cv_name }|.          "進來改過再出去
    rv_name = |R:{ iv_name }|.          "唯一回傳值
  ENDMETHOD.
ENDCLASS.

" 呼叫端 REPORT zrep_cls_002
"------------------------------------------------------------
REPORT zrep_cls_002.

START-OF-SELECTION.
  DATA(lv_c_name) = CONV char30( 'changing in class' ).

  DATA(lv_r_name) = NEW zcl_class_matl( )->test_parameter(
    EXPORTING iv_name = 'importing into class'
    IMPORTING ev_name = DATA(lv_e_name)
    CHANGING  cv_name = lv_c_name ).

  cl_demo_output=>display( |E={ lv_e_name } / C={ lv_c_name } / R={ lv_r_name }| ).

與原範例的差異：原範例以 CALL METHOD … EXPORTING / IMPORTING / CHANGING / RECEIVING 四段一起呼叫，並用四個全域變數加 WRITE 印出；改寫成函數式呼叫，回傳值直接指派，IMPORTING 內嵌宣告 DATA(lv_e_name)。原範例把變數名 gv_e_name 預設為 'exporting from class' 再傳入，但 EXPORTING 參數在方法開始時不會帶入呼叫端的值（傳參考時可讀到但不該依賴），這個初值沒有意義。

RETURNING 與 EXPORTING／CHANGING 並存：早期（7.0 以前）函數式方法只能有 IMPORTING＋RETURNING；自 7.02 起放寬，1809 可用。但「一個方法同時有回傳值又有輸出參數」是設計異味——呼叫端看 x = obj->m( ) 時不會意識到還有副作用。新寫的方法：要嘛只有 RETURNING，要嘛只用 EXPORTING。
參數預設是傳參考（by reference）；IMPORTING 傳參考時在方法內唯讀。需要在方法內修改輸入值的副本，宣告成 IMPORTING VALUE(iv_x)。RETURNING 一律傳值。

5. 事件：宣告、觸發與註冊處理方法（4.7、4.8）

觀念：事件是「物件對外廣播發生了什麼事」，觸發者不知道誰在聽。三個步驟：① 在類別中 EVENTS 宣告；② 在方法中 RAISE EVENT 觸發；③ 監聽者用 METHODS … FOR EVENT … OF … 宣告處理方法，並以 SET HANDLER 在執行期註冊。沒有註冊，RAISE EVENT 就什麼也不會發生（不會報錯）。

4.7 是 ZCL_INVENTORY 的 CHECK_MATERIAL：讀 MARA，查無資料就觸發 MATERIAL_NOT_FOUND；4.8 是呼叫端，把同一個物件的 HANDLE_MATERIAL_NOT_FOUND 註冊為處理方法。

CLASS zcl_inventory DEFINITION PUBLIC FINAL CREATE PUBLIC.
  PUBLIC SECTION.
    TYPES: BEGIN OF ty_material,
             matnr TYPE mara-matnr,
             mtart TYPE mara-mtart,
             meins TYPE mara-meins,
             ersda TYPE mara-ersda,
             ernam TYPE mara-ernam,
             laeda TYPE mara-laeda,
             aenam TYPE mara-aenam,
           END OF ty_material,
           tt_material TYPE STANDARD TABLE OF ty_material WITH EMPTY KEY,
           tt_matnr    TYPE STANDARD TABLE OF matnr WITH EMPTY KEY.

    EVENTS material_not_found
      EXPORTING VALUE(ev_count) TYPE i OPTIONAL.   "事件參數只能 EXPORTING 傳值

    METHODS check_material
      IMPORTING it_matnr           TYPE tt_matnr
      RETURNING VALUE(rt_material) TYPE tt_material.

    METHODS handle_material_not_found
      FOR EVENT material_not_found OF zcl_inventory
      IMPORTING ev_count sender.
ENDCLASS.

CLASS zcl_inventory IMPLEMENTATION.
  METHOD check_material.
    CHECK it_matnr IS NOT INITIAL.        "FOR ALL ENTRIES 空表會讀全表，先擋
    SELECT matnr, mtart, meins, ersda, ernam, laeda, aenam
      FROM mara
      FOR ALL ENTRIES IN @it_matnr
      WHERE matnr = @it_matnr-table_line
      INTO TABLE @rt_material.

    IF rt_material IS INITIAL.
      RAISE EVENT material_not_found EXPORTING ev_count = lines( it_matnr ).
    ENDIF.
    SORT rt_material BY matnr.            "HANA 沒有預設排序，要自己排
  ENDMETHOD.

  METHOD handle_material_not_found.
    MESSAGE |查詢 { ev_count } 個料號，MARA 中皆不存在| TYPE 'S' DISPLAY LIKE 'W'.
  ENDMETHOD.
ENDCLASS.

與原範例的差異／範例錯誤：

  • 欄位不一致：4.7 的 SELECT 只選了 mandt、matnr、ersda、ernam、laeda、aenam、mtart，但 4.8 輸出 gs_mara-meins——MEINS 從未被讀取，輸出永遠是空白。改寫版把 MEINS 加進選取欄位，並改用只含所需欄位的結構，不再 INTO TABLE 整個 MARA 結構。
  • 命名錯誤：4.8 的 PARAMETERS p_mtart TYPE mara-matnr，名字是物料類型（MTART），型別卻是料號（MATNR）。依程式用途（傳給 iv_material_id）應為料號。
  • LIKE 的陷阱：原程式 WHERE matnr LIKE iv_material_id，使用者沒輸入 % 時等於 =，但輸入料號沒補前導零（ALPHA 轉換）就會查不到。PARAMETERS 參照 MARA-MATNR 會自動做轉換，改寫成內表傳入時也要確保值已是內部格式。
  • 原程式 SELECT 沒有 @、欄位以空白分隔（舊 Open SQL）、沒有 ORDER BY；改成 ABAP SQL 新語法並在讀出後排序。
  • 原程式把 CREATE OBJECT 與 SET HANDLER 寫在 PARAMETERS 前面、事件區塊外面，這些敘述其實會被併入 START-OF-SELECTION 執行，讀起來卻像宣告區；改寫版全部放進 START-OF-SELECTION。
  • 原程式用 LOOP … WRITE 輸出；改用 CL_SALV_TABLE。
Casper 實務經驗 ① ②：HANA 沒有預設排序，原範例「讀出來直接印」在 HANA 上每次順序可能不同，任何取第一筆、或要比對前後結果的邏輯都要先 SORT 或 ORDER BY。查詢條件用列舉（多筆 EQ）比用 LIKE／區間安全——區間比的是字典序，遇到前導零、號碼段不連續就會漏抓或多抓，所以改寫版的選擇畫面加了 NO INTERVALS。
「查無資料」用事件通知只是書中為了示範事件語法。實務上，查無資料通常直接回傳空表由呼叫端判斷，或丟出類別式例外；事件適合「一對多、觸發者不在乎誰聽」的情境，例如 ALV 的 DOUBLE_CLICK、TOOLBAR（見 3-2 章 OOALV）。

6. 建構子與靜態建構子（4.9～4.11）

觀念：

實例建構子 CONSTRUCTOR靜態建構子 CLASS_CONSTRUCTOR
宣告METHODS constructorCLASS-METHODS class_constructor
執行時機每次 NEW／CREATE OBJECT 時執行一次每個內部階段中，第一次存取該類別（建立物件、存取靜態元件等）之前執行一次
參數只能有 IMPORTING（可 OPTIONAL），可宣告例外不能有任何參數、不能宣告例外
可存取實例與靜態元件只能存取靜態元件
可見性放在 PUBLIC SECTION（或以 CREATE PRIVATE 限制建立）固定在 PUBLIC SECTION

    CLASS-METHODS class_constructor.

與原範例的差異／範例錯誤：

  • 4.10 的命名與規則衝突：CLASS_CONSTRUCTOR 內指派 mv_init2。靜態建構子只能存取靜態元件，所以 mv_init2 在 SE24 中必定是 Static Attribute，否則無法編譯；但 mv_ 前綴依書中 4.1 自己的慣例是實例屬性（靜態應為 gv_）。改寫版更名為 gv_init2。
  • 4.9／4.10 在建構子裡 WRITE。建構子（尤其靜態建構子）的執行時機不由呼叫端控制，在裡面輸出畫面或彈訊息，換到背景作業、RFC、OData 就會出問題。改寫版記錄到內表，由呼叫端決定顯示。
  • 4.11 原本只建立一個物件，看不出「靜態建構子只跑一次」，改寫版建立兩個物件對照。原程式的輸出順序為 CLASS_CONSTRUCTOR → CONSTRUCTOR → CONSTRUCTOR TEST.。
  • 原寫法 CREATE OBJECT go_constructor EXPORTING iv_value = … 改成 NEW zcl_constructor( iv_value = … )。
建構子只做「讓物件處於可用狀態」的最少工作（檢查參數、設初值）。不要在建構子裡讀大量資料或呼叫 BAPI：建構子失敗時物件根本不存在，錯誤處理會很難寫。需要複雜的建立流程時，改用靜態工廠方法（CREATE PRIVATE ＋ CLASS-METHODS create），見 5-2 章 Factory 與 Singleton，以及本部 7-5 章 設計模式。

7. 方法的例外：傳統例外與類別式例外（4.12～4.14）

觀念：方法有兩種例外機制，同一個方法只能擇一：

  • 傳統例外（4.12）：方法簽章 EXCEPTIONS 宣告名稱，方法內 RAISE name，呼叫端用 EXCEPTIONS name = n 接、再判斷 sy-subrc。這是函數模組時代留下來的，只能傳一個數字、不能帶訊息與上下文。
  • 類別式例外（4.13）：方法簽章 RAISING cx_…，方法內 RAISE EXCEPTION，呼叫端 TRY … CATCH。例外是物件，可以帶文字、屬性與前一個例外（previous）。

8. 可見性：PUBLIC／PROTECTED／PRIVATE（4.15～4.18，勘誤第 2 條）

觀念：

區段類別本身子類別Friend 類別外部（其他程式／類別）
PUBLIC SECTION可可可可
PROTECTED SECTION可可可不可
PRIVATE SECTION可不可可不可

4.15～4.17 是 ZCL_MASTER 三個分別輸出三種屬性的方法，4.18 的 DISPLAY 在類別內部另外建立一個 ZCL_MASTER 物件，對它的三種屬性賦值並呼叫三個方法——全部合法，因為 ABAP 的可見性是以類別為單位，不是以物件為單位：同一類別的方法可以存取同類別其他物件的 PRIVATE 屬性。

CLASS zcl_master DEFINITION PUBLIC CREATE PUBLIC.
  PUBLIC SECTION.
    DATA mv_public TYPE string VALUE 'PUBLIC'.
    METHODS:
      display_public    RETURNING VALUE(rv_text) TYPE string,
      display_private   RETURNING VALUE(rv_text) TYPE string,
      display_protected RETURNING VALUE(rv_text) TYPE string,
      display           RETURNING VALUE(rt_text) TYPE string_table.
  PROTECTED SECTION.
    DATA mv_protected TYPE string VALUE 'PROTECTED'.
  PRIVATE SECTION.
    DATA mv_private   TYPE string VALUE 'PRIVATE'.   "勘誤表第 2 條：Initial Value 應為 'PRIVATE'
ENDCLASS.

CLASS zcl_master IMPLEMENTATION.
  METHOD display_public.    rv_text = mv_public.    ENDMETHOD.   "4.15
  METHOD display_private.   rv_text = mv_private.   ENDMETHOD.   "4.16
  METHOD display_protected. rv_text = mv_protected. ENDMETHOD.   "4.17

  METHOD display.                                                "4.18
    DATA(lo_master) = NEW zcl_master( ).
    lo_master->mv_public    = 'caller set value : public'.
    lo_master->mv_private   = 'caller set value : private'.     "同類別：可存取別的物件的 PRIVATE
    lo_master->mv_protected = 'caller set value : protected'.

                       ( lo_master->display_private( ) )
                       ( lo_master->display_protected( ) ) ).

勘誤表第 2 條（p114 圖 4-74「測試全局類 SE24」）：圖中屬性的 Initial Value 應為 'PRIVATE'，後續程式碼也要一致。在 SE24 的 Attributes 頁籤中 Initial Value 欄位要連同單引號輸入 'PRIVATE'（它是一段 ABAP 常值，不是純文字）；對應到原始碼就是 DATA mv_private TYPE string VALUE 'PRIVATE'.。原書圖上的值與此不符，照圖做在 SE24 測試（F8）時看到的初值會和書中說明對不起來。

與原範例的差異：原範例四個方法都 WRITE，4.18 以 CREATE OBJECT＋CALL METHOD 呼叫；改寫成回傳字串／字串表。資料夾裡沒有 ZCL_MASTER 的定義與 4.18 所在類別的說明，若把 DISPLAY 放在子類別，lo_master->mv_private 與 lo_master->mv_protected 兩行都會編譯錯誤（子類別只能存取「自己這個物件繼承來的」protected 元件，不能透過父類別型別的參考存取別的物件的 protected 元件），所以 4.18 必定是寫在 ZCL_MASTER 本身或其 Friend 類別中。

預設全部放 PRIVATE，確定要給子類別用才升 PROTECTED，確定是對外契約才升 PUBLIC。對外要讀的屬性用 DATA … READ-ONLY（只能用在 PUBLIC／PROTECTED 區段），比寫一堆 getter 簡潔，又不會被外部亂改。

9. 從外部呼叫：只看得到 PUBLIC，以及 NEW 鏈式呼叫（4.19）

觀念：類別外部只能存取 PUBLIC 元件。4.19 把 display_private( )、display_protected( ) 的呼叫註解掉——但注意，原範例的這兩個方法本身是宣告在哪個區段，資料夾中看不到；若照 4.15～4.17 的命名，方法是 PUBLIC、只有屬性分三區，那麼外部呼叫這兩個方法其實是合法的，會印出 private／protected 屬性的值——這正是封裝：外部拿不到屬性本身，但可以透過類別開放的方法間接取得。書中把它們註解掉，比較可能的原意是示範「若方法放在 PRIVATE／PROTECTED 區段，外部呼叫會編譯錯誤」。

10. 用本地類別組織報表：RUN 方法當進入點（4.20）

11. Friend（友元）：開放私有元件給指定類別

觀念：類別可以用 FRIENDS 指定信任的類別或介面，被指定者可以存取它的 PROTECTED 與 PRIVATE 元件（包括 CREATE PRIVATE 的建構子）。友元關係是單向、不遞移的：A 把 B 當朋友，不代表 B 把 A 當朋友；B 的朋友也不是 A 的朋友。但 B 的子類別會繼承「是 A 的朋友」這個身分。書中第 4 章範例資料夾沒有對應的 Friend 程式，以下依 SAP 標準語法補寫，最常見的實務用途是測試類別與工廠類別。

12. 物件生命週期與垃圾回收（4.21）

觀念：ABAP 沒有解構子（destructor）可供使用者程式呼叫；物件在「沒有任何參考變數指向它」之後，由垃圾回收器（Garbage Collector）在適當時機釋放。FREE go_obj／CLEAR go_obj 對參考變數的作用相同：只是讓這個變數不再指向物件，物件本身要等 GC 才真正回收。4.21 用 CL_ABAP_MEMORY_UTILITIES 量測建立並釋放 1000 個物件前後的記憶體用量，並手動呼叫 do_garbage_collection( ) 比較差異。

REPORT zrep_cls_t01.

CLASS lcl_payload DEFINITION FINAL.
  PUBLIC SECTION.
    METHODS constructor.
  PRIVATE SECTION.
    DATA mt_data TYPE string_table.
ENDCLASS.

CLASS lcl_payload IMPLEMENTATION.
  METHOD constructor.
    mt_data = VALUE #( FOR i = 1 UNTIL i > 100 ( |line { i }| ) ).   "讓每個物件有點份量
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  DATA lo_obj TYPE REF TO lcl_payload.

  cl_abap_memory_utilities=>get_total_used_size( IMPORTING size = DATA(lv_init_size) ).

  DO 1000 TIMES.
    lo_obj = NEW #( ).
    CLEAR lo_obj.                  "與 FREE lo_obj 相同：只斷開參考
  ENDDO.

  cl_abap_memory_utilities=>get_total_used_size( IMPORTING size = DATA(lv_before_gc) ).
  cl_abap_memory_utilities=>do_garbage_collection( ).
  cl_abap_memory_utilities=>get_total_used_size( IMPORTING size = DATA(lv_after_gc) ).

    ( |記憶體初始用量：{ lv_init_size NUMBER = USER } Bytes| )
    ( |建立並釋放 1000 個物件後：{ lv_before_gc NUMBER = USER } Bytes| )
    ( |執行垃圾回收後：{ lv_after_gc NUMBER = USER } Bytes| ) ) ).

與原範例的差異：

  • 原範例建立的是 CL_MATERIAL_DETAILS_LIST，這是某個標準元件的類別，不一定每套系統都有、建構子也可能需要參數；改寫版用一個自訂的本地類別，保證可編譯且物件有一定大小，量測差異才明顯。

do_garbage_collection( ) 只該在量測、除錯時使用，不要寫進正式程式——GC 會自動在需要時執行，手動觸發只會增加成本。真正的記憶體問題（例如把大量物件存進靜態內表、事件註冊後沒 SET HANDLER … ACTIVATION abap_false 導致物件永遠被參考）要用 S_MEMORY_INSPECTOR 比對 Memory Snapshot，或在 Debugger 的 Memory Analysis 工具查看。

全章的改寫原則（與 附錄 舊語法對照 一致）：

  • CREATE OBJECT → NEW zcl_x( )／NEW #( )；CALL METHOD → obj->m( )。
  • 方法內不 WRITE、不 MESSAGE（事件處理方法、UI 層除外），改回傳資料。
  • 傳統 EXCEPTIONS／RAISE name → 例外類別＋RAISING＋TRY…CATCH。
  • SELECT 明列欄位、加 @、讀完排序；輸出用 CL_SALV_TABLE。
Casper 實務經驗 ③：先找標準，再想客製。寫一支新的 ZCL_ 之前，先在 SE24／ADT 用關鍵字找標準類別（例如讀物料不必自己包 MARA，先看有沒有 released 的 CDS View 或 BAPI；輸出清單直接用 CL_SALV_TABLE）。第 4 章的範例是為了學語法才自己造輪子，專案上每多一個自建類別，就多一份維護與升級成本。

練習與自我檢核

  1. 實例屬性與靜態屬性：4.1 建立兩個物件 lo_a、lo_b，lo_a 改了 gv_cl_value，lo_b 讀到的值是什麼？為什麼？
    要點：相同。CLASS-DATA 整個類別（同一內部階段）只有一份，所有物件共用。
  2. 參數方向：方法宣告 EXPORTING ev_name，呼叫端要用哪個關鍵字接？RETURNING 參數為什麼一定要 VALUE( )？
    要點：呼叫端用 IMPORTING；RETURNING 的值要能在運算式中使用，必須傳值，方法結束後才複製給接收端。
  3. 呼叫寫法：把 CALL METHOD lo_acc->deposit EXPORTING im_deposit_amount = p_dep RECEIVING re_account_balance = l_bal. 改成現代寫法。
    要點：DATA(l_bal) = lo_acc->deposit( p_dep ).
  4. 事件：4.8 若拿掉 SET HANDLER，查無料號時會發生什麼？
    要點：RAISE EVENT 照常執行，但沒有處理方法被呼叫，也不會報錯——畫面上什麼都沒有。
  5. 範例除錯：4.8 輸出 MEINS 永遠是空白，原因與修法？
    要點：4.7 的 SELECT 欄位清單沒有 MEINS；加入欄位，或改用只含需要欄位的結構。
  6. 建構子：靜態建構子可以有參數嗎？可以存取實例屬性嗎？建立三個物件時兩種建構子各執行幾次？
    要點：不可有參數；只能存取靜態元件；靜態建構子 1 次、實例建構子 3 次。
  7. 例外：4.14 直接按 F8 執行（p_ivalue = 0），為什麼沒有看到除以零的例外訊息？
    要點：ABAP 中被除數為 0 時 0/0 = 0，不觸發 CX_SY_ZERODIVIDE。
  8. 可見性：4.18 的 DISPLAY 若放在 ZCL_MASTER 的子類別中，哪幾行會編譯錯誤？
    要點：存取 lo_master->mv_private 與 lo_master->mv_protected 的行（透過父類別參考存取別的物件的 protected 也不行）。
  9. 勘誤：勘誤表第 2 條說圖 4-74 的 Initial Value 應為什麼？在 SE24 要怎麼輸入？
    要點：'PRIVATE'，連單引號一起輸入，等同 DATA mv_private TYPE string VALUE 'PRIVATE'.
  10. Friend：A 宣告 FRIENDS B，B 可以存取 A 的哪些元件？A 可以存取 B 的 PRIVATE 嗎？
    要點：B 可存取 A 的所有元件（含 PROTECTED、PRIVATE、CREATE PRIVATE 建構）；關係單向，A 不能存取 B 的 PRIVATE。
  11. 垃圾回收：FREE lo_obj 會立刻釋放物件佔用的記憶體嗎？
    要點：不會。只是讓參考變數變成初始值；物件在沒有任何參考後，由 GC 擇時回收。
  12. 命名：4.20 的本地類別 ZCL_MAIN_REPORT 有什麼問題？
    要點：與全域類別命名空間混淆；本地類別應以 LCL_ 開頭。
  13. 實務：為什麼 4.7 讀 MARA 後應該 SORT？查詢料號時為什麼建議用多筆 EQ 而不是區間？
    要點：HANA 無預設排序，結果順序不穩定；區間比字典序，遇 ALPHA 前導零或號碼段不連續會漏抓或多抓。
