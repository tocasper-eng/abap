1. SAP 介面技術地圖：先搞清楚該用哪一種

老師開場就把常用的介面技術列出來，實務上選型錯了，後面全都是白工。目前 SAP 的介面技術主要有五類：

技術本質最適合的場景缺點 / 注意
Web Service（SOAP）把函數包成可經由 Web 呼叫的 API，靠 WSDL 定義SAP 對非 SAP、跨防火牆、跨平台；彈性最大要用 SOAMANAGER 建邏輯埠（Logical Port）；效能較差、XML 冗長
ALE / IDoc以商業物件（BO）為單位，用 IDoc 格式非同步傳遞SAP 對 SAP、主資料同步、EDI對接收端配置人員要求高；IDoc 結構＝1 控制記錄＋n 資料記錄＋n 狀態記錄
RFC遠端函數呼叫，是 BAPI／ALE 的底層系統間即時呼叫函數；效能最好要 SM59 目的地；跨防火牆需 SAP Cloud Connector 或 SAProuter
BAPI具 RFC 屬性、且註冊在 BOR 的標準商業介面建立／修改／查詢單據與主資料，有版本相容保證參數結構固定，客製欄位要靠 Extension
Middleware（仲介軟體）CRM 特有，靠 Adapter 傳 BDocCRM 與 ERP 之間BDoc 的本質是 qRFC；流程是 CRM → BDoc → IDoc/XML/BAPI 結構 → 外部系統

IDoc 的出站與入站四步驟（面試常考）：

  • 出站：① 應用層產生應用資料 → ② ALE 層建立出站 IDoc → ③ 通訊層尋找夥伴與埠 → ④ 發送 IDoc。
  • 入站：① 通訊層接收入站埠資料 → ② ALE 層建立入站 IDoc、依夥伴參數檔找 IDoc 處理類型 → ③ 應用層寫入文件。
SAP 與 SAP 之間的 SM59 邏輯連接是 R/3 型（型別 3）；SAP 對外部系統（例如產生檔案給 FTP、或註冊型外部程式）用的是 T 型（TCP/IP）。老師提到「SAP 發送到 FTP」的做法：建立 RFC 邏輯連接 → 用 FTP_CONNECT / FTP_COMMAND 系列函數連線登入 → 在指定位置建立檔案（詳見 4-4 章 FTP 段落）。

2. BOPF 與 BAPI 的層次關係

BOPF（Business Object Processing Framework）是一個基於物件導向 ABAP 的框架，是 SAP Business Suite 用來開發商業運用物件的基礎設施。用 BOPF 開發可以省下大量時間，因為權限控制、交易處理（transaction handling）、緩存管理這些技術細節框架都幫你做掉了，你只要專注在業務邏輯。

在 BOPF 的架構中，BAPI 是第三層——介面層（Interface Layer）。老師的重點：

  • Dynpro 是傳統 SAP 介面；SAPUI5 是 HTML5 的介面；兩者底下呼叫的商業邏輯可以是同一組。
  • SAP ERP 提供無數 BAPI 函數：單據新增、變更、查詢、庫存查詢、MRP 展算⋯⋯「你想得到的、想不到的都有」。
  • BAPI 若具有 RFC 屬性，就表示能讓外部程式執行。這是整章的核心句。
老師的白話口訣：「B-API，就是 Business 的 API。」 學會請購單的 BAPI，EEP／MES／電商網站就能直接在 SAP 開請購單，不用人工重打。

3. RFC 的五種型態：sRFC / aRFC / tRFC / qRFC / bgRFC

RFC 是 SAP 系統之間、以及 SAP 與外部系統之間程式通訊的基本介面技術，BAPI、ALE 等更高層技術都是基於 RFC 實現。依通訊方向分三種情境：

  • 兩個獨立的 SAP 系統之間通訊。
  • SAP 作為呼叫端，去呼叫外部遠端系統（非 SAP ABAP 系統）。
  • 外部系統作為呼叫端，來呼叫 SAP。

依同步性與可靠度，共有五種型態。選錯型態是介面專案最貴的錯誤：

型態全名特性監控 TCODE典型用途
sRFCSynchronous RFC同步，呼叫端等回應；目標系統必須在線，否則直接短拋（DUMP）ST22即時查詢：查庫存、查價格、查客戶信用
aRFCAsynchronous RFC非同步，不等回應（STARTING NEW TASK）；可用 RECEIVE RESULTS 回收結果；目標仍須在線SM50平行處理、把大批資料切成多工同時跑
tRFCTransactional RFC加 IN BACKGROUND TASK；先寫進 ARFCSSTATE / ARFCSDATA，COMMIT WORK 後才送出；保證只執行一次，但不保證順序SM58ALE/IDoc 傳輸、目標系統可能離線的情境
qRFCQueued RFCtRFC ＋ 佇列，保證 只執行一次且照順序；分出站佇列（Outbound）與入站佇列（Inbound）SMQ1 / SMQ2 / SMQRCRM Middleware 的 BDoc、必須保序的主資料變更
bgRFCBackground RFCNetWeaver 7.0 之後推出，取代 tRFC/qRFC；分 Type T（無序單元）與 Type Q（有序單元）；用類別 API 而非語法附加SBGRFCMON / SBGRFCCONFS/4HANA 新專案的建議做法
 
*&-------------------------------------------------------------*
*& 五種 RFC 呼叫語法對照
*&-------------------------------------------------------------*

" ① sRFC：同步。目標不在線 → 立刻例外／DUMP，必須 CATCH
TRY.
    CALL FUNCTION 'Z_MM_STOCK_GET'
      DESTINATION 'PRD_CLNT100'          "SM59 建立的 RFC 目的地
      EXPORTING  iv_werks = '1710'
      TABLES     et_stock = lt_stock
      EXCEPTIONS system_failure        = 1 MESSAGE DATA(lv_msg)
                 communication_failure = 2 MESSAGE lv_msg
                 OTHERS                = 3.
    IF sy-subrc <> 0.
      MESSAGE |RFC 失敗（{ sy-subrc }）：{ lv_msg }| TYPE 'E'.
    ENDIF.
  CATCH cx_root INTO DATA(lo_ex).
    MESSAGE lo_ex->get_text( ) TYPE 'E'.
ENDTRY.

" ② aRFC：非同步、平行處理。用 CALLING ... ON END OF TASK 回收
CALL FUNCTION 'Z_MM_STOCK_GET'
  STARTING NEW TASK  |TASK{ lv_idx }|          "任務名稱必須唯一
  DESTINATION IN GROUP DEFAULT                  "用 RZ12 的 Server Group
  CALLING lo_handler->on_task_end ON END OF TASK
  EXPORTING iv_werks = lv_werks
  EXCEPTIONS resource_failure = 1 OTHERS = 2.

" ③ tRFC：保證只執行一次，但不保證順序。一定要 COMMIT WORK 才真的送出
CALL FUNCTION 'Z_IF_SEND_DOC'
  IN BACKGROUND TASK
  DESTINATION 'MES_SYSTEM'
  EXPORTING is_doc = ls_doc.
COMMIT WORK.                                    "沒有這行，資料只躺在 ARFCSSTATE

" ④ qRFC：tRFC + 佇列，保證順序。先指定佇列名再呼叫
CALL FUNCTION 'TRFC_SET_QUEUE_NAME'
  EXPORTING qname = |ZPR{ lv_banfn }|           "同一佇列名者依序執行
  EXCEPTIONS OTHERS = 1.
CALL FUNCTION 'Z_IF_SEND_DOC'
  IN BACKGROUND TASK
  DESTINATION 'MES_SYSTEM'
  EXPORTING is_doc = ls_doc.
COMMIT WORK.

" ⑤ bgRFC（S/4HANA 建議做法）：Type Q＝有序單元
TRY.
    DATA(lo_dest) = cl_bgrfc_destination_outbound=>create( 'MES_SYSTEM' ).
    DATA(lo_unit) = lo_dest->create_qrfc_unit( ).
    lo_unit->add_queue_name_outbound( |ZPR{ lv_banfn }| ).
    CALL FUNCTION 'Z_IF_SEND_DOC'
      IN BACKGROUND UNIT lo_unit
      EXPORTING is_doc = ls_doc.
    COMMIT WORK.
  CATCH cx_bgrfc_invalid_destination
        cx_bgrfc_invalid_unit INTO DATA(lo_bg_ex).
    MESSAGE lo_bg_ex->get_text( ) TYPE 'E'.
ENDTRY.
tRFC/qRFC/bgRFC 少了 COMMIT WORK 就什麼都不會發生。資料只會停在 ARFCSSTATE（tRFC）或 bgRFC 單元表裡，SM58 看得到一筆「Transaction recorded」永遠不執行。這是介面上線第一天最常見的災難。
除錯順序背起來：同步失敗看 ST22；tRFC 卡住看 SM58（可手動 Execute LUW 重送）；qRFC 卡住看 SMQ1（出站）/ SMQ2（入站），常見狀態 SYSFAIL、CPICERR、RETRY；bgRFC 看 SBGRFCMON。

4. SM59：RFC 目的地與連線測試

RFC 目的地（Destination）是「連到哪裡、用什麼身分」的定義。SM59 裡最常用的型別：

型別說明常見用途
3（ABAP Connection）連到另一套 SAP ABAP 系統DEV → QAS → PRD、ALE/IDoc、跨系統 BAPI
T（TCP/IP Connection）連到外部程式；分 Registered Server Program 與 Start on Explicit HostJava／.NET／Python 註冊型伺服器、SAP Gateway 外掛
G（HTTP to External Server）對外部 HTTP/REST 端點ABAP 呼叫外部 REST API（配 CL_HTTP_CLIENT）
H（HTTP to ABAP System）對另一套 ABAP 系統的 HTTPOData／SOAP 內部呼叫
L（Logical Destination）指向另一個既有目的地做環境切換的間接層
NONE / 空白不指定＝呼叫本機系統本身測試時用 DESTINATION 'NONE' 走本機 RFC 路徑

建立目的地的步驟（（依講義步驟整理））：SM59 → 選型別（例如 3）→ 按 Create → 填 RFC Destination 名稱（建議 <SID>CLNT<MANDT> 命名）→ Technical Settings 填 Target Host、System Number → Logon & Security 填 Language、Client、User、Password（務必用 Type = System 或 Communication 的技術帳號，不要用個人帳號）→ 存檔 → 按 Connection Test 與 Remote Logon 驗證。

5. 建立 RFC-Enabled Function Module：SE37 的規矩

任何 ABAP 程式都能用 CALL FUNCTION ... DESTINATION 呼叫遠端功能；反過來，要讓外部程式（Python／Java／.NET）呼叫你，就得做一支具 RFC 屬性的函數模組。步驟：

  • SE37（或 SE80 的函數群組）建立函數 → Attributes 頁籤 → Processing Type 選 Remote-Enabled Module。
  • 勾選後，SAP 會對介面套用一組強制限制，違反的話啟動（Activate）就報錯。
限制說明做法
所有參數必須 pass by valueImport／Export／Changing 全部要勾 Pass Value；不能用 referenceSE37 介面畫面把 值傳遞 欄位打勾
型別必須是 DDIC 型別不能用程式內部型別、不能用 TYPE ANY／泛型；結構與表都要是 SE11 建立的先在 SE11 建 Structure 與 Table Type
不支援 CHANGING 的參考語意Changing 參數雖可用，但外部連接器支援度不一介面設計建議只用 IMPORTING / EXPORTING / TABLES
例外只能用傳統例外不能用 class-based exception 當介面例外（外部連接器看不懂）內部用 TRY/CATCH，介面用回傳 BAPIRET2 表告知結果
TABLES 參數雖已過時但仍可用對外部連接器相容性最好回傳多筆資料時用 TABLES 或 EXPORTING 一個 Table Type
不可有 Dynpro 互動WRITE、CALL SCREEN、MESSAGE 都會讓遠端呼叫掛掉訊息一律塞進 RETURN 表
字串型別的陷阱：RFC 介面可以用 STRING / XSTRING，但部分舊版連接器（尤其 NCo 舊版、C RFC SDK 傳統 API）處理深層型別（deep type）會有問題。對外介面最安全的是扁平字元型別（CHAR、NUMC、DEC）＋ DDIC 結構。另外，DECIMAL 欄位的小數位由 DDIC Domain 決定，外部系統若用 float 接會有精度誤差，金額欄位請雙方約定用字串傳遞。

6. 實作：給 Python / pyrfc 呼叫的 Z RFC 函數

這是實務上最常被要求的東西：外部系統要撈 SAP 的庫存或主資料。老師的專案要點也寫得很清楚——「基礎資料能自動下載到 MSSQL，不必每個都動態」。下面是一支完整、可直接照抄的 RFC 函數樣板。

先在 SE11 建好 DDIC 物件（（依講義步驟整理））：

  • Structure ZS_STOCK_S：MATNR、MAKTX、WERKS、LGORT、CHARG、LABST、UMLME、INSME、SPEME、MEINS、STPRS、PEINH、WAERS。
  • Structure ZS_RANGE_S：SIGN（CHAR1）、OPTION（CHAR2）、LOW（CHAR40）、HIGH（CHAR40）——用來把 SELECT-OPTIONS 從外部傳進來。
  • Table Type ZTT_STOCK（行型別 ZS_STOCK_S）、ZTT_RANGE（行型別 ZS_RANGE_S）。
FUNCTION z_mm_stock_get.
*"----------------------------------------------------------------------
*"*"Local Interface:
*"  IMPORTING
*"     VALUE(IV_WERKS) TYPE  WERKS_D OPTIONAL
*"     VALUE(IV_MAXROW) TYPE  I DEFAULT 10000
*"  EXPORTING
*"     VALUE(EV_COUNT) TYPE  I
*"  TABLES
*"      IT_MATNR STRUCTURE  ZS_RANGE_S OPTIONAL    "物料 select-option
*"      IT_LGORT STRUCTURE  ZS_RANGE_S OPTIONAL    "儲存地點 select-option
*"      ET_STOCK STRUCTURE  ZS_STOCK_S
*"      ET_RETURN STRUCTURE  BAPIRET2
*"----------------------------------------------------------------------
*"  注意：Remote-Enabled 時每個參數都必須勾 Pass Value，型別必須是 DDIC 型別
*"----------------------------------------------------------------------

  CLEAR: et_stock[], et_return[], ev_count.

  " 外部傳進來的 range 內表，型別要轉成 ABAP 的 RANGE 型別才能放進 WHERE
  DATA lr_matnr TYPE RANGE OF matnr.
  DATA lr_lgort TYPE RANGE OF lgort_d.

  lr_matnr = CORRESPONDING #( it_matnr[] ).
  lr_lgort = CORRESPONDING #( it_lgort[] ).

  " 參數檢核：介面一定要自己擋，外部系統什麼都敢送
  IF iv_werks IS INITIAL AND lr_matnr IS INITIAL.
    APPEND VALUE bapiret2( type       = 'E'
                           id         = 'ZIF'
                           number     = '001'
                           message    = '工廠與物料至少要給一個條件'
                           message_v1 = 'Z_MM_STOCK_GET' ) TO et_return.
    RETURN.
  ENDIF.

  TRY.
      SELECT FROM mard AS d
        INNER JOIN mara AS a ON a~matnr = d~matnr
        LEFT OUTER JOIN makt AS t ON  t~matnr = d~matnr
                                  AND t~spras = @sy-langu
        LEFT OUTER JOIN mbew AS b ON  b~matnr = d~matnr
                                  AND b~bwkey = d~werks
        FIELDS d~matnr, t~maktx, d~werks, d~lgort,
               d~labst, d~umlme, d~insme, d~speme,
               a~meins, b~stprs, b~peinh
        WHERE d~werks = @iv_werks              "空值時此條件由下面的 range 補
          AND d~matnr IN @lr_matnr
          AND d~lgort IN @lr_lgort
          AND ( d~labst <> 0 OR d~umlme <> 0
             OR d~insme <> 0 OR d~speme <> 0 )
        ORDER BY d~matnr, d~werks, d~lgort      "外部系統要穩定順序，一定要 ORDER BY
        INTO CORRESPONDING FIELDS OF TABLE @et_stock
        UP TO @iv_maxrow ROWS.

    CATCH cx_sy_open_sql_error INTO DATA(lo_sql_ex).
      APPEND VALUE bapiret2( type    = 'E' id = 'ZIF' number = '002'
                             message = lo_sql_ex->get_text( ) ) TO et_return.
      RETURN.
  ENDTRY.

  " 幣別補值（公司代碼幣別）；外部系統看到金額一定會問幣別
  SELECT SINGLE waers FROM t001k AS k
    INNER JOIN t001 AS c ON c~bukrs = k~bukrs
    FIELDS c~waers
    WHERE k~bwkey = @iv_werks
    INTO  @DATA(lv_waers).

  LOOP AT et_stock ASSIGNING FIELD-SYMBOL(<ls_stock>).
    <ls_stock>-waers = lv_waers.
  ENDLOOP.

  ev_count = lines( et_stock ).

  APPEND VALUE bapiret2(
    type       = COND #( WHEN ev_count = 0 THEN 'W' ELSE 'S' )
    id         = 'ZIF'
    number     = '000'
    message    = |查詢完成，共 { ev_count } 筆|
    message_v1 = |{ iv_werks }| ) TO et_return.

ENDFUNCTION.

# -*- coding: utf-8 -*-
# 需求：pip install pyrfc（並先安裝 SAP NW RFC SDK 並設定 PATH / LD_LIBRARY_PATH）
from pyrfc import Connection, ABAPApplicationError, CommunicationError

CONN = dict(
    user='RFC_USER', passwd='********',
    ashost='10.1.1.10', sysnr='00', client='100', lang='ZH',
    # 若走 SAP Cloud Connector / SAProuter：saprouter='/H/router/S/3299/H/host'
)

def get_stock(werks, matnr_list=None):
    # select-option 的四欄結構：SIGN / OPTION / LOW / HIGH
    it_matnr = [{'SIGN': 'I', 'OPTION': 'EQ', 'LOW': m, 'HIGH': ''}
                for m in (matnr_list or [])]
    with Connection(**CONN) as conn:
        result = conn.call('Z_MM_STOCK_GET',
                           IV_WERKS=werks,
                           IV_MAXROW=50000,
                           IT_MATNR=it_matnr)
    # RETURN 一定要判：type 為 E / A 就是失敗
    for msg in result['ET_RETURN']:
        if msg['TYPE'] in ('E', 'A'):
            raise RuntimeError(f"SAP 回傳錯誤：{msg['MESSAGE']}")
    return result['ET_STOCK']

if __name__ == '__main__':
    try:
        rows = get_stock('1710', ['TG11', 'TG12'])
        print(f'取得 {len(rows)} 筆庫存')
        # 之後用 pyodbc / SQLAlchemy 批次寫入 MSSQL
    except (ABAPApplicationError, CommunicationError) as e:
        print('RFC 失敗：', e)
老師強調過的實務眉角：條件用「區間（BT）」與用「列舉（EQ）」答案會不一樣，用列舉的才正確。介面設計時把 SELECT-OPTIONS 開成 range 表傳進來，外部系統就能用 SIGN='I' OPTION='EQ' 一筆一筆列舉，避開區間在非連號編碼（物料號、成本中心）上抓到不該抓的資料。
SELECT SINGLE 沒有排序保證，多筆符合時 HANA 回傳哪一筆是不確定的。介面函數尤其危險——同一支程式今天抓到 A、明天抓到 B。要嘛加足主鍵條件，要嘛改成 SELECT ... ORDER BY ... UP TO 1 ROWS。

8. BAPI 的本質：BO、BOR 與怎麼把 BAPI 找出來

BAPI（Business Application Programming Interface）是 SAP 企業物件的特定方法，儲存在企業物件儲藏庫（BOR）中，用來執行特定企業工作細項。在 SAP 系統中，BAPI 以 RFC 功能模組的形式存在於函數建立器裡。BAPI 具有標準企業介面，允許外部應用程式（透過 SAP 企業物件的協助）存取 SAP 程式、函式和資料。用戶端可以是同一套 SAP、外部系統（例如 .NET 應用程式）、HTTP 閘道或其他 SAP 系統；連接技術可以是 JS、Java、VB、ABAP。

先懂兩個名詞：

  • BO（Business Object，業務物件）：代表真實世界的物件，例如一張採購訂單、一筆物料資料。BO 包含業務資料，並完整描述業務過程。系統內部應用與系統之間就是在 BO 級別通訊。透過呼叫 BAPI，內外部應用可以用 Portal、Java、.NET、Web Service 等標準方式存取和操作業務物件。
  • BOR（Business Object Repository）：SAP 業務物件類型（BO 的定義與描述）和相關 BAPI 的組織中心。BO 依所屬應用層級組織以便查找；BOR 管理不同發佈版本，並保證介面的版本相容性（這是 BAPI 相對於自寫 RFC 最大的價值）。
TCODE用途
BAPIBAPI Explorer：依應用元件階層瀏覽所有已釋出（Released）的 BAPI，可看文件、參數、範例
SWO1Business Object Builder：顯示／維護業務物件類型，看它的 Key、Method、Attribute、Event
SWO2BOR Browser：以樹狀瀏覽業務物件
SWO3查看 BOR（Business Object Repository）
SE37直接看 BAPI 的函數介面與原始碼、做單獨測試
BAPI → Alphabetical用字母排序找，配合關鍵字（CREATE、CHANGE、GETDETAIL、GETLIST）猜名字

BO 的結構：SAP R/3 企業目標的目標類型（Object Type）相當於物件導向語言中「類別（Class）」的概念，其定義由六部分組成：基本資料、介面（Interfaces）、鍵（Key Fields）、方法（Methods）、特徵（Attributes）、事件（Events）。

老師的絕招：由 TCODE 反查 BAPI（10-2）

如果只知道交易代碼，可以這樣把 BAPI 挖出來。以「建立銷售訂單」VA01 為例：

  1. 進入 VA01 畫面 → 功能表 System → Status。
  2. 在交易代碼欄位上雙擊，進入交易定義，找到它的 Package（開發類別）＝ VA。
  3. 用 SE80 打開 Package VA。
  4. 展開 Business Engineering → Business Object Types（業務工程 → 業務物件類型）。依業務需求判斷，要建立銷售訂單，BUS2032（Sales Order） 可能性最大。
  5. 雙擊 BUS2032 打開 Methods，尋找和「建立銷售訂單」同名的方法——這裡就是 SalesOrder.CreateFromDat2。把游標停在該行，點上方的「程式」按鈕，就能看到原始碼，找到 BAPI_SALESORDER_CREATEFROMDAT2。同樣方法可以找到修改（CHANGE）、刪除的 BAPI。
  6. 也可以雙擊 SalesOrder.CreateFromDat2 這一行，在彈出視窗中找到 ABAP 子畫面：如果單選鈕是「API 功能」，名稱欄就是我們要找的 BAPI；如果是「函數模組」，那就是一支一般 FM。
另外三招也很好用：① SE84 → Enterprise Services / Business Objects 搜尋；② 在標準交易上開 ST05 SQL Trace 或 SAT，看它到底呼叫哪支 FM；③ 直接在 SE37 用萬用字元搜 BAPI_*CREATE*、BAPI_*GETDETAIL*。

9. BAPIRET2 與 COMMIT／ROLLBACK：BAPI 的兩條命

幾乎所有 BAPI 都有一個 RETURN 參數，型別 BAPIRET2（舊版是 BAPIRET1 / BAPIRETURN）。這是判斷成功失敗的唯一依據——sy-subrc 在 BAPI 呼叫後幾乎永遠是 0，看它是沒有意義的。

欄位意義
TYPE訊息類型：S=成功、I=資訊、W=警告、E=錯誤、A=中止。E 與 A 才算失敗
ID / NUMBER訊息類別（SE91）與訊息編號，組起來可用 MESSAGE ... INTO 重建文字
MESSAGE已組好的訊息文字（含變數替換）
MESSAGE_V1~V4訊息變數，訊息文字裡的 &1~&4
ROW / FIELD / PARAMETER出錯的內表列號、欄位、參數名稱——回饋給外部系統時一定要帶上
LOG_NO / LOG_MSG_NO應用 Log 編號，可到 SLG1 查完整記錄
BAPI 內部不會自己 COMMIT。SAP 標準 BAPI 只把資料放進 update task（更新任務）緩衝區，你必須自己呼叫 BAPI_TRANSACTION_COMMIT，資料才會真的寫進資料庫。失敗時則要呼叫 BAPI_TRANSACTION_ROLLBACK 清掉緩衝區與鎖，否則同一個 LUW 裡的下一次呼叫會被前一次的髒資料汙染。

WAIT = 'X' 的意義：讓 COMMIT 等到更新任務真的做完才返回（同步更新）。如果你 COMMIT 完馬上要用剛產生的單號去做下一步（例如建完 PR 馬上轉 PO、或馬上 SELECT 出來），沒有 WAIT = 'X' 就會抓不到資料。代價是速度較慢，批次大量建單時可考慮省略，但要自行確保後續不立即讀取。

把「判 RETURN ＋ COMMIT／ROLLBACK」寫成一支共用的工具類別，是專案上最值得做的投資：

*&-------------------------------------------------------------*
*& BAPI 回傳處理共用類別（放在自建的 ZCL_BAPI_UTIL）
*&-------------------------------------------------------------*
CLASS zcl_bapi_util DEFINITION PUBLIC FINAL CREATE PUBLIC.
  PUBLIC SECTION.
    " 判斷 RETURN 表裡有沒有 E / A
    CLASS-METHODS has_error
      IMPORTING it_return       TYPE bapiret2_t
      RETURNING VALUE(rv_error) TYPE abap_bool.

    " 把 RETURN 表串成一段可讀的訊息（給 MESSAGE 或介面回傳用）
    CLASS-METHODS to_text
      IMPORTING it_return      TYPE bapiret2_t
                iv_only_error  TYPE abap_bool DEFAULT abap_true
      RETURNING VALUE(rv_text) TYPE string.

    " 依 RETURN 結果自動決定 COMMIT 或 ROLLBACK
    CLASS-METHODS commit_or_rollback
      IMPORTING it_return    TYPE bapiret2_t
                iv_wait      TYPE abap_bool DEFAULT abap_true
      RETURNING VALUE(rv_ok) TYPE abap_bool.
ENDCLASS.

CLASS zcl_bapi_util IMPLEMENTATION.

  METHOD has_error.
    " line_exists 比 LOOP ... EXIT 乾淨，也不會動到 sy-subrc 的語意
    rv_error = xsdbool( line_exists( it_return[ type = 'E' ] ) OR
                        line_exists( it_return[ type = 'A' ] ) ).
  ENDMETHOD.

  METHOD to_text.
    rv_text = REDUCE string(
      INIT lv_txt = ``
      FOR <ls_r> IN it_return
        WHERE ( type = 'E' OR type = 'A' OR type = 'W' OR type = 'S' )
      NEXT lv_txt = COND #(
        WHEN iv_only_error = abap_true AND <ls_r>-type NA 'EA'
          THEN lv_txt
        ELSE |{ lv_txt }{ COND #( WHEN lv_txt IS INITIAL THEN `` ELSE |; | ) }| &&
             |[{ <ls_r>-type }]{ <ls_r>-id }{ <ls_r>-number } { <ls_r>-message }| ) ).
  ENDMETHOD.

  METHOD commit_or_rollback.
    IF has_error( it_return ) = abap_true.
      CALL FUNCTION 'BAPI_TRANSACTION_ROLLBACK'.   "清掉緩衝區與鎖
      rv_ok = abap_false.
    ELSE.
      CALL FUNCTION 'BAPI_TRANSACTION_COMMIT'
        EXPORTING wait = COND char1( WHEN iv_wait = abap_true
                                     THEN 'X' ELSE space ).
      rv_ok = abap_true.
    ENDIF.
  ENDMETHOD.

ENDCLASS.
*&-------------------------------------------------------------*
*& 標準呼叫樣板：任何 BAPI 都照這個骨架寫
*&-------------------------------------------------------------*
DATA lt_return TYPE bapiret2_t.

CALL FUNCTION 'BAPI_XXXX_CREATE'
  EXPORTING  ...
  IMPORTING  ...
  TABLES     return = lt_return.

IF zcl_bapi_util=>commit_or_rollback( it_return = lt_return
                                      iv_wait   = abap_true ) = abap_true.
  MESSAGE |建立成功：{ lv_docno }| TYPE 'S'.
ELSE.
  MESSAGE zcl_bapi_util=>to_text( lt_return ) TYPE 'S' DISPLAY LIKE 'E'.
ENDIF.

" 訊息要給使用者看清楚時，用 CL_SALV_TABLE 把整張 RETURN 表列出來
TRY.
    cl_salv_table=>factory( IMPORTING r_salv_table = DATA(lo_salv)
                            CHANGING  t_table      = lt_return ).
    lo_salv->get_columns( )->set_optimize( abap_true ).
    lo_salv->get_functions( )->set_all( abap_true ).
    lo_salv->get_display_settings( )->set_list_header( 'BAPI 回傳訊息' ).
    lo_salv->display( ).
  CATCH cx_salv_msg INTO DATA(lo_salv_ex).
    MESSAGE lo_salv_ex->get_text( ) TYPE 'E'.
ENDTRY.
兩個口訣：「BAPI 只看 RETURN，不看 SY-SUBRC」、「有建就要 COMMIT，有錯就要 ROLLBACK」。另外，同一支程式在一個 LUW 裡連續呼叫多支 BAPI（例如建 PR 再建 PO），中間不要各自 COMMIT，應該全部成功才一次 COMMIT，才有交易一致性。

10. 物料主檔 BAPI：GET_ALL 與 SAVEDATA

講義第 02 節的兩個範例：BAPI_MATERIAL_GET_ALL 讀出物料現況、BAPI_MATERIAL_SAVEDATA 寫回。老師的兩個案例是「修改物料主檔的淨重與單位」和「更改 MRP2 的前置天數（PLIFZ）」。

SAVEDATA 的核心觀念——X 結構（Checkbox Structure）：每個資料結構（CLIENTDATA、PLANTDATA、SALESDATA⋯）都有一個對應的 X 結構（CLIENTDATAX、PLANTDATAX⋯）。你要改哪個欄位，就在 X 結構的同名欄位填 'X'；沒填 'X' 的欄位即使有值也不會被寫入，反之填了 'X' 但值為空，就會把該欄位清空。這是所有 SAP 主資料 BAPI 的共通設計。

*& Report ZBAPI_MATERIAL_CHANGE
*& 讀取物料 → 修改淨重／重量單位（基本視圖）＋ MRP2 前置時間（工廠視圖）
*&---------------------------------------------------------------------*

  DATA lt_return TYPE STANDARD TABLE OF bapi_matreturn2.

  " ① 先讀出現況（GET_ALL 只讀不寫，可先確認物料存在與現值）
  CALL FUNCTION 'BAPI_MATERIAL_GET_ALL'
    EXPORTING material   = CONV bapimatall-material( p_matnr )
              plant      = CONV bapimatall-plant( p_werks )

                                       unit_of_wt = p_gewei ).

                                       unit_of_wt = abap_true ).
  "★ 老師講義原稿此處把 CLIDAOUT-UNIT_OF_WT 寫成 'X'（誤植），

15. Extension In / Out：把客製欄位塞進標準 BAPI

標準 BAPI 的參數是固定的，但客戶一定會有客製欄位（Append 在 EKPO、VBAP 上的 ZZ 欄位）。SAP 的官方解法是 Extension（擴展）：

  • EXTENSIONIN：呼叫方把客製欄位資料塞進去（型別多為 BAPIPAREX，欄位 STRUCTURE + VALUEPART1~4）。
  • EXTENSIONOUT：BAPI 把客製欄位回傳出來。
  • SAP 端要在對應的 BAdI / Customer Exit 中把 EXTENSIONIN 解開，寫進資料庫。常見的擴展結構命名是 BAPI_TE_<table>（例如 BAPI_TE_MEPOITEM、BAPI_TE_VBAP）與其 X 結構 BAPI_TE_<table>X。

講義 10-3 的另一個實用技巧：由 VA03 的 Extras → Output 找到客製程式。步驟是 VA03 → Extras → Output → Header → Edit，看到 Output Type（例如 Z001）→ SPRO → SAP Reference IMG 找到訂單的 Output Type 設定 → 點 Z001 → 左欄中間選項就會顯示「哪一支程式的哪一個 FORM」→ 到 SE38 找那支程式 → 進去找名為 ENTRY 的 FORM。老師記錄的實際路徑：entry → processing → print data → upload_data_to_external_db。測試方式：VA02 直接改資料儲存（務必在測試區），就會重新觸發輸出、重下資料。

練習與自我檢核

  1. 介面選型：一個電商網站要「即時查 SAP 庫存」和「每天晚上把 5 萬筆訂單丟進 SAP」。這兩個需求各該用哪種 RFC 型態？為什麼？
    要點：即時查用 sRFC（同步、要立刻回答）；大批丟單用 qRFC/bgRFC（保證只做一次且保序、目標忙碌時可排隊），或者用 IDoc/AIF。
  2. tRFC 沒動靜：程式寫了 CALL FUNCTION ... IN BACKGROUND TASK DESTINATION ...，SM58 看到一筆記錄卻永遠不執行，最可能是什麼？
    要點：忘了 COMMIT WORK。次要可能：目的地帳號鎖住、目標系統沒有那支函數。
  3. RFC-enabled FM 的三個硬性限制是什麼？如果我想用 class-based exception 當介面例外，該怎麼辦？
    要點：① 所有參數 pass by value；② 型別必須是 DDIC 型別；③ 不可有 Dynpro 互動（WRITE/CALL SCREEN）。class-based exception 不能當介面例外，改成內部 TRY/CATCH、外部用 BAPIRET2 表回傳。
  4. 判斷 BAPI 成功失敗：為什麼不能用 IF sy-subrc NE 0？講義第 08 節的 ZPO_CHANGE 就犯了這個錯，請改寫。
    要點：BAPI 呼叫後 sy-subrc 幾乎永遠是 0。要判 RETURN 表有沒有 TYPE = 'E' 或 'A'（用 line_exists( lt_return[ type = 'E' ] )）。
  5. COMMIT 的 WAIT：什麼情況一定要給 WAIT = 'X'？什麼情況可以省略？
    要點：COMMIT 後馬上要用產生的單號去 SELECT 或做下一個 BAPI，必須 WAIT='X'；純批次寫入且後續不立即讀取，可省略以換取速度。
  6. X 結構：BAPI_MATERIAL_SAVEDATA 的 PLANTDATAX-PLANT 應該填 'X' 還是填工廠代碼？為什麼？
    要點：填工廠代碼。X 結構中 KEY 欄位填真值，只有非 KEY 的資料欄位才填 'X'。
  7. 找 BAPI：只知道交易碼 ME51N，請用老師教的方法找出建立請購單的 BAPI。
    要點：System → Status 雙擊 TCODE 找 Package → SE80 開 Package → Business Object Types → 找 BUS2105（Purchase Requisition）→ 看 Method → 對應 FM。或直接在 SE37 搜 BAPI_PR_*。
  8. 兩支請購 BAPI：BAPI_PR_CREATE 與 BAPI_REQUISITION_CREATE 有何差異？該查哪一份 SAP Note？
    要點：前者有 X 結構、欄位較新，S/4 建議用；後者是舊版無 X 結構。Note 499627 - FAQ BAPIs for purchase requisitions。
  9. 客製欄位：客戶要在採購單項目加一個 ZZ 欄位，並由外部系統帶進來。完整要做哪幾件事？
    要點：① SE11 Append CI_EKPODB/CI_EKPO；② Append 到 BAPI_TE_MEPOITEM / BAPI_TE_MEPOITEMX；③ 呼叫時填 EXTENSIONIN（BAPIPAREX 的 VALUEPART1~4）；④ 實作 BAdI ME_BAPI_PO_CUST / ME_PROCESS_PO_CUST 把值搬進去。少了第 4 步不會有任何錯誤訊息。
  10. RFC 黑名單：外部呼叫回報「function module is blacklisted」，但 SE37 測試完全正常，怎麼處理？
    要點：執行報表 RS_RFC_BLACKLIST_CUSTOM 把該 FM 從黑名單剔除；另檢查 UCON（UCONCOCKPIT）與 S_RFC 權限。
  11. S/4 主資料：舊系統的介面用 BAPI_CUSTOMER_CREATE 建客戶，升級 S/4 之後要改成什麼？
    要點：改走 BP。優先 API_BUSINESS_PARTNER（OData），地端可用 CL_MD_BP_MAINTAIN=>maintain( ) 或 CMD_EI_API=>maintain_bapi( )，記得 BUT000/BUT100/BUT020 才是主資料真相，KNA1 是 CVI 同步出來的。
  12. 缺料表：要做一支「PP 缺料表」給 MSSQL，請設計 RFC 介面。
    要點：資料來源用 MD_STOCK_REQUIREMENTS_LIST_API（或 BAPI_MATERIAL_STOCK_REQ_LIST）取 MDEZX，篩出可用量為負的日期；BOM 反查用 CS_WHERE_USED_MAT（多階）。介面設計成 RFC-enabled FM，參數用 range 表讓外部列舉（不要用區間），一定要 ORDER BY，並回傳 BAPIRET2。
  13. 條件的坑：老師強調「條件用區間跟用列舉時答案會不同，用列舉的才正確」，這件事在設計 RFC 介面時要怎麼落實？
    要點：介面參數開成 SIGN/OPTION/LOW/HIGH 的 range 表，外部系統以 OPTION = 'EQ' 一筆一筆列舉；不要在介面內部自作聰明把使用者給的清單壓成 BT 區間。
  14. 不穩定的結果：一支介面函數每天跑出來的數字都不一樣，程式邏輯卻沒改，最可能的兩個原因是什麼？
    要點：① SELECT 沒有 ORDER BY 或用了 SELECT SINGLE，多筆符合時 HANA 回傳順序不定（正如成本評價同時有 H item category 與 E cost component 兩種角度，沒排序就一下抓到 H、一下抓到 E）；② FOR ALL ENTRIES 的驅動表為空時會撈出全表。兩者都要在程式裡明確擋掉。
