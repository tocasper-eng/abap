2. 報表方案的選擇、ALV 與經典清單、Include 結構

Col18 第一課開宗明義：動手寫程式之前先問四個問題（ABAP Programming Checklist）：

  1. 有沒有 SAP 標準報表能做？（SAP Easy Access → SAP 選單 → Information Systems，或 General Report Selection 子樹，看文件、實際執行比對輸出）
  2. 標準報表能不能涵蓋大部分需求？
  3. 能不能用報表工具（SAP Query、InfoSet Query、QuickViewer）完成？
  4. 真的要自己寫，有沒有 LDB 或模組化單元（函數模組、BAPI、方法）可以拿來取數？
先找標準，再想客製。這是 Casper 在每個專案都要一再講的第三條經驗：標準報表 → Query（1-4 章 SQVI／SQ01、5-8 章 BC407）→ 自寫程式，每往右一步，開發、測試、升級維護成本就高一級。BW（SAP Business Warehouse）是另一條路：資料萃取到 BW 後用非 ABAP 的查詢工具出報表。
方案優點限制
標準報表立即可用、零開發彈性有限，輸出欄位不能自訂
InfoSet Query介面簡單、不必寫程式；與 SAP Query 的 InfoSet 整合，必要時可到 SAP Query 再編輯；使用者存取整合在角色中；可做人資各領域的評估要先在 SAP Query 定義 InfoSet 與使用者群組；清單不能一筆多行
SAP Query自訂使用者群組、InfoSet、Query；可掛到 SAP Easy Access 選單；可彙總、計算、畫圖；一筆可多行；每個 Query 可定義基本清單加多張統計與排名清單只限 SAP 系統內資料；學習成本比其他工具高
自寫 ABAP完全彈性、可用全部 ABAP 語言有效能差、取錯資料、解讀錯資料的風險

兩種輸出格式：ALV（SAP List Viewer，以表格或樹狀呈現大量資料，本課只講表格）與經典 ABAP 清單（WRITE）。ALV 又分兩種程式模型：ALV Grid Control（SAP R/3 4.6 起，CL_GUI_ALV_GRID）與 ALV Object Model（SAP NetWeaver 2004 起，CL_SALV_TABLE）。原廠比較表的結論：ALV Grid 支援無障礙（Accessibility）、可在背景產生、內建互動排序／彙總／小計／隱藏欄、Excel in place、使用者可隱藏欄位與調欄寬欄序；經典清單則可做細部版面、一筆資料多行顯示，但不符合無障礙要求，互動功能多半要自己寫。兩者都允許程式設計師實作自訂互動功能。

無障礙（Accessibility）：2001 年 5 月美國《復健法》第 508 條（Section 508）要求公家機關只能採購無障礙的 IT。SAP 因此定出設計規範：軟體必須能只用鍵盤操作（螢幕閱讀器等輔助技術都需要）。在報表領域，ALV Grid 比經典清單更符合這項要求。

3. 經典清單：清單緩衝區、標準表頭與頁面格式

程式中第一個 WRITE 會觸發清單產生。輸出先寫到清單緩衝區（list buffer），全部寫完後系統才從緩衝區產生畫面影像並顯示。系統預設產生兩行標準表頭：第一行左上是程式屬性裡的標題、右上是頁碼；第二行是一條連續橫線；捲動時這兩行固定在視窗頂端。列印時第一行變成：左上系統日期、中間清單標題、右上頁碼。交易碼 LIBS 可以看 SAP 建議的清單版式，自己的報表長得像 SAP 標準報表，使用者會覺得一致。

語法作用與限制
REPORT … LINE-SIZE s LINE-COUNT m(n)設定行寬 s、每頁行數 m、其中 n 行保留給 END-OF-PAGE 頁尾。s、m 必須是數字常值，不能是變數；設 0 表示用預設。m 必須大於表頭加頁尾的行數，否則出錯
NEW-PAGE LINE-COUNT m在清單層級中改每頁行數，覆蓋 REPORT 的設定；行寬只能在建立新清單層級時改
REPORT … NO STANDARD PAGE HEADING關閉標準表頭；可用 NEW-PAGE NO-TITLE/WITH-TITLE、NO-HEADING/WITH-HEADING 局部覆蓋
TOP-OF-PAGE在基本清單遇到第一個 WRITE／ULINE／SKIP 時自動觸發，產生自訂頁首；捲動時固定在頂端；若沒關標準表頭，標準表頭會出現在它上面
END-OF-PAGE頁尾，只有在 LINE-COUNT m(n) 保留了 n 行時才會觸發

清單標題與欄標題：可維護一行清單標題和最多四行欄標題，路徑是編輯器「轉到 → 文字元素 → 清單標題」，或在清單畫面「系統 → 清單 → 清單表頭」（在清單上維護比較直觀，因為看得到輸出）。沒維護時系統欄位 sy-title 會帶程式屬性的標題。表頭和所有文字元素一樣可以翻譯。

强晟筆記寫「缺省的報表行寬是 83 列、頁長 60000 行」。行寬預設值依版本與視窗寬度而定（Col18 已不再給這個數字），實務上請一律明寫 LINE-SIZE，並記得上限是 1023；不要依賴預設。

4. WRITE 格式化、FORMAT、圖示與線條、捲動、多語文字、系統欄位

FORMAT 選項：COLOR n [ON|OFF]（行背景色）、INTENSIFIED [ON|OFF]（加強色）、INVERSE [ON|OFF]（前景背景互換）、HOTSPOT [ON|OFF]（滑鼠變手形、單擊即觸發 AT LINE-SELECTION）、INPUT [ON|OFF]（可輸入欄位）、RESET（全部回預設）。FORMAT 作用於之後的 WRITE，持續到 FORMAT COLOR OFF 或 FORMAT RESET。注意 RESET 會連 INTENSIFIED ON 這個標準設定一起關掉，所以用 COLOR OFF 比較好；每個新事件開始時系統都會把 FORMAT 重設。也可以對單一欄位加格式，例如 WRITE wa_spfli-carrid COLOR COL_KEY，這會覆蓋 FORMAT——就近原則。

WRITE 附加說明
NO-GAP欄位後不留空白，連續輸出
NO-ZERO值為 0 只輸出空白；C、N 型的前導 0 換成空白
DD/MM/YY 等覆蓋使用者主檔的日期格式（年份位數、分隔符；日月年順序依使用者設定）
CURRENCY cur依表 TCURX 的規則格式化金額。金額在資料庫以「幣別最小單位、不帶小數」存放，加 CURRENCY 時 p 型本身的小數位數會被完全忽略
UNIT unit依表 T006 格式化數量
USING EDIT MASK mask依格式樣板輸出
UNDER g從欄位 g 輸出的那一欄開始
LEFT-JUSTIFIED／CENTERED／RIGHT-JUSTIFIED靠左（C、N、D、T、X 預設）／置中／靠右（I、P、F 數值型預設）

圖示、符號、線條：WRITE … AS SYMBOL（先 INCLUDE <SYMBOL>）、AS ICON、AS LINE；一個 INCLUDE <LIST> 就等於同時載入 <SYMBOL>、<ICON>、<LINES>、<COLOR>。橫線用 ULINE（與清單同寬）、ULINE /m（第 m 欄到右邊界）、ULINE /m(n)（第 m 欄起長 n）、或 sy-uline；直線用 sy-vline。橫線與直線交叉處系統會自動換成四種 L 形角、四種 T 形邊與十字，所以可以畫出表格甚至樹狀；特殊線如 line_top_right_corner AS LINE。

捲動與固定欄：SET LEFT SCROLL-BOUNDARY [COLUMN n] 鎖定左側若干欄（不加 COLUMN 則用目前位置 sy-colno），必須寫在 TOP-OF-PAGE 與 TOP-OF-PAGE DURING LINE-SELECTION，因為系統每頁結束會把它歸 0。NEW-LINE NO-SCROLLING 讓下一行不隨橫向捲動（固定子標題），兩者可合用。SCROLL LIST TO PAGE p INDEX sy-lsind LINE l 可程式捲動到指定清單緩衝區的某頁某行。

頁面配置：NEW-PAGE 換頁；NEW-LINE（等於 WRITE /）；RESERVE n LINES（本頁剩不到 n 行就先換頁）；SKIP n；SKIP TO LINE n；BACK（回到表頭後第一行，與 RESERVE 合用時回到 RESERVE 的行）；POSITION n；SET BLANK LINES ON/OFF（OFF 為預設，不輸出空行）。RESERVE、POSITION、BACK 常用在列印郵寄標籤。

多語文字元素：文字元素（標準頁首、文字符號 text symbol、選擇文字）與原始碼分開存放，由登入語言決定顯示哪一種語言，因此不必動程式就能翻譯；定義輸出長度時要留足翻譯後的空間。引用方式有兩種：WRITE TEXT-001，或 WRITE 'Flight'(001)——後者的好處是沒有該語言翻譯時會顯示常值，不會變空白。忘了維護文字符號時，延伸語法檢查 SLIN 會報錯。

清單產生時的系統欄位：sy-linct（LINE-COUNT）、sy-linsz（LINE-SIZE）、sy-srows／sy-scols（視窗行數／欄數）、sy-pagno（目前頁）、sy-linno（目前行）、sy-colno（目前欄），後三個在產生清單時持續更新。標準清單介面自動提供：返回／退出／取消、首頁／上頁／下頁／末頁、列印、尋找／尋找下一個、儲存；標準選單有「儲存／傳送」與「清單表頭」。

5. 選擇畫面（一）：PARAMETERS 與 SELECT-OPTIONS

選擇畫面是程式與使用者之間的介面，用來限制從資料庫讀取的資料量。PARAMETERS 與 SELECT-OPTIONS 是宣告性語言元素，會自動產生標準選擇畫面（畫面號碼 1000）；接了 LDB 的程式，選擇畫面長相由 NODES 指定的節點決定；另外可以用 SELECTION-SCREEN BEGIN OF SCREEN 定義附加選擇畫面、CALL SELECTION-SCREEN 呼叫。報表在背景執行且有選擇畫面時，一定要有變式。基礎用法見 3-1 章，本節補原廠課的完整細節。

PARAMETERS 重點：

  • 名稱最多 8 個字元；可用 TYPE／LIKE；顯示文字在「轉到 → 文字元素 → 選擇文字」維護。
  • DEFAULT 預設值；MEMORY ID pid 從 SAP Memory 取目前值自動帶入。SAP Memory 是使用者專屬、存活到登出的記憶區，SET/GET 參數名最長 20 字元，可掛在資料元素上；在欄位按 F1 → Technical Information 的 Parameter ID 就能查到名稱。
  • OBLIGATORY 必填（畫面上出現問號／勾號標記，不填不能離開）。
  • 報表選擇畫面預設不做 ABAP 字典檢查；若參照的字典欄位有外鍵關係，可加 VALUE CHECK 觸發檢查。
  • AS CHECKBOX：一個字元，值為空白或 X。
  • RADIOBUTTON GROUP grp：群組名最多 4 個字元；同組只能選一個，被選者為 X；都沒預設時系統自動選第一個。
  • MODIF ID mod：把欄位歸到修改群組，方便執行時整批隱藏／鎖定（第 6 節）。

SELECT-OPTIONS 重點：名稱同樣最多 8 字元，但可以輸入範圍與複雜條件。它會產生一個帶表頭行的標準內表（選擇表 seltab），四欄 SIGN（I 包含／E 排除）、OPTION（運算子）、LOW、HIGH；FOR 後接已在 DATA（或 NODES）宣告的變數，LOW／HIGH 繼承其型別。

區塊：SELECTION-SCREEN BEGIN OF BLOCK blk WITH FRAME TITLE … 把邏輯相關的元素框起來，最多巢狀 5 層；標題可用 text-xxx 或最多 8 字元的欄位名（後者要在 INITIALIZATION 賦值）。Col18 特別提醒：給區塊加標題是為了無障礙。設計前先看交易碼 BIBS 的畫面設計準則。

Tabstrip：要定義三樣東西——選擇畫面上的子畫面區、各頁籤標題、每個頁籤對應的子畫面。子畫面寫法 SELECTION-SCREEN BEGIN OF SCREEN dynnr AS SUBSCREEN [NESTING LEVEL m] [NO INTERVALS]：NESTING LEVEL 用來縮小子畫面避免出現捲軸（tabstrip 沒框用 0，外面每多一層框加 1）；NO INTERVALS 隱藏該畫面所有 SELECT-OPTIONS 的 HIGH。頁籤區塊 BEGIN OF TABBED BLOCK blk FOR n LINES，頁籤 SELECTION-SCREEN TAB (len) name USER-COMMAND ucomm [DEFAULT [PROGRAM prog] SCREEN dynnr]——name 是系統自動產生的變數（不必宣告），文字超過 len 會被截斷；有 DEFAULT 就必須有 SCREEN。頁籤與子畫面的關聯可延到執行時才決定：系統為每個 tabbed block 自動產生同名結構，含 prog、dynnr、activetab 三欄。事件次序：AT SELECTION-SCREEN 先跑目前頁籤的子畫面、再跑 1000；AT SELECTION-SCREEN OUTPUT 先跑 1000、再跑下一個可見頁籤的子畫面。

8. 邏輯資料庫（LDB）：結構、GET 事件、選擇畫面與 LDB_PROCESS

邏輯資料庫是一種特殊的 ABAP 程式：讀資料庫、依階層把資料交給報表，同時提供選擇畫面、輸入檢查與錯誤對話、權限檢查。優點（兩版教材相同）：預先定義的選擇畫面、可用選擇畫面版本／變式／程式自己的附加選擇來調整；開發者不必知道表的確切結構與關係；資料依表階層（主鍵順序）送達；效能改善集中一處，所有掛這個 LDB 的程式自動受惠；權限檢查在 LDB 而不在報表。同一個 LDB 可以當多個 QuickView、Query、報表的資料來源；可執行程式在程式屬性指定 LDB，其他程式用函數 LDB_PROCESS 呼叫。

  • 數量：强晟筆記寫「ECC5 約 230 個」，Col18 寫「SAP ERP 超過 250 個」。名稱最長 20 字元；多數是 3 字元，第 3 碼是應用領域，例如 DDF＝Debtor Data（客戶）＋ F（Financials）。
  • 維護工具：SE36 Logical Database Builder。LDB 程式名 SAPDB<ldbname>，選擇畫面定義在 Include DB<ldbname>SEL。
  • 教學用 LDB F1S（套件 BC_DATAMODEL）：SPFLI（航線）→ SFLIGHT（航班）→ SBOOK（訂位）。
  • 節點名最長 14 字元，四種型別：T 表（節點名＝透明表名，不允許深層型別）、S 字典型別（任意名稱，可深層結構）、C 型別群組中的複雜型別（不建議，SAP Query 用起來有缺點）、A 動態節點（執行時才決定型別）。

事件流程：START-OF-SELECTION 在控制權交給 LDB 讀取常式之前觸發；LDB 在 put_<node> 副程式中 SELECT，執行 PUT node 就觸發報表的 GET node（可能執行很多次）；GET node LATE 在該節點所有下層節點處理完、讀下一筆之前觸發；全部讀完才觸發 END-OF-SELECTION。LDB 每個事件都有對應副程式（如 init 對應 INITIALIZATION），先跑 LDB 副程式，再跑報表的事件區塊；選擇畫面的 PBO／PAI 副程式中做檢查，權限檢查 AUTHORITY-CHECK 通常在 PAI。讀取深度由報表中最底層的 GET 決定，LDB 會讀完直接存取路徑上的所有記錄——只要深層節點時效率很差，應換一個節點位置較高的 LDB 或自己寫 SQL。

中止敘述：CHECK 條件不成立即結束目前處理區塊；STOP 結束處理但先執行 END-OF-SELECTION（若 STOP 就在 END-OF-SELECTION 中則立即結束並顯示清單）；EXIT 立即離開程式、不執行 END-OF-SELECTION，已產生的清單照樣顯示；REJECT 放棄目前這筆，在同一階層讀下一筆（可在副程式中用）。GET 事件開始時系統自動換行，並把格式重設為預設。

LDB 選擇畫面：FOR NODE 把選擇條件分配給節點，畫面長相取決於報表的 NODES 與 GET；SELECTION-SCREEN FIELD SELECTION FOR TABLE/NODE 允許報表用 GET node FIELDS f1 f2 只讀需要的欄位；DYNAMIC SELECTIONS FOR NODE 讓選擇畫面出現「動態選擇」按鈕，可選哪些欄位由選擇視圖（Selection View）決定：SAP 型或客戶自建的 CUS 型（CUS 優先）。建立方式：ABAP 編輯器 → Other Object → More → Selection view，Origin＝CUS、Name＝STANDARD （依講義步驟整理）。大型 LDB 有多個選擇畫面版本（用 EXCLUDE 取子集），在程式屬性輸入版本號。只用到子節點（如 SFLIGHT）時，父節點（SPFLI）的選擇條件也會出現。

報表自己加的選擇條件：若附加的 SELECT-OPTIONS 不是 LDB 的動態選擇欄位，LDB 的 WHERE 不會用到它，報表必須在 GET 區塊中自己 CHECK seltab；PARAMETERS 則要寫完整邏輯條件（簡寫 CHECK seltab 只適用 SELECT-OPTIONS）。

LDB_PROCESS（4.5 起）：讓對話程式、模組池也能用 LDB，還能多次呼叫。要準備依字典結構 LDBCB 的內表：LDBNODE（節點名）、GET（處理 GET）、GET_LATE（處理 GET LATE）、CB_PROG（回呼程式）、CB_FORM（回呼副程式名）；要讓 LDB 可重複處理，LDB 程式中必須有 LDB_PROCESS_INIT 副程式。回呼副程式中的條件檢查不成立時把參數 selected 設為空白，就不會再處理更深的節點。

9. 不用 LDB 自行取數：View、JOIN、FOR ALL ENTRIES、聚合與 GROUP BY／HAVING／ORDER BY

Open SQL（現稱 ABAP SQL）優於 Native SQL：與資料庫無關、可換資料庫而不改程式、完整整合在 Workbench 並有語法檢查、可使用 SAP 表緩衝。Native SQL 寫在 EXEC SQL [PERFORMING form] … ENDEXEC 之間，絕對不可用 Native SQL 修改 SAP 資料（參照完整性由 SAP 程式維護）；真的要用就集中在一個 Include，並限於 ISO 9075:1992 標準 SQL。S/4HANA 需要資料庫特有功能時請改用 AMDP 或 ADBC（CL_SQL_STATEMENT），不要再寫 EXEC SQL。

多表讀取的五條效能原則：① 結果集要小（適當 WHERE）；② 資料庫與應用伺服器間傳輸要少（明列欄位，不要 SELECT *）；③ 查詢次數要少（JOIN 取代巢狀 SELECT）；④ 搜尋範圍要小（WHERE 能用上索引）；⑤ 減輕資料庫負擔（善用 SAP 緩衝）。Col18 另加一句：有 SQL 的程式一定要做 Code Inspector（SCI）、執行時期分析（SAT）或 SQL Trace（ST05），效能調校細節見 5-21 章 BC490。

技術重點與限制
資料庫 View（SE11）在資料庫實作為 INNER JOIN；4.0 起可緩衝（規則同表緩衝，適合以讀為主）；優點：集中維護、可重用、程式只要一句 SELECT；缺點：彈性低，可能缺欄位。建立：SE11 → Database View → Table/Join Conditions（Relationships 鈕依外鍵帶出關聯）→ 檢查系統建議的 JOIN 條件 → View Flds → 啟用 （依講義步驟整理）。S/4HANA 新開發改用 CDS View（5-16 章）
INNER JOIN只留兩邊都符合條件的組合；條件不限主鍵，可用有外鍵關係或同 Domain 的欄位；同名欄位要加表名或別名；由資料庫決定讀表順序與索引
LEFT OUTER JOIN左表全部保留，右表沒資料的欄位由資料庫填 NULL，進 ABAP 時轉成型別初始值。例：不是每家航空公司（SCARR）都有航線（SPFLI），但名稱全都要列出。舊限制：右邊只能是一張表或 View、ON 只能用 AND、ON 每個比較都要有右表欄位、至少一個真正的 JOIN 條件。NetWeaver 7.40 SP05 起的新 Open SQL 已放寬，ON 條件不必再含右表欄位
FOR ALL ENTRIES以集合方式運作：先把第一批資料收進內表，一定要先檢查內表不為空——空內表會讓 FAE 讀回整張表；可先 DELETE ADJACENT DUPLICATES 去重避免重複讀；itab-col 是佔位符不是內表元件；結果自動去除重複列。建議用在「第一批資料不是從資料庫讀、而是已在程式中（例如使用者輸入）」的情況，否則用 JOIN。强晟筆記：JOIN 與 View 的效能遠高於 FAE
巢狀 SELECT內層 SELECT 會隨外層每一筆各執行一次，主從式環境效能極差；只能當最後手段，且要把筆數最少的表放最外層。4.0 起可改用子查詢

聚合函數：MAX、MIN、AVG（數值欄；結果型別 F）、SUM（數值欄）、COUNT( DISTINCT col )（不同值個數）、COUNT(*)（列數；結果型別 I）。MAX／MIN／SUM 的結果型別＝字典欄位型別；目標變數的型別要夠大。GROUP BY：沒有用在聚合函數的欄位都必須列在 GROUP BY；STRING／RAWSTRING 欄位不能 GROUP BY；Pool／Cluster 表不能 GROUP BY（S/4HANA 已大多轉成透明表）。用 INTO CORRESPONDING FIELDS 時，聚合欄要用 AS 取別名對應目標欄位。HAVING 限制的是群組（語法同 WHERE，可含聚合函數；同一欄可在 SELECT 用一種聚合、在 HAVING 用另一種）。ORDER BY：沒列在 ORDER BY 的欄位順序是未定義的，同一句跑兩次結果可能不同；ORDER BY PRIMARY KEY 只適用單表 SELECT *；排聚合欄要用別名；除了 ORDER BY PRIMARY KEY，加 ORDER BY 一律繞過 SAP 緩衝；效能上只在有索引支援時讓資料庫排序。

10. 資料格式化與控制層處理：內表 AT 與 Extract 資料集

控制層處理（control level processing）把資料分組輸出，讓清單結構更清楚。資料要先放進內表並依控制欄位升冪排序（也可以用 Extract 資料集）。4.0 起內表有三種：STANDARD、SORTED、HASHED（內表詳見 2-2 章）。

  • 填內表：SELECT … INTO TABLE 批次讀取；APPEND 附加到最後（只能用在 STANDARD／SORTED，之後 sy-tabix＝新行索引）；COLLECT 依非數值欄（鍵）找相同行，找到就把數值欄累加，找不到就新增——非鍵欄位必須全是數值。
  • SORT：無 BY 時依表鍵；BY f1 f2 任意型別欄位；ASCENDING（預設）／DESCENDING；SORTED 表不能用別的順序排；控制層處理必須是升冪。
  • LOOP … ENDLOOP：EXIT 中斷；ENDLOOP 後 sy-subrc＝0 表示至少跑一次、4 表示沒有任何行。
  • AT 結構：AT FIRST／AT LAST 各一次；AT NEW f 在 f（以及 f 左邊所有欄位）值改變時、控制層開始；AT END OF f 在控制層結束。中斷欄位要依序是內表的第 1、2… 欄。順序必須是：AT FIRST → AT NEW f1 → AT NEW f2 → 單筆處理 → AT END OF f2 → AT END OF f1 → AT LAST。在 AT 區塊內，控制鍵右邊的欄位內容不可依賴（强晟筆記：字元欄位被填 *、數值欄位清空）；寫 SUM 會把該層數值欄自動加總；ENDAT 後恢復為目前這筆的值。

Extract 資料集（舊技術）：用 FIELD-GROUPS 宣告欄位群組，INSERT f1 f2 INTO fg 把全域資料物件（或欄位符號，未指派者會被忽略）放入群組；特殊群組 HEADER 必須存在，是每筆記錄的排序鍵，系統自動把它放在其他群組前面，不能對 HEADER 下 EXTRACT。EXTRACT fg 把一筆寫入循序資料集；處理完用 SORT [BY …]（欄位必須在 HEADER 中）排序，再用不帶表名的 LOOP … ENDLOOP 處理，資料放回同名程式欄位。INSERT 不是宣告敘述，所以可在 START-OF-SELECTION 動態擴充群組；但某群組一旦 EXTRACT 過就不能再 INSERT。HEADER 中沒值的欄位以十六進位 0 填入，0 越多代表階層越深。單筆處理用 AT fg [WITH fg2]（fg 後面緊跟 fg2 才處理——用來「有明細才印表頭」）；Extract 不能用 SUM 敘述，只能在 AT END OF／AT LAST 中用 CNT(header 欄) 與 SUM(數值欄)，其他地方用會短路（runtime error）；Extract 的 LOOP 不能巢狀，但可連續多個。搭配欄位符號與單選鈕可讓同一支程式依使用者選擇換排序與輸出格式。

12. 互動式清單：細節清單、HIDE、AT LINE-SELECTION、系統欄位

每個基本清單最多可有 20 層細節清單，每層有自己的清單緩衝區；細節清單功能與基本清單相同。「返回」或「取消」離開目前清單並釋放其緩衝區，「退出」回選擇畫面。START-OF-SELECTION、GET、END-OF-SELECTION、TOP-OF-PAGE、END-OF-PAGE 只用於基本清單，離開基本清單後不再觸發；細節清單由 AT LINE-SELECTION（雙擊、點 HOTSPOT、按功能碼 PICK 的「細節」圖示或 F2）與 AT USER-COMMAND（選單、按鈕、功能鍵，用 CASE 判斷功能碼）產生；細節清單的頁首用 TOP-OF-PAGE DURING LINE-SELECTION，多層時用 CASE sy-lsind 區分。

  • sy-lsind：目前清單層級，觸發互動事件時加 1。事件中若沒有任何 WRITE／ULINE／SKIP，系統把 sy-lsind 還原，不產生新清單；也可在程式中改 sy-lsind 控制最大層數。
  • HIDE：把全域欄位的名稱與值連同目前清單行位置存進 HIDE 區，必須緊接在該行最後一個 WRITE 之後；通常存鍵值。選取流程：使用者選一行 → 系統依 sy-lilli 找到該行 → 到 HIDE 區把值寫回對應欄位 → 執行 AT LINE-SELECTION → 產生細節清單。每層清單有自己的 HIDE 區。
  • 無效行選擇：選到沒有 HIDE 值的行（頁首、頁尾）。做法：每次 AT LINE-SELECTION 結束時清空 HIDE 欄位，下次若選到無效行欄位保持初始值，用 CHECK 擋掉，就不會產生細節清單。
  • 緩衝區回收：從第 5 層回到第 3 層時，第 4、5 層緩衝區會被自動刪除。
  • GUI 標題：SET TITLEBAR 'T01' WITH f1 … f9，標題名最多 20 字元且大寫，最多 9 個參數，展開後總長最多 70 字元，會持續到設新標題為止。
  • 對話框清單：WINDOW STARTING AT c1 r1 [ENDING AT c2 r2]，座標以主視窗左上 (0,0) 起算；r1 ≤ 0 時全螢幕顯示。
  • GET CURSOR FIELD f VALUE v：依游標位置取欄位名與值，sy-subrc＝0 在欄位上、4 不在。不要把 VALUE 取得的值直接放進 SELECT 的 WHERE——它是輸出格式字串，與非字元欄位比較會出錯，這時用 HIDE。

13. ALV Grid Control 基礎：Control Framework、容器畫面、SET_TABLE_FOR_FIRST_DISPLAY

使用者角度的 ALV（Col18 Unit 3 L1）：畫面由三區組成——工具列（呼叫程式可隱藏個別功能或整列）、清單標題（單行）、資料區。資料以內表傳入，超出範圍自動出現捲軸；欄位可分前導欄（顏色不同、橫向捲動時固定）與一般欄；可選儲存格、整列、整欄、列加欄；設定 Line Selection 時會多一欄選取按鈕；排序欄標題有紅色小三角，合計欄標題有 Σ。標準功能：明細（Details，以對話框顯示選取列）、升／降冪排序（可多欄）、搜尋、篩選、合計（總和、平均、最大、最小）、小計（依非數值欄分組）、列印、預覽（Views: Output List）、匯出、版面（Layout）、圖形。滑鼠左鍵選欄（Ctrl 多選）、拖曳換欄序、拖曳欄界調寬；右鍵可隱藏欄、Optimum Width、設為最後固定欄。小計步驟：選要合計的數值欄 → 按 Σ → 選要分組的非數值欄 → 按小計鈕（清單會先依分組欄升冪排序）；複雜小計則直接按小計鈕，在對話框左側設定排序欄、升降冪、是否小計與階層順序 （依講義步驟整理）。當列印或下載時，系統處理的是整張清單而不只是螢幕上看得到的部分。

技術背景：控制項（Control）是獨立、可重用的二進位元件，隨 SAP GUI 安裝在前端（ActiveX 或 JavaBeans），把功能從應用伺服器移到前端，ABAP 端有包裝類別（Control Wrapper）。所有控制項都透過 Control Framework（CFW）以同一種方式溝通：應用伺服器是 Automation Client，前端 SAP GUI 的 Automation Controller 是 Automation Server，方法呼叫以 RFC 送到前端。控制項不能單獨存在，必須有畫面上保留的區域 → 容器控制項 → ALV Grid 這條物件鏈。程式與兩個 ABAP 實例（容器、Grid 的代表物件）以及至少一個 Dynpro 溝通，總共四個實例：ABAP 端兩個、前端兩個。

容器類別用途
CL_GUI_CUSTOM_CONTAINERSAP Custom Container：畫面／子畫面中用 Screen Painter 畫出的 Custom Control 區域
CL_GUI_DIALOGBOX_CONTAINER非強制回應（amodal）對話框或全螢幕
CL_GUI_DOCKING_CONTAINER可停靠、可調大小的子視窗（可貼在選擇畫面邊上，不必另畫畫面）

建立容器畫面（SE80 右鍵 Create → Screen，或在 CALL SCREEN 100 上雙擊前向導覽）：屬性設畫面號碼、短文、Screen type＝Normal、Next Screen（預設是自己，避免按 Enter 就離開；填 0 或空白則使用者動作後回到呼叫點）→ Layout 用左側 Custom Control 鈕拉出區域並命名（例：CONTROL_AREA）→ 雙擊元素設 Resizing vertical／horizontal 及 Min. Lines／Min. Columns → 元素清單（綠色方塊鈕）中把 OK 型欄位命名（例 OK_CODE）（依講義步驟整理）。畫面有四部分：屬性、版面、元素清單、流程邏輯；流程邏輯不能寫 ABAP，只能用 MODULE 呼叫 MODULE … OUTPUT（PBO）／MODULE … INPUT（PAI），可在不同畫面共用並以 sy-dynnr 區分。

GUI 狀態：Screen Painter 畫的畫面不像清單或選擇畫面有預設功能，必須用 SET PF-STATUS 指定 GUI 狀態（Menu Painter SE41，由 PBO 的狀態名稱雙擊建立）。GUI 狀態＝選單列＋標準工具列＋應用工具列＋功能鍵設定；「系統」「說明」選單每個畫面都有且不能改。狀態型別有 Normal Screen、Dialog Box、Context Menu。ALV 容器畫面的最小狀態：至少啟用 Back、Cancel、Exit（放在標準工具列即自動對應功能鍵，也放進選單）；每次改介面都要重新啟用。功能碼型別「空白」的功能被觸發時，功能碼放進畫面的 OK 欄位，PAI 開頭的自動欄位傳遞把它帶到程式同名欄位（型別 sy-ucomm）；LEAVE TO SCREEN 0 回到呼叫點、LEAVE PROGRAM 結束程式；OK 欄位要每個對話步驟清空（Enter 不會改變它），以免下一個畫面誤判。

建立物件：參照變數 DATA go_x TYPE REF TO class；CREATE OBJECT（或 7.40 的 NEW）時自動執行 CONSTRUCTOR，它只能有 IMPORTING 參數與 EXCEPTIONS，所有必填參數都要給。容器用 container_name 指定畫面區域名；Grid 用 i_parent 指定容器。必須在含該區域畫面的 PBO 中、畫面送到前端之前建立，而且只能建一次——用 IF go_container IS INITIAL 包起來，否則每個 PBO 都會多產生一個物件。全螢幕 ALV 可用 i_parent = cl_gui_custom_container=>screen0，此時不需要容器與 Custom Control 區。CREATE OBJECT／CALL METHOD 可用 Pattern（ABAP Objects Patterns）或從 SE80 導覽區把類別／方法拖放到編輯區自動產生，選用參數會以註解帶入。前端資源在程式結束時自動釋放，也可呼叫 free( )（繼承自 CL_GUI_OBJECT），再 CLEAR／FREE 參照讓垃圾回收處理 ABAP 端物件。

資料保存原則：代表物件不複製資料，只保存對內表的參照，所以內表的生命週期必須不短於 Grid 物件（通常宣告為全域）；只能傳 STANDARD 表，不可用 SORTED／HASHED；使用者在 ALV 排序會真的改變程式中內表的順序，其他動作只讀。代表物件不能直接存的三樣東西——要顯示的資料、顯示規則（欄位目錄）、使用者預先格式化設定——都要放在程式變數中，用方法傳入。

SET_TABLE_FOR_FIRST_DISPLAY 參數：it_outtab（資料，必填，CHANGING）、i_structure_name（字典結構名，系統自動產生欄位目錄，內表要有同名欄位）、is_variant／i_save／i_default（版面變式）、is_layout（外觀）、is_print（列印）、it_special_groups（欄位群組文字）、it_toolbar_excluding（隱藏標準功能）、it_fieldcatalog、it_sort、it_filter（初始排序／篩選，通常不必給，使用者可互動改，也會隨變式存取）。REFRESH_TABLE_DISPLAY 重送資料：i_soft_refresh＝空白表示保留並套用目前排序篩選、X 表示保留但不套用；is_stable（LVC_S_STBL 的 row、col 設 X）保留捲動位置。改了內表的行結構就必須重新呼叫 SET_TABLE_FOR_FIRST_DISPLAY，因為欄位目錄要重建。

15. 欄位目錄 Field Catalog（LVC_T_FCAT）

欄位目錄是資料區的格式描述：代表物件要知道每一欄的型別與格式，才能在螢幕與列印清單正確顯示。內表型別 LVC_T_FCAT、工作區 LVC_S_FCAT，每一列對應 ALV 的一欄，靠 fieldname 連到資料表的欄位。三種情況：

16. ALV 事件與方法：DOUBLE_CLICK、TOOLBAR、USER_COMMAND、BUTTON_CLICK、列印事件、右鍵選單

事件怎麼從前端傳到程式：前端控制項觸發事件 → SAP GUI 的 Automation Controller 收到，轉成特殊功能碼（加附帶資料）送給執行環境的 Basis Services → 轉給 ABAP 程式中的代表物件 → 代表物件觸發 ABAP Objects 事件，通知已註冊的處理器方法（handler method）。代表類別（proxy class，即 Control Wrapper）以統一方式存取 CFW；CFW 在前端與應用伺服器兩邊都維護作用中實例的清單。觸發事件的物件不知道誰會處理，這與一般方法呼叫不同。

處理器方法：任何類別都可以為其他類別的 public 事件定義處理器，定義部分加 FOR EVENT evt OF class，命名慣例 on_<event>；簽名只能有 IMPORTING，參數名與型別取自事件，不必全部接；每個事件都有隱含參數 sender（觸發的實例）。可以是靜態方法（CLASS-METHODS，不必建物件，呼叫用 =>）或實例方法（METHODS，要建物件，用 ->）。預設不會執行，必須在執行時用 SET HANDLER h FOR go_alv_grid（或 FOR ALL INSTANCES）註冊。物件導向基礎見 5-2 章 BC401。

17. 從報表呼叫其他程式與資料傳遞（SUBMIT、CALL TRANSACTION、ABAP／SAP Memory）

同步呼叫有兩種：中斷目前程式執行新程式、完成後回來；或結束目前程式啟動新程式。同一使用者 Session 中完整的 ABAP 程式只能循序執行；要平行請用 CALL FUNCTION … STARTING NEW TASK（見 4-1 章）。

敘述記憶體行為說明
SUBMIT prog [VIA SELECTION-SCREEN] AND RETURN開新的內部 Session 疊在堆疊上執行 1 型程式；VIA SELECTION-SCREEN 顯示其標準選擇畫面；AND RETURN 完成後回到下一句
SUBMIT prog（不加 AND RETURN）以被呼叫程式取代目前的內部 Session不回來
CALL TRANSACTION tcode [AND SKIP FIRST SCREEN]開新內部 Session插入呼叫鏈；SKIP FIRST SCREEN 不顯示第一個畫面內容但流程邏輯照跑；UPDATE 附加指定更新技術（非同步預設、同步、本地）
LEAVE TO TRANSACTION tcode移除所有內部 Session，開一個新的，ABAP Memory 被清空效果同命令欄輸入 /n<tcode>
LEAVE PROGRAM／程式自然結束移除堆疊頂端的內部 Session若是被 CALL TRANSACTION 或 SUBMIT AND RETURN 呼叫，回到呼叫端下一句；否則回到最初啟動程式的選單
Col18 p242 寫 LEAVE TO TRANSACTION「開一個含呼叫端程式 context 的新內部 Session」——應為被呼叫交易的程式 context，呼叫端已經被整個移除了。

記憶體結構：一個外部 Session＝一個 SAP GUI 視窗（系統 → 建立 Session，或 /O<tcode>），預設一個使用者最多 6 個；每個外部 Session 最多 9 個內部 Session（堆疊），每支程式在自己的內部 Session 執行，資料只在該 Session 可見。呼叫函數模組時，若該函數群組在目前內部 Session 還沒載入，就載入為額外的程式群組並初始化其全域資料；之後同群組的函數共用這些全域資料；新的內部 Session 要重新載入。

跨內部 Session 傳資料的方式：被呼叫程式的介面（標準選擇畫面）、ABAP Memory、SAP Memory、Shared Memory／Shared Buffer、資料庫表、前端本機檔（GUI_UPLOAD／GUI_DOWNLOAD 或 CL_GUI_FRONTEND_SERVICES）。

  • 選擇畫面介面：SUBMIT 時指定變式（USING SELECTION-SET）或 WITH p = v、WITH so IN range（EQ、NE、I、E 意義同選擇條件；多重值先用 TYPE RANGE OF 建表）；編輯器的 Pattern 可自動帶出目標程式的參數名。
  • ABAP Memory：使用者專屬、每個外部 Session 一份，可交換任何 ABAP 變數（欄位、結構、內表、複雜物件），不能跨外部 Session；/i 結束 Session 時釋放。EXPORT … TO MEMORY ID id（ID 最長 60 字元，同 ID 再 EXPORT 會覆蓋）、IMPORT … FROM MEMORY ID id（目標型別與名稱要一致，可用 TO 換名但型別須相同）、FREE MEMORY ID id。CALL TRANSACTION、SUBMIT 可用；LEAVE TO TRANSACTION 不行（記憶體被清掉）。
  • SAP Memory：使用者專屬、存活整個登入期間、所有外部 Session 共用，存 SET/GET 參數值，可作畫面欄位預設值。用 PARAMETERS／SELECT-OPTIONS 的 MEMORY ID、參照有參數 ID 的資料元素，或 SET PARAMETER ID 'pid' FIELD v／GET PARAMETER ID 'pid' FIELD v。
  • CALL TRANSACTION USING bdcdata：用 BDCDATA 內表餵畫面欄位——每個畫面先一行只填 program、dynpro、dynbegin＝X，之後每欄一行填 fnam／fval；可填 BDC_OKCODE（功能碼）、BDC_CURSOR（游標）。MODE A 全顯示（預設）／E 出錯才顯示／N 不顯示；MESSAGES INTO BDCMSGCOLL 型內表；sy-subrc 判斷成功。BDC 細節見 4-4 章、5-13 章 BC420。

18. ALV Object Model：CL_SALV_TABLE

基本原則：只要兩個方法——靜態方法 FACTORY（取代 CREATE OBJECT，傳入內表 t_table，回傳實例 r_salv_table；輸出型態也由它的參數決定）與實例方法 DISPLAY。三種輸出：全螢幕（預設）、嵌入容器（r_container）、經典清單（list_display = abap_true）。Pattern 或拖放產生呼叫時會連 TRY／CATCH 一起產生；可在「公用程式 → 設定 → ABAP 編輯器 → Pattern」勾選 Functional Writing Style。類別式例外要自己處理：TRY 包住、取消 CATCH 的註解、加 INTO 參照（型別為該例外類別或 CX_ROOT），未處理的例外會造成執行時期錯誤。

屬性物件的取法：每一種屬性或子物件（欄、按鈕、版面、列印…）都是另一個類別，類別名都是 CL_SALV_*，複數名代表一群（CL_SALV_COLUMNS_TABLE＝所有欄）、單數名代表一個（CL_SALV_COLUMN_TABLE＝某一欄）；它們不是從 CL_SALV_TABLE 繼承。做法永遠是兩步：① 用 CL_SALV_TABLE 的 GET_xxx 取得屬性物件（不是 CREATE OBJECT）；② 呼叫它的方法，改動立即生效。取一次就能呼叫多次。欄位順序影響所有欄，所以 set_column_position 在「所有欄」物件上；欄標題只屬於一欄，要先 get_columns( ) 再 get_column( 'X' )。

GET_FUNCTIONSCL_SALV_FUNCTIONS_LIST（排序、彙總等工具列功能；其 GET_FUNCTIONS 回傳各個 CL_SALV_FUNCTION）
GET_FUNCTIONAL_SETTINGSCL_SALV_FUNCTIONAL_SETTINGS（再 GET_HYPERLINKS、GET_TOOLTIPS）

GET_PRINTCL_SALV_PRINT

練習與自我檢核

  1. （Col18 U1）接到報表需求時，寫程式前要先確認哪四件事？
    要點：標準報表能否做到、能否涵蓋大部分、能否用 SAP Query／InfoSet Query／QuickViewer、自寫時有無 LDB 或函數／BAPI／方法可取數——即「先標準再客製」。
  2. 程式 ZTEST 的全域資料宣告應該在哪個 Include？
    要點：ZTEST_TOP（O01 為 PBO、I01 為 PAI、E01 為事件、F01 為副程式）。
  3. 說明 FORMAT RESET 與 FORMAT COLOR OFF 的差別，以及 WRITE … COLOR 與 FORMAT 衝突時誰優先。
    要點：RESET 連 INTENSIFIED ON 標準設定一起關；COLOR OFF 只關顏色；欄位層級的格式優先（就近原則）。每個事件開始 FORMAT 會重設。
  4. SELECT-OPTIONS 的選擇集合如何計算？使用者什麼都不填時會發生什麼？為什麼 Casper 建議用多筆 EQ 而非 BT？
    要點：所有 I 的聯集減去所有 E 的聯集；不填＝不限制；BT 比字典序，遇 ALPHA 前導零、號碼不連續、編碼改過會漏抓或多抓。
  5. 選擇畫面上 AT SELECTION-SCREEN OUTPUT 與 AT SELECTION-SCREEN 分別相當於 Dynpro 的什麼事件？要隱藏 MODIF ID 為 ADV 的所有欄位，程式寫在哪裡、怎麼寫？
    要點：OUTPUT＝PBO、AT SELECTION-SCREEN＝PAI；在 OUTPUT 中 LOOP AT SCREEN，group1＝'ADV' 時 active＝0 並 MODIFY SCREEN。
  6. 使用 Tabstrip 時，AT SELECTION-SCREEN 與 AT SELECTION-SCREEN OUTPUT 各被處理幾次、順序為何？
    要點：各兩次；PAI 先目前頁籤子畫面再 1000；PBO 先 1000 再下一個可見頁籤子畫面。
  7. 變式命名 CUS&DAILY 與 DAILY 在傳輸上有什麼不同？背景月報的日期條件應怎麼設定？
    要點：CUS&／SAP& 為系統變式、用戶端無關、隨程式自動傳輸；其他要手動加到傳輸請求。日期用選擇變數 D（動態日期）或 T（TVARVC）。
  8. LDB 中 STOP、EXIT、REJECT、CHECK 的差異？報表自己加的 SELECT-OPTIONS 為什麼要在 GET 裡 CHECK？
    要點：STOP 會先跑 END-OF-SELECTION、EXIT 不跑、REJECT 放棄本筆讀同層下一筆、CHECK 結束目前區塊；LDB 的 WHERE 由 LDB 程式決定，報表無法修改，非動態選擇欄位只能讀回後自己過濾。
  9. FOR ALL ENTRIES 最危險的錯誤是什麼？何時該用 FAE、何時用 JOIN？
    要點：驅動內表為空時讀回整張表；驅動資料已在程式（例如使用者輸入、上傳檔）時用 FAE，否則 JOIN；FAE 不能 ORDER BY，取回後自己 SORT 並注意結果已去重。
  10. 原廠測驗說「HAVING 會限制資料庫表被選出的列數」，這句話精確嗎？
    要點：不精確；WHERE 限制列、HAVING 限制 GROUP BY 之後的群組。另外沒列在 ORDER BY 的欄位順序是未定義的，HANA 上尤其明顯。
  11. 寫出控制層 AT 區塊的正確順序，並說明內表要先做什麼。改用 7.40 語法該怎麼寫？
    要點：AT FIRST → AT NEW f1 → AT NEW f2 → 單筆 → AT END OF f2 → AT END OF f1 → AT LAST；先依控制欄位升冪 SORT，控制欄位要是前幾欄；新寫法 LOOP AT … GROUP BY ＋ REDUCE。
  12. 比較內表與 Extract 資料集（至少四點）。
    要點：內表可多個／Extract 一個；內表可隨時增刪改／Extract 只能 EXTRACT、SORT、LOOP 且 SORT 後不能再加；內表單一靜態行型別／Extract 多結構動態；內表合計可在控制頭／Extract 只在控制尾且 SUM(f)、CNT(f) 經最佳化。
  13. 用程式控制列印時，為什麼 NEW-PAGE PRINT ON 的 PARAMETERS 結構必須由 GET_PRINT_PARAMETERS 產生？如何一次產生多個 Spool？
    要點：結構含內部檢查和，錯了程式中斷；valid＝X 才可用；每次 new_list_id＝X、PRINT OFF 結束目前請求，號碼看 sy-spono。
  14. 互動清單中如何避免「無效行選擇」？ALV 中對應的做法是什麼？

  19. 在 ALV Grid 工具列加一個「Bookings」按鈕並處理它，需要哪些事件與步驟？為什麼 SET HANDLER 要寫在 SET_TABLE_FOR_FIRST_DISPLAY 之前？
    要點：TOOLBAR 處理器 APPEND 到 e_object->mt_toolbar、USER_COMMAND 處理器依 e_ucomm 處理、SET HANDLER 註冊；TOOLBAR 在 SET_TABLE_FOR_FIRST_DISPLAY 執行期間就觸發。要把標準「明細」換成自訂功能，用 BEFORE_USER_COMMAND＋set_user_command。
  20. ABAP Memory 與 SAP Memory 的範圍差異？為什麼 LEAVE TO TRANSACTION 之後 IMPORT FROM MEMORY 拿不到資料？
    要點：ABAP Memory 每個外部 Session 一份、可傳任意變數；SAP Memory 整個登入共用、只存 SET/GET 參數；LEAVE TO TRANSACTION 移除所有內部 Session 並清空 ABAP Memory。
  21. 用 CL_SALV_TABLE 改某一欄的標題與顏色，步驟是什麼？為什麼要 CAST？
    要點：get_columns( ) 取所有欄 → get_column( '欄名' ) 取單欄 → 呼叫 set_long_text／set_color；get_column 回傳型別是 CL_SALV_COLUMN，顏色、熱點等方法在子類別 CL_SALV_COLUMN_TABLE，所以要 CAST。捕捉 cx_salv_not_found 等例外。
  22. 一張 S/4HANA 上要處理上千萬筆 ACDOCA 資料的明細報表，本章哪個技術最適合？為什麼不是一般 SALV？
