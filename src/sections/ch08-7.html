五段流程（每支批導都該有，缺一段就會出事）：

  1. 讀檔：Excel → 字串內表（第 3 節）。
  2. 轉換：補前導零（ALPHA）、單位轉內碼（CUNIT）、日期格式、大小寫；保留 Excel 原始列號。
  3. 檢核：必填、主檔存在（物料、工廠、成本中心、工作中心）、重複（檔內重複與系統已存在）。

  5. 回報：每一列一個狀態燈與完整訊息，並存進應用日誌 SLG1（第 12 節）。

CLASS lcl_template IMPLEMENTATION.
  METHOD download.
    DATA: lv_file   TYPE string,
          lv_path   TYPE string,
          lv_full   TYPE string,
          lv_action TYPE i.

    cl_gui_frontend_services=>file_save_dialog(
      EXPORTING default_file_name = |{ iv_title }_{ sy-datum }.xlsx|
                default_extension = 'xlsx'
                file_filter       = cl_gui_frontend_services=>filetype_excel
      CHANGING  filename    = lv_file
                path        = lv_path
                fullpath    = lv_full
                user_action = lv_action
      EXCEPTIONS OTHERS = 1 ).
    IF sy-subrc <> 0 OR lv_action <> cl_gui_frontend_services=>action_ok.
      RETURN.                                   "使用者取消
    ENDIF.

    SELECT SINGLE relid, objid
      FROM wwwdata
      WHERE relid = 'MI'
        AND objid = @iv_objid
        AND srtf2 = 0
      INTO @DATA(ls_key).
    IF sy-subrc <> 0.
      MESSAGE |SMW0 找不到模板 { iv_objid }| TYPE 'S' DISPLAY LIKE 'E'.
      RETURN.
    ENDIF.

    DATA(ls_wwwkey) = CORRESPONDING wwwdatatab( ls_key ).
    DATA(lv_dest)   = CONV rlgrap-filename( lv_full ).

                destination = lv_dest
      IMPORTING rc          = lv_rc.

      MESSAGE |模板已下載：{ lv_full }| TYPE 'S'.
    ELSE.
      MESSAGE |模板 { iv_objid } 下載失敗| TYPE 'S' DISPLAY LIKE 'E'.
    ENDIF.
  ENDMETHOD.
ENDCLASS.

3. Excel 上傳三選一：ALSM／TEXT_CONVERT_XLS_TO_SAP／CL_FDT_XL_SPREADSHEET

六支程式用了三種讀 Excel 的方式：固定資產與工作中心用標準 ALSM_EXCEL_TO_INTERNAL_TABLE；BOM 與途程用自建的 ZALSM_EXCEL_TO_INTERNAL_TABLE；客戶用自建的 ZFM_EXCEL_SHEET_UPLOAD（可指定工作表，原始碼不在素材中）。途程程式的 docx 附了 ZALSM 的截圖：函數群 ZPPFG1「PP 模組函數組」，短文「excel to internal table 擴充字段長度」，匯入參數 FILENAME（LIKE RLGRAP-FILENAME）、I_BEGIN_COL／I_BEGIN_ROW／I_END_COL／I_END_ROW（TYPE I），表格參數 INTERN LIKE ZALSMEX_TABLINE，例外 INCONSISTENT_PARAMETERS、UPLOAD_OLE。原始碼與標準版完全相同，只把輸出結構換成欄位更長的 ZALSMEX_TABLINE。

為什麼要複製一份？因為標準結構 ALSMEX_TABLINE 的 VALUE 只有 CHAR 50，物料長描述（200 字）、客戶地址（255 字）、規格型號（255 字）會被截斷。這是最常見的「批導後資料少一截」原因。

做法原理優點限制建議
ALSM_EXCEL_TO_INTERNAL_TABLEOLE 開啟使用者電腦上的 Excel → 選取範圍 → 複製到剪貼簿 → clipboard_import 讀回，以 TAB 切欄任何版本都有；輸出為 ROW／COL／VALUE 三欄，容易寫成通用程式需 SAP GUI for Windows＋已安裝 Excel；不能背景執行；VALUE 只有 50 字；會覆蓋使用者剪貼簿；大量資料很慢；Excel 行程偶爾殘留只適合小量、臨時工具
TEXT_CONVERT_XLS_TO_SAP（TRUX 函數群）同樣經由前端 Excel，直接依欄位順序轉成你給的結構化內表一行就轉成型別化內表；I_LINE_HEADER 可略過表頭同樣依賴前端 Excel／OLE；欄位順序必須與結構完全一致；型別轉換失敗整批報 CONVERSION_FAILED，看不出是哪一列結構固定的簡單模板可用
CL_FDT_XL_SPREADSHEET把 xlsx 以二進位上傳（GUI_UPLOAD BIN），在應用伺服器端解析 Office Open XML不需要前端安裝 Excel；可讀多個工作表；無 50 字限制；也可讀 AL11 上的檔案 → 可排背景只支援 xlsx（不支援舊 xls）；所有儲存格回傳為字串，日期會變成 Excel 序號（例如 45108）要自己換算S/4HANA 首選（也可考慮開源 abap2xlsx）

通用讀檔類別：回傳「列號＋欄號＋值」的中立格式，後續再依模板對應到型別化結構。保留 Excel 列號，錯誤回報才找得到是哪一列。

CLASS lcl_xlsx IMPLEMENTATION.
  METHOD read.
    DATA lt_bin TYPE solix_tab.
    cl_gui_frontend_services=>gui_upload(
      EXPORTING filename   = iv_file
                filetype   = 'BIN'
      IMPORTING filelength = DATA(lv_len)
      CHANGING  data_tab   = lt_bin

    IF sy-subrc <> 0.
      MESSAGE |檔案 { iv_file } 讀取失敗| TYPE 'E'.
    ENDIF.

    DATA(lv_xstr) = cl_bcs_convert=>solix_to_xstring( it_solix = lt_bin
                                                      iv_size  = lv_len ).
    DATA(lo_xl) = NEW cl_fdt_xl_spreadsheet( document_name = iv_file
                                             xdocument     = lv_xstr ).

    lo_xl->if_fdt_doc_spreadsheet~get_worksheet_names(
      IMPORTING worksheet_names = DATA(lt_sheets) ).
    DATA(lv_sheet) = COND string( WHEN iv_sheet IS NOT INITIAL THEN iv_sheet
                                  ELSE lt_sheets[ 1 ] ).

    DATA(lr_tab) = lo_xl->if_fdt_doc_spreadsheet~get_itab_from_worksheet( lv_sheet ).
    FIELD-SYMBOLS <lt_sheet> TYPE STANDARD TABLE.
    ASSIGN lr_tab->* TO <lt_sheet>.

    LOOP AT <lt_sheet> ASSIGNING FIELD-SYMBOL(<ls_line>) FROM iv_first_row.
      DATA(lv_row) = sy-tabix.                   "＝Excel 列號
      DO.
        ASSIGN COMPONENT sy-index OF STRUCTURE <ls_line> TO FIELD-SYMBOL(<lv_cell>).
        IF sy-subrc <> 0.
          EXIT.
        ENDIF.
        IF <lv_cell> IS NOT INITIAL.
          INSERT VALUE #( row = lv_row col = sy-index
                          value = condense( CONV string( <lv_cell> ) ) )
                 INTO TABLE rt_cells.
        ENDIF.
      ENDDO.
    ENDLOOP.
  ENDMETHOD.

  METHOD to_date.
    IF strlen( iv_cell ) = 8 AND iv_cell CO '0123456789'.
      rv_date = iv_cell.                          "使用者輸入文字 20240101
    ELSEIF iv_cell CO '0123456789. '.
      rv_date = CONV d( '18991230' ) + CONV i( iv_cell ).  "Excel 序號
    ENDIF.

7. ZSDU009 的問題與 S/4HANA 正解：CL_MD_BP_MAINTAIN 一次到位

原程式最大的問題是一個客戶拆成七、八次 COMMIT。只要中間任何一步失敗（例如銷售範圍的付款條件打錯），前面的 BP、角色、公司代碼早已寫進資料庫，留下一個「半成品客戶」：有 BP 沒銷售視圖、有銷售視圖沒稅號。業務第二次重跑又因為「BP 已存在」走修改分支，情況更亂。其他問題：

  • 合作夥伴功能被做了 ALPHA 轉換：PARVW1 = |{ PARVW1 ALPHA = IN }|。PARVW 的轉換常式是 PARVW（外碼 SP／SH／BP／PY ↔ 內碼 AG／WE／RE／RG），不是 ALPHA；應該用 CONVERSION_EXIT_PARVW_INPUT，否則使用者照畫面填 SH 會失敗。
  • 重複檢查只用 KNA1-NAME1 = 名稱，找到了也只在訊息加一個「/」，並沒有擋下。
  • 地址長度切片：street+35(40)、+75(40)… 把 255 字的街道硬切成 5 段塞進 STREET、STR_SUPPL1～3、LOCATION，會把中文字從中間切開。
  • ALV 欄位目錄以巨集 INIT_FIELDCAT 定義；「BP 編號欄可編輯」只對寫死的某一個開發者帳號開放，且 HANDLE_CHANGE 中留有 BREAK 開發者帳號——正式機的權限必須用權限物件控管，不能寫死帳號。
  • 程式表頭與 include 註解還是從別的程式複製來的名字，Tabstrip 的 PROG 常數也指向另一支程式——複製貼上開發的典型後遺症。

S/4HANA 正解：把 BP 一般資料、地址、角色、稅號、銀行、客戶的公司代碼、銷售範圍、合作夥伴功能、稅分類全部組進一個 CVIS_EI_EXTERN，呼叫一次 CL_MD_BP_MAINTAIN=>MAINTAIN，檢查訊息後只 COMMIT 一次。要嘛整個客戶建好，要嘛什麼都沒留下。

9. ZPPU002 BOM 批導：BAPI_MATERIAL_BOM_GROUP_CREATE 與分組控制

業務情境：研發把 BOM 整理在 Excel，一個父件一個 Sheet 太麻煩，於是約定「一列一個組件、父件資訊每列重複」，程式依父件分組建立。

模板（4 列表頭，第 5 列起為資料）：表頭部分 MAST-MATNR 物料、物料描述、MAST-WERKS 工廠（固定 1000）、MAST-STLAL 備選 BOM、MAST-STLAN 用途（固定 1）、STKO-BMENG 基本數量、STKO-BMEIN 單位、STKO-STLST 狀態（固定 1）、STKO-DATUV 有效期自；組件部分 STPO-POSNR 項目、STPO-POSTP 項目類別（固定 L）、STPO-IDNRK 組件、組件描述、STPO-MENGE 數量、基本計量單位（模板誤寫成「STOP-MEINS」）、STPO-SORTF 排序字串、替代項目的 ALPGR 組／ALPST 策略／ALPRF 優先級／EWAHR 使用可能性。第 1 列還有一段說明「標記相同數值」，意指同一父件的表頭欄位要填相同值。

原程式架構：F4 選檔的 FORM 裡順便讀了 Excel（使用者按 F4 選完檔就已讀檔，直接在欄位輸入路徑則讀不到任何資料）→ END-OF-SELECTION 逐列處理，AT END OF stlan 時呼叫 BAPI_MATERIAL_BOM_GROUP_CREATE（BOMGROUP／VARIANTS／ITEMS／MATERIALRELATIONS／ITEMASSIGNMENTS 五張表以同一個 BOM_GROUP_IDENTIFICATION 串起來）→ 以 REUSE_ALV_GRID_DISPLAY_LVC 顯示訊息。

原程式的問題：

  • 一次撈整張 MAST、MARA、MARC：SELECT * INTO TABLE @DATA(lt_mara) FROM mara，數十萬筆物料全部進記憶體，只為了查幾百個組件的單位。
  • 控制層級（AT END OF）依賴結構欄位順序與排序：結構是 matnr、maktx1、werks、stlal、stlan…，AT END OF stlan 會把左邊所有欄位（含物料描述）都算進分組鍵；Excel 若沒照父件排序、或同一父件描述打得不一致，BOM 就被拆成好幾次建立（第二次報「BOM 已存在」）。
  • 工廠、用途、狀態、項目類別在程式中被寫死（模板填什麼都沒用）；組件單位若與發貨單位（MARC-AUSME）不同就改用基本單位，靜悄悄地改掉使用者的輸入。
  • 成功與否的判斷用「LOOP 錯誤訊息後 sy-subrc」，然後又呼叫沒有配對 OPEN 的 CSAP_MAT_BOM_CLOSE 再 COMMIT 一次；錯誤訊息的「行次」欄位被註解掉，使用者不知道是哪一列錯。

現代改寫：用 LOOP AT … GROUP BY 明確以（物料、工廠、用途、備選）分組，不受欄位順序影響；主檔檢核只查檔案裡出現的物料。

METHOD create_boms.
  " 只查檔案中出現的物料（父件＋組件），不要整表撈
  DATA(lt_matnr) = VALUE ty_matnr_range(
    FOR r IN mt_rows ( sign = 'I' option = 'EQ' low = r-matnr )
                     ( sign = 'I' option = 'EQ' low = r-idnrk ) ).
  SORT lt_matnr BY low.
  DELETE ADJACENT DUPLICATES FROM lt_matnr COMPARING low.

  SELECT matnr, werks FROM marc
    WHERE matnr IN @lt_matnr AND werks = @p_werks
    INTO TABLE @DATA(lt_marc).                 "注意 IN 範圍筆數上限，量大時分批
  SELECT matnr, werks, stlan, stlal FROM mast
    WHERE matnr IN @lt_matnr AND werks = @p_werks
    INTO TABLE @DATA(lt_mast).

  LOOP AT mt_rows INTO DATA(ls_row)
       GROUP BY ( matnr = ls_row-matnr werks = ls_row-werks
                  stlan = ls_row-stlan stlal = ls_row-stlal )
       ASSIGNING FIELD-SYMBOL(<grp>).

    IF line_exists( lt_mast[ matnr = <grp>-matnr werks = <grp>-werks
                             stlan = <grp>-stlan stlal = <grp>-stlal ] ).

                      sort_string = ls_item-sortf

                      alt_item_prio = ls_item-alprf usage_prob = ls_item-ewahr
                      prod_rel = abap_true cost_rel = abap_true ) TO lt_items.
    ENDLOOP.

    DATA(ls_first) = VALUE ty_bom_row( mt_rows[ matnr = <grp>-matnr werks = <grp>-werks

    DATA(lt_bomgrp) = VALUE ty_bgr( ( bom_group_identification = 'G1' object_type = 'BGR'
                                      object_id = 'SIMPLE1' bom_usage = <grp>-stlan
                                      created_in_plant = <grp>-werks ) ).
    DATA(lt_variant) = VALUE ty_bom( ( bom_group_identification = 'G1' object_type = 'BOM'
                                       object_id = 'SIMPLE1' alternative_bom = <grp>-stlal
                                       bom_status = ls_first-stlst base_qty = ls_first-bmeng
                                       base_unit = ls_first-bmein
                                       valid_from_date = ls_first-datuv function = 'NEW' ) ).
    DATA(lt_matrel) = VALUE ty_mbm( ( bom_group_identification = 'G1'
                                      material_long = <grp>-matnr plant = <grp>-werks
                                      bom_usage = <grp>-stlan alternative_bom = <grp>-stlal ) ).
    DATA(lt_assign) = VALUE ty_rel( ( bom_group_identification = 'G1'
                                      sub_object_type = 'ITM' sub_object_id = 'SIMPLE1'
                                      super_object_type = 'BOM' super_object_id = 'SIMPLE1'
                                      valid_from_date = ls_first-datuv function = 'NEW' ) ).

    CALL FUNCTION 'BAPI_MATERIAL_BOM_GROUP_CREATE'

        testrun           = p_test              "先模擬（參數名以 SE37 為準）

原程式架構：以 SHDB 錄製的 CR01 畫面序列（SAPLCRA0 0101 → 4000 反覆以 OK 碼 =VORA、/00、=VK11、=UPD 切頁籤）組 BDCDATA，CALL TRANSACTION 'CR01' … MODE 'N' UPDATE 'S'，成功／失敗寫進結果表，最後 CALL SCREEN 2000 以 CL_GUI_ALV_GRID 顯示。程式底部另有一段 SUB_CREATE_WORKCENTER_TEST：用寫死的工廠、成本中心、作業類型測試 CRAP_WORKCENTER_CREATE，但 API03（預設值）與 CRCO（成本中心分配）參數都被註解掉，顯然沒試成功就改回 BDC；而且它的 DATA 區還整段複製了固定資產 BAPI 的變數宣告。

原程式的問題：

  • 作業類型的單位填錯欄：BDC 把 RC68A-LEINH(01)～(06) 填成「標準值計量單位 VGE01～06」，而不是模板的「單位 1～6（LEINH1～6）」。範例資料剛好兩者相同所以沒被發現，一旦作業單位與標準值單位不同（例如標準值 MIN、作業單位 H）就錯。
  • 「測試」勾選框沒作用：P_RUN 預設勾選，但 BDC 路徑完全沒讀它，使用者以為是模擬，其實已經建立。
  • 錯誤訊息：CALL TRANSACTION 沒有 MESSAGES INTO，事後用 sy-msgid／sy-msgno 呼叫 MESSAGE_TEXT_BUILD 又沒帶 MSGV1～4，得到的是「& 不存在」這種殘缺訊息；而且只保留最後一則。
  • 日期欄位以 CHAR10 直接丟進畫面，依賴使用者的日期格式設定（SU3）；權限檢查（C_ARPL_WRK）被註解掉。

11. ZPPU003 工藝路線批導：BAPI_ROUTING_CREATE

業務情境：每個自製物料一條途程（任務清單類型 N），一列 Excel 一道工序，工序帶工作中心、控制碼、工序短文、標準文本碼、基本數量與六個標準值（作業類型／標準值／單位）。

模板（4 列表頭）：MAPL-WERKS 工廠（預設 1000）、MAPL-MATNR 物料（內控號）、物料描述、MAPL-PLNNR 任務清單組碼（不填，由系統給號）、DATUV 生效日期、MAPL-PLNAL 組計數器、PLKO-KTEXT 途程描述、PLKO-VERWE 用途、PLKO-STATU 狀態、PLKO-PLNME 批量單位、PLPO-ARBPL 工作中心、PLPO-VORNR 工序號、PLPO-STEUS 控制碼、PLPO-LTXA1 工序短文本、PLPO-KTSCH 標準文本碼、PLPO-BMSCH 基本數量、PLPO-MEINH 計量單位、PLPO-LAR01～06／VGW01～06／VGE01～06。

原程式架構：F4 時以 ZALSM 讀 Excel（第 5 列起、35 欄）→ FRM_DEAL 做檢核並補物料描述與單位（批量單位、工序單位一律用 MARA-MEINS，模板填的值被忽略）→ 先顯示 ALV → 使用者按 START → 依（物料、工廠、組計數器）排序，AT END OF plnal 時呼叫 BAPI_ROUTING_CREATE（TASK、MATERIALTASKALLOCATION、OPERATION 三張表），成功 COMMIT 並把系統給的 PLNNR 回寫到 ALV。「先看再建」的兩段式互動很好，值得保留。

原程式的問題：

  • 一列檢核失敗就整支程式中止：FRM_DEAL 在 END-OF-SELECTION 中用 MESSAGE e001(00) 報「物料未建立工廠視圖」，使用者只看到第一個錯誤，改完一個再跑一次，改完一個再跑一次。
  • 同樣整表撈 MARC、MAKT、MARA 與所有 N 類型的 MAPL。
  • 排序是 matnr、werks、plnal，但結構欄位順序是 werks、matnr、maktx、plnnr、datuv、plnal——AT END OF plnal 的分組鍵包含描述與生效日，同一條途程若生效日填得不一致就被拆開。
  • 錯誤時在「訊息迴圈內」每則訊息呼叫一次 ROLLBACK；有一段註解掉的程式直接 UPDATE mapl SET loekz = 'X'（直接改標準表刪途程），絕對不可恢復使用。

範圍表會被展開成 SQL 的 IN 清單，數千個值以上可能超過資料庫陳述式長度限制（執行期錯誤），量大時請分批（例如每 1,000 筆一批），或改用 FOR ALL ENTRIES（記得先判斷內表非空，空表會變成「全表」）。ABAP 7.52 起也可以把內表當資料來源（SELECT … FROM @itab AS f）與資料庫表 JOIN，S/4HANA 1809 可用。
Casper 的第二條經驗在批導檢核裡特別重要：驗證「物料是否存在」要用列舉（IN 值清單／子查詢），不要偷懶寫「物料號 BETWEEN 檔案最小值 AND 最大值」——物料號是字元欄位，比的是字典序，混合純數字與英數、或前導零處理不一致時，區間會把不相干的物料抓進來、也會漏掉該有的。

14. 自寫批導 vs Migration Cockpit：怎麼選

這六支程式都是 2020～2022 年間在 S/4HANA 導入專案中寫的。當時 SAP 已經提供 Migration Cockpit（1809 為交易 LTMC，自訂物件用 LTMOM；2020 起改為 Fiori「Migrate Your Data」），它對物料（Product）、客戶／BP、固定資產（含餘額與交易）、BOM、工作中心、途程都有現成的遷移物件，模板、值對應（Mapping）、模擬、錯誤報告全部內建。那為什麼還要自己寫？工具細節見 5-13 章第 24 節，這裡只談選擇：

考量Migration Cockpit自寫批導程式
用途一次性的初始移轉（上線前、切換期）常態性業務作業（每週新料、每月新客戶、新產線途程）
模板SAP 產生、版本受控，欄位多且固定可貼合業務語言（中文欄名、填寫說明、下拉選單）

結論：初始移轉一律先評估 Migration Cockpit 的標準物件——這就是 Casper 第三條經驗「先找標準，再想客製」。只有兩種情況值得自己寫：① 上線後會被業務反覆使用的批次建檔（此時就是一支正式的業務程式，要有權限、日誌、模擬）；② 標準物件確實不支援、且 LTMOM 擴充成本高於自寫。另外，「批次修改既有主資料」通常也不用寫程式：物料用 MM17／MASS，BOM 用 CS20，途程換工作中心用 CA85。

LSMW 與錄製 BDC：SAP Note 2287723 說明 LSMW 在 S/4HANA 技術上仍可執行但不建議用於資料移轉；錄製 XD01／XK01 的 LSMW 與 BDC 在 S/4 已完全不可行（交易會導向 BP）。本章的工作中心 BDC 是「沒有正式 BAPI 時」的退而求其次，新專案請優先用 Migration Cockpit 的工作中心物件。

練習與自我檢核

  1. ALSM_EXCEL_TO_INTERNAL_TABLE 為什麼會讓物料長描述少一截？有哪兩種解法？
    要點：輸出結構 ALSMEX_TABLINE-VALUE 只有 CHAR 50。解法一是像原專案複製成 Z 函數並擴充結構長度（ZALSMEX_TABLINE）；解法二（建議）是改用 CL_FDT_XL_SPREADSHEET 在伺服器端解析 xlsx，沒有長度限制也不需要前端 Excel。
  2. 用 CL_FDT_XL_SPREADSHEET 讀到的日期欄位變成「45108」，怎麼轉？
    要點：那是 Excel 1900 日期系統的序號，ABAP 日期＝'18991230'＋序號（第 3 節 to_date）。或要求模板日期欄設為文字格式、填 YYYYMMDD。
  3. ZSDU009 一個客戶要 COMMIT 七、八次，會發生什麼事？S/4 的正解是什麼？
    要點：中途失敗會留下半成品客戶（有 BP 無銷售視圖等），重跑又走修改分支。正解是把 BP、角色、地址、稅號、銀行、公司代碼、銷售範圍、合作夥伴功能、稅分類組成一個 CVIS_EI_EXTERN，一次 CL_MD_BP_MAINTAIN=>MAINTAIN，檢查 BAPIRETM 後只 COMMIT 一次。
  4. 合作夥伴功能欄位（PARVW）該用什麼轉換常式？使用者填 SH 會轉成什麼？
    要點：CONVERSION_EXIT_PARVW_INPUT；SH（送達方）→ 內碼 WE，SP → AG，BP → RE，PY → RG。不能用 ALPHA。
  5. ZFIU018 為什麼要分成「全部 TESTRUN」與「正式建立」兩階段？原程式遇錯就 STOP 有什麼後果？
    要點：兩階段可確保「要嘛全部通過才寫、要嘛一筆都不寫」，避免移轉資料一半進一半沒進；原程式 STOP 前的資產已 COMMIT，使用者不知道停在哪一列，重跑還會重複建立。
  6. 資本化日期早於移轉年度與在移轉年度內的資產，分別用 BAPI_FIXEDASSET_OVRTAKE_CREATE 的哪個表格參數帶值？
    要點：早於移轉年度 → CUMULATEDVALUES（原值 ACQ_VALUE、以往累計折舊 ORD_DEP）；年度內 → TRANSACTIONS（異動類型 100，含 VALUEDATE）；本年已提折舊 → POSTEDVALUES。移轉年度不可寫死。
  7. BOM 批導用 AT END OF stlan 分組有什麼風險？現代寫法是什麼？
    要點：AT END OF 以結構中該欄位「左邊所有欄位」為分組鍵，且依賴內表已正確排序；描述不一致或未排序就會把一張 BOM 拆成多次建立。改用 LOOP AT … GROUP BY ( matnr werks stlan stlal )，明確指定分組鍵。
  8. 找出 ZPPU004 工作中心 BDC 的兩個邏輯錯誤。
    要點：① 作業類型單位 RC68A-LEINH 填成標準值單位 VGE01～06，而非模板的 LEINH1～6；② 「測試」勾選框 P_RUN 在 BDC 路徑中完全沒使用。另可提：沒有 MESSAGES INTO、MESSAGE_TEXT_BUILD 未帶變數、權限檢查被註解。
  9. 哪些 API 有 TESTRUN？沒有 TESTRUN 的物料 BAPI 要怎麼「先模擬」？
    要點：BAPI_FIXEDASSET_OVRTAKE_CREATE、BAPI_ROUTING_CREATE、BAPI_MATERIAL_BOM_GROUP_CREATE 有 TESTRUN，CRAP_WORKCENTER_CREATE 有 TEST；BAPI_MATERIAL_SAVEDATA 沒有，需自行做主檔檢核（T134、T023、T006、T001W、T024D…）、先在測試機跑，或呼叫後 ROLLBACK 乾跑。參數名以 SE37 為準。
  10. 主管問：「上線要搬 8,000 筆物料和 300 張 BOM，要不要寫程式？」你怎麼回答？
    要點：初始移轉先用 Migration Cockpit（1809 為 LTMC／LTMOM）的 Product 與 BOM 物件，內建模板、值對應、模擬與錯誤報告；只有上線後會被反覆使用、或標準物件無法滿足時才自寫批導，且要具備模擬、日誌、權限。這是「先找標準，再想客製」。
  11. 寫一段 ABAP SQL，查某工廠一批物料的途程工序與工作中心名稱，並說明為什麼一定要 ORDER BY。
    要點：MAPL → PLKO → PLAS → PLPO → CRHD（OBJTY='A'、OBJID=ARBID）→ CRTX；過濾刪除旗標與有效日；ORDER BY 物料、PLNAL、VORNR。HANA 沒有預設排序，不排序時工序順序與「第一筆」都不穩定。
  12. SAP PP Tables 文件中的 CRC、AFIH、AUFM 三項，放在 S/4HANA 新程式時各要注意什麼？
    要點：CRC 是邏輯資料庫不是表，新程式不用 LDB；AFIH 是 PM 維護訂單表頭，不屬 PP 生產訂單；物料移動在 S/4 以 MATDOC 為準，查訂單貨物移動建議直接查 MATDOC 或其 CDS 視圖。
