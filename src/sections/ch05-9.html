2. 使用者對話模型：單畫面交易與程式類型

使用者對話（User Dialog）是使用者與程式之間任何形式的互動：輸入資料、選擇選單項目、按按鈕、點選或雙擊清單條目。

SAP 程式設計模型（單畫面交易，Single-Screen Transaction）的目標，是用「一個畫面」取代多支交易碼冗長、巢狀的畫面序列：

  • 輸入畫面與資料畫面合併在同一視窗，省去不必要的切換，並確保使用者始終在正確的業務脈絡中。
  • 依使用者權限，可在同一交易中切換建立／修改／顯示模式。
  • 使用者可直接存取要編輯的物件，並用篩選器、樹狀結構或「最近編輯的物件」縮小選擇範圍。
  • 存檔後可再次顯示該物件，確認修改結果（系統保留脈絡）。

原廠範例是 FB60（供應商發票），畫面分成四區：物件選擇（樹狀）、物件 ID（抬頭關鍵資料）、物件明細（子物件）、應用功能（應用工具列只留少數功能：顯示/隱藏畫面區、以範本建立新物件、在不同工作階段間切換）。ME21N、VA01（Enjoy 版）也是同樣的設計。

3. 畫面原理：四個組成、PBO／PAI 與資料交換

畫面（Screen／Dynpro）是可自由定義的物件，用輸入/輸出欄位、清單等顯示或輸入資訊，是使用者與 ABAP 程式間的對話形式。它最大的長處是與 ABAP Dictionary 結合：自動做資料一致性檢查（外鍵、固定值），並提供 F1 欄位說明與 F4 輸入說明。

畫面的四個組成：畫面編號（畫面遮罩/版面 Layout）、畫面屬性、元素清單（Element List）、流程邏輯（Flow Logic）。流程邏輯寫的是流程邏輯語句，不是 ABAP 敘述；它的關鍵字清單在 Screen Painter 中按 Ctrl+F8 →「Statements in the Screen Flow Logic」查得到。

屬性分類（元素屬性）範例
可靜態定義、不可動態修改名稱、起始位置、資料格式、參照的 Dictionary 欄位
可靜態定義、也可動態修改Input、Output、Required、Invisible、Intensified（Bright）、可見長度
只能動態設定例如 ACTIVE（無靜態對應，執行期才有意義）

文字欄位、I/O 欄位、狀態圖示、群組框、選項按鈕、核取方塊、按鈕具有一般／Dictionary／程式／顯示四類屬性；Subscreen、Tabstrip、Table Control 則有一般屬性＋各自類型的特殊屬性。

畫面屬性的規則：

  • 「程式」＋「畫面號碼」唯一識別一個畫面。
  • 畫面號碼 1000～1010 保留給 ABAP Dictionary 表格維護畫面與可執行程式的標準選擇畫面；9000 以上保留給客戶（意義是：在 SAP 標準程式中客戶自加的畫面用 9000+；自己的 Z 模組池則慣例用 0100、0200⋯）。
  • 畫面類型決定用途（Normal／Subscreen／Modal Dialog Box），預設 Normal。
  • Next Screen 填 0 或留空＝畫面處理完回到它被呼叫的地方。
  • 建立畫面四步驟：設定畫面屬性 → Layout Editor 設計版面 → 元素清單設定欄位屬性 → 撰寫流程邏輯。也可在 ABAP 編輯器寫 CALL SCREEN 0100 或 SET SCREEN 0100 後雙擊號碼向前導覽建立。
  • 要以程式中定義的欄位（TOP include）當畫面欄位參照，必須先啟用（生成）程式，Screen Painter 才看得到。沒有參照的欄位要自己在 General Attributes 填 Format 與 Default Length（Dictionary CHAR ↔ ABAP C、NUMC ↔ N⋯）。
  • 圖形化 Layout Editor 只在 Windows 平台可用；其他平台（或舊 SAP GUI、防火牆環境）只能用文數字版 Screen Painter（§18 的 Splitter 更是只能在文數字版建立）。

兩個處理器與兩組資料：ABAP 處理器負責模組內的程式流程；DYNP 處理器控制流程邏輯並準備畫面上要顯示的資料。畫面欄位和 ABAP 全域欄位是兩組不同的資料，所以需要「複製」——而且只有同名欄位才會被複製：

  • PBO 所有模組執行完之後，ABAP 工作區 → 畫面欄位。
  • PAI 第一個模組執行之前，畫面欄位 → ABAP 工作區（有 FIELD 敘述的欄位例外，見 §10）。
  • PBO 呼叫的模組必須用 MODULE … OUTPUT 定義；MODULE … INPUT 只能在 PAI 呼叫。同一模組可被多個畫面呼叫，需要依畫面分流時讀 SY-DYNNR。
*& 畫面 0100 的流程邏輯（Flow Logic，不是 ABAP）
PROCESS BEFORE OUTPUT.
  MODULE status_0100.          " SET PF-STATUS / SET TITLEBAR
  MODULE fill_0100.            " 準備畫面資料（寫在 PBO 模組）
  MODULE modify_screen_0100.   " LOOP AT SCREEN（見 §4）
  MODULE clear_okcode.         " 最後清空命令欄位（見 §7）

PROCESS AFTER INPUT.
  MODULE exit_0100 AT EXIT-COMMAND.   " 功能類型 E：跳過自動檢查
  CHAIN.
    FIELD: sdyn_conn-carrid, sdyn_conn-connid.
    MODULE check_connection ON CHAIN-REQUEST.
  ENDCHAIN.
  MODULE user_command_0100.

MODULE fill_0100 OUTPUT.
  IF sdyn_conn-carrid IS NOT INITIAL AND sdyn_conn-connid IS NOT INITIAL.
    SELECT SINGLE carrid, connid, cityfrom, airpfrom, cityto, airpto,
                  fltime, deptime, arrtime
      FROM spfli
      WHERE carrid = @sdyn_conn-carrid
        AND connid = @sdyn_conn-connid
      INTO CORRESPONDING FIELDS OF @sdyn_conn.
  ENDIF.
ENDMODULE.
畫面欄位名稱與 ABAP 欄位大小寫無關但必須完全同名（含結構前綴，例如 SDYN_CONN-CARRID）。畫面欄位用 Dictionary 參照、程式卻用區域變數宣告，或名稱差一個字，畫面就會永遠空白且不報錯——這是 Dynpro 新手第一名的「靈異現象」。

4. 執行期動態修改畫面：SCREEN 系統表

動態修改元素屬性是暫時性的（只對這次畫面處理有效），但它能用「同一個畫面」取代一長串獨立畫面，省下開發與執行時間。原理：每次 PBO 開始時，系統把目前畫面每個元素的靜態屬性（或先前動態修改的屬性）讀進一張列型別為 SCREEN 的系統表；畫面上每個元素都有一列。

GROUP1～GROUP4修改群組（Groups）每個元素最多 4 個群組，群組名任意 3 字元

7. 功能碼處理：OK_CODE 的生命週期

使用者以按鈕、選單或功能鍵觸發功能類型 ' ' 的功能時，系統把功能碼放進畫面的 OK 欄位。要在 PAI 使用它：

  1. 在 Screen Painter 元素清單中替型別為 OK 的那一列取名（慣例 OK_CODE）。
  2. 在 ABAP 程式宣告同名、參照 SY-UCOMM 的全域欄位。
  3. PAI 開頭的自動欄位傳輸會把功能碼帶進程式；通常在 USER_COMMAND_nnnn 模組中判斷。

為什麼一定要清空：按 Enter 通常不會改變命令欄位的內容，若不清空，上一次的功能碼會在下一個畫面造成「意料之外的處理」（例如按 Enter 卻又存了一次檔）。兩種做法：

  • 做法 A（Col18 寫法）：在 PBO 最後放一個模組 CLEAR ok_code，透過 PBO 結尾的自動傳輸把畫面的命令欄位清空。
  • 做法 B（ABAP 關鍵字文件建議）：PAI 一開始把 OK_CODE 複製到另一個同型別欄位（save_ok），然後立刻清空 OK_CODE，後續只判斷 save_ok。

强晟筆記 p58 轉述原廠提醒「兩種方法不能混用」。實務上兩種都能運作，重點是全程式統一一種，避免有的畫面在 PBO 清、有的在 PAI 清，除錯時難以判斷命令欄位何時被改。本書範例一律採做法 B。

    WHEN OTHERS.
      MESSAGE |功能 { gv_save_ok } 尚未實作| TYPE 'S' DISPLAY LIKE 'W'.

8. 輸出元素：文字欄位、狀態圖示、群組框

文字欄位（Text Field）是畫面上固定位置的長方形顯示區，作為其他元素的標籤（也稱關鍵字），使用者執行期不能修改。規則：

  • 可包含線條、圖示等靜態元素；不能以底線 _ 開頭（2007 版還寫不能以問號 ? 開頭）。
  • 多個字的文字要用底線當分隔，系統才知道它們屬於同一個文字欄位；空白會被視為兩個文字欄位的分隔（Col18 Unit 3 測驗題）。
  • 標示選項按鈕或核取方塊時，要指定標籤在按鈕左邊或右邊。
  • 可翻譯：Screen Painter 的 Goto → Translation，會以使用者登入語言顯示；動態決定的文字要多語系，請改用 ABAP 文字元素（Text Symbols）。
  • 建立方式：直接在 Layout Editor 放文字欄位並輸入 Text 屬性；或從 Dictionary 結構帶入欄位時，系統一併帶入資料元素的欄位標籤與 I/O 範本。
  • 執行期可改 LENGTH、INTENSIFIED、INVISIBLE、ACTIVE。文字欄位與 I/O 欄位同名時，I/O 欄位設為不啟用，系統會自動隱藏對應的文字欄位。

狀態圖示（Status Icon）是顯示圖示的特殊輸出欄位，執行期才決定顯示哪個圖示，用來標示應用中的狀態（例如紅綠燈）。系統預定義的圖示代碼為 2～4 個字元，可執行報表 SHOWICON 查詢。

  • 系統固定設定 Output field 與 2D Display，不可修改；預設格式 CHAR。可動態修改 Vis. length、Bright、Invisible。
  • 只能在圖形化 Layout Editor 定義；為了顯示較長的 Quick Info，建議定義長度 132、可見長度 2。
  • 程式中宣告同名欄位，型別參照 Dictionary 結構 ICONS 的 TEXT 欄位；在 PBO 呼叫函數 ICON_CREATE 傳入圖示名稱與文字，取回技術值。

群組框（Group Box）把邏輯上同一組的元素框起來，純顯示用途；也可確保框內欄位共用同一右鍵選單（§16）。可有標題；可動態改 Vis. length、Invisible；框內元素全部不可見且畫面屬性勾選 Runtime compression 時，框本身也不顯示。要動態改框標題：勾選 Output 屬性，並在程式宣告同名全域欄位（Col18 測驗：不是用文字元素、也不是用 & 佔位符）。

9. 輸入元素：I/O 欄位、下拉框、核取方塊、選項按鈕、按鈕

I/O 欄位（又稱 Template）：輸入欄位讓使用者輸入、輸出欄位由系統顯示。輸入欄位可能有三種檢查：依資料型別的自動欄位檢查（日期欄位只能輸入有效日期）、參照 Dictionary 時的資料一致性檢查（外鍵、值集）、以及可能值說明。灰色標示的屬性可用 SCREEN 表暫時修改；不是所有屬性組合都能啟用，例如 CHAR 欄位不能勾 Leading zeros（只對數值欄位有意義）。

建立方式：直接在 Layout Editor 輸入底線決定長度（數值可用逗號作千分位、句點作小數點，最後一碼可放 V 作正負號佔位）；或 Dictionary/Program fields 帶入範本。要在程式中使用欄位內容，必須宣告全域欄位（原廠寫 DATA 或 TABLES；本書一律用 DATA）。

下拉框（Dropdown）：使用者只能從清單選，不能自由輸入（測驗題）。設定：Dropdown 屬性設 List box 或 Listbox with key（後者強制同時顯示鍵值與文字，前者由使用者自行決定是否顯示鍵值）→ 調整 Vis. length（可見長度決定欄位含按鈕與下拉清單的寬度，轉成下拉框時一定要改）→ Value list 設 ' ' 使用 Dictionary 值說明（欄位需有搜尋說明、兩欄的檢查表或固定值）→ 需要時設定功能碼，選取即觸發 PAI。值不來自 Dictionary 時，用 VRM_SET_VALUES 自行填入。

核取方塊與選項按鈕：選項按鈕一組只能選一個（選一個其他自動取消），核取方塊可多選。都必須命名；可另外顯示文字與圖示（Icon name）；可動態改 Input 與 Invisible。程式中宣告同名 TYPE c LENGTH 1 欄位，被選取時為 'X'，未選時維持初始值。選項按鈕要先個別建立，再選取後 Edit → Group → Radio button group → Define 組成群組；原廠建議每個選項按鈕群組用一個結構宣告，易讀易維護。指派功能碼後，選取即觸發 PAI；對群組中任一個按鈕指派功能碼，系統會把同一功能碼套到整組。

按鈕（Pushbutton）是命令欄位 OK_CODE 的「輸入欄位」。擺放原則：只關聯單一欄位或小組欄位時要盡量靠近它們，關聯一組時用群組框標示；關聯表格時，橫排在表格下方、與表格間空一行。可放文字、圖示或兩者（圖示可靜態指定或用 ICON_CREATE 動態產生）；可動態改 Vis. length、Output field、Invisible；要動態改按鈕文字，勾選 Output field 並宣告同名全域欄位。功能類型 ' ' 觸發一般 PAI；功能類型 E 會先執行 AT EXIT-COMMAND 模組（在自動傳輸與欄位檢查之前），若該模組沒有離開畫面，之後照常做欄位檢查與 PAI。

10. 錯誤處理（一）：SET/GET 參數、訊息類型與欄位檢查

SAP Memory 的預設值（SET/GET Parameter）：用參數 ID 把欄位值存到 SAP 記憶體，依使用者登入工作階段區分，但所有內部與外部工作階段都能取得。

  • SET 參數：在 PAI 把欄位內容複製到 SAP 記憶體。
  • GET 參數：在 PBO 結束時（程式資料都傳到畫面之後）從 SAP 記憶體帶入——但只有當畫面欄位仍是初始值時才會帶入。
  • 參照 Dictionary 的欄位，其資料元素上的參數 ID 會顯示在 Screen Painter 的 Parameter ID 屬性；SPA／GPA 兩個屬性可分別啟用 SET 與 GET。參數 ID 定義在表 TPARA，可在 ABAP Workbench 自行定義（例如航空公司是 CAR、物料是 MAT）。
强晟在 p75 留了一個問題：「如果在 INITIALIZATION 或 AT SELECTION-SCREEN OUTPUT 修改了初始值，GET 參數是不是就不起作用了？」答案是對。GET 參數在 PBO 最後才判斷「欄位是否仍為初始值」，程式先給了值（或 PARAMETERS 有 DEFAULT），SAP 記憶體的值就不會蓋上去。這也是「為什麼我的欄位沒有帶出上次輸入的值」的常見原因。

12. Subscreen 子畫面與函數群組封裝

Subscreen Area 是主畫面上保留的長方形區域，執行期把另一個畫面（類型 Subscreen）放進去；區域內不能放其他元素。用途：顯示主畫面的一組物件、依使用者輸入顯示或隱藏額外欄位；不同程式可重用同一個 Subscreen；一個主畫面可有多個 Subscreen，也可執行期動態決定放哪一個。使用場合：畫面增強（Screen Exit）、其他畫面物件中（Tabstrip）、Modification Assistant、Web 交易。

Subscreen Area 屬性：Subscreen 比區域大時只從左上角顯示放得下的部分，勾 Scrollable 會出現捲軸；Resizable 讓區域隨主視窗縱橫縮放，Minimum size 設下限；Context menu 為子畫面輸出欄位指定右鍵選單。建立時在 Object text 輸入區域名稱（CALL SUBSCREEN 靠它識別）。

Subscreen 的五條限制（必背）：

  1. CALL SUBSCREEN 不能放在 LOOP … ENDLOOP 或 CHAIN … ENDCHAIN 之間。
  2. Subscreen 不能有 OK_CODE 欄位（功能碼由主畫面處理）。
  3. 同一主畫面呼叫的所有 Subscreen 中，物件名稱必須唯一。
  4. Subscreen 不能有 AT EXIT-COMMAND 模組。
  5. Subscreen 的模組中不能用 SET TITLEBAR、SET PF-STATUS、SET SCREEN、LEAVE SCREEN。

必須在主畫面流程邏輯的 PBO 與 PAI 都 呼叫（測驗題），系統把子畫面的 PBO/PAI 當成主畫面 PBO/PAI 的一部分執行。流程邏輯中用到的欄位是程式的全域欄位，要宣告在 TOP include。

來自外部程式的 Subscreen：子畫面不在主畫面同一模組池時，主程式的全域資料子畫面看不到，子畫面的資料也傳不回來。解法是把 Subscreen 封裝在函數群組，用函數模組介面搬資料——這正是客戶子畫面（Customer Subscreen／Screen Exit）的技術（見 3-3 章、5-14 章 BC425）。呼叫順序：

  • PBO：先呼叫「送資料進函數群組」的函數模組（把介面參數複製到函數群組全域資料），再 CALL SUBSCREEN——確保子畫面 PBO 執行時資料已就位。
  • PAI：順序相反，先 CALL SUBSCREEN 跑子畫面 PAI，再呼叫「取回資料」的函數模組（把函數群組全域資料複製回介面參數）。

强晟的評語很直白：「真繞啊，完全是沒有辦法的辦法，來回倒騰資料。」——但它就是 SAP 標準交易開放 Screen Exit 的方式，看懂它才看得懂 CMOD／BAdI 的畫面增強。

13. Tabstrip 頁籤控制項：本地切換與 PAI 切換

Tabstrip 用直覺的方式把應用的多個組件放在同一畫面並自由切換，適合「上方是固定的抬頭資料、下方顯示其他各組資料」這種構成邏輯單元的情境。不應使用的情況：

  • 處理各組件時需要改變畫面環境（選單、按鈕、抬頭資料⋯）——包住 Tabstrip 的畫面必須保持不變。
  • 組件必須依特定順序處理——Tabstrip 的設計是讓使用者自由切換。
  • 組件是動態的：在某一頁的輸入會讓其他頁突然出現。

Tabstrip 與 Batch Input 相容（BDC 錄製時頁籤切換是可錄的，見 4-4 章）。頁籤標題只能一列；頁數太多時出現捲動鈕，右上角按鈕可列出所有標題，目前頁有勾號。

技術結構：每一頁（Page Element）＝ 頁籤標題 ＋ Subscreen Area ＋ Subscreen。頁籤標題在技術上就是按鈕（有名稱、文字、功能碼、功能類型）；要超過預設的 2 頁，就在標題區再放「按鈕」元素（測驗題：選 Pushbutton，不是 Subscreen）。程式中用 CONTROLS ts TYPE TABSTRIP 宣告同名物件，型別定義在類型群組 CXTAB，其中 ACTIVETAB 存放目前啟用頁的功能碼，其他欄位為內部保留。建立三步驟：定義 Tabstrip 區 → 定義（追加）頁籤標題 → 替每頁指定 Subscreen Area（指定後會自動填入該標題 Dictionary 屬性的 Reference object；也可在多個頁籤的 Reference 欄位填同一個區域名，讓它們共用一個區域）。

14. Table Control：建立、屬性與 PBO/PAI 資料傳輸

Table Control 是畫面上以表格形式顯示資料的區域，以迴圈處理；最上一列是標題列，以灰色分隔線區隔。可放表格元素、關鍵字、Template、核取方塊、選項按鈕（群組）與按鈕；每列最多 255 欄，每欄可有標題；顯示或輸入的是單一結構的資料列。

特性：可調大小的表格；使用者或程式可改欄寬與欄位順序並儲存、之後重新載入（顯示變式，可存為目前或預設設定）；選擇欄標記列（以不同顏色顯示）；列選擇模式單列/多列/全選/取消；欄標題可當按鈕標記欄；水平與垂直捲軸；任意數量的鍵（固定）欄；儲存格屬性執行期可變。

完全在前端處理（不觸發 PAI）的動作：水平捲動、交換欄、改欄寬、選欄、選列。會觸發 PAI 的：垂直捲動與儲存使用者設定（Col18 Unit 7 測驗題）。

建立：放置 Table Control 區並命名；程式中用 CONTROLS tc TYPE TABLEVIEW USING SCREEN nnnn 宣告同名物件（型別等同類型群組 CXTAB 的 CXTAB_CONTROL），執行期它保存 Table Control 的屬性；USING SCREEN 決定取哪個畫面的初始值；隨時可用 REFRESH CONTROL tc FROM SCREEN nnnn 重設為初始屬性（nnnn 可以是任何定義了同名 Table Control 的畫面）。欄位用 Dictionary/Program fields 一次帶入（有資料元素文字就當欄標題），或逐一放 I/O 欄位（一個欄位一欄）。選擇欄（Selection column）系統會自動建議，行為像核取方塊，必須是 CHAR 長度 1 的欄位，名稱填在 Table Control 屬性中，它同時是畫面與程式間傳輸結構的一個欄位。

表格類型（2007 版）：至少有一個輸入欄位的輸入型表格用 Entry table；只做選擇/傳遞或純顯示用 Selection table。

處理原則：

  • 為了效能，資料一次從資料庫讀進內表，Table Control 的列由內表填入；不要在每次 PBO 都重讀，只在鍵值改變時重讀。
  • 系統要知道能垂直捲多遠：把內表筆數放進 tc-lines（原廠 2007 版用 DESCRIBE TABLE，Col18 改為 lines( ) 函數）。
  • Table Control 處理列時只有一個工作區，所以 PBO 與 PAI 都需要各自的 LOOP … ENDLOOP：PBO 每圈把內表一列填到控制項一列；PAI 每圈把控制項的修改寫回內表正確的那一列（tc-current_line）。
  • 要分清楚模組是作用在「單列」（放 LOOP 內）還是「整個畫面」（放 LOOP 外）。

欄位傳輸順序的改變：PBO 中，每跑完流程邏輯一圈就把該列從程式傳到畫面，其餘非表格欄位照常在 PBO 結尾傳。PAI 中，先傳不屬於表格、也不在 FIELD 中的欄位，表格內容在迴圈中逐列傳入，FIELD 中的欄位在該 FIELD 敘述前一刻才傳。金額欄位傳輸時會依參考欄位（幣別）做格式化，參考欄位不含對應幣別就會出錯；傳輸順序依欄位在畫面上的位置，所以要用 FIELD 敘述延後金額/數量欄位的傳輸，確保參考欄位先傳、金額後傳。

16. 右鍵選單（Context Menu）

右鍵選單（滑鼠右鍵或 Shift+F10）是常用功能的捷徑，內容依點選位置（右鍵時的滑鼠指標、Shift+F10 時的游標）而定。建立畫面物件（畫面、輸入欄位、Table Control、群組框）時可決定是否提供右鍵選單。

運作機制：使用者在物件上叫出右鍵選單時，一個（ABAP Objects 意義上的）事件機制呼叫程式中的回呼副程式，並傳入選單參照 CL_CTMENU；程式用它組出選單（可載入 Menu Painter 定義的靜態選單，或動態建立）。使用者選了功能後，功能碼放進命令欄位，依功能類型觸發 PAI。

  • 建立：在 Object Navigator 對 GUI Status 按右鍵建立，或直接在 Menu Painter 建；它是一種特殊的 GUI Status，Status 類型選 Context menu。可連結任何功能碼與文字，參照技術確保大型應用一致。
  • 設計規則：不要放系統其他地方（按鈕或介面）沒有的功能；避免超過兩層串接；不超過 10 項但要涵蓋所有可用按鈕；用分隔線整理視覺結構；物件相關的項目放在最上面。
  • 連結畫面物件：回呼副程式名稱為 ON_CTMENU_<名稱>，在畫面屬性或元素一般屬性中指定。可直接指定給 I/O 欄位、文字欄位、狀態圖示；核取方塊、選項按鈕、按鈕沒有自己的回呼，但可從群組框或畫面繼承。指定給 Table Control 時，對控制項中所有沒有自己回呼的欄位都觸發（不能逐一指定）。指定給群組框、Table Control、畫面（一般或子畫面）時，底下沒有自己選單的欄位都會繼承。

18. Splitter Control：CL_DYNPRO_SPLITTER（Col18 第九單元）

Splitter Control 是一種 Dynpro 畫面元素，用一條分隔條（sash）把一塊區域切成兩個 Subscreen Area——水平並排或上下排列。典型用途：左邊列出所有航班、右邊顯示所選航班的明細。

  • 分隔條的位置在元素定義中靜態指定（百分比，相對於 Splitter 的寬或高），可在 PBO 由程式設定，使用者在畫面顯示時也能拖動。
  • General Attributes 設分隔位置；Splitter Attributes 設方向（水平/垂直）；設了 resize 屬性，兩個格子就能調整大小。
  • 每個格子（左/上、右/下）各定義一個 Subscreen，插入方式與一般 CALL SUBSCREEN 完全相同；子畫面裡可以再放 Splitter。
  • 可指派功能碼，使用者拖動分隔條時觸發，讓程式反應位置變化。
  • 只能在文數字版 Screen Painter 建立（Utilities → Settings → 取消勾選 Graphical layout editor）。因此原廠建議只在「必須用經典 Dynpro 且需要此功能」時使用。文數字版編輯器功能與圖形版相同，也是非 Windows 平台、非 Windows SAP GUI、過舊 SAP GUI 或防火牆保護的系統上的替代方案。

20.3 附錄：交易變式（SHD0）、畫面變式與 GuiXT

强晟 2007 筆記略過的「畫面變式」，在 Col63 附錄 p239–246 是完整專題，重點是不修改程式就能簡化標準交易：

  • 交易變式（Transaction Variant）是對一組畫面變式（Screen Variant）的參照；一個畫面可以有任意多個畫面變式。
  • 兩種類型：標準變式（Standard variant）每個交易一個，執行期直接取代 SAP 交付的交易，不需要新交易碼；一般交易變式可以有很多個，要建立「變式交易（Variant transaction）」類型的交易碼來呼叫。
  • 建立路徑：IMG 的 AcceleratedSAP → 個人化 → 交易變式（即 SHD0）。輸入交易碼與變式名稱（系統內唯一、客戶命名空間），用 Goto 決定用戶端相關或跨用戶端，再按應用工具列的建立按鈕。
  • 評估欄位：系統以 CALL 模式啟動交易，每按一次對話（觸發 PAI）就多送一個畫面讓你勾選欄位屬性，包括是否帶入欄位內容作預設值、取消輸入狀態（改唯讀）、隱藏欄位、隱藏按鈕。按繼續後存成畫面變式。
  • 畫面變式是獨立的 Repository 物件，名稱由「變式名稱＋用戶端（僅限用戶端相關變式）＋畫面編號」組成。
  • GuiXT：以腳本語言移動物件、插入畫面與按鈕、插入值說明、改欄位輸入屬性、刪除畫面元素；腳本可存在本機並匯入匯出。供應商是 Synactive（synactive.com）。
  • 啟動方式：SHD0 的測試環境（開發者用）、變式交易類型的交易碼、使用者選單。要放進角色（PFCG）或區域選單，一定要先有變式交易碼；使用者重新登入後就會看到。
先找標準，再想客製（Casper 實務經驗 3）：使用者抱怨「VA01 欄位太多、常填錯」，第一步不是寫 Screen Exit 也不是改標準，而是用 SHD0 做交易變式：隱藏用不到的欄位、把固定值設成預設並設唯讀，完全不動程式碼，升級也不必重測修改。做不到的才往 BAdI／畫面增強走（§12、5-14 章），最後才考慮修改標準。
S/4HANA 現況：SHD0 交易變式在 S/4HANA 的 SAP GUI 中仍可使用，也是 Fiori Launchpad 以 SAP GUI for HTML 包 Dynpro 交易時簡化畫面的常用手段；但它只對 Dynpro 交易有效，對 Fiori App 無效（Fiori 用 UI Adaptation／Key User 擴充）。GuiXT 屬前端腳本技術，SAP 後續主推的畫面個人化方案是 SAP Screen Personas；新專案遇到「要改標準畫面長相」的需求，請先評估 Fiori 標準 App 或 Screen Personas，不要再新增 GuiXT 腳本。

20.6 附錄：控件框架與輸入說明機制的重點

  • 控件框架（Control Framework）（p246–257）：EnjoySAP 控件是一對物件，前端是 ActiveX／Java Bean 的 GUI 物件，後端是 ABAP 代理物件，需要 R/3 4.6A 以上。附錄列出 CL_GUI_TEXTEDIT、CL_GUI_HTML_VIEWER、CL_GUI_PICTURE、樹狀控件、CL_GUI_ALV_GRID、CL_GUI_CFW、CL_GUI_CONTAINER。兩條規則：① 一個 Custom Control 區域只能建立一個 CL_GUI_CUSTOM_CONTAINER 實例，重複建立時舊實例會被蓋住，之前呼叫過的方法效果全部遺失（所以 PBO 中要用 IS NOT BOUND 判斷）；② 離開程式前要先呼叫 ->free( ) 釋放前端物件，再 FREE 參照，否則前端可能留下多餘的處理程序。完整內容見 5-10 章 BC412。
  • 輸入說明機制（p258–262）：搜尋說明可以掛在三個地方：欄位、檢查表、資料元素（掛在資料元素時只能指定一個 EXPORT 參數）。同一欄位有多種機制可用時，系統取層級最高的那一種。Screen Painter 上直接掛搜尋說明，或在 POV 用 F4IF_FIELD_VALUE_REQUEST／F4IF_INT_TABLE_VALUE_REQUEST 自己寫，都無法自動重用，而且應先考慮搜尋說明出口（Search Help Exit）。在流程邏輯中直接寫輸入檢查、再由它衍生輸入說明的舊做法不應再使用。要查某個欄位實際用了哪種機制，在 F4 結果清單上按右鍵選「技術資訊」即可。細節見 5-16 章 BC430 與 §11。

  2. （Unit 1）PBO 與 PAI 的資料傳輸各在什麼時間點發生？控制流程邏輯的是哪個處理器？

  3. （Unit 1）某欄位在 Screen Painter 設為 Invisible，程式在 PBO 寫 ACTIVE = 1 卻叫不出來，為什麼？還有哪兩種 SCREEN 用法不支援？
    參考答案要點：靜態不可見的元素要用 INVISIBLE = 0；ACTIVE = 0 才等同 INVISIBLE=1、INPUT=0、OUTPUT=0。不支援 LOOP AT SCREEN WHERE 與 READ TABLE SCREEN；且必須 MODIFY SCREEN、必須在 PBO。
  4. （Unit 1）CALL SCREEN、SET SCREEN、LEAVE TO SCREEN 差別？CALL SCREEN 省略 ENDING AT 會怎樣？
    參考答案要點：CALL SCREEN 插入序列、堆疊加一層；SET SCREEN 只覆寫 Next Screen；LEAVE TO SCREEN＝設定＋立即離開。省略 ENDING AT 時對話框大小取畫面屬性的 Lines/Columns；被呼叫畫面須為 Modal Dialog Box。
  5. （Unit 2）GUI Status 由哪些元件組成？Title Bar 算不算？應用工具列最多幾個按鈕？
    參考答案要點：選單列、標準工具列、應用工具列、功能鍵設定；Title Bar 不屬於 Status。最多 35 個按鈕；選單 15 項 3 層；選單列 8 個（自由 6 個）；Title 20 字元、9 個 & 佔位符。
  6. （Unit 2）為什麼要清空 OK_CODE？有哪兩種做法？
    參考答案要點：Enter 不會改變命令欄位，殘留的功能碼會在下一畫面誤觸發。做法 A：PBO 最後 CLEAR ok_code；做法 B：PAI 先 save_ok = ok_code 再清空。全程式擇一統一。
  7. （Unit 3）狀態圖示欄位建議的長度與可見長度？程式欄位的型別？要用哪個函數產生？
    參考答案要點：定義長度 132、可見長度 2；型別 ICONS-TEXT；在 PBO 呼叫 ICON_CREATE；圖示清單用 SHOWICON 查。
  8. （Unit 3）要動態修改群組框標題或按鈕文字，需要哪兩個步驟？
    參考答案要點：勾選 Output（field）屬性；在程式宣告同名全域欄位並給值。不是用文字元素，也不是用 & 佔位符。
  9. （Unit 4）在沒有 FIELD 的 PAI 模組中發出 E 訊息會發生什麼事？使用者修正後 PAI 從哪裡重跑？
    參考答案要點：訊息顯示但所有欄位都不能輸入。用 FIELD/CHAIN 時只有相關欄位可再輸入；修正後從第一個對應被修改欄位的 FIELD 處重跑，不重跑 PBO；只確認警告則從 MESSAGE 之後繼續。
  10. （Unit 4）ON INPUT 與 ON REQUEST 的差別？AT EXIT-COMMAND 有哪些限制？
    參考答案要點：ON INPUT＝欄位值不是初始值；ON REQUEST＝使用者輸入了新值。CHAIN 中用 ON CHAIN-INPUT／ON CHAIN-REQUEST。AT EXIT-COMMAND 每畫面一個、不能有 FIELD、只對功能類型 E 生效、在自動檢查之前執行、Subscreen 不可用。
  11. （Unit 4）Back、Exit、Cancel 在「檢查輸入」與「存檔對話框」的順序上有何不同？
    參考答案要點：Back（類型空白）先檢查再問存檔；Exit（類型 E）先問存檔再檢查；Cancel（類型 E）不檢查，只問資料遺失。單畫面交易中 Cancel 會以初始欄位重顯畫面讓使用者選新物件。SY-DATAR = 'X' 表示使用者輸入過資料。
  12. （Unit 5）列出 Subscreen 的五條限制；從函數群組嵌入子畫面時，PBO 與 PAI 的呼叫順序？
    參考答案要點：CALL SUBSCREEN 不能在 LOOP/CHAIN 中；不能有 OK_CODE；物件名唯一；不能有 AT EXIT-COMMAND；不能 SET TITLEBAR/PF-STATUS/SCREEN、LEAVE SCREEN。PBO 先呼叫送資料的函數模組再 CALL SUBSCREEN；PAI 先 CALL SUBSCREEN 再呼叫取回資料的函數模組。
  13. （Unit 6）Tabstrip 的本地切換與 PAI 切換在 Subscreen Area 數量、頁籤功能類型、欄位檢查範圍上各有何差異？哪一種適合顯示型交易？
    參考答案要點：本地＝每頁一個區域、功能類型 P、所有子畫面都送前端且 PAI 時全部檢查，適合顯示型；PAI 切換＝共用一個區域、功能類型空白、以變數呼叫子畫面、只檢查目前頁。ACTIVETAB 存目前頁功能碼，型別 TABSTRIP 定義在 CXTAB。
  14. （Unit 7）Table Control 中哪些動作會觸發 PAI？SY-LOOPC 在 PBO 與 PAI 的意義有何不同？
    參考答案要點：垂直捲動與儲存使用者設定觸發 PAI；水平捲動、換欄、改欄寬、選欄、選列都在前端。SY-LOOPC 在 PBO 是「能顯示幾列」，在 PAI 是「實際顯示幾列」；SY-STEPL 是畫面列，current_line 是內表列。
  15. （Unit 7）使用者把游標放在 Table Control 第 3 列按「明細」，目前 top_line = 21，對應內表第幾列？
    參考答案要點：21 + 3 − 1 = 23。GET CURSOR FIELD f LINE n 取得 n（sy-subrc = 0 表示游標在欄位上）。前提是內表順序穩定——SELECT 必須 ORDER BY。
  16. （Unit 7）為什麼金額欄位要用 FIELD 敘述延後傳輸？
    參考答案要點：金額傳輸時依參考欄位（幣別）格式化，傳輸順序依畫面位置；參考欄位必須先傳，否則出錯。用 FIELD 讓幣別先、金額後。
  17. （Unit 8）哪些元素可以直接指定右鍵選單回呼？核取方塊怎麼辦？回呼的形式是什麼？
    參考答案要點：I/O 欄位、文字欄位、狀態圖示可直接指定；核取方塊、選項按鈕、按鈕只能從群組框或畫面繼承。回呼為 FORM on_ctmenu_<name> USING p_menu TYPE REF TO cl_ctmenu，用 CL_CTMENU=>LOAD_GUI_STATUS 載入，再用 ADD_FUNCTION／HIDE_FUNCTIONS／DISABLE_FUNCTIONS 等調整。
  18. （Unit 9）Splitter Control 只能在哪種編輯器建立？用哪個類別控制分隔條位置？
    參考答案要點：只能在文數字版 Screen Painter；用 CL_DYNPRO_SPLITTER（PBO 用 SET_SASH、PAI 用 GET_GUISASH、兩者皆可用 GET_SASH）。
  19. （實作）用本章程式片段組出一支 ZBC410 交易：0100 輸入航空公司＋航線（FIELD/CHAIN 檢查、F4 只列該航空公司航線）→ 0200 Tabstrip（PAI 切換，三頁）→ 第二頁放 Table Control 維護 SFLIGHT 價格（過期航班整列鎖住、可依選取欄排序）→ 取消時跳資料遺失確認。
    參考答案要點：對照 §3～§15 的程式片段；完整可跑的 Table Control 骨架見 4-2 章 §16。檢核重點：OK_CODE 清空、E 訊息只鎖相關欄位、current_line 寫回、ORDER BY、Subscreen 不設 Status。
  20. （思考）主管要求「在 VA01 抬頭加一個頁籤放三個客製欄位」，你的處理順序是什麼？
    參考答案要點：先確認標準是否已有欄位或 Customizing 可達成 → 再用 SAP 提供的畫面增強（Customer Exit 子畫面／BAdI 子畫面，技術原理即 §12 的函數群組封裝）→ 最後才考慮修改標準。每往右一步，升級成本高一個量級（見 5-14 章、3-3 章）。
  21. （L29 Col63 練習 3）按 CANCEL 時，模型解答除了清空工作區，為什麼還要用空值執行 SET PARAMETER ID？
    參考答案要點：GET 參數在 PBO 結尾、只對「仍是初始值」的畫面欄位從 SAP 記憶體帶值。只清程式欄位的話，記憶體裡的上一個航班會在 PBO 結尾又被填回畫面，Cancel 就無法以空白畫面重顯。所以要連 CAR／CON／DAY 三個參數 ID 一起清。
  22. （L29 附錄）標準交易變式與一般交易變式差在哪？要讓使用者從角色選單執行變式需要什麼？
    參考答案要點：標準變式每個交易一個，執行期直接取代原交易，不需要新交易碼；一般變式可以有很多個，要建立「變式交易」類型的交易碼才能呼叫，放進角色或區域選單。維護用 SHD0；交易變式由多個畫面變式組成，畫面變式名稱＝變式名＋用戶端＋畫面編號。這是「先標準再客製」的第一步。
  23. （L29 附錄）在選擇畫面上用 TABBED BLOCK 做頁籤時，為什麼不能自己寫 CONTROLS？要在執行期改初始頁該怎麼做？
    參考答案要點：系統會自動產生 CONTROLS blk TYPE TABSTRIP，重複宣告會語法錯誤。執行期填系統自動建立的同名結構 blk-prog／blk-dynnr／blk-activetab（ACTIVETAB 放頁籤的 USER-COMMAND 功能碼）。TAB 用了 DEFAULT 就必須寫 SCREEN。
  24. （L29 術語）簡中資料寫「在正文菜单中⋯」「表标签控件」「登记数量(BOOKID)」，分別指什麼？哪個是誤譯？
    參考答案要點：正文菜单＝Context Menu（右鍵選單，把 context 直譯成「正文」是誤譯）；表标签控件＝Tabstrip（同書也寫成「制表符控制」）；BOOKID 是訂位編號，譯成「登记数量」是誤譯。搜尋 SAP 物件時一律用英文技術名稱。
