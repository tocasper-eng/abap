1. 內建資料型別總表（先把這張表背起來）

ABAP 的「資料型別」本身不佔記憶體，只有「資料物件（變數／常數）」才佔記憶體。型別可以是系統預定義（built-in）、也可以是 SE11 裡的 Data Element / Domain。下表是講義的核心表格，加上 S/4HANA 常用但講義只帶過的幾個型別。

講義強調的五個取值規則，實務上天天踩到：

  • 不寫 TYPE 時，預設型別是 C（DATA lv_a(10). 等同 TYPE c）。
  • C 型從左取、N 型從右取，超過定義長度就截斷。
  • C 可以放數字、文字或混合；但把 C 當數值用時是靠右對齊解讀。
  • D 與 T 可以直接做四則運算（D 加減的單位是「天」，T 加減的單位是「秒」）。
  • P 一定要用 DECIMALS 宣告小數位，沒寫就等於整數。

2. TYPES / DATA / CONSTANTS / STATICS：宣告的四把刀

TYPES 定義的是「型別」，不能賦值；DATA 才是「變數」；CONSTANTS 是一經定義就不能改的常數；STATICS 是「離開副程式仍然記得上次的值」的區域變數。

3. 結構、繼承（INCLUDE TYPE）與 CORRESPONDING

結構就是「一列資料」。講義示範三種寫法：TYPES BEGIN OF ... END OF（推薦）、DATA BEGIN OF ... END OF（可用但不建議）、以及參照 SE11 的 Structure。結構要「繼承」欄位時用 INCLUDE。

老師特別標紅的坑：自訂型別要用 INCLUDE TYPE，不可用 INCLUDE STRUCTURE；INCLUDE STRUCTURE 只能用在 DATA BEGIN OF 裡引用「資料物件或 DDIC 結構」。而且 INCLUDE 那一行結尾是句號不是逗號，前後的 DATA: / TYPES: 要重新起頭 — 這是初學者最常見的語法錯誤。
REPORT zdatatype03.
" 練習 03：型別、結構、繼承（INCLUDE TYPE）
TYPES ty_bu_partner  TYPE c LENGTH 10.
TYPES ty_bu_partner1 TYPE bu_partner.        " 直接參照 DDIC Data Element
TYPES ty_bu_partner2 TYPE ty_bu_partner.     " 型別再參照型別

TYPES: BEGIN OF ty_partner_info,
         nam TYPE c LENGTH 10,
         age TYPE i,
         tel TYPE n LENGTH 12,
       END OF ty_partner_info.

" 繼承：把 ty_partner_info 的欄位整批納入，再加自己的欄位
TYPES: BEGIN OF ty_customer.
         INCLUDE TYPE ty_partner_info.      " 注意：自訂型別用 INCLUDE TYPE
TYPES:   adr TYPE c LENGTH 40,
       END OF ty_customer.

START-OF-SELECTION.
  " VALUE #( ) 一次把整個結構填好，取代逐欄位 = 的舊寫法
  DATA(ls_info) = VALUE ty_partner_info( nam = 'RICKY'
                                         age = 30
                                         tel = '0930463002' ).

  " 欄位完全相同 → 直接用 =；欄位不同 → 用 CORRESPONDING #( )
  DATA(ls_cust) = CORRESPONDING ty_customer( ls_info ).
  ls_cust-nam = '繼承的'.
  ls_cust-adr = '桃園市中大路 300 號'.

  cl_demo_output=>write_data( ls_info ).
  cl_demo_output=>write_data( ls_cust ).
  cl_demo_output=>display( ).

結構賦值的三種情境，老師的總結是：「完全相同用 =，否則用 CORRESPONDING」。MOVE-CORRESPONDING 仍可用（它不是 obsolete），但新程式建議用建構式版本，因為它能寫在運算式裡、還能改欄位對應。

" 三種等價寫法（由舊到新）
MOVE-CORRESPONDING ls_from TO ls_to.               " 舊：只能當敘述句
ls_to = CORRESPONDING #( ls_from ).                " 新：可寫在任何運算式裡

" 欄位名稱不同時，用 MAPPING 對應、用 EXCEPT 排除
ls_to = CORRESPONDING #( ls_from
                         MAPPING kunnr = customer_id
                                 name1 = customer_name
                         EXCEPT  mandt ).
CORRESPONDING / MOVE-CORRESPONDING 只比對欄位名稱，不管順序、也不管型別。若來源是 CHAR20、目標是 CHAR10，會靜靜地截掉後面 10 碼而不報錯 — 這是報表資料「莫名其妙變短」的頭號元兇。

4. 賦值、offset+length、指標（FIELD-SYMBOLS / REF）

ABAP 給值的方式，講義列了三種：=、MOVE、WRITE ... TO ...。其中 MOVE 已是 obsolete，WRITE ... TO ... 是「帶格式的賦值」（不是輸出），只在需要套用輸出格式時才用。

offset + length 寫法是 ABAP 最有特色的語法：lv_field+3(5) 表示「跳過 3 個字元，取 5 個字元」，+3(*) 表示「跳過 3 個之後全取」。它可以出現在等號左邊（部分覆寫），這在處理日期字串時非常好用。

REPORT zdatatype05.
" 練習 05：offset+length、WRITE TO、日期部分覆寫
DATA(lv_date1) = sy-datum.
DATA(lv_date2) = sy-datum.

lv_date2+6(2) = '30'.            " 把 YYYYMMDD 的 DD 換成 30（等號左邊也能用 offset）

DATA(lv_ymd) = CONV char8( '20220126' ).
DATA(lv_yyyy)   = lv_ymd+0(4).   " 2022
DATA(lv_mm)     = lv_ymd+4(2).   " 01
DATA(lv_dd)     = lv_ymd+6(2).   " 26
DATA(lv_yymmdd) = lv_ymd+2(*).   " 220126 ← (*) 表示後面全取

" 現代等價寫法：substring( )，可讀性更好、也能用在字串型別
DATA(lv_yyyy2) = substring( val = lv_ymd off = 0 len = 4 ).
DATA(lv_ymd2)  = substring_from( val = lv_ymd off = 2 ).

用 offset+length 時，整段運算式中間不可以有空格（lv_a+3(5) 對，lv_a + 3(5) 錯，後者會被當成加法）。另外對 TYPE string 使用 +off(len) 在 Unicode 系統會有限制，字串請一律改用 substring( )。

FIELD-SYMBOLS 是指標（分身）：它本身不是變數，存的是別的變數的位址。改 <fs> 就等於改本尊。IS ASSIGNED 用來檢查有沒有指到東西 — 沒指到就用，會 dump。

5. 型別轉換的陷阱（老師說一定要小心驗算）

不同型別互相賦值時，ABAP 會「自動轉換」，但規則很多而且不一定符合直覺。講義的三個經典陷阱：

陷阱一：C → N → I 的資訊遺失。C 轉 N 時只保留數字字元，其他丟掉；N 再轉 I 時若超出範圍會 dump。

REPORT zdatatype08a.
" 陷阱一：'ABC1234567' 轉 N 只剩數字，且靠右對齊補 0
DATA lv_c TYPE c LENGTH 10 VALUE 'ABC1234567'.
DATA lv_n TYPE n LENGTH 10.
DATA lv_i TYPE i.

lv_n = lv_c.        " → 0001234567（字母被丟棄，右靠齊左補 0）
lv_i = lv_n.        " → 1234567

cl_demo_output=>write( |C={ lv_c } N={ lv_n } I={ lv_i }| ).
cl_demo_output=>display( ).

陷阱二：整數除法會四捨五入，不是無條件捨去。這是 ABAP 跟 C / Java 最大的差別。

REPORT zdatatype08b.
" 陷阱二：/ 、DIV 、MOD 的差別（結果型別是 N 或 I 時會先四捨五入）
DATA lv_r TYPE n LENGTH 2.

lv_r = 45 / 7.      cl_demo_output=>write( |45 /   7 = { lv_r }| ).  " 6  (6.43 四捨五入)
lv_r = 45 DIV 7.    cl_demo_output=>write( |45 DIV 7 = { lv_r }| ).  " 6  (整數商)
lv_r = 45 MOD 7.    cl_demo_output=>write( |45 MOD 7 = { lv_r }| ).  " 3  (餘數)

" 更容易中招的：5 / 2 = 3 而不是 2
DATA(lv_i) = 5 / 2.
cl_demo_output=>write( |5 / 2 存成 I = { lv_i }| ).                  " 3
" 要得到 2.5 必須讓結果型別有小數
DATA(lv_p) = CONV decfloat34( 5 ) / 2.
cl_demo_output=>write( |改用 DECFLOAT34 = { lv_p }| ).               " 2.5
cl_demo_output=>display( ).
ABAP 的 MOD 對負數的結果永遠是「非負數」（-5 MOD 3 = 1），跟 C / Java 的 %（會得到 -2）不同。從其他語言移植演算法時務必驗算。

陷阱三：先轉型再運算，還是先運算再轉型？講義的 sqrt( 5 ) + sqrt( 6 ) 例子非常經典：sqrt() 回傳的是 F 型別，直接相加後才轉整數得 5（2.236+2.449=4.685→5）；若各自先 CONV i( ) 變成 2+2 就只有 4。

P 型態注意事項（講義第 08 節）：P 是「壓縮定點數」，兩個十進位數字壓進一個位元組，正負號與小數點另佔半個位元組。在 ABAP 程式裡，有效數字可到 1～31 位、小數最多 14 位，例如 DATA lv_p TYPE p LENGTH 16 DECIMALS 14. 可以放 '12345678901234567.89012345678901' 這種數字；但在 SE11 的 DOMAIN 裡，DEC 型別的「長度」欄位填的是含小數在內的總位數（例如整數 9 位＋小數 2 位要填長度 11、小數位 2），兩邊的計數方式不一樣，這是初學者對照 SE11 時最容易搞混的地方。（依講義截圖步驟整理）
講義使用的 CALL FUNCTION 'ROUND'（參數 decimals、input、sign：'X'＝四捨五入、'+'＝無條件進位、'-'＝無條件捨去）仍然可用，但新程式直接用內建 round( ) 即可，不必呼叫 FM、也不用處理 overflow / input_invalid 例外。

7. 迴圈：DO / WHILE / LOOP 與 CHECK / EXIT / CONTINUE

ABAP 共有五大迴圈：DO、WHILE、LOOP AT、SELECT ... ENDSELECT（禁用）、PROVIDE（幾乎沒人用）。控制指令四個：

指令作用用在哪
CONTINUE無條件結束本圈，直接跑下一圈所有迴圈
CHECK cond條件不成立時等同 CONTINUE（跳過本圈）迴圈內；在副程式／方法內則是直接離開
EXIT離開最內層迴圈；不在迴圈裡則離開該處理區塊所有迴圈
STOP中止 START-OF-SELECTION，直接跳到 END-OF-SELECTION只在 Report 事件區塊；已列 obsolete
RETURN立刻離開整個副程式／方法方法內建議用它取代 EXIT
最常見的誤解：CHECK 在迴圈裡是「跳過這一圈」，不是「跳出迴圈」；而 EXIT 只跳出一層。雙層迴圈想一次跳出兩層，只能靠旗標變數或把內層抽成方法用 RETURN。

8. 日期與時間運算

D 型別可以直接加減，單位是天；T 型別可以直接加減，單位是秒。兩個日期相減得到天數（型別要用 I），兩個時間相減得到秒數。

REPORT zdate_basic.
" 日期／時間的基本運算
DATA(lv_today) = sy-datum.

" 1. 本月月初：把 DD 改成 01
DATA(lv_first) = lv_today.
lv_first+6(2) = '01'.

" 2. 上月月底 = 本月月初 - 1
DATA(lv_prev_last) = CONV d( lv_first - 1 ).

" 3. 本月月底 = 下月月初 - 1（+31 天必定落在下個月的 1~4 日）
DATA(lv_next_first) = CONV d( lv_first + 31 ).
lv_next_first+6(2) = '01'.
DATA(lv_last) = CONV d( lv_next_first - 1 ).

" 4. 兩日期相差幾天：直接相減
DATA(lv_days) = CONV i( lv_last - lv_first ) + 1.   " 本月天數

" 5. 時間相減得秒數
DATA lv_t1 TYPE t VALUE '183000'.
DATA lv_t2 TYPE t VALUE '200000'.
DATA(lv_sec)  = CONV i( lv_t2 - lv_t1 ).            " 5400
DATA(lv_hour) = lv_sec / 3600.                      " 注意：存成 I 會四捨五入成 2
DATA(lv_hour_exact) = CONV decfloat34( lv_sec ) / 3600.   " 1.5

cl_demo_output=>write( |月初 { lv_first } 月底 { lv_last } 上月底 { lv_prev_last } 本月 { lv_days } 天| ).
cl_demo_output=>write( |時差 { lv_sec } 秒 = { lv_hour_exact } 小時| ).
cl_demo_output=>display( ).

12. 金額與數量的小數處理（CURR / QUAN / TCURX）

SAP 的金額欄位（DDIC 型別 CURR）與數量欄位（QUAN）在資料庫裡都是 P 型別，而且一定要搭配一個參考欄位：CURR 參考幣別欄位（CUKY，如 WAERS），QUAN 參考單位欄位（UNIT，如 MEINS）。沒有參考欄位，SE11 不讓你啟用。

TCURX 陷阱（實務上最貴的一個 bug）：資料庫裡的 CURR 欄位一律以「2 位小數」儲存。若幣別的實際小數位不是 2（如 JPY 日圓 0 位、KWD 科威特第納爾 3 位，定義在表 TCURX），DB 裡的數字與畫面上的數字會差 10 的次方倍。
例：日圓 1000 元，BSEG-WRBTR 存的是 10.00；你若直接 SELECT 出來加總並輸出，會少 100 倍。只要用 ALV／WRITE 並指定 CURRENCY 參考欄位，SAP 會自動換算；但若你把它丟給 Excel、丟給介面、或轉成 STRING，就必須自己呼叫換算函數。

16. 從「寫對」到「寫好」：18 條實務守則

講義第 10-5 節的清單，這是老師整章最想留下來的東西。

  1. 命名規則：lv_（區域變數）、gv_（全域變數）、iv_（輸入參數）、ev_（輸出參數）、cv_（可改參數）、rv_（回傳值）、lt_/gt_（內表）、ls_/wa_（工作區）、lo_（物件）、lr_（參考）、<fs_>（field symbol）。
  2. 常數與程序名一眼看得懂：CONSTANTS c_max_attempts TYPE i VALUE 3.；程序名用「模組＋物件＋動作」如 ZMM_PO_CREATE_AND_VALIDATE。
  3. 模組化：一個方法只做一件事，超過一個畫面高度就該拆。
  4. 一定要寫註解：註解寫「為什麼」，不要寫「做什麼」。
  5. 內縮與對齊：ABAP Editor 的 Ctrl+Shift+F1（Pretty Printer）養成習慣。
  6. 迴圈中少用 SELECT SINGLE：改成一次撈進內表再對應（FOR ALL ENTRIES 或 JOIN）。
  7. 少用 SELECT *：只取需要的欄位，HANA 是欄式儲存，多取一欄就多一份成本。
  8. 注意索引：WHERE 條件的欄位若不在索引上，效能會斷崖式下降；用 ST05 / SAT 驗證。
  9. 內表操作注意排序：READ TABLE ... BINARY SEARCH 之前一定要先 SORT 同樣的 key，否則會讀不到。
  10. HASHED 表加速查詢：DATA lt_cust TYPE HASHED TABLE OF ... WITH UNIQUE KEY customer_id.（只能用完整 key 讀，但 O(1)）。
  11. 批次取代逐筆：APPEND LINES OF 取代逐行 APPEND；INSERT ... FROM TABLE 取代逐筆 INSERT。
  12. 用 LOOP AT ... GROUP BY 取代雙迴圈。
  13. 重要片段做例外處理：TRY ... CATCH cx_...。
  14. SY-SUBRC 檢查：資料庫操作後必加。
  15. 訊息用 SE91 訊息類別：MESSAGE e001(zmm_po) WITH lv_ebeln. 才能多語言，不要硬編中文字串。
  16. OO 可以不會寫，但要看得懂：PUBLIC（對外開放）、PROTECTED（子類可用）、PRIVATE（只有自己用）。
  17. 禁止 SELECT ... ENDSELECT，尤其放在迴圈裡。
  18. 多表操作用內表與透明表交互：先 FOR ALL ENTRIES 撈價格表，再用 READ TABLE 對應，不要在迴圈裡查 DB。
