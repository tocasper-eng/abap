2. AMDP 類別與方法宣告的限制

AMDP 類別就是一般的全域類別，只是多實作一個標記介面 IF_AMDP_MARKER_HDB（HDB＝SAP HANA，目前唯一支援的資料庫）。同一個類別可以同時有 AMDP 方法和一般方法。宣告區看不出哪個方法是 AMDP，要到實作區的 METHOD … BY DATABASE PROCEDURE|FUNCTION 才決定。

AMDP procedure 的參數限制（7.53 文件）：

  • 參數一律 VALUE( ) 傳值，不能傳參考。
  • 型別不能是泛型（generic）；只能是基本型別，或列型別為結構的表格型別，且結構的元件也都要是基本型別（不能巢狀）。
  • 不能用列舉型別，也不能參照已過時的 DF16_SCL／DF34_SCL。
  • 不能有 RETURNING（有 RETURNING 的是 AMDP function）。
  • 只有 IMPORTING 能設成選用：基本型別要給 DEFAULT（只能是字面值或常數）；表格參數用 OPTIONAL（7.53 起）。string、xstring、decfloat16/34 不能選用。
  • 參數名不能以 %_ 開頭，不能叫 endmethod；connection 保留給資料庫連線名稱（型別 DBCON_NAME）；client 保留給未來擴充，不要拿來當 client 參數名稱。
  • RAISING 只能宣告 CX_AMDP_… 系列例外；不能用非類別式的 EXCEPTIONS。
  • 建構子（constructor、class_constructor）不能是 AMDP 方法。
CLASS zcl_sd_amdp_sales DEFINITION
  PUBLIC FINAL CREATE PUBLIC.

  PUBLIC SECTION.
    INTERFACES if_amdp_marker_hdb.          "標記介面：沒有它就不能寫 BY DATABASE …

             netwr   TYPE netwr_ak,

    "AMDP procedure：全部 VALUE( )、沒有 RETURNING
    METHODS get_customer_rank
      IMPORTING VALUE(iv_mandt)     TYPE mandt        "不要命名為 client（保留字）
                VALUE(iv_vkorg)     TYPE vkorg
                VALUE(iv_date_from) TYPE erdat

                VALUE(iv_top)       TYPE i DEFAULT 10

ENDCLASS.
SAP 文件建議：不打算讓其他類別的 AMDP 呼叫的 AMDP procedure，宣告成 PRIVATE，再由一個一般的 PUBLIC 方法包起來呼叫。這樣在非 HANA 的系統上，可以在包裝方法裡改走 ABAP SQL 的替代實作（第 14 節）。
出處：AMDP - Procedure Implementations（7.53）、AMDP - Methods、AMDP - Use。

3. METHOD … BY DATABASE PROCEDURE：FOR、LANGUAGE、OPTIONS、USING

實作區的完整語法（7.53）：

METHOD meth BY DATABASE PROCEDURE|FUNCTION
            FOR db
            LANGUAGE db_lang
            [OPTIONS db_options]
            [USING db_entities]
            [USING SCHEMA schema1 OBJECTS db_entities] ... .
  ...   "這裡開始是 SQLScript，不是 ABAP
ENDMETHOD.
附加可填內容說明
FORHDB目前唯一值；類別必須實作 IF_AMDP_MARKER_HDB。標準資料庫不是 HANA 時呼叫會產生執行期錯誤。
LANGUAGESQLSCRIPT（LLANG 限 SAP 內部）語法檢查只有在 HANA 系統上才會真的檢查 SQLScript。
OPTIONSREAD-ONLY、DETERMINISTIC（只給 scalar function）、SUPPRESS SYNTAX ERRORS（SAP 內部）AMDP function 至少要在實作端（或宣告端 AMDP OPTIONS）指定一次 READ-ONLY；READ-ONLY 的方法只能呼叫同樣 READ-ONLY 的 AMDP。
USINGDDIC 透明表、DDIC／CDS 資料庫 view、其他 AMDP（class=>meth）程式中用到的 ABAP 管理物件都必須列在這裡，列了就必須用到；同一類別裡的其他 AMDP 方法也要列。
USING SCHEMA … OBJECTS邏輯資料庫 schema（DB_SCHEMA_MAP）7.53；搭配巨集 "$ABAP.schema( )" 存取其他 schema 的物件。

  METHOD get_customer_rank BY DATABASE PROCEDURE
                           FOR HDB
                           LANGUAGE SQLSCRIPT
                           OPTIONS READ-ONLY
                           USING vbak.
    -- 以下是 SQLScript（完整內容見第 7 節）
    et_rank = SELECT vkorg, kunnr, waerk,
                     SUM( netwr ) AS netwr,
                     0 AS rank_no
                FROM vbak

其他實作限制：方法體不能是空的；不能下 DDL（CREATE／ALTER／DROP）；不能下 TRUNCATE、LOCK TABLE；不能 COMMIT／ROLLBACK（LUW 一律由 ABAP 程式控制）；不能寫有表緩衝的表（SQLScript 的寫入不會觸發緩衝同步）；存取 DDIC 表時，AMDP 會依字典的欄位順序對應。

AMDP 裡要寫 SQLScript 的註解（-- 或 /* */）。SAP 強烈建議方法體只用 7-bit ASCII，也強烈不建議在 AMDP 裡用動態 SQL（EXEC）：資料庫物件是否存在無法靜態檢查，也有 SQL injection 風險。上面範例的中文註解只是為了講解，正式程式請改成英文註解。
出處：METHOD - BY DATABASE PROCEDURE, FUNCTION（7.53）、AMDP - Procedure Implementations。

4. SQLScript 基礎：table variable、冒號、IF、FOR

SQLScript 是 HANA 的程序式 SQL。在 AMDP 裡最常用的是下面幾種寫法：

  • Table variable：lt_x = SELECT … ; 直接把查詢結果指派給變數，不需要事先宣告，型別由查詢推導。它不是實際存到 DB 的暫存表，HANA 最佳化器可以把多個步驟合併（inline）成一個執行計畫。
  • 冒號：讀取變數或參數時要加冒號（:iv_vkorg、FROM :lt_x）；寫入（等號左邊）不加。
  • 純量變數：DECLARE lv_cnt INTEGER;，宣告要放在區塊開頭；可用 SELECT … INTO lv_cnt 取值。7.52 起可用 AMDP 巨集 "$ABAP.type( mandt )" 直接參照 ABAP 型別。
  • 控制結構：IF … THEN … ELSEIF … ELSE … END IF;、FOR i IN 1 .. n DO … END FOR;、WHILE … DO … END WHILE;。
  • CE_ 函數（Calculation Engine Plan Operators，例如 CE_COLUMN_TABLE、CE_JOIN）：SAP HANA SQLScript Reference 明寫 SAP 建議用 SQL 而不要用 CE 運算子，把兩者混用還可能明顯拖慢效能。看到舊教材的 CE_ 寫法，請改成一般 SQL。
-- 在 AMDP 方法體內（SQLScript）
DECLARE lv_top INTEGER;
DECLARE lv_cnt INTEGER;

-- 1) 參數檢查：IF／ELSE
IF :iv_top <= 0 THEN
  lv_top = 10;
ELSE
  lv_top = :iv_top;
END IF;

-- 2) 第一步就過濾 client、銷售組織、日期：中間結果越小越好
lt_orders = SELECT vbeln, kunnr, waerk, netwr
              FROM vbak
             WHERE mandt = :iv_mandt
               AND vkorg = :iv_vkorg
               AND erdat BETWEEN :iv_date_from AND :iv_date_to;

-- 3) 從 table variable 再查詢：FROM 後面要加冒號
lt_sum = SELECT kunnr, waerk, SUM( netwr ) AS netwr
           FROM :lt_orders
          GROUP BY kunnr, waerk;

-- 4) 純量查詢
SELECT COUNT(*) INTO lv_cnt FROM :lt_sum;

SQLScript 也能逐列處理：RECORD_COUNT( :lt ) 取筆數，:lt.col[:i] 讀第 i 列的欄位。但這只是「能做」，不代表「該做」：

-- ✗ 逐列迴圈：HANA 無法平行化，資料量一大就很慢
-- （DECLARE 必須放在區塊開頭，這裡為了對照才寫在一起）
DECLARE i INTEGER;
DECLARE lv_total DECIMAL(23,2) DEFAULT 0;
FOR i IN 1 .. RECORD_COUNT( :lt_sum ) DO
  lv_total = :lv_total + :lt_sum.netwr[:i];
END FOR;

-- ✓ 集合式寫法：交給 SQL 引擎平行計算
SELECT SUM( netwr ) INTO lv_total FROM :lt_sum;
SQLScript 的語法會隨 HANA 版本增加（例如 RECORD_COUNT、以索引讀寫 table variable）。本章以 SAP HANA 2.0 SPS02 的 SQLScript Reference 為準；你的系統若是更舊的 HANA，請先在系統上確認。AMDP 的語法檢查是依目前安裝的 HANA 版本進行。
出處：SAP HANA SQLScript Reference（2.0 SPS02，PDF）：第 9.4.3 節 For Loop、RECORD_COUNT、第 10 章 Calculation Engine Plan Operators（「SAP recommends that you use SQL rather than Calculation Engine Plan Operators」）、第 17 章 Best Practices（避免 cursor、避免動態 SQL）；AMDP in Release 7.52（$ABAP.type 巨集）。

5. 視窗函數、APPLY_FILTER 與 SESSION_CONTEXT

視窗函數是 AMDP 最常見的用途：在 1809 的 ABAP SQL 還沒有 OVER( )（7.54 才有），要做「每組排名、每組取前 N 筆、累計」就要用 SQLScript。

-- 每個客戶的訂單依建立日由新到舊編號
lt_numbered = SELECT kunnr, vbeln, erdat, netwr, waerk,
                     ROW_NUMBER() OVER ( PARTITION BY kunnr
                                         ORDER BY erdat DESC, vbeln DESC ) AS rn
                FROM :lt_orders;

-- 只留每個客戶最新 3 張
lt_last3 = SELECT kunnr, vbeln, erdat, netwr, waerk, rn
             FROM :lt_numbered
            WHERE rn <= 3;
HANA 沒有預設排序：ROW_NUMBER( ) 一定要有明確、而且唯一的 ORDER BY。只寫 ORDER BY erdat DESC 時，同一天建立的兩張訂單誰排第 1、誰排第 2 是不確定的，每次執行都可能不同；所以上例加了 vbeln DESC 當次要排序（tie-breaker）。Casper 的實際案例：成本評價資料同時存在 item category「H」與 cost component「E」兩種角度，兩者的成本構成欄位數量不同。程式取第一筆卻沒有排序，HANA 一下回 H、一下回 E，同一個物料每次算出的成本都不一樣。最後的做法是條件固定抓 H，並加上明確排序。在 SQLScript 裡，這代表 PARTITION／ORDER BY 必須包含能唯一決定順序的欄位；如果「角度」本身就是業務條件，應該先在 WHERE 固定，而不是交給排序決定。另見 5-21 章第 24 節。

APPLY_FILTER 把一段 WHERE 條件字串（不含 WHERE 關鍵字）套用到資料表或 table variable 上。它可以指派給 table variable，不會阻擋 SQL inline 最佳化；但 SQLScript Reference 也提醒，動態 SQL 的其他缺點它都有。篩選字串中不能有子查詢，也不能用完整限定的欄位名稱。

-- iv_where 例如：( VKORG = '1000' OR VKORG = '2000' )
-- 先用固定條件（client 一定要自己帶）縮小範圍，再套用動態條件
lt_client   = SELECT vbeln, kunnr, vkorg, auart, netwr, waerk
                FROM vbak
               WHERE mandt = :iv_mandt;
lt_filtered = APPLY_FILTER( :lt_client, :iv_where );   -- 對 table variable 套用

SESSION_CONTEXT 可以讀 HANA 的 session 變數。從 ABAP 呼叫時，ABAP 會設定兩個 ABAP 專用的變數：SESSION_CONTEXT('CLIENT') 永遠是 sy-mandt；SESSION_CONTEXT('CDS_CLIENT') 預設相同，但可能被 ABAP SQL 的 USING CLIENT 或 AMDP 的 CDS SESSION CLIENT 改掉。

-- 可以這樣寫，但 SAP 文件建議改用輸入參數傳 client（見第 6 節）
lt_orders = SELECT vbeln, kunnr, netwr
              FROM vbak
             WHERE mandt = SESSION_CONTEXT('CLIENT');
出處：SAP HANA SQLScript Reference 2.0 SPS02 第 9.8.3 節 APPLY_FILTER；AMDP - Client Handling（7.53）（CLIENT／CDS_CLIENT）；ABAP SQL sql_win（7.54）。

6. Client 處理：AMDP 不會幫你加 MANDT

ABAP SQL 會自動加上「目前 client」的條件，AMDP 不會。SAP 文件的原則是：AMDP 存取 client 相依的表或 view 時，必須明確選擇 client。所以參數介面通常要有一個 client 輸入參數，並用在 WHERE 條件裡；JOIN 的 ON 條件也要比對兩邊的 mandt。

忘了 client 條件，就會把所有 client 的資料一起讀出來。開發機、測試機常有 100／200／300 等多個 client；彙總金額會莫名變成兩三倍，或 ROW_NUMBER 排進別的 client 的訂單。這種錯誤在只有一個 client 的正式機上看不出來，換到多 client 的測試機才爆出來，更難追。

1809（7.52 起）另有宣告端的選項 AMDP OPTIONS CDS SESSION CLIENT clnt|CURRENT，用來設定 HANA session 變數 CDS_CLIENT（也就是 CDS 裡的 $session.client）：

  • CDS SESSION CLIENT iv_mandt：以輸入參數（型別要相容於 CLNT）的值設定；CURRENT：設成目前登入的 client（sy-mandt）。
  • 什麼時候必須用：AMDP 讀取的 CDS 資料庫 view，其 client 處理是 @ClientHandling.algorithm: #SESSION_VARIABLE（該 view 在 DB 上已含 MANDT = SESSION_CONTEXT('CDS_CLIENT')）。7.52 時是警告，7.53 起不加就是語法錯誤。若自己在 WHERE 裡選的 client 與 session 變數不同，結果會是空的。
  • session 變數只有在從 ABAP 呼叫該方法時才會設定；AMDP 之間互相呼叫時不會改變。
" 7.52+（1809 可用）：讀取 SESSION_VARIABLE 型 CDS view 的 AMDP
METHODS get_orders_from_cds
  AMDP OPTIONS READ-ONLY
               CDS SESSION CLIENT iv_mandt
  IMPORTING VALUE(iv_mandt)  TYPE mandt
  EXPORTING VALUE(et_orders) TYPE tt_orders
  RAISING   cx_amdp_error.

" 實作端：對這種 CDS view 不要再自己寫 mandt 條件
" METHOD get_orders_from_cds BY DATABASE PROCEDURE FOR HDB
"        LANGUAGE SQLSCRIPT OPTIONS READ-ONLY USING zsd_order_sqlv.
"   et_orders = SELECT ... FROM zsd_order_sqlv;
" ENDMETHOD.
ABAP Cloud（以及較新的 on-premise 版本）改用宣告端的 AMDP OPTIONS READ-ONLY CDS SESSION CLIENT DEPENDENT 或 CLIENT INDEPENDENT，並要求 AMDP 必須「client-safe」：USING 只能列 client-safe 的物件，SQLScript 不能呼叫帶 client 參數的 HANA 內建函數，也建議移除方法簽章中的 client 參數。這組寫法在 1809 不能用，確切的版本門檻本章未能確認，請以系統為準。
出處：AMDP - Client Handling（7.53）、[CLASS-]METHODS - AMDP OPTIONS（7.53）、AMDP in Release 7.53（Option CDS SESSION CLIENT mandatory）、SAP-samples cheat sheet：Making AMDP Methods Client-Safe。

7. AMDP procedure 範例：銷售組織內的客戶銷售排名

需求：指定銷售組織與期間，彙總每個客戶的訂單淨值，並在同一幣別內排名，只回傳前 N 名。這個需求在 1809 可以用 ABAP SQL 彙總後再到 ABAP 端排序；這裡用 AMDP 來示範完整流程（過濾 → 彙總 → 視窗函數 → 取前 N），並說明從 ABAP 呼叫的寫法。

CLASS zcl_sd_amdp_sales IMPLEMENTATION.

  METHOD get_customer_rank BY DATABASE PROCEDURE
                           FOR HDB
                           LANGUAGE SQLSCRIPT
                           OPTIONS READ-ONLY
                           USING vbak.
    DECLARE lv_top INTEGER;

    IF :iv_top <= 0 THEN
      lv_top = 10;
    ELSE
      lv_top = :iv_top;
    END IF;

    -- Step 1: filter client / sales org / period first
    lt_orders = SELECT kunnr, waerk, netwr
                  FROM vbak
                 WHERE mandt = :iv_mandt
                   AND vkorg = :iv_vkorg
                   AND erdat BETWEEN :iv_date_from AND :iv_date_to;

    -- Step 2: aggregate per customer and currency
    lt_sum = SELECT kunnr, waerk, SUM( netwr ) AS netwr
               FROM :lt_orders
              GROUP BY kunnr, waerk;

    -- Step 3: rank within currency; unique ORDER BY (netwr, kunnr)
    lt_ranked = SELECT kunnr, waerk, netwr,
                       CAST( ROW_NUMBER() OVER ( PARTITION BY waerk
                                                 ORDER BY netwr DESC, kunnr )
                             AS INTEGER ) AS rank_no
                  FROM :lt_sum;

    -- Step 4: column order and names match ty_rank
    et_rank = SELECT :iv_vkorg AS vkorg, kunnr, waerk, netwr, rank_no
                FROM :lt_ranked
               WHERE rank_no <= :lv_top
               ORDER BY waerk, rank_no;
  ENDMETHOD.

ENDCLASS.

11. AMDP BAdI 與 fallback class

BAdI 方法本來就可以用 AMDP procedure 實作，並用 GET BADI／CALL BADI 呼叫。另外還有專門的 AMDP BAdI：在 BAdI Builder 中標記為 AMDP BAdI，具有下列特性（7.53 文件）：

  • 沒有 filter。
  • 必須指定 fallback 實作類別：沒有啟用任何增強實作時就執行 fallback；而且 AMDP BAdI 的 procedure 必須先在 DB 上存在，其他 AMDP 才能在語法無誤的情況下呼叫它，所以 fallback 是強制的。
  • 每個 BAdI 方法都必須是 AMDP procedure，而且都針對同一種資料庫。
  • 主要用途：讓 AMDP 能在 AMDP 內部，依 Switch Framework 呼叫到客戶的增強實作。從 ABAP 呼叫不需要 AMDP BAdI；但要從 AMDP 呼叫，就只能透過 AMDP BAdI。呼叫端要在 USING 宣告。
  • AMDP BAdI 目前不支援 AMDP function。

12. 除錯：AMDP Debugger、TRACE、ST05／SQLM 的限制

AMDP Debugger 是 ADT 內建、獨立於 ABAP Debugger 的除錯器：ABAP Debugger 除錯的是應用伺服器上的 ABAP，AMDP Debugger 除錯的是在 HANA 上執行的資料庫 procedure。前提是 NetWeaver 7.50 SP00 以上、HANA SPS9 以上（SPS8 功能受限）、ADT 2.51 以上；1809 都符合。

  1. 先啟用：和 ABAP Debugger 不同，AMDP Debugger 必須先啟用才會停在中斷點。可以在 AMDP 程式碼左側的尺規按右鍵選 Activate AMDP Debugger，或直接在 SQLScript 行上設中斷點（會自動啟用）。需要的是一般的 ABAP 除錯權限，不需要另外的 DB 使用者。
  2. 設定中斷點：在 SQLScript 可執行敘述那一行的尺規上雙擊，或用右鍵 Toggle Breakpoint。
  3. 執行：從 ABAP 端執行程式；停下後可在 Variables 檢視看 table variable 的內容。
  4. 操作：F8 Resume（跑到下一個 AMDP 中斷點）、F6 Step Over（執行下一個 SQLScript 敘述）；沒有 F5 Step Into，要進入被呼叫的 procedure，就在那邊先設中斷點。
  5. 設定：Window → Preferences → ABAP Development → Debug 的專案設定中，Compile in Debug Mode 可選「只有含中斷點的 procedure」（預設，啟動快，但最佳化可能讓某些中斷點停不到）或「所有被呼叫的 procedure」（沒有副作用，但啟動慢）。

SQLScript 的 TRACE：TRACE( :var ) 會把 table variable 的內容寫到一個本機暫存表，原樣回傳輸入；暫存表名稱可以從監控 view SYS.SQLSCRIPT_TRACE 查。SQLScript Reference 明確說不要用在正式程式（負擔很大，而且命名規則可能改變）。

-- 開發時暫時加上，上線前一定要刪
lt_orders = SELECT kunnr, waerk, netwr FROM vbak WHERE mandt = :iv_mandt;
lt_orders = TRACE( :lt_orders );

-- 事後在 HANA 的 SQL console（例如 DBACOCKPIT 或 HANA Studio）查暫存表名稱
-- SELECT * FROM SYS.SQLSCRIPT_TRACE;
AMDP 不能存取本機暫存資料庫物件，而 TRACE 會寫本機暫存表。TRACE 在 AMDP（尤其是 OPTIONS READ-ONLY 的 AMDP）中能否使用，本章未能確認，請以系統為準；AMDP 的除錯請優先用 AMDP Debugger。

ST05／SQLM 的限制：ST05 的 SQL trace 對 AMDP 只記到「呼叫資料庫 procedure」這一筆與它的總時間，看不到 procedure 內哪一段 SQL 慢。SQLM（SQL Monitor）是以 ABAP 端的資料庫存取點彙總，也看不到 SQLScript 內部各敘述的細節。要分析內部，改到 HANA 端看執行計畫（SQLScript Reference 的 EXPLAIN PLAN FOR CALL、PlanViz），或用 AMDP Debugger 逐步確認中間結果的筆數。SAP Community 文章提到 ST05 另有 AMDP 相關工具，可以追到個別敘述，但本章未能確認它在 1809 的名稱與位置。

出處：SAP Help（NW 7.5）Debugging AMDPs、Activating the AMDP Debugger、Stepping in the AMDP Debugger、AMDP Debugger Settings；SQLScript Reference 2.0 SPS02 第 10.3.3 節 TRACE、第 16.5 節 EXPLAIN PLAN FOR Call；SAP Community：AMDP Statement performance trace；除錯概念另見 6-1 章。

AMDP 不是「寫了就快」。以下是最常見、會讓 AMDP 比 ABAP SQL 還慢的寫法：

陷阱症狀正確做法
沒有在第一步就過濾 client 與日期中間 table variable 有上千萬筆，記憶體與時間暴增第一個 SELECT 就帶 mandt、組織、日期等條件，並只選需要的欄位
逐列迴圈（FOR／WHILE、cursor）無法平行化，筆數一多就很慢改成集合式 SQL；SQLScript Reference 的最佳實務就寫了要避免 cursor
隱含型別轉換條件欄位被逐列轉型，過濾條件無法有效下推；或結果指派到輸出參數時型別不符而失敗參數直接參照欄位的字典型別（TYPE erdat、TYPE vkorg），不要用 string 或 i 去比字元欄位；視窗函數、COUNT 的結果用 CAST( … AS INTEGER ) 明確轉成輸出型別；區域變數用 "$ABAP.type( )"
中間結果過大、重複計算同一個子查詢被算好幾次把共同子運算抽成一個 table variable 重複使用

-- ✗ 先讀全部、最後才過濾：lt_all 是所有 client、所有年度的訂單
lt_all  = SELECT * FROM vbak;
lt_sum  = SELECT kunnr, SUM( netwr ) AS netwr FROM :lt_all GROUP BY kunnr;
et_out  = SELECT kunnr, netwr FROM :lt_sum;          -- 還忘了 client

-- ✓ 第一步就過濾 client 與日期，只選需要的欄位

            FROM vbak
           WHERE mandt = :iv_mandt
             AND erdat BETWEEN :iv_date_from AND :iv_date_to;

            FROM :lt_ord

HANA 沒有預設排序。SQLScript 裡的 table variable 沒有「列的順序」可言；ROW_NUMBER( )、LIMIT、「取第一筆」都要有明確而且唯一的 ORDER BY。Casper 的成本評價 H／E 案例（第 5 節）就是這個問題：兩種角度的資料並存、排序沒有唯一性，結果就會隨執行不同而改變。解法有兩層：先用 WHERE 把業務上該選的那一種固定下來（固定抓 H），再用唯一的 ORDER BY 決定剩下的順序。

15. 傳輸與相依性：USING、DDIC 變更、只能在 HANA 上執行

  • AMDP 跟一般類別一起傳輸。傳到目標系統後，並不是在匯入時建立 DB procedure，而是第一次被呼叫時才由 ABAP 執行環境在 HANA 上建立或更新。所以匯入成功，不代表在正式機一定能執行；正式機第一次呼叫可能比較慢，產生失敗會以 CX_AMDP_CREATION_ERROR 系列例外出現。
  • USING 子句就是相依性宣告：where-used、套件檢查都靠它，也讓 AMDP 能依字典的欄位順序存取表。沒列在 USING 的 ABAP 管理物件不能存取（/1BCAMDP/ 命名空間的暫存物件除外）。
  • DDIC 變更的影響：USING 列出的表如果刪除或改名了 AMDP 用到的欄位，AMDP 會在語法檢查或第一次呼叫時失敗。改表之前，先用 where-used 找出所有列了這個表的 AMDP，逐一重新做語法檢查。表結構變更後，AMDP 是否會自動重新產生，本章未能確認，請以系統為準。
  • 只能在 HANA 上執行：標準資料庫不是 HANA 時，呼叫會產生執行期錯誤。要支援多種資料庫，就依 cl_abap_dbfeatures 分流到 ABAP SQL 的替代實作。
  • 權限：AS ABAP 連線 HANA 的資料庫使用者要有管理 procedure 的權限；權限不足時 AMDP 可能出現語法錯誤，可用 SICK 檢查。
  • 跨 schema：若要讀其他 schema 的物件，用邏輯 schema（DB_SCHEMA_MAP）＋ "$ABAP.schema( )"，每個系統各自設定對應，程式碼就不必改。
"包裝方法：HANA 走 AMDP，其他資料庫走 ABAP SQL（AMDP 本身設為 PRIVATE）
"宣告示意：METHODS get_rank_portable IMPORTING iv_vkorg ... iv_top TYPE i
"                                   RETURNING VALUE(rt_rank) TYPE tt_rank.
METHOD get_rank_portable.
  IF cl_abap_dbfeatures=>use_features(
       requested_features = VALUE #( ( cl_abap_dbfeatures=>call_amdp_method ) ) ).
    get_customer_rank_amdp( EXPORTING iv_mandt     = sy-mandt
                                      iv_vkorg     = iv_vkorg
                                      iv_date_from = iv_date_from
                                      iv_date_to   = iv_date_to
                                      iv_top       = iv_top
                            IMPORTING et_rank      = rt_rank ).
  ELSE.
    SELECT kunnr, waerk, SUM( netwr ) AS netwr
      FROM vbak
      WHERE vkorg = @iv_vkorg
        AND erdat BETWEEN @iv_date_from AND @iv_date_to
      GROUP BY kunnr, waerk
      ORDER BY waerk, netwr DESCENDING, kunnr
      INTO TABLE @DATA(lt_sum).
    LOOP AT lt_sum INTO DATA(ls_sum)
         GROUP BY ls_sum-waerk INTO DATA(lg_waerk).
      DATA(lv_no) = 0.
      LOOP AT GROUP lg_waerk INTO DATA(ls_member).
        lv_no = lv_no + 1.
        IF lv_no > iv_top.
          EXIT.
        ENDIF.
        rt_rank = VALUE #( BASE rt_rank
                           ( vkorg = iv_vkorg kunnr = ls_member-kunnr waerk = ls_member-waerk
                             netwr = ls_member-netwr rank_no = lv_no ) ).
      ENDLOOP.
    ENDLOOP.
  ENDIF.
ENDMETHOD.

16. 實作範例：每個客戶最近三張訂單──ABAP SQL、CDS、AMDP 三種做法

需求：指定銷售組織，列出每個客戶最近建立的三張銷售訂單（VBAK）。「最近」的定義是 erdat 由新到舊；同一天的訂單再依 vbeln 由大到小，確保排序唯一。

做法 A：ABAP SQL 視窗運算式（7.54 以上）

" 需 7.54（S/4HANA 1909）以上：ABAP SQL 的 OVER( ) 視窗運算式
SELECT kunnr, vbeln, erdat, netwr, waerk,
       ROW_NUMBER( ) OVER( PARTITION BY kunnr
                           ORDER BY erdat DESCENDING, vbeln DESCENDING ) AS rn
  FROM vbak
  WHERE vkorg = @p_vkorg
  ORDER BY kunnr, erdat DESCENDING, vbeln DESCENDING
  INTO TABLE @DATA(lt_numbered).

DELETE lt_numbered WHERE rn > 3.    "只留每個客戶最新 3 張
7.54 文件寫明：視窗運算式只能出現在查詢的 SELECT 清單，不能用在 WHERE、GROUP BY、HAVING。所以上例是讀回後在 ABAP 端刪掉 rn > 3 的列，多傳了資料。能否把它放進 WITH 的 CTE、再在外層用 WHERE rn <= 3 過濾，本章未能在 7.54 文件中確認，請以系統為準。1809 不能用做法 A。

做法 B：CDS

本章查閱 7.53／7.54 的 CDS DDL 文件，沒有找到視窗函數（OVER）語法。所以「每組取前 N 筆」不能只靠一般的 CDS view，CDS 端的做法就是第 9 節的 CDS table function（DDL 在 CDS、實作在 AMDP）。它的好處是：外界看到的是一個 CDS entity，可以在 ABAP SQL、其他 CDS view 中使用，也能加 DCL；壞處是實作仍然是 SQLScript。更新版本的 CDS view entity 是否支援視窗函數，本章未能確認。
