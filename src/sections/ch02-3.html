1. ALV 家族演進：先知道自己站在哪一代

老師在講義裡把 ABAP 的工作排序講得很直白：報表開發＝ALV、單據列印＝SmartForms／Form、財務樞紐＝Report Painter。而 ALV 本身歷經三代，第四代則已經跳到 Fiori。

2. 最短的 ALV：CL_SALV_TABLE 三步驟

講義第 04 節標題就叫「NEW ALV(SALV) 2004 發佈，最短的 ALV」，原始程式是 ZSALV。SALV 的三步驟永遠一樣：

  1. 備資料：SELECT 進內表。
  2. factory：cl_salv_table=>factory( ) 把內表交給 ALV，拿回一個 lo_alv 參考。
  3. display：lo_alv->display( )。
REPORT zsalv.
" 講義原始 ZSALV：SELECT * FROM sflight ... + cl_salv_table=>factory + display
" 現代寫法：明列欄位、內嵌宣告、TRY/CATCH

SELECT carrid, connid, fldate, price, currency, seatsmax, seatsocc
  FROM sflight
  UP TO 25 ROWS
  INTO TABLE @DATA(lt_flight).

TRY.
    " list_display = IF_SALV_C_BOOL_SAP=>false → GRID 樣式（Excel 風格）
    " list_display = IF_SALV_C_BOOL_SAP=>true  → LIST 樣式（傳統清單）
    cl_salv_table=>factory(
      EXPORTING list_display = if_salv_c_bool_sap=>false
      IMPORTING r_salv_table = DATA(lo_alv)
      CHANGING  t_table      = lt_flight ).

    lo_alv->display( ).

  CATCH cx_salv_msg INTO DATA(lx_msg).
    MESSAGE lx_msg->get_text( ) TYPE 'E'.
ENDTRY.
factory 的三種輸出容器：
• 不帶 r_container → 全螢幕 ALV（最常用）。
• 帶 r_container = lo_container（CL_GUI_CUSTOM_CONTAINER）＋ container_name → 嵌在自畫的 Screen 裡。
• 帶 CL_GUI_DOCKING_CONTAINER → 停靠在選擇畫面旁邊，做「不用另開畫面」的報表。
SALV 的資料表不能是有 HEADER LINE 的舊式內表，也不能是深層巢狀（含內表的內表）結構，否則 factory 會丟 CX_SALV_MSG。另外 t_table 是 CHANGING 參數，代表 ALV 直接引用你的內表——顯示期間不要把它 REFRESH 掉。

4. Field Catalog（欄位目錄）：ALV 的靈魂

欄位目錄用來控制 ALV 每一欄的屬性：順序、對齊、可編輯、顏色、加總、要不要顯示⋯⋯。傳統 ALV 有三種建法，各有適用場合：

作法怎麼做適合
① 全自動（DDIC）FM 參數 I_STRUCTURE_NAME = 'SFLIGHT'；SALV 則是 factory 自動依內表行型別產生內表結構＝某個 DDIC 結構／資料表，欄位全部要顯示
② 半自動（MERGE）REUSE_ALV_FIELDCATALOG_MERGE 讀程式內表的宣告或 DDIC 結構自動產生，再手工覆寫少數欄位欄位很多、只想改其中幾個屬性
③ 全手動逐欄 APPEND 一筆 SLIS_FIELDCAT_ALV / LVC_S_FCAT內表是自訂 TYPES、抬頭要中文、要精準控制

講義 Z202202_24 是全手動版本，逐欄 CLEAR / col_pos + 1 / APPEND，寫了一百多行。現代 ABAP 可以用 VALUE #( ) 一次寫完，可讀性天差地遠：

DATA(lt_fcat) = VALUE lvc_t_fcat(

  ( fieldname = 'ERDAT' col_pos = 2  outputlen = 10 scrtext_m = '訂單日期' )
  ( fieldname = 'ERNAM' col_pos = 3  outputlen = 12 scrtext_m = '輸入人員' )

" ── 半自動：先讓系統依 DDIC 結構生成，再覆寫個別欄位 ──────────────
" 舊法：REUSE_ALV_FIELDCATALOG_MERGE（講義 BALVSD11 / BALVHD01 用它）
" 新法（推薦）：CL_SALV_DATA_DESCR 或直接用 SALV，不必自己生 fieldcat
DATA lt_fcat TYPE lvc_t_fcat.

CALL FUNCTION 'LVC_FIELDCATALOG_MERGE'
  EXPORTING
    i_structure_name       = 'SFLIGHT'
    i_client_never_display = abap_true   " 自動隱藏 MANDT
  CHANGING
    ct_fieldcat            = lt_fcat
  EXCEPTIONS
    inconsistent_interface = 1
    program_error          = 2
    OTHERS                 = 3.
IF sy-subrc <> 0.
  MESSAGE '欄位目錄建立失敗' TYPE 'E'.
ENDIF.

LOOP AT lt_fcat ASSIGNING FIELD-SYMBOL(<ls_fcat>).
  CASE <ls_fcat>-fieldname.
    WHEN 'CARRID'.   <ls_fcat>-key       = abap_true.
                     <ls_fcat>-outputlen = 7.
    WHEN 'PRICE'.    <ls_fcat>-do_sum    = abap_true.
    WHEN 'SEATSMAX'. <ls_fcat>-no_out    = abap_true.   " 隱藏但可從 layout 拉出來

  ENDCASE.
ENDLOOP.
三個一定會踩的坑：
1. fieldname 必須大寫，而且要跟內表欄位名一字不差，寫錯不會報錯、只是那欄空白或不見。
2. 所有要顯示的欄位，內表一定要有對應欄位；ALV 不會幫你補。
3. 單引號內的字串（結構名、欄位名、功能碼）在呼叫系統物件時一律大寫。

5. 紅綠燈（Exception / Lights）與圖示欄位

紅綠燈有兩種做法，講義兩種都示範了：

  1. Exception 欄位：內表加一個 CHAR1（或 CHAR4）欄位，值填 1 = 紅、2 = 黃、3 = 綠，再告訴 ALV 這欄是燈號欄。
    傳統：layout-lights_fieldname = 'LIGHTS'（LVC：excp_fname）。
    SALV：lo_cols->set_exception_column( 'LIGHT' )。
  2. ICON 欄位：內表欄位型別 icon-id（或 CHAR4），值填 icon_led_green / icon_led_red / icon_led_yellow 等常數，fieldcat 該欄設 icon = 'X'。這種做法可以一列放好幾顆燈（講義 ZEKET_43 就放了 LIGHT1/2/3 三顆）。

*& Report ZSALV_LIGHT  ── 掛上警示燈的 NEW ALV（講義原名 ZSALV_LIGHT）

         INCLUDE TYPE sflight.
TYPES:   light TYPE char1,     " 講義原本欄位名叫 EXCEPTION，屬保留字風險，改名
       END OF ty_row.

另一種常被搞混的是自己在 LOOP 裡算小計（AT END OF）。兩者差別如下：

ALV 自動小計（IT_SORT + DO_SUM）AT END OF 自己算
誰算ALV 控制項在前端算你在程式裡算，多插一列進內表
使用者拖欄位重排小計自動跟著重算不會重算，數字會錯
匯出 Excel會帶小計列會帶（因為它就是資料列）
建議優先使用只有要特殊格式（例如小計列要不同文字）才用
 
" ── AT END OF 的正確用法：使用前必須先 SORT，而且只看「該欄與其左邊所有欄」──
SORT lt_out BY kunnr matnr.

DATA lv_sum TYPE vbap-zmeng.

LOOP AT lt_out INTO DATA(ls_out).
  lv_sum = lv_sum + ls_out-zmeng.

  AT END OF kunnr.          " 注意：判斷的是 kunnr 及其「左側全部欄位」
    WRITE: / |客戶 { ls_out-kunnr } 小計：{ lv_sum NUMBER = USER }|.
    CLEAR lv_sum.
  ENDAT.
ENDLOOP.
AT END OF 的三個陷阱：
1. 一定要先 SORT，否則群組會斷斷續續。
2. AT ... ENDAT 區塊內，除了控制欄位以外的其他欄位都會被填成 *（星號），所以要在進入 AT 之前先把要用的值存起來。
3. 講義 ZEKET_43 註記「DO_SUM 做不出來，可能跟 JOIN 有關」——真正原因通常是：數量欄沒有綁單位欄（qfieldname／cfieldname 沒設），或該欄的 datatype 被手動指定成 CHAR。金額欄要綁 CFIELDNAME，數量欄要綁 QFIELDNAME，否則 ALV 不知道能不能加總。

8. Layout 變式（DISVARIANT）：讓使用者自己排版面

使用者最常抱怨的是「欄位太多、順序不對」。正解不是改程式，而是把版面存成變式。傳統做法要自己接 4 支 FM（講義 BALVSD01 / BALVSD11 就是完整示範）：

FM時機用途
REUSE_ALV_VARIANT_DEFAULT_GETINITIALIZATION取得預設變式，填進選擇畫面的 P_VARI
REUSE_ALV_VARIANT_F4AT SELECTION-SCREEN ON VALUE-REQUEST提供 F4 選變式
REUSE_ALV_VARIANT_EXISTENCEAT SELECTION-SCREEN檢查使用者輸入的變式存不存在
REUSE_ALV_LIST/GRID_DISPLAY 的 IS_VARIANT / I_SAVE顯示時I_SAVE：' '不可存、'U' 只能存個人、'X' 只能存共用、'A' 兩種都可
 
*&--------------------------------------------------------------------*
*& Layout 變式完整套路（講義 BALVSD01 / BALVSD11 的現代化版本）
*&--------------------------------------------------------------------*
DATA: gs_variant  TYPE disvariant,
      gs_variant_x TYPE disvariant,
      gv_exit     TYPE char1.
CONSTANTS gc_save TYPE char1 VALUE 'A'.   " A = 個人 + 共用皆可儲存

SELECTION-SCREEN BEGIN OF BLOCK b_var WITH FRAME TITLE TEXT-064.
PARAMETERS p_vari TYPE disvariant-variant.
SELECTION-SCREEN END OF BLOCK b_var.

INITIALIZATION.
  gs_variant-report = sy-repid.
  gs_variant_x      = gs_variant.
  CALL FUNCTION 'REUSE_ALV_VARIANT_DEFAULT_GET'
    EXPORTING  i_save     = gc_save
    CHANGING   cs_variant = gs_variant_x
    EXCEPTIONS not_found  = 2.
  IF sy-subrc = 0.
    p_vari = gs_variant_x-variant.
  ENDIF.

AT SELECTION-SCREEN ON VALUE-REQUEST FOR p_vari.
  CALL FUNCTION 'REUSE_ALV_VARIANT_F4'
    EXPORTING  is_variant = gs_variant
               i_save     = gc_save
    IMPORTING  e_exit     = gv_exit
               es_variant = gs_variant_x
    EXCEPTIONS not_found  = 2.
  IF sy-subrc = 2.
    MESSAGE ID sy-msgid TYPE 'S' NUMBER sy-msgno
       WITH sy-msgv1 sy-msgv2 sy-msgv3 sy-msgv4.
  ELSEIF gv_exit IS INITIAL.
    p_vari = gs_variant_x-variant.
  ENDIF.

AT SELECTION-SCREEN.
  IF p_vari IS NOT INITIAL.
    gs_variant_x         = gs_variant.
    gs_variant_x-variant = p_vari.
    CALL FUNCTION 'REUSE_ALV_VARIANT_EXISTENCE'
      EXPORTING i_save     = gc_save
      CHANGING  cs_variant = gs_variant_x.
    gs_variant = gs_variant_x.
  ELSE.
    CLEAR gs_variant.
    gs_variant-report = sy-repid.
  ENDIF.
SALV 只要三行就搞定同一件事（而且 F4、儲存、預設全部自動）：
DATA(lo_layout) = lo_alv->get_layout( ).
lo_layout->set_key( VALUE #( report = sy-repid handle = '0001' ) ).

FORM save_to_db.

  " 依內表的 key 撈出實體表資料（FOR ALL ENTRIES 前務必檢查非空）
  IF gt_out IS INITIAL.
    MESSAGE '無資料可存' TYPE 'S' DISPLAY LIKE 'E'.
    RETURN.

  SELECT ebeln, ebelp, etenr, eindt, slfdt, menge
    FROM eket

      AND ebelp = @gt_out-ebelp
      AND etenr = @gt_out-etenr
    INTO TABLE @DATA(lt_eket).

  LOOP AT lt_eket ASSIGNING FIELD-SYMBOL(<ls_eket>).

    ASSIGN gt_out[ ebeln = <ls_eket>-ebeln
                   ebelp = <ls_eket>-ebelp
                   etenr = <ls_eket>-etenr ] TO FIELD-SYMBOL(<ls_out>).
    IF sy-subrc = 0.
      <ls_eket>-eindt = <ls_out>-eindt.
      <ls_eket>-slfdt = <ls_out>-eindt.
    ENDIF.
  ENDLOOP.

  " 標準 SAP 表建議走 BAPI（BAPI_PO_CHANGE），示範用 UPDATE 說明交易一致性
  UPDATE eket FROM TABLE @lt_eket.
  IF sy-subrc = 0.
    COMMIT WORK AND WAIT.
    MESSAGE '存檔成功！' TYPE 'S'.
  ELSE.
    ROLLBACK WORK.
    MESSAGE '存檔失敗！' TYPE 'S' DISPLAY LIKE 'E'.
  ENDIF.

ENDFORM.
直接 UPDATE 標準表是大忌。講義為了教「內表 → 實體表回寫」與 COMMIT WORK / ROLLBACK WORK 的觀念才這樣寫；正式專案改採購單一定要用 BAPI_PO_CHANGE + BAPI_TRANSACTION_COMMIT，改銷售訂單用 BAPI_SALESORDER_CHANGE。直接 UPDATE 會略過所有檢核、不寫變更文件（CDHDR/CDPOS）、不觸發後續流程，之後帳一定對不起來。
FOR ALL ENTRIES 三大陷阱：（1）驅動內表為空 → 條件被忽略，等於全表掃描；使用前一定要 IF lt_x IS NOT INITIAL。（2）結果會自動去重複（等同 DISTINCT），所以 SELECT 欄位一定要包含完整主鍵。（3）驅動內表太大時會被切成多次 DB 呼叫，效能不見得比 JOIN 好——能 JOIN 就 JOIN。
可編輯 ALV 的三個必要條件，缺一不可：
① fieldcat 該欄 edit = 'X'（或 layout edit = 'X' 整張開放）。
② 呼叫 register_edit_event( mc_evt_modified )（或舊式 I_GRID_SETTINGS-EDT_CLL_CB = 'X'）。
③ 存檔前呼叫 go_grid->check_changed_data( )，把游標還停在編輯格的最後一筆值 flush 回內表。
另外，可編輯且有小數的數量／金額欄一定要指定 decimals_o（講義第 26 支程式特別註記），否則使用者輸入 1.5 會被吃成 15。

11. GUI Status 與自訂按鈕：SE41 的正確作法

講義第 25 支程式的「特色一」就是 PF_STATUS_SET 前置準備。SAP 官方說明講得很清楚：要設自訂 Status，請以函數群組 SALV 的 STANDARD 為樣板複製。步驟如下（依講義步驟整理）：

  1. SE41 Menu Painter → 程式名輸入 SAPLSALV、Status 輸入 STANDARD（或 STANDARD_FULLSCREEN）。
  2. 功能表 Status → 複製，目標程式填你自己的 Z 程式、Status 名稱自取（例如 ZSTATUS）。
  3. 在 Application Toolbar（應用工具列）新增按鈕，功能碼取 ZADD、ZSAV、ZCAS 之類的 Z 開頭代碼，填上圖示與 Quickinfo。建議放 Application Bar，不要塞進 Menu Bar——使用者根本不會去點選單。
  4. 存檔後一定要啟動（Activate）。物件變多時，可用 SE80 的物件清單一次全選啟動，或用 SE38 執行 RS_WORKING_AREA_ACTIVATE／在 SE80 對 Package 按「Activate All」。
  5. 在程式的 PF_STATUS_SET 事件裡 SET PF-STATUS 'ZSTATUS' EXCLUDING rt_extab.
RT_EXTAB 是什麼？SAP 說明原文：Parameter RT_EXTAB 內含「目前必須停用」的 ALV 專屬功能碼，你必須把這張表原封不動傳給 SET PF-STATUS ... EXCLUDING。不傳的話，畫面上會出現一些當下根本不能用的按鈕，按下去就 dump。因為這個 callback 太常用，SAP 讓你可以直接用 I_CALLBACK_PF_STATUS_SET 參數傳 FORM 名稱，不必建事件表。

SALV 的自訂按鈕作法不同——它用 set_screen_status( )，而且要先在自己的程式裡建一個 Status（同樣從 SAPLSALV 的 STANDARD 複製）：

" ── SALV 掛自訂 GUI Status ─────────────────────────────────────
" set_functions 三個選項：
"   c_functions_none / c_functions_default / c_functions_all
lo_alv->set_screen_status(
  report        = sy-repid          " Status 存在哪一支程式
  pfstatus      = 'ZSALV_STATUS'    " SE41 從 SAPLSALV-STANDARD 複製而來
  set_functions = lo_alv->c_functions_all ).

" 或者不自訂 Status，只把標準功能全開（最省事）
lo_alv->get_functions( )->set_all( abap_true ).

" 也可以逐項開關

16. 老師強調的注意事項與坑

  1. 在 ALV 中，所有要顯示的欄位都必須在對應內表中有欄位，欄位名不能寫錯。
  2. ABAP 字串大小寫很重要。單引號包起來的字串，呼叫系統方法時一律用大寫。
  3. 傳給 ALV 的欄位名稱必須大寫，否則資料不會顯示。
  4. 用 巨集（DEFINE）或副程式（FORM）可以大幅縮短欄位目錄的程式碼並重複使用；現代寫法更推薦 VALUE #( ) 或抽成方法。
  5. FORM 內定義的變數在離開 FORM 後就被系統釋放、記憶體回收——不要期待它跨 FORM 存活。
  6. 程式一直出錯時，建議把關鍵字都改成大寫再試（講義 Z202202_25 的註記）。
  7. 有些 SLIS 結構無法用 SE11 直接查，要用 SE80 打開 type-pool SLIS 來看。
  8. ZEKET_43 的功能演進清單（可當作自己練習的檢核表）：排序、抓供應商編號、加物料編號、TOP_OF_PAGE 抬頭與圖片、日期格式化、日期可修改、PF_STATUS_SET 功能表、USER_COMMAND 存檔、回寫 EKET、單位欄位、紅綠燈、LEAVE PROGRAM 退出、DO_SUM、用副程式改寫、兩次 INNER JOIN。
