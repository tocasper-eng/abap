2. 架構：設計時、執行時與 Adobe Document Services

使用者視角：用 TCODE 開應用 → 在畫面輸入資料、觸發業務流程 → 列印。可以先在 SAP GUI 自動載入的 Adobe Reader 預覽 PDF，再從預覽觸發輸出，產生 spool request，於 SP01 管理。

設計時（Design Time）要做三件事，都在 SFP（或 SE80 → 其他物件 → More 頁籤）：

物件內容重點
Interface（介面）程式可以傳哪些資料給表單；另含全域資料與初始化程式碼獨立的 Repository 物件、可重複使用；沒有表單也能單獨存在（Col18 Unit 1 測驗題）
Form（表單範本）= Context（此表單實際用介面中的哪些部分，另可加文字模組、圖片）+ LayoutContext 永遠屬於某一張表單
Layout（版面）在 Adobe LiveCycle Designer 設計的靜態與動態元素技術上存成 XML 格式 XDP（XML Data Package）

表單範本啟用（Activate）時做三件事：檢查 Context 語法 → 儲存 → 最重要的：產生一支函數模組。這支生成的函數模組封裝了表單的全部屬性，程式要印表單時呼叫的就是它（部分文件把「表單範本」稱為「表單物件 form object」）。

執行時（Runtime）：ABAP 程式取得並計算所有資料 → 傳給生成的函數模組。因為介面可重複使用，只要多張表單共用同一個介面，一支列印程式就能呼叫多張表單。

列印情境的系統架構（Web AS 6.20 起 SAP 系統可同時跑 ABAP 與 Java，需安裝 J2EE 引擎）：

  1. 整合進傳統 ABAP 程式（列印情境）：大量處理，列印、郵寄、傳真；資料擷取與 spool 處理由 ABAP 負責。
  2. 瀏覽器互動情境：使用者在網頁中填表，Java Web Dynpro，或 NW 7.0 起的 ABAP Web Dynpro（見 5-23 章 Web Dynpro ABAP）。

兩種情境的渲染（rendering）都由 ADS 完成。ABAP 端流程：應用程式透過 PPF（Post Processing Framework，Output Control 的後繼者）判斷要不要輸出、輸出哪一種 → 表單處理執行環境（Form Processing Runtime）開關 spool job，並以 SOAP over HTTP 呼叫 ADS 的 Web Service → ADS 負責填欄位、分頁、套版 → 回傳 PDF → 依程式設定送 spool 或郵寄。

ADS 部署在 J2EE 引擎上，由 ADS Web Service 與下列 SAP J2EE 服務組成：Document Services Data Manager、Document Services Font Manager、PDF Manipulation Module、XML Form Module、Document Services License Service。注意：SFP 的複製、測試等功能也需要標準 ADS 連線可用。

PDF 表單相對於 SmartForms／SAPscript 的優點（Col18 列舉）：PDF 是網路表單的事實標準；Designer 好用且整合於 ABAP Workbench；BMP/JPEG/GIF/PNG/EXIF 圖片免轉換直接放；物件（含文字）可旋轉；同一張表單可混用直式橫式頁面；可做無障礙表單；複雜版面元素可在開發者間共享；可匯入現有 PDF／Word；TrueType 字型免上傳；PostScript/PCL/PDF/Zebra 印表機都能印條碼；郵寄傳真更容易；表單是標準 Repository 物件，走傳輸與版本管理；可做互動情境。

相關 SAP Note：735050（SAP ERP 可用的表單總覽）、894389（Interactive Forms 限制）、852235（ERP 6.0 一般限制）。2007 版筆記還提到 mySAP ERP 2004 隨附的表單只提供給 pilot customer 使用，這在今天已不適用。
S/4HANA 現況：Adobe Forms 是 S/4HANA 的策略性表單技術；SAPscript（5-18 章）與 SmartForms（4-3 章、5-19 章）仍可執行，但新開發請一律用 Adobe Forms。ADS 有兩種來源：地端 NetWeaver AS Java 上的 ADS，或 SAP BTP 上的 SAP Forms Service by Adobe（雲端渲染，連線設定依官方設定指南與 SAP Note）。S/4HANA 的新版 Output Management 以 BRFplus 決定輸出（OPD），新式表單多採 Gateway/OData 型的資料來源（對應 XML Schema-Based 介面），並可用 Fiori「Maintain Form Templates」管理範本。本章的 ABAP Dictionary-Based 介面＋自寫列印程式仍是客製報表、客製單據最常見的做法。

3. 表單介面（Form Interface）

每張 PDF 表單都需要介面，它是 ABAP 程式與表單之間的連結：只有定義在介面裡的資料才能從程式傳進表單。開發一定從介面開始。

介面類型（Properties 頁籤決定，差別在參數數量與種類）：

類型用途說明
ABAP Dictionary-Based列印情境（新開發一律選它）預設 import 參數只有 /1BCDWB/DOCPARAMS（TYPE SFPDOCPARAMS），預設 export 參數只有 /1BCDWB/FORMOUTPUT（TYPE FPFORMOUTPUT）
Smart Forms-Compatible保留舊列印程式不改時用可加 export 參數、可用 TABLES 參數（只有要在表單 ABAP 程式裡改內表時才需要）
XML Schema-Based（NW 7.0 起）主要給 Web Dynpro 互動情境沒有 Context；S/4HANA Gateway 型表單亦屬此類

不建議用 Smart Forms 相容介面的三個理由：① 會收到錯誤的列印參數（例如封面頁），且 XSF/XDF 參數已不能用；② spool job 含多個 PDF 時只拿得回一個；③ 只有 ABAP Dictionary 介面能設定 Business Communication Services（BCS）。

參數欄位（和 SE37 定義函數參數一樣）：

  • 參數名稱；型別指定只允許 TYPE（從 SmartForms 移轉來的介面才可用 LIKE）；型別名稱可為 ABAP 型別（c、i、n…）或字典型別（資料元素、表格類型）。
  • Optional：多張表單共用一個介面時，把不是每張都需要的參數設為選用，可讓介面數量保持精簡。
  • Pass Value：傳值（複製）而非傳參照，參數可在介面程式中修改而不影響原值；但大參數（內表）會拖慢效能。
  • Default Value：非結構參數可設預設值；有預設值者自動為選用。

例外：介面宣告的例外可在表單的 ABAP 程式中用 RAISE <exception> 或 MESSAGE … RAISING <exception> 觸發，它是傳統例外（非 6.10 起的類別型例外），實際由生成的函數模組拋出，呼叫端以 sy-subrc 判斷。

對外不可見的部分：全域定義（Global Fields、Field Symbols、Global Types）、初始化程式碼（Initialization）、金額數量欄位（Currency/Quantity Fields）。

  • Global Fields：用預設值或初始化程式碼給值；可放進版面；移轉來的 SmartForms 還能在程式行節點使用。
  • Field Symbols：變數的佔位符，動態程式與加速內表處理時好用；PDF 表單中可在 ABAP 程式碼裡指派。
  • Global Types：需要 ABAP 內建型別或字典型別以外的型別時，在 Types 編輯器宣告本地型別。
  • Initialization：資料送進表單前的最後加工處。非移轉自 SmartForms 的表單，這是唯一能執行 ABAP 的地方。用到的介面欄位或全域欄位必須列在 Input／Output 參數中；Input 與 Output 的區分只是結構化用途，兩者都是傳參照，所以修改 input 參數是永久的（Col18 測驗題補充：只有設了 Pass Value 的 import 參數才能在初始化中修改）。用 DATA 宣告的區域變數出了初始化就看不到，不能用在版面。SYST 系統欄位不必宣告但不應修改。
  • Currency/Quantity Fields：ABAP 區分金額數量的內部與外部表示，例如內部 1000 可能印成 USD 10.00 或 JPY 1000（小數位資訊在 TCURX、T006）。NW ’04 時代必須為每個要列印的金額數量欄位指定參考欄位（F4 選欄位 → 選參考欄位 → 標示是金額或數量）；NW 7.0 起字典參考會自動評估，自訂參考只用於覆寫。

4. 表單 Context：拖放、內表、條件與 Alternative

SFP 輸入表單名稱 → 建立，Properties 頁籤填：描述、版面類型（只與互動情境有關：ACF Active Component Framework 需在 PC 安裝元件，見 SAP Note 766191；較新的 ZCI Zero Client Installation 只需新版 Adobe Reader，見 SAP Note 955795）、使用的介面名稱（雙擊可開啟；修改被表單使用中的介面時系統不會警告，但可能把表單弄壞）。第一次儲存自動帶入套件，之後要改用「轉到 → 物件目錄條目」（套件與傳輸見 1-1 章）。

Context 頁籤分四區：

  • Interface（左上）：所有介面欄位加系統欄位 SFPSY-DATE、SFPSY-TIME、SFPSY-USERNAME、SFPSY-SUBRC；若為 SmartForms 相容介面則顯示 SFSY-…。
  • Context（右上）：版面可用的元素，是介面的子集再加上圖片、文字等；在這裡按右鍵建立新元素。
  • 介面欄位屬性（左下）與 Context 元素的屬性／明細／條件（右下，例如圖片來源、外部文字名稱）。

使用介面的要點：

  • 從介面樹拖放到 Context 樹，或右鍵「建立 → 資料、結構和迴圈（Loop）」；SmartForms 相容介面可再用「建立 → 資料和結構」加入 sy- 系統欄位。
  • 來自結構與內表的原始欄位標記為「Generated」；可以把欄位拖進內表，讓每筆資料有自己的長文字。
  • 可在右下「屬性」改名；參照字典型別的欄位會自動帶出描述（NW ’04 SP11 起，SAP Note 808116）。
  • Context 中欄位順序無關緊要，除非是巢狀。
  • 不需要的欄位設為 Inactive（右鍵）：它就不進 XML 資料流（XFD），可提升效能。但 inactive 不會把必填參數變成選用，列印程式仍須傳值。測試時把非來自介面的 Context 欄位設 inactive 很有用。

內表的 XML 表示：Context 中的內表永遠以巢狀方式顯示，這反映它在 XSD（XML Schema Definition）中的結構。Designer 需要這份 XSD，SFP 會自動從 Context 產生，不能手改。內表與欄位之間一定有一層 DATA 代表行型別，要加欄位就加在 DATA 結構裡；要巢狀，就把第一個內表拖進第二個的 DATA 結構。

內表（Loop）節點的屬性（Col18 補充）：

  • 可限定傳入 XML 資料流的列：相當於 LOOP AT it INTO wa FROM r1 TO r2，或加 WHERE 條件 LOOP AT it INTO wa WHERE field = value。
  • WHERE 最常用於把 T2 巢狀進 T1：例如 T1 為客戶、T2 為訂位，在 T2 設 CUST_NUMBER = T1-CUST_NUMBER，結果是一張 XML 表，版面很好處理。
  • Control Level 頁籤（NW 7.0 起）：依欄位分組，讓平面內表輸出成巢狀樣子；只有資料已依該層級排序才有意義。
  • 只要某一列時，不要用整張表加 WHERE 或索引，改用右鍵「建立 → Single Record」（NW 7.0 起），指定列號或鍵值，Designer 會把它當結構處理；結果可用 SFPSY-SUBRC（SY-SUBRC 的複本）判斷。

條件（Condition）：大多數節點可設條件，執行時不成立，該元素（若是結構、內表、資料夾則連同所有子元素）就不進資料流。條件能減少資料傳輸、也能從版面隱藏欄位。條件中可用所有介面欄位（即使沒拖進 Context），但不能參照其他 Context 欄位或 ABAP 系統欄位。有條件的節點圖示旁會多一個條件符號。

Alternative（二選一）：有 TRUE、FALSE 兩個子節點，條件成立處理 TRUE 分支，否則處理 FALSE 分支，像 ABAP 的 IF／ELSE。

Alternative 的條件和一般節點的條件意義不同：它決定資料流要放 TRUE 還是 FALSE 的內容，不決定 Alternative 本身要不要處理（Alternative 的邏輯一定會處理）。
Context 條件請用「列舉」思維：例如「只有航空公司為 AA、LH、SQ 才印附加條款」就寫成多個等式，而不是字母區間。區間比的是字典序，不是業務語意，編碼規則一變就漏抓或多抓（Casper 實務經驗第 2 條）。

5. 資料夾與圖片（Folder / Graphic）

資料夾：表單越細，Context 樹越難看懂。把節點分組放進資料夾，可收合展開。典型用途：

  • 催款單依逾期天數有不同催款文字，執行時只傳其中一段：各文字設不同條件，再收進同一資料夾。
  • 多個節點共用同一條件：不必每個節點各設一次，改把條件設在資料夾上，會傳遞給所有子節點。

資料夾也讓 Designer 端的作業更簡單，並幫你組織版面。

圖片：右鍵 Context 頂層節點 → 建立 → 圖片（Graphic），在右下屬性指定圖片類型：

類型設定說明
Graphic Content（圖片內容）指定一個 Context 欄位，執行時裝圖片資料；型別 STRING（Base64 編碼）或 XSTRING（二進位），並填 MIME 類型，例如 image/bmp、image/jpeg最常用：由程式讀 MIME Repository 或 SE78 後傳入

6. 地址：Business Address Services（BAS）與非 BAS 地址

很多應用改用 BAS（6.10 以前叫 Central Address Management）取代自己的地址表，地址以地址號碼唯一識別。放進版面的地址會依國家別規則格式化（依 ISO 11180 與萬國郵政聯盟規範，細節見函數 ADDRESS_INTO_PRINTFORM 說明）。在 Context 建立地址節點，就不必懂 BAS 細節也不必煩惱格式，版面上它就是一般文字。

地址節點的欄位：

  • 地址類型：① 公司地址（交貨地址、公司代碼），只需 10 位字元的地址號碼；② 私人地址（自然人，含稱謂等屬性；一人可有多地址），需地址號碼＋人員號碼；③ 公司聯絡人（有部門、房號等），也需地址號碼＋人員號碼；④ 動態定義：指定一個介面參數，執行時填 1、2、3 對應前三種。號碼通常都是介面參數。
  • 寄件國家（Sender Country）：必填，可用介面參數動態決定；若判定為國內地址就不印國家。
  • 執行時在 BAS 找不到指定號碼的地址，生成的函數模組會發出錯誤訊息並中止。
  • 同時有郵政信箱與街道地址時，下拉選擇印哪個；選「動態定義」則指定一個欄位，執行時值為 X 印街道、空白印信箱。
  • 行優先順序（Priority of Lines）：空間不夠時先隱藏地址的哪些部分，例如 A 稱謂、P 必要空行、D 部門（詳見 ADDRESS_INTO_PRINTFORM 文件）。

不在 BAS 的地址：若應用沒用 BAS 但仍要國家別格式，必須自己用 ABAP 呼叫 ADDRESS_INTO_PRINTFORM（在列印程式或介面初始化皆可），把應用的地址欄位一一對應到輸入結構，決定 number_of_lines（最大行數），再把回傳的單欄內表轉成 TLINE 兩欄內表（TDFORMAT 段落格式、TDLINE 內容），當作動態文字放進表單。

7. 長文字：文字模組、Include Text、動態文字與 Smart Styles

Context 可放四種長文字，SFP 會自動轉成 ADS 看得懂的 XHTML（HTML4 的 XML 版本）：① BAS 地址、② 文字模組（SmartForms Text Module）、③ Include Text（SAPscript 文字）、④ 動態文字。

為什麼要把文字集中存在資料庫：只建一次、到處重用；要改只改一處，所有表單同步生效。典型例子：頁首（公司地址）、頁尾（董事、登記資訊）、整頁的交易條款。

文字模組編輯重點：

  • 「管理」頁籤必須指定樣式，預設 SYSTEM。所見即所得，段落格式與字元格式的可選清單取決於樣式；格式名稱 1～2 個字元，* 代表預設段落。
  • 行會依版面元素寬度自動換行，編輯器的標準寬度不影響輸出。Enter 開新段落（可換格式）、Shift+Enter 段內換行。
  • 超連結技術上可放，但不會出現在 PDF（6.40 亦然）；全螢幕編輯器可切到 SAPscript 行編輯器，但 SAPscript 命令執行時一律忽略，最好別用。
  • 欄位用 &…& 包起來，例如 &SFPSY-DATE&，只能用按鈕插入／編輯。可用：介面欄位、SFPSY 欄位、部分 SYST 欄位（如 sy-mandt、sy-sysid；清單處理欄位如 sy-pagno 不可用）。欄位名不分大小寫；SAPscript／SmartForms 的格式選項（偏移、非零等）在 PDF 表單中被忽略。
  • 文字中的欄位執行時若未定義，程式會中止，而且設計時無法做語法檢查（字典欄位與 SFPSY 欄位除外）。

放進 Context：右鍵「建立 → 文字」。名稱與語言若動態決定，設計時無法檢查，建議勾「即使文字不存在也不報錯」避免中止；不指定語言則用表單原始語言。樣式有三種選擇：「從文字模組複製樣式」、指定另一個樣式（樣式不能動態，不加單引號）、兩者都不選（連 SYSTEM 都不套，印成純文字）。

Include Text 的限制：SAPscript 命令全被忽略（所以不能巢狀 INCLUDE），SAPscript 樣式也被忽略；所有段落與字元格式一律以 Context 指定的 Smart Style 解讀。例如 SAPscript 裡 B 是粗體，Smart Style 裡 B 若是小字，就全部印成小字；樣式中沒定義的格式直接忽略。可用「標準段落」覆寫所有 * 段落（相當於 INCLUDE 的 PARAGRAPH 附加），「第一段」設定第一段格式（相當於 NEW-PARAGRAPH）；標準段落留空時，所有標準段落都用第一段的格式。

動態文字：指定一個行型別為 TLINE 的內表，執行時裝 ITF 格式文字（TDFORMAT 段落格式、TDLINE 內容，看起來就像行編輯器的文字）。要連續文字，只在第一行填段落格式，其餘行只填 TDLINE，每行最多 132 字元，結果都在同一段。字元格式用角括號：前文<AB>格式化文字</>後文。這張 TLINE 內表只能在動態文字節點的「欄位」中指定，不要另外做成獨立 Context 節點；樣式必須是 Smart Style。

8. Adobe LiveCycle Designer：基本操作、物件庫、測試資料

選 SFP 的「Layout」頁籤即開啟內嵌的 Designer。前置條件（教材年代）：完整安裝的 SAP GUI 6.20／6.40 以上、Adobe Reader 6.0 以上。

兩個會讓你白做工的陷阱：① 不要用新版 Designer 建的表單再拿舊版 Designer 改。② SFP 在顯示模式時 Designer 仍可編輯，你改得很開心，離開版面區就全部丟失；狀態列只會提示一次「對版面的修改不能在顯示模式下儲存！」。

工作區：中央是版面編輯器（Layout Editor）；上方可開 Script Editor（FormCalc／JavaScript）；左右是面板視窗（Palette），可經「面板 → 管理面板」開關，「復位面板位置」回到標準。工具列有選單列及四條按鈕列（標準、字型、段落、版面），拖曳時按 Ctrl 可自由擺放，「工具 → 自訂」可顯示／隱藏。

面板用途
Hierarchy（層級）以樹狀列出版面所有物件；右鍵重新命名、刪除；Ctrl 多選。名稱大小寫敏感（Field ≠ field ≠ FIELD）；同一子表單中同名元素會編號 FIELD[0]、FIELD[1]，應避免
Data View（資料檢視）顯示所有 active 的 Context 節點（Adobe 稱 data schema）。不要在這裡直接改，要改資料來源就改 Context
Library（物件庫）可拖放到頁面的所有物件，可自訂；SAP 附「Form Builder」頁籤（含預定義日期物件）
Object／Layout／Border物件屬性、尺寸位置（Expand to fit、邊距、標題位置、旋轉 90 度與錨點）、框線與背景填色（無、純色、雙色漸層）
Font／Paragraph文字欄位與靜態文字的字型段落
Info／ReportInfo 顯示 Context 輸入的資訊；Report 列出欄位與 Context 的繫結狀況，本地預覽的警告也在這
Drawing Aids（繪圖輔助）格線、尺規單位（改單位會自動換算既有數值），設定存進表單

加入物件的步驟：① 選頁面；② Context 物件從 Data View 拖，其他物件（靜態文字、圖片）從 Library 拖（右鍵「保持繪圖工具」可連續建立同型物件）；③ 在 Hierarchy 重新命名成有意義的名稱；④ 調整大小；⑤ 在 Layout／Border／Object／Font／Paragraph 設細節。「編輯 → 複製多個」可一次複製並對齊；「版面」選單提供對齊與同尺寸功能。

巢狀 vs. 連續物件：設計時精確定位的物件（Master Page 上的樣板物件、Positioned 子表單中的物件），在 Hierarchy 中調整順序不影響版面位置；執行時才決定位置的物件（Flowed 內容），Hierarchy 順序就是輸出順序，例如兩個 Master Page 預設排上面的先處理、交換表格儲存格順序就會交換輸出位置。

重用與共享物件庫：把物件右鍵「新增到物件庫」或直接拖進 Library 頁籤；可把多個物件存成一個庫物件；可「新增群組」；「恢復標準物件」可還原。物件庫可發佈到伺服器，每個物件存成獨立 XML 檔（副檔名 XFO），預設依登入語言分目錄；「共享物件庫位置」可指定一份 XML 清單：

9. 表單結構：Master Page、Content Area、Body Page 與 Subform

「頁」這個詞聽起來簡單，但 Designer 的頁面觀念要分清楚：

元素角色SmartForms／SAPscript 粗略對應
Master Page（主頁面）至少一個，自動建立。放在上面的物件出現在所有輸出頁，這種永遠不變的物件稱為樣板物件（boilerplate），例如 Logo次視窗（Secondary Window）
Content Area（內容區）主頁面上至少一個，定義動態輸出可用的空間；只能放在主頁面上主視窗（MAIN Window）的組合
Body Page（頁體，新版 Design View 的 Page）頂層子表單，是動態內容的容器，使用內容區的空間；空間不夠時找下一個內容區（可能自動換頁），所以一個頁體可以印成很多頁
Subform（子表單）把多個物件包成一組，可收合；分 Positioned（物件固定在子表單內的相對位置，Hierarchy 順序無關）與 Flowed（依執行時占用空間一個接一個排，頁體就是典型）範本（Template）／迴圈

設計順序建議先做靜態的主頁面，再做頁體。

多個主頁面（在 Object 面板設定，記得先切到 Master Pages 頁籤，只在 Hierarchy 雙擊節點不夠）：頁面尺寸（信封、A4）、方向（Portrait 直式／Landscape 橫式）、出現次數上限。例如第一個主頁面（有地址、Logo）限 1 次，資料多到一頁放不下時，Hierarchy 中第二個主頁面自動成為後續頁；若限了次數卻沒有其他主頁面，執行時該限制會被忽略。

頁體的位置（Place）：要開新頁就設「Top of Next Page」或「Top of Page <主頁面>」；第一個頁體的「Following Previous」其實就是從 Hierarchy 第一個主頁面開始。設「On Page <主頁面>」時：前一個子表單已在那個主頁面，就同頁接著印（空間夠的話）；前一個在別的主頁面，就換頁並用指定主頁面開新頁。

範例：插入「交易條款」頁：另建主頁面 TERMS，再建新頁體，Place 設「Top of Page TERMS」。也可以讓前一個子表單設「之後 → 到 TERMS 頁」，但每個強制換頁都做一個新頁體，Hierarchy 會好讀很多。

防止換頁：① 選物件；② Hierarchy 右鍵「Wrap in Subform」；③ Object 面板 Subform 頁籤取消「Allow Page Breaks within Content」。主頁面上、或 Positioned 子表單內的子表單不可用。兩個子表單之間不換頁：設「Keep with Previous」／「Keep with Next」。

教材的可讀性建議：① 雖然可以完全不用頁體、所有東西都放主頁面，強烈不建議；② 子表單 B 要在另一個主頁面時，不要把它巢狀在子表單 A 裡；③ 不要在子表單的「After」設「Go to next page」，要換頁就新建頁體；④ 頁體設 Keep with Previous/Next 沒有意義，只用於一般子表單；⑤ 巢狀子表單會降低處理效能。

10. 靜態元素、動態欄位與資料繫結（Data Binding）

靜態圖片（通常放主頁面當樣板物件）：必須用有效 URL 指定位置（檔案伺服器、內網或網際網路；NW ’04 無法存取 MIME Repository）。

  • 用資料夾圖示瀏覽時要填完整路徑：C:\image.gif 在 Designer 預覽可以用，實際執行時 C:\ 指的是 ADS 所在伺服器的磁碟，而且路徑必須公開可存取。
  • 網址必須加 http:// 或 https://，且 ADS 要連得到。
  • 勾「嵌入圖片（Embed Image Data）」可避免執行時路徑錯誤。注意：嵌入後 URL 仍必須保留當作原始位置參考；嵌入後修改 URL，圖片會重新上傳。
  • 尺寸三選一：Use Image Size（原尺寸，不能拉把手）、Scale Image Proportionally（等比縮放）、Scale Image to Fit（自訂尺寸，不保比例）。

靜態文字：所見即所得，自動斷字；Enter 新段落、Shift+Enter 換行（同段同格式）。框太小時右下角出現紅色小加號。先選取文字再到 Font 面板改字型、粗斜體、底線、顏色；Paragraph 面板設水平對齊（左、右、置中、左右對齊）、垂直對齊、縮排與間距。

字型陷阱：Designer 預覽用的是你電腦上的字型，執行時用的是 ADS 伺服器上的字型，兩者可能完全不同。只用 ADS 伺服器上有安裝的字型；最保險的是 Times New Roman、Arial、Courier（强晟補充：中文用宋體、黑體）。每份文件用的字型越少越好（效能）。

幾何物件：線（任意角度，Object 面板有水平／垂直／45 度按鈕）、矩形（框線、圓角、背景色）、圓（可只畫弧）。通常放主頁面。

動態欄位的兩種放法：① 從 Data View 拖到版面（最佳，自動建立型別正確的欄位與資料繫結）；② 從 Library 拖文字欄位再手動繫結。已放進版面的 Context 元素在 Data View 名稱右側有特殊符號；同一欄位可放多次，此時面板中部分屬性會顯示「混合」。Data View 右鍵「顯示資訊」可看字典描述或外部文字的類型與鍵值。

文字欄位（Text Field）可對應簡單字串、文字模組、SAPscript 文字、動態文字或 BAS 地址，Designer 一視同仁：

  • Layout：長度未知就勾 Expand to fit（只有一行就只允許水平延伸）；輸入的寬度只是粗估。
  • Caption（標題）：描述動態內容的靜態文字，與給視障者的 Tooltip 不同；設定位置（上下左右）與保留空間；Font／Paragraph 面板的小三角可選「編輯標題」「編輯值」，預設兩者一起。
  • Object → Field：Appearance 只對互動表單有意義；Allow Multiple Lines 只在 Binding 未選 XHTML 時相關，不勾時普通文字超過一行會被截掉；Limit Length 對應字典長度，相當於 SAPscript 的 &symbol(8)&。
  • Object → Value：Type 只與互動有關；Default 值在沒有繫結或繫結失效時使用（空欄位仍保持空）。
  • Object → Binding → Data Format：要保留格式、換行、字型就選 XHTML。從 Data View 拖來的格式化文字（地址、SmartForms 文字、SAPscript 文字、動態文字）會自動勾選；選了 XHTML 後 Font 與 Paragraph 面板的設定都被忽略。文字沒有格式就不要選 XHTML，看起來一樣但效能很差。
筆記勘誤：强晟筆記此段寫「如果從數據視圖拖一個對應上下文中 ABAP 欄位的文本欄位，這個選項會自動被選中」，與下一句「沒有格式就不應選 XHTML」矛盾。依原意應為：一般 ABAP 欄位（Plain Text）不會自動選 XHTML，只有格式化文字才會。

資料繫結規則：

  • 所有動態欄位都必須有繫結，它連結版面物件與 Context（Data Connection）；繫結大小寫敏感。
  • 絕對名稱以 $record 開頭（代表一批資料的目前記錄，例如這一位客戶）；相對名稱只對同一子表單內的元素有效。
  • 繫結設 Normal 時，物件名稱必須等於 Data View 欄位名，所以改名會斷掉繫結；同一 Context 元素要在版面放多次，繫結要設 Global；繫結錯誤或設 None 會得到錯誤或空資料。
  • 必須手動設定繫結的情況：從 Library 拖入、複製貼上既有元素（繫結不會跟著複製）、元素移到別的子表單或拆掉子表單。最簡單的補救：點繫結欄右邊小三角從 Context 選，或把 Data View 的元素拖到該欄位上，順便更新名稱、標題、型別。

檢查繫結：Report 面板的 Binding 頁籤列出一般繫結欄位、參照繫結欄位（含相對或絕對路徑）、無繫結欄位（值由腳本決定時才該這樣），以及「未繫結的資料節點」（Context 有、版面沒用）。繫結失敗的欄位名左側會出現警示燈。未繫結節點太多，表示 Context 甚至介面該瘦身了。

其他動態欄位：

  • Image Field：對應 Context 的 Graphic Content 或 Graphic Reference；可 Expand to fit。URL 或嵌入設定會被忽略，除非繫結設 None（那還不如直接用靜態圖片）。
  • Numeric Field：Decimal、Float、Integer（Binding 頁籤設定）。金額與小數在 SAP 有特殊處理，一律從 Data View 拖，會自動帶正確型別與小數位所需的腳本。
  • Date/Time Field：Date、Time、Date and Time 三種。ABAP 型別 d/t（字典 DATS/TIMS）會自動轉成正確輸入格式；ABAP 與字典都沒有「日期加時間」的單一型別。
  • Floating Field（浮動欄位）：嵌在靜態文字裡的欄位，例如用客戶真名取代「親愛的先生／女士」。游標放在靜態文字中 →「插入 → Floating Field」→ 選取該欄位到 Binding 頁籤指定繫結（用小三角選最安全）→ 右鍵重新命名。預設是文字欄位，可在 Field 頁籤改型別；Presence 自動顯示為 Hidden 不必擔心。頁碼也用浮動欄位：「插入 → 目前頁碼」或「總頁數」，會自動帶腳本。

輸出格式化的途徑：顯示樣式（日期格式、去前導零…）、Field 頁籤的 Limit Length、ABAP 程式（偏移、壓縮空白）。字元欄位沒有像 SAPscript／SmartForms 那樣的輸出選項（如偏移），要在列印程式或介面初始化中先處理好。

11. 顯示樣式（Display Pattern）與地區設定

顯示樣式（部分文件稱 picture clause）以規則描述日期、時間、數字、文字在文件中的呈現。例如 ABAP 內部 YYYYMMDD 的今天可以印成「2007-12-16」「Sonntag, den 16. Dezember 2007」或「Sunday, December 16, 2007」。

  • 樣式是選用的，只在必要時用；不用就依 locale 的標準格式。在 Object → Field 頁籤設定，下拉有常用樣式，也可自由輸入，輸入後按 Enter 讓 Designer 檢查語法。
  • Field 頁籤的 Edit Pattern、Value 頁籤的 Validation Pattern 只給互動表單；Binding 頁籤的 Data Pattern 定義資料如何被讀入，Context 來的日期時間會自動正確解析，不要手動設。
  • 樣式由符號（依欄位型別，例如 MMMM＝完整月份名，執行時依 locale 變成 January／Januar／Janvier）、單引號包起來的字面文字（例如 '請於下列日期前付款' MM-DD-YY），以及可直接使用的逗號、減號、冒號、斜線、句點、空白組成。
  • 樣式不會自動翻譯，而且大小寫敏感；長樣式要確保欄位夠寬，啟用後用測試程式確認。
  • 多選一樣式語法：category{pattern}|category{pattern}，數量不限，執行時採用符合資料的那一個（例如各地車牌格式不同）。

12. 表格：動態表格、表頭、條件分頁、控制層級與巢狀表格

發票、訂單確認沒有表格很難想像。資料在 ABAP 收進內表傳給生成的函數模組，逐列處理由 ADS 完成。表格其實是巢狀子表單：至少一個表格子表單加一個列子表單，儲存格是一般版面元素。列子表單能在執行時重複的叫動態表格（往下長），列數設計時固定的叫靜態表格。

建立動態表格（Designer 7.1 以上）：Data View 面板選單 → Options → 勾「Allow Tables To Be Generated」，再把內表從 Data View 拖到頁面；沒勾的話產生的是巢狀 Flowed／Positioned 子表單。除非要做多行列或橫向延伸的表格，一般都產生動態表格。放進頁面時，除非確定不超過一頁，放在 Flowed 子表單中才能分頁。拖曳格線調欄寬列高；用 Table 工具列或 Table 選單增刪儲存格，例如「Table → Insert → Row Above」加表頭列。

減少傳給 ADS 的資料：與其在版面刪欄位，不如縮小介面的行型別，或在 Context 把多餘欄位設 inactive。

條件分頁（Conditional Break）：在 DATA 列的 Object → Pagination 頁籤按加號新增條件，每個條件可選 FormCalc 或 JavaScript，任何結果為真／假的邏輯式都行。最常見是比較這一列與前一列的某個儲存格，例如航空公司不同就插入空白分隔列或新表頭；Designer 會為表格欄位產生建議程式碼供修改。可跳到的位置與一般子表單相同，也可以不換頁只插入額外表頭（把它設為 Leader）。

條件分頁與控制層級的前提是「資料已排序」（教材 Hint 原話：依列比較的條件分頁通常只在表格事先排序過才有意義）。在 S/4HANA 上，HANA 沒有預設排序，SELECT 不加 ORDER BY 或不 SORT，同一張單據今天印出三段 AA、明天印出 AA／LH／AA 交錯是正常現象。Casper 在成本評價案上就是這樣踩坑（item category H 與 cost component E 兩種資料交替被抓到，成本結果不穩定，最後固定抓 H）。凡是「分組」「取第一筆」「跟上一列比」，一律在 ABAP 先明確排序。

// 實務請以 Designer 自動產生的建議程式碼為底再修改
this.index > 0 &&
  this.CARRID.rawValue !=
  this.parent.resolveNode("DATA[" + (this.index - 1) + "]").CARRID.rawValue

表頭注意：條件分頁設的表頭，在「資料放不下而自然換頁」時不會出現，除非你明確指定；反之，表頭若在 Pagination 頁籤勾了「Include Header Row in Subsequent Pages」，只在一般換頁出現，條件分頁時不出現。所以一張表可以有好幾個表頭，分別服務一般換頁與資料驅動的分頁。

控制層級（Control Level）：同一排序欄位值相同的一群記錄。最簡單的做法是在 Context 內表的 Control Levels 頁籤設定（每層可選升冪／降冪），再把表格從 Data View 拖到版面，看起來就像巢狀表格。資料可以自己排序（在列印程式或表單初始化），並在 Properties 頁籤勾 Already sorted；或取消勾選讓系統在渲染前自動排序，但只有全域介面欄位或 call-by-value 的 import 參數才行（call-by-reference import 參數是唯讀的）。

巢狀表格：例如每條航線（ID、NO.、Departure、Destination）下列出所有航班日期。兩種做法：① 介面本身就是巢狀（巢狀字典型別或本地型別），直接從 Data View 拖；② 在 Context 把一張內表巢狀進另一張，並在內層表設 WHERE 條件說明兩表如何結合（Col18 測驗題：巢狀時必須指定的是 WHERE）。

13. 表單腳本：FormCalc 與 JavaScript

PDF 表單列印時，資料在 ABAP（Web AS ABAP）收集 → 傳給 J2EE 上的 ADS → 與版面和邏輯合併 → PDF 回傳 ABAP。渲染期間無法與 ABAP 溝通，所以表單本身不能寫 ABAP，只能對動態元素寫 FormCalc 或 JavaScript。

  • 可加腳本的是所有非靜態物件（數值、文字、日期、圖片欄位、子表單…）；內容區、靜態文字、靜態圖片、線／圓／矩形沒有事件。但腳本可以存取表單中所有物件，包括靜態物件。
  • 選物件後在 Script Editor 輸入，選事件、選語言（每個事件可不同）。列印表單：簡單工作用 FormCalc、複雜工作用 JavaScript；互動（Web）表單用 JavaScript。
  • 腳本可在 Client 或 Server 執行，列印表單沒有使用者互動，應在 Server 端執行。預設語言與執行位置請在表單屬性設好。
  • 放大 Script Editor 才看得到「Show Events with Scripts」；配合在 Hierarchy 全選，可一次看全表單的腳本。打句點會跳出成員提示（可在 Tools → Options → Workspace 關閉）。

事件與處理順序：

事件時機典型用途
initialize物件初始化，資料流合併之後動態決定欄位值、套預定義樣式
calculate合併後、顯示前；計算相依值改變時會重算查看並改寫欄位值（覆蓋原繫結結果）；絕對避免自我參照

FormCalc 語法基礎：分號 ; 或 // 開始註解到行尾；命令可跨行；約 37 個關鍵字（if、do、or…）不分大小寫；運算子 + - * /，比較 == <> < > <= >= 或 eq ne lt gt le ge。ABAP 程式設計師注意：= 是指派，== 才是相等。變數大小寫敏感。

存取 Context 欄位（accessor）：前綴 $record.，照 Data View 的名稱以句點串接，ABAP 的原始寫法（連字號）在這裡無效。內表與欄位之間一定有一層 DATA；不指定第幾筆就取第一筆（更一般的規則：同層同名物件，模糊參照一律指第一個）；指定第幾筆用 $record.IT_SUMS.DATA[4].CURRENCY，索引從 0 起算（不像 sy-tabix 從 1）；目前列用不帶索引的 DATA；全部列用 DATA[*]。版面上沒用到的 Context 欄位也能存取。沒有繫結的欄位、或要改物件屬性時，改用 Hierarchy 中的名稱。

存取物件：$ 代表目前物件；同層、外層子表單所在層、直接子物件（腳本掛在子表單時）可直接寫名稱；測試方法是在 Script Editor 打名稱加句點，有提示就能直接存取。沿子表單往下可用兩個句點省略中間層，例如從 SUB1 用 $..PHONE。完整名稱從主頁面或頁面名稱開始（無名子表單略過）：在 Hierarchy 選物件、開任一事件，第一行註解就是 data.Masters.FIRST.SUB1.SUB2.NAME::ready:layout，雙冒號前就是完整名稱。為了效能，路徑寫最短即可。隱藏子表單等於隱藏其全部內容。

函數：按 Script Editor 工具列綠色 fn 看清單（邏輯、字串、算術）。函數名不分大小寫，參數（變數）大小寫敏感。

  • HasValue(v)：欄位有值回傳 1、沒值回傳 0。
  • Exists(v)：參照有效回傳 1，可用來檢查重複子表單的某索引是否存在，例如 if (Exists(TABLE.DATA[0].FIELD) == 0) then … endif。
  • Substr(s, start, count)：從第 start 個字元（第一個字元為 1）起取最多 count 個字元。
筆記勘誤：强晟筆記寫「HasValue 在字段有值時返回 0，沒有值就返回 1」，正好相反，Col18 與 Adobe 文件皆為有值回傳 1（true）。又寫「Substr(s, n1, n2) 返回從第 n1 到第 n2 個字元」，第三個參數其實是長度不是結束位置。

找腳本錯誤：跑 Designer 預覽，結果在 Report 面板的 Warnings 頁籤（依版本會覆蓋或累加，累加時用「Clear Warnings」清掉）。同一事件中語法錯誤之後的命令全被忽略，之前的正確命令照常執行。

SAP 語法檢查（Ctrl+F2）與表單啟用（Ctrl+F3）都不檢查版面與腳本，只保證介面與 Context 正確。用本地 XML 測試資料預覽只適合快速看樣子，Server 端腳本可能得到錯誤結果，一定要用 ABAP 程式實測。更持久的方法是 Trace：SFP「公用程式 → 設定」指定是否產生 Trace 檔、深度與存放目錄；Level 1（Short Trace）足以追腳本錯誤，「Very detailed」會附上 ADS 渲染細節並把 Trace 附在 PDF 裡；需要除錯權限；背景處理不能下載，要用 Very detailed 讓 Trace 附在 spool 文件上。

效能：能不寫腳本就不寫。替代方案依序為：列印程式或介面初始化的 ABAP、靜態屬性取代動態屬性、能用動態屬性就不用腳本、短（相對）名稱取代長路徑、用子表單隱藏元素。典型例子：不要在表單裡加總明細，在 ABAP 算好，介面除了明細內表再多一個合計參數。

不寫程式就讓空值欄位整組隱藏：① Hierarchy 選取元素 → 右鍵 Wrap in Subform；② 子表單的繫結設為那個可能有值或沒值的欄位；③ Binding 頁籤勾 Repeat Subform for Each Data Item，但不要勾 Min Count 與 Max。

14. 整合進 ABAP：列印程式的標準結構

表單本身不能執行，只能用測試資料預覽，一定要有 ABAP 程式處理。從表單列印的角度，列印程式由下列部分組成：

  1. 從資料庫取業務資料：最重的部分。額外計算也在這裡做，讓表單內的計算越少越好（Enterprise Services Architecture 的精神：不要把多餘資料傳給表單、也不在表單內再取資料）。想知道表單實際用了哪些欄位，可呼叫 FP_FIELD_LIST，回傳單欄內表列出欄位名（結構會展開成個別欄位）。
  2. 取得生成的函數模組名稱：名稱因表單與系統而異（形如 /1BCDWB/SM000000xx），必須呼叫 FP_FUNCTION_MODULE_NAME 傳入表單名，由 E_FUNCNAME 取得；E_INTERFACE_TYPE 為 S 表示 SmartForms 相容介面，空白表示新介面。它用類別型例外，不能查 sy-subrc，要用 TRY…CATCH。
  3. 開啟列印：新介面必須明確呼叫 FP_JOB_OPEN（唯一參數 IE_OUTPUTPARAMS TYPE SFPOUTPUTPARAMS）。
  4. 呼叫生成的函數模組：在 OPEN 與 CLOSE 之間可呼叫任意次，產生多份 PDF，成為同一 spool request 的不同部分，SP01 可分別列印。SmartForms 與 PDF 表單不能混在同一個 job。
  5. 結束列印：FP_JOB_CLOSE 回傳是否成功與 spool ID。熟 SAPscript 的人可把 FP_JOB_OPEN／CLOSE 想成 OPEN_FORM／CLOSE_FORM。
SmartForms 相容（舊）介面的表單絕對不能呼叫 FP_JOB_OPEN／FP_JOB_CLOSE，否則程式中止；舊介面的生成函數模組會隱含地自己開關。

SFPOUTPUTPARAMS 常用欄位：

欄位作用
NODIALOGX＝不顯示印表機對話框
PREVIEWX＝預覽
NOPRINT不做後端列印，但仍可從 Adobe Reader 預覽中列印
NOPDFX＝只產生列印檔 PDL（Printer Definition Language）不產生 PDF，較快，但 SP01 無法檢視。預設兩者都產生；PDL 用於 PostScript、PCL、Zebra
GETPDF／GETPDLX＝把 PDF／PDL 以 XSTRING 放在 /1BCDWB/FORMOUTPUT-PDF／-PDL 回傳；GETPDF = X 時無法預覽
DEST、COPIES輸出裝置、份數
REQNEWX＝開新的 spool request；不設（預設）則嘗試併入既有 request（SAP Note 85318）
REQFINALX＝關閉 spool request，之後其他文件不能再用
CONNECTION指定 ADS 的 RFC 目的地（HTTP/HTTPS），不填用標準 ADS 連線
XFP輸出 XML 格式的表單資料（不含版面）供外部系統處理，對應 SmartForms 的 XSF、SAPscript 的 RDI
XDCNAME執行時改用另一個 XDC 印表機描述檔（字型替代等）

生成函數模組的標準參數：唯一的（選用）標準 import 參數 /1BCDWB/DOCPARAMS（SFPDOCPARAMS）：LANGU 處理語言（無此語言用登入語言，再無用表單原始語言）、REPLANGU1～3 最多三個替代語言、COUNTRY 決定小數點與日期時間格式（語言＋國家＝locale）、FILLABLE（X＝可互動並授與 Reader 權限，可填寫並連資料存檔；N＝可填但不能連同資料存檔）、DARATAB 歸檔索引表。唯一的（選用）標準 export 參數 /1BCDWB/FORMOUTPUT（FPFORMOUTPUT）：PDF、PDL、PAGES（列印頁數）。其餘參數都是你在介面定義的業務資料，所以生成的函數模組永遠動態呼叫。

*&-------------------------------------------------------------*
*& ZBC480_PRINT_INVOICE：航班訂位發票（ABAP Dictionary-Based 介面）
*&   表單 ZBC480_INVOICE / 介面 ZBC480_IF_INVOICE
*&   介面 import：IS_CUSTOMER TYPE scustom, IT_BOOKINGS TYPE zbc480_t_booking
*&-------------------------------------------------------------*
REPORT zbc480_print_invoice.

DATA gv_custid TYPE s_customer.
SELECT-OPTIONS s_cust FOR gv_custid NO INTERVALS OBLIGATORY.  "列舉客戶，不給區間
PARAMETERS: p_form TYPE fpname    DEFAULT 'ZBC480_INVOICE',
            p_dest TYPE rspopname DEFAULT 'LP01',
            p_prev AS CHECKBOX    DEFAULT abap_true.

START-OF-SELECTION.
  " ① 取業務資料：明列欄位、@ 主機變數、明確排序（HANA 無預設排序）
  DATA lt_customers TYPE STANDARD TABLE OF scustom WITH EMPTY KEY.
  SELECT id, name, form, street, postcode, city, country, langu, email
    FROM scustom
    WHERE id IN @s_cust
    ORDER BY id
    INTO CORRESPONDING FIELDS OF TABLE @lt_customers.
  IF lt_customers IS INITIAL.
    MESSAGE '查無客戶資料' TYPE 'S' DISPLAY LIKE 'E'.
    RETURN.
  ENDIF.

  DATA lt_bookings TYPE zbc480_t_booking.
  SELECT customid, carrid, connid, fldate, bookid, forcuram, forcurkey, order_date
    FROM sbook
    WHERE customid IN @s_cust
      AND cancelled = @abap_false
    ORDER BY customid, carrid, connid, fldate, bookid
    INTO CORRESPONDING FIELDS OF TABLE @lt_bookings.

  " ② 取生成的函數模組名稱（類別型例外）
  DATA lv_fm_name TYPE rs38l_fnam.
  TRY.
      CALL FUNCTION 'FP_FUNCTION_MODULE_NAME'
        EXPORTING
          i_name     = p_form
        IMPORTING
          e_funcname = lv_fm_name.
    CATCH cx_fp_api INTO DATA(lx_fp).
      MESSAGE lx_fp->get_text( ) TYPE 'S' DISPLAY LIKE 'E'.
      RETURN.
  ENDTRY.

  " ③ 開啟列印工作
  DATA(ls_outparams) = VALUE sfpoutputparams(
    dest     = p_dest
    nodialog = abap_true
    preview  = p_prev
    reqnew   = abap_true ).
  CALL FUNCTION 'FP_JOB_OPEN'
    CHANGING
      ie_outputparams = ls_outparams
    EXCEPTIONS
      cancel          = 1
      usage_error     = 2
      system_error    = 3
      internal_error  = 4
      OTHERS          = 5.
  IF sy-subrc <> 0.
    MESSAGE |FP_JOB_OPEN 失敗（{ sy-subrc }）| TYPE 'S' DISPLAY LIKE 'E'.
    RETURN.
  ENDIF.

  " ④ 每位客戶呼叫一次生成的函數模組 → 同一 spool request 的多個部分
  DATA ls_formout TYPE fpformoutput.
  LOOP AT lt_customers INTO DATA(ls_cust).
    DATA(ls_docparams) = VALUE sfpdocparams( langu   = ls_cust-langu
                                             country = ls_cust-country ).
    DATA(lt_cust_book) = VALUE zbc480_t_booking(
      FOR b IN lt_bookings WHERE ( customid = ls_cust-id ) ( b ) ).

    CALL FUNCTION lv_fm_name                      "永遠動態呼叫
      EXPORTING
        /1bcdwb/docparams  = ls_docparams
        is_customer        = ls_cust
        it_bookings        = lt_cust_book
      IMPORTING
        /1bcdwb/formoutput = ls_formout
      EXCEPTIONS
        usage_error        = 1
        system_error       = 2
        internal_error     = 3
        OTHERS             = 4.
    IF sy-subrc <> 0.
      DATA lv_ads_err TYPE string.
      CALL FUNCTION 'FP_GET_LAST_ADS_ERRSTR'      "取 ADS 端的錯誤字串
        IMPORTING e_adserrstr = lv_ads_err.
      MESSAGE |客戶 { ls_cust-id } 輸出失敗：{ lv_ads_err }| TYPE 'I'.
    ENDIF.
  ENDLOOP.

  " ⑤ 結束列印工作，取回 spool 號碼
  DATA ls_result TYPE sfpjoboutput.
  CALL FUNCTION 'FP_JOB_CLOSE'
    IMPORTING
      e_result       = ls_result
    EXCEPTIONS
      usage_error    = 1
      system_error   = 2
      internal_error = 3
      OTHERS         = 4.
  IF sy-subrc = 0.
    LOOP AT ls_result-spoolids INTO DATA(lv_spool).
      MESSAGE |已產生 Spool { lv_spool }（SP01 查看）| TYPE 'S'.
    ENDLOOP.
  ENDIF.
選擇畫面用 NO INTERVALS 逼使用者列舉客戶號碼，是 Casper 實務經驗第 2 條的體現：客戶號碼有 ALPHA 前導零、號碼段又常不連續，用 BT 區間印單據很容易多印或漏印。其他選擇畫面技巧見 3-1 章、內嵌宣告與 FOR／REDUCE 見 2-2 章。

Additional Print Options（NW 7.31 起）：選輸出裝置後按 Enter，出現「Additional print options」按鈕，可選整份 PDF 的附加選項（僅 PCL／POSTSCRIPT 型裝置；SAP Note 1806471）。沒有列印對話框（背景、更新作業）時改用 Print Ticket，把 ticket 名稱傳給 SFPOUTPUTPARAMS 的 Print Ticket 欄位。前提：ADS 7.31 SP7 或 7.40 SP2、Basis 7.31 SP07 或 7.40 SP02（SAP Note 1729666）。

表單翻譯（SE63）：① 啟用表單；② 進 SE63；③ 選單「Translation – ABAP Objects → Other Texts」；④ 選 PDF-Based Forms → PDFB；⑤ 物件名稱填大寫表單名，來源／目標語言要含 locale 共四碼（例如 enUS），用 F4 選最保險；⑥ 下方視窗「Edit → Copy Source Text」把來源文字流複製過來（依版本可能只有選單沒有圖示）；⑦ 翻譯藍色標示的字並存檔；⑧ 執行時用 SFPDOCPARAMS 的 LANGU 選語言、COUNTRY 決定 locale。

列印預覽：SP01 與 SFP 的預覽用 Adobe Reader 顯示；同一 spool request 的多份 PDF 保持為獨立部分，可用箭頭到首／上／下／末部分。SAP GUI 預覽其實是 HTML 控制項內嵌瀏覽器，Reader 沒開「在瀏覽器中顯示 PDF」時預覽會空白、另外跳出 Reader 視窗。

15. 例外處理、取回 PDF 另行處理、沿用 SmartForms 程式

類別型例外（6.10 引入，詳見 5-2 章 ABAP Objects）：可能拋例外的程式碼包在 TRY … ENDTRY；拋出後跳到第一個合適的 CATCH，目前區塊與外層都找不到就短傾印（dump）；沒拋就不執行任何 CATCH。CATCH 類別 INTO 參照變數 可取得例外物件，所有例外類別都有 GET_TEXT。多個 CATCH 要子類別在前、父類別在後；根類別是 CX_ROOT（Col18 測驗題）。

呼叫全域方法或函數前，要先看它用舊（sy-subrc）還是新（類別型）例外。FP_FUNCTION_MODULE_NAME 可能拋 CX_FP_API_REPOSITORY、CX_FP_API_USAGE、CX_FP_API_INTERNAL，繼承鏈為 CX_ROOT → CX_STATIC_CHECK → CX_FP_EXCEPTION → CX_FP_API；不需分辨時抓任一父類別即可。所有 PDF 表單處理專屬的例外都是 CX_FP_EXCEPTION 的子類別。

*&-------------------------------------------------------------*
*& 例外順序：子類別在前、父類別在後
*&-------------------------------------------------------------*
TRY.
    CALL FUNCTION 'FP_FUNCTION_MODULE_NAME'
      EXPORTING i_name     = p_form
      IMPORTING e_funcname = lv_fm_name.
  CATCH cx_fp_api_repository INTO DATA(lx_repo).  "表單不存在或未啟用
    MESSAGE |表單 { p_form } 不存在或未啟用：{ lx_repo->get_text( ) }| TYPE 'E'.
  CATCH cx_fp_api_usage INTO DATA(lx_usage).      "呼叫方式錯誤
    MESSAGE lx_usage->get_text( ) TYPE 'E'.
  CATCH cx_fp_exception INTO DATA(lx_fp).         "其他 PDF 表單例外（含 INTERNAL）
    MESSAGE lx_fp->get_text( ) TYPE 'E'.

16. 下載上傳、PDF 匯入與無障礙表單

下載／上傳表單物件：表單是 ABAP Repository 物件，可像報表、TCODE 一樣傳輸；但傳輸太慢或沒有匯入權限時，可用 SFP「公用程式 → 下載表單物件／上傳表單物件」。

  • 下載的是目前版本（含所有語言），不必先儲存或啟用。
  • 2007 版筆記說「下載表單要記得也下載它使用的介面」；Col18 改為「下載表單時會一併下載使用的介面」（Unit 8 測驗題答案為 True）。以新版為準，但上傳到另一系統前仍建議確認介面已存在。
  • 只下載 Context 一部分：選節點（不能多選）→「公用程式 → 下載子樹」。
  • 下載 PDF：① Layout 頁籤 → 版面編輯器的 Preview PDF 頁籤（沒合併資料，除非表單屬性指定了 XML 測試資料）→ Ctrl+Shift+S；② 從 spool 預覽（「表單 → 測試」或跑列印程式）→ Ctrl+Shift+S 或「檔案 → 另存副本」。
  • 從 Designer 手動複製 XML 原始碼不會帶 Context，會得到殘缺表單。

匯入 PDF：因為 PDF（頁面描述）與 XFA（表單物件的宣告式組合）本質不同，不可能一對一轉換，它只是加速把現有 PDF 表單（例如傳真單、稅務表單）轉成 ADS 可用 XFA 範本的輔助工具，事後調整可能要花好幾小時。多數文字、表單欄位、多數圖片、線與矩形可轉；限制：內嵌字型無法轉入 XFT、PDF 內的 JavaScript 變成 XFT 裡的註解需重做、多數 Acrobat 內建表單動作不轉、向量圖與部分點陣圖不支援。步驟：SFP → Layout 頁籤 →「工具 → 匯入」→ 檔案類型選 Adobe PDF Files (*.pdf) → 開啟。選項用預設最好：

  • Conversion Type：永遠選 Optimize for editing。
  • Join Text：Paragraph（最好維護，相近文字併成會自動換行的文字塊）／Text Block（不換行）／Line by line（每行一塊）／Single Words、Single Characters（最像原稿但極難維護，不建議）；容差一般用 High，特殊情況調低避免不該合併的文字被併起來。
  • Page Range 只選需要的頁；Image conversion 勾選以內嵌圖片；Summary report 勾選以找出未知字型、編碼問題；Trace information 一律設 none（專家才看得懂，又大幅增加 XFT 大小）。
  • 也能匯入 Microsoft Word 與 RTF 文件。

無障礙（Accessibility）：目標族群與做法：

障礙問題解法
行動不便無法使用滑鼠在 Adobe Reader 用 Tab 移動欄位（只與互動表單有關）

前兩類自動滿足，全盲族群需要表單作者依原則設計：建立邏輯結構（標題頁、標題、章節、多欄文字、表格），把相關單元（地址、單據資訊）用子表單組起來。ADS 渲染時產生閱讀順序，預設每頁「子表單由上而下、由左而右，子表單內也由上而下、由左而右」。

閱讀順序範例：Field1（X=13cm, Y=0.7cm）、Field2（X=18cm, Y=0.65cm）、StaticText1（X=13.2cm, Y=1.55cm），螢幕閱讀器會讀「E A Payment」（强晟筆記譯為「高 前 低後」）。三個問題：① Field2 的 Y 比較高所以先被讀 → 把 Field2 的 Y 對齊 Field1；② 說明文字在欄位下方所以晚讀 → 把 Payment 設成 Field1 的 Caption（位置 Bottom）；③ E 是什麼意思 → 不想顯示標題就寫在 Tooltip 或自訂螢幕閱讀文字。又如「名／姓／暱稱」與「街道／郵遞區號／城市」兩欄並排，直接放在頁面上會讀成「名、街道、姓、郵遞區號…」，用子表單包成兩組就能改正順序而不必移動版面。

  • 替代文字：Accessibility 面板可設圖片與條碼的替代文字、自訂螢幕閱讀文字（MSAA 相容閱讀器優先讀它，而非 Tooltip、Caption 或技術名稱），可逐物件改搜尋順序或關閉。
  • 浮動欄位與代表文字節點、地址節點的欄位，Screen Reader Precedence 要設 None，否則會把技術名稱也念出來。
  • 要讓閱讀器認得是表格，必須用 XFA 表格（子表單 Flowed、方向 Table／Table Row），不要用一般子表單階層（Flowed／Western Text）拼的「假表格」。表格導覽靠閱讀器廠商與 Adobe 合作（2007 版舉 Reader 6.0.2 + JAWS 5.0，Col18 舉 Reader 7.0 + JAWS 7.0）。
  • Tab 順序：預設從左上開始由左而右、由上而下，會尊重子表單、選項按鈕、內容區（並排的兩個子表單會先走完第一個）；主頁面與主子表單依垂直位置決定先後。要改：「檢視 → Tab Order」依序點選物件。

17. 客製化與管理：催款單、字型、ADS 連線

先標準、再客製（Casper 實務經驗第 3 條）：SAP 已經為很多業務提供標準 PDF 表單與列印程式，第一步是找到標準表單、複製到客戶命名空間改版面，並在客製化中切換，而不是自己從頭寫列印程式、更不是改標準程式。增強點見 3-4 章 BAdI／Enhancement Framework。

範例一：催款單（FI 催款）

  3. 把自己的表單登錄進催款程序：依客製化路徑（或 SPRO）選催款程序（例如四級催款、每兩週）→ 選「一般／法律催款程序的表單」並輸入公司代碼 → 在各催款層級填入你的表單副本 → 存檔，忽略「表單不存在或未啟用」的警告（因為系統只會去檢查 SAPscript 表單）。

18. 舊表單移轉：SAPscript 與 SmartForms → PDF 表單

先看舊表格做法（Col18 Unit 9）：Designer 6.0／7.0 沒有 Table 物件，要手動用子表單拼表格（7.1 起會自動把舊表格顯示成新表格）：

  1. 外層子表單（例如 IT_BOOKINGS）：Flowed、方向 Top to Bottom；不勾 Repeat Subform for Each Data Item；要整張在一頁就不勾 Allow Page Breaks within Content（資料少時忽略，放不下時自動換頁從下一頁開始）；外框在外層 Border 面板設。
  2. 內層子表單（永遠叫 DATA）：Flowed、方向 Western Text；不勾 Allow Page Breaks；勾 Repeat Subform for Each Data Item；邊距上下左右 0cm，寬高 Expand to fit；列與列之間的橫線在內層 Border 面板設（Unit 9 測驗題）。
  3. 刪掉不印的欄位（沒有腳本就不能把同一內表處理兩次、留部分欄位給第二輪）；列印表單避免 3D 框：「Object → Field → Appearance」選 None（同型欄位可 Ctrl／Shift 多選一起改）。
  4. 移除 Caption（否則每列都重複）：多選欄位 →「Layout → Caption → Position → None」。個別欄寬無關，由整張表決定；高度填最小值並 Expand to fit。
  5. 儲存格框線與網底在各儲存格 Border 面板設；邊距如 0.1cm。
  6. 欄寬最好在外層 Object → Subform 頁籤的 Column Widths 一次填，例如 2cm 2.3cm 3cm 3.5cm 2cm 4cm，值與單位間不能有空格，不寫單位預設是英吋（Drawing Aids 的單位只用於尺規）。
  7. 表頭：外層右鍵 Insert Subform 命名 HEADER（F2 改名），放在 DATA 上方，Flowed／Western Text，每欄放一個靜態文字、邊距與資料欄一致；HEADER 的 Binding 不勾 Repeat；DATA 的 Binding 設 Overflow Leader = HEADER，換頁時表頭就會重複。

移轉 SmartForms 的前置作業：確認所有參照物件（字典型別、Smart Styles、文字模組、SAPscript 文字）都存在；把多情境大表單拆小：① 每種業務情境各建一個暫存副本；② 在各副本刪掉不屬於該情境的條件與子樹（用 SmartForms Builder 與 NW 7.0 起的 Form Info 圖形精靈，2007 版寫 NW ’04）；③ 介面也拿掉條件（簡化並加速取資料）；④ 存檔啟用。

移轉步驟：SMARTFORMS 初始畫面「公用程式 → 移轉 → Interactive Form（舊版選單為「基於 PDF 的表單」）→ 匯出」，輸入 SmartForm 名、目標 PDF 表單名與目標介面名（預設取自 SmartForm，可相同可不同；已存在可選覆寫或改名）。主要選項：

  • Generate Interface：建立或覆寫介面（確認後）；介面已移轉並手改過就取消。
  • Texts：移轉所有文字節點。文字元素 → 靜態文字（ITF 轉 XHTML）；文字模組與 SAPscript 文字 → 參照 Context 的欄位（XFA <field>），執行時才由 ITF 轉 XHTML。子選項：Append Mode（A 直接接、N 新行、P 新段落；ADS 不支援，以包含 append_mode__ 欄位的子表單加腳本模擬，建議不要用）、Generate Data Binding to Context（sfsy 欄位如 sfsy-page、sfsy-formpages 與部分 sy 欄位如 sy-datum、sy-uzeit 由 ADS 直接解析；&mystruct-myfield& 改名為 mystruct.myfield）、Display Fields as Placeholders（不自動繫結，顯示成 {MYSTRUCT-MYFIELD}，事後手動替換）。
  • Addresses：成為連到 Context 地址節點的欄位，執行時以純文字帶入，移轉後需手動排版。
  • Folder／Templates／Tables and Loops：分別成為 Context 的資料夾／迴圈節點與版面的 XFA <subform>；取消時該節點被忽略但子節點照移轉規則處理（例如 Texts 開著，資料夾中的文字仍會移轉）。
  • Output Options：框線、網底、頁面保護移入版面；視窗節點的輸出選項一律移轉。
  • Header/Footer Events：成為 XFA leader／trailer 子表單。
  • Conditions：資料驅動條件（CARRIER = 'LH'）由 ABAP 評估 → 產生 Context 條件；版面驅動條件（只在第一頁）由 ADS 評估 → 產生含 subform_condition__ 的子表單，但 ADS／Designer 不支援，須以腳本重建。預設不移轉條件，建議先評估並拆成多張表單。
  • Program Nodes：程式節點只允許存在於移轉表單，預設不勾，建議改用其他方式（如腳本）實現。移轉的程式行保留原碼，但全部在產生資料流時（ADS 渲染前）執行，不能依賴換頁等版面時點。

執行轉換後用「公用程式 → 移轉 → Interactive Form → 顯示日誌」看協定（沒有錯誤就不會顯示日誌），再用「… → 編輯」進 Designer 收尾，最後啟用表單與介面。不要低估收尾的時間。移轉後若要讓舊程式自動改用 PDF 表單，記得做第 15 節的 Switch Runtime。

SmartForms 中應避免（移轉時都要手工修）：SAP 字元（<123>）；流程邏輯中的程式行節點；超出 Adobe XHTML 子集的文字格式（移轉時遺失）；資料相關輸出條件（條件頁籤的表格控制）與時間條件（如主視窗關閉後）的組合；過時的 R/3 4.6C 表格；範本儲存格版面被其他儲存格打斷（text1 在 cell 1-1、text2 在 cell 1-2、text3 又在 cell 1-1）；表格參數與匯出參數（新介面不支援，表格改成 TYPE <表格類型> 的 import 參數，應用資料不要用 export 參數）；文字模組、圖片、地址、迴圈上以 OR 連結的輸出條件（如 SFSY-PAGE > 10）與資料條件的組合；依版面條件（目前頁 = 1）或版面事件（換頁）的程式行；輸出格式 XDF 或 HTML。

實務判斷：SmartForms 簡單、邏輯乾淨→用移轉工具加 Switch Runtime，舊程式不動；SmartForms 複雜、塞滿程式節點與版面條件→直接重做 PDF 表單，把邏輯搬回列印程式或介面初始化；SAPscript→一律重做。SmartForms 本身的實作見 4-3 章 與 5-19 章。

練習與自我檢核

  1. 下列哪一個可以沒有表單而獨立存在：介面、Context、Layout、生成的函數模組？
    要點：介面。它是獨立的 Repository 物件，可被多張表單共用；Context 與 Layout 永遠屬於某張表單，函數模組是表單啟用時產生的。
  2. 新開發應選哪種介面類型？為何不建議 Smart Forms 相容介面？
    要點：ABAP Dictionary-Based。相容介面會拿到錯誤的列印參數、XSF/XDF 參數不能用、多份 PDF 的 spool 只回一份、不能設定 BCS。XML Schema-Based 主要給 Web Dynpro／Gateway 型表單。
  3. 介面初始化中改了 import 參數卻沒生效或出錯，最可能原因？
    要點：該參數沒勾 Pass Value（call-by-reference import 是唯讀）；另外用到的欄位必須列在初始化的 Input／Output 參數中，用 DATA 宣告的區域變數不能用在版面。
  4. Context 中把欄位設 Inactive 有什麼效果？會讓必填參數變選用嗎？
    要點：不進 XML 資料流、提升效能；不會，列印程式仍須傳值。
  5. Alternative 節點的條件與一般節點條件差在哪？
    要點：一般條件決定該節點（含子節點）是否進資料流；Alternative 條件決定走 TRUE 或 FALSE 分支，Alternative 本身一定被處理。條件中可用所有介面欄位，不能用其他 Context 欄位與系統欄位。
  6. 文字模組與 Include Text 的維護 TCODE、Client 相依性與傳輸方式？
    要點：文字模組在 SMARTFORMS、跨 Client、自動進傳輸；Include Text 在 SO10（不是 SO01）、Client 相依、手動加傳輸。兩者的 SAPscript 命令與輸出選項在 PDF 表單中都被忽略，格式以 Smart Style 解讀。
  7. Master Page、Content Area、Body Page 各相當於 SmartForms 的什麼？
    要點：主頁面上的物件≈次視窗；內容區＋頁體≈主視窗；頁體是動態內容容器，可延伸成多頁。
  8. 哪些情況必須手動設定資料繫結？繫結 Normal 的風險？
    要點：從 Library 拖入、複製貼上、移到別的子表單或拆子表單。Normal 繫結靠名稱對應，版面物件改名就斷；同一元素放多次要用 Global。
  9. 寫出一個依幣別決定小數位、最大到千萬的數字顯示樣式。
    要點：zz,zzz,zz9.88；符號 8 代表依幣別／單位的小數位，USD 印兩位、JPY 不印小數。樣式不自動翻譯、大小寫敏感。
  10. 表格用條件分頁「航空公司不同就插分隔表頭」，但輸出時分組亂跳，原因與解法？
    要點：資料沒排序。HANA 沒有預設排序，SELECT 要 ORDER BY 或 ABAP SORT；控制層級要嘛自己排序並勾 Already sorted，要嘛讓系統排序（只限全域欄位或 call-by-value 參數）。
  11. FormCalc 的 calculate 事件與 initialize 事件在指派上的差別？為何不能寫 $ = $ + 1？
    要點：calculate 取最後一個運算式的值、不需指派；它可能重算多次，自我參照會累加出錯。其他事件要寫 $ = 值。
  12. FormCalc 與 JavaScript 的四個 accessor 對照？HasValue 回傳值？
    要點：$／this、$record／xfa.record、欄位值直接寫／.rawValue、變數直接寫／.value。HasValue 有值回傳 1（强晟筆記寫反了）。
  13. 為什麼 Ctrl+F3 啟用成功，執行時表單仍可能出錯？如何追？
    要點：啟用只檢查介面與 Context，不檢查版面與腳本；用 Designer 預覽的 Warnings、SFP「公用程式 → 設定」的 Trace（需除錯權限），並一定要用 ABAP 程式實測。
  14. 寫出新介面列印程式的五個步驟與對應函數。
    要點：取資料（FP_FIELD_LIST 可查表單用到的欄位）→ FP_FUNCTION_MODULE_NAME（TRY…CATCH CX_FP_API）→ FP_JOB_OPEN（SFPOUTPUTPARAMS）→ 動態呼叫生成函數（/1BCDWB/DOCPARAMS、/1BCDWB/FORMOUTPUT，可多次）→ FP_JOB_CLOSE（SFPJOBOUTPUT）。舊介面不可呼叫 JOB_OPEN／CLOSE。
  15. SFPOUTPUTPARAMS 中哪個欄位開新 spool request？要把 PDF 拿回來寄信要設哪個？此時能預覽嗎？
    要點：REQNEW；GETPDF，PDF 在 /1BCDWB/FORMOUTPUT-PDF，此時不能預覽。寄信用 CL_BCS，別忘了 COMMIT WORK。
  16. SmartForms 移轉成 PDF 表單後，如何讓舊列印程式不改碼就改印 PDF？
    要點：SMARTFORMS「公用程式 → 移轉 → … → Switch Runtime」在 STXFPCUST 登錄，SSF_FUNCTION_MODULE_NAME 會自動回傳 PDF 表單的函數名。
  17. 催款單要改用自己的 PDF 表單，需做哪些客製化？為何會出現「表單不存在」警告？
    要點：複製 F150_DUNN_PDF；BTE 事件 1720（FI-FI）的 P/S 模組改 FI_PRINT_DUNNING_NOTICE_PDF；在催款程序各層級填表單副本。警告是因為系統只檢查 SAPscript 表單，可忽略。這就是「先標準再客製」。
  18. 設定 SM59 的 ADS 連線：類型、埠號規則、Path Prefix？
    要點：類型 G；5<J2EE 執行個體號>00；/AdobeDocumentServices/Config?style=rpc（SSL 為 AdobeDocumentServicesSec），忽略 Query string 警告，測試 status_reason = OK。
  19. SAPscript 的 /: PERFORM、&SAPSCRIPT-JOBPAGES&、最後一頁判斷在 PDF 表單怎麼處理？
    要點：PERFORM 不可用（只能腳本）；JOBPAGES 表單內取不到；最後一頁用 layout:ready 比較 $layout.pageCount() 與 $layout.page(ref($))。
  20. 實作題：建立介面 ZBC480_IF_INVOICE（IS_CUSTOMER、IT_BOOKINGS、Global Field GT_SUMS）、表單 ZBC480_INVOICE（主頁面放 Logo 與地址、頁體放依航空公司分組並有重複表頭的訂位表、頁尾「第 x／y 頁」），並寫列印程式讓每位客戶一份 PDF、同一 spool，另可勾選改為寄 PDF。
    要點：合計在初始化用 REDUCE 算；Logo 走 Graphic Content（XSTRING）；表格 Overflow Leader／Include Header Row in Subsequent Pages；控制層級前先 ORDER BY；頁碼用 layout:ready；程式參考第 14、15 節。
