老師的一句總結：「OOALV 與 Function ALV 最大的差異就是——前者把程式放在各個物件中，不像後者一目了然。但更適合規畫複雜系統，需要更多的程式技巧。」

到了 S/4HANA，這已經不只是「哪個比較好用」的品味問題，而是硬性條件：

  • ABAP Cloud 開發模型只允許使用 released API（C1 contract）。絕大多數 REUSE_ALV_* 這類經典函數模組都沒有釋出給 Cloud，Function ALV 在 ABAP Cloud / BTP ABAP Environment 上根本編譯不過。
  • RAP（ABAP RESTful Application Programming Model）的 Behavior Implementation 全部是 CLASS ... IMPLEMENTATION ＋ 介面 IF_ABAP_BEHAVIOR_HANDLER，不會 OO 就寫不出一行。
  • 單元測試（ABAP Unit）是類別導向的（FOR TESTING、CL_ABAP_UNIT_ASSERT），沒有類別就沒有測試。
  • Clean ABAP 官方風格指南預設所有新程式都以類別為單位，FORM/PERFORM 已被標記為 obsolete。
S/4HANA 上 FORM / PERFORM（Subroutine）與 TABLES:、WITH HEADER LINE 在 ABAP Cloud 語法檢查中直接是語法錯誤；在 On-Premise 的標準 ABAP 也只是「還能編譯的過時語法」。本章講義原文大量使用 FORM，我們保留它的教學順序，但範例一律改寫成本地類別（Local Class）的方法。

2. OO 基本觀念：類別、物件、封裝

講義開宗明義的定義，先背下來：

  • 類（Class）：用來描述「具有相同屬性和方法的物件」的集合。它定義了該集合中每個物件所共有的屬性（Attributes）和方法（Methods）。類別是藍圖。
  • 物件（Object）：是類的實例（Instance），是一個現實實體的抽象。一個物件可以被認為是「把資料（屬性）和程式（方法）封裝在一起」的實體。
  • 方法（Methods）：對物件的操作。
  • 物件是動態的概念：其中的屬性反映了物件當前的狀態。
  • OOALV 就是利用 ALV 的一個實例（Instance）來顯示的。

ABAP 的類別分兩種存放位置，兩者語法完全相同，差別只在「誰看得到」：

 本地類別 Local Class全域類別 Global Class
建立工具直接寫在程式（SE38／SE80）裡，或 Include *_CL1SE24 或 SE80 → Class/Interface；Eclipse ADT 建 Class
命名習慣用 LCL_ 開頭（Local CLass）客製一律 ZCL_ / YCL_；SAP 標準是 CL_
可見範圍只有該支程式看得到整個系統都能用，可被別的程式、BAdI、RAP 引用

老師特別把「SE24 vs SE37」擺在一起講：SE37 的 Function Module 是「一包程序」，SE24 的 Class 是「一包狀態 ＋ 一包程序」。學 OO 的第一個練習，就是用 SE24 打開 CL_GUI_CUSTOM_CONTAINER，觀察三個頁籤：Attributes（屬性）／Methods（方法）／Events（事件）——不必看懂全部，重點是建立「原來一個 SAP 標準物件長這樣」的直覺。

類別的完整宣告骨架（DEFINITION ／ IMPLEMENTATION 分離）：

"====================================================================
" 本地類別：定義區（DEFINITION）——只宣告「有什麼」
"====================================================================
CLASS lcl_flight DEFINITION.

  PUBLIC SECTION.
    "-- 常數：全大寫，只能讀不能寫
    CONSTANTS: c_currency TYPE waers VALUE 'TWD'.

    "-- 靜態屬性（類別屬性）：所有物件共用同一份
    CLASS-DATA: gv_count TYPE i.

    "-- 實例屬性：每個物件各有一份
    DATA: mv_carrid TYPE sflight-carrid READ-ONLY,
          mv_connid TYPE sflight-connid READ-ONLY.

    "-- 建構子：CREATE OBJECT / NEW #( ) 時自動執行
    METHODS constructor
      IMPORTING iv_carrid TYPE sflight-carrid
                iv_connid TYPE sflight-connid.

    "-- 一般實例方法
    METHODS get_seats_free
      RETURNING VALUE(rv_free) TYPE i.

    METHODS describe
      RETURNING VALUE(rv_text) TYPE string.

    "-- 靜態方法：不需要物件就能呼叫，用 => 存取
    CLASS-METHODS get_instance_count
      RETURNING VALUE(rv_count) TYPE i.

  PROTECTED SECTION.
    "-- 只有自己和「子類別」看得到
    METHODS read_db.

  PRIVATE SECTION.
    "-- 只有自己看得到（外面完全碰不到）
    DATA: ms_flight TYPE sflight.

ENDCLASS.

"====================================================================
" 本地類別：實作區（IMPLEMENTATION）——寫「怎麼做」
"====================================================================
CLASS lcl_flight IMPLEMENTATION.

  METHOD constructor.
    mv_carrid = iv_carrid.
    mv_connid = iv_connid.
    read_db( ).                    " 呼叫自己的 protected 方法，不必寫 me->
    gv_count = gv_count + 1.       " 靜態屬性：每建一個物件就 +1
  ENDMETHOD.

  METHOD read_db.
    "-- 明列欄位，主機變數一律加 @
    SELECT SINGLE carrid, connid, fldate, seatsmax, seatsocc
      FROM sflight
      WHERE carrid = @mv_carrid
        AND connid = @mv_connid
      INTO CORRESPONDING FIELDS OF @ms_flight.
  ENDMETHOD.

  METHOD get_seats_free.
    rv_free = ms_flight-seatsmax - ms_flight-seatsocc.
  ENDMETHOD.

  METHOD describe.
    "-- 字串範本比 CONCATENATE 清楚得多
    rv_text = |{ mv_carrid }-{ mv_connid } 剩餘座位 { get_seats_free( ) }|.
  ENDMETHOD.

  METHOD get_instance_count.
    rv_count = gv_count.
  ENDMETHOD.

ENDCLASS.
可見性區段誰能存取實務原則
PUBLIC SECTION任何人（外部程式、子類別、自己）只放「對外承諾的介面」。屬性盡量不要放 public，要放就加 READ-ONLY
PROTECTED SECTION自己 ＋ 所有子類別給繼承用的鉤子（hook）方法放這裡
PRIVATE SECTION只有自己（同一個類別）預設全部放這裡，需要才往上開。這就是「封裝」
口訣：「屬性 private、方法 public、繼承用 protected」。想改屬性就寫 SET_ 方法，想讀就寫 GET_ 方法或加 READ-ONLY——這樣未來欄位改型別，外部程式不必跟著改。

3. 建立物件：CREATE OBJECT 與 NEW #( )、參照變數的生死

ABAP 的物件變數叫做參照變數（Reference Variable），宣告時用 TYPE REF TO。它本身不是物件，只是一根指向物件的指標；剛宣告時是 INITIAL（空指標），必須「建立物件」之後才指得到東西。

"====================================================================
" 三種建立物件的寫法（結果相同，新程式一律用第三種）
"====================================================================
DATA lo_flight TYPE REF TO lcl_flight.

"-- 舊：CREATE OBJECT（講義原文的寫法，S/4 仍可用但不推薦）
CREATE OBJECT lo_flight
  EXPORTING
    iv_carrid = 'AA'
    iv_connid = '0017'.

"-- 中：NEW 建構式運算子，變數已宣告 → 型別可用 #
lo_flight = NEW #( iv_carrid = 'AA' iv_connid = '0017' ).

"-- 新（推薦）：內嵌宣告 ＋ NEW，一行搞定
DATA(lo_flight2) = NEW lcl_flight( iv_carrid = 'AA' iv_connid = '0017' ).

"-- 呼叫方法：實例用 ->，靜態用 =>
DATA(lv_free) = lo_flight2->get_seats_free( ).
DATA(lv_txt)  = lo_flight2->describe( ).
DATA(lv_cnt)  = lcl_flight=>get_instance_count( ).   " 靜態方法不需要物件

"-- 判斷參照是否有效：用 IS BOUND，不要用 IS INITIAL 判斷「物件活著沒」
IF lo_flight2 IS BOUND.
  cl_demo_output=>write( lv_txt ).
ENDIF.

"-- 解除參照（讓 Garbage Collector 有機會回收）
CLEAR lo_flight2.        " 或 FREE lo_flight2.
講義提醒：CREATE OBJECT 這個關鍵字後面「接冒號」或「不接冒號」都可以——CREATE OBJECT: a EXPORTING ... 是鏈式寫法。混用時很容易漏掉句點，這是初學者第一個常見編譯錯誤。
參照變數 ≠ 物件。lo_a = lo_b 是把「指標」複製過去，兩個變數指向同一個物件，改 A 就會影響 B。要真正複製內容必須自己寫 copy 方法或用 CORRESPONDING #( ) 搬結構。

4. 建構子、靜態成員、繼承、多型、介面、FRIENDS

4-1 建構子 CONSTRUCTOR 與 CLASS_CONSTRUCTOR

  • CONSTRUCTOR（實例建構子）：每次建立物件時自動執行一次，只能有 IMPORTING 參數與 RAISING，不能有 RETURNING / EXPORTING。
  • CLASS_CONSTRUCTOR（靜態建構子）：整個程式執行期間，在第一次用到這個類別之前自動執行一次，沒有任何參數。適合載入設定檔、讀常數表。
  • 子類別的 CONSTRUCTOR 必須先呼叫 super->constructor( ) 才能碰自己的屬性。
CLASS lcl_config DEFINITION CREATE PRIVATE.
  PUBLIC SECTION.
    CLASS-METHODS class_constructor.          " 靜態建構子，無參數
    CLASS-METHODS get_plant_name
      IMPORTING iv_werks       TYPE werks_d
      RETURNING VALUE(rv_name) TYPE name1.
  PRIVATE SECTION.
    CLASS-DATA gt_t001w TYPE SORTED TABLE OF t001w
                        WITH UNIQUE KEY werks.
ENDCLASS.

CLASS lcl_config IMPLEMENTATION.

  METHOD class_constructor.
    "-- 全程式只會跑這一次：把工廠主檔一次讀進記憶體當快取
    SELECT werks, name1
      FROM t001w
      INTO CORRESPONDING FIELDS OF TABLE @gt_t001w.
  ENDMETHOD.

  METHOD get_plant_name.
    "-- 用 line_exists 判斷，比 READ TABLE + sy-subrc 乾淨
    IF line_exists( gt_t001w[ werks = iv_werks ] ).
      rv_name = gt_t001w[ werks = iv_werks ]-name1.
    ELSE.
      rv_name = |工廠 { iv_werks } 不存在|.
    ENDIF.
  ENDMETHOD.

ENDCLASS.
CLASS ... DEFINITION CREATE PRIVATE 表示「外面不准 NEW 我」，只能透過我提供的靜態工廠方法取得實例——這就是 Singleton／Factory 樣式。CL_SALV_TABLE=>FACTORY( ) 用的正是這一招，所以你永遠不會寫 NEW cl_salv_table( )。

4-2 繼承 INHERITING FROM、多型、REDEFINITION

"-- 父類別：抽象類別不能被實例化，只能被繼承
CLASS lcl_doc DEFINITION ABSTRACT.
  PUBLIC SECTION.
    METHODS constructor IMPORTING iv_id TYPE char10.
    "-- 抽象方法：只有簽章沒有實作，子類別「必須」實作
    METHODS get_title ABSTRACT RETURNING VALUE(rv_title) TYPE string.
    "-- 一般方法：子類別可以選擇性覆寫
    METHODS print.
  PROTECTED SECTION.
    DATA mv_id TYPE char10.
ENDCLASS.

CLASS lcl_doc IMPLEMENTATION.
  METHOD constructor.
    mv_id = iv_id.
  ENDMETHOD.
  METHOD print.
    cl_demo_output=>write( |【{ get_title( ) }】{ mv_id }| ).
  ENDMETHOD.
ENDCLASS.

"-- 子類別 1：銷售訂單
CLASS lcl_so DEFINITION INHERITING FROM lcl_doc.
  PUBLIC SECTION.
    METHODS get_title REDEFINITION.
ENDCLASS.
CLASS lcl_so IMPLEMENTATION.
  METHOD get_title.
    rv_title = '銷售訂單'.
  ENDMETHOD.
ENDCLASS.

"-- 子類別 2：採購單，FINAL 表示不准再被繼承
CLASS lcl_po DEFINITION INHERITING FROM lcl_doc FINAL.
  PUBLIC SECTION.
    METHODS get_title REDEFINITION.
    METHODS print     REDEFINITION.
ENDCLASS.
CLASS lcl_po IMPLEMENTATION.
  METHOD get_title.
    rv_title = '採購單'.
  ENDMETHOD.
  METHOD print.
    super->print( ).                       " 先做父類別原本要做的事
    cl_demo_output=>write( '（需採購主管核准）' ).
  ENDMETHOD.
ENDCLASS.

"-- 用父類別參照當內表行型別，才裝得下所有子類別的物件
TYPES ty_doc_tab TYPE STANDARD TABLE OF REF TO lcl_doc WITH EMPTY KEY.

START-OF-SELECTION.
  "-- 多型（Polymorphism）：同一個父型別的參照，跑出不同行為
  DATA(lt_docs) = VALUE ty_doc_tab(
      ( NEW lcl_so( '4500001234' ) )
      ( NEW lcl_po( '4700005678' ) ) ).

  LOOP AT lt_docs INTO DATA(lo_doc).
    lo_doc->print( ).      " 呼叫的是同一個 print，執行的卻是各自的版本
  ENDLOOP.
關鍵字意思常見用途
INHERITING FROM繼承（ABAP 只支援單一繼承）共用邏輯放父類別
ABSTRACT（類別）不能被實例化當共同基底
ABSTRACT（方法）只有簽章沒有實作，子類別必須 REDEFINITION強制子類別填空
FINAL（類別）不能再被繼承大部分實作類別都該加 FINAL
FINAL（方法）子類別不能再覆寫這個方法保護關鍵演算法
REDEFINITION覆寫父類別方法（不可改簽章）多型的實作手段
super->呼叫父類別的版本擴充而非取代原行為
me->指向自己這個物件區分同名的區域變數與屬性
REDEFINITION 不能改參數。想「多加一個參數」只能新增一個方法，或改用介面。另外 PRIVATE 的方法不能被 REDEFINITION——要讓子類別能覆寫，父類別至少要放 PROTECTED。

4-3 介面 INTERFACE：ABAP 版的「多重繼承」

"-- 介面：只有宣告，沒有實作；沒有可見性區段（一律 public）
INTERFACE lif_printable.
  METHODS to_line RETURNING VALUE(rv_line) TYPE string.
  CONSTANTS c_sep TYPE c LENGTH 1 VALUE ';'.
ENDINTERFACE.

INTERFACE lif_checkable.
  METHODS is_valid RETURNING VALUE(rv_ok) TYPE abap_bool.
ENDINTERFACE.

"-- 一個類別可以實作「多個」介面，這就是 ABAP 的多重繼承替代方案
CLASS lcl_material DEFINITION FINAL.
  PUBLIC SECTION.
    INTERFACES: lif_printable,
                lif_checkable.
    METHODS constructor IMPORTING iv_matnr TYPE matnr.
  PRIVATE SECTION.
    DATA mv_matnr TYPE matnr.
ENDCLASS.

CLASS lcl_material IMPLEMENTATION.
  METHOD constructor.
    mv_matnr = iv_matnr.
  ENDMETHOD.

  "-- 實作介面方法時，名稱要用「介面名~方法名」（波浪號）
  METHOD lif_printable~to_line.
    rv_line = |MATNR{ lif_printable=>c_sep }{ mv_matnr }|.
  ENDMETHOD.

  METHOD lif_checkable~is_valid.
    SELECT SINGLE @abap_true
      FROM mara
      WHERE matnr = @mv_matnr
      INTO @rv_ok.
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  "-- 用介面型別的參照持有物件：呼叫端只認介面，不認實作類別
  DATA(lo_p) = CAST lif_printable( NEW lcl_material( '000000000000001234' ) ).
  cl_demo_output=>write( lo_p->to_line( ) ).

  "-- 想換回別的介面 / 檢查型別，用 CAST 搭配 TRY，或用 IS INSTANCE OF
  DATA(lo_obj) = CAST object( lo_p ).
  IF lo_obj IS INSTANCE OF lif_checkable.
    DATA(lo_c) = CAST lif_checkable( lo_obj ).
    cl_demo_output=>write( COND string( WHEN lo_c->is_valid( ) THEN '料號存在'
                                        ELSE '料號不存在' ) ).
  ENDIF.
介面在 SAP 標準隨處可見，而且是最好的「白名單」：IF_SALV_C_SELECTION_MODE、IF_SALV_C_REFRESH、IF_ABAP_BEHAVIOR_HANDLER（RAP）、IF_OO_ADT_CLASSRUN（Eclipse 的 main 方法）。看到 IF_ 開頭就知道是介面。

4-4 FRIENDS：把私有大門開一條縫

"-- 讓 lcl_alv_handler 可以直接存取 lcl_report 的 PRIVATE 成員
CLASS lcl_alv_handler DEFINITION DEFERRED.      " 前向宣告（尚未定義先報名）

CLASS lcl_report DEFINITION FINAL
  FRIENDS lcl_alv_handler.                      " 我把 private 開放給這位朋友
  PUBLIC SECTION.
    METHODS run.
  PRIVATE SECTION.
    DATA mt_data TYPE STANDARD TABLE OF sflight WITH EMPTY KEY.
ENDCLASS.
FRIENDS 是單向的，而且會破壞封裝。實務上只在兩個地方合理使用：(1) 單元測試類別要看被測類別的內部狀態（LOCAL FRIENDS ltcl_test）；(2) 同一支程式裡 ALV 事件 handler 需要直接改主程式的內表。除此之外請改用 public 方法。

5. 事件 EVENTS：RAISE EVENT 與 SET HANDLER

事件是 OOALV 的靈魂——「使用者雙擊了某一格」這件事，是 CL_GUI_ALV_GRID 物件丟出來（RAISE）的，你要事先登記（SET HANDLER）才收得到。先用自製類別把機制看懂：

"====================== 事件發送端 ======================
CLASS lcl_stock DEFINITION.
  PUBLIC SECTION.
    "-- 宣告事件；EXPORTING 的參數一律是 VALUE( ) 傳值
    EVENTS: below_safety
              EXPORTING VALUE(ev_matnr) TYPE matnr
                        VALUE(ev_qty)   TYPE menge_d.
    METHODS issue IMPORTING iv_matnr TYPE matnr
                            iv_qty   TYPE menge_d.
  PRIVATE SECTION.
    DATA mv_onhand TYPE menge_d VALUE 100.
ENDCLASS.

CLASS lcl_stock IMPLEMENTATION.
  METHOD issue.
    mv_onhand = mv_onhand - iv_qty.
    IF mv_onhand < 20.
      "-- 丟出事件；有登記的 handler 才會被叫到，沒人登記就自動忽略
      RAISE EVENT below_safety
        EXPORTING ev_matnr = iv_matnr
                  ev_qty   = mv_onhand.
    ENDIF.
  ENDMETHOD.
ENDCLASS.

"====================== 事件接收端 ======================
CLASS lcl_alert DEFINITION.
  PUBLIC SECTION.
    "-- FOR EVENT 事件名 OF 類別名；IMPORTING 只列你想收的參數（名稱要一致）
    METHODS on_low FOR EVENT below_safety OF lcl_stock
      IMPORTING ev_matnr ev_qty sender.
ENDCLASS.

CLASS lcl_alert IMPLEMENTATION.
  METHOD on_low.
    "-- sender 是系統自動提供的：誰丟出這個事件
    MESSAGE |料號 { ev_matnr } 低於安全庫存，剩 { ev_qty NUMBER = USER }| TYPE 'I'.
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  DATA(lo_stock) = NEW lcl_stock( ).
  DATA(lo_alert) = NEW lcl_alert( ).

  "-- 登記：把 lo_alert 的 on_low 掛到 lo_stock 這個物件的事件上
  SET HANDLER lo_alert->on_low FOR lo_stock.

  "-- 想一次登記「所有同類別的物件」：FOR ALL INSTANCES
  " SET HANDLER lo_alert->on_low FOR ALL INSTANCES.

  lo_stock->issue( iv_matnr = '000000000000001234' iv_qty = 90 ).

  "-- 取消登記
  SET HANDLER lo_alert->on_low FOR lo_stock ACTIVATION space.
語法說明
EVENTS ev EXPORTING VALUE(p) TYPE t宣告實例事件（參數只能傳值）
CLASS-EVENTS靜態事件，用 FOR ALL INSTANCES 或直接對類別登記
RAISE EVENT ev EXPORTING ...發送事件；同步執行所有 handler，執行完才回到原處
FOR EVENT ev OF cls宣告 handler 方法
IMPORTING ... senderhandler 可以額外收 sender（發送者參照）
SET HANDLER h FOR o登記單一物件
SET HANDLER h FOR ALL INSTANCES登記所有同類別物件（含未來建立的）
... ACTIVATION space取消登記
SET HANDLER 會建立一個「強參照」：只要事件發送者還活著，handler 物件就不會被回收。ALV 程式如果每次 PBO 都 NEW 一個 handler 又 SET HANDLER，記憶體會一路長上去（Memory Leak）。正解是：handler 物件只建立一次（用 IF lo_handler IS NOT BOUND 包起來），這也是本章第 8 節那個 IF wcl_alv IS INITIAL 判斷式真正的用意。

6. 例外處理：TRY / CATCH cx_root

講義第 15 節「從程式師的角度學 OOP」用的是最經典的例子：除以零不再 short dump，而是被 catch 起來。這正是 OO 帶來的最大實務好處之一——類別式例外（Class-based Exception）。

REPORT zrep_error_check_01.

DATA: gv_result TYPE p LENGTH 8 DECIMALS 2.

"-- 現代寫法：例外參照用內嵌宣告 DATA(lx)，型別由 CATCH 決定
DATA: gv_dividend TYPE i VALUE 19,
      gv_divisor  TYPE i VALUE 0.

TRY.
    "-- 除以零：舊時代直接 dump，現在會丟 CX_SY_ZERODIVIDE
    gv_result = gv_dividend / gv_divisor.
    cl_demo_output=>write( |結果 = { gv_result }| ).

  CATCH cx_sy_zerodivide INTO DATA(lx_zero).
    "-- 抓「具體」的例外，訊息才有意義
    cl_demo_output=>write( |除數為零：{ lx_zero->get_text( ) }| ).

  CATCH cx_root INTO DATA(lx_root).
    "-- cx_root 是所有例外的共同祖先，放最後當保險絲
    cl_demo_output=>write( lx_root->get_text( ) ).

  CLEANUP.
    "-- 只有在例外「往外傳」時才會執行，用來釋放資源（關檔、解鎖）

ENDTRY.

"-- 另一個常見陷阱：字串取子字串超出長度 → CX_SY_RANGE_OUT_OF_BOUNDS
TRY.
    DATA(lv_s) = CONV string( '1234567890' ).
    DATA(lv_c) = lv_s+11(1).           " 位置 11 超出範圍
  CATCH cx_sy_range_out_of_bounds INTO DATA(lx_rng).
    cl_demo_output=>write( lx_rng->get_text( ) ).
ENDTRY.
例外類別繼承自意義
CX_STATIC_CHECKCX_ROOT語法檢查會強制你 CATCH 或在方法上宣告 RAISING（自訂商業例外用這個）
CX_DYNAMIC_CHECKCX_ROOT執行期才檢查（例：CX_SY_CONVERSION_NO_NUMBER）
CX_NO_CHECKCX_ROOT不強制處理，一路往上傳（例：CX_SY_DYNAMIC_OSQL_SEMANTICS）
自訂例外請在 SE24 建 ZCX_XXX，繼承 CX_STATIC_CHECK，勾「with message class」就能把 T100 訊息掛進去，get_text( ) 直接回傳中文訊息。
不要寫 CATCH cx_root 之後什麼都不做（空的 CATCH 區塊）。這是 SAP 程式碼審查最常被打槍的寫法，錯誤被吃掉之後線上問題完全查不到。至少要 MESSAGE 或寫 Application Log（BAL_*）。

7. Screen 設計入門：SE51、PBO / PAI、MODULE

OOALV 的第一步不是寫程式，而是畫一個螢幕。這一節把 Dialog 螢幕的基本結構講清楚，第 4-2 章會再深入 Tabstrip 與 Table Control。

7-1 一個 Screen 由四個部分組成

組成SE51 頁籤 / 工具內容
Attributes（屬性）AttributesScreen number、Short description、Screen type（Normal／Subscreen／Modal dialog box）、Next screen、OK code 欄位名稱
Element list（元素清單）Element list畫面上每個欄位的名稱、型別、長度、輸入／輸出屬性

Flow logic（流程邏輯）Flow logicPROCESS BEFORE OUTPUT / PROCESS AFTER INPUT / PROCESS ON VALUE-REQUEST（F4）/ PROCESS ON HELP-REQUEST（F1）

7-2 事件流程：PBO → 使用者操作 → PAI

  • PBO（Process Before Output）：畫面顯示之前執行。負責：SET PF-STATUS、SET TITLEBAR、把內部變數的值搬到螢幕欄位、LOOP AT SCREEN 控制欄位顯示/唯讀、建立 ALV 物件。
  • 畫面顯示，使用者輸入、按按鈕或選單。
  • PAI（Process After Input）：使用者按下任何功能鍵之後執行。負責：檢核輸入、依 OK_CODE 決定下一步。
  • 螢幕欄位與程式中同名的全域變數會自動雙向搬運（PBO 前程式→螢幕，PAI 前螢幕→程式）。這是 Dialog 程式最重要的潛規則。
*-- SE51 → Flow logic（螢幕 8000）------------------------------------
PROCESS BEFORE OUTPUT.
  MODULE status_8000.          " 設狀態列與標題
  MODULE display_alv.          " 建立 / 刷新 ALV

PROCESS AFTER INPUT.
  MODULE exit_8000 AT EXIT-COMMAND.   " 型別 E 的功能碼，跳過所有檢核先執行
  MODULE user_command_8000.

*-- 欄位層級檢核：CHAIN ... ENDCHAIN 讓整組欄位一起「亮起來」可重新輸入
  CHAIN.
    FIELD: p_werks, p_matnr.
    MODULE check_material ON CHAIN-REQUEST.   " 只有值被改過才執行
  ENDCHAIN.

  FIELD p_menge MODULE check_qty ON REQUEST.  " 單一欄位檢核

*-- F4（搜尋說明）與 F1（欄位說明）
PROCESS ON VALUE-REQUEST.
  FIELD p_matnr MODULE f4_matnr.

PROCESS ON HELP-REQUEST.
  FIELD p_matnr MODULE f1_matnr.
CHAIN / FIELD 的關鍵作用：在 FIELD 或 CHAIN 區塊內的 MODULE 中發出 MESSAGE ... TYPE 'E'，只有該欄位（或整個 CHAIN 內的欄位）會變成可輸入，其他欄位鎖住；若 MODULE 沒有寫在 FIELD/CHAIN 裡就丟 E 訊息，整個畫面會全部鎖死，使用者只能按「取消」離開——這是 Dialog 程式最常見的災難。

7-3 OK_CODE 的正確處理方式

*-- 主程式宣告：兩個變數，一個接畫面、一個給邏輯用
DATA: ok_code TYPE sy-ucomm,      " 螢幕 Attributes 的「OK code」欄位要填 OK_CODE
      save_ok TYPE sy-ucomm.

MODULE user_command_8000 INPUT.

  save_ok = ok_code.
  CLEAR ok_code.        "★★ 一定要清空！否則下一次進 PAI 會沿用舊功能碼

  CASE save_ok.
    WHEN 'BACK' OR 'EXIT' OR 'CANCEL'.
      "-- LEAVE TO SCREEN 0：回到呼叫者（正常退出）
      LEAVE TO SCREEN 0.

    WHEN 'ERP300'.                      " 自訂按鈕（講義 Home Work 第 3 題）
      MESSAGE 'ERP300' TYPE 'I'.
      LEAVE PROGRAM.                    " 直接結束整支程式

    WHEN 'REFRESH'.
      PERFORM get_data.                 " 或呼叫方法重讀資料
      go_grid->refresh_table_display(
        EXPORTING is_stable = VALUE lvc_s_stbl( row = abap_true col = abap_true )
        EXCEPTIONS finished = 1 OTHERS = 2 ).

    WHEN OTHERS.
  ENDCASE.

ENDMODULE.

*-- AT EXIT-COMMAND 專用模組（功能碼型別必須在 SE41 設成 E）
MODULE exit_8000 INPUT.
  CASE ok_code.
    WHEN 'ECAN'.
      LEAVE TO SCREEN 0.
  ENDCASE.
ENDMODULE.
離開指令行為用在哪
LEAVE TO SCREEN 0結束目前螢幕，回到呼叫它的地方（呼叫堆疊往回一層）最標準的退出方式
LEAVE TO SCREEN 9000跳到指定螢幕（不回原處）畫面串接
SET SCREEN 0. LEAVE SCREEN.等同於 LEAVE TO SCREEN 0（舊寫法）維護舊碼會看到
LEAVE PROGRAM直接結束整支程式（不管堆疊）講義範例用它；但若程式被 SUBMIT 呼叫會一起被砍，正式程式建議用 LEAVE TO SCREEN 0
LEAVE TO TRANSACTION 'VA03'跳到別的交易碼單據跳轉
CALL SCREEN 8100 STARTING AT 10 5 ENDING AT 80 20彈出對話視窗（螢幕型別要設 Modal dialog box）明細視窗
講義親身踩過的坑：「測試時若無法返回，應是 NEXT SCREEN 沒清空。」
・SE51 的 Next screen 若留空 → 執行完 PAI 之後停在原畫面（自己叫自己），這是互動式畫面要的行為。
・若填 0 → PAI 跑完就離開。
・老師 2024/12/27 的補充：「畫面上按自己追加的鈕才會結束（注意 SCREEN 的 NEXT SCREEN 也要設 8000）」——填自己的螢幕號 8000，效果等同留空，都是「留在原畫面」，這樣才有機會讓自訂按鈕決定何時退出。可參考程式 Z2409_OO_300。

7-4 GUI 狀態列與標題列（SE41 Menu Painter）

講義第 10 節的做法是複製 SAP 標準狀態列，這是最省事的一招：

    IF ls_screen-group1 = 'DSP'.

FORM prepare_field_catalog CHANGING pt_fieldcat TYPE lvc_t_fcat.

    EXPORTING

9-2 資料讀取（JOIN ＋ 紅綠燈）

FORM get_data.

  CLEAR gt_out.

  "-- 一次 JOIN 抬頭與明細；欄位明列、主機變數加 @
  SELECT k~vbeln, p~posnr, p~matnr, p~pstyv,
         p~kwmeng, p~netwr, k~waerk, k~erdat
    FROM vbak AS k
    INNER JOIN vbap AS p ON p~vbeln = k~vbeln
    WHERE k~erdat IN @s_erdat
      AND k~vbeln IN @s_vbeln
    ORDER BY k~vbeln, p~posnr
    INTO CORRESPONDING FIELDS OF TABLE @gt_out
    UP TO 500 ROWS.

  "-- 用 FIELD-SYMBOL 直接改內表，不必再 MODIFY
  LOOP AT gt_out ASSIGNING FIELD-SYMBOL(<ls>).
    <ls>-light = COND #( WHEN <ls>-netwr >= 100000 THEN '1'    " 紅
                         WHEN <ls>-netwr >=  10000 THEN '2'    " 黃
                         ELSE '3' ).                            " 綠
  ENDLOOP.

ENDFORM.
S/4HANA 提醒：JOIN 之後如果只是要顯示，優先考慮直接建一個 CDS View（DEFINE VIEW ENTITY），把 JOIN 推到 HANA 資料庫層做，程式端只要 SELECT FROM ZI_SalesOrderItem。這也是「Code Push-Down」的基本功。另外 SELECT ... UP TO n ROWS 若沒有 ORDER BY，HANA 不保證回傳順序——上面範例刻意加了 ORDER BY。

MODULE display_alv OUTPUT.

  IF go_grid IS NOT BOUND.
    "================ 第一次：建立所有物件 ================

    "-- 1) 容器：container_name 必須與 SE51 Custom Control 的名稱完全一致
    go_container = NEW cl_gui_custom_container(
                     container_name = 'CONTAINER' ).

    "-- 2) 網格：以容器為 parent
    go_grid = NEW cl_gui_alv_grid( i_parent = go_container ).

    "-- 3) 欄位目錄：自訂結構無法用 MERGE，這裡改用 SALV 產生再微調
    PERFORM build_fieldcat CHANGING gt_fcat.

    "-- 4) 版面：紅綠燈欄位用 excp_fname 指定
    gs_layout = VALUE lvc_s_layo(
                  zebra      = abap_true
                  cwidth_opt = abap_true
                  sel_mode   = 'D'
                  grid_title = |訂單明細（{ lines( gt_out ) } 筆）|
                  smalltitle = abap_true
                  excp_fname = 'LIGHT' ).      " 紅綠燈

    "-- 5) 事件 handler：★只建立一次，避免 memory leak / 事件重複觸發
    go_handler = NEW lcl_alv_event( ).
    SET HANDLER go_handler->on_double_click  FOR go_grid.
    SET HANDLER go_handler->on_hotspot_click FOR go_grid.
    SET HANDLER go_handler->on_toolbar       FOR go_grid.
    SET HANDLER go_handler->on_user_command  FOR go_grid.
    SET HANDLER go_handler->on_data_changed  FOR go_grid.

    "-- 6) 可編輯模式（勾了 p_edit 才開）
    IF p_edit = abap_true.
      go_grid->set_ready_for_input( 1 ).
      "-- 按 Enter 就觸發 data_changed，不必等按儲存
      go_grid->register_edit_event(
        i_event_id = cl_gui_alv_grid=>mc_evt_modified ).
    ENDIF.

    "-- 7) 首次顯示
    go_grid->set_table_for_first_display(
      EXPORTING
        is_layout                     = gs_layout
        i_save                        = 'A'      " 允許存版面配置（Layout Variant）
        i_default                     = abap_true
      CHANGING
        it_outtab                     = gt_out
        it_fieldcatalog               = gt_fcat
      EXCEPTIONS
        invalid_parameter_combination = 1
        program_error                 = 2
        too_many_lines                = 3
        OTHERS                        = 4 ).
    IF sy-subrc <> 0.
      MESSAGE ID sy-msgid TYPE 'S' NUMBER sy-msgno
              WITH sy-msgv1 sy-msgv2 sy-msgv3 sy-msgv4 DISPLAY LIKE 'E'.
    ENDIF.

  ELSE.
    "================ 之後每次 PBO：只刷新 ================
    go_grid->refresh_table_display(
      EXPORTING  is_stable = VALUE lvc_s_stbl( row = abap_true col = abap_true )
      EXCEPTIONS finished  = 1
                 OTHERS    = 2 ).
  ENDIF.

  "-- 讓所有 GUI 控制項的指令真正送到前端
  cl_gui_cfw=>flush( ).

ENDMODULE.

*&---------------------------------------------------------------------*
*& Form BUILD_FIELDCAT（自訂結構也能產生 fieldcat）
*&---------------------------------------------------------------------*
FORM build_fieldcat CHANGING pt_fcat TYPE lvc_t_fcat.

  TRY.
      "-- 借 SALV 幫我們做 RTTI 分析，再轉成 LVC 格式
      cl_salv_table=>factory(
        IMPORTING r_salv_table = DATA(lo_salv)
        CHANGING  t_table      = gt_out ).

      pt_fcat = cl_salv_controller_metadata=>get_lvc_fieldcatalog(
                  r_columns      = lo_salv->get_columns( )
                  r_aggregations = lo_salv->get_aggregations( ) ).

    CATCH cx_salv_msg INTO DATA(lx_salv).
      MESSAGE lx_salv->get_text( ) TYPE 'E'.
  ENDTRY.

  "-- 微調每一欄
  LOOP AT pt_fcat ASSIGNING FIELD-SYMBOL(<fc>).
    CASE <fc>-fieldname.
      WHEN 'VBELN'.  <fc>-coltext = '銷售訂單'. <fc>-hotspot = abap_true.
      WHEN 'POSNR'.  <fc>-coltext = '項次'.
      WHEN 'MATNR'.  <fc>-coltext = '料號'.
      WHEN 'PSTYV'.  <fc>-coltext = '項目類別'.
      WHEN 'KWMENG'. <fc>-coltext = '訂單數量'. <fc>-edit = p_edit.
      WHEN 'NETWR'.  <fc>-coltext = '淨值'.
                     <fc>-do_sum = abap_true.
                     <fc>-cfieldname = 'WAERK'.   " 幣別參照欄
      WHEN 'ERDAT'.  <fc>-coltext = '建立日期'.
      WHEN 'LIGHT'.  <fc>-no_out  = abap_true.    " 紅綠燈欄位本身不顯示
      WHEN OTHERS.
    ENDCASE.
  ENDLOOP.

ENDFORM.

*& Module USER_COMMAND_8000 INPUT
*&---------------------------------------------------------------------*
MODULE user_command_8000 INPUT.

  save_ok = ok_code.
  CLEAR ok_code.

  "-- 編輯模式：先把使用者改的值收回內表（會觸發 data_changed 事件）

10. CL_GUI_ALV_GRID 常用方法與事件速查

方法用途備註
SET_TABLE_FOR_FIRST_DISPLAY首次顯示只能呼叫一次；it_outtab 是 CHANGING（ALV 直接綁著你的內表）
REFRESH_TABLE_DISPLAY資料變了要重畫傳 is_stable(row/col) = 'X' 才能保留捲軸位置

SET_FRONTEND_LAYOUT / GET_FRONTEND_LAYOUT執行中換版面改標題常用

SET_SELECTED_ROWS程式指定選取列refresh 後要重設

11. 其他容器：SPLITTER / DOCKING / DIALOGBOX / SCREEN0

CL_GUI_CUSTOM_CONTAINER 只是容器家族的一員。所有容器都繼承自 CL_GUI_CONTAINER，所以任何一個都可以當 ALV 的 i_parent。

容器類別特性需要 SE51 螢幕嗎
CL_GUI_CUSTOM_CONTAINER放在螢幕上你畫的 Custom Control 區塊裡要（且要有 Custom Control 元素）
CL_GUI_DOCKING_CONTAINER停靠在螢幕的上／下／左／右邊，可自動撐滿要有螢幕，但不必畫 Custom Control

CL_GUI_DIALOGBOX_CONTAINER獨立的浮動視窗（可移動、可關閉）不必畫元素；要處理 CLOSE 事件

12. CL_SALV_TABLE：三種顯示模式與內嵌到 Screen

SALV（2004 年出的第三代）最大的價值是「同一段程式碼，可以全螢幕顯示，也可以塞進容器」。講義第 16 節的 ZREP_CLS_041 是最精簡的版本：

*&---------------------------------------------------------------------*
*& Report ZREP_CLS_041（2004 年 SALV）—— 現代化改寫
*&---------------------------------------------------------------------*
REPORT zrep_cls_041.

SELECT ebeln, bukrs, bsart, lifnr, ekorg, ekgrp, waers, bedat
  FROM ekko
  UP TO 100 ROWS
  ORDER BY ebeln
  INTO TABLE @DATA(gt_ekko).

TRY.
    "-- 模式一：全螢幕（r_container 不傳）
    cl_salv_table=>factory(

14. 記憶體洩漏、物件釋放與 CL_GUI_CFW

GUI 控制項（Container、Grid、Tree、Picture…）是前端物件：ABAP 這邊只有一個代理（proxy），真正的控制項活在 SAP GUI 裡。因此它們有一套自己的生命週期規則。

方法做什麼什麼時候呼叫
cl_gui_cfw=>flush( )把累積的前端指令一次送到 SAP GUI 並等待回應建立/修改控制項之後、需要立即看到效果時。不要在迴圈裡呼叫（每次都是一次網路往返）
cl_gui_cfw=>dispatch( )把前端事件分派給對應的 handlerPAI 中若事件沒被觸發時使用（多數情況 ALV 會自動處理）
lo_ctrl->free( )銷毀前端控制項並釋放資源離開螢幕前、或要重建控制項前
CLEAR lo_ctrl清掉 ABAP 端的參照free( ) 之後緊接著做
 
*-- 標準的釋放順序：子先於父，handler 最後
METHOD cleanup.

  IF mo_grid IS BOUND.
    "-- 先取消事件登記，切斷循環參照
    SET HANDLER mo_handler->on_double_click FOR mo_grid ACTIVATION space.
    SET HANDLER mo_handler->on_toolbar      FOR mo_grid ACTIVATION space.

    mo_grid->free( EXCEPTIONS cntl_error = 1 cntl_system_error = 2 OTHERS = 3 ).
    CLEAR mo_grid.
  ENDIF.

  IF mo_split IS BOUND.
    mo_split->free( EXCEPTIONS OTHERS = 0 ).
    CLEAR: mo_split, mo_top, mo_bottom.
  ENDIF.

  IF mo_container IS BOUND.
    mo_container->free( EXCEPTIONS OTHERS = 0 ).
    CLEAR mo_container.
  ENDIF.

  CLEAR mo_handler.
  cl_gui_cfw=>flush( ).

ENDMETHOD.
三個真正會出事的記憶體陷阱
1. 每次 PBO 都 NEW 容器：第二次進 PBO 時前端已經有一個叫 CONTAINER 的控制項，會拋 CNTL_ERROR，或畫面上疊了兩層 ALV。所以一定要包 IF ... IS NOT BOUND。
2. SET HANDLER 沒解除的循環參照：Grid 指向 handler、handler 指向 Grid，兩邊互相咬住，Garbage Collector 回收不了。長時間執行的 Dialog 交易會慢慢吃光 roll area。
3. ALV 內表是 CHANGING 綁定：set_table_for_first_display 的 it_outtab 是 CHANGING，ALV 直接指向你的內表記憶體。不要在顯示中 REFRESH 或重新指派那個內表變數，會造成 dump 或顯示垃圾資料；要換資料就 CLEAR 後重新 APPEND，再 refresh_table_display( )。
除錯工具：ST22 看 dump（找 CNTL_ERROR、CNTL_SYSTEM_ERROR）、SAT（ABAP Trace）看是不是 flush 呼叫太多次、SM04 看 session 記憶體。
