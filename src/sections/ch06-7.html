第 6-7 章 DBCO 與外部資料庫整合

SAP 不是孤島：MES、BPM、報表平台、舊系統常常各自有一顆 SQL Server。本章從 DBCO 的連線設定講起，說明 SAP 如何用 ADBC 讀寫外部資料庫、把資料「下載」到 SQL Server、呼叫對方的儲存程序；再拆解一支真實上線的原料工單收發料程式 ZPPR0002／ZPPR0005，看它的資料流、踩過的坑，以及把收發料紀錄交給外部系統時該怎麼設計。最後一節反過來看：外部的網頁平台怎麼把 SQL Server 的儲存程序當資料來源，這時 SAP 端只要「給資料」就好。

2. 三種整合方向：先想清楚誰主動、誰負責

「SAP 跟 SQL Server 串」其實有三種完全不同的做法，選錯方向，後面所有程式都會很痛：

方向做法適用風險
A. SAP 主動讀外部DBCO ＋ ADBC execute_querySAP 報表要顯示 MES／BPM 的即時資料（簽核狀態、機台產量）對方 DB 慢或斷線時，SAP 報表跟著卡；要設逾時與錯誤處理
B. SAP 主動寫外部（「下載至 SQL Server」）DBCO ＋ ADBC execute_update，背景作業排程把 BOM、物料主檔、工單、收發料紀錄同步給外部報表平台SAP 已 COMMIT、外部寫失敗 → 兩邊不一致，需要重送機制
C. 外部主動讀 SAP 同步出去的資料方向 B 同步到中介資料庫，由外部平台用儲存程序組報表（第 13 節）網頁平台、Power BI、低代碼平台的查詢與下鑽最乾淨；SAP 只負責「給資料」，邏輯留在對方
絕對不要做的第四種：讓外部系統直接連 SAP 的底層資料庫（HANA schema 或舊版 MSSQL 的 SAP schema）讀寫標準表。這繞過 SAP 的授權、鎖、更新工作與緩衝，升級時表結構一變就壞（例如 S/4HANA 的 MSEG 變成 MATDOC 上的相容視圖、VBUK／VBUP 已併入 VBAK／VBAP），而且多數授權合約也不允許。外部要讀 SAP 資料，走 RFC／BAPI、OData、CDS 或 SAP 自己推出去的中介表。

Casper 的第 3 條經驗在這裡一樣適用：先找標準——需要的是傳輸業務文件就先看 IDoc（5-22 章）、要即時查詢就先看 RFC／BAPI（4-1 章）；DBCO 直連是「對方只給你一顆資料庫」時的務實解法。

3. DBCO 設定：DBCON 表每個欄位的意義

DBCO 維護的是資料表 DBCON（跨 client）。每一列就是一條「次要資料庫連線」（secondary database connection），ABAP 程式用連線名稱引用它。素材截圖中的欄位如下：

畫面欄位DBCON 欄位說明與建議
DB ConnectionCON_NAME連線名稱，程式裡用的就是它。建議用 Z 開頭且看得出對象，例如 ZEXTDB、ZMES_PRD；各系統（DEV／QAS／PRD）名稱相同、內容不同，程式就不必改
DBMSDBMS對方資料庫類型：SQL Server 填 MSS；Oracle 是 ORA、HANA 是 HDB、DB2 是 DB6 等
User NameUSER_NAME對方資料庫的登入帳號 <DB_USER>。要是 SQL Server 驗證帳號，權限只給需要的表／儲存程序
DB passwordPASSWORD輸入兩次，以加密形式存放，畫面上只顯示星號
Conn. infoCON_ENV連線字串。SQL Server 格式：MSSQL_SERVER=<DB_HOST> MSSQL_DBNAME=<DBNAME>；具名執行個體寫 MSSQL_SERVER=<DB_HOST>\<INSTANCE>，非預設埠可寫 <DB_HOST>,<PORT>。兩組參數之間用空白分隔
PermanentDB_RECO勾選代表此連線是「必要連線」：工作程序會把它當成永久連線，連不上時會反覆重試並影響工作程序。外部、非關鍵的資料庫建議不要勾（素材第二張截圖就是把它取消勾選）
Connection LimitMAX_CONN此連線同時開啟的上限，0 表示不限制
Optimum ConnsOPT_CONN保持開啟的理想連線數，0 表示不保留

前置條件：SAP 應用伺服器要能「說」SQL Server 的語言。這需要兩樣東西：

  1. SQL Server 的 DBSL：SAP kernel 目錄下的 dbmssslib（Windows 是 dbmssslib.dll、Linux 是 dbmssslib.so），版本要與 kernel 相符；S/4HANA 主資料庫是 HANA，預設 kernel 裡不一定有 MSS 的 DBSL，要由 Basis 另外放進去。
  2. Microsoft SQL Server 的用戶端（ODBC Driver for SQL Server）：安裝在每一台應用伺服器上。只裝在中央執行個體，程式剛好分配到別台 AS 時就會連不上。

網路面則要確認 AS 到 <DB_HOST> 的 SQL Server 埠（預設 1433）有開。

測試連線：在 DBACOCKPIT（或素材中的 ST04_MSS）左側選 System Landscape → Database Connections，選中連線按 Test，就能看到能否連上與錯誤訊息；清單中也會列出 DB Name、DB Host、User Name、Permanent 等欄位，比進 DBCO 一筆一筆看方便。
素材中的坑：在 S/4HANA（主資料庫為 HANA）的 DBA Cockpit 點 System Configuration 想「集中設定」外部 SQL Server 時，會出現 For <undefined>, no systems are enabled or configured that support the required action 與 Check the system registration——筆記寫著「中央的無法設定」。這不是權限問題，而是 System Configuration 管的是「要被監控的系統」；只是要讓 ABAP 連線，走 DBCO 或 Database Connections 節點即可。

4. ADBC 基礎：從外部資料庫讀資料

ADBC（ABAP Database Connectivity）是 Native SQL 的物件導向介面，四個類別就夠用：

  • CL_SQL_CONNECTION：get_connection( 'ZEXTDB' ) 依 DBCO 名稱開連線；commit( )、rollback( )、close( )。
  • CL_SQL_STATEMENT：set_param( ) 綁定 ? 參數；execute_query( ) 查詢、execute_update( ) 增刪改、execute_ddl( ) 建表、execute_procedure( ) 呼叫儲存程序。
  • CL_SQL_RESULT_SET：set_param_table( ) 指定接收內表，next_package( ) 分批取回，close( ) 釋放游標。
  • CX_SQL_EXCEPTION：所有錯誤都丟這個例外，屬性 sql_code、sql_message、db_error 可以直接顯示給使用者或寫 log。
REPORT zext_read_demo.

" 外部 DB 表 ZEXT_POCHANGE：外部簽核系統的採購單變更紀錄

        TYPE 'I' DISPLAY LIKE 'E'.

欄位怎麼對應：set_param_table 預設依位置把結果欄位填進內表欄位，所以 SELECT 的欄位順序要與結構一致；也可以傳第二個參數 corresponding_fields 指定欄位名清單。日期、數量這類型別差異最好在 SQL 端先轉好（上例用 CONVERT(char(8), …, 112) 轉成 yyyymmdd 給 ABAP 的 d 型別）。

5. 把連線包成一個類別：錯誤處理與關閉集中管理

每支程式都自己 get_connection／close，遲早有人忘了關、忘了 rollback。實務上建議包一個小類別，連線名稱集中在一處，例外轉成自己的訊息：

CLASS zcl_ext_db DEFINITION PUBLIC FINAL CREATE PUBLIC.
  PUBLIC SECTION.
    CONSTANTS gc_con TYPE dbcon_name VALUE 'ZEXTDB'.   "DBCO 連線名稱只寫在這裡

    METHODS constructor
      RAISING cx_sql_exception.
    METHODS stmt
      RETURNING VALUE(ro_stmt) TYPE REF TO cl_sql_statement.
    METHODS commit
      RAISING cx_sql_exception.
    METHODS rollback.
    METHODS close.
  PRIVATE SECTION.
    DATA mo_con TYPE REF TO cl_sql_connection.
ENDCLASS.

CLASS zcl_ext_db IMPLEMENTATION.
  METHOD constructor.
    mo_con = cl_sql_connection=>get_connection( gc_con ).
  ENDMETHOD.

  METHOD stmt.
    ro_stmt = mo_con->create_statement( ).
  ENDMETHOD.

  METHOD commit.
    mo_con->commit( ).
  ENDMETHOD.

  METHOD rollback.
    TRY.
        mo_con->rollback( ).
      CATCH cx_sql_exception ##NO_HANDLER.
        " 連線已斷時 rollback 也會失敗，這裡吞掉即可
    ENDTRY.
  ENDMETHOD.

  METHOD close.
    TRY.
        mo_con->close( ).
      CATCH cx_sql_exception ##NO_HANDLER.
    ENDTRY.
  ENDMETHOD.
ENDCLASS.
次要連線的交易是獨立的：對 ZEXTDB 的 commit( ) 只提交外部 DB 的交易，與 SAP 主資料庫的 COMMIT WORK 各自獨立，沒有兩階段提交。反過來說，主程式的 COMMIT WORK 也不會替你提交外部連線上的變更——結束前沒 commit 就關連線，資料會被回滾。所以「先寫 SAP、再寫外部」或反之，都要設計失敗時的補救（第 11 節）。

6. 下載至 SQL Server：參數化寫入與批次提交

業務情境：外部報表平台要看 SAP 的 BOM 用量結構，Basis 開好 DBCO 後，由背景作業每天把資料「下載」到外部 DB 的 ZEXT_BOM_ITEM。素材只有截圖，（依講義步驟整理）寫法如下：先刪除本次範圍，再逐筆以參數化 INSERT 寫入，每 N 筆提交一次。

REPORT zext_bom_download.

PARAMETERS: p_werks TYPE werks_d OBLIGATORY,
            p_pack  TYPE i DEFAULT 1000.

START-OF-SELECTION.
  " 1. 從 SAP 取資料（S/4HANA 可改用 CDS；這裡示範 BOM 表頭＋項目）
  SELECT mast~matnr, mast~werks, mast~stlan, stpo~posnr,
         stpo~idnrk, stpo~menge, stpo~meins
    FROM mast
    INNER JOIN stpo ON stpo~stlnr = mast~stlnr
                   AND stpo~stlty = 'M'
    WHERE mast~werks = @p_werks
    ORDER BY mast~matnr, mast~stlan, stpo~posnr          "HANA 沒有預設排序
    INTO TABLE @DATA(lt_bom).

  " 2. 寫到外部 DB
  DATA: lv_matnr TYPE matnr,
        lv_werks TYPE werks_d,
        lv_stlan TYPE stlan,
        lv_posnr TYPE sposn,
        lv_idnrk TYPE idnrk,
        lv_menge TYPE kmpmg,
        lv_meins TYPE meins,
        lv_count TYPE i.

  TRY.
      DATA(lo_db) = NEW zcl_ext_db( ).

      DATA(lo_del) = lo_db->stmt( ).
      lo_del->set_param( REF #( p_werks ) ).
      DATA(lv_deleted) = lo_del->execute_update(
        `DELETE FROM dbo.ZEXT_BOM_ITEM WHERE werks = ?` ).

      " 同一個 statement 物件重複執行：參數以參考綁定，改變數值再執行即可
      DATA(lo_ins) = lo_db->stmt( ).
      lo_ins->set_param( REF #( lv_matnr ) ).
      lo_ins->set_param( REF #( lv_werks ) ).
      lo_ins->set_param( REF #( lv_stlan ) ).
      lo_ins->set_param( REF #( lv_posnr ) ).
      lo_ins->set_param( REF #( lv_idnrk ) ).
      lo_ins->set_param( REF #( lv_menge ) ).
      lo_ins->set_param( REF #( lv_meins ) ).

      LOOP AT lt_bom INTO DATA(ls_bom).
        lv_matnr = ls_bom-matnr.
        lv_werks = ls_bom-werks.
        lv_stlan = ls_bom-stlan.
        lv_posnr = ls_bom-posnr.
        lv_idnrk = ls_bom-idnrk.
        lv_menge = ls_bom-menge.
        lv_meins = ls_bom-meins.
        lo_ins->execute_update(
          `INSERT INTO dbo.ZEXT_BOM_ITEM ` &&
          `(matnr, werks, stlan, posnr, idnrk, menge, meins, sync_ts) ` &&
          `VALUES (?, ?, ?, ?, ?, ?, ?, SYSUTCDATETIME())` ).
        lv_count = lv_count + 1.
        IF lv_count MOD p_pack = 0.
          lo_db->commit( ).                                "批次提交，避免外部交易記錄檔爆掉
        ENDIF.
      ENDLOOP.

      lo_db->commit( ).
      lo_db->close( ).
      MESSAGE |刪除 { lv_deleted } 筆，寫入 { lv_count } 筆| TYPE 'S'.

    CATCH cx_sql_exception INTO DATA(lx_sql).
      IF lo_db IS BOUND.
        lo_db->rollback( ).
        lo_db->close( ).
      ENDIF.
      MESSAGE |寫入外部 DB 失敗：{ lx_sql->sql_message }| TYPE 'E'.
  ENDTRY.
批次提交的代價：每 1000 筆 commit 一次，失敗時前面已提交的資料會留在外部 DB，而 DELETE 也已經提交——外部報表會看到「半套」資料。要避免有兩種做法：(1) 寫進暫存表 ZEXT_BOM_ITEM_STG，全部成功後由對方儲存程序在單一交易內切換；(2) 以同步批號 sync_id 標記，外部只讀「最後一個完整批號」。

陣列寫入：資料量上萬筆時，逐筆 execute_update 的網路往返會成為瓶頸。ADBC 的 CL_SQL_STATEMENT 另有 set_param_table，可以一次綁定整個內表做陣列 DML（請先在 SE24 確認你系統的 CL_SQL_STATEMENT 有此方法及其參數）：

TYPES: BEGIN OF ty_row,
         matnr TYPE matnr,
         werks TYPE werks_d,
         stlan TYPE stlan,
         posnr TYPE sposn,
         idnrk TYPE idnrk,
         menge TYPE kmpmg,
         meins TYPE meins,
       END OF ty_row.

" 欄位順序要與 INSERT 的 ? 順序一致
DATA(lt_rows) = VALUE STANDARD TABLE OF ty_row WITH EMPTY KEY(
  FOR ls IN lt_bom ( CORRESPONDING #( ls ) ) ).

TRY.
    DATA(lo_db) = NEW zcl_ext_db( ).
    DATA(lo_stmt) = lo_db->stmt( ).
    lo_stmt->set_param_table( REF #( lt_rows ) ).
    DATA(lv_rows) = lo_stmt->execute_update(
      `INSERT INTO dbo.ZEXT_BOM_ITEM_STG ` &&
      `(matnr, werks, stlan, posnr, idnrk, menge, meins) ` &&
      `VALUES (?, ?, ?, ?, ?, ?, ?)` ).
    lo_db->commit( ).
    lo_db->close( ).
  CATCH cx_sql_exception INTO DATA(lx_sql).
    IF lo_db IS BOUND.
      lo_db->rollback( ).
      lo_db->close( ).
    ENDIF.
    MESSAGE lx_sql->get_text( ) TYPE 'E'.
ENDTRY.

7. 呼叫外部的儲存程序：邏輯留在對方，SAP 只呼叫

素材第四份的關鍵字是「用後端儲存程序當資料來源」：外部 DB 提供 dbo.up_FUN_BOMTree，傳入物料與用途就回傳整棵展開後的 BOM。這個分工值得推廣到 SAP 端——SAP 需要外部的計算結果時，不要把一段長長的 T-SQL 寫在 ABAP 字串裡，而是請對方包成儲存程序，SAP 只 EXEC。

比較SQL 寫在 ABAP 字串裡對方提供儲存程序
對方改表結構SAP 要改程式、走傳輸對方改儲存程序即可，介面（參數與回傳欄位）不變
權限DB 帳號要有各表 SELECT／INSERT 權限帳號只給 EXECUTE 權限，看不到表
SQL injection一不小心就拼字串參數型別由程序定義
效能與執行計畫每次動態解析對方 DBA 可以調整、看執行計畫
責任歸屬資料錯了雙方互推「呼叫參數對 → 回傳錯」就是對方的事，界線清楚

對方 DBA 提供的儲存程序大致長這樣（依講義步驟整理，示意）：

CREATE PROCEDURE dbo.up_FUN_BOMTree
    @matnr NVARCHAR(40),
    @usage CHAR(1)
AS
BEGIN
    SET NOCOUNT ON;   -- 不回傳「n rows affected」，避免被當成第一個結果集
    WITH bom AS (
        SELECT h.matnr AS root, 0 AS lvl, h.matnr AS parent, h.matnr AS comp,
               CAST(1 AS DECIMAL(13,3)) AS qty, CAST('' AS NVARCHAR(3)) AS unit
          FROM dbo.ZEXT_BOM_ITEM h
         WHERE h.matnr = @matnr AND h.stlan = @usage
        UNION ALL
        SELECT b.root, b.lvl + 1, i.matnr, i.idnrk, i.menge, i.meins
          FROM bom b
          JOIN dbo.ZEXT_BOM_ITEM i ON i.matnr = b.comp AND i.stlan = @usage
    )
    SELECT DISTINCT root, lvl, parent, comp, qty, unit
      FROM bom
     ORDER BY lvl, parent, comp;   -- 明確排序
END

8. ABAP SQL 的 CONNECTION 子句：只限「對方也是 SAP 結構」

如果次要資料庫裡的表，在本系統 ABAP 字典中也有相同名稱、相同結構的定義（典型是另一套 SAP 系統的資料庫、或 SAP 提供的附屬資料庫），可以直接用 ABAP SQL 加 CONNECTION，享受語法檢查與型別安全：

" 次要連線 ZSAP_ARCH 指向一顆「舊 SAP 系統」的資料庫
DATA(lv_con) = CONV dbcon_name( 'ZSAP_ARCH' ).

SELECT vbeln, erdat, kunnr, netwr, waerk
  FROM vbak CONNECTION (lv_con)            "動態連線名稱，用括號
  WHERE erdat BETWEEN @p_from AND @p_to
  ORDER BY vbeln
  INTO TABLE @DATA(lt_old_orders).

" 靜態寫法：FROM vbak CONNECTION zsap_arch
限制：CONNECTION 子句會用本系統字典中的表定義去組 SQL，所以對方必須是 SAP 的 schema（含 MANDT 欄與相同欄位名）。像 dbo.ZEXT_POCHANGE 這種外部系統自己的表，本系統字典沒有，就只能用 ADBC。也不要為了用 CONNECTION 而在本系統建一個「假的」同名透明表——它會在本系統主資料庫也建出一張空表，還會誤導後人。

原程式流程：

  1. AT SELECTION-SCREEN：以員編查 BUT000 帶姓名。
  2. START-OF-SELECTION：authority_rtn（依作業別檢查 ZAOWH／ZAOPD／ZAOQA）→ 讀 CAUFV 與 ZPPROWMP0002 → 決定兩個異動類型 → 對每張工單：檢查已下達、讀 RESB、讀自建表頭與明細、逐元件補 AFPO／MARD／MSKA／銷售訂單已發量／物料群組 → 依「略過已完成」刪列並預填本次數量 → REUSE_ALV_GRID_DISPLAY。

                      AND j~stat  = 'I0002'              "REL 已下達
                      AND j~inact = @abap_false

                           AND d~werks = r~werks
                           AND d~lgort = r~lgort

11. ZPPR0002／ZPPR0005 的原程式問題

#原程式問題改法
1delete_db_rtn 先刪 ZPPROWHD0001／ZPPROWDE0003 並 COMMIT WORK，insert_db_rtn 再逐筆 MODIFY 並再 COMMIT兩次 commit 之間若 dump 或斷線，累計收發量就整筆消失；而物料憑證早已過帳，無從回推不需要先刪：直接 MODIFY ztab FROM TABLE @lt_dtl，表頭與明細在同一個 LUW、只 commit 一次；確實要刪的列用 DELETE ztab FROM TABLE 同 LUW 處理
2BAPI 每張工單各自 COMMIT，之後才更新 Z 表憑證成功、Z 表失敗 → 累計量與實際憑證不符，下次作業會重複發料Z 表以憑證為準：每張工單 BAPI 成功後立即把該工單的 Z 表變更一起寫入（同一次 BAPI_TRANSACTION_COMMIT 之前以 MODIFY 寫入，讓它與憑證同 LUW）；或累計量不存，改由 MATDOC 即時彙總
3preare_migo_261qa_item 的第一個 LOOP 用 t_261_h-aufnr（應為 t_261qa_h）判斷換單，後面又對 T_RESB_261 再 LOOP 一次追加相同項目QA 判定發料的項目可能被加兩次 → 261 重複扣帳只保留一段組項目邏輯，鍵值用當前表頭；過帳前以 REDUCE 驗證項目數量合計等於畫面輸入
4t_scr100_dtl_so_qty 查沖銷：WHERE sjahr = lt_mseg-mblnr AND smbln = lt_mseg-mjahr憑證號與年度對調，永遠查不到沖銷 → 已沖銷的量也被算進銷售訂單已發量smbln = mblnr AND sjahr = mjahr AND smblp = zeile；S/4HANA 改讀 MATDOC 並直接排除已沖銷（見下方程式）

6ZPPR0002 → ZPPR0005 用 EXPORT t_sel TO MEMORY ID 'ZPPR0002'＋SUBMIT … AND RETURN＋IMPORT … FROM MEMORY ID 'ZPPR0002_DTL'兩支程式的內表結構必須一模一樣且無型別檢查；另一支改欄位就靜默失敗合併成一支（ALV 選取 → 可編輯 CL_GUI_ALV_GRID），或把 ZPPR0005 的邏輯封裝成類別方法，以參數傳遞
7authority_rtn 開頭 CHECK sy-mandt <> '130'.某個 client 直接跳過權限檢查，測試便利變成正式漏洞（client 被複製時更危險）刪除；測試帳號給角色即可
8工單鎖 ENQUEUE_ESORDER 的呼叫在 START-OF-SELECTION 被註解掉兩個人同時對同一張工單作業，會各自依舊累計量過帳 → 超發進入可編輯模式前鎖工單（或鎖自建表的鎖物件），鎖不到就唯讀
9員編以 SELECT SINGLE * FROM but000 WHERE nickname = … 驗證，姓名存進 Z 表、寫進憑證表頭文字員編是自由輸入、任何人都能打別人的員編，稽核上不可信；NICKNAME 也沒有唯一性作業人員以 sy-uname 為準（ERNAM／AENAM 原本就有），員編只當顯示；或以使用者 → 員工對照表查
10成品入庫以外、固定抓 lgort = 'B800' 的庫存寫死儲位，組織調整就失效放到參數表（工廠 → 參考儲位）
11「略過已完成」條件：A AND B AND C AND D AND E OR F OR GAND 優先於 OR，語意正確但難讀；後人加條件極易改錯拆成具名的布林方法 is_completed( )，每個條件一行、加括號
12TABLES、OCCURS 0 WITH HEADER LINE、LIKE、巨集 DEFINE m_message（內含 EXIT）、REUSE_ALV_*巨集裡的 EXIT 會跳出呼叫它的 FORM，除錯時看不出來全面改寫為類別＋內嵌宣告；ALV 顯示用 CL_SALV_TABLE、需要輸入的畫面用 CL_GUI_ALV_GRID

第 4 點在 S/4HANA 的寫法：MSEG 已是 MATDOC 上的相容視圖，直接讀 MATDOC 並以「未被沖銷、本身也不是沖銷憑證」過濾：

" 銷售訂單庫存（特殊庫存 E）對某工單元件已發出、且未被沖銷的數量
SELECT m~shkzg, SUM( m~menge ) AS menge
  FROM matdoc AS m
  WHERE m~werks = @ls_comp-werks
    AND m~matnr = @ls_comp-idnrk
    AND m~lgort = @ls_comp-lgort_ik
    AND m~mat_kdauf = @ls_comp-kdauf
    AND m~mat_kdpos = @ls_comp-kdpos
    AND m~record_type = 'MDOC'                         "只算憑證列，不算彙總列
    AND m~cancelled   = @abap_false                    "沒有被沖銷
    AND m~smbln       = @space                         "本身不是沖銷憑證
  GROUP BY m~shkzg
  INTO TABLE @DATA(lt_sum).

" 貸方 H（發出）為正、借方 S（退回）為負
DATA(lv_so_issued) = REDUCE menge_d( INIT s = 0
                                     FOR r IN lt_sum
                                     NEXT s = s + COND menge_d( WHEN r-shkzg = 'H' THEN r-menge
                                                                ELSE 0 - r-menge ) ).
MATDOC 的特殊庫存銷售訂單欄位名（MAT_KDAUF／MAT_KDPOS）與 CANCELLED、RECORD_TYPE 的用法，請以你系統 SE11 的 MATDOC 定義為準；若不確定，改讀 MSEG 相容視圖，但把沖銷條件的欄位對應改正（smbln = mblnr AND sjahr = mjahr AND smblp = zeile）。

12. 把收發料紀錄推到外部資料庫：時機與重送

若外部 MES／報表平台要即時看到收發料，最常見的錯誤是在 APPROVE 的過帳迴圈裡「順便」用 DBCO 寫外部 DB：外部一慢，使用者就卡在畫面上；外部寫失敗，SAP 已過帳也收不回來。正確的切法是 SAP 先完成自己的 LUW，再非同步推送：

  1. 過帳成功時，在同一個 LUW 寫一列到出口佇列表 ZPP_EXT_QUEUE（憑證號、年度、狀態 = 'N'）。
  2. 背景作業（SM37 每 5 分鐘）讀 'N' 的列，以 ADBC 寫到外部 dbo.ZEXT_WO_ISSUE，外部 commit 成功後把佇列列改成 'S'；失敗改 'E' 並記錄 sql_message。
  3. 外部表以（憑證號＋年度＋項次）為主鍵，用 MERGE 或「存在就略過」，重送不會重複。
METHOD push_queue.
  SELECT q~mblnr, q~mjahr, q~zeile, q~aufnr, q~matnr, q~werks,
         q~lgort, q~bwart, q~menge, q~meins, q~budat, q~ernam
    FROM zpp_ext_queue AS q
    WHERE q~status = 'N'
    ORDER BY q~mjahr, q~mblnr, q~zeile
    INTO TABLE @DATA(lt_queue)
    UP TO 5000 ROWS.
  CHECK lt_queue IS NOT INITIAL.

  DATA ls_row LIKE LINE OF lt_queue.
  TRY.
      DATA(lo_db) = NEW zcl_ext_db( ).
      DATA(lo_stmt) = lo_db->stmt( ).
      lo_stmt->set_param( REF #( ls_row-mblnr ) ).
      lo_stmt->set_param( REF #( ls_row-mjahr ) ).
      lo_stmt->set_param( REF #( ls_row-zeile ) ).
      lo_stmt->set_param( REF #( ls_row-aufnr ) ).
      lo_stmt->set_param( REF #( ls_row-matnr ) ).
      lo_stmt->set_param( REF #( ls_row-werks ) ).
      lo_stmt->set_param( REF #( ls_row-lgort ) ).
      lo_stmt->set_param( REF #( ls_row-bwart ) ).
      lo_stmt->set_param( REF #( ls_row-menge ) ).
      lo_stmt->set_param( REF #( ls_row-meins ) ).
      lo_stmt->set_param( REF #( ls_row-budat ) ).
      lo_stmt->set_param( REF #( ls_row-ernam ) ).

      LOOP AT lt_queue INTO ls_row.
        " 由對方提供的儲存程序做「存在就更新、不存在就新增」，SAP 不寫 MERGE
        lo_stmt->execute_update(
          `EXEC dbo.up_Upsert_WoIssue ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?, ?` ).
      ENDLOOP.
      lo_db->commit( ).
      lo_db->close( ).

      " 外部已提交，再以主鍵逐筆更新 SAP 端佇列狀態（不用憑證號區間）
      DATA lv_ts TYPE timestampl.
      GET TIME STAMP FIELD lv_ts.                          "UTC
      LOOP AT lt_queue INTO DATA(ls_done).
        UPDATE zpp_ext_queue SET status = 'S', sent_ts = @lv_ts
          WHERE mblnr = @ls_done-mblnr
            AND mjahr = @ls_done-mjahr
            AND zeile = @ls_done-zeile.
      ENDLOOP.
      COMMIT WORK.

    CATCH cx_sql_exception INTO DATA(lx_sql).
      IF lo_db IS BOUND.
        lo_db->rollback( ).
        lo_db->close( ).
      ENDIF.
      MESSAGE |推送失敗，下次重送：{ lx_sql->sql_message }| TYPE 'S' DISPLAY LIKE 'E'.
  ENDTRY.
ENDMETHOD.
寫法注意：狀態回寫以主鍵逐筆（列舉）更新，而不是「本批最小憑證號 BT 最大憑證號」——憑證號段不連續、跨年度重號時，區間比的是字典序，會把還沒推送的列也標成已送、或漏標（Casper 的第 2 條經驗）。時間戳用 GET TIME STAMP FIELD 取 UTC 的 timestampl，1809 即可用；7.54 以上也可改用 UTCLONG 與 utclong_current( )。

13. 反方向：外部平台用儲存程序當資料來源

素材第四份是另一個角度：某雲端 ERP／低代碼網頁平台要做「用量結構」查詢（物料編號、工廠、建立日期區間 → 列出 BOM 表頭：SEQ、WERKS、STLAN、AENNR、DATUV、VALID_TO、REVLV、BMENG、BMEIN、建立日期、ERTIM、AEDAT、AETIM、UNAME），點物料編號下鑽到「R_61X」頁，顯示展開後的元件：主件、用途、level、主件名、群組編號、子階主件、I_POSNR、子階類別（L）、子階件號、子階件名、子階數量、子階單位。

平台上的設定步驟（依講義步驟整理）：

  1. 在查詢頁的資料元件旁放一個 Drilldown 元件：BindingObject 指向主表格、Mode = tab、TargetRemoteName 指向伺服器端元件（s_61x.s_61x）、Page = R_61X。
  2. Drilldown 的 Columns 設定欄位對應：MATNR = 主件、STLAN 同理——把點選列的值當參數帶到下一頁。
  3. 伺服器端元件的 CommandType 設為 StoreProcedure，不寫 SQL 文字。
  4. 在元件原始碼的 setData 中呼叫儲存程序 dbo.up_FUN_BOMTree，把兩個參數傳進去，結果直接回給畫面。
素材中的 SQL injection：原平台腳本是 "exec <DBNAME>.dbo.up_FUN_BOMTree '" + param.para1 + "','" + param.para2 + "'"——把網頁傳來的參數直接拼進 SQL 字串。只要有人在物料欄輸入 x'; DROP TABLE …; -- 就能執行任意指令。即使「CommandType 是 StoreProcedure」，只要呼叫字串是拼出來的，就一樣有漏洞。正確做法是使用平台的參數化查詢 API（以 @matnr、@usage 具名參數傳值），同時讓平台用的 DB 帳號只有 EXECUTE 權限。ABAP 端同理：永遠 set_param，不要 && 使用者輸入。

這個案例的價值在於分工：SAP 每天把 BOM 同步到外部 DB（第 6 節），BOM 展開的遞迴邏輯寫在對方的儲存程序裡，網頁平台只負責畫面與下鑽。SAP 不用為了一個網頁報表開 RFC、寫 OData，也不用讓外部平台碰 SAP 資料庫。要注意的只有一點：外部看到的是「上次同步」的資料，畫面上要顯示同步時間（第 6 節的 sync_ts）。

14. 安全、效能與資料正確性檢核

帳密存放：外部 DB 的帳密只存在 DBCON（加密），不要寫在程式常數、選擇畫面預設值、TVARVC 或文件裡；DBCO 的維護權限（S_TABU_DIS／S_TABU_NAM 對 DBCON）只給 Basis。各系統的 DBCON 分別維護，不要把正式機的連線資訊傳輸到開發機。外部帳號採最小權限：只讀的整合只給 SELECT 或 EXECUTE。
SQL injection：ADBC 的 SQL 是字串，編譯器不會幫你擋。所有值一律 ? ＋ set_param；表名、欄位名、排序欄這種不能參數化的部分，只能從程式內的白名單常數挑，絕不接受使用者輸入。
批次與交易：大量寫入要分批 commit（第 6 節），但分批就代表可能「寫一半」，要搭配暫存表切換或批號機制；讀取大量資料用 next_package( upto ) 分包，別一次載入百萬筆到記憶體。長時間作業一律丟背景，並設定外部 DB 的查詢逾時。
字元集與 NVARCHAR：SAP 是 Unicode，外部欄位若是 VARCHAR（依 DB 定序的單位元組字碼頁），中文會變問號或亂碼。外部表的文字欄一律用 NVARCHAR，長度以「字元」計；ABAP 的 c LENGTH 40 對 NVARCHAR(40)。物料號碼的前導零（ALPHA 轉換）要事先約定兩邊存哪一種格式。
時區：SAP 的 sy-datum／sy-uzeit 是系統時區、sy-datlo／sy-timlo 是使用者時區，SQL Server 的 GETDATE() 是 DB 主機時區。建議兩邊交換的時間戳一律 UTC（SAP 端 GET TIME STAMP、SQL 端 SYSUTCDATETIME()），顯示時再轉換。
HANA／SQL Server 都沒有預設排序：不論 ABAP SQL 讀 SAP、還是 ADBC 讀外部，只要邏輯是「取第一筆」或依順序比對，就要明寫 ORDER BY。Casper 在成本評價上踩過的坑（同時有 item category H 與 cost component E，沒排序時一下抓到 H、一下抓到 E，最後固定抓 H）在跨系統整合裡一樣會發生，而且更難查——因為兩邊的執行計畫都會變。
效能觀察工具：SQL Server 端的慢查詢可以用 DBACOCKPIT／ST04_MSS 看；素材列出的 STUN_MSS 套件相關交易還有 SQLSTMT_MSS（在新視窗顯示 ABAP 的 SQL）、EXPL_MSS（執行計畫）、DB02_MSS、DB12_MSS（多連線）。這些是針對「SAP 自己跑在 SQL Server 上」設計的；主資料庫是 HANA 時，部分功能只對已登錄的系統可用（見第 3 節的錯誤訊息）。
