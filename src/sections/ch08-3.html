4. 關鍵邏輯一：重建「關帳日當下」的未清項與部分付款

「關帳日當下未清」＝「今天仍未清且關帳日前已過帳」（BSID）＋「關帳日前過帳、但在關帳日之後才清帳」（BSAD，augdt > p_datum）。原程式這個觀念是對的（2021-12 補上 BSAD 那段之前，回溯月份的對帳單都會少列），改寫時用 UNION ALL（7.50+）一次取回。

TYPES: BEGIN OF ty_ref_sum,
         rebzj  TYPE rebzj,
         rebzg  TYPE rebzg,
         rebzz  TYPE rebzz,
         amount TYPE dmbtr,
       END OF ty_ref_sum.
DATA lt_ref_sum TYPE HASHED TABLE OF ty_ref_sum WITH UNIQUE KEY rebzj rebzg rebzz.

LOOP AT lt_open INTO DATA(ls_part) WHERE rebzg IS NOT INITIAL.
  COLLECT VALUE ty_ref_sum(
            rebzj  = ls_part-rebzj
            rebzg  = ls_part-rebzg
            rebzz  = ls_part-rebzz
            amount = COND #( WHEN ls_part-shkzg = 'H' THEN ls_part-dmbtr * -1
                             ELSE ls_part-dmbtr ) )
    INTO lt_ref_sum.
ENDLOOP.

" ③ 發票行 + 已沖部分付款 = 剩餘未收；找不到原發票的部分付款要保留成獨立行，總額才對得起來

                                ELSE ls_inv-dmbtr ).
  DATA(lv_paid)   = VALUE #( lt_ref_sum[ rebzj = ls_inv-gjahr
                                         rebzg = ls_inv-belnr

                  budat    = ls_inv-budat
                  belnr    = ls_inv-belnr
                  buzei    = ls_inv-buzei

                  residual = lv_signed + lv_paid ) TO lt_stmt_item.

ENDLOOP.
" lt_ref_sum 剩下的就是「參照不到發票」的部分付款 → 另列為 Unapplied Payment
原程式在這裡的三個問題：
  • BSID 與 BSAD 處理不對稱。BSID 那段過濾 rebzg = space，部分付款另外扣回發票；BSAD 那段沒過濾，已清掉的部分付款會變成獨立一行；而「扣回 BSAD 部分付款」那段在 2023-02 被整段註解。結果是：同一張發票，查當月與查上個月，明細呈現方式不同，總額卻恰好相等，會計很難對。改寫版把兩邊合併後統一處理。
  • 部分付款只認憑證類型 DZ／AB。其他類型（例如手動沖帳 SA、殘額過帳）帶 REBZG 時會被當成發票本身列出。改寫版以「有沒有 REBZG」判斷，不以憑證類型判斷——這也是 Casper 第二條的精神：條件寫成業務語意（有參照），不要寫成碰巧成立的清單。
  • 巢狀 LOOP … WHERE 在標準表上，n×m 次掃描；客戶一多背景作業就跑不完。改用 HASHED 表一次查找。
另外特殊總帳（UMSKZ，例如預收款 A、票據 W）是否要出現在對帳單，是業務規則，請明確寫成條件（列舉 UMSKZ 值），不要默默全收。
S/4HANA 差異：BSID／BSAD 在 S/4HANA 已不是實體索引表，而是同名的相容性視圖（Compatibility View），底層讀的是 BSEG／ACDOCA 的實際行項目，所以舊程式的 SELECT 仍能執行、結果一致，但它是「為了相容而存在」。新開發建議直接讀 ACDOCA，或讀 SAP 發布的 CDS 視圖 I_OperationalAcctgDocItem（含 NetDueDate、ClearingDate、InvoiceReference 等欄位；欄位名稱與是否 released 請以你系統的 ADT／SE11 為準）。

原程式寄信段的問題：
  • 寄件者寫死成某個 SAP 使用者代號（cl_sapuser_bcs=>create( gc_uname )），該帳號一旦被鎖或離職改名，整批對帳單就寄不出去。改用設定表中的共用信箱。
  • 信件本文用十幾行 <font face=Arial> 寫死公司全名、電話、官網。公司更名、換電話就要改程式、走傳輸。改用 SO10 標準文字（可多語）或郵件範本維護。
  • CATCH cx_bcs 後什麼都不做，寄失敗完全無聲；背景作業還會顯示成功。改寫版每個客戶都寫一筆執行紀錄（可再寫進 BAL 應用程式日誌，SLG1 查詢）。
  • 每封信 SUBMIT rsconn01：強迫 SAPconnect 立刻處理整個佇列，數百個客戶時非常慢，也會干擾其他程式的郵件。正確做法是由 Basis 在 SCOT 排定傳送作業，程式只負責 set_send_immediately 與 COMMIT。
  • set_link_to_outbox( 'X' ) 會讓每封信進寄件者的 SAP 外寄匣，批次寄數百封時外寄匣會爆量；需要追蹤請用 SOST。

  3. 測試機（DEV／QAS）一定要在 SCOT 設定轉寄或封鎖外部網域，否則從正式機複製回來的客戶郵箱，會讓測試對帳單真的寄到客戶手上——這是對帳單專案最常見、也最尷尬的事故。

11. ZSDF004 程式架構：選單 SUBMIT 分派＋九支子程式共用骨架

選單程式只做一件事：把六個 SELECT-OPTIONS 轉成 RSPARAMS，依單選鈕決定子程式名稱與 P_TYPE（版型），SUBMIT (lv_report) WITH SELECTION-TABLE rspar_tab AND RETURN。每支子程式的骨架都一樣：

  1. 權限：AUTHORITY-CHECK M_MATE_MAT（BEGRU 'N'），把 MARA 中權限群組 N 的物料組成 range，再找出含這些物料的銷售訂單組成 range，最後把這些訂單從結果刪掉（ELSE 分支在講義中被刪減為「…」，完整規則無法確認）。
  2. 取數：SELECT 訂單或交貨單清單 → REUSE_ALV_GRID_DISPLAY_LVC 顯示，SEL 欄勾選。

日圓金額差 100 倍的坑。原程式把 PRCD_ELEMENTS-KBETR 直接放進字串並加上「￥」。SAP 內部對沒有小數位的幣別（JPY、KRW 等，TCURX 設定）仍以兩位小數儲存，1,000 日圓在資料庫裡是 10.00；只有用 CURRENCY = waerk 格式化（或 WRITE … CURRENCY、CURRENCY_AMOUNT_SAP_TO_DISPLAY）才會還原成 1,000。直接轉字串就會印出 10.00，差 100 倍。同理，原程式把 CNY 與 JPY 都印成「￥」，對報關文件是模糊的，建議一律印 ISO 幣別代碼。
PI 與報關發票算法不同，尾差對不上。R01 用「PR02 單價 × 數量」；R02 在一次修改中改成「VBAP-NETWR ÷ KWMENG × 交貨量」以「最佳化尾差」。結果同一張訂單，PI 總額與報關發票總額可能差幾分錢，海關或客戶一對就出問題。另外 KBETR 是「每 KPEIN 個 KMEIN 的價格」，條件價格單位不是 1 時直接乘數量就錯。所有單據的單價與金額應該由同一個方法算，而且以 NETWR 為準。
Casper 第一條再出現：原程式多處 READ TABLE … INDEX 1 取「第一筆」：VBPA 業務員、T052U 付款條件文字、KNA1＋ADRC 地址（這個連 SORT 都沒有），R06 還有一句 SELECT SINGLE * FROM vbkd WHERE vbeln = … 沒給 POSNR——訂單有項目層 VBKD 時，拿到表頭還是某個項目完全看資料庫心情。一律要寫完整鍵，或先 ORDER BY 再取第一筆。
T052U 用 SPRAS = '1' 的原因：程式註解寫「中文環境維護的也是英文」——付款條件的英文說明被維護在中文語言鍵下。'1' 是中文的內部語言鍵，不是英文。正確做法是在英文（E）下維護翻譯，程式依單據語言讀取；否則日後有人把中文鍵改成真的中文，英文 PI 就會印出中文付款條件。

13. 報關彙總、結匯單（Commercial Invoice／Packing List）與箱數

                            AND c~zkunnr = l~kunnr

原程式的箱號欄印成「1,2,3,5,7,8」這種逐一列舉的清單，而不是壓成「1-3,5,7-8」。對關務來說列舉看起來冗長，但可逐箱核對、不會因為跳號而誤判——這正是 Casper 第二條「列舉比區間安全」在單據上的體現。若客戶堅持要區間格式，也請在系統內保留列舉值，只在輸出時壓縮。
批號、效期與標準欄位對照：R06 從 MCHA 的自建附加欄位 ZZBATCH 讀「對外批號」，用自建函數 ZWMFU0 以生產日期推算效期，部分版型改讀滅菌批表 ZWMT008。SAP 標準：批次主檔 MCH1（S/4HANA 預設批次層級為物料層級，應讀 MCH1 而非工廠層級的 MCHA）的 HSDAT 生產日、VFDAT 有效期限（由物料主檔 MARA-MHDHB 總貨架壽命自動計算）、LICHA 供應商批號；更多屬性放批次分類（MSC3N）。原程式還在某版型把工廠寫死為 1000 去讀 MCHA，多工廠時必錯。
S/4HANA 外貿功能差異：ECC 的 SD 外貿（Foreign Trade）在 S/4HANA 由 International Trade（及 SAP GTS）取代，商品編碼（HS／Commodity Code）改為可設有效期間的分類管理，細節請依版本查 Simplification List。本案的 HS 編碼、申報要素、中英文品名都放在自建表 ZTSDBGYS，這在標準功能不足（特別是中國海關的申報要素）時合理，但要有維護畫面（SM30）、變更記錄與負責單位，不然 HS 編碼改版時沒人知道要改。

14. 英文大寫金額：ZFM_SPELL_AMOUNT_POINT 的問題與 SPELL_AMOUNT 正確用法

外貿發票最後一行通常是「SAY US DOLLARS ONE THOUSAND TWO HUNDRED THIRTY-FOUR AND CENTS FIFTY ONLY」。原專案寫了共用函數 ZFM_SPELL_AMOUNT_POINT（群組 ZMMFG002「common functions」，短文「英文大寫（翻譯 point）」；匯入 I_AMOUNT 無型別、說明為「憑證貨幣計量的淨價值」，匯出 E_AMOUNT 無型別）。做法是：把金額轉成字串、以「.」切成整數與小數，整數丟 SPELL_AMOUNT，小數兩位各自再丟一次，組成「… AND POINT FIVE-SIX」。

這支函數的問題：
  • CURRENCY = sy-waers：SY-WAERS 是過時的系統欄位，通常為空或不正確；SPELL_AMOUNT 需要實際幣別才能正確處理小數位（JPY 的內部位移問題也由它處理）。
  • 小數逐位念成「POINT FIVE-SIX」不是商業發票慣例；0.50 會念成「POINT FIVE」，客戶與銀行常要的是「AND CENTS FIFTY」。
  • 匯入參數無型別、字串切割依賴小數點字元與千分位設定；負數會帶出「-」。
  • 程式裡有 IF … <> 'ZERO' .. 兩個句點的筆誤（剛好合法，因為空敘述被允許），代表這段沒有被仔細審查。
其實 SPELL_AMOUNT 本身就回傳整數文字 WORD 與小數文字 DECWORD，不需要自己切。
METHOD amount_in_words.
  " iv_amount：內部格式金額；iv_waers：單據幣別
  DATA ls_words TYPE spell.

  CALL FUNCTION 'SPELL_AMOUNT'
    EXPORTING
      amount    = iv_amount
      currency  = iv_waers
      language  = 'E'
    IMPORTING
      in_words  = ls_words
    EXCEPTIONS
      not_found = 1
      too_large = 2
      OTHERS    = 3.
  IF sy-subrc <> 0.
    RETURN.
  ENDIF.

  SELECT SINGLE ltext FROM tcurt
    WHERE spras = 'E' AND waers = @iv_waers
    INTO @DATA(lv_curr_name).

  rv_text = COND #(
    WHEN ls_words-decword IS INITIAL OR ls_words-decword = 'ZERO'
    THEN |SAY { to_upper( lv_curr_name ) } { ls_words-word } ONLY|
    ELSE |SAY { to_upper( lv_curr_name ) } { ls_words-word } AND CENTS { ls_words-decword } ONLY| ).
ENDMETHOD.
大寫金額一律對「合計金額」算一次，並與數字合計放在同一個方法產生；不要各單據各算。這支方法很適合寫 ABAP Unit：0、0.01、0.50、1,234.56、JPY 1000、負數各一個測試案例。

15. Excel 輸出現代化：OLE＋剪貼簿 → 伺服器端產生 xlsx

ZSDF004 九支程式全部用 OLE Automation 操作使用者電腦上的 Excel，明細靠剪貼簿貼上。這在 2000 年代很普遍，但在 S/4HANA 專案有一連串問題：

問題說明
只能在 SAP GUI for Windows＋本機裝 Excel 時執行SAP GUI for HTML、Fiori Launchpad、背景作業全都不能用；也就無法「出貨過帳後自動產生並寄出」
覆蓋使用者剪貼簿使用者剛複製的內容被清掉；執行中若使用者按了 Ctrl+C，貼進 Excel 的就是別的東西——單據內容錯了還不會報錯
慢且脆弱每格一次 OLE 往返；Excel 版本、巨集安全設定、防毒都會影響；FREE OBJECT 沒做好會留下 EXCEL.EXE 殭屍程序
座標寫死set_cell USING 13 4 … 這類列欄號散落各程式；範本多一列，程式就要改
檔案落在使用者本機沒有存檔紀錄、無法稽核「發給海關的是哪一版」

替代方案依需求選：固定版面、要 PDF → SmartForms 或 Adobe Forms（SFP，S/4HANA 輸出管理主推，見 4-3 章）；海關或客戶要可編輯的 Excel → 伺服器端產生 xlsx，例如開源的 abap2xlsx（非 SAP 標準，導入前需經公司原始碼審查），較新的 S/4HANA 版本另有 XCO 的 XLSX 模組可用（依版本確認）。範本不再放 SMW0 下載到本機，而是放 MIME Repository，由程式在伺服器端讀取：

METHOD build_invoice_xlsx.
  " 1. 讀範本（SE80 MIME Repository；路徑放設定表）
  DATA lv_template TYPE xstring.
  DATA(lo_mr) = cl_mime_repository_api=>get_api( ).
  lo_mr->get( EXPORTING  i_url     = ms_cfg-template_url      " 例：/SAP/PUBLIC/ZSDF004/PI_STD.xlsx
              IMPORTING  e_content = lv_template
              EXCEPTIONS OTHERS    = 1 ).
  IF sy-subrc <> 0.
    RAISE EXCEPTION TYPE zcx_sd_ft_doc EXPORTING textid = zcx_sd_ft_doc=>template_not_found.
  ENDIF.

  TRY.
      " 2. abap2xlsx 載入範本、填值（開源專案，API 以導入版本為準）
      DATA(lo_excel) = CAST zif_excel_reader( NEW zcl_excel_reader_2007( ) )->load( lv_template ).
      DATA(lo_ws)    = lo_excel->get_active_worksheet( ).

      " 表頭：座標集中在版型設定（ZSD_FT_LAYOUT：版型 / 欄位名 / 欄 / 列），不散落在程式裡
      LOOP AT mt_layout INTO DATA(ls_pos) WHERE area = 'H'.
        ASSIGN COMPONENT ls_pos-fieldname OF STRUCTURE is_head TO FIELD-SYMBOL(<lv_value>).
        IF sy-subrc = 0.
          lo_ws->set_cell( ip_column = ls_pos-col ip_row = ls_pos-row ip_value = <lv_value> ).
        ENDIF.
      ENDLOOP.

      " 明細：從起始列往下寫，不用剪貼簿
      DATA(lv_row) = ms_layout_head-item_start_row.
      LOOP AT it_item INTO DATA(ls_item).
        LOOP AT mt_layout INTO ls_pos WHERE area = 'I'.
          ASSIGN COMPONENT ls_pos-fieldname OF STRUCTURE ls_item TO <lv_value>.
          IF sy-subrc = 0.
            lo_ws->set_cell( ip_column = ls_pos-col ip_row = lv_row ip_value = <lv_value> ).
          ENDIF.
        ENDLOOP.
        lv_row = lv_row + 1.
      ENDLOOP.

      " 3. 輸出 xstring：前景可 gui_download，背景可當郵件附件或存 DMS / 附件服務
      rv_xlsx = CAST zif_excel_writer( NEW zcl_excel_writer_2007( ) )->write_file( lo_excel ).
    CATCH zcx_excel INTO DATA(lx_excel).
      RAISE EXCEPTION TYPE zcx_sd_ft_doc EXPORTING previous = lx_excel.
  ENDTRY.
ENDMETHOD.
範本若需要「插入列並沿用格式」，abap2xlsx 的作法與 Excel OLE 的 Rows.Insert 不同（通常是預留樣式、逐列套用 style），實作前先用小範本驗證。無論選哪個工具，產出的檔案都應該在系統內留存（例如掛在交貨單的附件上），日後海關查核時才能證明當時送出的內容。

16. ZSDF004 原程式問題與改進、S/4HANA 與上線注意事項

原寫法問題改進
九支子程式各有一份 set_cell、range_paste、get_col_by_number、frm_download_template、frm_check_authority、ALV 顯示同一個 bug 要修九次；表頭註解都還寫著 R07抽出共用類別：資料來源（訂單層／交貨單層）× 版型（輸出格式）。用策略模式（Strategy）讓每種單據只實作「取數」與「欄位對應」，見 7-5 章
TABLES: vbak, vbkd, likp；RANGE OF … WITH HEADER LINE；R06 的 DATA: BEGIN OF gt_data OCCURS 0舊語法參照變數、標準 RANGE 表、內嵌宣告
REUSE_ALV_GRID_DISPLAY（R06）／REUSE_ALV_GRID_DISPLAY_LVC（其餘）兩套 ALV FM 混用CL_SALV_TABLE 多選（2-3 章）
LOOP 內 SELECT SINGLE * 與逐筆 SELECT … APPENDINGN+1 查詢；SELECT * 取整列JOIN 或 FOR ALL ENTRIES（先檢查驅動表非空）、明列欄位
權限：以 MARA-BEGRU = 'N' 產生全部物料 range，再產生訂單 range物料多時 range 過大，會觸發 SQL 敘述過長的短傾印；且邏輯難以驗證對結果列中實際出現的 BEGRU 逐一 AUTHORITY-CHECK；或以 CDS 視圖＋存取控制（DCL）處理
特定客戶號寫死於 IF（數量換算、依物料彙總）新增客戶要改程式；客戶號也不該出現在原始碼設定表（例：ZSD_FT_CUST，放 C000001 這類鍵值與旗標）
幣別符號 IF 串（USD→$、EUR→€、CNY/JPY→￥）JPY 金額差 100 倍、CNY/JPY 無法區分CURRENCY 格式化＋ISO 代碼
PI 用 PR02 單價、報關用 NETWR 比例單據間金額尾差不一致單一計價方法，以 NETWR 為準
T052U 讀中文語言鍵當英文語言維護錯位英文下維護翻譯
TRANSLATE … TO UPPER CASE、CONCATENATE、MOVE-CORRESPONDING 表頭行舊寫法to_upper( )、字串範本、CORRESPONDING #( )
OLE Excel＋剪貼簿＋SMW0 下載到本機見 8-3-15伺服器端產生、系統內留存
MCHA 寫死工廠 1000、自建效期函數多工廠錯誤；重造標準MCH1-VFDAT／HSDAT，批次分類

上線注意事項：① 以同一票貨把 PI、報關發票、箱單、結匯單的數量、金額、淨毛重、件數四項交叉核對，任何一項不一致都不能上線。② 測試 JPY、無小數位幣別與 KPEIN ≠ 1 的價格條件。③ 測試一箱多大類、一料多批、部分交貨、同一交貨單多張訂單。④ ZTSDKHCHXX 缺資料時要明確報錯（原程式靜默留空，單據上品名與重量就是空白）。⑤ 關務單據屬於法定文件，產出檔要留存並可追溯到交貨單與列印人。

練習與自我檢核

  1. 未清項 vs 餘額結轉：客戶說「對帳單上看不到我上個月付的款」。你判斷他要的是哪一種對帳單？兩種各要讀哪些資料？
    要點：他要的是期初／本期／期末（餘額結轉式），本期收款必須列出；未清項式對帳單本來就不列已清項目。前者讀 ACDOCA 期間彙總＋本期明細（8-3-05），後者讀 BSID＋BSAD（augdt > 關帳日）或 I_OperationalAcctgDocItem。
  2. 關帳日回溯：為什麼只讀 BSID 產生的「6 月 30 日對帳單」在 7 月 10 日重跑時金額會變少？
    要點：7 月 1～10 日收款清掉的發票已移到 BSAD；要補上 augdt > p_datum 的 BSAD 行項目。
  3. 排序穩定性：對帳單明細依 kunnr、budat 排序後逐行累計餘額，會有什麼問題？怎麼修？
    要點：HANA 無預設排序，同日多筆順序不定，累計餘額逐行數字每次不同；加入 belnr、buzei（或 docln）為排序鍵（Casper 第一條）。
  4. 到期日：指出原程式用 J_1A_SD_CI_DUEDATE_CHECK 的兩個風險，並寫出替代呼叫。
    要點：在地化函數、以 FI 憑證號當請款單號的號碼巧合；改 NET_DUE_DATE_GET 或 NetDueDate 欄位；到期日不要寫回 ZFBDT。
  5. 批次寄信：列出把對帳單排成每月背景作業時，至少四項必須先處理的設定或程式修改。
    要點：變式＋動態日期、寄件者設定化、測試機 SCOT 封鎖外寄、寄送紀錄與失敗重寄、移除每封 SUBMIT RSCONN01、背景使用者權限。
  6. 收件人：S/4HANA 中，要取「客戶應收帳款部門的聯絡人郵箱」，應該讀哪兩張 BP 表？關係類型是什麼？
    要點：BUT050（關係類型 BUR001 聯絡人）＋BUT051（部門 ABTNR、郵箱）；原函數中被註解的那段就是這個做法。
  7. 日圓：PRCD_ELEMENTS-KBETR = 10.00、幣別 JPY，原程式印出什麼？正確應為多少？怎麼寫？
    要點：印出「￥10.00」，正確為 1,000 日圓；用 |{ kbetr CURRENCY = waerk }| 或 CURRENCY_AMOUNT_SAP_TO_DISPLAY。
  8. 箱數：一張交貨單 10 箱，其中 2 箱同時裝了大類 A 與 B 的貨。各大類箱數與總件數各是多少？為什麼總件數不能相加？
    要點：各大類的箱數分別計算（混裝的 2 箱在 A、B 各算一次），總件數＝整張單 COUNT DISTINCT＝10；相加會多出 2。
  9. 大寫金額：用 SPELL_AMOUNT 產生「SAY US DOLLAR … AND CENTS … ONLY」，並說明原 ZFM_SPELL_AMOUNT_POINT 傳 SY-WAERS 的問題。
    要點：見 8-3-14；SY-WAERS 過時且常為空，幣別小數位處理錯誤。
  10. 重構設計：把 ZSDF004 九支子程式重構成類別架構，畫出你的類別清單與責任。
    要點：資料來源介面（訂單層、交貨單層）、單據策略介面（取數＋欄位對應＋版型）、共用服務（計價、大寫金額、HS 彙總、箱數、xlsx/PDF 產生、留存）、設定表（版型座標、特殊客戶、範本路徑）；Excel 產出改伺服器端，可背景執行。
